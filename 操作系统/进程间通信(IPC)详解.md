# 进程间通信(IPC)详解

## 为什么需要 IPC

进程之间默认是互相隔离的——各有各的独立地址空间，一个进程看不到另一个进程内存里的数据。要在进程之间传递信息，就得靠操作系统提供的**进程间通信（IPC，Inter-Process Communication）** 机制。

## 常见 IPC 方式及适用场景

### 匿名管道（Pipe）

只能用在**有亲缘关系**的进程之间（典型是父子进程），比如 shell 里的 `|` 就是用匿名管道把前一个命令的输出接到后一个命令的输入。数据是单向流动的字节流，没有消息边界的概念。

### 命名管道（FIFO）/ Unix Domain Socket

解决了匿名管道"只能用在亲缘进程间"的限制，**没有亲缘关系的进程**也能通过一个文件系统路径找到同一个通信端点进行通信。Unix Domain Socket 相比命名管道更灵活，支持双向通信，还能传递文件描述符。

### 消息队列

适合传递**结构化的小块消息**。发送方把消息放进队列，接收方按需取出，天然支持消息边界，不像管道那样是无结构的字节流。

### 共享内存

适合传递**大量数据**，因为多个进程直接映射同一块物理内存，避免了数据在进程间来回拷贝的开销，是几种 IPC 方式里性能最高的一种。但共享内存本身不提供同步机制，需要额外配合信号量、互斥锁等手段来避免多个进程同时读写导致的竞态问题。

### 信号（Signal）

适合**异步通知**场景，比如通知进程收到了某个事件、要求进程退出。信号传递的信息量很小（本质上就是一个事件编号），不适合传输实际数据内容。

### 套接字（Socket）

TCP/UDP/RPC 这一类，适合**跨机器**的进程间通信。即使是同一台机器上的两个进程，也可以选择用本机 Socket（loopback）通信，只是性能上不如共享内存或 Unix Domain Socket。

## 如何选择合适的 IPC 方式

大致的判断思路：

1. 先看**是否跨机器**——跨机器只能用网络相关的方式（TCP/UDP/RPC）
2. 同机器内，看**是否有亲缘关系**——没有亲缘关系就不能用匿名管道
3. 再看**数据量大小和结构化程度**——小结构化消息用消息队列，大数据量用共享内存
4. 如果只是简单的事件通知，不需要传数据本身，用信号最轻量

## 面试里怎么答

被问到"进程间通信方式有哪些，怎么选"时，不要只是干巴巴列出六七种方式的名字，而是按"具体场景"来组织回答：父子进程之间用管道，无亲缘关系的本机进程用命名管道或 Unix Domain Socket，需要传大量数据用共享内存（但要提到需要配合同步机制），只是简单通知用信号，跨机器通信用 Socket/RPC——这样能体现出"知道每种方式解决的是什么具体问题"，而不是死记硬背列表。
