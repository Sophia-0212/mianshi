# 内存管理详解：碎片、伙伴系统、Overcommit 与 OOM

## 内存管理主要做什么

操作系统的内存管理，大致要干这几件事：

1. **分配与回收**：进程要内存就给，用完了就收回来
2. **地址转换**：通过 MMU + 页表把虚拟地址翻译成物理地址（详见[虚拟内存详解](虚拟内存详解.md)）
3. **进程隔离**：每个进程只能看到自己的地址空间，看不到别的进程
4. **页面回收/换页**：内存紧张时把不常用的页换到磁盘上
5. **共享与映射**：比如写时复制（COW）、`mmap`、共享内存，让多个进程能高效共享同一块物理内存

## VSZ、RSS、PSS 是什么区别

排查内存问题经常会看到这三个指标，很容易搞混：

- **VSZ（Virtual Size）**：进程映射的虚拟地址空间大小，包含还没真正分配物理页的部分，**不代表实际物理内存占用**
- **RSS（Resident Set Size）**：进程当前**实际驻留在物理内存里**的页面大小
- **PSS（Proportional Set Size）**：把共享页按"共享的进程数"均摊后算出来的占用量，多个进程共享同一块内存时，PSS 比 RSS 更能反映"真实分摊到的开销"

常用排查命令：

```bash
grep -E 'VmSize|VmRSS|RssAnon|RssFile|RssShmem|VmSwap' /proc/<pid>/status
cat /proc/<pid>/smaps_rollup
```

## 内存碎片：内部碎片 vs 外部碎片

- **内部碎片**：分配给你的内存块里，有一部分实际没用上（比如按页分配，最后一页没用满）
- **外部碎片**：空闲内存被切成很多互不相邻的小块，虽然总空闲量够，但没有一块连续的空间能满足新的分配请求

## 内存管理方式：连续 vs 非连续

**连续分配**：以整块（Buddy System，伙伴系统）为主。

伙伴系统把内存按 2 的幂次切块，释放时如果相邻的"伙伴块"也是空闲的，就合并成更大的块。

![伙伴系统内存管理](https://oss.javaguide.cn/github/javaguide/cs-basics/operating-system/linux-buddy-system.png)

问题：请求大小不是 2 的幂次时依然会浪费内存。比如请求 65，系统只能给一个 128 大小的块，剩下 63 就浪费掉了。

![伙伴系统内存浪费问题](https://oss.javaguide.cn/github/javaguide/cs-basics/operating-system/buddy-system-memory-waste.png)

针对伙伴系统"最小分配粒度太粗"的问题，Linux 内核里常用的内核对象缓存用的是 **SLAB/SLUB 分配器**——按对象类型预先建好缓存池，减少反复分配释放的开销。

**非连续分配**：段式管理、页式管理、段页式管理（详见[虚拟内存详解](虚拟内存详解.md)）。

## Swap、工作集与抖动

- **Swap**：磁盘上给匿名页准备的"备用空间"，不是免费的内存扩容，比内存慢得多
- **工作集（Working Set）**：进程当前正在活跃使用的那部分页面
- **抖动（Thrashing）**：工作集塞不进物理内存时，CPU 大部分时间都在处理缺页、页面回收、磁盘 I/O，真正干活的时间反而很少

排查命令：

```bash
free -h
vmstat 1
grep -E 'pgfault|pgmajfault|pswpin|pswpout|pgscan|pgsteal' /proc/vmstat
cat /proc/pressure/memory
```

## Overcommit 和 OOM Killer

Linux 允许进程申请的虚拟内存总量**超过实际的物理内存 + Swap 总量**，这叫 **Overcommit**。原因是 `malloc()`/`mmap()` 调用成功，只代表虚拟地址空间预留成功，**不代表真的分配了物理页**——物理页往往是等第一次真正访问（写）的时候才分配（按需分页）。

当物理内存真的紧张到腾不出来的时候，内核的 **OOM Killer** 会挑一个进程杀掉来释放内存。容器场景下要特别注意：cgroup 限制的内存上限，可能在**宿主机整体内存还很充裕**的情况下就触发容器内的 OOM，跟宿主机的整体内存状况没关系。

## mmap、COW、共享内存

- **`mmap()`**：创建虚拟内存映射（可以是文件映射，也可以是匿名映射），调用成功不代表数据立刻被真的加载进内存
- 多个进程 `mmap` 同一个文件时，可以通过 **Page Cache** 共享同一份物理内存
- **写时复制（COW，Copy-On-Write）**：常见于 `fork()`。父子进程一开始共享同一批物理页（都标成只读），谁第一个尝试写入，就触发缺页异常，系统给它单独复制一份私有页
