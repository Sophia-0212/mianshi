# CPU调度与系统负载

## 进程调度算法

**非抢占式**（一旦开始执行就不会被打断，直到主动让出或结束）：

- **FCFS（先来先服务）**：谁先到谁先执行，公平但不考虑任务长短，容易让短任务被长任务堵在后面
- **SJF（短作业优先）**：优先执行预计耗时最短的任务，平均等待时间更优，但长任务可能一直被插队（饥饿）

**抢占式**（可以被更高优先级的任务或时间片到期打断）：

- **RR（时间片轮转）**：每个任务轮流跑一个固定时间片，公平性好，适合交互式系统
- **优先级调度**：按优先级高低决定执行顺序，需要处理"高优先级任务持续占用导致低优先级饥饿"的问题
- **MLFQ（多级反馈队列）**：设置多个优先级队列，任务用得越久优先级越低，兼顾短任务的响应速度和长任务的公平性

实际的 Linux 内核用的是更复杂的算法：主流是 **CFS（完全公平调度器）**，核心思想是给每个任务算一个"虚拟运行时间（vruntime）"，谁的 vruntime 小就优先调度谁，尽量让所有任务获得的 CPU 时间趋于公平。从 Linux 6.6 开始，内核引入了 **EEVDF（Earliest Eligible Virtual Deadline First）** 调度器，进一步优化了延迟和公平性的平衡。

## 调度器和分派程序的区别

这两个概念经常被混着说，其实分工不同：

- **调度器（Scheduler）**：负责"决策"——按调度算法从就绪队列里选出下一个该运行的任务
- **分派程序（Dispatcher）**：负责"执行"——真正完成上下文切换的动作，保存当前任务的寄存器/程序计数器，恢复被选中任务的执行状态，把 CPU 控制权转交给它

## load average 和 CPU 使用率的区别

这是排查线上问题时经常被问到的点，两者反映的是不同维度：

- **load average（系统负载）**：统计的是"可运行状态（R）+ 不可中断睡眠状态（D）"的任务数量。D 状态通常是在等磁盘 I/O——所以 **load 很高不一定是 CPU 在忙，可能是大量进程卡在等 I/O**
- **CPU 使用率**：能进一步拆分成用户态时间占比、内核态时间占比、I/O 等待时间占比、空闲时间占比等，能更精细地反映 CPU 到底在干什么

排查思路：先看 `uptime` 拿到 load average 的大致水平，再用 `top` 看整体 CPU 分布，`vmstat 1` 看系统级别的 CPU/内存/IO 走势，`pidstat`、`mpstat` 进一步定位到具体进程或每个核心的情况。

## 面试里怎么答

调度算法这块常见的问法是"讲讲进程调度算法有哪些，Linux 用的是什么"。可以按"非抢占式 vs 抢占式"分类讲完经典算法后，落到"Linux 实际用的是 CFS，核心是 vruntime，保证长期运行下每个任务获得的 CPU 时间趋于公平"这个结论，如果对方追问新版本，可以补充 EEVDF 这个更新的调度器。

被问到"load average 很高是不是 CPU 很忙"时，一定要先纠正这个常见误区：**load 高不代表 CPU 忙，很可能是大量进程卡在磁盘 I/O 等待上**，再补充具体的排查命令组合，展示实际排障经验而不只是背概念。
