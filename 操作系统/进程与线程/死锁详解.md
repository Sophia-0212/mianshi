# 死锁详解

## 什么是死锁

死锁指的是多个进程/线程之间**循环等待对方持有的资源**，谁都无法继续往下走，必须靠外部干预（比如强制杀掉某个进程）才能解开。经典场景是"交叉持锁"：线程 A 拿着锁1、等锁2，线程 B 拿着锁2、等锁1，两边就这么僵住了。

## 产生死锁的四个必要条件

死锁要发生，必须同时满足以下四个条件——只要破坏其中任何一个，就能避免死锁：

1. **互斥**：资源一次只能被一个线程独占使用
2. **占有并等待**：线程已经持有至少一个资源，同时还在等待获取别的资源
3. **非抢占**：资源只能由持有它的线程自愿释放，不能被别的线程强行抢走
4. **循环等待**：存在一个"线程1等线程2、线程2等线程3……最后又绕回等线程1"的循环等待链

## 模拟死锁的代码示例

两个线程分别以相反顺序获取两个锁，就会构成经典死锁：

```java
public class DeadLockDemo {
    private static final Object resource1 = new Object();
    private static final Object resource2 = new Object();

    public static void main(String[] args) {
        new Thread(() -> {
            synchronized (resource1) {
                System.out.println(Thread.currentThread() + "get resource1");
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
                System.out.println(Thread.currentThread() + "waiting get resource2");
                synchronized (resource2) {
                    System.out.println(Thread.currentThread() + "get resource2");
                }
            }
        }, "线程 1").start();

        new Thread(() -> {
            synchronized (resource2) {
                System.out.println(Thread.currentThread() + "get resource2");
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
                System.out.println(Thread.currentThread() + "waiting get resource1");
                synchronized (resource1) {
                    System.out.println(Thread.currentThread() + "get resource1");
                }
            }
        }, "线程 2").start();
    }
}
```

运行结果，两个线程各自拿到一把锁后就永远卡住，等对方释放另一把锁：

```
Thread[线程 1,5,main]get resource1
Thread[线程 2,5,main]get resource2
Thread[线程 1,5,main]waiting get resource2
Thread[线程 2,5,main]waiting get resource1
```

## 解决死锁的方法

四类思路：

1. **预防**：从设计上破坏四个必要条件之一。最常用的做法是约定所有线程都**按同一顺序**获取多个锁，直接消除循环等待
2. **避免**：运行时动态检测，只在确认"不会导致死锁"的情况下才分配资源（比如银行家算法），但实际系统里代价较高，很少直接用
3. **检测**：定期检查资源分配图（或等待图）里有没有环。Java 里可以用 `jcmd`、`jstack` 打印线程栈，或者用 `ThreadMXBean.findDeadlockedThreads()` 编程式检测
4. **解除/恢复**：检测到死锁后，强制终止某个进程/线程，或者回滚某个事务，打破死锁

## 面试里怎么答

被问到死锁，可以按这个顺序组织：先给出死锁的定义（循环等待，谁都无法继续），再列出四个必要条件，然后强调"破坏任意一个条件即可避免死锁"这个核心思路，最后举一个"多把锁按不同顺序获取"导致死锁的具体例子，并说明实践中最常用的预防手段就是**统一加锁顺序**。
