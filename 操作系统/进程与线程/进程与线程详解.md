# 进程与线程详解

## 进程和线程的区别

类比工厂和工人：**进程**像一个独立的工厂，有自己独立的厂房、设备（独立的地址空间、文件表等资源）；**线程**像工厂里的工人，共享厂房和设备，但每个人有自己的工具箱（独立的栈、寄存器、程序计数器）。

| 维度 | 进程 | 线程 |
|---|---|---|
| 基本定位 | 资源分配和隔离的单位 | CPU 调度和执行的单位 |
| 地址空间 | 独立的虚拟地址空间 | 同一进程内的线程共享地址空间 |
| 私有内容 | PID、地址空间、文件描述符表、权限 | 线程 ID、栈、寄存器、程序计数器、TLS（线程局部存储） |
| 通信方式 | 需要 IPC（进程间通信） | 可以直接访问共享内存 |
| 创建/切换成本 | 通常更高 | 通常更低 |
| 故障影响范围 | 隔离性好，一个进程崩溃不影响别的进程 | 一个线程出错可能拖垮整个进程 |

Java 里，JVM 运行时数据区域中，堆、方法区是所有线程共享的；虚拟机栈、程序计数器、本地方法栈是每个线程私有的——这跟进程/线程"共享 vs 私有"资源的划分逻辑是一致的。

## 有了进程为什么还需要线程

线程能在**一个进程内部**以更低的开销实现并发。对 I/O 密集型任务，多线程可以在等待 I/O 时切换去干别的活；对 CPU 密集型任务，多线程能真正利用多核并行计算。但线程数量也不是越多越好——线程一多，调度和锁竞争的开销会显著上升，反而拖累整体性能。

## 多线程一定能提高性能吗

不一定。要看：

- 任务是 I/O 密集型还是 CPU 密集型
- CPU 核心数够不够多
- 共享资源的竞争程度

线程数超过合理范围后，调度切换和锁等待的开销会盖过并发带来的收益，吞吐量和延迟反而会变差。

## 线程间同步的方式有哪些

1. **互斥锁（Mutex）**：保证同一时刻只有一个线程访问共享资源
2. **读写锁（Read-Write Lock）**：允许多个读操作并发，但写操作互斥
3. **信号量（Semaphore）**：控制同时访问某资源的线程数量
4. **屏障（Barrier）**：让一组线程都到达某个点后才能继续往下走
5. **条件变量（Condition Variable）/ 事件通知**：线程等待某个条件成立再被唤醒

## PCB 是什么，包含哪些信息

**PCB（Process Control Block，进程控制块）** 是内核用来管理进程的核心数据结构，主要包含：

- 标识信息（PID 等）
- 状态与调度信息（进程当前状态、优先级）
- CPU 上下文（寄存器值、程序计数器）
- 内存管理信息（页表指针等）
- 资源信息（打开的文件描述符等）

## TCB 是什么，和 PCB 有什么关系

**TCB（Thread Control Block，线程控制块）** 保存的是线程级别的执行上下文。在 Linux 里，进程和线程在内核层面被统一抽象成 `task_struct`，线程本质上是共享了大部分资源、但拥有独立执行上下文的一种特殊"任务"。

## 进程有哪几种状态

经典五态模型：

1. **创建状态**：进程正在被创建
2. **就绪状态**：已经准备好运行，等 CPU 调度
3. **运行状态**：正在 CPU 上执行
4. **阻塞状态**：等待某个事件（比如 I/O 完成）才能继续
5. **结束状态**：进程执行完毕或被终止

有些教材还会区分出"挂起状态"，跟"阻塞"的区别在于挂起通常意味着进程被换出到磁盘上，暂时完全不参与调度。

## 进程间的通信方式有哪些

按场景选择：

- **匿名管道（pipe）**：适合有亲缘关系的进程（比如父子进程）之间通信
- **命名管道 / Unix Domain Socket**：适合没有亲缘关系的进程之间通信
- **消息队列**：适合传递结构化的小消息
- **共享内存**：适合传递大量数据，需要配合信号量等同步机制防止竞态
- **信号（Signal）**：适合异步通知（比如通知进程退出）
- **TCP/UDP/RPC**：适合跨机器的进程间通信

（更完整的对比见[进程间通信(IPC)详解](../进程间通信(IPC)详解.md)）

## fork、exec、wait 分别做什么

- **`fork()`**：创建一个新的子进程，几乎是当前进程的一个副本
- **`exec()`**：用新的程序替换掉当前进程的代码和数据（常见组合是先 `fork()` 再 `exec()`，实现"创建一个新进程去跑另一个程序"）
- **`wait()` / `waitpid()`**：父进程等待子进程结束，并回收子进程的退出状态，避免产生僵尸进程

## 什么是上下文切换

上下文切换指的是保存当前执行单元（进程/线程）的寄存器、程序计数器、栈指针等状态，然后加载另一个执行单元的状态，让 CPU 切换去执行它。

**进程切换的成本比线程切换更高**，因为进程切换还涉及地址空间的切换（页表切换），会导致 TLB 大量失效，需要重新填充，而线程切换在同一进程内不涉及这部分开销。

## 进程的调度算法有哪些

**非抢占式**：
- FCFS（先到先服务）
- SJF（短作业优先）

**抢占式**：
- RR（时间片轮转）
- Priority Scheduling（优先级调度）
- MLFQ（多级反馈队列）

实际的 Linux 内核用的调度算法更复杂：主流是基于虚拟运行时间（vruntime）的 **CFS（完全公平调度器）**，从 Linux 6.6 开始又引入了 **EEVDF** 调度器。

## 究竟是谁来调度进程的

- **调度器（Scheduler）**：负责根据调度算法从就绪队列里挑出下一个要运行的任务
- **分派程序（Dispatcher）**：负责真正执行上下文切换——保存/恢复寄存器、程序计数器，把控制权真正转交给被选中的任务

## load average 和 CPU 使用率有什么区别

- **load average**：反映的是"可运行 + 处于不可中断睡眠状态"（Linux 里的 R 和 D 状态）的任务数量，不完全等同于 CPU 繁忙程度，磁盘 I/O 阻塞多的时候 load 也会很高
- **CPU 使用率**：拆分成用户态时间、内核态时间、I/O 等待时间、空闲时间等多个维度

排查工具：`uptime`、`top`、`vmstat`、`pidstat`、`mpstat`
