# 0925. 长按键入

**题目描述**

你的朋友正在使用键盘输入他的名字 `name`。偶尔，在键入字符 `c` 时手指可能会在键盘上停留过长时间，导致字符被重复输入多次。你将会检查键盘输入的字符 `typed`，如果它对应的可能是你的朋友的名字（其中一些字符可能被长按后出现重复），那么就返回 `true`。

```
示例 1：
输入: name = "alex", typed = "aaleex"
输出: true
解释: 'a' 和 'e' 被长按

示例 2：
输入: name = "saeed", typed = "ssaaedd"
输出: false
解释: 'e' 一定需要被键入两次，但在 typed 的输出中不是这样的

示例 3：
输入: name = "leelee", typed = "lleeelee"
输出: true

示例 4：
输入: name = "laiden", typed = "laiden"
输出: true
解释: 长按键入的情况可能不会发生
```

## 思路

这道题表面上看是字符串比较，但不能直接逐字符对比，为什么呢？因为 `typed` 里某个字符可能因为长按被重复了若干次，字符数量根本对不上。正确的切入点是"分组"的思想：把 `name` 和 `typed` 都按照连续相同字符切分成一段一段的组，每组记录"字符是什么"和"这组连续出现了几次"。

举个例子，`name = "alex"` 分组后是 `[('a',1), ('l',1), ('e',1), ('x',1)]`；`typed = "aaleex"` 分组后是 `[('a',2), ('l',1), ('e',2), ('x',1)]`。你可以看到两边分组的数量是一样的（都是 4 组），并且对应位置上的字符完全一致（`a,l,e,x` 对 `a,l,e,x`），而且 `typed` 每组的次数都大于等于 `name` 对应组的次数（2≥1, 1≥1, 2≥1, 1≥1）。这正是长按键入的本质：长按只会让某个字符被多次触发，不会改变字符出现的顺序，也不会让某组的次数比原来还少。

所以合法的判断条件就是：两边分组后组数相同、每组字符相同、而且 `typed` 每组的次数不小于 `name` 对应组的次数。反例 `saeed` vs `ssaaedd`：`name` 分组是 `[(s,1),(a,1),(e,2),(d,1)]`，`typed` 分组是 `[(s,2),(a,2),(e,1),(d,2)]`。第三组 `e` 在 `name` 中出现了 2 次，但在 `typed` 中只出现了 1 次，1 < 2，说明这个字符被"按少了"，不符合长按的规律（长按只会增多不会减少），所以返回 false。

具体实现上有两种常见写法：

第一种是显式分组后再比较，先把两个字符串各自转换成 `(字符, 计数)` 的分组列表，再比较列表长度是否相等，然后逐组比较字符和计数关系。这种写法思路最直观，但需要额外的空间存储分组结果。

第二种是双指针原地比较，不用显式生成分组列表，而是用两个指针 `i`（指向 `name`）和 `j`（指向 `typed`）同步往前走。每一轮：

1. 如果当前 `name[i] != typed[j]`，直接返回 false（字符本身就不匹配，肯定不合法）。
2. 记录当前字符 `c = name[i]`，分别统计 `name` 从 `i` 开始连续等于 `c` 的个数 `cntName`，和 `typed` 从 `j` 开始连续等于 `c` 的个数 `cntTyped`。
3. 如果 `cntTyped < cntName`，说明这一组字符在 `typed` 中出现的次数不够，返回 false。
4. 把 `i` 和 `j` 分别跳过各自这一组的长度，进入下一组比较。

等 `i` 遍历完 `name` 之后，如果 `j` 也恰好遍历完 `typed`，说明匹配成功了；但如果 `name` 已经遍历完而 `typed` 还有剩余字符，得额外检查这部分剩余字符是不是最后一组字符的延续长按（比如 `name="alex"`，`typed="aalexx"` 走到最后 `x` 这组的时候逻辑本身就会吸收掉多余的 `x`，所以只要每组的判断逻辑写对了，天然就能处理末尾多余字符的情况，不用额外补丁）。真正需要留意的边界是：如果 `typed` 剩余的字符和 `name` 已经耗尽后对不上（比如 `typed` 最后多出一段和 `name` 末尾字符不同的字符），这种情况也会在下一轮的字符比较中被判定为 false，或者是在两指针都结束后判断长度是否都走到了终点。

双指针写法的优势是不需要额外的分组数组，空间复杂度更优，是这道题更推荐的实现方式。

复杂度分析：设 `name` 长度为 `n`，`typed` 长度为 `m`。双指针只需要一次线性遍历（每个字符最多被访问一次），时间复杂度 O(n + m)。分组写法的时间复杂度相同，但空间复杂度是 O(n + m)（要存分组结果）；双指针写法只用常数个变量记录计数，空间复杂度 O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    bool isLongPressedName(string name, string typed) {
        int i = 0, j = 0;
        int n = name.size(), m = typed.size();
        while (i < n && j < m) {
            if (name[i] != typed[j]) return false;  // 字符本身不一致，直接失败
            char c = name[i];
            int cntName = 0, cntTyped = 0;
            while (i < n && name[i] == c) { i++; cntName++; }   // 统计 name 这一组的长度
            while (j < m && typed[j] == c) { j++; cntTyped++; } // 统计 typed 这一组的长度
            if (cntTyped < cntName) return false;  // typed 这组次数不够，不可能是长按结果
        }
        return i == n && j == m;  // 两边必须同时走完，否则说明有多余或缺失的字符
    }
};
```

### Python

标准库一行解：Python 的 `itertools.groupby` 恰好就是"按连续相同元素分组"的标准工具，非常契合本题的分组思想，可以直接用它生成分组序列再比较。

```python
from itertools import groupby

class Solution:
    def isLongPressedName(self, name: str, typed: str) -> bool:
        # groupby 把连续相同字符聚成一组，(字符, 该组长度) 的序列
        g1 = [(c, len(list(g))) for c, g in groupby(name)]
        g2 = [(c, len(list(g))) for c, g in groupby(typed)]
        if len(g1) != len(g2):
            return False  # 分组数不同，字符出现的模式已经不一致
        # 逐组比较：字符必须相同，typed 的计数必须不小于 name 的计数
        return all(c1 == c2 and n2 >= n1 for (c1, n1), (c2, n2) in zip(g1, g2))
```

原理说明：`groupby(s)` 会把字符串中连续重复的字符压缩成一个个 `(字符, 迭代器)` 的组，取 `len(list(g))` 就能拿到这一组的长度。这一行解法几乎就是"分组比较法"的直接翻译，代码简洁，但会为每个分组构造中间列表，实际面试更看重你能不能手写出双指针版本，因为双指针体现的是你对字符串扫描和边界处理的掌控力，也是这题真正想考察的能力。

手写实现（面试考察点：双指针同步扫描 + 分组计数比较，是这道题的标准解法）：

```python
class Solution:
    def isLongPressedName(self, name: str, typed: str) -> bool:
        n, m = len(name), len(typed)
        i, j = 0, 0
        while i < n and j < m:
            if name[i] != typed[j]:
                return False  # 当前字符不一致，直接失败
            c = name[i]
            start_i = i
            while i < n and name[i] == c:
                i += 1  # 统计 name 中这一组连续 c 的长度
            cnt_name = i - start_i
            start_j = j
            while j < m and typed[j] == c:
                j += 1  # 统计 typed 中这一组连续 c 的长度
            cnt_typed = j - start_j
            if cnt_typed < cnt_name:
                return False  # typed 这一组次数不足，不满足长按只增不减的性质
        return i == n and j == m  # 两个指针都必须走到末尾
```

### Go

```go
func isLongPressedName(name string, typed string) bool {
    n, m := len(name), len(typed)
    i, j := 0, 0
    for i < n && j < m {
        if name[i] != typed[j] {
            return false // 字符不一致
        }
        c := name[i]
        startI := i
        for i < n && name[i] == c {
            i++ // 统计 name 这一组的长度
        }
        cntName := i - startI
        startJ := j
        for j < m && typed[j] == c {
            j++ // 统计 typed 这一组的长度
        }
        cntTyped := j - startJ
        if cntTyped < cntName {
            return false // typed 次数不够，非法
        }
    }
    return i == n && j == m // 两指针都要走完
}
```

## 总结

- 这题的关键洞察是把"长按"翻译成"分组次数的不等式"：长按只会让某个字符连续出现的次数增多，不会改变字符出现的种类和顺序，所以把字符串按连续相同字符分组后，只要比较组序列是否一致、且 `typed` 每组次数不小于 `name` 对应组次数即可。
- 双指针写法比显式分组更省空间，是这类"连续字符分组比较"问题的通用技巧，能不额外创建数组、纯粹靠指针移动就完成分组统计。
- 容易漏掉的边界是：两个指针的循环结束条件必须都满足（`i == n && j == m`），如果只判断某一个指针到达终点，会漏判 `name` 提前结束但 `typed` 还有多余无关字符的情况。
- 这道题和后面判断字符串是否可以通过某种规则变形的题目（比如比较字符出现模式的题）有相通之处，核心都是先抽象出"分组"或"模式"再做等价比较，而不是逐字符死板对比。
