# 35. 搜索插入位置

**题目描述**

给定一个排序数组和一个目标值，在数组中找到目标值，并返回其下标。如果目标值不存在于数组中，返回它将会被按顺序插入的位置。请必须使用时间复杂度为 O(log n) 的算法。

```
示例：
输入: nums = [1,3,5,6], target = 5
输出: 2
解释: 5在数组中，下标为2

输入: nums = [1,3,5,6], target = 2
输出: 1
解释: 2不在数组中，但应该插入到下标1的位置（1和3之间），插入后数组变为[1,2,3,5,6]

输入: nums = [1,3,5,6], target = 7
输出: 4
解释: 7应该插入到数组末尾，下标4
```

## 思路

题目里明确要求 O(log n) 的时间复杂度，这其实就已经把答案暗示给你了，一看到这个复杂度要求，脑子里就该立刻蹦出"二分查找"。你可以把这题看成 0704 二分查找的一个自然延伸：标准二分查找只需要回答"target 在不在数组里，在的话下标是多少"，而这题多了一个要求，就是 target 不存在的时候，还得给出一个合理的"插入位置"。

先想清楚插入位置是什么意思：如果把 target 插到你返回的那个下标处，数组还得保持升序。也就是说，这个下标左边的所有元素都得比 target 小，右边（包括它自己）的所有元素都得大于等于 target。说白了，这其实就是"第一个大于等于 target 的元素下标"，如果这个下标压根不存在（意味着 target 比所有元素都大），那就插到数组末尾去。

那怎么求这个下标呢？在标准二分查找左闭右闭的写法上稍微改一下就行了。先回顾一下二分查找的三种情况：

- `nums[mid] == target`：直接命中了，返回 `mid` 就行，这既是这个元素本身的下标，天然也就是"插入位置"，因为它已经在那了。
- `nums[mid] < target`：说明 mid 和它左边的元素都不可能是插入位置——它们都比 target 小嘛，所以收缩 `left = mid + 1`。
- `nums[mid] > target`：这时候 mid 有可能就是插入位置（target 应该插在 mid 左边或者就是 mid 这个位置），所以收缩 `right = mid - 1`，但心里得记着这个候选位置。

关键的地方在这：当循环跑完了（也就是 `left > right` 了），`left` 指针最后停的那个位置，恰好就是插入点。这一点你得好好体会一下：整个二分的过程中，`left` 一直在往右扫描，去确定"比 target 小的那部分区域的右边界再加1"在哪；`right` 一直在往左扫描，去确定"大于等于 target 的那部分区域的左边界再减1"在哪。等区间收缩空了，`left` 正好就停在"第一个大于等于 target 的位置"上，这就是插入点。

举个例子体会一下：`nums = [1,3,5,6]`，`target = 2`。第一次 `mid=1`（值是3），3比2大，所以 `right=0`；接着区间变成 `[0,0]`，`mid=0`（值是1），1比2小，所以 `left=1`；这时候 `left=1 > right=0`，循环就结束了，`left=1` 正好就是插入位置（夹在1和3之间）。

这个规律其实跟 `bisect_left` 的原理是完全一样的：`bisect_left` 返回的就是"数组里第一个大于等于 target 的下标"，正好就是这题要的答案。你要是搞懂了"二分查找收缩完之后 left 停在哪"这个问题，其实也就顺带搞懂了 `bisect_left` 底层是怎么实现的。

边界情况也说一下：如果 target 比数组里所有元素都大，那 `left` 会一路被推到数组末尾（`left = n`），这正好就是插到末尾的正确位置；反过来，如果 target 比所有元素都小，`right` 会一路被推到 -1，`left` 就停在 0，插到最前面，同样是对的。

复杂度这块就很清楚了：二分查找嘛，时间复杂度 **O(log n)**，正好满足题目要求；空间上就用了几个变量，是 **O(1)**。

## 代码

### C++

```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int left = 0, right = nums.size() - 1;  // 左闭右闭区间
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                return mid;              // 命中，直接返回下标
            } else if (nums[mid] < target) {
                left = mid + 1;          // target在右边，收缩左边界
            } else {
                right = mid - 1;         // target在左边，收缩右边界
            }
        }
        return left;  // 区间收缩为空，left即为插入位置
    }
};
```

### Python

标准库一行解（`bisect_left` 本质就是本题要求的逻辑：返回第一个大于等于 target 的下标，若target存在则返回其下标，不存在则返回应插入的位置）：

```python
from bisect import bisect_left

class Solution:
    def searchInsert(self, nums: list[int], target: int) -> int:
        return bisect_left(nums, target)  # 直接返回第一个>=target的下标
```

手写实现（面试考察点，还原 `bisect_left` 的二分查找底层逻辑）：

```python
class Solution:
    def searchInsert(self, nums: list[int], target: int) -> int:
        left, right = 0, len(nums) - 1  # 左闭右闭区间
        while left <= right:
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid              # 命中，直接返回下标
            elif nums[mid] < target:
                left = mid + 1          # target在右边，收缩左边界
            else:
                right = mid - 1         # target在左边，收缩右边界
        return left  # 区间收缩为空，left即为插入位置
```

## 总结

- 这题跟 0704 二分查找几乎是同一套代码框架，唯一的区别就是：找不到 target 的时候不返回 -1，而是返回 `left` 指针最后停留的那个位置，这个位置正好就是"第一个大于等于 target 的下标"，也就是合理的插入点。
- 想搞懂这类题，关键就是理解"二分查找收缩完之后 `left` 停在哪"——这个位置天生就满足"左边全都严格小于 target、自身以及右边全都大于等于 target"这个性质，而这恰好就是插入位置要满足的条件。
- 说白了，这题的解法本质上就是把 `bisect_left` 手写还原了一遍。如果你之前已经搞懂了 0034 题（查找左右边界）里"查找左边界"那部分的二分写法，会发现这两者的收缩逻辑几乎一模一样，都是命中或者大于 target 的时候往左收缩。
- 有个容易搞混的地方：如果你把代码写成命中之后也继续收缩（就像 0034 题查左边界那样），其实对这题一样能得到正确答案，因为 target 存在的时候它自己就是"第一个大于等于 target 的位置"；不过命中就直接返回的写法更简洁，毕竟这题不需要你去区分"是不是有多个相同的值"，只要找到一个下标就够了。
