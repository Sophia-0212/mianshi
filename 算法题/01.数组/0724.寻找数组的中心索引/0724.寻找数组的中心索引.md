# 724. 寻找数组的中心索引

**题目描述**

给你一个整数数组 `nums`，请计算数组的中心索引。数组中心索引是数组的一个下标，其左侧所有元素相加的和等于右侧所有元素相加的和。如果数组不存在中心索引，返回 -1。如果数组有多个中心索引，应返回最靠近左边的那一个。

注意：中心索引左侧或右侧不存在元素时，视为和为 0。

```
示例：
输入: nums = [1,7,3,6,5,6]
输出: 3
解释: 中心索引是3，左侧数之和 (1+7+3=11)，右侧数之和 (5+6=11)，二者相等

输入: nums = [1,2,3]
输出: -1
解释: 不存在满足条件的中心索引

输入: nums = [2,1,-1]
输出: 0
解释: 中心索引是0，左侧和为0（不存在元素），右侧数之和 (1+-1=0)
```

## 思路

暴力解法是对每个下标都单独算一次左侧和跟右侧和，再比较是不是相等，这样每个下标算一次和就要 O(n)，加起来整体就是 O(n²) 了。要优化到线性时间，关键就在于别重复计算——你想啊，每次下标往后移动一位，左侧和跟右侧和其实都能从上一步"增量更新"得到，根本不需要每次都重新遍历一遍。

这就是**前缀和**的核心思想：先花一次遍历把数组的总和 `total` 求出来，然后再遍历一次数组，同时维护一个变量 `left_sum`，表示"当前下标左边所有元素的和"。对于下标 `i` 来说：

- 左侧和，就是已经维护好的 `left_sum`（表示 `nums[0..i-1]` 的和）。
- 右侧和呢，可以用总和减去左侧和、再减去当前这个元素本身来得到：`right_sum = total - left_sum - nums[i]`。这里不需要单独再维护一个"右侧和"的变量，因为它完全可以从总和推出来，这也是前缀和技巧里很常见的一个套路——用整体减去已知的部分，剩下的就是你要的那部分。

遍历的时候依次比较 `left_sum` 和 `right_sum` 是不是相等，一旦找到满足条件的下标就立刻返回——为什么呢？因为题目要求返回最靠左的中心索引，而我们是从左到右遍历的，所以第一个命中的天然就是答案。比较完之后，把 `left_sum` 更新成 `left_sum + nums[i]`，给下一轮做准备。

这里有个挺关键的设计点：**不需要额外开一个数组去存每个位置的前缀和，用一个滚动变量 `left_sum` 就够了**，为什么呢？因为算下标 `i` 的答案时，你只关心"当前左侧和"这一个值，前面的前缀和信息，算完当前这个下标之后就没用了，所以完全可以用 O(1) 空间去代替 O(n) 空间的前缀和数组。

边界情况这里，题目特别说明了"中心索引左侧或右侧没有元素的话，和视为 0"，这一点在代码里其实是天然成立的：下标是 0 的时候，`left_sum` 一开始就是 0（还没累加任何元素呢）；下标是 `n-1` 的时候，`right_sum = total - left_sum - nums[n-1]`，如果这个位置真的是数组最后一个元素，右边确实没有元素可以求和，公式依然能正确地算出 0 来。

复杂度分析：求总和要遍历一次数组，再遍历一次数组去做比较和更新，两次都是线性扫描，时间复杂度是 **O(n)**；就用了 `total` 和 `left_sum` 这两个额外变量，空间复杂度是 **O(1)**。

## 代码

### C++

```cpp
class Solution {
public:
    int pivotIndex(vector<int>& nums) {
        int total = 0;
        for (int num : nums) {
            total += num;  // 先求出数组总和
        }

        int left_sum = 0;  // 维护当前下标左侧的累加和
        for (int i = 0; i < nums.size(); i++) {
            int right_sum = total - left_sum - nums[i];  // 右侧和 = 总和 - 左侧和 - 当前值
            if (left_sum == right_sum) {
                return i;  // 找到最靠左的中心索引，立即返回
            }
            left_sum += nums[i];  // 更新左侧和，为下一个下标做准备
        }
        return -1;  // 遍历完仍未找到，不存在中心索引
    }
};
```

### Java

```java
class Solution {
    public int pivotIndex(int[] nums) {
        int total = 0;
        for (int num : nums) {
            total += num; // 先求出数组总和
        }

        int leftSum = 0; // 维护当前下标左侧的累加和

            if (leftSum == rightSum) {
                return i; // 最靠左的中心索引
            }
            leftSum += nums[i]; // 更新左侧和
        }
        return -1; // 不存在中心索引
    }
}
```

### Python

标准库中没有直接针对"中心索引"的一行解法，但可以借助 `itertools.accumulate` 计算前缀和数组来简化逻辑（`accumulate` 是标准库提供的累加迭代器，效果等价于手写前缀和数组）：

```python
from itertools import accumulate

class Solution:
    def pivotIndex(self, nums: list[int]) -> int:
        total = sum(nums)
        left_sum = 0
        for i, num in enumerate(nums):
            if left_sum == total - left_sum - num:  # 右侧和 = 总和 - 左侧和 - 当前值
                return i
            left_sum += num
        return -1
```

（说明：这里没有强行套用 `accumulate` 构造完整前缀和数组，因为逐个比较仍需要边遍历边判断，用滚动变量 `left_sum` 已经是最简洁直接的写法，属于手写和库函数思路一致的情况。）

手写实现（面试考察点，强调用滚动变量代替前缀和数组，节省空间）：

```python
class Solution:

        total = sum(nums)  # 数组总和

                return i  # 找到最靠左的中心索引
            left_sum += nums[i]  # 更新左侧和
        return -1  # 不存在中心索引
```

## 总结

- 前缀和的核心价值就在于，把"每次都重新求和"这种重复计算，换成"维护一个滚动累加变量，边遍历边更新"，这样就能把时间复杂度从 O(n²) 降到 O(n)。
- 这题有个挺巧妙的地方，就是不需要真的去维护"右侧和"这个变量，而是直接用 `总和 - 左侧和 - 当前值` 推出来，省掉了一次独立的累加逻辑，这就是"用整体减去部分求剩余部分"这个思路的典型应用。
- 题目里说"中心索引两侧没有元素的话视为和为0"，这个特殊说明其实在滚动变量的初始值（就是0）和总和减法公式里都能自然满足，不需要额外写分支去判断。
- 前缀和这个技巧还广泛用在区间求和、子数组和为定值这些问题上，这题算是前缀和思想里最基础的形式，把它吃透了，对理解更复杂的前缀和变体（比如前缀和加哈希表去求子数组和的问题）会很有帮助。
