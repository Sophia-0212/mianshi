# 922. 按奇偶排序数组II

**题目描述**

给定一个非负整数数组 `nums`，其中一半整数是奇数，一半整数是偶数。对数组进行排序，使得当 `nums[i]` 为奇数时，`i` 也是奇数；当 `nums[i]` 为偶数时，`i` 也是偶数。返回任意满足上述条件的数组即可。

```
示例：
输入: nums = [4,2,5,7]
输出: [4,5,2,7]
解释: [4,7,2,5]、[2,5,4,7]等也是可行的答案

输入: nums = [2,3]
输出: [2,3]
```

## 思路

你想啊，题目要求的排列规律其实很直接：下标是偶数（0、2、4……）的位置必须放偶数值，下标是奇数（1、3、5……）的位置必须放奇数值。因为题目已经保证了数组里恰好一半是奇数、一半是偶数，数量上是对得上的，所以肯定能找到一种排法满足要求。

先说说最直接的暴力做法：新开一个数组，用两个指针分别扫一遍原数组，把所有偶数和所有奇数分别收集出来，再按照奇偶下标交替填进新数组，这样时间是 O(n)，但代价是要多开一个 O(n) 的数组。那如果面试官问你，能不能原地做、不开额外数组呢？这时候就得靠双指针原地交换来搞定了。

具体思路是维护两个指针：`even` 指向下一个需要填偶数值的偶数下标（从 0 开始，每次跳 2），`odd` 指向下一个需要填奇数值的奇数下标（从 1 开始，每次跳 2）。这两个指针同时往右推进，每一步都检查一下当前位置的值到底对不对：

- 如果 `nums[even]` 已经是偶数了，说明这个位置本来就没毛病，那 `even` 直接跳到下一个偶数下标（`even += 2`）就行，不用管它。
- 但如果 `nums[even]` 是奇数呢？说白了就是这个位置放错了，得找个地方把它换出去。这时候就去看 `odd` 指向的位置：如果 `nums[odd]` 恰好是偶数（同样也放错地方了，本来奇数下标该放奇数值），那就直接把 `nums[even]` 和 `nums[odd]` 换一下——你发现没有，这一次交换正好把两个错误的位置一起纠正了：偶数下标那边换来了偶数值，奇数下标那边也换来了奇数值。换完之后，`even` 和 `odd` 各自往前走一步。

换个更简单的说法来描述这个双指针的推进逻辑：只要当前偶数下标的值已经是偶数，就跳过去，让 `even` 继续前进；一旦发现偶数下标放的是奇数，就去奇数下标那边找一个值是偶数的位置来交换，换完两边都对了，指针接着往前走。

那你可能会问，为什么不用担心"找不到能交换的对象"这种情况呢？这里的关键是题目保证了奇偶数量各占一半，如果某个偶数下标上冒出来一个奇数值，那按数量守恒来算，必然在某个奇数下标上藏着一个偶数值等着被换，所以交换对象是一定存在的，不会出现死循环或者找不到对象换的尴尬情况。

这个方法说白了跟"双指针原地划分"的思路是一脉相承的，跟移动零、移除元素那种双指针模式很像，区别就是这里维护的是两个各自独立前进的指针，分别负责奇偶两条"轨道"，而不是一个快指针一个慢指针挤在同一条轨道上走。

边界情况的话：数组长度为 0，或者本来就已经完全满足条件、不需要任何交换的时候，两个指针会一直走在 `nums[even]` 是偶数的那个分支上，直接跳过所有交换，循环正常走完，返回原数组就行，不用特殊处理。

复杂度这块：`even` 和 `odd` 这两个指针加起来最多各推进 n/2 次，每次要么直接前进，要么交换完再前进，所以整体时间复杂度是 **O(n)**；空间上就用了两个指针变量和交换时的临时变量，是 **O(1)**，满足原地排序的要求。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> sortArrayByParityII(vector<int>& nums) {
        int n = nums.size();
        int odd = 1;  // 下一个需要修正的奇数下标（值应为奇数）
        for (int even = 0; even < n; even += 2) {  // even遍历所有偶数下标
            if (nums[even] % 2 != 0) {  // 偶数下标处的值是奇数，说明放错了
                // 找到一个值为偶数的奇数下标进行交换
                while (odd < n && nums[odd] % 2 != 0) {
                    odd += 2;  // 该奇数下标本身值就是奇数，合法，跳过
                }
                swap(nums[even], nums[odd]);  // 交换后两边都被纠正
            }
        }
        return nums;
    }
};
```

### Java

```java
class Solution {
    public int[] sortArrayByParityII(int[] nums) {
        int n = nums.length;
        int odd = 1; // 下一个需要修正的奇数下标
        for (int even = 0; even < n; even += 2) { // even遍历所有偶数下标
            if (nums[even] % 2 != 0) { // 偶数下标处是奇数值，放错了
                while (odd < n && nums[odd] % 2 != 0) {
                    odd += 2; // 该位置本身合法，跳过
                }
                int temp = nums[even];
                nums[even] = nums[odd];
                nums[odd] = temp; // 交换，同时修正两个位置
            }
        }
        return nums;
    }
}
```

### Python

本题没有直接对应的标准库一行原地解法（若不要求原地，可以用列表推导分别取出奇偶数再交替拼接，但这属于额外空间的做法而非库函数捷径），因此只给出双指针原地交换的手写实现：

```python
class Solution:
    def sortArrayByParityII(self, nums: list[int]) -> list[int]:
        n = len(nums)
        odd = 1  # 下一个需要修正的奇数下标
        for even in range(0, n, 2):  # even遍历所有偶数下标
            if nums[even] % 2 != 0:  # 偶数下标处是奇数值，放错了
                while odd < n and nums[odd] % 2 != 0:
                    odd += 2  # 该位置本身合法，跳过
                nums[even], nums[odd] = nums[odd], nums[even]  # 交换纠正
        return nums
```

## 总结

- 这题的双指针跟别的题不太一样，不是同向推进也不是相向而行，而是**两个指针各自负责一条"轨道"**——偶数下标轨道和奇数下标轨道，只有当某条轨道上冒出个"放错位置"的值时，才会触发跨轨道的交换，这算是双指针技巧的另一种变体玩法。
- 交换操作巧妙的地方就在于"一次交换同时纠正两个错误"：偶数下标上的奇数值和奇数下标上的偶数值正好互补，换一下两个位置就都合法了，不需要额外的中间存储，挺省事的。
- 为什么不怕换不到人？就是因为题目保证了奇偶数量各占一半，这个条件保证了交换对象必然存在，是整个算法能正确终止的前提；如果数量不对等，这套双指针策略就玩不转了。
- 跟移动零、移除元素这些双指针题比起来，这题特殊的地方就是这个"双轨道"结构，但说白了本质上还是在利用问题本身的结构性质——也就是奇偶位置的对应关系——来避免用额外空间，这是原地算法设计里挺常见的一个思路。
