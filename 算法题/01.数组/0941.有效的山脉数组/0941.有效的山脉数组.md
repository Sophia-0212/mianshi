# 941. 有效的山脉数组

**题目描述**

给定一个整数数组 `arr`，如果它是有效的山脉数组就返回 `true`，否则返回 `false`。

一个数组被称为山脉数组，需要满足以下条件：

- `arr.length >= 3`
- 存在某个下标 `i`（`0 < i < arr.length - 1`），满足：
  - `arr[0] < arr[1] < ... < arr[i-1] < arr[i]`（严格递增到 i）
  - `arr[i] > arr[i+1] > ... > arr[arr.length - 1]`（从 i 严格递减到末尾）

```
示例：
输入: arr = [2,1]
输出: false
解释: 数组长度小于3，且没有先增后减的结构

输入: arr = [0,3,2,1]
输出: true
解释: 先从0递增到3（山顶），再从3递减到1

输入: arr = [3,5,5]
输出: false
解释: 5,5相等，不满足严格递增（也不满足严格递减）
```

## 思路

这题说白了就是判断数组是不是呈现一个"单峰"的形状：一段严格上升，紧接着一段严格下降，而且上升段和下降段都不能是空的（山顶不能是数组的第一个或者最后一个元素）。

一个挺直观的方法，就是用双指针从数组两端往中间收缩：

- 用 `left` 从下标 0 开始，只要后一个元素比当前这个大，就一直往右走，模拟"爬坡"的过程，一直爬到爬不上去为止，这时候 `left` 就停在这段严格递增序列能到达的最高点。
- 用 `right` 从数组末尾开始，只要前一个元素比当前这个大，就一直往左走，模拟从另一侧"爬坡"，一直走到 `right` 停在从右往左看这段严格递增序列能到达的最高点。

那你想啊，如果整个数组真的是一个有效的山脉，这两个指针从两端各自爬到山顶之后，应该**恰好停在同一个位置**——因为山顶是唯一的最高点，不管你是从左边爬还是从右边爬，最后都会停在这一个点上。所以最后只需要判断 `left == right`，并且这个位置不能是数组的两端（不然就说明整个数组是单调的，根本没有真正的"峰"）。

那为什么这个方法是对的呢？你可以这样想：如果数组是有效山脉，设山顶下标是 `peak`，那从左边出发，`left` 会严格递增地一路爬到 `peak`（因为 `arr[peak-1] < arr[peak]`），并且在 `peak` 这个位置因为 `arr[peak] > arr[peak+1]` 而停下来；同理 `right` 从右边出发也会精确地停在 `peak`。反过来说，如果数组不是有效山脉，比如中间出现了平台（相邻元素相等），或者出现了先降后升这种情况，那两个指针爬完坡停下的位置肯定不会重合，或者会停在数组的端点上。

边界情况这里得注意几点：
1. 数组长度小于 3 的话，直接返回 `false`，为什么呢，因为山脉至少得有"上坡+山顶+下坡"这三个元素才行。
2. 山顶不能是下标 0（那就意味着一开始就在下降，没有上坡段），也不能是数组最后一个下标（意味着一直在上升，没有下坡段），所以判断条件是 `0 < peak < n - 1`。
3. 相邻元素相等的情况（比如 `[3,5,5]`）会导致爬坡指针一遇到相等元素就停下来，这样 `left` 和 `right` 就没法在真正的山顶重合，这个方法正好就间接地把这种情况判为无效了。

复杂度分析：两个指针加起来最多各遍历一次数组，整体时间复杂度是 **O(n)**，就用了两个额外的指针变量，空间复杂度是 **O(1)**。

## 代码

### C++

```cpp
class Solution {
public:
    bool validMountainArray(vector<int>& arr) {
        int n = arr.size();
        if (n < 3) return false;  // 山脉至少需要3个元素

        int left = 0;
        while (left + 1 < n && arr[left] < arr[left + 1]) {
            left++;  // 从左往右爬坡，直到无法再上升
        }

        int right = n - 1;
        while (right - 1 >= 0 && arr[right] < arr[right - 1]) {
            right--;  // 从右往左爬坡，直到无法再上升
        }

        // 两个指针必须在同一个位置汇合，且该位置不能是数组端点
        return left == right && left != 0 && right != n - 1;
    }
};
```

## 总结

- 本题的双指针不是常见的"相向查找目标值"模式，而是"从两端各自贪心爬坡到能到达的最高点"，再通过判断两个终点是否重合来验证山脉的唯一性，这是双指针思想的一种变体应用。
- 严格递增/递减的要求意味着相邻元素相等时爬坡会立即停止，这个特性天然处理了"平台"这种非法情况，不需要额外的相等判断分支。
- 容易漏掉的边界是山顶不能出现在数组两端——如果只判断 `left == right` 而不排除端点，会把单调递增或单调递减的数组误判为有效山脉。
- 这道题与"寻找数组的峰值"类问题（如山脉数组的顶峰索引）思路相通，都是利用单调性来定位极值点，但本题额外要求验证整个数组必须严格满足单峰形状，而不仅仅是找到峰值位置。
