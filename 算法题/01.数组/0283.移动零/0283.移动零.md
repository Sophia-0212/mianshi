# 283. 移动零

**题目描述**

给定一个数组 `nums`，编写一个函数将所有 `0` 移动到数组的末尾，同时保持非零元素的相对顺序。要求必须在原数组上进行操作，不能拷贝额外的数组，且尽量减少操作次数。

```
示例：
输入: nums = [0,1,0,3,12]
输出: [1,3,12,0,0]

输入: nums = [0,0,1]
输出: [1,0,0]
```

## 思路

这题你仔细想想，其实跟"移除数组中特定元素还得保持顺序"是同一类问题（对应 LeetCode 27 题移除元素）：只不过这里不是把 0 删掉，而是把非零元素往前挪、把 0 "挤"到后面去。所以这里其实可以用同一种双指针（也就是快慢指针）的套路来解决。

核心思路是这样的：用一个慢指针 `slow` 表示"下一个非零元素该放在哪个位置"，用快指针 `fast` 去遍历整个数组，负责找非零元素。

- `fast` 从头扫到尾，把数组里每一个元素都过一遍。
- 当 `nums[fast]` 不等于 0 的时候，说明找到了一个要保留的非零元素，那就把它放到 `nums[slow]` 那个位置上（如果这时候 `slow == fast`，那就是自己赋值给自己，不影响结果），然后 `slow` 往后挪一位，给下一个非零元素预留位置。
- 当 `nums[fast] == 0` 的时候，就跳过，什么都不干——`fast` 继续往前走，但 `slow` 不动，因为这个位置将来是要被后面的非零元素占掉的。

遍历完了之后，`slow` 指向的位置，就是"所有非零元素已经按原来的顺序排好"之后的下一个空位，这时候从 `slow` 一直到数组末尾的所有位置，都应该填成 0（因为原来那些位置上的值，已经被前面的非零元素覆盖掉了，或者本来就是待清空的）。

那为什么这样能保持非零元素的相对顺序呢？因为 `fast` 是严格从左往右扫的，遇到非零元素就按扫到的先后顺序依次填进 `slow` 那个位置，而 `slow` 也是单调往后走的，所以非零元素之间原来谁先谁后的关系，是不会被打乱的。

这里有个实现上挺关键的点：**填完非零元素之后，剩下的位置得清零，不能留着原来的脏数据不管**。因为整个操作是原地做的，`nums[slow]` 后面那些位置可能还残留着之前扫过的旧值（比如说原来是个非零值，但已经被复制到前面去了），这时候必须显式地把它们置成 0，不然数组末尾可能就不是纯粹的 0 了。

边界情况说一下：如果数组里压根没有 0，那 `slow` 就会跟着 `fast` 一起走到数组末尾，这时候不需要做任何清零操作，数组保持原样就行；如果数组全是 0，`slow` 会一直停在下标 0 那里，最后整个数组都会被清零，结果也是对的。

复杂度这块：整个过程只需要遍历数组两次（一次是填充非零元素，一次是清零剩下的位置），而且都是线性扫描，时间复杂度是 **O(n)**；就用了 `slow` 和 `fast` 这两个额外的指针变量，空间复杂度是 **O(1)**，满足原地操作的要求。

## 代码

### C++

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0; // slow 指向下一个非零元素应存放的位置
        for (int fast = 0; fast < nums.size(); fast++) {
            if (nums[fast] != 0) {
                nums[slow] = nums[fast]; // 把非零元素前移到slow位置
                slow++;                  // slow右移，指向下一个待填充位置
            }
        }
        // slow之后的位置全部填0
        for (int i = slow; i < nums.size(); i++) {
            nums[i] = 0;
        }
    }
};
```

### Python

本题要求原地操作且强调"减少操作次数"，标准库没有直接对应的一行原地解法（`nums.sort(key=lambda x: x == 0)` 虽然能得到正确结果，但排序的时间复杂度是 O(n log n)，不符合本题追求线性时间的初衷，因此不作为推荐解法），下面给出双指针的手写实现：

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        slow = 0  # slow 指向下一个非零元素应存放的位置
        for fast in range(len(nums)):
            if nums[fast] != 0:
                nums[slow] = nums[fast]  # 把非零元素前移到slow位置
                slow += 1                 # slow右移，指向下一个待填充位置

        for i in range(slow, len(nums)):
            nums[i] = 0  # slow之后的位置全部填0
```

## 总结

- 这题跟"移除元素"（27题）说白了是同一套双指针模板的两种用法：27题是把等于目标值的元素排除到有效区间之外，这题是把非零元素往前收拢，两者 `slow`/`fast` 往前推进的逻辑是完全一样的，只是这题收尾的时候多一步——要把尾部清零。
- 双指针能保证非零元素的相对顺序不变，这是因为 `fast` 是严格从左往右扫的，`slow` 又是单调递增地去接收非零元素，这两者往前推进的相对顺序，就保证了原来的顺序被完整保留下来了。
- 容易漏掉的一步就是清零操作——光做"把非零元素往前搬"是不够的，如果不把 `slow` 之后的位置显式置零，数组末尾可能会残留脏数据，而不是真正的 0。
- 这种"原地把数组划分成两部分（满足条件的/不满足条件的）"的双指针技巧，其实还可以推广到别的分区问题上，比如按奇偶性分区、按正负性分区之类的，本质上都是用一个慢指针去维护"已处理区间"的边界。
