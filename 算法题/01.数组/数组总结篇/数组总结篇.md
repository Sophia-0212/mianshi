# 数组总结篇

数组类算法题你想啊，看起来挺简单的，毕竟数据结构本身也没什么花样，但恰恰就是各种经典技巧的高频考察载体。所以说白了，你要理清楚"什么场景该用什么技巧"，这比单独去记住某一道题的解法要重要得多。

## 双指针法：原地删除 / 覆盖类问题

**适用场景**：需要在 O(1) 额外空间内对数组做"过滤"或者"重排"，并且允许改变元素的相对顺序，或者说题目本身要求保持相对顺序，但可以逐个覆盖来实现。

**核心模式**：这里的关键是用一个 `slow` 指针记录"下一个应该写入的位置"，再用一个 `fast` 指针负责"探测"当前这个元素到底需不需要保留。`fast` 始终比 `slow` 走得快或者一样快，这两者步调不一致，正是这类问题的关键——`slow` 只有遇到"合法元素"的时候才前进并写入，而 `fast` 呢，每一步都在往前走。

**代表题目**：`0027.移除元素` 用快慢指针把不等于 `val` 的元素覆盖到数组前部；`0977.有序数组的平方` 则是双指针的另一种变体玩法——从两端往中间收缩，而不是同向前进，为什么呢？因为这题的极值必然出现在边界，这是要先分析出题目的单调性质，才能设计出来的指针方向。

```
// 同向双指针（覆盖类）伪代码
slow = 0
for fast in range(n):
    if 满足保留条件(nums[fast]):
        nums[slow] = nums[fast]
        slow += 1
return slow
```

## 滑动窗口：连续子数组 / 子串问题

**适用场景**：需要在数组或字符串里找到满足某个条件（和、计数、字符种类等等）的最优**连续**区间，而且这个条件随着窗口边界移动是有单调性的，也就是说，窗口变大条件变强还是变弱，是可以预测的。

**核心模式**：维护一个 `[left, right]` 区间，`right` 负责扩张窗口去纳入新元素，一旦当前窗口满足条件了，就用 `left` 去收缩窗口，看能不能找到更优的解，更短或者更少，一直收缩到窗口不再满足条件为止。这两个指针都只往一个方向移动，整体上是均摊 O(n)，虽然代码写出来经常是"外层 for、内层 while"这种嵌套的形式，但你别被这个表象骗了，本质还是线性扫描。

**代表题目**：`0209.长度最小的子数组` 是滑动窗口最标准的应用——说白了就是利用数组元素全是正整数这个条件，保证窗口和会随着右边界扩张单调增大、随着左边界收缩单调减小，从而可以用线性扫描找到最短的满足条件的子数组。

```
// 滑动窗口伪代码
left = 0
window_state = 初始值
for right in range(n):
    更新 window_state 纳入 nums[right]
    while window_state 满足条件:
        更新答案(right - left + 1)
        更新 window_state 移出 nums[left]
        left += 1
```

## 模拟法：矩阵 / 循环边界类问题

**适用场景**：题目描述的是一个具体的、要按规则一步步执行的过程，比如按方向去遍历矩阵，这种题说白了没什么捷径算法可用，核心难点就在于把这个过程的规则转化成清晰、不遗漏也不重复的代码逻辑。

**核心模式**：你想啊，把复杂的整体过程拆解成若干个"重复的子过程"，比如螺旋矩阵里的"一圈"，用一组边界变量去描述当前子过程的范围，每完成一个子过程就把边界收缩一下，进入下一轮。这里的关键是善用"循环不变量"这个思想，比如统一约定每条边不包含终点，这样能让四个方向的处理代码结构高度一致，减少很多特判分支。

**代表题目**：`0059.螺旋矩阵II` 用 `top`/`bottom`/`left`/`right` 四个边界变量去模拟顺时针螺旋填充的过程，每填完一条边就收缩对应的边界。

## 二分查找：有序数组查找类问题

**适用场景**：数组本身有序，或者能转化成有序结构上的判定问题，而且要查找某个目标值、或者目标值的边界位置。核心价值就是把 O(n) 的线性查找降到 O(log n)。

**核心模式**：维护一个区间 `[left, right]`，每次取中点跟目标比较一下，根据比较的结果**丢弃一半**区间，这样区间就是指数级缩小的。这里的关键是要明确区间的开闭约定，这个系列里统一采用左闭右闭，并且保证循环条件、`mid` 的计算方式、边界更新方式这三者是自洽的，不然很容易写出死循环或者漏边界的 bug。

**代表题目**：`0704.二分查找` 是最基础的应用，后面遇到"有序数组求某个条件的边界"这类题（比如平方根、旋转数组查找等等）都是二分查找的变体。

## 技巧串联

| 题目 | 核心技巧 | 关键前提条件 |
|------|----------|--------------|
| 0704.二分查找 | 二分查找 | 数组有序 |
| 0027.移除元素 | 双指针（同向覆盖） | 允许改变元素顺序，O(1) 额外空间 |
| 0977.有序数组的平方 | 双指针（两端收缩） | 数组有序，平方是单调放大绝对值的操作 |
| 0209.长度最小的子数组 | 滑动窗口 | 元素全为正数，窗口和随边界单调变化 |
| 0059.螺旋矩阵II | 模拟 + 循环不变量 | 无特殊数学性质，靠边界管理保证正确性 |

从这张表其实能看出一条挺清晰的脉络：**能不能用比 O(n²) 更优的技巧，往往取决于这道题是不是藏着某种单调性或者有序性**。你想啊，二分查找利用的是"整体有序"，滑动窗口利用的是"窗口指标单调变化"，双指针两端收缩利用的是"极值在边界"，而模拟法呢，说白了就是在没有额外数学性质可以利用的时候，退回到"老老实实按规则执行，但要把执行过程管理清楚"这个兜底方案。所以做题的时候第一步永远是先问自己：这道题有没有可以利用的单调性、有序性？如果有，那大概率能找到比暴力解法更优的双指针、滑动窗口或者二分方案；如果没有，那就诚实地走模拟或者穷举，重点转向怎么把边界和状态管理写对。
