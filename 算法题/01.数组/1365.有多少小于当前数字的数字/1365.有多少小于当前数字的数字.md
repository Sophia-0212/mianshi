# 1365. 有多少小于当前数字的数字

**题目描述**

给你一个数组 `nums`，对于其中每个元素 `nums[i]`，请你统计数组中比它小的所有数字的数目。

```
示例：
输入: nums = [8,1,2,2,3]
输出: [4,0,1,1,3]
解释:
对于 nums[0]=8，存在4个比它小的数（1,2,2,3）
对于 nums[1]=1，不存在比它小的数
对于 nums[2]=2，存在1个比它小的数（1）
对于 nums[3]=2，存在1个比它小的数（1）
对于 nums[4]=3，存在3个比它小的数（1,2,2）
```

## 思路

最直接的想法你肯定能想到：对每个元素都遍历一次数组，去统计比它小的数有多少个，这样时间复杂度是 O(n²)。但数组一大，这个方法就会很慢，所以得找个更高效的做法。

这里的关键观察是：**"比某个值小的数字个数"这件事，其实只跟这个值本身有关，跟它在原数组里的位置没关系**。也就是说，如果两个位置上的值是一样的，它们对应的答案也一定是一样的。这就提示我们，可以先把值排序一下，对每个不同的值只算一次答案，再把结果映射回原数组。

具体怎么做呢，分三步：

1. 先复制一份原数组，排个序，得到一个升序序列。排序之后，你会发现，任意一个值在这个序列里第一次出现的下标，恰好就等于"比它小的数字的个数"。为什么呢？因为排序之后，下标之前的所有元素都严格小于（或者等于）当前这个值，而由于是第一次出现，前面那些元素必然都是严格小于它的。
2. 用一个哈希表去记录"值 -> 比它小的数字个数"。遍历排序后的数组，只在某个值第一次出现的时候，把它的下标存进哈希表——后面重复出现的相同值就不用再更新了，因为答案不会变。
3. 再遍历一次原数组，对每个元素直接去查哈希表拿答案，组装成结果数组。

那为什么"第一次出现的下标"就是答案呢？举个例子，`[1,2,2,3]`，排序之后 2 第一次出现在下标 1 的位置，这时候下标 0 那个位置是 1，唯一比 2 小的数就是这个 1，个数正好是 1，跟下标是对上的。那你想，如果不加"只在第一次出现时记录"这个限制，直接对每个下标都去覆盖哈希表，那最后一次出现的那个 2（下标 2）就会把值覆盖成 2，这就错了——第二个 2 前面比它小的数目其实还是 1，不是 2。所以必须保证哈希表存的是每个值*第一次*出现时的那个下标。

边界情况方面，数组里只有一个元素，或者所有元素都相同的时候，每个位置的答案都是 0，这个逻辑在排序去重的过程里天然就能成立，不用额外特判。

复杂度分析：排序的时间复杂度是 O(n log n)，两次线性遍历各是 O(n)，所以整体时间复杂度是 **O(n log n)**，比暴力法的 O(n²) 要好。空间复杂度上，除了要返回的结果数组，还需要一份排序的副本和一个哈希表，是 **O(n)**。

顺带说一句，也可以用计数排序的思路做到 O(n + k)（k 是数值范围），也就是开一个长度为最大值加1的计数数组，统计每个值出现的次数，再做一遍前缀和，前缀和数组里下标 v-1 处的值就是"比 v 小的数字个数"。不过这题的数值范围通常不大，排序法也更通用，所以下面主要还是以排序加哈希的写法为主。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> smallerNumbersThanCurrent(vector<int>& nums) {
        vector<int> sorted_nums = nums;                 // 复制一份用于排序，不破坏原数组
        sort(sorted_nums.begin(), sorted_nums.end());    // 升序排序

        unordered_map<int, int> value_to_count;          // 值 -> 比它小的数字个数
        for (int i = 0; i < sorted_nums.size(); i++) {
            // 只在该值第一次出现时记录下标（即为比它小的数字个数）
            if (value_to_count.find(sorted_nums[i]) == value_to_count.end()) {
                value_to_count[sorted_nums[i]] = i;
            }
        }

        vector<int> result;
        result.reserve(nums.size());
        for (int num : nums) {
            result.push_back(value_to_count[num]);       // 直接查表得到答案
        }
        return result;
    }
};
```

### Java

```java
class Solution {
    public int[] smallerNumbersThanCurrent(int[] nums) {
        int[] sortedNums = nums.clone();       // 复制一份用于排序，不破坏原数组
        Arrays.sort(sortedNums);               // 升序排序

        Map<Integer, Integer> valueToCount = new HashMap<>(); // 值 -> 比它小的数字个数
        for (int i = 0; i < sortedNums.length; i++) {
            // 只在该值第一次出现时记录下标
            valueToCount.putIfAbsent(sortedNums[i], i);
        }

        int[] result = new int[nums.length];
        for (int i = 0; i < nums.length; i++) {
            result[i] = valueToCount.get(nums[i]); // 直接查表得到答案
        }
        return result;
    }
}
```

### Python

标准库辅助解（结合 `sorted` 排序 + 字典去重记录首次下标，`sorted` 底层是 Timsort，稳定且时间复杂度 O(n log n)）：

```python
class Solution:
    def smallerNumbersThanCurrent(self, nums: list[int]) -> list[int]:
        sorted_nums = sorted(nums)  # 升序排序，得到一份新数组
        value_to_count = {}
        for i, v in enumerate(sorted_nums):
            # setdefault 保证只在第一次出现时写入下标
            value_to_count.setdefault(v, i)
        return [value_to_count[num] for num in nums]  # 查表组装结果
```

手写实现（面试考察点，不依赖内置排序细节，强调"首次下标即答案"这一核心洞察）：

```python
class Solution:
    def smallerNumbersThanCurrent(self, nums: list[int]) -> list[int]:
        sorted_nums = sorted(nums)          # 排序后相同值相邻，且下标连续
        value_to_count = {}                 # 记录每个值第一次出现的下标
        for i in range(len(sorted_nums)):
            v = sorted_nums[i]
            if v not in value_to_count:      # 只记录第一次出现
                value_to_count[v] = i

        result = []
        for num in nums:                    # 按原数组顺序输出答案
            result.append(value_to_count[num])
        return result
```

### Go

```go
import "sort"

func smallerNumbersThanCurrent(nums []int) []int {
    sortedNums := make([]int, len(nums))
    copy(sortedNums, nums)          // 复制一份用于排序，不破坏原数组
    sort.Ints(sortedNums)           // 升序排序

    valueToCount := make(map[int]int) // 值 -> 比它小的数字个数
    for i, v := range sortedNums {
        if _, ok := valueToCount[v]; !ok {
            valueToCount[v] = i // 只在第一次出现时记录下标
        }
    }

    result := make([]int, len(nums))
    for i, num := range nums {
        result[i] = valueToCount[num] // 直接查表得到答案
    }
    return result
}
```

## 总结

- 核心技巧就是把"对每个元素单独统计"这件事，转化成"对每个不同的值统计一次"，利用排序之后下标跟"比它小的数字个数"天然对应的关系，把 O(n²) 优化到了 O(n log n)。
- 哈希表在这里的作用不是简单计数，而是记录**去重后每个值第一次出现的位置**，这个细节容易出错——如果不加"仅首次记录"这个判断，重复值就会被后面的下标覆盖掉，导致结果出错。
- 这题跟"计数排序 + 前缀和"的思路本质上是相通的：如果数值范围比较小，可以直接用计数数组做前缀和，省掉排序的 O(n log n) 开销，做到线性时间。
- 容易踩的坑：别在排序之后直接拿元素值当下标去输出，必须通过哈希表把排序的结果映射回原数组的每个位置，顺序不能搞乱。
