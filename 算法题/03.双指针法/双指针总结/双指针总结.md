# 双指针法总结

## 核心思想

双指针法的本质，说白了就是用两个（或多个）移动的下标变量，替代原本需要嵌套循环才能完成的遍历，把 O(n²) 的暴力解法优化到 O(n)。

暴力解法之所以是 O(n²)，往往是因为对数组/链表中的每一个元素，都要再用一层循环去"重新扫描"一遍其余元素，去找满足条件的另一个位置。而双指针的关键洞察在于：只要这个问题具备某种单调性或方向性（比如数组有序、链表按顺序遍历），内层这次"重新扫描"其实不需要从头开始，可以利用上一轮已经扫描过的信息，让两个指针始终朝着让搜索空间变小的方向移动，各自只走一遍，整体就退化成了线性扫描。

换句话说，双指针不是"两个 for 循环"，而是"一个 while 循环里维护两个状态"，指针的每一步移动都在收缩问题规模，而且从不回退。这也是它能把复杂度降到 O(n) 的根本原因。

根据两个指针的运动方式和应用场景，双指针大致可以分成几种典型模式。

## 一、快慢指针（原地删除/覆盖类）

**特征**：一个慢指针 `slow` 指向"已处理好的结果区"的末尾，一个快指针 `fast` 负责往前探测原数组，遇到符合条件的元素就"搬"到慢指针的位置上，随后慢指针前进一步。两个指针同向移动，慢指针的速度始终不超过快指针。

这种模式常用于要求 O(1) 空间、原地修改数组的场景，本质是把"删除/去重"转化成了"覆盖"，避免了真正的删除操作（数组删除是 O(n) 的搬移开销）。

比如移除元素（0027，移除数组中所有等于 val 的元素）：

```
slow = 0
for fast in range(n):
    if nums[fast] != val:
        nums[slow] = nums[fast]
        slow += 1
return slow  # 新数组长度
```

`fast` 遍历一遍原数组，`slow` 只在遇到"该保留"的元素时才前进并写入，最终 `slow` 就是新数组的长度。

移动零（把所有 0 移到数组末尾，非零元素保持相对顺序）思路完全一样：`slow` 记录"下一个非零元素应该放的位置"，`fast` 找到非零元素就交换/赋值给 `slow` 位置。这类问题的共同点是：结果数组的长度小于等于原数组，而且可以在一次遍历中"边读边写"。

## 二、对撞指针（从两端向中间收缩）

**特征**：一个指针 `left` 从数组头部出发，一个指针 `right` 从数组尾部出发，两者相向而行，每一步根据当前的比较结果决定移动哪一个指针，一直到两者相遇或交错为止。

这种模式高度依赖**数组有序**这个前提，因为"移动哪个指针"的决策依据，就是有序性带来的单调关系。

比如有序数组的平方（0977）：数组已经按升序排列，但平方之后原本的负数区间会变大，最大的平方值只可能出现在原数组的最左端或最右端。于是从两端向中间比较 `nums[left]²` 和 `nums[right]²`，谁大就填入结果数组的末尾，对应指针内移：

```
left, right = 0, n - 1
i = n - 1  # 结果数组从后往前填
while left <= right:
    if nums[left]**2 > nums[right]**2:
        result[i] = nums[left]**2; left += 1
    else:
        result[i] = nums[right]**2; right -= 1
    i -= 1
```

反转字符串（0344）更直接：`left`、`right` 各自向中间靠拢，交换两端字符，一直到相遇，天然就是 O(1) 空间。

三数之和/四数之和的内层双指针也是对撞指针的典型应用：先固定最外层一个数（或两个数），排序后在剩余区间用对撞指针查找两数之和等于目标值——这正是把"两数之和"从哈希法换成双指针的关键前提（数组已排序，可以用大小关系判断移动方向）。

## 三、滑动窗口（双指针维护一个区间）

**特征**：`left` 和 `right` 两个指针共同框定一个连续区间 `[left, right]`，`right` 负责扩张窗口纳入新元素，`left` 负责在窗口满足/超出某个条件时收缩窗口，两者都只往右移动，从不回退，所以整体是 O(n) 的。

比如长度最小的子数组（0209，找和 ≥ target 的最短连续子数组）：

```
left = 0; sum = 0; ans = 无穷大
for right in range(n):
    sum += nums[right]          # 窗口右边界扩张
    while sum >= target:        # 窗口满足条件，尝试收缩左边界
        ans = min(ans, right - left + 1)
        sum -= nums[left]
        left += 1
```

`right` 遍历一遍数组是 O(n)，`left` 在整个过程中总的移动次数也不会超过 n 次（不会回退），所以总复杂度还是 O(n)，而不是看起来的"内外层循环" O(n²)。滑动窗口本质上就是对撞指针思想在"求最优连续区间"这类问题上的变形。

## 四、快慢指针判环/找中点（链表场景）

**特征**：两个指针从同一起点出发，`slow` 每次走一步，`fast` 每次走两步，速度不同就导致两者在环形结构中必然相遇，或者 `fast` 先到达链表末尾从而定位中点。

环形链表 II（0142，判断链表是否有环，并找出环的入口）：`slow`、`fast` 同速比 1:2 前进，如果有环必然会在环内相遇；相遇后把其中一个指针重置到头节点，两指针再以相同速度前进，第二次相遇的点就是环入口（这是基于环长与起点距离的数学关系推导出的技巧）。

删除链表的倒数第 N 个节点（0019）：用一个虚拟头节点加快慢指针，`fast` 先走 N 步，之后 `slow`、`fast` 同速前进，`fast` 到达末尾时 `slow` 正好指向待删除节点的前一个节点——这是利用固定步差，把"倒数第 N 个"转化成"正数第几个"的问题，避免了先遍历一遍求长度再二次遍历定位。

## 五、同向双指针（链表相交场景）

**特征**：两个指针分别从两条不同的链表头部出发，同速前进，当某个指针走到链表末尾时，让它跳到另一条链表的头部继续走，两个指针最终会在相交点相遇（或者都为 null 时同时到达终点）。

链表相交（面试题 02.07）：设链表 A 长度为 a、链表 B 长度为 b、公共部分长度为 c。指针 pA 走完 A 后接着走 B，指针 pB 走完 B 后接着走 A，两者走的总路程都是 `a + b`，所以会在相交点同时到达（不相交的话就同时到达 null）。这种"接力"式的同向双指针巧妙地用路程相等替代了先求链表长度、再对齐起点的两次遍历。

## 如何判断该用双指针

遇到题目可以从以下几个特征入手判断是否适合双指针：

- **数据本身有序，或可以先排序**：对撞指针、滑动窗口都依赖"移动某个指针一定不会错过更优解"这个单调性保证，这通常来自有序性。
- **要求原地操作、O(1) 额外空间**：快慢指针的"覆盖式"写入天然满足这个约束，这是哈希法（需要额外的 O(n) 空间）做不到的。
- **求连续子数组/子串的最优区间**：滑动窗口是首选，尤其是暴力解法是"枚举左右边界"的 O(n²) 时。
- **链表结构，无法随机访问（不能用下标直接跳转）**：只能靠指针一步步移动模拟，快慢指针（判环/找中点/倒数第 N 个）、同向接力指针都是应对链表这一限制的标准手法。
- **需要在有序区间里查找一对/两对满足和/差条件的元素**：对撞指针从两端收缩，一次遍历就能覆盖所有可能组合，不需要嵌套枚举。

## 双指针 vs 哈希法

两者都能把某些 O(n²) 的暴力枚举优化到 O(n)，但适用的前提不一样，选择的关键在于数据是否有序、以及空间复杂度的要求。

**两数之和**用哈希法更优：数组无序，而且题目通常要求返回下标而不是直接排序破坏原始顺序信息；哈希表能在 O(1) 内完成"是否存在 target - nums[i]"的查找，一次遍历就够了，不需要排序那 O(n log n) 的开销。

**三数之和/四数之和**用双指针更优：先排序（一次性 O(n log n) 的代价），之后固定一个数，剩余两个数用对撞指针在有序区间里查找，可以在查找过程中自然地跳过重复元素来去重；如果用哈希法，由于是三个数或更多的组合，去重逻辑会变得很复杂，还需要额外的空间存哈希表，而且哈希法本身也不具备"跳过重复"的顺序感知能力。

一般规律是这样的：**当问题不涉及严格顺序、只需要快速判断"是否存在/是否配对"时，哈希法更直接**，用空间换时间，一次遍历搞定，代价是 O(n) 的额外空间；**当问题可以排序（或者数据本身就有序），并且需要控制空间复杂度为 O(1)，或者需要处理多元组合去重时，双指针更优**，用有序性代替额外的存储空间，代价是可能需要先排序。此外，滑动窗口类问题（求最优连续区间）几乎是双指针的专属场景，哈希法在这类问题上通常没法直接给出线性解法。
