# 0347. 前K个高频元素

**题目描述**

给定一个整数数组 `nums` 和一个整数 `k`，返回其中出现频率前 `k` 高的元素。可以按任意顺序返回答案。

```
示例：
输入: nums = [1,1,1,2,2,3], k = 2
输出: [1,2]
解释: 元素1出现3次，元素2出现2次，元素3出现1次，频率最高的2个是1和2
```

要求：答案唯一确定（假设频率相同时任意返回其中一个都算正确）。

## 思路

这道题咱们可以拆成两个子问题来看：**统计每个元素的出现频率**，还有**从频率信息里找出前 k 大**。

第一步很简单，就是用哈希表统计频率。遍历一遍数组，用哈希表记录每个元素出现的次数，这一步是 O(n)，没什么技巧性，属于基本操作。

第二步才是这道题真正的核心：从频率表里找前 K 高。你可能第一反应是把所有元素按频率排个序，取前 k 个不就行了？但问题是排序的复杂度是 O(m log m)（这里 m 是不同元素的个数），如果 m 很大而 k 很小，这样做就相当浪费了大量排序工作——说白了，咱们并不需要知道所有元素的完整顺序，只需要知道"谁是前 k 大"就够了。

那这里的关键是**为什么用小顶堆而不是大顶堆**，这也是本题最容易想错的地方。很多人第一反应都是"要找最大的 k 个，那肯定得用大顶堆吧"，但其实更优的做法恰恰是用**小顶堆**。为什么呢？我来解释一下：

咱们维护一个大小固定为 k 的小顶堆，堆顶始终是堆中**最小**的那个元素。遍历到新元素的时候：
- 如果堆的大小还没到 k，那直接把新元素放进堆里就行。
- 如果堆已经满了，也就是大小等于 k 了，这时候就拿新元素的频率跟堆顶（也就是当前堆中最小的）比一比：要是新元素频率更大，说明堆顶这个元素已经不够格留在"前 k 大"里了，那就把堆顶弹出去，让新元素入堆；要是新元素频率不比堆顶大，说明它连堆里最小的都比不过，那就直接丢掉，不用入堆了。

你想啊，这样做的效果是什么？堆里始终维护着"目前见过的、频率最大的 k 个元素"，而堆顶（也就是最小值）恰好就是这 k 个里最容易被淘汰的那个。用它去跟新元素比较，就能用 O(log k) 的代价决定新元素是否应该取代堆里最弱的那一个。

那如果反过来用大顶堆维护所有 m 个元素会怎样呢？堆顶是最大值，虽然能很快知道当前最大的是谁，但要拿到"前 k 个"仍然得弹出 k 次，而且如果堆里存了所有 m 个元素，堆的大小就是 O(m) 而不是 O(k) 了。当 m 远大于 k 的时候，小顶堆的方式明显更省时间和空间——因为小顶堆的大小始终被限制在 k，每次操作都是 O(log k)，而不是 O(log m)。

**复杂度分析**：哈希统计是 O(n)；小顶堆维护过程中，每个不同元素最多做一次 O(log k) 的堆操作，加起来是 O(m log k)（m 是不同元素个数，m <= n）；总体时间复杂度就是 O(n + m log k)，空间复杂度 O(m + k)。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> freq;  // 哈希统计频率
        for (int num : nums) {
            freq[num]++;
        }

        // 小顶堆：pair<频率, 元素值>，按频率比较，堆顶是频率最小的
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>> minHeap;

        for (auto& [num, count] : freq) {
            minHeap.push({count, num});
            if (minHeap.size() > k) {
                minHeap.pop();  // 堆内超过k个，弹出频率最小的（不够格留在前k）
            }
        }

        vector<int> result;
        while (!minHeap.empty()) {
            result.push_back(minHeap.top().second);
            minHeap.pop();
        }
        return result;
    }
};
```

### Java

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();  // 哈希统计频率
        for (int num : nums) {
            freq.put(num, freq.getOrDefault(num, 0) + 1);
        }

        // 小顶堆：按频率升序排列，堆顶是频率最小的元素
        PriorityQueue<int[]> minHeap = new PriorityQueue<>((a, b) -> a[1] - b[1]);

        for (Map.Entry<Integer, Integer> entry : freq.entrySet()) {
            minHeap.offer(new int[]{entry.getKey(), entry.getValue()});
            if (minHeap.size() > k) {
                minHeap.poll();  // 堆内超过k个，弹出频率最小的
            }
        }

        int[] result = new int[k];
        for (int i = 0; i < k; i++) {
            result[i] = minHeap.poll()[0];
        }
        return result;
    }
}
```

### Python

标准库一行解：`collections.Counter.most_common(k)` 底层同样是用堆（`heapq.nlargest`）实现的，直接返回前 k 高频元素。

```python
from collections import Counter

class Solution:
    def topKFrequent(self, nums: list[int], k: int) -> list[int]:
        count = Counter(nums)  # 统计频率
        return [num for num, _ in count.most_common(k)]  # 库函数直接取前k高频
```

手写实现（面试考察点，用 `heapq` 手动维护小顶堆还原底层原理）：

```python
import heapq
from collections import Counter

class Solution:
    def topKFrequent(self, nums: list[int], k: int) -> list[int]:
        freq = Counter(nums)  # 哈希统计频率
        min_heap = []  # heapq 默认就是小顶堆，堆顶是最小元素

        for num, cnt in freq.items():
            heapq.heappush(min_heap, (cnt, num))  # 按 (频率, 元素值) 入堆，堆顶频率最小
            if len(min_heap) > k:
                heapq.heappop(min_heap)  # 堆内超过k个，弹出频率最小的

        return [num for _, num in min_heap]  # 堆中剩余的k个即为答案
```

### Go

Go 没有内置堆，需要实现 `container/heap` 接口的 `Len`/`Less`/`Swap`/`Push`/`Pop` 方法来自定义小顶堆。

```go
import "container/heap"

// 定义 (频率, 元素值) 对组成的小顶堆
type pair struct {
    freq int
    num  int
}
type minHeap []pair

func (h minHeap) Len() int            { return len(h) }
func (h minHeap) Less(i, j int) bool  { return h[i].freq < h[j].freq } // 频率小的排前面，堆顶最小
func (h minHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x interface{}) { *h = append(*h, x.(pair)) }
func (h *minHeap) Pop() interface{} {
    old := *h
    n := len(old)
    item := old[n-1]
    *h = old[:n-1]
    return item
}

func topKFrequent(nums []int, k int) []int {
    freq := make(map[int]int) // 哈希统计频率
    for _, num := range nums {
        freq[num]++
    }

    h := &minHeap{}
    heap.Init(h)
    for num, cnt := range freq {
        heap.Push(h, pair{freq: cnt, num: num})
        if h.Len() > k {
            heap.Pop(h) // 堆内超过k个，弹出频率最小的
        }
    }

    result := make([]int, 0, k)
    for _, p := range *h {
        result = append(result, p.num)
    }
    return result
}
```

## 总结

- 找前 K 大问题有个通用套路，就是"用大小固定为 k 的堆，逐个元素跟堆顶比较，决定是否替换"，堆的大小始终维持在 k，而不是把所有元素都塞进堆里再排序，这个思路一定要记牢。
- 为什么用小顶堆而不是大顶堆呢？说白了就是因为堆顶要作为"当前 k 个候选里最容易被淘汰的那个"，这样才方便用一次比较就决定新元素能不能挤进前 k；这个"堆顶是最不合格的候选"正好对应小顶堆堆顶是最小值这个性质，两者是对上的。
- 复杂度上小顶堆方案是 O(n + m log k)，比对所有 m 个元素排序的 O(m log m) 更优，尤其是当 k 远小于 m 的时候，优势特别明显。
- Python 里 `Counter.most_common(k)` 是个很方便的库函数一行解，实际写代码时直接用挺好；但面试中通常会要求你手写 `heapq` 版本，理解"为什么是小顶堆"才是这道题真正考察的点。
