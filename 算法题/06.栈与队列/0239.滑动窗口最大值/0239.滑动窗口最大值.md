# 0239. 滑动窗口最大值

**题目描述**

给定一个整数数组 `nums` 和一个窗口大小 `k`，窗口从数组最左侧开始，每次向右滑动一位，直到到达数组最右侧。返回每次窗口滑动后窗口中的最大值。

```
示例：
输入: nums = [1,3,-1,-3,5,3,6,7], k = 3
输出: [3,3,5,5,6,7]
解释:
窗口位置                最大值
---------------        -----
[1  3  -1] -3  5  3  6  7       3
 1 [3  -1  -3] 5  3  6  7       3
 1  3 [-1  -3  5] 3  6  7       5
 1  3  -1 [-3  5  3] 6  7       5
 1  3  -1  -3 [5  3  6] 7       6
 1  3  -1  -3  5 [3  6  7]      7
```

要求：`1 <= k <= nums.length`，返回长度为 `n - k + 1` 的结果数组。

## 思路

先说说暴力解法为什么不行。你想啊，最直接的想法就是每次窗口滑动的时候，都把窗口内的 k 个元素遍历一遍找最大值，这样时间复杂度是 O(n*k)。但问题是，当 n 和 k 都比较大的时候（比如 n=10^5），这个复杂度就直接超时了，所以肯定得想个更高效的办法。

那核心思路是什么呢？就是用**单调队列（Monotonic Deque）**。这里说的"队列"其实是双端队列（deque），因为咱们需要同时支持从队尾插入删除、还要从队头删除。单调队列维护的可不是窗口里的所有元素，而是"未来仍有可能成为窗口最大值的候选元素"，并且要保持队列内元素**单调递减**，也就是队头永远是最大值。

那为什么可以只维护候选元素，而不是把窗口里所有元素都存下来呢？这里的关键是：假设队列里有两个元素 A 和 B，A 在 B 的左边，说明 A 更早进入窗口。如果 A <= B，那么 A 就永远不可能成为未来窗口的最大值了——为什么呢？因为只要 B 还在窗口内，B 一定比 A 大；一旦 B 滑出窗口，A 也必然已经滑出窗口了，因为 A 比 B 更早进入，肯定更早滑出。所以说白了，A 一旦遇到比它大或者相等的 B，就可以直接被淘汰掉，以后再也不用管它了。这正是单调队列能把复杂度降下来的关键：每个元素最多被比较、淘汰一次。

维护单调队列要做两个操作，我一个一个说：

1. 第一个操作是**新元素入队前，先从队尾淘汰**。当新元素 `nums[i]` 要入队的时候，只要队尾元素小于 `nums[i]`（这里注意一下，不是小于等于，队列里存的是下标，理论上允许存相等值的下标，因为相等的旧元素可能因为位置更靠后而先滑出窗口——不过更常见、也更简洁的写法是严格小于就弹出，等于的时候也弹出同样是对的，只要保证队列整体是非严格递减就行），就不断把队尾弹出去。为什么要弹？因为这些队尾元素比新元素小，而且比新元素更早进入窗口，早晚会更早滑出窗口，或者干脆被新元素比下去，已经没有存在的意义了。弹完之后再把新元素的下标压进队尾。这一步就保证了队列从队头到队尾是单调递减的。

2. 第二个操作是**窗口滑动的时候，从队头淘汰滑出窗口的元素**。队列里存的是下标，不是值本身，为什么要存下标呢？因为要判断这个元素是否还在窗口范围内，就必须知道它的位置。所以每次窗口右移之后，都要检查一下队头的下标是不是已经小于窗口左边界了，如果是，说明这个下标对应的元素已经滑出窗口了，就把队头弹出去。

3. 最后一步就是**取窗口最大值**。维护好单调队列之后，**队头元素永远就是当前窗口的最大值**。这是因为队列单调递减，队头肯定最大；又因为队头一定在窗口范围内（滑出窗口的已经在第二步被淘汰掉了），所以队头就是答案，直接取就行。

那为什么要用双端队列而不是普通队列呢？很简单，普通队列只能从队头出、队尾进，但咱们这里需要"队尾也能删除"（就是第一步里淘汰队尾小元素这个操作），所以必须用支持两端操作的双端队列。

把整个流程串起来说一下：遍历数组，对每个新元素 `nums[i]`，做三件事：
1. 先做队尾淘汰，维护好单调性，再把 `i` 压入队尾。
2. 检查队头是不是滑出了当前窗口，也就是判断 `队头下标 <= i - k` 是否成立，如果是就弹出。
3. 当 `i >= k - 1` 的时候，说明窗口已经形成了（也就是已经有 k 个元素进入过窗口），这时候就记录队头对应的值，作为这一位置的窗口最大值。

咱们拿示例 `nums = [1,3,-1,-3,5,3,6,7], k=3` 走一遍看看（队列存下标，括号里标注对应值）：

- `i=0`，值1：队空，直接入队。队列：`[0(1)]`
- `i=1`，值3：队尾 `0(1)` 小于 3，弹出；队列变空，入队 `1`。队列：`[1(3)]`
- `i=2`，值-1：队尾 `1(3)` 不小于 -1，不弹出，直接入队 `2`。队列：`[1(3), 2(-1)]`。此时 `i=2=k-1`，窗口形成，队头是 `1(3)`，最大值为 **3**。
- `i=3`，值-3：队尾 `2(-1)` 不小于 -3，不弹出，入队 `3`。队列：`[1(3), 2(-1), 3(-3)]`。检查队头 `1` 是否 `<= i-k = 0`？不满足，队头有效。最大值为 **3**。
- `i=4`，值5：队尾 `3(-3)` 小于5弹出，`2(-1)` 小于5弹出，`1(3)` 小于5弹出，队列空，入队 `4`。队列：`[4(5)]`。检查队头 `<= i-k=1`？不满足。最大值为 **5**。
- `i=5`，值3：队尾 `4(5)` 不小于3，不弹出，入队 `5`。队列：`[4(5), 5(3)]`。检查队头 `<= i-k=2`？不满足。最大值为 **5**。
- `i=6`，值6：队尾 `5(3)` 小于6弹出，`4(5)` 小于6弹出，队空，入队 `6`。队列：`[6(6)]`。检查队头 `<= i-k=3`？不满足。最大值为 **6**。
- `i=7`，值7：队尾 `6(6)` 小于7弹出，入队 `7`。队列：`[7(7)]`。检查队头 `<= i-k=4`？不满足。最大值为 **7**。

走完一遍下来，最终结果就是 `[3,3,5,5,6,7]`，跟预期一致。

**复杂度分析**：时间复杂度是 O(n)。虽然看起来里面有个"内层 while 循环弹出"，好像会拖慢速度，但其实每个元素这一生最多只会被压入队列一次、弹出队列一次，所以总的弹出次数不会超过 n 次，摊到每次操作上是均摊 O(1)，整体算下来就是 O(n)。空间复杂度是 O(k)，因为队列中最多同时存在 k 个下标。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        deque<int> dq;  // 双端队列，存下标，保持对应值单调递减
        vector<int> result;

        for (int i = 0; i < nums.size(); i++) {
            // 步骤1：新元素入队前，从队尾淘汰所有小于它的元素
            while (!dq.empty() && nums[dq.back()] < nums[i]) {
                dq.pop_back();
            }
            dq.push_back(i);

            // 步骤2：淘汰滑出窗口左边界的队头
            if (dq.front() <= i - k) {
                dq.pop_front();
            }

            // 步骤3：窗口形成后，队头即当前窗口最大值
            if (i >= k - 1) {
                result.push_back(nums[dq.front()]);
            }
        }
        return result;
    }
};
```

### Java

```java
class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        Deque<Integer> dq = new ArrayDeque<>();  // 存下标，保持对应值单调递减
        int n = nums.length;
        int[] result = new int[n - k + 1];
        int idx = 0;

        for (int i = 0; i < n; i++) {
            // 步骤1：从队尾淘汰所有小于新元素的下标
            while (!dq.isEmpty() && nums[dq.peekLast()] < nums[i]) {
                dq.pollLast();
            }
            dq.offerLast(i);

            // 步骤2：淘汰滑出窗口左边界的队头
            if (dq.peekFirst() <= i - k) {
                dq.pollFirst();
            }

            // 步骤3：窗口形成后记录队头对应的最大值
            if (i >= k - 1) {
                result[idx++] = nums[dq.peekFirst()];
            }
        }
        return result;
    }
}
```

### Python

Python 的 `collections.deque` 是双端队列的标准库实现，两端操作都是 O(1)，这里直接使用库解；单调队列的逻辑本身仍需手写（标准库不会帮你维护单调性）。

```python
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: list[int], k: int) -> list[int]:
        dq = deque()  # 存下标，保持对应值单调递减
        result = []

        for i, num in enumerate(nums):
            # 步骤1：从队尾淘汰所有小于新元素的下标
            while dq and nums[dq[-1]] < num:
                dq.pop()
            dq.append(i)

            # 步骤2：淘汰滑出窗口左边界的队头
            if dq[0] <= i - k:
                dq.popleft()

            # 步骤3：窗口形成后记录队头对应的最大值
            if i >= k - 1:
                result.append(nums[dq[0]])

        return result
```

### Go

```go
func maxSlidingWindow(nums []int, k int) []int {
    var dq []int // 双端队列，存下标，保持对应值单调递减（用 slice 模拟）
    result := make([]int, 0, len(nums)-k+1)

    for i, num := range nums {
        // 步骤1：从队尾淘汰所有小于新元素的下标
        for len(dq) > 0 && nums[dq[len(dq)-1]] < num {
            dq = dq[:len(dq)-1] // 弹出队尾
        }
        dq = append(dq, i) // 新下标入队尾

        // 步骤2：淘汰滑出窗口左边界的队头
        if dq[0] <= i-k {
            dq = dq[1:] // 弹出队头
        }

        // 步骤3：窗口形成后记录队头对应的最大值
        if i >= k-1 {
            result = append(result, nums[dq[0]])
        }
    }
    return result
}
```

## 总结

- 单调队列这东西说白了就是"只保留未来还有可能成为最大值的候选元素"，靠在队尾淘汰掉"更早进入窗口但值更小"的元素，把每个元素的比较次数分摊到 O(1)，整体就做到 O(n) 了。
- 队列里为什么存下标而不是值？因为你得通过下标才能判断这个元素是不是已经滑出窗口了，这是维护窗口左边界淘汰逻辑的前提，这点一定要记住。
- 两个淘汰方向千万不能搞混：队尾淘汰是为了维护单调性，淘汰的是"没用的小元素"；队头淘汰是为了维护窗口范围，淘汰的是"过期的元素"。这两者要维护的目标完全不同，缺一不可。
- 还有一点要提一下，单调队列和后面会讲到的单调栈是两种不同的工具，别搞混了：单调栈通常解决的是"下一个更大/更小元素"这类问题，只需要维护一端；单调队列则专门用来解决"滑动窗口最值"这类问题，需要双端操作。适用场景不一样，不要混着用。
