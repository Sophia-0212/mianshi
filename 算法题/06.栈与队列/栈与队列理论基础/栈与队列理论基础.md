# 栈与队列理论基础

**基本概念**

栈（Stack）和队列（Queue）都是限制了访问顺序的线性数据结构，它们的区别就在于"从哪端进、从哪端出"，你可以这么理解：

- 栈是 LIFO（Last In First Out，后进先出）：只能从一端（也就是栈顶）插入和删除，最后进去的元素反而最先出来。
- 队列是 FIFO（First In First Out，先进先出）：从一端（队尾）插入，从另一端（队头）删除，最先进去的元素也最先出来。

你想啊，这两者都只暴露"一端"或者"两端"的操作，不支持随机访问中间元素，正是这个限制，才让它们能在特定场景下把问题简化下来。

## 底层实现方式：数组 vs 链表

栈和队列说白了本质上是一种"操作受限的接口"，底层可以用数组或者链表实现，各有各的取舍，我说一下：

**数组实现栈**：用一个数组加一个 `top` 指针（指向栈顶元素的下一个位置）。push 的时候把元素写到 `arr[top]` 再 `top++`；pop 的时候 `top--` 再读取。优点是内存连续、缓存友好，访问速度快；缺点是容量固定，或者需要扩容（均摊下来是 O(1)，但偶尔会触发一次 O(n) 的搬迁）。

**链表实现栈**：用单链表的头插头删来模拟栈顶操作，push 就是头插一个新节点，pop 就是删除头节点。优点是没有容量上限，不需要扩容；缺点是每个节点多了一份指针的内存开销，而且内存不连续，缓存命中率不如数组。

**数组实现队列**：如果只用普通数组，从队尾插入倒是容易，但从队头删除就得把后面所有元素往前搬一位，这是个 O(n) 操作，效率很低。实际工程里通常用"循环数组"（circular buffer）来解决这个问题——用两个指针 `head` 和 `tail` 循环移动，删除队头只需要 `head++`（取模回绕就行），不需要搬移其他元素，插入删除都是 O(1)。

**链表实现队列**：用单链表，维护 `head` 和 `tail` 两个指针。队尾插入的时候在 `tail` 后面接个新节点再更新 `tail`；队头删除的时候直接把 `head` 移到下一个节点就行。天然就是 O(1)，不需要处理扩容或者回绕的问题，算是最直观的队列实现方式了。

综合来看的话：如果需要频繁随机访问，或者对缓存性能比较敏感，那数组（循环数组）更合适；如果元素数量变化很大，不想处理扩容逻辑，那链表更省心。其实绝大多数语言的标准库队列（比如双端队列）底层用的是分段的动态数组（也就是 deque 的分块结构），这样正好能兼顾两者的优点。

## 四语言标准库对比

| 语言 | 栈 | 队列 |
|------|-----|------|
| C++ | `std::stack`（默认基于 `deque` 实现） | `std::queue`（默认基于 `deque` 实现） |
| Java | `Deque<Integer> stack = new ArrayDeque<>()`（官方推荐用 `Deque` 代替过时的 `Stack` 类） | `Deque<Integer> queue = new ArrayDeque<>()`（作队列用时调用 `offer`/`poll`） |
| Python | `list`（`append`/`pop` 模拟栈，O(1) 摊还） | `collections.deque`（`append`/`popleft`，两端操作都是 O(1)） |
| Go | `slice`（`append` 入栈，`s[:len(s)-1]` 出栈） | `slice` 模拟（`append` 入队，`s[0]` 出队后 `s = s[1:]`），或用 `container/list` 双向链表 |

几点需要注意的坑，我挨个说一下：

- **Java 的 `Stack` 类是历史遗留下来的东西**，它继承自 `Vector`，所有方法都加了同步锁，性能不如 `ArrayDeque`。官方文档里其实明确推荐用 `Deque` 接口的 `push`/`pop`/`peek` 来实现栈的语义，不建议直接用 `Stack` 类。
- **Python 的 `list` 用作队列效率很低**：`list.pop(0)` 是 O(n) 的，为什么呢？因为要搬移剩余的所有元素；而 `collections.deque` 底层是双向链表结构（分块数组），`popleft()` 是 O(1) 的，所以队列场景必须用 `deque`，不要用 `list`，这是个常见的坑。
- **Go 没有内置的栈/队列容器**，通常就是直接用 `slice` 模拟：栈操作（`append` 和截断末尾）都是均摊 O(1)；队列如果用 `s = s[1:]` 来出队，底层数组的起始指针会一直往后移，虽然单次操作是 O(1)，但会造成内存没法及时释放，长期运行的队列场景更推荐用 `container/list` 或者手写循环数组。
- **C++ 的 `stack`/`queue` 是容器适配器**，不是独立容器，默认底层用的是 `deque`，你也可以指定用 `vector`（栈）或者 `list`。

## 栈的天然适用场景

栈的核心特性是"后进先出"，这天然就匹配下面几类问题：

**括号匹配 / 表达式合法性校验**：左括号入栈，遇到右括号就检查栈顶的左括号是否与之匹配。为什么呢？因为最近出现的、还没被匹配的左括号一定是最先应该被匹配掉的那个，这正是 LIFO 的语义所在。

**表达式求值（中缀转后缀、逆波兰表达式计算）**：不管是用栈暂存运算符（处理优先级和结合性），还是用栈暂存操作数（逆波兰表达式求值时遇到运算符就弹出最近的两个数来计算），说白了都是利用"最近产生的中间结果应该被最先使用"这一特性。

**DFS（深度优先搜索）**：DFS 的语义就是"一条路走到底，走不通了再回退到最近的分叉点"，这个"最近"正好就对应栈顶。你想啊，递归函数调用本身就是用系统调用栈实现的，手写迭代版 DFS 的时候通常也是显式维护一个栈。

## 队列的天然适用场景

队列的核心特性是"先进先出"，天然匹配下面几类问题：

**BFS（广度优先搜索）**：BFS 要求按"层"扩展，先访问的节点，它的邻居也要先被访问到，这正是 FIFO 保证的顺序。如果用栈来做类似的遍历，就会变成 DFS 的效果，而不是逐层扩展了。

**滑动窗口类问题**：维护一个固定或者可变大小的窗口时，窗口右边界新元素入队、左边界旧元素出队，这符合"先进的先离开窗口"的直觉。特别是单调队列（用双端队列维护窗口内的最大/最小值候选），既需要队尾插入、队头删除的队列语义，又需要队尾也能删除来保持单调性，因此这类问题通常用双端队列（deque）而不是普通队列。

## 小结

栈和队列都是通过限制访问方式换来了语义上的确定性：栈保证"最后来的最先处理"，队列保证"最先来的最先处理"。选哪个数据结构可不是随意的，而是要看问题本身的时序要求——需要"回退到最近状态"就用栈，需要"按到达顺序处理"就用队列。理解了这一点，再看具体题目的时候就能快速判断该用哪种结构了，而不是死记硬背套路。
