# 0225. 用队列实现栈

**题目描述**

仅使用一个或两个队列实现后入先出栈，支持以下操作：

- `push(x)`：将元素 x 压入栈顶
- `pop()`：移除并返回栈顶元素
- `top()`：返回栈顶元素
- `empty()`：判断栈是否为空

```
示例：
输入:
["MyStack", "push", "push", "top", "pop", "empty"]
[[], [1], [2], [], [], []]
输出:
[null, null, null, 2, 2, false]
```

要求：只能使用队列的标准操作（push、peek/front、pop、size、empty）。

## 思路

队列是 FIFO，栈是 LIFO，方向正好是反着来的。队列只能从队头取出"最先进去"的那个元素，可栈需要取出的却是"最后进去"的那个元素，所以我们得想个办法，把"最后进去的"倒腾到队头去。

**核心技巧是：push 的时候，把新元素之前的所有元素重新入队一遍**。

具体怎么做呢（用一个队列就能实现）：

1. 新元素 x 先直接入队（这时候 x 排在队尾）。
2. 把队列里排在 x **前面**的那些旧元素，依次出队再重新入队，一共要执行 `size - 1` 次（这里的 `size` 是入队之后的队列长度）。
3. 这样一操作，x 就被"转"到了队头，而其余元素还是保持原来的相对顺序，排在 x 后面。

你可以这样直觉地理解：每次 push 都让新元素立刻"插队"到队头，这样队头始终是最后 push 进来的那个元素，也就是栈顶。这样一来，`pop()` 和 `top()` 直接操作队头就行了，不需要额外处理。

**这里有个关键点得说清楚**：为什么是"重新入队size-1次"，不是别的次数呢？你想啊，新元素入队之后，它自己就占了一个位置，剩下`size - 1`个才是需要挪到它后面去的旧元素；把这些旧元素依次出队再入队一次，它们就绕到队列末尾去了，新元素自然就留在了队头。

其实也可以用**两个队列**来实现（这是另一种常见写法）：push 的时候把新元素放进空队列 queue2，再把 queue1 里的所有元素依次转移到 queue2 里，最后交换一下 queue1 和 queue2 的角色，效果跟单队列版本是等价的，只是这里显式用了两个队列容器，避免了"原地绕圈"这个技巧，看起来更直观，不过空间上多用了一个队列。

**复杂度分析**：

- push：需要把队列里已有的 `size-1` 个元素重新入队一次，是 O(n)。
- pop / top：直接操作队头就行，O(1)。
- 空间复杂度是 O(n)。

拿 0232 题（用栈实现队列）来对比一下：0232 是"pop 贵、push 便宜"，而且 pop 的代价还能被均摊掉；但 0225 这题反过来，是"push 贵、pop 便宜"，push 的 O(n) 代价**是没法均摊的**，因为每次 push 都得重新排一次队,不存在"下次操作不用再排"这种便宜可占。这就是这两题本质上不对称的地方。

## 代码

### C++

```cpp
class MyStack {
private:
    queue<int> q;  // 单队列模拟栈，队头始终是"栈顶"

public:
    MyStack() {}

    void push(int x) {
        q.push(x);                     // 新元素先入队，排在队尾
        int n = q.size();
        for (int i = 0; i < n - 1; i++) {  // 把 x 前面的旧元素依次挪到它后面
            q.push(q.front());
            q.pop();
        }
        // 循环结束后，x 被转到了队头，即栈顶
    }

    int pop() {
        int val = q.front();  // 队头就是栈顶
        q.pop();
        return val;
    }

    int top() {
        return q.front();  // 队头即栈顶
    }

    bool empty() {
        return q.empty();
    }
};
```

### Java

```java
class MyStack {
    private Deque<Integer> queue;  // 用 Deque 当普通队列使（offer/poll 操作队尾/队头）

    public MyStack() {
        queue = new ArrayDeque<>();
    }

    public void push(int x) {
        queue.offer(x);              // 新元素入队，排在队尾
        int n = queue.size();
        for (int i = 0; i < n - 1; i++) {  // 把 x 前面的旧元素依次挪到它后面
            queue.offer(queue.poll());
        }
        // x 被转到队头，即栈顶
    }

    public int pop() {
        return queue.poll();  // 队头即栈顶
    }

    public int top() {
        return queue.peek();  // 队头即栈顶
    }

    public boolean empty() {
        return queue.isEmpty();
    }
}
```

### Python

用 `collections.deque` 作为队列（`popleft` 是 O(1)，若用 `list.pop(0)` 会退化为 O(n)，不适合这里）。

```python
from collections import deque

class MyStack:
    def __init__(self):
        self.queue = deque()  # 单队列模拟栈，队头始终是"栈顶"

    def push(self, x: int) -> None:
        self.queue.append(x)          # 新元素入队，排在队尾
        n = len(self.queue)
        for _ in range(n - 1):        # 把 x 前面的旧元素依次挪到它后面
            self.queue.append(self.queue.popleft())
        # x 被转到队头，即栈顶

    def pop(self) -> int:
        return self.queue.popleft()   # 队头即栈顶

    def top(self) -> int:
        return self.queue[0]          # 队头即栈顶

    def empty(self) -> bool:
        return len(self.queue) == 0
```

### Go

```go
type MyStack struct {
    queue []int // 用 slice 模拟队列，队头是 queue[0]，队尾是 append 的位置
}

func Constructor() MyStack {
    return MyStack{}
}

func (s *MyStack) Push(x int) {
    s.queue = append(s.queue, x) // 新元素入队，排在队尾
    n := len(s.queue)
    for i := 0; i < n-1; i++ { // 把 x 前面的旧元素依次挪到它后面
        front := s.queue[0]
        s.queue = s.queue[1:]             // 队头出队
        s.queue = append(s.queue, front)  // 重新入队，排到队尾
    }
    // x 被转到队头，即栈顶
}

func (s *MyStack) Pop() int {
    val := s.queue[0] // 队头即栈顶
    s.queue = s.queue[1:]
    return val
}

func (s *MyStack) Top() int {
    return s.queue[0] // 队头即栈顶
}

func (s *MyStack) Empty() bool {
    return len(s.queue) == 0
}
```

## 总结

- 单队列模拟栈的核心技巧就是"push 的时候把新元素之前的所有旧元素重新入队一次"，让新元素始终占据队头这个位置，这样队头就等价于栈顶了。
- 跟双队列写法比起来，单队列版本更省空间，但本质上是同一个思路的两种实现方式：双队列显式区分出"当前队列"和"临时队列"，单队列则是原地绕圈来达到同样的效果。
- 复杂度上跟 0232 题（用栈实现队列）呈一种镜像关系：这里是 push 贵（O(n)）、pop 便宜（O(1)），而且 push 的代价没法像 0232 的 pop 那样被均摊掉，因为每次 push 都必须重新排一次队，没有"复用上次工作"的空间。
- 判断空的逻辑很简单，只需要看底层队列是不是空的就行，不需要额外维护一个计数器。
