# 0141. 环形链表

**题目描述**

给定一个链表的头节点 `head`，判断链表中是否存在环。链表中的环是指：链表某个节点的 `next` 指针指向了链表中靠前的某个节点，形成一个循环，导致从这个节点出发沿着 `next` 一直走会无限循环下去，而不会到达 `null`。

本题只需要返回是否存在环（布尔值），不需要找出环的入口位置（找入口是进阶版 142 题的要求）。

```
示例：
输入: head = [3,2,0,-4]，其中最后一个节点的 next 指向下标为 1 的节点（形成环）
输出: true

输入: head = [1,2]，不存在环
输出: false
```

## 思路

判断链表有没有环，最直观但不太优雅的做法是：用一个哈希集合记录访问过的节点地址，遍历的时候如果发现某个节点已经在集合里出现过，那就说明有环；要是一直遍历到 `null` 都没重复出现，那就是无环。这个方法时间复杂度是 O(n)，但空间复杂度也是 O(n)，因为最坏情况下要把所有节点地址都塞进哈希集合里。

真正能体现算法思维、也是这道题真正想考察的解法，是 **Floyd 判圈算法**（也叫龟兔赛跑算法），它只用两个指针就能在 O(1) 空间内搞定判断。核心思路是这样的：

设两个指针 `slow` 和 `fast`，都从头节点出发。每一轮循环，`slow` 走一步，`fast` 走两步。这里得讲清楚为什么这样走一定能检测出环。

**如果链表没有环**，`fast` 指针肯定会比 `slow` 更快到达链表末尾（碰到 `null`），所以只要在循环里判断 `fast` 或者 `fast.next` 是不是空，一旦是空就可以直接返回 `false`。

**如果链表有环**呢？关键得想清楚一点：一旦两个指针都进了环里，它们其实就相当于在一条"环形跑道"上跑，`fast` 每一轮比 `slow` 多走一步，也就是说两者的相对速度差恒定是 1（每一轮 `fast` 相对 `slow` 多跑一格）。你想啊，在一个长度有限的环上，只要存在恒定的相对速度差，追赶的那个（`fast`）就一定能在有限轮数内追上被追的那个（`slow`）——这其实就是经典的"环形跑道追及问题"：只要环的周长是个有限值 `L`，速度差是 1，那最多经过 `L` 轮，`fast` 就能把跟 `slow` 之间的距离差从初始值一点点缩小到 0，也就是两者会在环内某一点相遇。相遇之后就能确定环的存在，返回 `true`。

有个细节需要特别注意，就是循环终止条件怎么写。因为 `fast` 每次要走两步，所以判断条件得同时检查 `fast != null` 和 `fast.next != null`，不然 `fast` 只剩一个节点可走的时候去访问 `fast.next.next` 就会报空指针异常。另外，判断两个指针是不是相遇，一定要放在每一轮指针移动**之后**去检查（`slow == fast`），不能放在移动之前——为什么呢？因为初始状态两者都指向头节点，一开始本来就是相等的，要是放在移动前判断，那刚进循环就会被误判成有环了。

咱们对比一下时间和空间复杂度：哈希集合法是时间 O(n)、空间 O(n)；快慢指针法是时间 O(n)（最坏情况下 `slow` 走到追上 `fast` 之前，走的步数不会超过链表长度加环长，量级上仍然是线性的）、空间 O(1)。在链表可能很长的场景下，快慢指针法的空间优势就非常明显了，这也是为什么面试官几乎都会期待看到 Floyd 判圈算法，而不是哈希集合法。

再顺带提一下和 142 题（环形链表 II，要求返回入环的第一个节点）的关系：141 题只要判断相不相遇就能返回结果了，而 142 题在两指针相遇之后，还得再利用"环外距离等于相遇点到入口的距离"这个数学性质，重新弄一个指针从头节点出发，跟相遇点的指针同速前进，两者再次相遇的位置就是环的入口。说白了，141 题就是 142 题去掉"找入口"这一步之后的简化版本。

## 代码

### C++

```cpp
/**
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode(int x) : val(x), next(nullptr) {}
 * };
 */
class Solution {
public:
    bool hasCycle(ListNode *head) {
        ListNode *slow = head, *fast = head; // 两个指针都从头节点出发
        while (fast != nullptr && fast->next != nullptr) {
            slow = slow->next;         // 慢指针走一步
            fast = fast->next->next;   // 快指针走两步
            if (slow == fast) {        // 移动之后再判断是否相遇
                return true;            // 相遇说明存在环
            }
        }
        return false; // fast 提前到达链表末尾，说明无环
    }
};
```

### Python

标准库思路说明：Python 没有针对"链表判圈"这种场景的现成库函数，因为这属于自定义数据结构上的指针操作，没有通用容器能直接调用。这里先给一个更直观但空间不是最优的哈希集合写法作为对照，再给出面试真正考察的手写快慢指针版本。

哈希集合写法（空间 O(n)，用于对照理解，不是本题推荐解法）：

```python
class Solution:
    def hasCycle(self, head: 'Optional[ListNode]') -> bool:
        visited = set()          # 记录访问过的节点地址
        node = head
        while node:
            if node in visited:  # 该节点已经访问过，说明存在环
                return True
            visited.add(node)
            node = node.next
        return False              # 遍历到 null，说明无环
```

手写实现（面试考察点，Floyd 判圈算法，O(1) 空间）：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def hasCycle(self, head: 'Optional[ListNode]') -> bool:
        slow, fast = head, head  # 两个指针都从头节点出发
        while fast and fast.next:
            slow = slow.next        # 慢指针走一步
            fast = fast.next.next   # 快指针走两步
            if slow == fast:        # 移动之后判断是否相遇
                return True          # 相遇说明存在环
        return False  # fast 提前到达链表末尾，说明无环
```

## 总结

- Floyd 判圈算法的正确性，说白了就是建立在"恒定相对速度差在有限环上必然导致追及"这个朴素的物理直觉上：快慢指针速度差是 1，环的周长又是有限的，所以追赶所需的轮数肯定是有限的，不会无限循环下去。
- 循环终止条件一定要同时判断 `fast` 和 `fast.next` 非空，因为快指针一次要跨两步，少判断一个的话，链表比较短的时候就会访问越界指针。
- 相遇判断要放在指针移动之后，不能放在移动之前，不然会因为起点相同，导致循环刚开始就被误判成有环了。
- 这道题其实是 142 题（环形链表 II）的简化版：141 题只要判断相遇就能返回结果，142 题在相遇之后还得利用等距性质重新定位入环点。理解清楚这两题的递进关系，能帮你更系统地掌握 Floyd 判圈算法的完整应用。
