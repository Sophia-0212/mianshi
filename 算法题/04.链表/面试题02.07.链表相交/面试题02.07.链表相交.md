# 面试题 02.07. 链表相交

**题目描述**

给定两个单链表的头节点 `headA` 和 `headB`，判断两个链表是否相交，如果相交，返回相交的起始节点；如果不相交，返回 `null`。

需要注意：这里的"相交"指的是两个链表从某个节点开始，后续所有节点（包括该节点本身）在内存中是完全同一批节点，即节点的引用/地址相同，而不是节点的值恰好相等。

```
示例：
链表 A: 4 -> 1 -> 8 -> 4 -> 5
链表 B:      5 -> 6 -> 1 -> 8 -> 4 -> 5
（A 和 B 从值为 8 的节点开始是同一批节点，即地址相同）
输出: 相交起始节点，值为 8
解释: 从这个节点开始，A 和 B 之后的部分完全共享（同一段内存）
```

## 思路

你想啊，如果两个链表相交，那从相交点开始，它们其实是共享同一段"尾部"的，唯一的区别就是相交点之前各自"私有"的那一段长度不一样。设链表 A 的私有部分长度为 `a`，链表 B 的私有部分长度为 `b`，共享部分长度为 `c`（要是不相交，`c` 就是 0）。

**核心思路是这样的**：先分别求出两个链表的长度 `lenA` 和 `lenB`，算出长度差 `diff = |lenA - lenB|`。让较长的链表先走 `diff` 步，这样操作完之后，两个指针到链表末尾的剩余距离就相等了（都是 `min(lenA, lenB)`，也就是较短链表的完整长度）。接下来让两个指针同步往前走，每一步都比较它们是不是指向同一个节点：

- 如果相交，同步走的过程中一定会在真正的相交点第一次相遇（因为从相交点开始，后续的路径完全相同，长度差已经提前被消化掉了）。
- 如果不相交，两个指针会同时走到各自链表的末尾（也就是 `null`），这时候它们是相等的（都是 `null`），可以统一把这个"相遇"结果当作返回值。

**为什么要先走长度差 `diff` 步呢**？你想想，如果不做这个操作，直接同步遍历两个长度不同的链表，就算它们真的相交，也会因为起点没对齐，导致永远不会指向同一个节点（除非私有部分长度恰好一样）。走长度差这一步的目的，就是把两个指针"距离终点的步数"拉平，让它们到达相交点的时候步数正好对齐。

**这里有个关键细节**：判断"是不是同一个节点"，用的是**引用/地址比较**（在支持指针比较的语言里就是判断指针是否相等，比如 Python 里判断 `is`），千万不能用节点的值来判断，因为不同节点完全可能存储相同的值，但它们其实是不同的对象。

时间复杂度是 O(m + n)，`m`、`n` 分别是两条链表的长度（求长度各遍历一次，之后再同步遍历一次，总量级还是线性的）；空间复杂度是 O(1)，只用了常数个指针。

## 代码

链表节点定义：

```cpp
struct ListNode {
    int val;
    ListNode *next;
    ListNode(int x) : val(x), next(NULL) {}
};
```

### C++

```cpp
class Solution {
public:
    ListNode* getIntersectionNode(ListNode* headA, ListNode* headB) {
        int lenA = getLength(headA);
        int lenB = getLength(headB);
        ListNode* curA = headA;
        ListNode* curB = headB;

        // 让较长的链表先走长度差步，对齐两指针到终点的剩余距离
        if (lenA > lenB) {
            for (int i = 0; i < lenA - lenB; i++) curA = curA->next;
        } else {
            for (int i = 0; i < lenB - lenA; i++) curB = curB->next;
        }

        // 同步前进，比较的是节点地址（指针本身）是否相同，不是值
        while (curA != curB) {
            curA = curA->next;
            curB = curB->next;
        }
        return curA;  // 相交则返回交点；不相交时 curA、curB 都会同时变为 nullptr
    }

private:
    int getLength(ListNode* head) {
        int len = 0;
        while (head != nullptr) {
            len++;
            head = head->next;
        }
        return len;
    }
};
```

### Python

链表相交判断依赖节点身份比较，属于结构性操作，没有对应的标准库一行解，这里只给手写实现：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> ListNode:
        def get_length(head):
            length = 0
            while head is not None:
                length += 1
                head = head.next
            return length

        len_a, len_b = get_length(headA), get_length(headB)
        cur_a, cur_b = headA, headB

        # 让较长链表先走长度差步，对齐剩余距离
        if len_a > len_b:
            for _ in range(len_a - len_b):
                cur_a = cur_a.next
        else:
            for _ in range(len_b - len_a):
                cur_b = cur_b.next

        # 同步前进，用 is 比较节点身份（地址），不是值相等
        while cur_a is not cur_b:
            cur_a = cur_a.next
            cur_b = cur_b.next
        return cur_a  # 相交返回交点；不相交时两者同时变为 None
```

## 总结

- 这道题最容易犯的错误就是用节点的**值**来判断是否相交，正确做法应该是比较节点的**引用/地址**，因为不同链表完全可以有值相同但是不同对象的节点，这一点一定要说清楚。
- 核心技巧就是"先消化长度差，再同步遍历"：让较长链表先走 `|lenA - lenB|` 步，之后两指针每一步都保持"到链表末尾距离相等"，如果存在交点，就必然会同步到达。
- 不相交其实是这个算法的自然退化情况：两指针会同步走到各自链表末尾（都变成 `null`/`None`/`nil`），这时候它们是相等的，直接拿这个当统一的返回值就行，不需要单独判断"不相交"这个分支。
- 跟"环形链表判环"里的快慢指针不一样，这道题的两个指针速度始终是一样的（都是一步一步走），差异只体现在起跑时间上（通过提前走长度差步来实现），这是双指针技巧里"对齐后同步"这个子模式的典型代表。
