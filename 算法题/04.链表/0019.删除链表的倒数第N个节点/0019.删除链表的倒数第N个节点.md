# 0019. 删除链表的倒数第N个节点

**题目描述**

给定一个链表的头节点 `head`，删除链表的倒数第 `n` 个节点，并返回链表的头节点。题目保证 `n` 是合法的（不超过链表长度）。

```
示例：
输入: head = [1,2,3,4,5], n = 2
输出: [1,2,3,5]
解释: 倒数第 2 个节点是值为 4 的节点，删除后链表变为 1->2->3->5
```

## 思路

咱们先说最直观的想法：分两步走，先遍历一遍链表数出总长度 `L`，那倒数第 `n` 个节点其实就是正数第 `L - n + 1` 个（从 1 开始数），再遍历一次找到它前面那个节点，删掉就行。这个思路时间复杂度也是 O(n)，但问题是它要遍历两次链表，那我们能不能只走一趟就搞定呢？

这里的关键就是**快慢指针法**，它就是用来把两次遍历压成一次的。你想啊，如果让快指针先比慢指针多走 `n` 步，之后两个指针再以同样的速度往前走，那快指针走到链表末尾的时候，快慢指针之间不就一直保持着 `n` 个节点的间距吗？这就意味着慢指针刚好停在"倒数第 `n+1` 个节点"上——说白了，这正好就是要删除节点的前驱。

那为什么这么走是对的呢？咱们推一下：设链表总长度是 `L`，我们希望慢指针最后停在第 `L - n` 个节点（从虚拟头节点开始数，0-indexed），这样它正好是待删除节点（也就是第 `L - n + 1` 个）的前驱。如果快指针提前多走 `n` 步，等它走到链表末尾（也就是总共走了 `L` 步）的时候，慢指针只走了 `L - n` 步，恰好落在我们要的前驱位置上。

实现的时候还是要借助虚拟头节点，为什么呢？因为如果 `n` 正好等于链表长度，那要删除的就是原来的头节点，这时候"待删除节点的前驱"其实就是虚拟头节点自己——用 `dummy` 之后这种边界情况就被自然覆盖了，不用再单独判断。

具体步骤是这样的：
1. `fast = dummy`，`slow = dummy`
2. 先让 `fast` 往前走 `n` 步，这样 `fast` 和 `slow` 之间就形成了 `n` 个节点的间距
3. 然后 `fast` 和 `slow` 一起往前走，直到 `fast->next == nullptr`——注意这里判断的是走到最后一个节点，而不是走到 `null`，这么处理是因为这样刚好能让 `slow` 落在待删除节点的前驱上
4. 这时候 `slow->next` 就是要删除的节点，直接 `slow->next = slow->next->next` 跳过去就行

时间复杂度是 O(n)：原来要遍历两次，现在用快慢指针联合走一趟就够了，严格来说访问节点的总量级没变，只是省掉了"先单独数一遍长度"这个步骤，实现上更简洁；空间复杂度是 O(1)，没用额外的存储空间。

## 代码

链表节点定义：

```cpp
struct ListNode {
    int val;
    ListNode *next;
    ListNode(int x) : val(x), next(NULL) {}
};
```

### C++

```cpp
class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        ListNode* dummy = new ListNode(0);  // 虚拟头节点，涵盖"删除原头节点"的边界情况
        dummy->next = head;
        ListNode* fast = dummy;
        ListNode* slow = dummy;

        for (int i = 0; i < n; i++) {
            fast = fast->next;  // fast 先走 n 步，制造 n 个节点的间距
        }

        while (fast->next != nullptr) {  // fast 走到最后一个节点为止（不是走到 null）
            fast = fast->next;
            slow = slow->next;  // 保持间距同步前进
        }

        slow->next = slow->next->next;  // slow 现在正好是待删除节点的前驱，跳过它
        ListNode* newHead = dummy->next;
        delete dummy;
        return newHead;
    }
};
```

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def removeNthFromEnd(self, head: ListNode, n: int) -> ListNode:
        dummy = ListNode(0)  # 虚拟头节点
        dummy.next = head
        fast = dummy
        slow = dummy

        for _ in range(n):
            fast = fast.next  # fast 先走 n 步，制造间距

        while fast.next is not None:  # fast 走到最后一个节点
            fast = fast.next
            slow = slow.next            # 同步前进保持间距

        slow.next = slow.next.next  # slow 是待删除节点的前驱
        return dummy.next
```

```go
    Val  int
    Next *ListNode
}

func removeNthFromEnd(head *ListNode, n int) *ListNode {
    dummy := &ListNode{Next: head} // 虚拟头节点
    fast, slow := dummy, dummy

    for i := 0; i < n; i++ {
        fast = fast.Next // fast 先走 n 步，制造间距
    }

    for fast.Next != nil { // fast 走到最后一个节点
        fast = fast.Next
        slow = slow.Next // 同步前进保持间距
    }

    slow.Next = slow.Next.Next // slow 是待删除节点的前驱
    return dummy.Next
}
```

## 总结

- 这道题的核心就是快慢指针的间距设计：让 `fast` 先走 `n` 步，制造出固定间距，之后两个指针同步往前挪，`fast` 走到末尾的时候，`slow` 必然会落在倒数第 `n+1` 个节点上，也就是待删除节点的前驱。
- 有个特别容易踩坑的地方，就是循环终止条件：一定要判断 `fast->next == nullptr`（走到最后一个节点），而不是 `fast == nullptr`（走到 `null`）。为什么呢？因为少走一步才能让 `slow` 精确停在"前驱"上，而不是停在"待删除节点本身"。
- 虚拟头节点在这里解决的是这样一个边界情况：当 `n` 正好等于链表长度时，要删除的其实是原头节点，它的前驱就是 `dummy`。用了虚拟头节点之后，这种特殊情况和普通情况就完全统一了，不用再额外写判断。
- 这道题和"环形链表判环"其实都属于快慢指针的应用，但目的不太一样：这里是用间距差去找位置，环形链表那道题是用速度差去判断是否存在环。搞清楚这两者的差异，才能真正灵活地用好双指针这个技巧。
