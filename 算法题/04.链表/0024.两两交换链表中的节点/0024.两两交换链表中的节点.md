# 0024. 两两交换链表中的节点

**题目描述**

给定一个链表，两两交换其中相邻的节点，并返回交换后的链表。要求不能只是单纯地改变节点内部的值，而是需要实际进行节点交换（即改变指针指向）。

```
示例：
输入: head = [1,2,3,4]
输出: [2,1,4,3]
解释: 第1、2个节点交换，第3、4个节点交换，得到 2->1->4->3
```

## 思路

这道题的难点不在于"交换"这个概念本身好不好理解，而在于**交换过程中指针操作的顺序**——你想啊，一旦某个指针被你覆盖了，但之前没提前保存好，那后面需要用到的那个节点引用就永久丢失了，链表直接就断了。

这里还是用虚拟头节点来处理：因为第一对交换涉及的是原来的头节点，交换完之后头节点就变成第二个节点了，直接操作 `head` 这个变量很难优雅地处理这种变化。用了虚拟头节点之后，"交换涉及头部的一对节点"和"交换中间的一对节点"这两种情况的逻辑就能保持一致，不用分别写。

设 `cur` 是当前这一对待交换节点的前驱（一开始就是 `dummy`）。假设 `cur` 后面的两个节点分别是 `first = cur->next` 和 `second = cur->next->next`，那交换这一对节点，说白了就是要重新接三处指针：

1. `cur->next` 要指向 `second`（交换之后 `second` 排到前面去了）
2. `second->next` 要指向 `first`（`second` 排前面之后，紧接着就要接上 `first`）
3. `first->next` 要指向原来 `second` 之后的那个节点，也就是交换前的 `second->next`

**这里有个关键坑点**，一定要注意：第 2 步执行完 `second->next = first` 之后，`first` 原来的 `next`（也就是这一对节点交换前的下一个节点，交换后应该接在 `first` 后面）就已经拿不到了——因为不管是 `second->next` 还是 `first->next`，这两个指针都已经被改成别的值了，你再也找不回原来那个引用。所以必须在动手改任何指针**之前**，先用一个临时变量把这个"后续节点"的引用保存下来：

```
ListNode* next = second->next;  // 提前保存交换后应接在 first 之后的节点
```

保存好之后，三步指针操作的正确顺序就是这样的（配合提前保存的 `next`）：

```
cur->next = second;    // 1. second 顶替到前面
second->next = first;  // 2. second 后面接 first
first->next = next;    // 3. first 后面接上原本保存的后续节点
```

交换完这一对之后，`cur` 要前进到 `first` 这个位置——为什么呢？因为 `first` 现在是这一对交换后排在后面的节点，它才是下一对交换的前驱。接着继续处理下一对，一直到 `cur->next` 或者 `cur->next->next` 为空为止，这说明剩下的节点数不够两个了，不用再交换了。

时间复杂度是 O(n)，每个节点只被访问常数次；空间复杂度是 O(1)，只用了几个额外的指针变量。

## 代码

链表节点定义：

```cpp
struct ListNode {
    int val;
    ListNode *next;
    ListNode(int x) : val(x), next(NULL) {}
};
```

### C++

```cpp
class Solution {
public:
    ListNode* swapPairs(ListNode* head) {
        ListNode* dummy = new ListNode(0);  // 虚拟头节点，统一处理涉及原头节点的交换
        dummy->next = head;
        ListNode* cur = dummy;  // cur 是当前待交换这一对节点的前驱
        while (cur->next != nullptr && cur->next->next != nullptr) {
            ListNode* first = cur->next;         // 这一对的第一个节点
            ListNode* second = cur->next->next;  // 这一对的第二个节点
            ListNode* next = second->next;        // 提前保存后续节点，防止丢失引用

            cur->next = second;    // 1. second 顶替到前面
            second->next = first;  // 2. second 后接 first
            first->next = next;     // 3. first 后接原本保存的后续节点

            cur = first;  // first 现在排在后面，成为下一对交换的前驱
        }
        ListNode* newHead = dummy->next;
        delete dummy;
        return newHead;
    }
};
```

### Python

节点两两交换是链式指针操作，没有对应的标准库一行解，只给手写实现：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def swapPairs(self, head: ListNode) -> ListNode:
        dummy = ListNode(0)  # 虚拟头节点
        dummy.next = head
        cur = dummy            # cur 是当前待交换这一对节点的前驱
        while cur.next is not None and cur.next.next is not None:
            first = cur.next             # 这一对的第一个节点
            second = cur.next.next       # 这一对的第二个节点
            nxt = second.next             # 提前保存后续节点，防止丢失引用

            cur.next = second   # 1. second 顶替到前面
            second.next = first  # 2. second 后接 first
            first.next = nxt      # 3. first 后接后续节点

            cur = first  # first 成为下一对交换的前驱
        return dummy.next
```

### Go

```go
type ListNode struct {
    Val  int
    Next *ListNode
}

func swapPairs(head *ListNode) *ListNode {
    dummy := &ListNode{Next: head} // 虚拟头节点
    cur := dummy                     // cur 是当前待交换这一对节点的前驱
    for cur.Next != nil && cur.Next.Next != nil {
        first := cur.Next        // 这一对的第一个节点
        second := cur.Next.Next  // 这一对的第二个节点
        next := second.Next        // 提前保存后续节点，防止丢失引用

        cur.Next = second    // 1. second 顶替到前面
        second.Next = first  // 2. second 后接 first
        first.Next = next     // 3. first 后接后续节点

        cur = first // first 成为下一对交换的前驱
    }
    return dummy.Next
}
```

## 总结

- 这道题最容易出错的地方就是指针覆盖的顺序：只要某个 `next` 被你重新赋值了，原来的引用就再也拿不回来了。所以一定要在改任何指针之前，先把交换后还要用到的那个引用（也就是 `second->next`，这对节点之后的部分）提前存到临时变量里。
- 三步指针重连的顺序，建议就固定记成这样：`cur->next = second` → `second->next = first` → `first->next = next`——先接前面，再接中间，最后接后面，顺序不能乱。
- 每轮交换完，`cur` 要更新成 `first`（也就是原来排前面、交换后排到后面去的那个节点），而不是 `second`。为什么呢？因为下一对交换的"前驱"，必须是当前这一对交换完之后排在末位的那个节点。
- 循环条件写成 `cur->next != nullptr && cur->next->next != nullptr`，这样能保证当剩余节点数是奇数（最后只剩一个节点）的时候，循环能正确停下来，不会发生空指针访问。这个技巧其实跟"删除倒数第N个节点"里判断链表长度够不够的思路是一致的。
