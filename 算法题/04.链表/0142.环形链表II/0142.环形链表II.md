# 0142. 环形链表 II

**题目描述**

给定一个链表的头节点 `head`，判断链表中是否存在环。如果存在，返回环的入口节点；如果不存在，返回 `null`。不允许通过修改链表本身来判断（比如给节点打标记）。

```
示例：
输入: head = [3,2,0,-4]，其中最后一个节点 -4 的 next 指向值为 2 的节点（形成环）
输出: 返回值为 2 的节点
解释: 链表中存在环，且环的入口节点是索引为 1（值为 2）的节点
```

## 思路

判断链表有没有环，经典解法就是**快慢指针法（也叫 Floyd 判圈算法）**：慢指针 `slow` 每次走一步，快指针 `fast` 每次走两步，两者从头节点同时出发。你想啊，如果链表里存在环，快指针会先进到环里，然后在环内不断"套圈"去追慢指针，因为每一步快指针相对慢指针都多走一步（速度差恒定是 1），两者之间的相对距离在环里每走一步就缩小 1，所以最终必然会相遇（不会出现"永远差一步追不上"的情况，因为这个距离是一步一步、离散地缩小到 0 的）。要是链表里没有环，快指针就会先到达链表末尾（碰到 `null`），据此就能判断是无环的。

但这道题要求更进一步：不光要判断有没有环，还要找出**环的入口节点**在哪。这里需要用到一个不太直观的数学结论，下面咱们完整推一遍。

**数学推导**

设：
- 从链表头节点到环入口的距离为 `a`（即环外部分的长度）
- 从环入口到快慢指针第一次相遇点的距离为 `b`（沿着环走的方向）
- 从相遇点继续往前走，回到环入口的距离为 `c`（也就是环的剩余部分，环的总长度为 `b + c`）

快慢指针第一次相遇的时候：

- 慢指针一共走过的距离是：`slow_dist = a + b`（先走 `a` 步到入口，再在环里走了 `b` 步到相遇点）
- 快指针一共走过的距离呢？因为快指针速度是慢指针的两倍，同样的时间里走的距离自然是慢指针的 2 倍，也就是 `fast_dist = 2 * slow_dist = 2(a + b)`
- 但另一方面，快指针比慢指针多走的那部分路程，其实全都消耗在"多绕的整数圈环"上了，可以写成：`fast_dist = a + b + k * (b + c)`，这里的 `k` 就是快指针追上慢指针之前，比慢指针多绕的圈数（`k >= 1`，为什么呢？因为快指针必须先进入环，之后才能追上慢指针，怎么也得绕一圈多才能追上）

把两个 `fast_dist` 的表达式放在一起：

```
2(a + b) = a + b + k(b + c)
=> a + b = k(b + c)
=> a = k(b + c) - b
=> a = (k-1)(b + c) + c        （把 k(b+c) 拆成 (k-1)(b+c) + (b+c)，再减去 b，剩下 c）
```

所以：

```
a = c + (k-1)(b + c)
```

这个等式说白了就是：**从链表头节点走到环入口的距离 `a`，等于从相遇点走到环入口的距离 `c`，再加上（`k-1`）圈完整的环长**。

这里的关键是，环是循环的，多走 `(k-1)` 整圈其实相当于回到原地，不会产生额外的位移影响（只是多绕了几圈而已），所以咱们可以直接理解成 `a` 和 `c` 在"走到环入口"这件事上是等价的：**从头节点出发走 `a` 步能到环入口，从相遇点出发沿环走 `c` 步也能到环入口，其实是同一个目的地**。

基于这个结论，算法的第二阶段就很好理解了：让一个指针 `p1` 从头节点 `head` 出发，另一个指针 `p2` 从第一次相遇点出发，两者都每次走一步，同步往前走。根据前面的推导，`p1` 走 `a` 步就能到环入口，`p2` 走 `c` 步也能到环入口（因为 `a` 和 `c` 效果是等价的，虽然 `k-1` 圈的余量会让 `p2` 多绕几圈，但多绕整数圈不影响它们同时到达入口这个事实）。所以 `p1` 和 `p2` 必然会在环入口处第一次相遇，这个相遇点就是答案。

时间复杂度是 O(n)，两个阶段都是线性遍历；空间复杂度是 O(1)，只用了常数个指针，没有用额外的哈希表去记录访问过的节点——这正是这道题"不能修改链表、不能用额外标记结构"这个隐含要求下的最优解。

## 代码

链表节点定义：

```cpp
struct ListNode {
    int val;
    ListNode *next;
    ListNode(int x) : val(x), next(NULL) {}
};
```

### C++

```cpp
class Solution {
public:
    ListNode* detectCycle(ListNode* head) {
        ListNode* slow = head;
        ListNode* fast = head;

        // 阶段一：快慢指针判断是否有环，slow 每次1步，fast 每次2步
        while (fast != nullptr && fast->next != nullptr) {
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) {  // 相遇，说明有环，跳出进入阶段二
                // 阶段二：p1 从头节点出发，p2 从相遇点出发，同步走，相遇处即环入口
                ListNode* p1 = head;
                ListNode* p2 = slow;  // slow 此刻就是相遇点
                while (p1 != p2) {
                    p1 = p1->next;
                    p2 = p2->next;
                }
                return p1;  // p1 == p2，即为环入口
            }
        }
        return nullptr;  // fast 到达链表末尾，说明无环
    }
};
```

### Java

```java
class ListNode {
    int val;
    ListNode next;
    ListNode(int x) { val = x; }
}

class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;

        // 阶段一：判断是否有环
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {  // 相遇，说明有环
                // 阶段二：找环入口
                ListNode p1 = head;
                ListNode p2 = slow;
                while (p1 != p2) {
                    p1 = p1.next;
                    p2 = p2.next;
                }
                return p1;  // 环入口
            }
        }
        return null;  // 无环
    }
}
```

### Python

判环加找入口，这本质上是链式指针操作，没有对应的标准库一行解，这里只给手写实现：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def detectCycle(self, head: ListNode) -> ListNode:
        slow = fast = head

        # 阶段一：快慢指针判断是否有环
        while fast is not None and fast.next is not None:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:  # 相遇，说明有环
                # 阶段二：p1 从头出发，p2 从相遇点出发，同步走，相遇即环入口
                p1, p2 = head, slow
                while p1 is not p2:
                    p1 = p1.next
                    p2 = p2.next
                return p1  # 环入口
        return None  # 无环
```

```go
    slow, fast := head, head

    // 阶段一：判断是否有环
    for fast != nil && fast.Next != nil {

        fast = fast.Next.Next
        if slow == fast { // 相遇，说明有环

                p2 = p2.Next
            }
            return p1 // 环入口
        }
    }
    return nil // 无环
}
```

## 总结

- 判环就用快慢指针（速度比 2:1），能相遇就说明有环，原理是环内两指针的相对距离每走一步就缩小 1，必然会收敛到 0；快指针先到达 `null` 那就是无环。
- 找入口的核心，就是靠数学推导出来的这个等式 `a = c + (k-1)(b+c)`：头节点到环入口的距离 `a`，等于相遇点到环入口的距离 `c`（再加上若干整圈，反正不影响到达同一个目的地）。根据这个结论，让一个指针从头出发、另一个从相遇点出发，同步往前走，第二次相遇的地方就是环入口。
- 循环条件 `fast != nullptr && fast->next != nullptr` 这两个条件缺一不可：既要防止 `fast` 本身为空的时候还去访问 `fast->next` 导致崩溃，也要防止 `fast->next` 为空的时候访问 `fast->next->next` 崩溃。
- 这道题其实是快慢指针技巧的一个高阶应用，跟"删除倒数第N个节点"里"固定间距"的用法不一样，这里用的是"速度差"而不是"步数差"；同时它也是"链表相交"问题的一个变体思路来源——有些解法会把环入口问题转化成链表相交问题来统一处理。
