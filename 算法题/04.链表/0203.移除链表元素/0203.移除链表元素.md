# 0203. 移除链表元素

**题目描述**

给定一个链表的头节点 `head` 和一个整数 `val`，删除链表中所有满足 `Node.val == val` 的节点，返回新的头节点。

```
示例：
输入: head = [1,2,6,3,4,5,6], val = 6
输出: [1,2,3,4,5]
解释: 链表中值为 6 的节点（第 3 个和最后一个）被删除，其余节点保持原有相对顺序
```

## 思路

这道题最容易踩坑的地方在哪呢？就是如果要删的值刚好是头节点，那删头节点和删中间节点走的其实是两套完全不同的逻辑。

你想啊，删中间节点很简单，让前一个节点的 `next` 直接跳过当前这个节点就行，也就是 `prev->next = cur->next`。但是删头节点呢？头节点没有"前一个节点"可以操作啊，只能直接把 `head` 这个指针本身指向 `head->next`，这其实是在改指针本身，跟删中间节点不是一回事。

而且如果头部连续好几个都等于 `val`，比如 `[val, val, val, 1, 2]` 这种，你还得用循环去处理头部的连续删除，这样代码里就会出现两段几乎一样的逻辑，一段专门处理头，一段处理中间，很啰嗦。

那怎么解决这个不一致呢？就是用**虚拟头节点**这个技巧。思路是在原链表前面加一个 `dummy` 节点，让 `dummy->next` 指向原来的 `head`。这样一来，原来的头节点也变成了一个"有前驱"的普通节点了，所有节点——包括原来的头节点——删除逻辑就能统一写成一句话：判断 `cur->next` 是不是要删的值，是的话就跳过它，不是的话就往前走。

遍历的时候我用 `cur` 指向"当前已经确认要保留的最后一个节点"，然后每次检查的是 `cur->next` 要不要删。这里有个关键点要强调一下：判断和删除的对象永远是 `cur->next`，不是 `cur` 自己。为什么呢？因为删除操作靠的是前驱节点去重新接线，`cur` 永远是安全的、已经确认保留下来的节点，不会被误删。

最后遍历结束，返回的是 `dummy->next`，而不是 `head`。为什么不能返回 `head`？因为如果原来的头节点被删掉了，`head` 这个变量就已经不指向正确的新头了，所以必须靠 `dummy` 来兜底。

复杂度上，时间是 O(n)，只需要遍历一次链表；空间是 O(1)，就多了几个指针变量，dummy 节点本身占的空间也是常数级的。

## 代码

链表节点定义：

```cpp
struct ListNode {
    int val;
    ListNode *next;
    ListNode(int x) : val(x), next(NULL) {}
};
```

### C++

```cpp
class Solution {
public:
    ListNode* removeElements(ListNode* head, int val) {
        ListNode* dummy = new ListNode(0);  // 虚拟头节点，统一头部与中间节点的删除逻辑
        dummy->next = head;
        ListNode* cur = dummy;  // cur 始终指向"已确认保留"的最后一个节点
        while (cur->next != nullptr) {
            if (cur->next->val == val) {
                ListNode* toDelete = cur->next;
                cur->next = cur->next->next;  // 跳过待删除节点，重新连接
                delete toDelete;               // 释放内存，避免泄漏
            } else {
                cur = cur->next;  // 当前节点保留，指针后移
            }
        }
        ListNode* newHead = dummy->next;  // 真正的新头节点
        delete dummy;
        return newHead;
    }
};
```

### Java

```java
class ListNode {
    int val;
    ListNode next;
    ListNode(int x) { val = x; }
}

class Solution {
    public ListNode removeElements(ListNode head, int val) {
        ListNode dummy = new ListNode(0);  // 虚拟头节点
        dummy.next = head;
        ListNode cur = dummy;  // cur 指向已确认保留的最后一个节点
        while (cur.next != null) {
            if (cur.next.val == val) {
                cur.next = cur.next.next;  // 跳过待删除节点（Java 有 GC，无需手动释放）
            } else {
                cur = cur.next;  // 保留当前节点，指针后移
            }
        }
        return dummy.next;  // 返回新头节点
    }
}
```

### Python

这道题没有能直接套用的标准库一行解（链表遍历删除是结构性操作，`filter` 之类只适用于序列而非链式指针结构），因此只给手写实现：

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def removeElements(self, head: ListNode, val: int) -> ListNode:
        dummy = ListNode(0)      # 虚拟头节点
        dummy.next = head
        cur = dummy              # cur 指向已确认保留的最后一个节点
        while cur.next is not None:
            if cur.next.val == val:
                cur.next = cur.next.next  # 跳过待删除节点
            else:
                cur = cur.next             # 保留当前节点，指针后移
        return dummy.next
```

### Go

```go
type ListNode struct {
    Val  int
    Next *ListNode
}

func removeElements(head *ListNode, val int) *ListNode {
    dummy := &ListNode{Next: head} // 虚拟头节点
    cur := dummy                    // cur 指向已确认保留的最后一个节点
    for cur.Next != nil {
        if cur.Next.Val == val {
            cur.Next = cur.Next.Next // 跳过待删除节点
        } else {
            cur = cur.Next // 保留当前节点，指针后移
        }
    }
    return dummy.Next
}
```

## 总结

- 这题其实是虚拟头节点技巧最经典的入门场景。核心就是头节点也可能被删掉，导致你不能直接用原来的 `head` 变量去返回，所以必须引入一个 `dummy` 节点来统一处理。
- 最容易犯错的地方是判断条件写在 `cur` 还是 `cur->next` 上。一定要记住，检查和删除的对象是 `cur->next`，`cur` 本身永远是已经确认保留、安全的节点，因为删除操作得靠前驱指针才能完成"跳过"这个动作。
- 循环条件那里也要注意，是 `cur->next != nullptr`，不是 `cur != nullptr`。因为每一步我们看的都是"下一个节点"要不要删，如果 `cur->next` 为空了，说明已经走到链表末尾了。
- 这道题算是个基础题，后面像"两两交换节点""删除倒数第N个节点"这些题，用的都是虚拟头节点加前驱指针操作这个套路，把这题吃透了，后面套路都差不多。
