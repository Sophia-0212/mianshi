# 0657. 机器人能否返回原点

**题目描述**

在二维平面上，有一个机器人从原点 `(0, 0)` 开始。给出它的移动顺序，判断这个机器人在完成移动后是否在 `(0, 0)` 处结束。

移动顺序由字符串 `moves` 表示，字符 `moves[i]` 表示其第 i 次移动，只能有四种不同类型的移动：
- `'U'`：向上移动一格（y 坐标 +1）
- `'D'`：向下移动一格（y 坐标 -1）
- `'L'`：向左移动一格（x 坐标 -1）
- `'R'`：向右移动一格（x 坐标 +1）

如果机器人在完成所有动作后返回原点，返回 `true`，否则返回 `false`。

```
示例：
输入：moves = "UD"
输出：true
解释：机器人先向上移动一格，然后向下移动一格，所有动作都完成后，机器人回到原点，所以返回 true。

输入：moves = "LL"
输出：false
解释：机器人向左移动两次，最终它位于原点的左侧，距离原点有两次单位距离，所以返回 false。
```

## 思路

这道题其实是最基础的一类模拟题：给你一串指令，逐条执行完之后判断最终状态满不满足某个条件。这里解题的核心洞察是——机器人是否回到原点，说白了就等价于**水平方向的净位移是 0，而且垂直方向的净位移也是 0**。为什么呢？因为二维平面上一个点要回到原点，必须同时满足两个坐标轴都归零，这其实是个可以拆成两个独立子问题的判定条件，x 轴和 y 轴互不影响。

最直接的做法就是维护两个整型变量 `x` 和 `y`，一开始都是 0，然后遍历指令字符串：
- 遇到 `'U'`，`y += 1`
- 遇到 `'D'`，`y -= 1`
- 遇到 `'L'`，`x -= 1`
- 遇到 `'R'`，`x += 1`

遍历完之后判断一下 `x == 0 && y == 0` 就行了。这个做法足够直观，正确性一眼就能看出来，因为它精确地模拟了机器人每一步的真实坐标变化。

还有一种等价、而且更简洁的写法，用的是"上下抵消、左右抵消"这个对称性的观察：机器人能回到原点，当且仅当指令里 `'U'` 的次数等于 `'D'` 的次数，同时 `'L'` 的次数等于 `'R'` 的次数。这个可以用哈希表（或者四个独立计数器）统计每种指令出现的次数，最后比较两组数量分别相不相等。这种写法在概念上跟坐标累加法完全等价——说白了坐标累加本身就是在做次数相减，只不过用哈希表统计次数的方式，在某些扩展场景下会更有优势，比如以后指令集合扩展成更多方向，或者需要统计每种指令的具体次数用来做别的分析，哈希表这种写法会更容易复用和扩展。

这里说一下需要注意的边界条件：空字符串（也就是没有移动指令）的时候，机器人显然还停在原点，应该返回 `true`，这两种实现方式在这种输入下都能自然给出正确答案，不需要额外特判。同时也要注意一下，坐标变化量一般不会因为字符串长度增长就产生数值溢出的问题（除非输入规模特别夸张），正常情况下用标准整型完全够用。

复杂度这块：不管是坐标累加法还是哈希计数法，都只需要遍历一次字符串，时间复杂度是 O(n)；坐标累加法只用两个整型变量，空间复杂度 O(1)；哈希计数法呢，因为字符集只有 4 种固定字符，就算用哈希表存，空间复杂度也是 O(1)，毕竟就那么几个 key。

## 代码

### C++

```cpp
class Solution {
public:
    bool judgeCircle(string moves) {
        int x = 0, y = 0;  // 记录水平、垂直方向的净位移
        for (char c : moves) {
            if (c == 'U') y++;       // 向上，y 坐标 +1
            else if (c == 'D') y--;  // 向下，y 坐标 -1
            else if (c == 'L') x--;  // 向左，x 坐标 -1
            else if (c == 'R') x++;  // 向右，x 坐标 +1
        }
        return x == 0 && y == 0;  // 两个方向都归零才算回到原点
    }
};
```

### Java

```java
class Solution {
    public boolean judgeCircle(String moves) {
        int x = 0, y = 0;  // 水平、垂直方向的净位移
        for (char c : moves.toCharArray()) {
            switch (c) {
                case 'U': y++; break;  // 向上
                case 'D': y--; break;  // 向下
                case 'L': x--; break;  // 向左
                case 'R': x++; break;  // 向右
            }
        }
        return x == 0 && y == 0;  // 两轴净位移都为 0 即回到原点
    }
}
```

### Python

标准库这边没有针对这类模拟题的通用一行解，不过可以用 `collections.Counter` 统计次数让代码更简洁一点，这里先给计数法，再给坐标累加的手写版本对比一下。

计数法（借助库函数）：

```python
from collections import Counter

class Solution:
    def judgeCircle(self, moves: str) -> bool:
        cnt = Counter(moves)  # 统计每种指令出现的次数
        # 上下抵消、左右抵消，两组次数分别相等即可回到原点
        return cnt['U'] == cnt['D'] and cnt['L'] == cnt['R']
```

手写坐标累加版本（面试更常考察这种直接模拟的写法，逻辑上最直观）：

```python
class Solution:
    def judgeCircle(self, moves: str) -> bool:
        x, y = 0, 0  # 水平、垂直方向的净位移
        for c in moves:
            if c == 'U':
                y += 1
            elif c == 'D':
                y -= 1
            elif c == 'L':
                x -= 1
            elif c == 'R':
                x += 1
        return x == 0 and y == 0  # 两个方向都归零才算回到原点
```

## 总结

- 判断"是否回到原点"这类多维坐标问题，你会发现可以拆解成各坐标轴独立判断，只要每一维都归零，整体自然就归零了，这种拆解思路在处理多维模拟问题时特别常用。
- 坐标累加法和"相反方向次数相等"的计数法本质上是等价的，累加本身其实就是次数相减的另一种表达方式，遇到类似的方向抵消问题时，这两种写法可以互相转化，看场景选更合适的一种就行。
- 这道题算是最简单的模拟类问题了，重点不在算法技巧上，而是在于培养"把复杂条件拆解成若干独立可判断的子条件"这种思维习惯，这个技巧在更复杂的模拟题里同样用得上。
- 容易踩的坑是方向和坐标轴的对应关系搞反了，比如把上下当成 x 轴而不是 y 轴。做这类题的时候建议先把坐标系约定明确好再动手写代码，避免中途搞混。
