# 0031. 下一个排列

**题目描述**

整数数组的一个**排列**就是将其所有成员以序列或线性顺序排列。例如，`nums = [1,2,3]` 的排列包括 `[1,2,3]`、`[1,3,2]`、`[3,1,2]` 等。

整数数组的**下一个排列**是指其整数的下一个字典序更大的排列。更加正式地，如果数组的所有排列根据其字典顺序从小到大排列在一个容器中，那么数组的下一个排列就是在这个有序容器中排在它后面的那个排列。如果不存在下一个更大的排列，那么这个数组必须重排为最小的排列（也就是升序排列）。

给你一个整数数组 `nums`，找出 `nums` 的下一个排列。必须**原地**修改，只允许使用额外常数空间。

```
示例：
输入：nums = [1,2,3]
输出：[1,3,2]

输入：nums = [3,2,1]
输出：[1,2,3]
解释：[3,2,1] 已经是最大排列（完全降序），下一个排列回到最小排列（完全升序）。

输入：nums = [1,1,5]
输出：[1,5,1]
```

## 思路

这道题其实是个经典的模拟算法题，标准解法分三步走：**从右往左找升序对 → 从右往左找可交换的元素 → 反转后缀**。那要真正理解这个算法，咱们得从"字典序"的本质出发来想问题：什么样的操作，能让一个排列变成"刚好比它大一点点"的下一个排列呢？

**第一步：从右往左找第一个升序对的位置。** 咱们从数组末尾开始往左扫，找到第一个满足 `nums[i] < nums[i+1]` 的位置 `i`——也就是说，`nums[i]` 到数组末尾这一段，从 `i+1` 开始其实是完全降序的，为什么呢？因为要是中途出现了升序，扫描早就在那儿停下来了。这个位置 `i` 的意义在哪呢：`nums[i]` 是从右边数起，第一个"还有潜力变大"的元素。为什么这么说？因为它右边那一段是纯降序的，说白了这已经是这段能排出的最大排列了，如果 `nums[i]` 不变，光调整它右边的顺序，永远得不出比当前排列更大的结果，唯一的出路就是让 `nums[i]` 本身变大一点。那如果扫描完整个数组都找不到这样的位置呢（也就是整个数组从左到右完全降序），说明当前排列已经是所有排列里字典序最大的了，下一个排列就该回到最小排列，也就是把整个数组反转一下（等价于升序排列）。

**第二步：在 `nums[i]` 右侧，也就是 `[i+1, n-1]` 这段降序区间里，从右往左找到第一个大于 `nums[i]` 的元素，记它的位置为 `j`，然后交换 `nums[i]` 和 `nums[j]`。** 你可能会问，为什么非得"从右往左找第一个大于 `nums[i]` 的元素"，随便找一个更大的不行吗？这里的关键是：因为右侧区间是降序排列的，从右往左扫描碰到的第一个比 `nums[i]` 大的元素，恰好就是这个区间里**所有大于 `nums[i]` 的元素中最小的那一个**——降序数组里越靠右元素越小嘛，所以第一个满足条件的必然是这些候选里最小的。用这个最小的、刚好比 `nums[i]` 大一点的元素去换掉 `nums[i]`，才能保证新排列相对旧排列的增量是"刚好够大、不多不少"，这其实就是字典序"下一个"的核心要求——不能跳得太大。

**第三步：把 `[i+1, n-1]` 这段区间整体反转一下。** 交换完 `i` 和 `j` 位置的元素之后，`[i+1, n-1]` 这段其实还是降序的——因为交换只影响了两个位置的值，不会改变其余元素的相对顺序，而且新换进来的这个值也不会破坏降序性，因为它本来就是原区间里第一个大于 `nums[i]` 的元素，其余比它更大的元素都排在它左边，正好符合降序。但你想啊，降序意味着这段目前是"能排出的最大排列"，而咱们希望在固定了前缀（包括 `nums[i]`）之后，后缀部分取到**最小**的排列，这样才能保证整体结果是"刚好比原排列大"，而不是一下跳到更远的排列去。把降序区间整体反转，就变成升序了，也就是这个区间能排出的最小排列。

把这三步串起来看，其实很清晰：第一步定位"必须变大的那一位"，第二步找"变大多少最合适"，第三步让"剩下的位置尽量小"，这三步共同保证了结果是字典序上紧邻当前排列的下一个更大排列，不多不少。

边界条件说一下：数组长度为 1 的时候不存在下一个排列这个概念，函数应该直接返回（或者保持原样），代码里第一步找不到升序对的兜底逻辑天然就覆盖了这种情况。数组里有重复元素的时候（比如示例里的 `[1,1,5]`），这个算法依然成立，因为整个推理过程只依赖"严格小于"和"严格大于"的比较关系，并不要求元素互不相同。

复杂度这块：三步都是线性扫描——找升序对、找交换位置、反转区间，最坏情况下各自把数组遍历一遍，所以总时间复杂度是 O(n)；只用了常数个额外变量（下标和临时交换变量），所以空间复杂度是 O(1)，满足题目原地修改的要求。

## 代码

### C++

```cpp
class Solution {
public:
    void nextPermutation(vector<int>& nums) {
        int n = nums.size();
        int i = n - 2;
        // 第一步：从右往左找第一个升序对 nums[i] < nums[i+1]
        while (i >= 0 && nums[i] >= nums[i + 1]) {
            i--;
        }
        if (i >= 0) {
            int j = n - 1;
            // 第二步：从右往左找第一个大于 nums[i] 的元素
            while (nums[j] <= nums[i]) {
                j--;
            }
            swap(nums[i], nums[j]);  // 交换，让前缀刚好变大一点
        }
        // 第三步：反转 i 之后的区间，使其变为最小排列
        // 如果 i == -1（整个数组降序），reverse 整个数组即为最小排列
        reverse(nums.begin() + i + 1, nums.end());
    }
};
```

### Java

```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;
        int i = n - 2;
        // 第一步：从右往左找第一个升序对 nums[i] < nums[i+1]
        while (i >= 0 && nums[i] >= nums[i + 1]) {
            i--;
        }
        if (i >= 0) {
            int j = n - 1;
            // 第二步：从右往左找第一个大于 nums[i] 的元素
            while (nums[j] <= nums[i]) {
                j--;
            }
            int tmp = nums[i]; nums[i] = nums[j]; nums[j] = tmp;  // 交换
        }
        // 第三步：反转 i 之后的区间，变为最小排列
        reverse(nums, i + 1, n - 1);
    }

    private void reverse(int[] nums, int left, int right) {
        while (left < right) {
            int tmp = nums[left]; nums[left] = nums[right]; nums[right] = tmp;
            left++;
            right--;
        }
    }
}
```

### Python

这道题要求原地修改数组结构，标准库这边没有能直接对应的一行解法——`itertools.permutations` 只能生成全部排列，满足不了原地 O(1) 空间的要求，思路上也不等价，所以这里只给手写实现：

```python
class Solution:
    def nextPermutation(self, nums: list[int]) -> None:
        n = len(nums)
        i = n - 2
        # 第一步：从右往左找第一个升序对 nums[i] < nums[i+1]
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1

        if i >= 0:
            j = n - 1
            # 第二步：从右往左找第一个大于 nums[i] 的元素
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]  # 交换，前缀刚好变大一点

        # 第三步：反转 i 之后的区间，使其变为最小排列
        # i == -1 时（整个数组降序），reverse 整个数组即为最小排列
        left, right = i + 1, n - 1
        while left < right:
            nums[left], nums[right] = nums[right], nums[left]
            left += 1
            right -= 1
```

## 总结

- 这道题的三步——找升序对、找交换元素、反转后缀——分别对应字典序问题里的三个关键子问题：定位"必须变大的位置"、决定"变大多少最合适"、保证"剩余部分尽量小"，把这三步的动机理解透了，就能自己推导出算法本身，根本不需要死记步骤。
- "从右往左找第一个升序对"和"降序区间整体反转就是升序"，这两个观察其实建立在同一个前提上：从后缀开始的降序区间已经是这段能排出的最大排列，反转之后就是最小排列，这个对称性贯穿了整道题。
- 遇到重复元素的时候算法依然是对的，因为整个推理过程只依赖严格大小比较，不需要额外特判——这也提示咱们设计算法的时候要留意条件判断用的是严格比较还是非严格比较，这会直接影响对重复元素处理得对不对。
- 这道题和"上一个排列"（求字典序更小的前一个排列）是个对称问题，只需要把所有大小比较的方向反过来——找降序对、找第一个小于 `nums[i]` 的元素——理解了本质之后就能直接迁移过去解决这个对称的变体问题。
