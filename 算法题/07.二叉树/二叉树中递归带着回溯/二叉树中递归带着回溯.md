# 二叉树中递归带着回溯

**内容概述**

这是一篇方法论文档，不是具体题目，讲二叉树递归中隐含的回溯思想。你会发现很多二叉树题目看起来是"普通的递归遍历"，但说白了本质上是回溯法的一种应用，只是因为写法上没有出现显式的 `pop`/`remove` 操作，容易被大家忽略。这篇就用 0257 题（二叉树的所有路径）作为例子，把这层关系讲清楚。

## 回溯的本质：选择、递归、撤销选择

回溯法的标准模式说白了可以概括成三个动作：**做出一个选择 → 基于这个选择继续递归探索 → 递归返回后撤销这个选择**。这个模式最早出现在排列组合、子集这类显式需要"尝试所有可能性"的问题里，写法通常是这样：

```
def backtrack(路径, 选择列表):
    if 满足终止条件:
        记录路径
        return
    for 选择 in 选择列表:
        做出选择（路径.append(选择)）
        backtrack(路径, 新的选择列表)
        撤销选择（路径.pop()）
```

二叉树的递归遍历天然就符合这个模式，只是"选择列表"变成了"左孩子和右孩子"这两个固定的选项，不需要用 `for` 循环去遍历一组候选项，而是直接写两次递归调用，一次对应左孩子，一次对应右孩子。

## 为什么二叉树所有路径问题是回溯

拿 0257 题来说，你想啊：题目要收集从根到每个叶子节点的路径。用递归维护一个 `path` 数组记录当前路径，递归进入某个子节点前，先把这个子节点的值加入 `path`，这就是"做出选择"，然后递归探索这个子节点的子树，这叫"基于选择继续探索"，等递归调用返回后，如果紧接着要探索另一个方向（比如递归完左子树后要递归右子树），就必须把刚才加入的值从 `path` 中移除，这就是"撤销选择"，为什么呢？因为不撤销的话，`path` 里会残留左子树那一支的节点，导致右子树递归时路径数据是错的。

这个"加入 → 递归 → 移除"的三步，跟排列组合类问题里的回溯代码结构完全一致，只是二叉树场景下"要不要撤销"取决于两个递归调用（左、右）之间是否共享同一个可变的 `path` 对象。

## 隐式回溯：参数传值方式决定是否需要手动撤销

这里要强调一个容易被忽略的点：**即使代码里完全没有出现 `pop`/`remove`，回溯思想依然可能在起作用，只是被参数传递方式"隐藏"了**。

你想啊，如果递归函数在调用子节点前，把 `path` 通过**值传递**的方式往下传，比如 Python 里用 `path + [node.val]` 生成一个全新的列表，而不是在原列表上 `append`，那么每次递归调用拿到的都是一份独立的路径拷贝，父节点的 `path` 不会被子节点的操作影响，兄弟分支之间天然互不干扰。这种情况下，虽然代码里没有显式的撤销操作，但效果和"加入 → 递归 → 手动撤销"完全一样——只是撤销这一步被"重新创建一份新对象"取代了，代价就是每次递归都要拷贝一份数据，空间开销更大。

反过来，如果用**引用传递**，比如 C++/Java 中直接对同一个 `vector`/`ArrayList` 做 `push_back`/`add`，多个递归分支共享的就是同一个底层数据结构了，父节点做的修改会被子节点看到，子节点做的修改在递归返回后也会残留在父节点视角的 `path` 里，这时就必须手动撤销（`pop_back`/`remove`），不然数据会串。

所以说，判断一段二叉树递归代码"有没有回溯"，不能只看有没有 `pop` 这一行代码，而要看：**这个递归过程中，是否存在一个会被多个分支共享、且会被修改的状态**。如果存在，就必须要有某种方式（手动撤销，或者传值拷贝）来保证状态在分支之间不发生串联污染，这两种方式在语义上是等价的，区别只在于是用时间开销（拷贝）还是显式代码（撤销）来解决这个问题。

## 什么时候会用到这个思想

除了收集路径类问题，判断是否存在某条路径满足条件（比如路径总和等于目标值）、统计满足条件的路径数量，本质上都是同一个模式：递归下降的过程中携带一份"当前路径的状态"，到达叶子节点或满足条件时做判断/记录，返回时再视情况撤销状态。理解了这一层，遇到"沿着树的某条路径累积信息，最后在叶子节点判断"这类题目时，你就能很快识别出它属于回溯的范畴，而不是把它当成一个全新的问题类型。

## 总结

- 二叉树递归中"进入子节点前修改状态，递归返回后撤销状态"，说白了本质上就是回溯法"选择-递归-撤销选择"模式的具体体现，只是选择集合固定成了"左孩子、右孩子"这两项。
- 判断代码是否隐含回溯，关键要看是不是存在被多个递归分支共享、而且会被修改的可变状态，而不是看代码里是否出现 `pop`/`remove` 这样的字面操作。
- 值传递（每次创建新对象）和引用传递加手动撤销，是解决"状态污染"问题的两种等价方式，前者用空间换代码简洁性，后者用显式操作换空间效率。
- 涉及"路径"的二叉树题目（收集路径、路径总和判断、路径计数）大多可以用这套回溯思路统一理解，这是判断一类题目归属的一个很有效的方法。
