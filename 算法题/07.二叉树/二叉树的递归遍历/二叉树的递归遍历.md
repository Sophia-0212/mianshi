# 二叉树的递归遍历

**内容概述**

这篇讲二叉树前序、中序、后序遍历的递归实现。你会发现三种遍历的递归代码结构几乎一模一样，唯一的区别就是"访问当前节点"这一行代码放在递归调用左子树、右子树的前面、中间还是后面。理解了这一点，三种遍历就不需要死记硬背了，而是能自己推导出来。

节点定义（后续代码统一使用）：

```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```

## 思路

写递归代码，最容易出问题的地方其实不是逻辑本身，而是"想清楚递归函数该长什么样"这一步。这里咱们用三要素来拆解一下。

**第一要素：确定递归函数的参数和返回值。** 遍历类问题一般不需要返回值，把结果收集到一个外部的 `result` 数组里就行，所以递归函数的参数通常是"当前节点 + 结果收集容器"，返回值是 `void`。如果题目要求递归函数本身返回某个计算结果，比如求深度，那返回值类型就不一样了，但遍历这里咱们先按最简单的情况处理。

**第二要素：确定终止条件。** 二叉树递归的终止条件几乎总是"当前节点为空"，为什么呢？因为空节点没有值可访问，也没有子节点可以继续递归，直接返回就行了。这一步一定要写在最前面，不然会对空指针取值，直接导致运行时错误。

**第三要素：确定单层递归的逻辑。** 这才是三种遍历唯一的区别所在。单层递归要做三件事：处理左子树（递归调用）、处理右子树（递归调用）、处理当前节点（把值放进结果里）。这三件事的**顺序**决定了到底是哪种遍历：

- 前序：当前节点、左子树、右子树 → 根左右
- 中序：左子树、当前节点、右子树 → 左根右
- 后序：左子树、右子树、当前节点 → 左右根

也就是说，三种遍历里，递归调用左右子树的相对顺序永远不变，都是先左后右，变化的只是"处理当前节点"这一步插在哪个位置。这也就解释了为什么把前序遍历的代码稍微挪动一行，就能得到中序或者后序遍历的代码了。

时间复杂度都是 O(n)，因为每个节点恰好被访问一次；空间复杂度是 O(h)，h 是树的高度，这是递归调用栈的开销，最坏情况下树退化成一条链，空间复杂度就是 O(n)。

## 代码

### C++

```cpp
class Solution {
public:
    // 前序遍历：根 -> 左 -> 右
    void preorder(TreeNode* root, vector<int>& result) {
        if (root == nullptr) return;   // 终止条件：空节点直接返回
        result.push_back(root->val);   // 先处理当前节点（根）
        preorder(root->left, result);  // 再递归处理左子树
        preorder(root->right, result); // 最后递归处理右子树
    }

    // 中序遍历：左 -> 根 -> 右
    void inorder(TreeNode* root, vector<int>& result) {
        if (root == nullptr) return;
        inorder(root->left, result);   // 先递归处理左子树
        result.push_back(root->val);   // 左子树处理完后处理当前节点
        inorder(root->right, result);  // 最后递归处理右子树
    }

    // 后序遍历：左 -> 右 -> 根
    void postorder(TreeNode* root, vector<int>& result) {
        if (root == nullptr) return;
        postorder(root->left, result);  // 先递归处理左子树
        postorder(root->right, result); // 再递归处理右子树
        result.push_back(root->val);    // 左右子树都处理完后才处理当前节点
    }
};
```

## 总结

- 二叉树递归遍历的三要素：参数与返回值、终止条件（节点为空）、单层递归逻辑（也就是处理当前节点插入的位置）。
- 前中后序遍历的代码结构完全相同，唯一的区别就是"处理当前节点"这一行代码相对于两次递归调用的位置。
- 递归的时间复杂度是 O(n)，空间复杂度取决于递归调用栈的深度，也就是树的高度 O(h)，最坏情况会退化成 O(n)。
- 理解递归遍历是后面理解迭代遍历（用栈显式模拟）和统一迭代法的基础，说白了迭代版本本质上就是把递归调用栈的行为手动搬到一个显式的栈里去。
