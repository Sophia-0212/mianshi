# 0112. 路径总和

**题目描述**

给你二叉树的根节点 `root` 和一个表示目标和的整数 `targetSum`，判断该树中是否存在**根节点到叶子节点**的路径，这条路径上所有节点值相加等于 `targetSum`。存在则返回 `true`，否则返回 `false`。

```
示例：
输入: root = [5,4,8,11,null,13,4,7,2,null,null,null,1], targetSum = 22
       5
      / \
     4   8
    /   / \
   11  13  4
  /  \      \
 7    2      1
输出: true
解释: 存在路径 5->4->11->2，和为22
```

## 思路

这道题是"二叉树中递归带着回溯"这个思想的一个直接应用：需要沿着一条从根到叶子的路径把节点值累加起来，等到达叶子节点的时候，判断累加结果是不是等于目标值。

一种直观的写法，跟 0257 题类似，是用一个变量记录"从根到当前节点这条路径上所有值的和"，到达叶子节点时判断这个和是不是等于 `targetSum`。但更简洁的写法是**用减法代替加法**：给递归函数传入一个"剩余目标值"，每往下走一层，就把这个剩余目标值减去当前节点的值，这样递归到叶子节点的时候，只需要判断"剩余目标值有没有恰好减到 0"就行了，不需要额外维护一个"当前路径和"再去跟 `targetSum` 比较，逻辑上更直接一些。

具体怎么做呢？

第一步，递归函数接收当前节点和"剩余需要凑够的目标值" `remain`。

第二步，如果当前节点是空的，直接返回 `false`——空节点不可能构成一条有效路径。

第三步，先用当前节点的值去更新 `remain`，也就是 `remain -= node->val`。

第四步，如果当前节点是叶子节点（左右孩子都是空的），那就判断 `remain` 是不是恰好等于 0，是的话就说明找到了一条满足条件的路径，返回 `true`。

第五步，如果不是叶子节点，就递归地去左子树或者右子树里继续找——只要左子树或者右子树里有一条满足条件的路径就行，所以用逻辑或（`||`/`or`）连接两次递归调用的结果。

这里的"回溯"体现得比 0257 题更隐蔽一些。为什么呢？因为 `remain` 是以值传递的方式往下传的——每次递归调用都有自己独立的一份 `remain` 副本，不是共享一个可修改的全局变量——所以递归返回到某一层去尝试另一个分支的时候，这一层的 `remain` 值不会被子递归里的操作污染，这正是"隐式回溯"的体现（在"二叉树中递归带着回溯"那篇里也讨论过：值传递的参数天然就不需要手动去撤销）。如果非要用一个共享的全局变量去记录已经消耗的和，那就必须在递归返回之后手动把这次消耗的值加回去，这属于显式回溯的写法。

时间复杂度是 O(n)，每个节点最多访问一次；空间复杂度是 O(h)，是递归调用栈的开销。

## 代码

二叉树节点定义：

```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```

### C++

```cpp
class Solution {
public:
    // remain 表示还需要凑够多少值才能达到目标，用值传递天然实现隐式回溯
    bool traverse(TreeNode* node, int remain) {
        if (node == nullptr) return false;         // 空节点不构成有效路径
        remain -= node->val;                       // 用当前节点值抵消剩余目标值
        if (node->left == nullptr && node->right == nullptr) {
            // 到达叶子节点，判断是否恰好凑够目标值
            return remain == 0;
        }
        // 只要左子树或右子树中有一条路径满足条件即可
        return traverse(node->left, remain) || traverse(node->right, remain);
    }

    bool hasPathSum(TreeNode* root, int targetSum) {
        if (root == nullptr) return false;  // 空树不存在任何路径
        return traverse(root, targetSum);
    }
};
```

### Java

```java
class Solution {
    public boolean hasPathSum(TreeNode root, int targetSum) {
        if (root == null) return false;   // 空树不存在任何路径
        return traverse(root, targetSum);
    }

    // remain 用值传递（基本类型天然是值传递），实现隐式回溯
    private boolean traverse(TreeNode node, int remain) {
        if (node == null) return false;              // 空节点不构成有效路径
        remain -= node.val;                           // 抵消剩余目标值
        if (node.left == null && node.right == null) {
            return remain == 0;                        // 叶子节点，判断是否恰好凑够
        }
        return traverse(node.left, remain) || traverse(node.right, remain); // 任一子树满足即可
    }
}
```

### Python

```python
class Solution:
    def hasPathSum(self, root, targetSum):
        if root is None:
            return False                 # 空树不存在任何路径
        return self.traverse(root, targetSum)

    def traverse(self, node, remain):
        # remain 用值传递（Python整数不可变，天然实现隐式回溯）
        if node is None:
            return False                 # 空节点不构成有效路径
        remain -= node.val               # 抵消剩余目标值
        if node.left is None and node.right is None:
            return remain == 0           # 叶子节点，判断是否恰好凑够
        return self.traverse(node.left, remain) or self.traverse(node.right, remain)  # 任一子树满足即可
```

### Go

```go
func hasPathSum(root *TreeNode, targetSum int) bool {
    if root == nil {
        return false // 空树不存在任何路径
    }
    return traverse(root, targetSum)
}

// remain 用值传递（Go中int是值类型），实现隐式回溯
func traverse(node *TreeNode, remain int) bool {
    if node == nil {
        return false // 空节点不构成有效路径
    }
    remain -= node.Val // 抵消剩余目标值
    if node.Left == nil && node.Right == nil {
        return remain == 0 // 叶子节点，判断是否恰好凑够
    }
    // 任一子树满足即可
    return traverse(node.Left, remain) || traverse(node.Right, remain)
}
```

## 总结

- 用"剩余目标值不断减去当前节点值，到叶子节点判断是不是恰好为0"这种写法，比维护"当前路径和再跟目标比较"更简洁，这两种逻辑是等价的。
- `remain` 这个参数以值传递的方式在递归中往下传，天然就实现了回溯，不需要手动去撤销状态，这是"隐式回溯"在实际题目里的一个具体应用，正好呼应了本系列里专门讲回溯思想的那篇方法论文档。
- 判断是不是存在满足条件的路径，只需要左子树或者右子树里**任意一条**满足就行，用逻辑或连接两次递归结果，不需要把两侧都探索完再去决策。
- 这道题跟 0257 题（收集所有路径）的区别在于：0257 要收集所有的路径，这道题只需要判断"是否存在"一条路径就够了，所以不需要显式维护一个路径列表，只需要维护一个数值即可，是同一类问题在不同要求下的简化版本。
