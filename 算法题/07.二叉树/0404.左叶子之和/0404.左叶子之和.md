# 0404. 左叶子之和

**题目描述**

给定二叉树的根节点 `root`，返回所有**左叶子之和**。

```
示例：
输入: root = [3,9,20,null,null,15,7]
      3
     / \
    9  20
      /  \
     15   7
输出: 24
解释: 左叶子节点是9和15，9+15=24
```

## 思路

这道题的难点你想啊，其实不在于怎么遍历，而在于怎么准确判断一个节点是不是"左叶子"。这里容易搞混的地方是：判断一个节点是不是叶子很简单，左右孩子都为空就是叶子；但"左叶子"多了一个条件——这个叶子还得同时是它父节点的左孩子。

那问题就来了：光看节点自己是不够的。一个节点是不是叶子，看它自己的左右孩子就行；但它是不是"左"叶子，得看它在父节点眼里是挂在左边还是右边，这个信息节点自己是不知道的。所以说，判断逻辑必须放在父节点这一层去做，不能等递归钻到子节点内部再去问"我是不是左叶子"——因为子节点根本不知道自己是父节点的左孩子还是右孩子。

具体怎么做呢？递归遍历二叉树的时候，每访问到一个节点，就去看它的左孩子存不存在。如果存在，再判断这个左孩子本身是不是叶子节点（也就是它的左右孩子都为空）。如果左孩子存在而且确实是叶子，那就把这个左孩子的值累加进结果里。你看，这个判断动作是在父节点这一层完成的，这样就天然满足了"左叶子"需要结合父子关系来判断的要求。

递归的写法可以这么想：

1. 当前节点为空的话，直接返回 0，这是终止条件。
2. 如果当前节点的左孩子存在，并且是叶子节点，说明找到了一个左叶子，就把它的值算进结果里，可以直接加到返回值上，也可以单独判断了再累加。
3. 否则，也就是左孩子不存在，或者左孩子不是叶子，那就得继续往左子树递归，去更深的地方找。
4. 同时右子树也要递归下去——因为右子树内部也可能藏着"某个节点的左孩子是叶子"的情况，只是这整个右子树相对于原来的根节点来说不算左孩子而已。
5. 最后把左子树递归回来的结果和右子树递归回来的结果加起来，就是当前这棵子树里左叶子的总和。

当然也可以用层序遍历，也就是 BFS 的思路：一层一层遍历的时候，检查每个节点的左孩子，只要左孩子非空并且是叶子，就直接把值累加进去。逻辑上跟递归版本是一样的，只不过是用队列代替了递归调用栈。

时间复杂度这块，每个节点只访问一次，所以是 O(n)；空间复杂度的话，递归法是 O(h)，也就是树的高度，BFS 法最坏情况下是 O(n)。

## 代码

二叉树节点定义：

```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```

### C++

```cpp
class Solution {
public:
    int sumOfLeftLeaves(TreeNode* root) {
        if (root == nullptr) return 0;               // 终止条件：空节点贡献为0
        int leftValue = 0;
        // 判断当前节点的左孩子是否存在且是叶子节点
        if (root->left != nullptr && root->left->left == nullptr && root->left->right == nullptr) {
            leftValue = root->left->val;             // 找到一个左叶子，记录它的值
        } else {
            leftValue = sumOfLeftLeaves(root->left);  // 左孩子不是叶子（或不存在），继续往下找
        }
        int rightValue = sumOfLeftLeaves(root->right); // 右子树内部同样可能藏着左叶子，需要递归
        return leftValue + rightValue;                // 合并左右子树的结果
    }
};
```

### Java

class Solution {
    public int sumOfLeftLeaves(TreeNode root) {
        if (root == null) return 0;                    // 终止条件

    }
}

## 总结

- 说白了，"左叶子"的判断关键就是要结合父子关系：节点自己是不是叶子（左右孩子都空）这个好判断，但"是不是左孩子"这个信息只有在父节点这一层才拿得到，所以判断逻辑得放在父节点那里做，不能等递归进到子节点内部再去判断。
- 递归的时候，"左孩子是叶子"和"左孩子不是叶子或不存在"这两种情况要分开处理：前一种直接把值累加进去，后一种就继续往下递归接着找。
- 右子树这边也不能漏，得照样递归遍历，因为右子树内部同样可能藏着"某个节点的左孩子是叶子"的情况，只是这些左叶子相对于最开始的根节点来说，是处在右子树这个范围里的。
- 那 BFS 的写法呢，逻辑上是等价的，只是用队列迭代代替了递归调用栈，如果不想用递归，或者担心递归深度太深爆栈，用这种写法会更稳一些。
