# 0701. 二叉搜索树中的插入操作

**题目描述**

给定二叉搜索树（BST）的根节点 `root` 和要插入树中的值 `val`，将值 `val` 插入到 BST 中，返回插入后 BST 的根节点。可以假设原始 BST 中不存在与 `val` 相同的值，插入操作可以以任意有效方式完成，只要在插入后，原有的每个不同值对应的节点值保持不变。

```
示例：
输入: root = [4,2,7,1,3], val = 5
输出: [4,2,7,1,3,5]
解释: 5 应该插在 4 的右子树（因为 5>4），再插在 7 的左子树（因为 5<7）。
```

## 思路

这道题的插入操作其实是在 0700（BST 中的搜索）基础上自然延伸出来的。你回想一下 0700 的查找逻辑：从根节点出发，根据目标值和当前节点值的比较结果，决定往左走还是往右走，一直走到找到目标或者走到空节点为止。插入操作走的就是同一条路径，唯一的区别在哪呢？**查找失败的时候（也就是走到空节点了），不是返回 `null`，而是在这个空位置上创建一个新节点**。

具体说说，BST 插入不需要考虑"插入后树是否平衡"这种复杂问题——那是 AVL 树、红黑树这些自平衡结构才要操心的事——这里只需要保持基本的 BST 性质（左小右大）就够了，所以插入的位置是唯一确定的：沿着"比当前节点小就往左走，比当前节点大就往右走"这条路径一直走下去，直到碰到一个空位置，把新值往这一放就完成插入了。

那递归怎么实现呢？

- **终止条件**：如果当前节点为空，说明找到插入位置了，创建一个新节点返回就行（这个新节点会被上一层递归接到 `left` 或者 `right` 上）。
- **单层递归逻辑**：
  - 如果 `val < root->val`：说明新值应该插到左子树里，那就递归调用 `insertIntoBST(root->left, val)`，然后把返回结果重新赋值给 `root->left`——这一步是关键，为什么呢？因为递归返回的可能是新创建的节点，也可能是原来就存在的 `root->left`，这样写就保证了无论哪种情况都能正确地把子树"接回"到 `root` 上。
  - 如果 `val > root->val`：同理，递归处理右子树，`root->right = insertIntoBST(root->right, val)`。
  - 最后返回 `root`（当前节点本身没变，只是它的某个子树可能被更新了）。

这个"递归返回值重新赋值给子节点指针"的写法，在很多二叉树修改类题目里都会反复出现（比如后面的 0450 删除节点、0669 修剪 BST），核心思想是什么呢？**递归函数不仅要完成子树内部的修改，还得负责把修改后的子树正确地"接回"到父节点上**，调用者不用管子树内部到底发生了什么变化，只需要拿返回值去更新对应的指针就行。

当然也可以用迭代写法：用一个指针从根节点开始，按照跟查找一样的规则移动，但同时要记录"当前节点的父节点"，为什么呢？因为一旦确定要往哪个方向走结果发现是空节点，就得马上用父节点的指针把新节点接上去，不像递归那样可以靠返回值自动完成"接回"这个动作。

复杂度这块，因为只需要沿着一条路径走到底，时间复杂度是 O(h)，h 是树高，平衡树下就是 O(log n)，最坏情况（退化成链）会到 O(n)。空间复杂度呢，递归写法是 O(h)（也就是调用栈的开销），迭代写法是 O(1)。

## 代码

二叉树节点定义：

```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```

### C++

```cpp
class Solution {
public:
    // 递归写法
    TreeNode* insertIntoBST(TreeNode* root, int val) {
        if (root == nullptr) {
            return new TreeNode(val); // 找到空位置，创建新节点
        }
        if (val < root->val) {
            root->left = insertIntoBST(root->left, val);  // 插入左子树，并把结果接回
        } else {
            root->right = insertIntoBST(root->right, val); // 插入右子树，并把结果接回
        }
        return root; // 当前节点本身不变，返回给上一层
    }

    // 迭代写法：需要额外记录父节点，才能把新节点接上去
    TreeNode* insertIntoBSTIterative(TreeNode* root, int val) {
        if (root == nullptr) {
            return new TreeNode(val); // 空树，新节点即为根
        }
        TreeNode* cur = root;
        TreeNode* parent = nullptr;
        while (cur != nullptr) {
            parent = cur; // 记录父节点，供后续接回新节点
            cur = (val < cur->val) ? cur->left : cur->right; // 决定移动方向
        }
        if (val < parent->val) {
            parent->left = new TreeNode(val); // 接到父节点左侧
        } else {
            parent->right = new TreeNode(val); // 接到父节点右侧
        }
        return root;
    }
};
```

class Solution:
    def insertIntoBST(self, root: TreeNode, val: int) -> TreeNode:

            root.right = self.insertIntoBST(root.right, val)  # 插入右子树并接回

    def insertIntoBSTIterative(self, root: TreeNode, val: int) -> TreeNode:

        cur = root
        parent = None

            parent.left = TreeNode(val)  # 接到左侧

            parent.right = TreeNode(val)  # 接到右侧

## 总结

- BST 插入说白了就是沿着"比当前节点小往左、比当前节点大往右"这条路径走到空位置，插入位置是唯一确定的，不用考虑树的平衡性。
- 递归写法的关键模式是 `root.left = insertIntoBST(root.left, val)`——用递归返回值重新赋值给子节点指针，这样才能保证修改后的子树被正确"接回"父节点，这个模式后面在删除、修剪类题目里还会反复出现。
- 迭代写法需要额外维护一个 `parent` 指针，为什么呢？因为迭代过程中一旦到达空位置，就得立即用父节点的指针把新节点接上去，不像递归那样可以靠返回值自动完成。
- 时间复杂度取决于树高，也就是 O(h)，因为只需要走一条路径，不用探测整棵树，这跟 0700 的查找操作是同一类效率特征。
