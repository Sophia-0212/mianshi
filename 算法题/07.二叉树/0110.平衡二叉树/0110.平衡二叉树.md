# 0110. 平衡二叉树

**题目描述**

给定一个二叉树，判断它是否是高度平衡的二叉树。这里定义平衡二叉树为：一个二叉树中每个节点的左右两个子树的高度差的绝对值不超过 1。

```
示例1（平衡）：
输入: root = [3,9,20,null,null,15,7]
输出: true

示例2（不平衡）：
输入: root = [1,2,2,3,3,null,null,4,4]
输出: false
```

## 思路

最直接的想法是什么呢？对每个节点，分别递归求出它左右子树的高度，比较一下高度差是不是超过 1，如果所有节点都满足，那就是平衡二叉树。这个思路本身完全正确，但有个效率问题——你想啊，如果每次判断一个节点是否平衡的时候，都重新递归计算一次左右子树高度，那么在自顶向下逐层判断的过程中，子树的高度会被重复算很多次（父节点算高度的时候会递归到子节点，子节点自己判断平衡的时候又要再算一遍高度），这么一来整体时间复杂度就退化到 O(n²) 了。

那优化的关键是什么呢？说白了就是把"求高度"和"判断是否平衡"合并成同一次递归，而且要用**自底向上**的方式：递归函数不仅要返回子树高度，还要在发现不平衡的时候提前标记出来并往上传递这个信息，这样就不用再继续做没意义的计算了。

具体怎么做呢？定义一个递归函数，它返回值的含义是"以当前节点为根的子树的高度"，但如果发现子树本身已经不平衡了，就直接返回一个特殊值（比如 -1）当作"不平衡"的标记，不再继续正常计算高度。

单层递归的逻辑是这样的：

第一步，递归求左子树的高度 `leftHeight`。如果左子树已经标记为不平衡了（返回值是 -1），那当前节点也直接判定为不平衡，返回 -1（不需要再去看右子树了，你可以把这理解成一种剪枝）。

第二步，同理递归求右子树的高度 `rightHeight`，如果已经是 -1 了，直接返回 -1。

第三步，如果左右子树都没出现不平衡的标记，那就比较一下 `abs(leftHeight - rightHeight)` 是不是超过 1。超过的话，当前节点就判定为不平衡，返回 -1；不超过的话，就返回 `max(leftHeight, rightHeight) + 1` 当作当前节点的正常高度，接着往上传递。

那这样一来，因为每个节点只会被访问一次（结果是自底向上传递的，不会重复计算子树高度），整体时间复杂度就降到 O(n) 了。这个"用特殊值标记提前终止"的技巧，在很多需要"边计算边判断"的树形递归题目里都很常用，你可以记住这个套路。

## 代码

二叉树节点定义：

```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```

### C++

```cpp
class Solution {
public:
    // 返回以node为根的子树高度；如果已经不平衡，返回-1作为标记
    int getHeight(TreeNode* node) {
        if (node == nullptr) return 0;               // 终止条件：空树高度为0
        int leftHeight = getHeight(node->left);      // 递归求左子树高度
        if (leftHeight == -1) return -1;             // 左子树已不平衡，直接剪枝返回
        int rightHeight = getHeight(node->right);    // 递归求右子树高度
        if (rightHeight == -1) return -1;             // 右子树已不平衡，直接剪枝返回
        if (abs(leftHeight - rightHeight) > 1) return -1; // 当前节点左右高度差超过1，标记不平衡
        return max(leftHeight, rightHeight) + 1;      // 正常返回当前子树高度
    }

    bool isBalanced(TreeNode* root) {
        return getHeight(root) != -1;  // 只要最终返回值不是-1，说明整棵树平衡
    }
};
```

### Java

```java
class Solution {
    public boolean isBalanced(TreeNode root) {
        return getHeight(root) != -1;  // 只要不是-1，说明整棵树平衡
    }

    // 返回以node为根的子树高度；不平衡时返回-1
    private int getHeight(TreeNode node) {
        if (node == null) return 0;                    // 终止条件
        int leftHeight = getHeight(node.left);          // 左子树高度
        if (leftHeight == -1) return -1;                // 左子树已不平衡，剪枝
        int rightHeight = getHeight(node.right);         // 右子树高度
        if (rightHeight == -1) return -1;                // 右子树已不平衡，剪枝
        if (Math.abs(leftHeight - rightHeight) > 1) return -1; // 高度差超过1，标记不平衡
        return Math.max(leftHeight, rightHeight) + 1;    // 正常返回高度
    }
}
```

### Go

```go
func isBalanced(root *TreeNode) bool {
    return getHeight(root) != -1 // 只要不是-1，说明整棵树平衡
}

// 返回以node为根的子树高度；不平衡时返回-1
func getHeight(node *TreeNode) int {
    if node == nil {
        return 0 // 终止条件
    }
    leftHeight := getHeight(node.Left) // 左子树高度
    if leftHeight == -1 {
        return -1 // 左子树已不平衡，剪枝
    }
    rightHeight := getHeight(node.Right) // 右子树高度
    if rightHeight == -1 {
        return -1 // 右子树已不平衡，剪枝
    }
    diff := leftHeight - rightHeight
    if diff > 1 || diff < -1 {
        return -1 // 高度差超过1，标记不平衡
    }
    if leftHeight > rightHeight {
        return leftHeight + 1 // 正常返回高度
    }
    return rightHeight + 1
}
```

## 总结

- 朴素解法在每个节点都重新算一次子树高度，会造成大量重复计算，时间复杂度会退化到 O(n²)。
- 优化解法把"求高度"和"判断平衡"合并到同一次后序遍历里，用 -1 当作"已发现不平衡"的标记，一旦某个子树标记为不平衡，就立即往上返回，不再继续算下去，实现提前剪枝。
- 优化之后每个节点只访问一次，时间复杂度降到 O(n)，空间复杂度就是递归调用栈的开销 O(h)。
- 这种"用特殊返回值同时携带结果和错误/终止信号"的技巧，在树形递归里是很常见的性能优化手段，值得你在类似题目里举一反三。
