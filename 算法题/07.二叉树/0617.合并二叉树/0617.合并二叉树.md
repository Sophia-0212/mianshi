# 0617. 合并二叉树

**题目描述**

给定两棵二叉树 `root1` 和 `root2`，想象当你将其中一棵覆盖到另一棵上时，两棵树的一些节点会重叠，而另一些节点则不会。你需要将这两棵树合并成一棵新树。合并的规则是：如果两个节点重叠，那么将两个节点的值相加作为合并后节点的新值；否则，不为 `null` 的节点将直接作为新树的节点。

```
示例：
输入: root1 = [1,3,2,5], root2 = [2,1,3,null,4,null,7]
输出: [3,4,5,5,4,null,7]
解释: 对应位置节点值相加，root1 有的位置 root2 没有（或反过来），直接用存在的那个节点。
```

## 思路

这道题算是二叉树递归里最简单的一类了，说白了就是"同时遍历两棵树，对应位置做点处理"。核心逻辑可以归纳成一句话：只要有一个节点非空，结果树在这个位置就得有节点；只有两个节点都为空的时候，结果才是空。

具体到递归的三要素上说一下。

终止条件是这样的：如果 `root1` 为空，那就直接返回 `root2`——不管 `root2` 是不是也为空，都拿它作为结果，如果 `root2` 恰好也是空的，那返回的自然就是空。反过来，如果 `root2` 为空，就直接返回 `root1`。你看，这两个判断合起来，就已经把"至少一个为空"的所有情况都覆盖了，根本不需要再单独去判断"两个都为空"这种情况，因为那种情况早就被"`root1` 为空则返回 `root2`，此时 `root2` 也恰好为空"这一条给覆盖掉了。

单层递归逻辑是这样的：如果两个节点都非空，能走到这一步就说明两棵树在当前位置都有节点，这时候才需要真正做合并——把 `root2` 的值加到 `root1` 上面，也就是 `root1->val += root2->val`，然后递归合并左子树 `root1->left` 和 `root2->left`，把结果挂到 `root1->left` 上；右子树同理递归合并。最后返回 `root1`，作为这个位置合并完之后的节点。

那这里有个问题，要不要新建一棵树呢？上面这种写法是直接在 `root1` 的基础上改，把 `root1` 当作最终结果返回，这样能省去创建新节点的开销，但代价是会破坏 `root1` 原来的结构——如果调用者后面还要用到原始的 `root1`，这种写法就不合适了。另一种更"干净"的写法是每次都用 `new TreeNode(root1->val + root2->val)` 创建一个全新的节点，不改动任何一棵原树，这样空间上多花 O(n) 去创建新节点，但能保留两棵输入树的完整性。这其实是个很典型的、面试时可以主动拿出来讨论的权衡点：工程上如果后面不再需要原树了，直接复用 `root1` 会更省内存；如果需要保留原树，那就应该新建节点。这里代码把两种写法都实现了，默认版本用的是复用 `root1` 的写法，这也是比较常见的推荐解法，同时也附带了新建节点的版本。

复杂度这块，递归只会访问两棵树中较小那部分对应的所有节点对，一旦某一边为空就停止递归了。设两棵树节点数分别是 `m` 和 `n`，那时间复杂度就是 O(min(m, n))；空间复杂度是递归调用栈的开销，也是 O(min(depth1, depth2))。

## 代码

二叉树节点定义：

```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```

### C++

```cpp
class Solution {
public:
    // 复用 root1 的结构，直接在其上修改（省空间，但会破坏原树）
    TreeNode* mergeTrees(TreeNode* root1, TreeNode* root2) {
        if (root1 == nullptr) return root2; // root1 为空，结果取决于 root2（可能也为空）
        if (root2 == nullptr) return root1; // root2 为空，直接用 root1
        root1->val += root2->val;             // 两者都非空，值相加
        root1->left = mergeTrees(root1->left, root2->left);   // 递归合并左子树
        root1->right = mergeTrees(root1->right, root2->right); // 递归合并右子树
        return root1;
    }

    // 新建节点版本，不修改任意一棵原树
    TreeNode* mergeTreesNew(TreeNode* root1, TreeNode* root2) {
        if (root1 == nullptr) return root2;
        if (root2 == nullptr) return root1;
        TreeNode* node = new TreeNode(root1->val + root2->val); // 新建节点承载合并结果
        node->left = mergeTreesNew(root1->left, root2->left);
        node->right = mergeTreesNew(root1->right, root2->right);
        return node;
    }
};
```

## 总结

- 合并二叉树的核心就是"两棵树同步递归"：只要有一个节点非空，结果就要保留这个位置的节点；两个都为空的时候，才是真正的空。
- 终止条件那两行判断——`root1` 为空就返回 `root2`，`root2` 为空就返回 `root1`——已经隐式地覆盖了"两者都为空"这种情况，不需要再额外判断。
- 要不要复用原树结构，这是个工程上的权衡点：复用能省空间，但会破坏原树；新建节点能保留原树，但要多花 O(n) 空间，面试的时候可以主动把这个权衡点提出来聊一聊。
- 时间复杂度取决于两棵树里比较小的那一棵，因为递归只要碰到任意一侧为空，就不会再往下深入了。
