# 0222. 完全二叉树的节点个数

**题目描述**

给你一棵完全二叉树的根节点 `root`，求出该树的节点个数。

```
示例：
输入: root = [1,2,3,4,5,6]
       1
      / \
     2   3
    / \  /
   4  5 6
输出: 6
```

## 思路

**先说通用解法：O(n) 递归。** 不管这棵树是不是完全二叉树，都可以用最普通的后序遍历思路来想：以某个节点为根的这棵树，它的节点总数等于左子树节点数加右子树节点数，再加上它自己这一个。这个方法对任意二叉树都成立，但你会发现它根本没用上"完全二叉树"这个特殊条件，时间复杂度是 O(n)，因为每个节点都得访问一遍。

**那怎么优化呢？利用完全二叉树的性质，能做到 O(log n × log n)。** 完全二叉树有个很关键的性质：**一棵完全二叉树，要么整棵树就是满二叉树，要么最多只有一侧子树不是满的**。基于这一点，我们可以设计一个更快的判断方法：

1. 分别沿着"一直往左走"和"一直往右走"这两条路径，统计出左子树的深度 `leftDepth` 和右子树的深度 `rightDepth`——这一步只需要 O(log n)，因为只是走一条路径走到底而已。
2. 如果 `leftDepth == rightDepth`，说明了什么呢？说明当前这棵树是一棵**满二叉树**。为什么呢？因为在完全二叉树里，只有满二叉树才会出现"最左路径和最右路径长度相等"这种情况。这时候就可以直接套公式 `2^depth - 1` 把节点总数算出来，都不需要再往下递归了。
3. 那如果 `leftDepth != rightDepth` 呢？这就说明当前这棵树不是满的，但是根据完全二叉树的性质，**左子树和右子树里必然有一个是满二叉树**：具体来说，如果左子树深度比右子树深度大，左子树本身不一定是满的，但按照完全二叉树的填充规则，往往是右子树是满的（也就是深度较小的那棵子树是满的），这个时候就去递归处理不满的那一侧，满的那一侧直接套公式算就行了。

说得更严谨一点，具体做法是：先算出根节点一直往左走到底的深度 `leftDepth`，和一直往右走到底的深度 `rightDepth`。如果两者相等，那当前整棵树就是满二叉树，直接返回 `2^leftDepth - 1`。如果不相等，说明这棵树不满，这时候就递归求解 `countNodes(root->left) + countNodes(root->right) + 1`，但关键是——因为完全二叉树每次递归的时候，总能排除掉已经确定是满二叉树的那一侧（那一侧可以直接用公式算），所以整体的递归深度只有 O(log n) 层，而每一层判断是不是满二叉树的开销又是 O(log n)，所以加起来总的时间复杂度就是 O(log n × log n)。

这个优化解法的价值在哪呢？就是它展示了"怎么利用题目给定的特殊结构（这里是完全二叉树）把通用算法的复杂度降下来"，说白了这是一道很经典的、考察你对数据结构性质理解程度的题。

class TreeNode:

### C++

```cpp
class Solution {
public:
    // 通用解法：O(n) 后序遍历
    int countNodesGeneral(TreeNode* root) {
        if (root == nullptr) return 0;               // 终止条件
        int leftCount = countNodesGeneral(root->left);   // 左子树节点数
        int rightCount = countNodesGeneral(root->right); // 右子树节点数
        return leftCount + rightCount + 1;            // 加上自己
    }

    // 优化解法：利用完全二叉树性质，O(log n * log n)
    int countNodes(TreeNode* root) {
        if (root == nullptr) return 0;
        TreeNode* left = root->left;
        TreeNode* right = root->right;
        int leftDepth = 0, rightDepth = 0;
        while (left) { leftDepth++; left = left->left; }    // 一直往左走到底，统计深度
        while (right) { rightDepth++; right = right->right; } // 一直往右走到底，统计深度
        if (leftDepth == rightDepth) {
            // 左右深度相等，说明是满二叉树，直接用位运算公式 2^depth - 1
            return (1 << (leftDepth + 1)) - 1;
        }
        // 不是满二叉树，递归左右子树（其中必有一侧下一层判断会命中满二叉树分支）
        return countNodes(root->left) + countNodes(root->right) + 1;
    }
};
```

    }
}

### Python

```python
class Solution:
    def countNodesGeneral(self, root):
        # 通用解法：O(n)
        if root is None:
            return 0
        left_count = self.countNodesGeneral(root.left)
        right_count = self.countNodesGeneral(root.right)
        return left_count + right_count + 1

    def countNodes(self, root):
        # 优化解法：O(log n * log n)
        if root is None:
            return 0
        left, right = root.left, root.right
        left_depth, right_depth = 0, 0
        while left:              # 一直往左走到底，统计深度
            left_depth += 1
            left = left.left
        while right:              # 一直往右走到底，统计深度
            right_depth += 1
            right = right.right
        if left_depth == right_depth:
            return (1 << (left_depth + 1)) - 1   # 满二叉树，公式计算
        return self.countNodes(root.left) + self.countNodes(root.right) + 1  # 递归处理
```

func countNodes(root *TreeNode) int {
    if root == nil {
        return 0
    }
    left, right := root.Left, root.Right
    leftDepth, rightDepth := 0, 0
    for left != nil { // 一直往左走到底，统计深度

        left = left.Left

        right = right.Right

## 总结

- 通用解法就是用后序遍历，累加左右子树的节点数就行，能适用于任意二叉树，复杂度是 O(n)。
- 优化解法呢，利用的是完全二叉树"最左路径深度等于最右路径深度时，一定是满二叉树"这个性质，把满二叉树那部分直接用公式 `2^depth - 1` 算出来，不用再一个个节点去访问了。
- 优化解法的递归深度是 O(log n)，每一层还需要花 O(log n) 的时间去统计左右深度，所以总的复杂度是 O(log n × log n)，比通用解法快得多。
- 这道题的价值就在于，它展示了"通用算法 + 特殊结构性质 = 更优解法"这样一种思路，算是数据结构性质应用类题目里比较有代表性的一道。
