# 二叉树理论基础

**内容概述**

二叉树是后面所有二叉树相关题目的地基。这篇不讲具体题目，就是把二叉树的基本概念、分类和存储方式理清楚，免得后面刷题的时候对"满二叉树""完全二叉树"这类术语产生混淆。

## 二叉树的定义

二叉树是每个节点最多有两个子节点的树结构，这两个子节点分别称为左孩子和右孩子。二叉树的节点定义一般是这样：

```
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};
```

二叉树可以是空树，一个节点都没有，也可以只有一个根节点，或者继续向下延伸出左右子树。这里的关键是，左右子树本身又是一棵二叉树，这个"自相似"的性质正是后面所有递归解法成立的根本原因：一棵二叉树的问题可以拆解成根节点 + 左子树问题 + 右子树问题。

## 几种特殊的二叉树

**满二叉树**：如果一棵二叉树只有度为 0 和度为 2 的节点，也就是每个节点要么是叶子，要么恰好有两个孩子，并且所有叶子节点都在同一层，那这棵树就是满二叉树。深度为 k 的满二叉树，节点总数是 2^k - 1。

**完全二叉树**：除了最底层，其他层的节点数都达到最大值，而且最底层的节点都集中在左边连续排列，不能有"中间空一个"的情况。你想啊，完全二叉树是堆的基础结构，也是后面数组存储二叉树能够成立的前提——正因为节点排列是连续且左对齐的，才能用简单的下标公式去定位父子关系。这里要注意，完全二叉树并不要求最后一层的节点必须占满，只要求是从左往右连续填充就行。

**二叉搜索树（BST）**：这个就不一样了，是有数值大小约束的树，不再只关注形状。对树中任意一个节点，其左子树上所有节点的值都得小于该节点值，右子树上所有节点的值都得大于该节点值。这个性质就带来一个好处：二叉搜索树的中序遍历结果一定是一个递增序列，这也是后面很多 BST 相关题目（比如验证 BST、BST 中的搜索）的核心突破口。

**平衡二叉搜索树（AVL）**：在满足 BST 性质的基础上，还要进一步要求任意节点的左右两个子树的高度差不超过 1。为什么要平衡呢？就是为了保证查找、插入、删除操作都能维持在 O(log n)——如果不做平衡处理，BST 在最坏情况下（比如插入的数据本身就是有序的）会退化成一条链，操作复杂度就退化成 O(n) 了。C++ 的 `map`、`set`，Java 的 `TreeMap`、`TreeSet` 底层都是用红黑树（一种更宽松的自平衡 BST）实现的。

这几个概念容易搞混的地方在于：满二叉树和完全二叉树描述的是"形状"，二叉搜索树描述的是"数值排列规则"，平衡二叉树描述的是"高度约束"。这三者是从不同维度定义的，一棵树可以同时满足多个条件，比如既是完全二叉树又是 BST，也可以互不相关。

## 二叉树的存储方式

二叉树可以用链式存储，也可以用数组存储。

**链式存储**是最常见的方式，每个节点包含一个值域和指向左右孩子的指针（或引用/None）。这种方式的好处是插入删除很灵活，不需要预先分配连续空间，缺点呢就是访问某个节点必须从根节点开始沿着指针一步步找，没有随机访问的能力。

**数组存储**只对完全二叉树友好。为什么呢？因为完全二叉树的节点是从左到右连续排列的，可以把根节点放在数组下标 0（或 1，看约定）的位置，然后对于下标为 `i` 的节点：

- 左孩子下标：`2*i + 1`（如果从 0 开始）
- 右孩子下标：`2*i + 2`
- 父节点下标：`(i - 1) / 2`

堆（大顶堆/小顶堆）就是用数组存储完全二叉树的典型例子。堆本身是一棵完全二叉树，而且满足"父节点的值大于等于（或小于等于）子节点的值"，所以可以直接用一个连续数组来表示，不需要额外的指针开销，插入和删除堆顶元素的时候，通过数组下标运算就能定位父子关系，效率很高。那如果一棵二叉树不是完全二叉树呢？用数组存储就会在中间产生大量空洞（因为要按照满二叉树的编号规则预留位置），空间浪费很严重，所以普通二叉树基本不会用数组存储。

## 二叉树的遍历方式总览

二叉树的遍历分为两大类：深度优先遍历（DFS）和广度优先遍历（BFS）。

**深度优先遍历**包括前序、中序、后序三种，区别只在于"访问根节点"这一步发生的时机：

- 前序遍历：根 → 左 → 右（先访问根节点）
- 中序遍历：左 → 根 → 右（根节点在中间访问）
- 后序遍历：左 → 右 → 根（最后访问根节点）

这三种遍历都可以用递归实现，也可以用栈模拟实现迭代版本，这两者本质上是等价的——递归调用本身就是系统栈在帮你维护"未处理完的节点"，你手写迭代版本说白了只是把这个隐式的栈显式地拿出来自己控制而已。

**广度优先遍历**就是层序遍历，一层一层从上到下、从左到右去访问。层序遍历天然适合用队列来实现：把根节点入队，每次出队一个节点就把它的孩子入队，一直到队列为空。这里的关键是，层序遍历不太适合用递归的方式自然表达，虽然也能用递归实现按层收集，但需要显式传递层数参数，不如迭代直观。

DFS 和 BFS 怎么选？如果题目关心的是"路径"相关的信息，比如从根到叶子的某条路径、某条路径的和，那 DFS 更自然，因为递归本身就是在模拟一条从根到当前节点的路径；如果题目关心的是"层"相关的信息，比如每一层的节点数量、找某一层最左边的节点、判断是否是完全二叉树的层次结构，那 BFS 更直接，因为队列天然就是按层组织数据的。

## 总结

- 二叉树的分类要分清维度：满二叉树/完全二叉树是形状约束，BST 是数值约束，平衡二叉树是高度约束，这几种约束可以叠加，也可以各自独立存在。
- 数组存储只对完全二叉树高效，堆就是数组存储二叉树的典范应用，普通二叉树一般还是用链式存储。
- 前中后序遍历的代码结构几乎相同，区别只是访问根节点的时机不同；层序遍历用队列实现，是二叉树中 BFS 的标准写法。
- 后面的具体题目会反复用到这里的结论：涉及路径的用 DFS（递归），涉及层信息的用 BFS（队列）。
