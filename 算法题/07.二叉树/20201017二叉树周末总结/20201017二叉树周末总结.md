# 二叉树周末总结（2020.10.17）

**内容概述**

这周做的题目集中在两大主题：一是 BST（二叉搜索树）相关题目共享的核心技巧——利用有序性剪枝、中序遍历得到有序序列、`pre` 指针记录相邻关系；二是普通二叉树求最近公共祖先（0236）的回溯思路。这篇总结把这些技巧串联起来，梳理它们之间的联系和区别。

## BST 核心技巧一：利用有序性剪枝

BST 最本质的性质是"左子树全部小于根节点，右子树全部大于根节点"，你想啊，这个性质带来的最直接好处是什么呢？**很多操作不再需要探测两个方向，只需要根据值的大小比较，就能确定唯一的前进方向**。

- **0700（BST 中的搜索）**：查找一个值，普通二叉树需要左右都递归探测，但 BST 只需要比较目标值和当前节点值，就能直接确定往左还是往右走。
- 这个思路说白了本质上就是把"二分查找"从有序数组迁移到了树形结构上：数组的"中点"变成了"当前节点"，数组的"左右半区"变成了"左右子树"，你把这个对应关系想清楚了就懂了。

**那复杂度上能收益多少呢？** 在树相对平衡的情况下，这类操作的时间复杂度是 O(log n)，而不利用有序性的普通二叉树操作往往是 O(n)。但要注意，如果 BST 退化成一条链了，比如插入的数据本身就是严格递增或递减的，复杂度就会退化回 O(n)，这也是为什么会有"平衡二叉搜索树"（比如 AVL 树、红黑树）存在的意义。

## BST 核心技巧二：中序遍历得到有序序列

BST 还有一个关键性质：**对 BST 做中序遍历，结果是一个（非严格或严格，取决于是否有重复值）递增序列**。这个性质衍生出了一整类"转化为处理有序序列"的解题思路：

- **0098（验证二叉搜索树）**：判断是否合法 BST，说白了等价于判断中序遍历结果是不是严格递增。
- **0530（BST 的最小绝对差）**：最小差值必然出现在中序遍历相邻元素之间，不需要去比较所有节点两两组合。
- **0501（BST 中的众数）**：相同的值在中序遍历结果中必然连续排列，可以边遍历边统计连续出现的次数。

## BST 核心技巧三：pre 指针技巧

0530 和 0501 这两道题都用到了同一个编码模式：**在中序遍历的过程中，用一个 `pre` 指针记录"上一个访问的节点"，处理当前节点的时候，把当前节点和 `pre` 做比较，再更新 `pre`**。

```
// pre 指针模式伪代码（中序遍历）
def inorder(node):
    if node is None: return
    inorder(node.left)
    if pre is not None:
        与 pre 比较，更新答案（最小差值 / 连续计数等）
    pre = node
    inorder(node.right)
```

这个模式的价值在哪呢？**不需要真的把整个中序遍历结果存到一个数组里再去遍历比较**，而是把"存储+二次遍历"压缩成了"边遍历边比较"的单次遍历，这样额外空间就从 O(n)（存储序列）降到了 O(1)（只需要几个标量变量）。这是一个通用的空间优化技巧，只要问题的答案只依赖"相邻元素关系"，你就可以考虑用这个模式。

## 普通二叉树的回溯思路：最近公共祖先（0236）

0236 跟前面几道 BST 题目不一样，处理的是**普通二叉树**，没有有序性可以利用，所以不能走"确定方向"这个捷径，必须真正地去探测左右两侧子树。

核心思路是**后序遍历回溯**：递归函数在探测完左右子树之后，根据左右子树各自的返回结果，判断当前节点是不是最近公共祖先——如果左右子树分别找到了 `p` 和 `q`，当前节点就是答案；如果只有一侧找到了，就把结果往上传递。

这里为什么"后序遍历"是必须的呢？因为**判断当前节点的角色，依赖于已经知道左右子树的查找结果**，这是一种"先解决子问题，再利用子问题的答案解决当前问题"的分治思想，跟递归遍历里"后序适合处理需要先知道子树信息才能算出当前节点结果"这种场景（比如求树的高度、判断平衡二叉树）说白了其实是同一类模式。

## 技巧对比小结

| 题目 | 树类型 | 核心技巧 | 时间复杂度 |
|------|--------|----------|------------|
| 0700 | BST | 有序性剪枝，确定唯一方向 | O(log n)~O(n) |
| 0098 | BST | 中序遍历判断严格递增 | O(n) |
| 0530 | BST | 中序遍历 + pre 指针求最小差 | O(n) |
| 0501 | BST | 中序遍历 + pre 指针统计连续频率 | O(n) |
| 0236 | 普通二叉树 | 后序遍历回溯，左右子树结果合并判断 | O(n) |

从这张表你能看出一条很清晰的界线：**能不能用"确定方向、只探测一侧"的方式加速，取决于这棵树是不是有序的（BST）**。有序性存在的时候，不管是查找还是统计，都能设计出比 O(n) 更优或者更省空间的解法；一旦失去了有序性，也就是普通二叉树，就必须老老实实地去探测所有相关节点，这时候"后序遍历回溯"就是处理"需要综合左右子树信息才能判断当前节点"这类问题的标准武器。

## 小结

- BST 题目的解题第一反应应该是：能不能利用"左小右大"这个有序性来减少探测范围？能不能把问题转化成处理中序遍历得到的有序序列？
- `pre` 指针 + 中序遍历是处理"BST 相邻节点关系"类问题（比如求最小差、求众数等）的通用省空间技巧，说白了本质上就是把"存储+二次遍历"压缩成了单次遍历。
- 普通二叉树没有有序性可以利用的时候，就回到"后序遍历回溯"这个分治思路：先递归得到左右子树的结果，再综合判断当前节点的角色。
