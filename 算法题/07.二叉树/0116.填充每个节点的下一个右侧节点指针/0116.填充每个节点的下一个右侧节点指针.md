# 116. 填充每个节点的下一个右侧节点指针

**题目描述**

给定一棵**完美二叉树**（每一层的节点都被完全填充，且所有叶子节点都在同一层），树的每个节点除了 `left`、`right` 指针外，还多了一个 `next` 指针。请填充每个节点的 `next` 指针，让它指向其同一层的右侧下一个节点。如果找不到下一个右侧节点，则将 `next` 设为 `null`。初始状态下所有 `next` 指针都为 `null`。

```
示例：
输入: root = [1,2,3,4,5,6,7]
输出: [1,#,2,3,#,4,5,6,7,#]
解释: 给定的二叉树是完美二叉树，
      填充后：第 1 层的 1 的 next 指向 null（因为它是本层唯一节点）
      第 2 层：2 -> 3 -> null
      第 3 层：4 -> 5 -> 6 -> 7 -> null
      （# 表示每层的结尾，即该层最后一个节点的 next 是 null）
```

## 思路

这道题我一般会想到两种解法：一种是比较通用、但要多花点空间的层序遍历；另一种呢，是利用"完美二叉树"这个特殊条件，做到 O(1) 额外空间。我先说说思路，再讲讲为什么最终选了第二种。

**思路一：BFS 层序遍历（通用解法，先说一下）**

最直观的想法就是一层一层处理：用一个队列做标准的层序遍历，每次把一整层的节点都取出来，按从左到右的顺序，依次把前一个节点的 `next` 指向后一个节点，最后一个节点的 `next` 保持 `null` 就行。这个方法的好处是不依赖"完美二叉树"这个特殊条件，随便什么二叉树，只要每层节点顺序明确，都能用。但问题是，队列本身要占 O(n) 的额外空间去存每一层的节点，这就是它的代价。

**思路二：利用已经连好的 next 指针去连下一层（O(1) 额外空间，这道题我用的是这个）**

题目特意限定了是"完美二叉树"，这一点很关键，正是因为有这个条件，才能把队列省掉。你想啊，完美二叉树能保证什么？它保证只要一个节点有孩子，那左右孩子一定是成对出现的，不会出现只有一侧孩子的情况，而且同一层的节点数量都是固定的。

那核心思路是什么呢？说白了就是**利用上一层已经连好的 next 链条，去推出下一层怎么连**。你可以这么想：假设当前这一层（第 k 层）所有节点的 `next` 指针已经全部连好了，形成了一条从左到右的链。那现在要连第 k+1 层，可以这样一步步来：

1. 从第 k 层最左边的节点开始，把它当作"当前层遍历指针"，叫它 `cur`。
2. 对 `cur` 指向的每个节点来说，它左孩子的 `next` 应该指向它自己的右孩子——为什么呢？因为这两个孩子在下一层本来就是相邻的，也就是 `cur.left.next = cur.right`。
3. 这里有个关键点：如果 `cur` 在当前层还有下一个节点（也就是 `cur.next` 不为空），那么 `cur` 的右孩子的 `next` 就应该指向 `cur.next` 的左孩子，写成代码就是 `cur.right.next = cur.next.left`。为什么要单独处理这一步呢？因为这是跨越两个不同父节点、把下一层"接壤的地方"连起来的关键——`cur` 的右孩子和 `cur.next` 的左孩子，在第 k+1 层其实是紧挨着的两个节点，中间没别的东西，所以必须靠这一步把它们连上。
4. 然后把 `cur` 沿着当前层的 next 链条往右挪一位（也就是 `cur = cur.next`），重复第 2、3 步，一直走到当前层走完为止。
5. 当前层处理完之后，第 k+1 层的 next 指针其实就全部连好了。这时候把"层的起点"往下移到第 k+1 层最左边的节点上（也就是原来第 k 层起点的 `left` 孩子），然后重复上面这个过程，一直到某一层的起点没有左孩子了，说明已经走到最后一层，就可以停了。

那这个方法为什么是对的呢？关键在于它靠的是一个归纳的性质：**只要上一层的 next 链条连好了，就一定能推出下一层的链条怎么连**。根节点自己就是第一层，它天然只有自己一个节点，next 本来就是 null，不需要额外处理，正好可以当作归纳的起点。

再说说边界条件：如果某一层起点节点的 `left` 是空的，那就说明已经到叶子层了（完美二叉树能保证同一层的节点要么都有孩子、要么都没有），这时候就该停止遍历了。另外第 3 步里判断 `cur.next` 是否存在也是必须的，如果 `cur` 已经是本层最后一个节点了，那就不用再做跨节点的连接了。

复杂度这块，两种方法的时间复杂度都是 O(n)，因为每个节点都只会被访问常数次。空间复杂度上就不一样了：BFS 那种方法需要 O(n)（最坏情况下某一层能有 n/2 个节点堆在队列里，量级上还是 O(n)）；而利用已有 next 指针这种做法，只用了几个指针变量，完全不需要队列也不需要递归栈，才是真正意义上的 O(1) 额外空间——当然这里说的不算输入树本身占的空间。

## 代码

以下四种语言均采用**思路二（O(1) 空间，利用已连接的 next 层间递进）**实现。

### C++

```cpp
class Node {
public:
    int val;
    Node* left;
    Node* right;
    Node* next;

    Node() : val(0), left(nullptr), right(nullptr), next(nullptr) {}
    Node(int _val) : val(_val), left(nullptr), right(nullptr), next(nullptr) {}
};

class Solution {
public:
    Node* connect(Node* root) {
        if (root == nullptr) return root;

        Node* levelStart = root;  // 当前层的最左节点，作为每层的起点
        while (levelStart->left != nullptr) {  // 只要还有下一层（有左孩子）就继续
            Node* cur = levelStart;  // cur 沿当前层的 next 链条向右移动
            while (cur != nullptr) {
                cur->left->next = cur->right;  // 同一父节点下，左孩子的 next 指向右孩子
                if (cur->next != nullptr) {
                    // 跨父节点连接：cur 的右孩子 next 指向 cur.next 的左孩子
                    cur->right->next = cur->next->left;
                }
                cur = cur->next;  // 沿当前层链条前进，处理下一个父节点
            }
            levelStart = levelStart->left;  // 下移到下一层的最左节点
        }
        return root;
    }
};
```

### Python

标准库没有针对这种"树内指针原地连接"问题的一行解法，本题只写手写实现：

```python
class Node:
    def __init__(self, val=0, left=None, right=None, next=None):
        self.val = val
        self.left = left
        self.right = right
        self.next = next


class Solution:
    def connect(self, root: 'Node') -> 'Node':
        if root is None:
            return root

        level_start = root  # 当前层的最左节点，作为每层的起点
        while level_start.left is not None:  # 只要还有下一层（有左孩子）就继续
            cur = level_start  # cur 沿当前层的 next 链条向右移动
            while cur is not None:
                cur.left.next = cur.right  # 同一父节点下，左孩子 next 指向右孩子
                if cur.next is not None:
                    # 跨父节点连接：cur 的右孩子 next 指向 cur.next 的左孩子
                    cur.right.next = cur.next.left
                cur = cur.next  # 沿当前层链条前进，处理下一个父节点

            level_start = level_start.left  # 下移到下一层的最左节点

        return root
```

面试考察点：能不能想清楚"用上一层已经建好的 next 链条去推出下一层"这个归纳思路，尤其是"跨父节点连接"（也就是 `cur.right.next = cur.next.left`）这一步，这是这道题能从 O(n) 空间优化到 O(1) 空间的关键难点所在。

### Go

```go
type Node struct {
    Val   int
    Left  *Node
    Right *Node
    Next  *Node
}

func connect(root *Node) *Node {
    if root == nil {
        return root
    }

    levelStart := root // 当前层的最左节点，作为每层的起点
    for levelStart.Left != nil {  // 只要还有下一层就继续
        cur := levelStart // cur 沿当前层的 next 链条向右移动
        for cur != nil {
            cur.Left.Next = cur.Right // 同一父节点下，左孩子 next 指向右孩子
            if cur.Next != nil {
                // 跨父节点连接
                cur.Right.Next = cur.Next.Left
            }
            cur = cur.Next // 沿当前层链条前进
        }
        levelStart = levelStart.Left // 下移到下一层最左节点
    }
    return root
}
```

## 总结

- BFS 层序遍历是比较通用的解法，思路简单，但代价是要用 O(n) 的队列空间；而利用已经连好的 next 链条逐层往下推的方法呢，能做到 O(1) 额外空间，不过它的代价是只能用在完美二叉树这种同层节点数量固定、左右孩子必定成对出现的特殊结构上。
- O(1) 解法说白了本质就是一个归纳的过程：上一层的 next 链条连好了，才有条件去连下一层，根节点自己就构成了归纳的起点，因为它就一个节点，next 天然是 null。
- 这里最容易出错的地方就是"跨父节点连接"这一步（也就是 `cur.right.next = cur.next.left`），很多人容易只记得去连同一个父节点下的左右孩子，却忘了不同父节点之间在下一层其实也是相邻的，这一步必须单独处理才行。
- 整个循环可以这么理解：外层循环控制的是"还有没有下一层"（通过 `levelStart.left != nil` 来判断，完美二叉树能保证不会出现只有一侧孩子的怪情况），内层循环控制的是"在当前层内从左往右移动，顺便把下一层连好"。这两层循环分别对应着"层间往下推进"和"层内从左到右遍历"，把这两层循环各自的职责想清楚，是写对这道题代码的关键。
