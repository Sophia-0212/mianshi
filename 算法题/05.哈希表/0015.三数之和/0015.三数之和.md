# 0015. 三数之和

**题目描述**

给定一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k`、`j != k`，且 `nums[i] + nums[j] + nums[k] == 0`。请找出所有满足条件且不重复的三元组。

```
示例：
输入: nums = [-1,0,1,2,-1,-4]
输出: [[-1,-1,2],[-1,0,1]]
解释: 满足要求的三元组集合为上面两个，结果不能包含重复的三元组
```

## 思路

先说说我的第一反应哈。三数之和，你一看，很自然会想到这不就是两数之和的升级版嘛——固定第一个数，剩下两个数再用哈希表按两数之和的套路去解，两数之和不就是这么做的吗。但这题有个地方要注意，也是最容易被忽略的一个点：**结果里不能有重复的三元组**。这个去重的要求，恰恰就是哈希法在这题里的硬伤，也是我最终选择**排序 + 双指针**而不是哈希法的核心原因。

那我具体说说为什么哈希法在这里去重会很麻烦。你想啊，如果用哈希法，思路无非就是固定住 `nums[i]`，然后拿一个 map 去记录剩下元素的值和下标，查一下 `-nums[i]-nums[j]` 存不存在。问题是，这样找出来的三元组是基于下标定位的，你要去重的话，就得把三元组的值排个序放进 set 里判断有没有重复出现过，说白了就是要对结果本身再做一遍去重的工作（比如用 `set<vector<int>>`，或者先把三元组排序再一个个比较）。这一套逻辑绕来绕去，效率也不高，而且你在查找的过程中根本没法提前判断出"这个分支肯定会重复"，只能等结果都出来了再去筛。

那为什么排序加双指针在这题里就合适多了呢？关键就在于：先把数组排一下序，这样相同的数字自然就挨在一起了，这就给去重提供了一个非常天然的判断依据——遍历的时候只要发现当前值跟前一个位置一样，直接跳过就行，等于在遍历的过程中就把重复的三元组给挡住了，压根不需要等结果出来再回头去重。

具体怎么做呢：

1. 对数组排序。
2. 固定第一个数 `nums[i]`（外层循环，`i` 从 0 到 n-3）：
   - 如果 `nums[i] > 0`，因为数组已排序，后面的数都大于等于 `nums[i]`，三数之和不可能为 0，直接 break（剪枝）。
   - **外层去重**：如果 `i > 0` 且 `nums[i] == nums[i-1]`，说明这个数字上一轮已经作为第一个数处理过，跳过，避免重复的三元组以相同的第一个数开头。
3. 在剩下的区间 `[i+1, n-1]` 用双指针 `left`、`right` 分别指向区间左右端：
   - 计算 `sum = nums[i] + nums[left] + nums[right]`：
     - 如果 `sum == 0`，记录这个三元组，然后 `left++`、`right--` 继续寻找其他组合。
     - 如果 `sum > 0`，说明 `right` 太大，`right--`。
     - 如果 `sum < 0`，说明 `left` 太小，`left++`。
   - **内层去重**：找到一组解后，跳过所有与 `nums[left]` 相同的值（`left++` 直到值变化），以及所有与 `nums[right]` 相同的值（`right--` 直到值变化），避免同一个第一个数下产生重复的第二、三个数组合。

你看，这三层去重——外层的 `i`、内层的 `left`、内层的 `right`——配合排序后相邻元素挨在一起的这个特性，就能很优雅地在遍历过程中直接把重复分支跳过去，完全不用等结果出来再回头处理。这也正是双指针法相比哈希法在这道题上的优势所在。

**复杂度这块简单说一下**：设数组长度是 n。
- 时间复杂度是 O(n²)：外层循环跑一遍是 O(n)，内层双指针扫描区间也是 O(n)，虽然排序本身要 O(n log n)，但整体还是被 O(n²) 给盖过去了。
- 空间复杂度是 O(1)：这里不算排序占用的空间，原地排序一般认为额外空间是 O(log n) 或者 O(1)，具体看排序算法怎么实现的。

## 代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        vector<vector<int>> result;
        sort(nums.begin(), nums.end());  // 排序，为双指针和去重提供基础
        int n = nums.size();
        for (int i = 0; i < n - 2; i++) {
            if (nums[i] > 0) break;  // 排序后最小值大于0，后面不可能凑出0，直接结束
            if (i > 0 && nums[i] == nums[i - 1]) continue;  // 外层去重：跳过重复的第一个数

            int left = i + 1, right = n - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (sum == 0) {
                    result.push_back({nums[i], nums[left], nums[right]});  // 记录一个解
                    while (left < right && nums[left] == nums[left + 1]) left++;  // 内层去重：跳过重复的left
                    while (left < right && nums[right] == nums[right - 1]) right--;  // 内层去重：跳过重复的right
                    left++;
                    right--;
                } else if (sum > 0) {
                    right--;  // 和太大，右指针左移减小sum
                } else {
                    left++;  // 和太小，左指针右移增大sum
                }
            }
        }
        return result;
    }
};
```

### Python

本题不适合用哈希法，因为去重会很麻烦，所以这里没有什么"标准库一行解"，直接给你排序加双指针的手写实现：

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()  # 排序，为双指针和去重提供基础
        n = len(nums)
        result = []
        for i in range(n - 2):
            if nums[i] > 0:  # 排序后最小值大于0，后面不可能凑出0
                break
            if i > 0 and nums[i] == nums[i - 1]:  # 外层去重：跳过重复的第一个数
                continue

            left, right = i + 1, n - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if total == 0:
                    result.append([nums[i], nums[left], nums[right]])  # 记录一个解
                    while left < right and nums[left] == nums[left + 1]:
                        left += 1  # 内层去重：跳过重复的left
                    while left < right and nums[right] == nums[right - 1]:
                        right -= 1  # 内层去重：跳过重复的right
                    left += 1
                    right -= 1
                elif total > 0:
                    right -= 1  # 和太大，右指针左移
                else:
                    left += 1  # 和太小，左指针右移
        return result
```

## 总结

- 三数之和为什么不用哈希法了？核心就是**去重这个需求在作怪**：哈希法找出来的解是基于下标的，去重就得对结果值再做一遍额外处理；而排序之后用双指针，可以直接在遍历过程中利用相邻元素相等这个性质，顺手就把重复分支跳过去了。
- 排序是双指针法能生效的前提，你想啊，只有数组是有序的，才能利用"sum 大了就右指针左移，sum 小了就左指针右移"这种单调性去收缩区间，这个前提丢了双指针就玩不转了。
- 三层去重逻辑一定要分清楚：外层 `i` 的去重，是为了避免以相同数字开头的三元组重复出现；内层 `left`/`right` 的去重，是为了避免同一个 `i` 下面产生重复的第二、三个数的组合——这两者作用的层级不一样，缺哪个都不行。
- 说到 `nums[i] > 0` 时的那个 break 剪枝，它利用的是排序后数组单调不减的性质，本质上是个不影响正确性的性能优化。你把这行代码去掉，结果照样是对的，只不过会多跑几轮没意义的循环而已。
