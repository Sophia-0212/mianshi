# 0202. 快乐数

**题目描述**

编写一个算法来判断一个数 `n` 是不是快乐数。

「快乐数」的定义为：对于一个正整数，每一次将该数替换为它每个位置上的数字的平方和，然后重复这个过程直到这个数变为 1，也可能是**无限循环但始终变不到 1**。如果可以变为 1，那么这个数就是快乐数。

```
示例 1：
输入: n = 19
输出: true
解释:
1² + 9² = 82
8² + 2² = 68
6² + 8² = 100
1² + 0² + 0² = 1

示例 2：
输入: n = 2
输出: false
解释: 2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → ... 会陷入无限循环，且循环体不含 1
```

## 思路

反复计算各位数字平方和：得到 1 则成功，进入不含 1 的循环则失败。

- 哈希集合记录中间数，出现重复即可判环。时间 O(log n)，空间 O(log n) 为上界。
- Floyd 快慢指针：慢指针变换一次，快指针变换两次，相遇后判断是否为 1。时间 O(log n)，辅助空间 O(1)。

固定整数范围下，两者均可视为常数复杂度。

### LeetCode 写法与原有示例

这题没有能直接对应的标准库一行解，毕竟判环这个逻辑得显式维护状态，所以就直接给你手写实现了：

```python
class Solution:
    # 方法：get_sum；按题目要求处理输入并返回结果，核心算法见方法体。
    def get_sum(self, n: int) -> int:
        total = 0
        while n > 0:
            digit = n % 10
            total += digit * digit  # 累加每一位数字的平方
            n //= 10
        return total

    # 方法：isHappy；按题目要求处理输入并返回结果，核心算法见方法体。
    def isHappy(self, n: int) -> bool:
        seen = set()  # 记录出现过的中间结果，用于判环
        while n != 1 and n not in seen:
            seen.add(n)  # 记录当前值，防止死循环
            n = self.get_sum(n)  # 计算下一步的各位数字平方和
        return n == 1  # n==1 说明是快乐数，否则说明检测到循环
```

    sum := 0
    for n > 0 {
        digit := n % 10
        sum += digit * digit // 累加每一位数字的平方
        n /= 10
    }
    return sum
}

// 方法：isHappy；按题目要求处理输入并返回结果，核心算法见方法体。
func isHappy(n int) bool {
    seen := make(map[int]struct{}) // 记录出现过的中间结果，用于判环
    for n != 1 {
        if _, ok := seen[n]; ok {
            return false // 之前出现过，说明进入循环但没有到达 1
        }
        seen[n] = struct{}{} // 记录当前值
        n = getSum(n)         // 计算下一步的各位数字平方和
    }
    return true // n==1，是快乐数
}

## C++

### LeetCode 写法与原有示例

```cpp
// 依赖说明：unordered_set：C++ STL 哈希集合。

class Solution {
public:
    // 方法：getSum；按题目要求处理输入并返回结果，核心算法见方法体。
    int getSum(int n) {
        int sum = 0;
        while (n > 0) {
            int digit = n % 10;
            sum += digit * digit;  // 累加每一位数字的平方
            n /= 10;
        }
        return sum;
    }

    // 方法：isHappy；按题目要求处理输入并返回结果，核心算法见方法体。
    bool isHappy(int n) {
        unordered_set<int> seen;  // 记录出现过的中间结果，用于判环
        while (n != 1 && !seen.count(n)) {
            seen.insert(n);  // 记录当前值，防止后续重复判断陷入死循环
            n = getSum(n);   // 计算下一步的各位数字平方和
        }
        return n == 1;  // 循环退出时 n==1 说明是快乐数，否则说明检测到循环
    }
};```

## 总结

- 这道题的核心其实不是数学计算，而是"判环"——用 set 把历史状态记下来、检测有没有重复出现，这是判断隐式序列是否进入循环的一个通用手段，跟链表判环用快慢指针，其实是同一类问题的两种不同解法，你可以类比着记。
- 为什么用 set 而不是 map？就是因为我们只需要判断某个中间结果"是否出现过"，不需要额外记录什么值，这就是个典型的存在性判断场景。
- 其实也可以用快慢指针来代替 set 判环，也就是每一步分别走一步和两步，这样空间复杂度能降到 O(1)，不过代码逻辑相对来说没有 set 版本那么直观，算是这道题的一个进阶写法，面试官问深了可以提一下。
- 数字各位的平方和会很快收敛到一个有限范围内（不超过 243）来回跳动，所以判环这个过程实际执行的次数是有限的、常数级别的，不会真的无限循环下去，这个也是为什么这个算法能保证一定会终止。
