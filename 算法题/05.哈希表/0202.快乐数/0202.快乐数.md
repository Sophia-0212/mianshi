# 0202. 快乐数

**题目描述**

编写一个算法来判断一个数 `n` 是不是快乐数。

「快乐数」的定义为：对于一个正整数，每一次将该数替换为它每个位置上的数字的平方和，然后重复这个过程直到这个数变为 1，也可能是**无限循环但始终变不到 1**。如果可以变为 1，那么这个数就是快乐数。

```
示例 1：
输入: n = 19
输出: true
解释:
1² + 9² = 82
8² + 2² = 68
6² + 8² = 100
1² + 0² + 0² = 1

示例 2：
输入: n = 2
输出: false
解释: 2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → ... 会陷入无限循环，且循环体不含 1
```

## 思路

这道题的关键难点在哪呢？就是要判断"一个数最终到底会不会变成 1"。你想啊，如果你直接去迭代求各位数字的平方和，一旦这个数不是快乐数，理论上这个过程会一直无限循环下去，程序自己是停不下来的。

那这里的**核心洞察**是什么呢？就是：如果一个数不是快乐数，那反复求平方和的这个过程，一定会陷入一个**循环（cycle）**——也就是说，之前算出来过的某个中间结果，一定会再次出现。你仔细想想，这个问题的本质其实跟"判断链表是否有环"是一回事，都是在一个隐式的序列里检测有没有重复访问同一个节点。

链表判环你可能会想到用快慢指针，也就是 Floyd 判圈算法，这题其实也能这么做（让"慢指针"每次走一步，"快指针"每次走两步，看它俩会不会相遇）。但说实话，更直观、也更容易写对的办法是用哈希表：**用一个 set 把每一步算出来的中间结果都记下来，如果发现某个结果之前已经出现过了，那就说明陷入循环了，而且这个循环里没有 1，这时候直接返回 false 就行**。

具体步骤是这样的：

1. 维护一个 `set`，用来存储已经出现过的中间数字。
2. 每一步计算当前数字各位的平方和，得到新的数字：
   - 如果新数字等于 1，返回 true（是快乐数）。
   - 如果新数字已经在 `set` 中出现过，说明进入循环但没有到达 1，返回 false。
   - 否则把新数字加入 `set`，继续下一轮计算。

这里为什么用 `set` 而不是 `map` 呢？因为我们只需要判断"这个中间结果有没有出现过"，不需要额外记录别的信息，比如出现的位置或者次数，这就是个典型的判重场景，用 set 就够了。

**复杂度这块说一下**：设数字位数是 d（不过这题里 d 基本可以当常数级来看，因为算着算着，数字很快就会收缩到一个比较小的范围里）。
- 时间复杂度是 O(log n)：可以证明，中间结果很快就会落到一个有限范围（不超过 243，也就是三位数每位都是 9 的时候，9²×3=243）里循环，或者直接收敛到 1，所以循环的次数其实是常数级别的，很有限。
- 空间复杂度是 O(log n)，这取决于 set 里存了多少个中间结果。

## 代码

### C++

```cpp
class Solution {
public:
    int getSum(int n) {
        int sum = 0;
        while (n > 0) {
            int digit = n % 10;
            sum += digit * digit;  // 累加每一位数字的平方
            n /= 10;
        }
        return sum;
    }

    bool isHappy(int n) {
        unordered_set<int> seen;  // 记录出现过的中间结果，用于判环
        while (n != 1 && !seen.count(n)) {
            seen.insert(n);  // 记录当前值，防止后续重复判断陷入死循环
            n = getSum(n);   // 计算下一步的各位数字平方和
        }
        return n == 1;  // 循环退出时 n==1 说明是快乐数，否则说明检测到循环
    }
};
```

### Python

这题没有能直接对应的标准库一行解，毕竟判环这个逻辑得显式维护状态，所以就直接给你手写实现了：

```python
class Solution:
    def get_sum(self, n: int) -> int:
        total = 0
        while n > 0:
            digit = n % 10
            total += digit * digit  # 累加每一位数字的平方
            n //= 10
        return total

    def isHappy(self, n: int) -> bool:
        seen = set()  # 记录出现过的中间结果，用于判环
        while n != 1 and n not in seen:
            seen.add(n)  # 记录当前值，防止死循环
            n = self.get_sum(n)  # 计算下一步的各位数字平方和
        return n == 1  # n==1 说明是快乐数，否则说明检测到循环
```

### Go

```go
func getSum(n int) int {
    sum := 0
    for n > 0 {
        digit := n % 10
        sum += digit * digit // 累加每一位数字的平方
        n /= 10
    }
    return sum
}

func isHappy(n int) bool {
    seen := make(map[int]struct{}) // 记录出现过的中间结果，用于判环
    for n != 1 {
        if _, ok := seen[n]; ok {
            return false // 之前出现过，说明进入循环但没有到达 1
        }
        seen[n] = struct{}{} // 记录当前值
        n = getSum(n)         // 计算下一步的各位数字平方和
    }
    return true // n==1，是快乐数
}
```

## 总结

- 这道题的核心其实不是数学计算，而是"判环"——用 set 把历史状态记下来、检测有没有重复出现，这是判断隐式序列是否进入循环的一个通用手段，跟链表判环用快慢指针，其实是同一类问题的两种不同解法，你可以类比着记。
- 为什么用 set 而不是 map？就是因为我们只需要判断某个中间结果"是否出现过"，不需要额外记录什么值，这就是个典型的存在性判断场景。
- 其实也可以用快慢指针来代替 set 判环，也就是每一步分别走一步和两步，这样空间复杂度能降到 O(1)，不过代码逻辑相对来说没有 set 版本那么直观，算是这道题的一个进阶写法，面试官问深了可以提一下。
- 数字各位的平方和会很快收敛到一个有限范围内（不超过 243）来回跳动，所以判环这个过程实际执行的次数是有限的、常数级别的，不会真的无限循环下去，这个也是为什么这个算法能保证一定会终止。
