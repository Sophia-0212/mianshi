# 哈希表理论基础

**题目描述**

本篇不针对具体题目，而是梳理哈希表这一数据结构的核心原理，以及在算法题中选择「数组 / set / map」三种哈希实现方式的判断依据，为后续具体题目打基础。

## 思路

哈希表通过哈希函数定位桶，用键比较确认命中。查找、插入、删除平均时间 O(1)，最坏 O(n)；存储空间 O(n)，扩容成本通常均摊计算。

- 拉链法：同桶元素存于链表等结构；冲突过多时查找变慢。
- 开放地址法：冲突后继续探测空槽；删除需保留探测链，通常使用墓碑标记。
- 数组用于小而连续的值域；集合用于去重；映射用于记录键值关系。
- C++ `unordered_map/unordered_set`、Java `HashMap/HashSet`、Python `dict/set` 提供哈希容器；Go 可用 `map[T]struct{}` 表示集合。
- C++ `map/set` 是有序树结构，操作 O(log n)，与哈希容器区分。

## 总结

- 哈希表这个数据结构，本质上就是用空间换时间，核心思路是通过哈希函数把 key 映射到一个有限的索引空间里，从而平均 O(1) 就能完成查找、插入、删除。
- 拉链法是用链表或者树来处理冲突，实现起来简单，删除也方便；线性探测法则是把数据都塞进数组本身，缓存友好，但删除比较复杂，而且对负载因子很敏感。
- C++ 和 Java 的哈希容器底层大多用拉链法，Python 的 dict、set 用的是开放地址法，Go 的 map 用的是拉链法（桶加溢出桶），这些实现细节各不相同，但对外表现出来的语义是一致的。
- 选哈希载体的时候，先判断值域是不是小且连续，是的话用数组；再判断是否需要键值映射，需要就用 map，不需要（只判重或求交集）就用 set。
