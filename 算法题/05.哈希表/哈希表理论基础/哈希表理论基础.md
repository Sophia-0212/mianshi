# 哈希表理论基础

**题目描述**

本篇不针对具体题目，而是梳理哈希表这一数据结构的核心原理，以及在算法题中选择「数组 / set / map」三种哈希实现方式的判断依据，为后续具体题目打基础。

## 思路

### 什么是哈希表

哈希表这个东西，你可以理解成一种「用空间换时间」的数据结构。你想啊，普通数组要判断一个元素在不在里面，得从头遍历一遍，时间复杂度是 O(n)；但哈希表不这么干，它是通过一个**哈希函数**，直接把元素映射到一个固定范围的索引上，然后通过索引直接访问，这样一来，查询、插入、删除的平均时间复杂度就降到 O(1) 了。

那哈希函数具体是干什么的呢？说白了就是：给它任意类型的 key，它给你输出一个有限范围内的整数，通常就是数组下标。举个最简单的例子，哈希函数可以是 `hash(key) = key % tableSize`，这样就能把任意大小的 key 压缩到 `[0, tableSize)` 这个区间里去。

### 哈希碰撞及解决方法

这里有个问题：哈希函数的值域是有限的，但 key 的取值空间往往比这个值域大得多，所以必然会出现不同的 key 映射到同一个索引上的情况，这就是所谓的**哈希碰撞（Hash Collision）**。那怎么解决呢？常见的方法有两种：

**1. 拉链法（也叫链地址法，Separate Chaining）**

这个方法的关键是，每个哈希桶——也就是数组的每个位置——不直接存值，而是存一个链表或者数组。一旦发生碰撞，新元素就直接挂到对应桶的链表尾部。查找的时候，先定位到桶，再遍历桶里的链表逐一比较就行了。

- 优点是实现简单，删除也方便，桶数组不需要扩容太激进，就算冲突比较多，也只是链表变长一点，不会影响到其他桶。
- 缺点呢，如果某个桶的链表太长了，查找就退化成 O(n) 了；而且还需要额外的指针空间。
- 有个细节值得一提：Java 的 `HashMap` 在 JDK 8 之前就是纯拉链法，但 JDK 8 之后，一旦链表长度超过阈值（也就是 8），就会自动转换成红黑树，这样就把最坏情况进一步优化到 O(log n) 了。

**2. 线性探测法（也叫开放地址法，Open Addressing / Linear Probing）**

这个方法跟拉链法不一样，所有元素都直接存在哈希表数组本身里，不用额外的链表。一旦发生碰撞，就从冲突的位置开始，按固定步长——线性探测通常是 +1——往后找下一个空位插进去。查找的时候也是按这个顺序去探测，一直探测到找到目标或者遇到空位为止。

- 优点是没有额外的指针开销，内存是连续的，对缓存很友好。
- 缺点是删除操作比较麻烦，你不能直接把位置置空，不然会打断后面元素的探测链，所以通常得打个「墓碑」标记来处理。另外，负载因子——也就是已用槽位占总槽位的比例——一旦升高，性能就会急剧下降，所以必须把装载因子控制在比较低的水平，比如 0.5 到 0.75 之间，还得及时扩容才行。

除了这两种方法之外，还有二次探测、双重哈希、再哈希这些变体，但归根结底，核心思路都是在解决同一个问题：发生碰撞之后，该往哪里放。

### 四种语言的哈希表实现对比

| 语言 | 映射结构 | 去重结构 | 底层实现 |
|------|----------|----------|----------|
| C++ | `unordered_map` | `unordered_set` | 拉链法，桶数组+链表 |
| Java | `HashMap` | `HashSet` | 拉链法，JDK8+ 链表转红黑树优化 |
| Python | `dict` | `set` | 开放地址法（伪随机探测） |
| Go | `map` | 无原生 set，常用 `map[T]struct{}` 或 `map[T]bool` 模拟 | 拉链法（桶+溢出桶） |

这里有几点差异需要你留意一下：

- C++ 的 `map`（底层是红黑树）和 `unordered_map`（底层是哈希表）其实是两个完全不同的结构。`map` 是有序的，但操作是 O(log n)；`unordered_map` 是无序的，操作平均是 O(1)。所以刷题的时候，如果不要求有序，优先用 `unordered_map` 或 `unordered_set`。
- Go 没有内置的 set 类型，社区里通常用 `map[T]struct{}` 来模拟，为什么呢？因为空结构体 `struct{}` 是不占内存的，比 `map[T]bool` 更省空间。
- Python 的 `dict` 从 3.7 版本开始会保证插入顺序，但这只是一个实现细节，不代表它是排序结构，这一点别搞混了。
- Java 的 `HashMap` 允许有一个 `null` key，而 `HashSet` 底层其实就是包装了一个 `HashMap`。

### 什么场景该用数组、set、map

这一步是刷题里最容易被问到、也最容易选错的地方。判断依据主要看两点：**值域大小**，以及**是否需要建立键值映射关系**。

**1. 值域小且连续 → 用数组模拟哈希**

如果 key 的取值范围是已知的、小的、而且连续的——比如只出现小写字母，值域就是 26；或者只出现 ASCII 字符，值域是 256——这种情况下，你直接开一个固定大小的数组就行了，用字符或数字本身（减去一个偏移量）作为下标，比如 `count[c - 'a']++`。

为什么这种方式比 `unordered_map` 更快呢？因为数组的访问完全没有哈希计算和冲突处理的开销，而且内存是连续的，缓存命中率也高。典型场景包括：字母异位词判断（242题）、字符串数组找公共字符（1002题）、赎金信字符统计（383题）。

**2. 只需要判断"存在"或"去重"，不需要值 → 用 set**

如果你只关心某个元素出不出现过，不需要记录它出现了几次、也不需要对应什么其他信息，那用 `set` 就够了。比如判断两个数组有没有交集，或者判断一个数字序列有没有出现循环（也就是快乐数问题）。这里的关键是，当值域很大或者不连续——比如可能出现负数、大整数——数组就没法模拟了，这时候必须用 `set`。

**3. 需要键值对应关系 → 用 map**

如果你需要记录「这个 key 对应的 value 是什么」，比如两数之和里要记录"数值对应下标"，四数相加II里要记录"两数之和对应出现次数"，这种一对一或者一对多的映射关系，必须用 `map` 才能实现。

给你一个简单的选择顺序：**先看值域是不是小且连续，能用数组就用数组，这是最快的；不能用数组的话，再看是否需要维护键值映射，需要的话用 map，不需要的话（也就是只判重或求交并集）就用 set。**

## 总结

- 哈希表这个数据结构，本质上就是用空间换时间，核心思路是通过哈希函数把 key 映射到一个有限的索引空间里，从而平均 O(1) 就能完成查找、插入、删除。
- 拉链法是用链表或者树来处理冲突，实现起来简单，删除也方便；线性探测法则是把数据都塞进数组本身，缓存友好，但删除比较复杂，而且对负载因子很敏感。
- C++ 和 Java 的哈希容器底层大多用拉链法，Python 的 dict、set 用的是开放地址法，Go 的 map 用的是拉链法（桶加溢出桶），这些实现细节各不相同，但对外表现出来的语义是一致的。
- 选哈希载体的时候，先判断值域是不是小且连续，是的话用数组；再判断是否需要键值映射，需要就用 map，不需要（只判重或求交集）就用 set。
