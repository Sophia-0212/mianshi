# 0349. 两个数组的交集

**题目描述**

给定两个数组 `nums1` 和 `nums2`，返回它们的交集，结果中的每个元素只能出现一次（去重），可以以任意顺序返回结果。

```
示例 1：
输入: nums1 = [1,2,2,1], nums2 = [2,2]
输出: [2]

示例 2：
输入: nums1 = [4,9,5], nums2 = [9,4,9,8]
输出: [9,4]
```

## 思路

这题要求「交集且不含重复元素」，你想啊，这不就是哈希表里典型的**去重+存在性判断**场景嘛，所以第一反应应该是用 `set`，而不是用数组模拟哈希。

那为什么这题不适合用数组哈希呢？这里的关键是，数组模拟哈希要求值域小而且连续，比如前两题的 26 个小写字母就很合适。但这题元素是任意整数啊，题目根本没限定范围，可能出现负数，也可能出现很大的数，你要是开一个覆盖全部可能取值的数组，既浪费空间又可能直接越界。相比之下呢，`unordered_set`/`HashSet`/`set`/`map[int]bool` 这些不需要你提前知道值域大小，任意整数都可以直接扔进去。说白了，这就是数组哈希法和 set 哈希法适用场景的关键区别：**数组哈希要求值域小且连续，set 哈希适用于值域未知或者稀疏的场景**。

那具体怎么做呢？

1. 先把 `nums1` 的所有元素放进一个 `set`，这样就自动去重了。
2. 然后遍历 `nums2`，看看每个元素是不是在这个 `set` 里出现过：
   - 如果出现过，那就说明这是交集元素，把它加进结果集里（结果也用 set 存，这样能防止 `nums2` 内部有重复元素导致结果重复添加）。
3. 最后把结果 set 转成数组返回就行了。

那如果题目提示元素范围比较小，比如说 0 到 1000 之间，其实也可以用数组哈希法代替 set，速度会更快。这两种方法本质上思路是一样的，只是哈希的载体不同，具体用哪个还是要看值域灵活选择。

**复杂度分析**：设两数组长度分别为 m、n。
- 时间复杂度是 O(m + n)，因为构建 set 和遍历第二个数组都是线性的，set 的插入和查询平均下来是 O(1)。
- 空间复杂度是 O(m + n)，因为需要额外的 set 来存储元素以及结果。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> intersection(vector<int>& nums1, vector<int>& nums2) {
        unordered_set<int> set1(nums1.begin(), nums1.end());  // nums1 去重存入 set
        unordered_set<int> resultSet;  // 用 set 存结果，防止重复添加
        for (int num : nums2) {
            if (set1.count(num)) {  // 判断 nums2 的元素是否在 nums1 中出现过
                resultSet.insert(num);
            }
        }
        return vector<int>(resultSet.begin(), resultSet.end());  // 转换为数组返回
    }
};
```

### Java

```java
class Solution {
    public int[] intersection(int[] nums1, int[] nums2) {
        Set<Integer> set1 = new HashSet<>();  // nums1 去重存入 set
        for (int num : nums1) {
            set1.add(num);
        }
        Set<Integer> resultSet = new HashSet<>();  // 用 set 存结果，防止重复添加
        for (int num : nums2) {
            if (set1.contains(num)) {  // 判断 nums2 的元素是否在 nums1 中出现过
                resultSet.add(num);
            }
        }
        int[] result = new int[resultSet.size()];
        int i = 0;
        for (int num : resultSet) {
            result[i++] = num;  // 转换为数组返回
        }
        return result;
    }
}
```

### Python

标准库一行解（`set` 直接支持 `&` 运算符求交集，语义与本题完全一致）：

```python
class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
        return list(set(nums1) & set(nums2))  # 两个集合的交集运算符
```

手写实现（面试考察点，还原 set 哈希去重+查询存在性的原理）：

```python
class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
        set1 = set(nums1)  # nums1 去重存入 set
        result_set = set()  # 用 set 存结果，防止重复添加
        for num in nums2:
            if num in set1:  # 判断 nums2 的元素是否在 nums1 中出现过（平均 O(1)）
                result_set.add(num)
        return list(result_set)
```

### Go

```go
func intersection(nums1 []int, nums2 []int) []int {
    set1 := make(map[int]struct{}, len(nums1)) // nums1 去重存入 set（用空结构体节省内存）
    for _, num := range nums1 {
        set1[num] = struct{}{}
    }
    resultSet := make(map[int]struct{}) // 用 set 存结果，防止重复添加
    for _, num := range nums2 {
        if _, ok := set1[num]; ok { // 判断 nums2 的元素是否在 nums1 中出现过
            resultSet[num] = struct{}{}
        }
    }
    result := make([]int, 0, len(resultSet))
    for num := range resultSet {
        result = append(result, num) // 转换为数组返回
    }
    return result
}
```

## 总结

- 「求交集且去重」这种场景，说白了就是哈希表里只需要判断存在性、不需要维护键值映射的情况，所以应该用 `set`，不是 `map`。
- 数组哈希法要求值域小且连续；set 哈希法不依赖值域大小，任意整数都能处理，包括负数和大数。这题元素范围没限定，用 set 更通用。
- 结果为什么也要先用 set 暂存再转数组呢，就是为了防止第二个数组内部本身有重复元素，导致交集元素被重复添加进结果里。
- 那如果题目明确告诉你值域比较小，比如限定在 0 到 1000 之间，数组哈希法会比 set 快，因为省去了哈希函数计算和冲突处理这些开销。
