# 0001. 两数之和

**题目描述**

给定一个整数数组 `nums` 和一个目标值 `target`，在该数组中找出和为目标值的两个整数，返回它们的数组下标。假设每种输入只对应一个答案，且同一个元素不能重复使用。

```
示例 1：
输入: nums = [2,7,11,15], target = 9
输出: [0,1]
解释: nums[0] + nums[1] == 9，返回 [0, 1]

示例 2：
输入: nums = [3,2,4], target = 6
输出: [1,2]
```

## 思路

你想啊，最直接的办法就是双重循环，把所有两数组合都枚举一遍，这样时间复杂度是 O(n²)。但这肯定不是最优解，那怎么优化到 O(n) 呢？关键就在于，我们在遍历数组的时候，怎么才能快速判断"是否存在另一个数，使得两者之和等于 target"。

这里的关键是，这其实就是哈希表**键值映射**最典型的应用场景：我们需要记录"值 -> 下标"这样一个对应关系，所以要用 `map`，不能用 `set`。为什么呢？因为 `set` 只能告诉你这个值存不存在，但取不出它对应的下标，而我们恰恰需要下标。

那具体怎么做呢？核心思路就是**一次遍历，边查边存**：

1. 先维护一个 `map`，key 是数组里出现过的值，value 是这个值对应的下标。
2. 然后遍历数组，对于当前元素 `nums[i]`，算出 `complement = target - nums[i]`，也就是我们还需要找的"另一半"。
3. 接着检查这个 `complement` 是不是已经在 `map` 里出现过了：
   - 如果存在，说明找到答案了，直接返回 `[map[complement], i]`。
   - 如果不存在，就把当前值和下标存进 `map`：`map[nums[i]] = i`，然后继续下一轮。

这里有个细节要注意，就是"先查后存"还是"先存后查"的顺序问题。我们这里用的是**边遍历边查找**，也就是说，查询 `complement` 的那一刻，`map` 里只包含当前元素**之前**遍历过的那些元素。这样一来，就自然保证了不会出现用同一个元素和自己配对的情况——因为当前元素这时候还没被存进 map 呢。

**复杂度分析**：假设数组长度是 n。
- 时间复杂度这块，是 O(n)，说白了就是只需要遍历一次数组，每次查询和插入 map 平均下来都是 O(1)。
- 空间复杂度是 O(n)，最坏情况下可能要把所有元素都存进 map 里。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> valueToIndex;  // 记录 值->下标 的映射
        for (int i = 0; i < nums.size(); i++) {
            int complement = target - nums[i];  // 计算还需要的另一半
            auto it = valueToIndex.find(complement);
            if (it != valueToIndex.end()) {  // 之前遍历过的元素中存在 complement
                return {it->second, i};  // 返回两个下标
            }
            valueToIndex[nums[i]] = i;  // 当前元素存入 map，供后续查找
        }
        return {};  // 题目保证有解，正常不会执行到这里
    }
};
```

### Java

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> valueToIndex = new HashMap<>();  // 记录 值->下标 的映射
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];  // 计算还需要的另一半
            if (valueToIndex.containsKey(complement)) {  // 之前遍历过的元素中存在 complement
                return new int[]{valueToIndex.get(complement), i};  // 返回两个下标
            }
            valueToIndex.put(nums[i], i);  // 当前元素存入 map，供后续查找
        }
        return new int[]{};  // 题目保证有解，正常不会执行到这里
    }
}
```

### Python

标准库没有直接针对「两数之和」的一行解（`dict` 本身就是哈希映射的标准用法，这里直接手写体现映射查找的完整过程）：

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        value_to_index = {}  # 记录 值->下标 的映射
        for i, num in enumerate(nums):
            complement = target - num  # 计算还需要的另一半
            if complement in value_to_index:  # 之前遍历过的元素中存在 complement
                return [value_to_index[complement], i]  # 返回两个下标
            value_to_index[num] = i  # 当前元素存入 map，供后续查找
        return []  # 题目保证有解，正常不会执行到这里
```

### Go

```go
func twoSum(nums []int, target int) []int {
    valueToIndex := make(map[int]int) // 记录 值->下标 的映射
    for i, num := range nums {
        complement := target - num // 计算还需要的另一半
        if j, ok := valueToIndex[complement]; ok {
            return []int{j, i} // 之前遍历过的元素中存在 complement，返回两个下标
        }
        valueToIndex[num] = i // 当前元素存入 map，供后续查找
    }
    return []int{} // 题目保证有解，正常不会执行到这里
}
```

## 总结

- 说白了，只要你需要"值 -> 下标"这种键值映射关系，就必须用 `map`，`set` 是搞不定的，因为它只能判断存在性，取不出下标来。
- "边遍历边查找边存储"是这道题从 O(n²) 优化到 O(n) 的关键所在：用一次遍历就同时完成了查询和更新，而不是先建好表再查两遍。
- 先查询 `complement`，再把当前元素存进 map，这个顺序很重要，它保证了不会出现"用自己和自己匹配"这种错误——因为当前元素在查询的那一刻，map 里还不包含它自己。
- 这道题其实是哈希表在算法题里最经典的入门应用，后面会讲到的三数之和、四数之和、四数相加II，说白了都是这个思路的不同变体或者推广。
