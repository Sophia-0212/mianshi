# 0205. 同构字符串

**题目描述**

给定两个字符串 `s` 和 `t`，判断它们是否是同构的。如果 `s` 中的字符可以按某种映射关系替换得到 `t`，那么这两个字符串是同构的。

映射关系必须满足：`s` 中每个字符都映射到 `t` 中唯一的字符，同时不同字符不能映射到同一个字符（即映射是一一对应的双射关系），但一个字符可以映射到它自己。

```
示例 1：
输入: s = "egg", t = "add"
输出: true
解释: e->a, g->d

示例 2：
输入: s = "foo", t = "bar"
输出: false
解释: o 需要同时映射到 a 和 r，不满足单一映射

示例 3：
输入: s = "paper", t = "title"
输出: true
```

## 思路

这道题最容易踩的坑是什么呢？就是只做单向映射。你想啊，如果只建一个从 `s` 到 `t` 的哈希表，会漏掉"多对一"这种反例。我举个例子你就明白了：`s = "ab"`，`t = "aa"`。按 `s -> t` 这个方向来看，`a` 映射到 `a`，`b` 也映射到 `a`，每次检查当前字符的映射是不是跟之前记录的一致，好像都能通过——因为 `a` 第一次出现的时候记录了映射到 `a`，后面也没再冲突；`b` 第一次出现记录映射到 `a`，同样没冲突。但你仔细看，实际上 `a` 和 `b` 这两个不同的字符，都指向了 `t` 里的同一个字符 `a`，这就违反了"不同字符不能映射到同一个字符"这条双射要求。所以这里的关键是，必须同时检查反向的关系才行。

那怎么解决呢？说白了就是维护两个哈希表：一个记录 `s -> t` 的映射，叫 `mapST`；一个记录 `t -> s` 的映射，叫 `mapTS`。然后同时遍历两个字符串的每一位 `i`，针对字符 `s[i]` 和 `t[i]`：

- 如果 `mapST` 里已经有 `s[i]` 的映射记录了，那这个记录必须等于 `t[i]`，不然就说明 `s[i]` 之前映射到了别的字符，现在又要映射到 `t[i]`，这不就矛盾了嘛，直接返回 false。
- 如果 `mapTS` 里已经有 `t[i]` 的映射记录了，那这个记录必须等于 `s[i]`，不然就说明 `t[i]` 之前是被别的字符映射过来的，现在又被 `s[i]` 映射，同样矛盾，也返回 false。
- 如果两边都没有记录，那说明这是第一次遇到这一对字符，就把 `s[i] -> t[i]` 和 `t[i] -> s[i]` 这两个方向同时记下来。

只要把整个字符串遍历完都没冲突，那就说明这是一个合法的双射关系，返回 true。

再说说边界条件：如果 `s` 和 `t` 长度不一样，直接返回 false 就行，因为长度不同根本不可能建立字符级别的一一对应关系。空字符串的话，按题目约定就算同构（互为空映射，天然就是合法的）。

另外还有一种思路，跟上面这个是等价的：不用哈希表存字符映射，而是记录每个字符"上一次出现的位置"，然后比较 `s` 和 `t` 在每个位置上字符的上一次出现位置是不是一致——如果一致，就说明两边字符出现的模式是一样的。这种做法本质上跟双向映射是一回事，只是换了种编码方式，用位置代替字符本身来做标记，同样能避开多对一的问题。

**复杂度这块说一下**：设字符串长度是 `n`，这里只需要一次遍历，每次哈希表的插入和查询都是 O(1)（前提是字符集大小固定，比如 ASCII 字符），所以时间复杂度是 O(n)。空间复杂度是 O(k)，k 是字符集大小，因为哈希表最多也就存下字符集里所有字符的映射关系，一般可以当作 O(1)来看，毕竟字符集是常数大小的。

## 代码

### C++

```cpp
class Solution {
public:
    bool isIsomorphic(string s, string t) {
        if (s.size() != t.size()) return false;  // 长度不同不可能同构
        unordered_map<char, char> mapST, mapTS;   // 双向哈希表
        for (int i = 0; i < s.size(); i++) {
            char a = s[i], b = t[i];
            // 检查 s->t 方向：a 是否已经映射到别的字符
            if (mapST.count(a) && mapST[a] != b) return false;
            // 检查 t->s 方向：b 是否已经被别的字符映射过
            if (mapTS.count(b) && mapTS[b] != a) return false;
            mapST[a] = b;  // 记录本次映射（重复赋值也没影响）
            mapTS[b] = a;
        }
        return true;  // 全程无冲突，是合法双射
    }
};
```

### Java

```java
class Solution {
    public boolean isIsomorphic(String s, String t) {
        if (s.length() != t.length()) return false;  // 长度不同直接排除
        Map<Character, Character> mapST = new HashMap<>();
        Map<Character, Character> mapTS = new HashMap<>();
        for (int i = 0; i < s.length(); i++) {
            char a = s.charAt(i), b = t.charAt(i);
            // s->t 方向冲突检测
            if (mapST.containsKey(a) && mapST.get(a) != b) return false;
            // t->s 方向冲突检测
            if (mapTS.containsKey(b) && mapTS.get(b) != a) return false;
            mapST.put(a, b);
            mapTS.put(b, a);
        }
        return true;
    }
}
```

### Python

这里说一下标准库一行解的情况：这道题没有能直接对应的库函数一步搞定"双向唯一映射"的判断，因为它本质上是需要同时校验两个方向约束的定制逻辑，`zip` 顶多帮你并行遍历一下，核心的判断逻辑还是得手写。

```python
class Solution:
    def isIsomorphic(self, s: str, t: str) -> bool:
        # 借助 zip 并行遍历，用集合大小间接验证双射：
        # 如果 (s[i], t[i]) 组成的配对集合的大小，
        # 等于 s 去重后的字符数，也等于 t 去重后的字符数，
        # 就说明每个 s 字符和每个 t 字符都只参与了一组配对（双射成立）
        if len(s) != len(t):
            return False
        pairs = set(zip(s, t))
        return len(pairs) == len(set(s)) == len(set(t))
```

原理说一下：`zip(s, t)` 会把两个字符串按位置配成 `(s[i], t[i])` 这样的元组序列，放进集合里就自动去重了。你想，如果双射关系是合法的，那每一对 `(a, b)` 就只会以固定的搭配出现，配对集合的大小应该恰好等于 `s` 里不同字符的个数（这个数也应该等于 `t` 里不同字符的个数）。但如果某个字符对应了不止一种搭配——比如说 `a` 既配 `x` 又配 `y`，这就说明映射不是唯一的了——配对集合的大小就会大于去重后的字符数，等式自然就不成立了。这个写法确实简洁，但可读性不如手写版本直观，面试的时候我更建议你能讲清楚双向哈希表逐字符校验的手写实现，这样面试官更容易看出你真正理解了原理。

手写实现（面试考察点：双向哈希表逐位校验，你要能清楚讲出"为什么必须两个方向都检查"）：

```python
class Solution:
    def isIsomorphic(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        map_st, map_ts = {}, {}  # 双向哈希表
        for a, b in zip(s, t):
            # s->t 方向：a 已经映射过，但映射的不是当前的 b
            if a in map_st and map_st[a] != b:
                return False
            # t->s 方向：b 已经被映射过，但映射来源不是当前的 a
            if b in map_ts and map_ts[b] != a:
                return False
            map_st[a] = b
            map_ts[b] = a
        return True
```

### Go

```go
func isIsomorphic(s string, t string) bool {
    if len(s) != len(t) {
        return false // 长度不同直接排除
    }
    mapST := make(map[byte]byte) // s -> t 映射
    mapTS := make(map[byte]byte) // t -> s 映射
    for i := 0; i < len(s); i++ {
        a, b := s[i], t[i]
        if v, ok := mapST[a]; ok && v != b {
            return false // a 之前映射到别的字符，冲突
        }
        if v, ok := mapTS[b]; ok && v != a {
            return false // b 之前被别的字符映射，冲突
        }
        mapST[a] = b
        mapTS[b] = a
    }
    return true
}
```

## 总结

- 这道题的核心陷阱就是"看起来只需要单向映射，但实际上必须双向校验"。你想，单向哈希表只能保证 `s` 里相同的字符映射到相同的 `t` 字符，但它没法阻止不同的 `s` 字符映射到同一个 `t` 字符，所以双向哈希表才是保证双射关系最直接的手段。
- 记录"上一次出现位置"的做法，跟双向哈希表其实是同一个思路的不同实现，本质上都是在给字符出现的"模式"编码，然后比较两边的模式是不是一致。理解了这一层，你就能举一反三去处理类似的模式匹配问题，比如判断两个字符串的字符出现顺序是否同构。
- 这题跟后面的"单词规律"（也就是 LeetCode 290，判断字符串数组和单词是否遵循同一种映射规律）几乎是同一个题型的变体，只是把字符级别的映射换成了单词级别的映射而已，解法完全可以套用双向哈希表的思路，面试官问到你可以直接类比过去。
- 有个容易出错的地方是遍历的时机：一定要先检查冲突，再更新映射。如果你先更新再检查，就会把原有的映射记录给覆盖掉，导致冲突检测直接失效，这个顺序千万不能反。
