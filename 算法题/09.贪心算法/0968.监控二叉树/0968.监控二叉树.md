# 968. 监控二叉树

**题目描述**

给定一个二叉树，我们需要在树的节点上安装摄像头。节点上的每个摄像头都可以监视其父对象、自身及其直接子对象。计算监控树的所有节点所需的最少摄像头数量。

```
示例：
输入: root = [0,0,null,0,0]
      对应二叉树：
              0
             /
            0
           / \
          0   0
输出: 1
解释: 如图所示，一台摄像头足以监控所有节点（安装在第二层的节点上）。
```

要求：树节点值均为 0（题目本身值无实际意义，只关心结构），返回最少摄像头数。

## 思路

### 为什么必须自底向上（后序遍历）处理

第一个要确定的问题是遍历顺序。这道题看起来是在树上做决策，很容易先想到自顶向下：从根节点开始，边下降边决定要不要装摄像头。但你仔细分析一下会发现这条路走不通。为什么呢？判断一个节点该不该装摄像头，前提是知道它的孩子节点有没有被覆盖到——如果孩子已经被覆盖了（比如孩子自己装了摄像头，或者孩子被更下层的摄像头覆盖到），那当前节点就不需要装；如果孩子还没被覆盖，当前节点就必须装摄像头来兜底。而"孩子有没有被覆盖"这件事，只有在孩子及其子树都处理完之后才能确定。自顶向下处理的时候，处理当前节点的那一刻，它的孩子还完全没有被访问过，根本没法知道孩子的覆盖状态，只能瞎猜或者装摄像头覆盖一切来蒙混过关，这样必然导致装的摄像头远多于最优解。

反过来，自底向上（后序遍历：先递归左子树、再递归右子树、最后处理当前节点）就完全没有这个问题了。当我们的递归函数处理到某个节点时，它的左右子树已经全部递归完毕了，左右孩子的"覆盖状态"已经是确定的、可以直接读取的信息。当前节点只需要根据这两个已知状态做一次判断，就能决定自己应该处于什么状态，这个决策是有充分依据的、可以立即确定的，不需要任何猜测或回溯。这就是本题选择后序遍历的根本原因：状态从叶子向根逐层汇聚，每一层的决策都建立在下一层已经完全确定的事实之上。

### 三种状态的设计

要让"根据孩子状态判断自己状态"这件事能够递归地进行下去，需要给每个节点定义一个能被父节点复用的状态描述。这道题巧妙的地方就在于把每个节点的处境归纳成三种，而且仅需三种状态：

- **状态 0：无覆盖**。这个节点既没有装摄像头，也不在任何摄像头的监控范围内，是一个"裸露"的、亟需被处理的节点。
- **状态 1：有摄像头**。这个节点自己装了一台摄像头，它可以覆盖自己、自己的父节点、自己的两个孩子。
- **状态 2：有覆盖但无摄像头**。这个节点没有装摄像头，但它被别人的摄像头照到了（要么是孩子的摄像头往上照到它，要么是父节点的摄像头往下照到它）。

这三种状态覆盖了一个节点相对于"摄像头监控网络"能处于的所有可能处境，不多不少，是对问题本质的一个精确抽象。

这里必须重点解释一个容易忽略但至关重要的细节：**空节点（null）的状态被人为定义为状态 2（有覆盖）**，而不是状态 0 或者干脆不参与判断。这个设定初看有点反直觉——空节点凭什么算"有覆盖"？但它的作用是让叶子节点的逻辑能够自然地、正确地跑起来，而不需要给叶子节点写特殊分支。你想象一个叶子节点，它的左右孩子都是 null。如果我们把 null 定义为状态 0（无覆盖），那么按照后面要讲的状态转移规则，"孩子中有状态 0" 会直接触发当前节点装摄像头，于是这个叶子节点自己就会被强制装上摄像头。可是我们后面会证明，最优策略恰恰是不要在叶子节点装摄像头，而是让叶子节点向上传递"我没被覆盖"的信号，把装摄像头的责任交给它的父节点。所以 null 只能被定义为状态 2：它是"有覆盖"的，这样叶子节点在检查左右孩子（两个 null）时，看到的是"两个孩子都是状态 2，都没有摄像头"，于是根据转移规则的第三种情况，叶子节点自己会被判定为状态 0（无覆盖），从而把"需要装摄像头"这个决策正确地推给了它的父节点，而不是自己抢先装上。

### 贪心策略的核心：让叶子的父节点装摄像头

理解了三种状态之后，可以正面回答这道题真正的贪心洞察：**摄像头应该尽量装在离叶子最近的、能够覆盖到叶子的最高层节点上，而不是装在叶子节点本身**，也就是"让叶子节点的父节点安装摄像头"。

用一条链 A—B—C 来说明，其中 A 是根，B 是 A 的孩子，C 是 B 的唯一孩子（C 是叶子）。如果我们的策略是在叶子 C 上装摄像头，这台摄像头能覆盖的范围是：C 自己、C 的父节点 B。仅此而已，覆盖不到 A。要覆盖到 A，还需要再判断 A 有没有被覆盖——A 没有装摄像头也没有别的孩子能覆盖它，所以还得在 A 上再装一台。这条链最终用了 2 台摄像头（C 和 A）。

但如果换一种策略，在 B 上装摄像头：这台摄像头能覆盖的范围是 B 自己、B 的父节点 A、B 的孩子 C。一台摄像头就把 A、B、C 三个节点全部覆盖了，只用 1 台。

对比这两种方案就能看出问题所在了：摄像头的监控范围是"自身 + 父节点 + 直接子节点"，装在哪个节点上，决定了这个覆盖范围向上下辐射的深度是否被充分利用。装在叶子节点上，摄像头的"向下"这一格监控能力完全被浪费（叶子没有孩子），只有"向上一层"在起作用；而装在叶子的父节点上，"向下一层"覆盖了叶子，"向上一层"覆盖了祖父节点，"自身"覆盖了父节点，三格监控能力都被用满了。换句话说，把摄像头往上挪一层，恰好能多覆盖一层原本需要额外摄像头才能覆盖到的祖先节点，这一层的收益是完全免费的（没有增加摄像头数量），所以只要条件允许（也就是孩子没有已经无法再等的覆盖需求），就应该优先把摄像头放到尽可能高、但仍能满足"不能让任何孩子处于无覆盖状态被漏掉"这个约束的位置。这正是贪心的本质：局部上每一步都选择让当前这台摄像头的监控范围利用率最大化的位置，全局上得到的就是覆盖整棵树所需的最少摄像头数。

### 状态转移的三条规则

有了三种状态的定义和贪心的方向，具体到每个节点的判断，后序遍历中根据左右孩子的状态 `left` 和 `right` 来决定当前节点状态，规则如下，按优先级顺序判断：

1. **只要左右孩子中有一个是状态 0（无覆盖）**，当前节点必须立即安装摄像头，状态变为 1，同时摄像头计数加一。为什么呢？因为无覆盖的孩子已经等不起了——如果当前节点不装摄像头，这个孩子将永远失去被覆盖的机会（它自己不会主动装摄像头，题目也不允许走回头路重新在它身上装），所以当前节点是能够挽救这个孩子的最后、也是唯一的机会，必须当场装上。
2. **否则（两个孩子都不是状态 0），如果左右孩子中有一个是状态 1（有摄像头）**，说明孩子的摄像头已经把当前节点覆盖到了，当前节点不需要再装摄像头，状态变为 2（有覆盖但无摄像头）。
3. **否则（两个孩子都是状态 2，都是有覆盖但都没装摄像头）**，说明没有任何一台摄像头能覆盖到当前节点——状态 2 的节点本身不带摄像头，它自己被覆盖不代表它能覆盖别人，所以当前节点得不到任何来自孩子方向的监控，只能被判定为状态 0（无覆盖），把这个"未决"状态原样向上传递给它的父节点去处理。

这三条规则的顺序不能颠倒：必须先检查是否存在无覆盖的孩子（最紧迫的情况），再检查是否已被覆盖，最后才是都没有覆盖也没有摄像头的兜底情况，因为一个节点可能同时满足多个条件的表面特征，只有按这个优先级才能保证决策的正确性。

### 根节点的收尾处理

后序遍历结束后，还有一个边界情况需要处理：根节点没有父节点，所以如果根节点最终被判定为状态 0（无覆盖），不会再有谁来给它兜底装摄像头。因此递归全部结束之后，需要单独检查根节点的返回状态，如果是状态 0，就额外给摄像头计数加一，相当于在根节点上强制装一台。

### 复杂度分析

整个算法是一次标准的后序遍历，每个节点只会被访问一次，在访问时进行 O(1) 的状态比较和判断，因此时间复杂度是 O(n)，其中 n 是树中节点总数。空间复杂度主要来自递归调用栈的深度，最坏情况下（树退化成一条链）递归深度为 O(n)，加上用来记录摄像头数量的计数器变量占用的常数空间，整体空间复杂度是 O(n)；如果是一棵较为平衡的二叉树，递归深度则是 O(log n)。

## 代码

### C++

```cpp
class Solution {
public:
    int result = 0; // 摄像头计数器

    // 三种状态：0 = 无覆盖，1 = 有摄像头，2 = 有覆盖无摄像头
    int traverse(TreeNode* node) {
        if (node == nullptr) {
            return 2; // 空节点定义为"有覆盖"，避免叶子节点被误判为需要装摄像头
        }

        int left = traverse(node->left);   // 后序遍历：先处理左子树
        int right = traverse(node->right); // 再处理右子树

        if (left == 0 || right == 0) {
            // 只要有一个孩子无覆盖，当前节点必须装摄像头兜底
            result++;
            return 1;
        }

        if (left == 1 || right == 1) {
            // 有孩子已经装了摄像头，当前节点被覆盖到
            return 2;
        }

        // 两个孩子都是"有覆盖无摄像头"，当前节点得不到覆盖，交给父节点处理
        return 0;
    }

    int minCameraCover(TreeNode* root) {
        if (traverse(root) == 0) {
            // 根节点没有父节点兜底，若根节点仍无覆盖，必须单独装一台
            result++;
        }
        return result;
    }
};
```

## 总结

- 本题必须自底向上（后序遍历）处理，因为判断当前节点是否需要装摄像头依赖于孩子节点的覆盖状态，而这个状态只有在孩子及其子树递归完成后才能确定。
- 三种状态（无覆盖 / 有摄像头 / 有覆盖无摄像头）是解题的核心设计，其中空节点被定义为"有覆盖"是让叶子节点逻辑自动正确工作的关键技巧，不需要为叶子写特殊分支。
- 贪心的本质是让摄像头尽量装在叶子节点的父节点而不是叶子节点本身，因为这样能同时利用摄像头"向上覆盖父节点、向下覆盖孩子"的两格监控能力，覆盖范围更大，摄像头利用率最高。
- 状态转移要按"存在无覆盖孩子 → 存在有摄像头孩子 → 否则无覆盖"的优先级顺序判断，遍历结束后还需单独检查根节点是否为无覆盖状态并补装一台摄像头。
