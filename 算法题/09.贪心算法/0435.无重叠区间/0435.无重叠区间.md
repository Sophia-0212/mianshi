# 0435. 无重叠区间

**题目描述**

给定一个区间的数组 `intervals`，其中 `intervals[i] = [starti, endi]`，返回需要移除区间的最小数量，使剩余区间互不重叠（区间的边界重合不算重叠，例如 `[1,2]` 和 `[2,3]` 视为不重叠）。

```
示例：
输入: intervals = [[1,2],[2,3],[3,4],[1,3]]
输出: 1
解释: 移除 [1,3] 后，剩下的区间 [[1,2],[2,3],[3,4]] 互不重叠。
```

## 思路

**贪心策略是什么**

这道题跟 452 题（用最少数量的箭引爆气球）思路几乎一模一样，本质上都是"区间重叠判断"问题，只是最终统计的目标不同罢了。这里我按右边界从小到大排序（当然按左边界排序也能讲通，这里选按右边界排序，逻辑更直观一些），排序后遍历区间，维护一个变量 `end` 记录"当前保留下来的区间的右边界"，初始为第一个区间的右边界。

对每个新遍历到的区间，判断它的左边界是不是小于 `end`：

- 如果小于，说明这个区间跟当前保留的区间发生重叠了，必须移除一个（移除计数加一）。为什么移除的是当前这个新区间呢？因为已经按右边界排过序了，当前遍历到的这个区间的右边界一定大于或等于 `end`（排序保证了右边界非递减），所以应该保留原来右边界更小的那个，`end` 不更新。
- 如果大于或等于，说明不重叠，这个区间可以直接保留，把 `end` 更新为这个新区间的右边界。

**为什么发生重叠时要移除右边界更大的区间**

你想啊，如果两个区间发生重叠了，不管移除哪一个，剩余需要移除的区间总数在"这一步"上都会加 1，这一步本身其实没区别。但移除哪一个会实质性地影响后续能保留多少区间——这才是贪心选择要考虑的关键点。

用交换论证来说明一下：假设最优解中，在这次重叠冲突里保留了右边界更大的区间 B，移除了右边界更小的区间 A。现在把这个选择换成"保留 A，移除 B"，这时候后续判断是否重叠的参照右边界，就从 B 的右边界变成了 A 的右边界，而 A 的右边界更小，也就是说参照的右边界变小了，这会让后续区间更容易满足"左边界 >= 参照右边界"这个不重叠条件（因为条件变得更宽松了），不会让后续本可以保留的区间因为参照右边界变化而被误判为重叠。所以，"保留右边界更小的那个"这个策略产生的最终移除总数，不会比保留右边界更大的那个更差——它给后续留出了更大的、不重叠的可用空间。因此贪心选择保留右边界小的区间，是不劣于任何其他选择的最优策略。

反过来说，如果保留了右边界更大的那个区间，相当于让后续判断的"及格线"变高了，本来可以保留的后续区间可能因为左边界小于这个偏大的右边界而被误判为重叠，导致移除更多本不需要移除的区间——这就是错误的贪心方向。

**452 题和 435 题的差异**

这两题在思路结构上几乎是同一个模板的两种应用，但目标和边界判断有些细微差异，写代码的时候要格外注意：

- 452 题求"最少需要几支箭"，本质上是在统计"有多少组互不重叠的区间集合"（每一组用一支箭覆盖，箭数就等于分组数）。
- 435 题求"最少移除几个区间"，本质上是"总区间数 - 不重叠分组数"（保留的区间数等于分组数，移除数就是总数减去这个值）。
- 边界重合的语义不一样：452 题的边界重合（气球左边界恰好等于箭的覆盖右边界）算作可以引爆，因为箭可以打在边界点上，所以用 `<=` 判断重叠；435 题题目明确说边界重合不算重叠（`[1,2]` 和 `[2,3]` 不重叠），所以用 `<` 判断重叠。这个符号上的一字之差，是这两题代码里最容易写错的地方，得留意。

**复杂度分析**

排序时间复杂度 O(n log n)，遍历一次时间复杂度 O(n)，总时间复杂度 O(n log n)；空间复杂度 O(1)（不考虑排序辅助空间）。

## 代码

### C++

```cpp
class Solution {
public:
    static bool cmp(const vector<int>& a, const vector<int>& b) {
        return a[1] < b[1];  // 按右边界从小到大排序
    }

    int eraseOverlapIntervals(vector<vector<int>>& intervals) {
        if (intervals.empty()) return 0;
        sort(intervals.begin(), intervals.end(), cmp);  // 按右边界排序
        int count = 0;                 // 需要移除的区间数
        int end = intervals[0][1];     // 当前保留区间的右边界
        for (int i = 1; i < intervals.size(); i++) {
            if (intervals[i][0] < end) {
                // 左边界小于当前保留区间右边界，发生重叠（边界重合不算重叠，用严格小于）
                // 排序后右边界非递减，当前区间右边界必然>=end，故移除当前区间，end不更新
                count++;
            } else {
                // 不重叠，保留这个区间，更新右边界
                end = intervals[i][1];
            }
        }
        return count;
    }
};
```

            }
        }

    }
}

import "sort"

func eraseOverlapIntervals(intervals [][]int) int {
    if len(intervals) == 0 {
        return 0
    }
    // 按右边界从小到大排序
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][1] < intervals[j][1]
    })
    count := 0                    // 需要移除的区间数
    end := intervals[0][1]        // 当前保留区间的右边界
    for i := 1; i < len(intervals); i++ {
        if intervals[i][0] < end {

            count++
        } else {
            // 不重叠，保留并更新右边界
            end = intervals[i][1]
        }
    }
    return count
}

## 总结

- 跟 452 题共享同一套"排序 + 维护边界变量"的贪心模板，区别在于统计目标（箭数 vs 移除数）和边界重合的语义（`<=` vs `<`）。
- 重叠时保留右边界更小的区间是关键贪心选择，用交换论证可以证明：保留右边界小的区间不会让后续判断变严格，所以不劣于保留右边界大的区间。
- 452 题统计"分组数"就是答案，435 题需要用"总数 - 分组数"才能得到移除数，二者本质上是同一个分组过程的不同读数方式。
- 区间重叠类问题写代码时要特别注意边界符号（`<` 还是 `<=`），这取决于题目对"边界重合是否算重叠"的具体定义。
