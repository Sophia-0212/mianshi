# 0649. Dota2参议院

**题目描述**

Dota2 的世界里有两个阵营：Radiant（天辉）和 Dire（夜魔）。Dota2 参议院由来自两派的参议员组成，现在参议院希望对某一 Dota2 游戏里的改变作出决定，他们以投票的形式决定。这个投票过程按照以下规则进行：

给定一个字符串 `senate` 代表每个参议员的阵营，`senate[i]` 为 `'R'` 或 `'D'`，字符所在位置代表投票次序。参议员按照排列顺序，轮流行使两项权利中的一项：
- **禁止一名参议员的权利**：参议员可以让另一位参议员在这一轮和随后的几轮中丧失所有权利。
- **宣布胜利**：如果参议员发现所有的参议员都是同一个阵营的，他可以宣布胜利并决定在游戏中的有关变化。

给定一个字符串代表每个参议员的阵营，请预测哪一个阵营最终会宣布胜利并在 Dota2 游戏中决定改变。输出应该是 `Radiant` 或 `Dire`。

```
示例：
输入：senate = "RD"
输出："Radiant"
解释：第 1 个参议员来自 Radiant 阵营，他可以使用第一项权利让第 2 个参议员失去权力。
剩下所有的参议员都是 Radiant 阵营的，所以宣布胜利。

输入：senate = "RDD"
输出："Dire"
解释：
第 1 个参议员来自 Radiant 阵营，他可以使用第一项权利禁止第 2 个参议员的权利。
第 2 个参议员被禁止了所有的权利。
第 3 个参议员来自 Dire 阵营，他可以使用他的权利禁止第 1 个参议员的权利。
因为参议院中只剩下第 3 个参议员，所以他可以宣布胜利。
```

## 思路

这道题表面上是在模拟投票流程，但真正的难点在于：投票是持续多轮进行的，不是走一遍字符串就结束了。如果每一轮都真的重新构造队列去模拟，会比较低效，而且容易写错索引。要抓住的贪心本质是——**每个参议员在轮到自己的时候，永远应该去禁止对方阵营中下一个即将行动的人**，为什么呢？因为那个人是对自己阵营威胁最直接、最紧迫的对手：与其禁止对方阵营里排得靠后的议员，不如先干掉马上就要出手的那个，这样自己才能保住这一轮的先发权。

基于这个贪心策略，我用两个队列分别存放 R 阵营和 D 阵营参议员的原始下标 `radiant` 和 `dire`。每一轮比较两个队列的队首下标：
- 若 `radiant` 队首下标更小，说明这个 R 参议员先轮到行动，他可以禁掉 `dire` 队首的那名议员（D 队首出队，不再入队，相当于被永久移除）；R 队首自己完成了这轮行动后，需要重新排到队伍末尾等待下一轮，但要保证他"下一轮"的次序仍然是合理的，所以重新入队时把下标加上 `n`（字符串总长度），表示"这是第二轮的位置"，这样即使两个队列混合比较，也能保证同一轮里先出现的人总是先被处理，跨轮次的顺序也不会错乱。
- 同理，若 `dire` 队首下标更小，则 D 阵营先禁掉 `radiant` 队首，D 队首本身下标加 `n` 重新入队。

不断重复这个"比较两队队首、小的禁大的、胜者重新入队（下标+n）"的过程，直到某一个队列完全空了，另一个队列不空，那不空的那个阵营就是最终胜者。

那为什么给重新入队的下标加 `n` 是正确的呢？因为 `n` 是原始字符串长度，也就是"一轮"的总参议员数上限。第一轮里所有原始下标都小于 `n`，当某个参议员活到第二轮的时候，他的"逻辑时间"应该晚于第一轮里所有还没行动过的参议员，加上 `n` 之后，他的下标必然大于第一轮任何原始下标，从而保证队列比较时严格反映了"谁先行动"的时间顺序。这其实是一种常见的技巧：用同一个数值维度（下标）同时编码"原始顺序"和"所在轮次"。

边界条件：只需要判断某一队列为空作为终止条件；由于每一轮都会消耗恰好一个议员（要么被禁止移出局，要么留下但下标变大），队列总长度单调递减，算法一定会终止。

复杂度分析：每个参议员最多入队 O(1) 次（每轮判定后不是出局就是转入下一轮，两个队列总长度之和每轮至少减 1），所以整体时间复杂度是 O(n)，空间复杂度是 O(n)（两个队列存储所有下标）。

## 代码

### C++

```cpp
class Solution {
public:
    string predictPartyVictory(string senate) {
        int n = senate.size();
        queue<int> radiant, dire;  // 分别存放 R、D 阵营参议员的下标
        for (int i = 0; i < n; i++) {
            if (senate[i] == 'R') radiant.push(i);
            else dire.push(i);
        }
        while (!radiant.empty() && !dire.empty()) {
            int r = radiant.front(); radiant.pop();  // R 阵营下一个行动的人
            int d = dire.front(); dire.pop();        // D 阵营下一个行动的人
            if (r < d) {
                // R 先行动，禁掉 D，R 存活并进入下一轮（下标+n 表示时间顺序后移）
                radiant.push(r + n);
            } else {
                dire.push(d + n);
            }
        }
        return radiant.empty() ? "Dire" : "Radiant";  // 哪个队列还有剩余就是赢家
    }
};
```

### Java

```java
class Solution {
    public String predictPartyVictory(String senate) {
        int n = senate.length();
        Queue<Integer> radiant = new LinkedList<>();
        Queue<Integer> dire = new LinkedList<>();
        for (int i = 0; i < n; i++) {
            if (senate.charAt(i) == 'R') radiant.offer(i);
            else dire.offer(i);
        }
        while (!radiant.isEmpty() && !dire.isEmpty()) {
            int r = radiant.poll();  // R 阵营下一个行动的下标
            int d = dire.poll();     // D 阵营下一个行动的下标
            if (r < d) {
                radiant.offer(r + n);  // R 先行动，禁掉 D，自己进入下一轮
            } else {
                dire.offer(d + n);     // D 先行动，禁掉 R，自己进入下一轮
            }
        }
        return radiant.isEmpty() ? "Dire" : "Radiant";
    }
}
```

### Python

本题是状态模拟类问题，没有对应的标准库一行解，只有手写队列模拟：

```python
from collections import deque

class Solution:
    def predictPartyVictory(self, senate: str) -> str:
        n = len(senate)
        radiant = deque(i for i, c in enumerate(senate) if c == 'R')  # R 阵营下标队列
        dire = deque(i for i, c in enumerate(senate) if c == 'D')    # D 阵营下标队列

        while radiant and dire:
            r = radiant.popleft()  # R 阵营下一个要行动的人
            d = dire.popleft()     # D 阵营下一个要行动的人
            if r < d:
                # R 更早行动，禁掉 D；R 存活，下标+n 表示进入下一轮
                radiant.append(r + n)
            else:
                dire.append(d + n)

        return "Radiant" if radiant else "Dire"  # 非空的队列即为胜者
```

### Go

```go
func predictPartyVictory(senate string) string {
    n := len(senate)
    radiant := make([]int, 0, n)
    dire := make([]int, 0, n)
    for i, c := range senate {
        if c == 'R' {
            radiant = append(radiant, i)
        } else {
            dire = append(dire, i)
        }
    }

    for len(radiant) > 0 && len(dire) > 0 {
        r, d := radiant[0], dire[0]
        radiant, dire = radiant[1:], dire[1:] // 弹出两队队首
        if r < d {
            radiant = append(radiant, r+n) // R 先行动，禁掉 D，自己进入下一轮
        } else {
            dire = append(dire, d+n) // D 先行动，禁掉 R，自己进入下一轮
        }
    }

    if len(radiant) > 0 {
        return "Radiant"
    }
    return "Dire"
}
```

## 总结

- 核心贪心策略是"谁先行动谁就优先消灭对方下一个即将行动的人"，本质上是在争夺行动的先手权，这类"轮流行动、互相消耗"的博弈模拟题经常可以转化为贪心+队列模型。
- 给重新入队的下标加上 `n` 是本题最关键的技巧：它把"轮次信息"编码进了下标数值本身，让两个独立队列之间依然可以通过简单的数值比较还原出全局的真实时间顺序，避免了显式模拟每一轮、每一个位置的复杂操作。
- 时间复杂度做到了 O(n)，因为每一轮必定有一个参议员永久出局，循环次数不会超过参议员总数。
- 容易犯的错误是直接用两个指针在原字符串上模拟轮转，忘了被禁止的参议员是永久出局的，还试图给"存活"和"出局"分别加复杂的标记数组——队列模型天然免除了这个麻烦，因为出队的人默认不会再出现，除非显式重新入队。
