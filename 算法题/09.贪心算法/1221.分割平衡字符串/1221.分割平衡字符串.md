# 1221. 分割平衡字符串

**题目描述**

在一个「平衡字符串」中，`'L'` 和 `'R'` 字符的数量是相同的。

给你一个平衡字符串 `s`，请你将它分割成尽可能多的平衡字符串。注意：分割得到的每个字符串都必须是平衡字符串（要求分割后每一部分单独看，L 和 R 数量相等），且必须使用原字符串的全部字符（不能省略任何字符）。

返回可以通过分割得到的平衡字符串的最大数量。

```
示例：
输入：s = "RLRRLLRLRL"
输出：4
解释：s 可以分割为 "RL"、"RRLL"、"RL"、"RL"，每个子字符串中都包含相同数量的 'L' 和 'R'。

输入：s = "RLLLLRRRLR"
输出：3
解释：s 可以分割为 "RL"、"LLLRRR"、"LR"，每个子字符串中都包含相同数量的 'L' 和 'R'。
```

## 思路

这题算是"贪心+计数器归零切分"这一类技巧里最基础的应用了，把这道题吃透，后面很多括号匹配、前缀和归零分段的题目都能用类似思路去解决。

先想清楚一个直觉性的问题：为什么贪心地"一旦满足条件就立刻切一刀"是对的，而不用考虑"要不要再往后多看几个字符，凑出一个更大的平衡串"呢？答案就在于，题目要的是**分割数量最多**，不是分出来的子串要满足什么别的花样要求。你想啊，如果在第i个位置计数器刚好归零了（也就是从上一个切点到i这一段里L和R数量相等），这时候不切、继续往后走会怎样？最终大字符串肯定还是保持平衡的（因为整体本来就是平衡的），但这么一来，本来可以独立切出来的一段，就被强行跟后面的内容合并成了一段，只会让总的分割段数变少或不变，绝不会变多。所以，只要出现计数器归零的机会，立刻切分总是不劣的选择，这就是这个贪心策略成立的关键。

那具体怎么实现呢？从左到右扫描字符串，维护一个计数器 `balance`（初始为0），遇到 `'L'` 就加1，遇到 `'R'` 就减1（反过来也行，只要两者符号相反就成）。当 `balance` 回到0的时候，说明什么呢？说明从上一次切分点到当前位置这一段子串里，L和R的数量正好相等，构成了一个合法的平衡子串——这时候就把结果计数器加1，代表切出了一段，然后接着往后扫。不用真的物理切割字符串，逻辑上认为"这一段结束了"就行，计数器归零之后自然就重新开始统计下一段了。

这里还能证明一下：整个大字符串本身是平衡的（题目给的前提条件），所以扫到字符串末尾的时候，`balance` 一定会恰好归零一次，作为最后一段的收尾，不会出现"扫完了但计数器还不为零"这种情况。这也是为什么循环外不需要单独处理收尾逻辑。

边界条件说一下：字符串长度为0时结果应该是0（虽然题目一般保证是非空且平衡的）；如果字符串全是最小平衡单元"LR"或"RL"这种两两组合，那每两个字符就能切一次，这是这个算法能切出最多段数的最好情形。

复杂度分析：只需要一次线性扫描，时间复杂度O(n)；只用了一个整数计数器和一个结果计数器，空间复杂度O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int balancedStringSplit(string s) {
        int balance = 0;  // L 记 +1，R 记 -1，归零说明当前段落平衡
        int count = 0;    // 记录切分出的平衡子串数量
        for (char c : s) {
            balance += (c == 'L') ? 1 : -1;  // 累加当前字符对平衡度的贡献
            if (balance == 0) {
                count++;      // 归零，说明可以在此处切一刀
            }
        }
        return count;
    }
};
```

### Java

```java
class Solution {
    public int balancedStringSplit(String s) {
        int balance = 0;  // L 记 +1，R 记 -1
        int count = 0;     // 切分出的平衡子串数量
        for (char c : s.toCharArray()) {
            balance += (c == 'L') ? 1 : -1;  // 更新当前字符的贡献
            if (balance == 0) {
                count++;  // 计数器归零，可以在此处独立切出一段
            }
        }
        return count;
    }
}
```

### Python

本题逻辑非常简单，标准库没有直接对应的一行解法，直接给出手写实现：

```python
class Solution:
    def balancedStringSplit(self, s: str) -> int:
        balance = 0  # L 记 +1，R 记 -1，归零说明当前段落已经平衡
        count = 0    # 切分出的平衡子串数量
        for c in s:
            balance += 1 if c == 'L' else -1  # 累加当前字符对平衡度的贡献
            if balance == 0:
                count += 1  # 归零，贪心地立刻切一刀
        return count
```

### Go

```go
func balancedStringSplit(s string) int {
    balance := 0 // L 记 +1，R 记 -1
    count := 0   // 切分出的平衡子串数量
    for _, c := range s {
        if c == 'L' {
            balance++ // L 对平衡度贡献 +1
        } else {
            balance-- // R 对平衡度贡献 -1
        }
        if balance == 0 {
            count++ // 归零，说明当前段落已平衡，贪心切一刀
        }
    }
    return count
}
```

## 总结

- 这题贪心为什么成立呢？说白了就是"越早切分，总段数不会变少"这个单调性——只要计数器归零就立刻切，既不会影响整体的平衡性，又能保证段数最多。
- "遇到某类字符+1、遇到另一类字符-1、计数器归零就算成立"，这是处理成对匹配、平衡类问题的一个通用范式，同样的思路你在有效括号匹配、判断字符串能否被特定模式整除这些题目里也能看到。
- 不用真的对字符串做切割操作，只要用一个整型变量去模拟"当前段落是不是平衡的"就行，这是用O(1)额外空间代替显式数据结构操作的一个典型例子。
- 容易搞混的一点是，这里统计的是"能切出多少段"，不是"每段具体是什么内容"，所以归零那一瞬间给计数器加一就够了，完全不需要记录子串的起止下标或者具体字符。
