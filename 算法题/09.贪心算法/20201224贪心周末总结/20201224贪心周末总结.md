# 20201224贪心周末总结

这周集中做了四道区间相关的贪心题：452（用最少数量的箭引爆气球）、435（无重叠区间）、763（划分字母区间）、56（合并区间）。这四题表面上问的问题各不相同（有的求箭数、有的求移除数、有的求切分片段、有的求合并结果），但你仔细看会发现底层用到的贪心思路高度同源，都是围绕"区间重叠判断"展开的。这篇总结把这四题串起来看，梳理出一套通用的处理范式。

## 区间类问题的通用处理范式

这四道题里，452、435、56 三题的第一步都是"排序"——按左边界（或右边界）把所有区间从小到大排好。排序看起来只是一个预处理步骤，但它的作用远不止"让数据更整齐"，你想啊，如果不排序，任意两个区间之间是否重叠，理论上需要两两比较才能确认，这在最坏情况下是 O(n²) 的复杂度，而且比较逻辑会因为区间顺序混乱而变得复杂。排序之后，区间按照左边界（或右边界）单调递增排列，这样只需要维护一个或两个变量（比如"当前箭的覆盖右边界""当前保留区间的右边界"），用一次线性遍历（O(n)）就能正确处理所有的重叠关系。排序把"任意顺序下复杂的两两关系"转化成了"局部相邻区间之间简单的顺序关系"，这就是这类问题里贪心算法能够生效的根本原因。

763 题（划分字母区间）虽然表面上不涉及对一组显式的区间数组排序，用的是"记录每个字母最后出现位置"这样一个数组，但你仔细看它的本质：可以把每个字母的"首次出现到最后一次出现"看作一个隐式区间，问题实际上是在做这些隐式区间的合并——维护 `right` 变量的过程，就是在不断合并当前片段内所有出现过的字母对应的区间，直到没有字母的区间能再扩展这个片段。所以763题在思路上和另外三题是同源的，属于"区间合并思想"在字符串场景下的一种变体应用，只是它借助字符集大小固定（26个字母）这一特点，用数组下标代替了显式的排序步骤。

## 四题的共性与细微差异对比

| 题目 | 排序依据 | 重叠/切分判断条件 | 贪心目标 |
|---|---|---|---|
| 452 箭引爆气球 | 左边界升序 | 左边界 <= 当前箭覆盖右边界（含等号，边界重合可以引爆） | 统计不重叠分组数 = 最少箭数 |
| 435 无重叠区间 | 左边界升序（或右边界升序） | 左边界 < 当前保留区间右边界（不含等号，边界重合不算重叠） | 总区间数 - 不重叠分组数 = 最少移除数 |
| 763 划分字母区间 | 无需显式排序，用最后出现位置数组 | 遍历下标 == 当前片段右边界时切分 | 最多切分出的片段数 |
| 56 合并区间 | 左边界升序 | 左边界 <= 结果集最后区间右边界 | 合并后的区间列表 |

从这个表格能看出几个值得注意的细节：

第一，边界重合的语义在不同题目里并不统一，得根据题意具体判断，不能想当然地套用统一的 `<=` 或 `<`。452题中箭可以打在气球区间的边界点上，所以边界重合视为可以引爆，用 `<=`；435题题目明确说明边界重合的区间不算重叠（比如 `[1,2]` 和 `[2,3]`），所以要用严格的 `<`。这一个符号的差异，是这两题代码里最容易出错、也最能体现"读题要读细节"的地方。

第二，452和435本质上是同一个"分组"过程的两种不同读数方式。452题统计的是"能划分出多少组互不重叠的区间集合"，这个分组数直接就是答案（箭数）；435题统计的也是同样的分组过程，但答案是"总区间数减去分组数"，因为分组数对应的是"最多能保留多少个互不重叠的区间"，移除数自然就是总数减去保留数。理解了这一层，就能看出这两题几乎是用同一套遍历逻辑，只是最后返回的数值做了一次简单的算术变换。

第三，56题和前两题的核心差别在于它需要真正构造并返回合并后的区间数组，而不只是统计一个数字，所以需要一个 `result` 列表来累积实际的区间结果，并且合并时要更新右边界为"较大值"（覆盖两者），这一点跟452题合并时取"较小值"（求交集）恰好相反——因为452题要找箭能同时命中两者的公共部分，而56题要合并出能完整覆盖两者的并集。

## 总结

- 排序 + 线性遍历是区间类问题的核心处理范式，把原本无序的两两比较关系转化为有序的相邻关系，把复杂度从 O(n²) 降到 O(n log n)。
- 452和435的贪心逻辑本质相同（都是统计不重叠分组数），差异仅在于边界语义（`<=` 还是 `<`）和最终读数方式（分组数本身，还是总数减分组数）。
- 763题借助字符集有限的特点，用数组代替排序，本质仍是区间合并思想的变体，说明贪心策略的迁移不局限于表面形式相同的题目。
- 求交集（取较小右边界，如452）和求并集（取较大右边界，如56）是两种方向相反但同样常见的区间合并操作，写代码前要先想清楚这道题究竟是要"两者都覆盖"还是"两者合起来覆盖"，方向搞反会导致贪心逻辑完全错误。
