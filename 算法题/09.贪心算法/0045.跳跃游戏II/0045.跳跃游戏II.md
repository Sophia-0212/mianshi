# 0045. 跳跃游戏II

**题目描述**

给定一个非负整数数组 `nums`，数组中的每个元素代表你在该位置可以跳跃的最大长度。你的目标是使用最少的跳跃次数到达数组的最后一个位置。假设你总能到达数组的最后一个位置。

```
示例：
输入: nums = [2,3,1,1,4]
输出: 2
解释: 跳到下标1（跳1步），然后跳3步到达最后一个位置（下标4）。
```

## 思路

**贪心策略是什么**

这题我维护两个边界变量。你想啊，一个叫 `curDistance`，表示"当前这一跳，我最远能跳到哪儿"；另一个叫 `nextDistance`，表示"如果我再多跳一步，下一跳最远能跳到哪儿"。遍历数组的时候，我会一直用 `max(nextDistance, i + nums[i])` 去更新 `nextDistance`。那什么时候跳跃次数才加一呢？就是当我遍历到某个下标 `i`，正好等于 `curDistance` 的时候——这说明当前这一跳的覆盖范围已经走到头了，必须再跳一次才能往前走，这时候跳跃次数加一，同时把 `curDistance` 更新成 `nextDistance`，正式进入下一跳能覆盖的范围。

这里的关键是什么呢？其实这本质上就是一种类似 BFS 按层扩展的思路。你可以把 `curDistance` 想象成当前这一"层"（用现在的跳跃次数能覆盖到的范围），`nextDistance` 就是下一"层"能覆盖的范围。每次遍历走到当前层的边界，就必须往下一层扩展，层数——也就是跳跃次数——就加一。

**为什么这样贪心是对的**

那为什么这样贪心是对的呢？你要用最少的跳跃次数到达终点，说白了就等价于：用最少数量的"覆盖区间"去把从起点到终点的整条路径完整盖住，每一次跳跃对应一个覆盖区间。要让区间数量最少，那每一个区间就得尽可能大，也就是说，每一跳都应该在当前能选的范围里，挑一个能让下一跳覆盖范围最大化的落脚点。

这里有个挺巧妙的地方：我们其实不需要在"当前范围内的每个位置"里，非得显式地挑出一个具体落脚点来——可以偷个懒。只要把当前覆盖范围内所有位置都遍历一遍，同时一直记录这些位置里谁能提供最大的下一跳覆盖范围（也就是不停更新 `nextDistance`），这就等于隐式地选出了"当前范围内最优的落脚点"了。为什么呢？因为不管你最终具体是从哪个位置起跳的，只要这个位置落在当前覆盖范围之内，它就是可达的，而它能提供的下一跳范围早就已经被合并进 `nextDistance` 里了。

那为什么必须要把当前范围内所有位置都遍历完，才能决定跳跃，不能提前跳呢？你想，如果还没遍历完当前范围就急着跳，很可能会错过范围里某个位置能提供的更大跳跃能力。打个比方，假设当前范围是下标0到3，恰好下标3这个位置能跳得特别远（比0、1、2都远），但你遍历到下标1的时候就提前拍板"这一跳就跳到这儿了"，那你就永远看不到下标3能提供的这个更大范围了，后面很可能就得多跳几次才能到终点。反过来说，如果把当前范围内所有位置都遍历完、并且一直合并记录这个范围里能达到的最大下一跳范围，那就能保证每一次"层扩展"都用上了当前信息下能达到的最大范围，一点都不会浪费。

这其实正是 BFS 按层扩展求最短路径层数的贪心本质——你得把每一层能覆盖的所有节点都处理完，才能保证扩展出来的下一层，是当前状态下能达到的最大范围，这样才能保证层数（也就是跳跃次数）最少。反过来也可以这么论证它的最优性：假设存在一种跳跃次数更少的方案，那它每一跳的覆盖范围肯定不会超过"遍历完当前范围内所有位置后能得到的最大 nextDistance"，因为这已经是当前范围内所有位置能提供的覆盖能力的最大值了，不存在比它更大的选择。所以按这个方法一层一层扩展得到的跳跃次数，已经是理论上能达到的最小值了。

**实现细节：循环条件为什么写成 `i < nums.size() - 1`**

这里有个实现细节值得说一说：遍历的时候通常不会遍历数组的最后一个下标。为什么呢？因为一旦到达最后一个位置，任务其实已经完成了，不需要再判断"是不是还要为了继续前进多跳一次"。如果让最后一个下标也参与"`i == curDistance` 时跳跃次数加一"这个判断，可能就会出问题——比如 `curDistance` 恰好等于最后一个下标的时候，会被误判成"还需要再跳一次才能继续"，但实际上已经不用再往前走了，这就多算了一次不必要的跳跃。所以遍历范围只到倒数第二个下标为止，就是为了避免这种多算的情况。

**复杂度分析**

只需要遍历一次数组，时间复杂度 O(n)。只需要几个变量记录当前范围、下一范围和跳跃次数，空间复杂度 O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        if (nums.size() == 1) return 0;  // 起点即终点，不需要跳跃
        int curDistance = 0;   // 当前这一跳能到达的最远距离
        int nextDistance = 0;  // 再多跳一步能到达的最远距离
        int result = 0;        // 跳跃次数
        for (int i = 0; i < nums.size() - 1; i++) {  // 不遍历最后一个下标，避免多算一次
            nextDistance = max(nextDistance, i + nums[i]);  // 持续合并下一跳能到达的最大范围
            if (i == curDistance) {  // 当前跳跃的覆盖范围已经走到尽头，必须再跳一次
                curDistance = nextDistance;  // 扩展到下一层覆盖范围
                result++;                    // 跳跃次数加一
            }
        }
        return result;
    }
};
```

## 总结

- 贪心策略就是维护两个边界，`curDistance`（当前跳的覆盖范围）和 `nextDistance`（下一跳的覆盖范围），等遍历走到当前边界了才扩展到下一层，本质上就是 BFS 按层扩展求最短路径层数的思路。
- 正确性的关键在哪儿呢？就在于遍历完当前范围内所有位置后拿到的最大 `nextDistance`，正是这个范围内能提供的最大跳跃能力，不会再有更优的选择了，所以按层扩展得到的次数就是理论最小值。
- 如果提前跳跃、没把当前范围内所有位置遍历完，就可能错过范围里某个位置更大的跳跃能力，导致后面得多跳几次。
- 实现的时候循环范围要写成 `i < nums.size() - 1`，这样才能避免在已经到达终点的情况下还多算一次不必要的跳跃。
