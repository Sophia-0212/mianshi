# 0135. 分发糖果

**题目描述**

老师想给孩子们分发糖果，有 `n` 个孩子站成一排，每个孩子获得的糖果数量必须大于等于 1。老师会根据孩子们的表现给每个孩子一个评分数组 `ratings`，要求：

- 相邻两个孩子中，评分更高的孩子必须获得更多的糖果；
- 求满足以上条件所需要的最少糖果数总和。

```
示例：
输入: ratings = [1,0,2]
输出: 5
解释: 你可以分别给这三个孩子分发 2、1、2 颗糖果。

输入: ratings = [1,2,2]
输出: 4
解释: 你可以分别给这三个孩子分发 1、2、1 颗糖果。
第三个孩子只得到 1 颗糖果，这满足题面中的两个条件，因为评分相同的两个孩子不要求糖果数量的相对关系。
```

## 思路

这道题的难点在哪儿呢？糖果数量同时受到**左边邻居**和**右边邻居**两个方向的约束——你想啊，如果只看一个方向，很容易在处理下一个方向的时候把前一次的结果覆盖掉。直接同时兼顾两个方向很难贪心，但如果把问题拆成"只看左边"和"只看右边"两次独立的遍历，各自的贪心就变得非常简单了。

**第一次遍历（从左到右）**：只考虑"如果当前孩子比左边孩子评分高，那么糖果数必须比左边多"这一条件。先把每个孩子的糖果数都初始化为 1（保证最低要求），然后从左往右扫描：如果 `ratings[i] > ratings[i-1]`，就让 `candy[i] = candy[i-1] + 1`；否则不处理（保持 1，或者维持之前赋的值）。这一步就保证了所有"右边比左边高"的位置都满足了糖果递增的要求。

**第二次遍历（从右到左）**：只考虑"如果当前孩子比右边孩子评分高，那么糖果数必须比右边多"这一条件。从右往左扫描：如果 `ratings[i] > ratings[i+1]`，那 `candy[i]` 就需要比 `candy[i+1]` 多，但注意，此时 `candy[i]` 已经在第一次遍历中被赋过值了（可能是满足左边条件的值），所以要取 `max(candy[i], candy[i+1] + 1)`，而不能直接覆盖。

**为什么这个"两次遍历、每次只看一个方向，最后取较大值合并"的贪心是正确的？** 关键就在于，每个位置的糖果数最终必须同时满足两个方向的约束——如果两边都比它低，那就取两者中要求更严格的那个；如果只有一边更高，那就遵从那一边。第一次遍历确保了"左边约束"对所有位置都成立，而且是这一约束下的最小解；第二次遍历在不破坏第一次结果的前提下（注意用的是 `max` 而不是直接赋值），把"右边约束"也补齐到最小解。两次都是局部最优（每一步只取满足当前方向约束所需的最小增量），而这两个局部最优合并之后恰好构成全局最优，为什么呢？因为两个方向的约束是独立可分解的——一个孩子的糖果数只需要 `>=` 两侧约束中更大的那个即可同时满足两个条件，不存在因为满足了左边约束而破坏右边约束的情况（`max` 操作保证了这一点）。

最后把所有孩子的糖果数相加，就是答案了。

**复杂度分析**：两次线性遍历，时间复杂度 O(n)；需要一个长度为 n 的数组保存每个孩子的糖果数，空间复杂度 O(n)。

## 代码

### C++

```cpp
class Solution {
public:
    int candy(vector<int>& ratings) {
        int n = ratings.size();
        vector<int> candyVec(n, 1); // 每个孩子至少 1 颗糖果

        // 从左到右：只处理右边比左边评分高的情况
        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i - 1]) {
                candyVec[i] = candyVec[i - 1] + 1;
            }
        }

        // 从右到左：只处理左边比右边评分高的情况，取较大值不破坏之前的结果
        for (int i = n - 2; i >= 0; i--) {
            if (ratings[i] > ratings[i + 1]) {
                candyVec[i] = max(candyVec[i], candyVec[i + 1] + 1);
            }
        }

        int result = 0;
        for (int c : candyVec) result += c; // 汇总糖果总数
        return result;
    }
};
```

```python
class Solution:
    def candy(self, ratings: list[int]) -> int:
        n = len(ratings)
        candy_arr = [1] * n  # 每个孩子至少 1 颗糖果

        # 从左到右：处理右边比左边评分高的情况
        for i in range(1, n):
            if ratings[i] > ratings[i - 1]:
                candy_arr[i] = candy_arr[i - 1] + 1

        # 从右到左：处理左边比右边评分高的情况，取较大值避免覆盖
        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i + 1]:
                candy_arr[i] = max(candy_arr[i], candy_arr[i + 1] + 1)

        return sum(candy_arr)  # 汇总糖果总数
```

```go
func candy(ratings []int) int {
    n := len(ratings)
    candyArr := make([]int, n)
    for i := range candyArr {
        candyArr[i] = 1 // 每个孩子至少 1 颗糖果
    }

    // 从左到右：处理右边比左边评分高的情况
    for i := 1; i < n; i++ {
        if ratings[i] > ratings[i-1] {
            candyArr[i] = candyArr[i-1] + 1
        }
    }

    // 从右到左：处理左边比右边评分高的情况，取较大值
    for i := n - 2; i >= 0; i-- {
        if ratings[i] > ratings[i+1] {
            if candyArr[i+1]+1 > candyArr[i] {
                candyArr[i] = candyArr[i+1] + 1
            }
        }
    }

    result := 0
    for _, c := range candyArr {
        result += c // 汇总
    }
    return result
}
```

## 总结

- 当一个位置同时受两个方向约束、直接一次遍历难以兼顾的时候，可以拆成"只看左边"和"只看右边"两次独立遍历，这是贪心里"分而治之"的常见技巧。
- 第二次遍历必须用 `max(当前值, 新约束值)` 合并结果，不能直接赋值覆盖，不然会破坏第一次遍历已经满足的约束。
- 两次遍历各自都是在自己方向上的最小解，合并后依然是全局最小解，因为两个方向的约束通过 `max` 操作可以无冲突地同时满足。
- 这种"两次单方向遍历 + 合并"的模式在后续类似需要同时满足左右邻居约束的题目中还会反复出现，值得作为一个独立的贪心套路记住。
