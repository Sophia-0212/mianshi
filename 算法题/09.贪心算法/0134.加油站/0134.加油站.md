# 0134. 加油站

**题目描述**

在一条环形路径上有 `n` 个加油站，第 `i` 个加油站有汽油 `gas[i]` 升。你有一辆油箱容量无限的汽车，从第 `i` 个加油站开往第 `i+1` 个加油站需要消耗汽油 `cost[i]` 升。你从其中一个加油站出发，开始时油箱为空。

给定两个整数数组 `gas` 和 `cost`，如果你可以绕环路行驶一周，则返回出发时加油站的编号，否则返回 -1。题目保证如果存在解，则该解唯一。

```
示例：
输入: gas = [1,2,3,4,5], cost = [3,4,5,1,2]
输出: 3
解释:
从下标 3 出发，可获得 4 升汽油，油箱剩余 = 0 + 4 = 4
开往下标 4，此时油箱有 4 - 1 + 5 = 8
开往下标 0，此时油箱有 8 - 2 + 1 = 7
开往下标 1，此时油箱有 7 - 3 + 2 = 6
开往下标 2，此时油箱有 6 - 4 + 3 = 5
开往下标 3，走完了整个环路
```

## 思路

**第一步：判断解是否存在**

你想啊，把这一圈跑下来，总共能加到的油是 `sum(gas)`，总共要消耗的油是 `sum(cost)`。如果 `sum(gas) < sum(cost)`，那不管从哪里出发，油都不够，直接返回 -1 就行。这是个必要条件，后面的贪心讨论都是建立在 `sum(gas) >= sum(cost)` 这个前提上的。

**第二步：贪心找起点**

我们定义每个加油站的"净收益" `rest[i] = gas[i] - cost[i]`，表示在这一站加油、开往下一站之后，油箱净变化多少。如果 `sum(gas) >= sum(cost)`，也就是 `sum(rest) >= 0`，那一定存在一个起点能跑完全程。

贪心策略是这样的：从下标 0 开始，用一个变量 `curSum` 累加 `rest[i]`。一旦发现 `curSum` 变成负数了，说明什么呢？说明从当前的起始候选点出发，油箱在到达 `i` 这一站时已经耗尽了（撑不到这里）。所以**从起始候选点到 `i` 之间的任何一个点作为起点都不可能成功**——为什么呢？因为如果起点在这个区间内更靠后，能带的"余量"只会更少，前面已经是负的了，换一个更晚的起点只会让情况更糟或者一样撑不住。所以我们直接把起始候选点重置为 `i + 1`，重新开始累加。

那为什么"从 i+1 重新开始"是安全的、不会错过真正的答案呢？可以这样理解：设原本的候选起点为 `start`，我们在 `[start, i]` 这段区间上验证过 `curSum` 首次跌破 0 是在下标 `i`。对于区间内任意一点 `j`（`start <= j <= i`），从 `j` 出发时的累加和是 `curSum(start..i) - curSum(start..j-1)`。由于 `curSum(start..i) < 0`，而且前缀 `curSum(start..j-1) >= 0`（因为在 `j` 之前都没有跌破 0），所以从 `j` 出发到 `i` 的累加和只会更小，同样是负的，撑不到 `i` 之后。这就说明 `[start, i]` 内的所有点都不可能是答案，可以整体跳过，起点安全地跳到 `i + 1`。

遍历完一整圈之后，最后停留的 `curSum` 不会是负的（因为总和 `sum(rest) >= 0`，而且我们已经跳过了所有会导致负数的区间），这时候的候选起点就是唯一解。

**为什么不需要模拟"绕圈之后再验证一次"？** 因为一旦确定 `sum(rest) >= 0`，并且找到了满足"从起点到任意后续点累加和都不为负"的候选点，数学上就已经保证了它能绕完一整圈——这正是贪心算法在这里成立的核心：局部的"及时止损、重新起跳"策略，配合全局总量非负这个前提，直接就能推导出全局可行解，不需要额外验证了。

**复杂度分析**：只需要一次线性遍历，时间复杂度 O(n)；只用了常数个额外变量，空间复杂度 O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int totalSum = 0;   // 全局净收益之和，用于判断解是否存在
        int curSum = 0;     // 从当前候选起点累加到 i 的净收益
        int start = 0;      // 候选起点下标
        for (int i = 0; i < gas.size(); i++) {
            int rest = gas[i] - cost[i]; // 当前站的净收益
            curSum += rest;
            totalSum += rest;
            if (curSum < 0) {            // 从 start 出发撑不到 i，说明 [start, i] 都不可行
                start = i + 1;           // 候选起点跳到下一个位置
                curSum = 0;              // 重新累加
            }
        }
        if (totalSum < 0) return -1;     // 总油量不够，无解
        return start;                    // 唯一解
    }
};
```

        int totalSum = 0; // 全局净收益之和

                curSum = 0;
            }
        }
        if (totalSum < 0) return -1;    // 总量不足，无解
        return start;
    }
}

## 总结

- 先用总量判断解是否存在（`sum(gas) < sum(cost)` 直接无解），再用贪心遍历找具体起点，这两步不能颠倒，也不能省掉第一步。
- 贪心核心是：局部累加和一旦跌破 0，说明当前区间内所有候选起点都不可行，直接把候选起点跳到跌破点的下一位，这样才能保证不遗漏、不重复验证。
- 之所以贪心成立，是因为"总量非负"这个全局条件，保证了跳过所有不可行区间后剩下的候选点必然能撑完全程，不需要额外的绕圈验证。
- 本题只需一次 O(n) 遍历，是贪心算法中"边扫描边决策、及时重置"的典型模板。
