# 0406. 根据身高重建队列

**题目描述**

假设有打乱顺序的一群人站成一个队列，每个人由一个整数对 `(h, k)` 描述，其中 `h` 是这个人的身高，`k` 是排在这个人前面且身高大于或等于 `h` 的人数。请你重新构造并返回输入数组 `people` 所表示的队列。返回的队列应该形如 `[[h1,k1],[h2,k2],...]`，其中 `[hi, ki]` 是队列中第 `i` 个人的属性。

```
示例：
输入: people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]
输出: [[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]
解释:
编号为 0 的人身高为 5，前面没有身高大于等于 5 的人，所以他必须排在最前面。
编号为 1 的人身高为 7，前面也没有身高大于等于 7 的人，所以他排在第二位。
编号为 2 的人身高为 5，前面有 2 个身高大于等于 5 的人，那就是编号为 0 和 1 的人。
...（以此类推）
```

## 思路

这道题每个人受两个维度（身高 `h` 和前面人数 `k`）的约束，两个维度互相耦合，直接排列很难同时满足所有约束。贪心的关键思路是：**先固定一个维度的顺序，让这个维度不再变化，然后只用第二个维度去决定插入位置**，这样就把二维问题降成了一维问题。

**排序规则**：按身高 `h` 降序排列；如果身高相同，则按 `k` 升序排列。

**为什么先按身高降序处理？** 你想啊，`k` 的含义是"前面身高大于等于自己的人数"。如果我们从身高最高的人开始逐个插入队列，那对于当前正在插入的人来说，**已经插入队列中的人身高一定都大于等于他**（因为身高是降序处理的，后处理的人身高更低或相等）。这意味着什么呢？当前这个人前面应该有多少个身高≥他的人，就等价于他在当前已排好的队列中应该插入的下标位置——直接把他插入到下标为 `k` 的位置就行了，不需要考虑后续还没处理的人（因为后续的人身高更低，不会被计入他的 `k` 值）。

反过来说，如果先处理身高低的人，插入位置就会因为后续插入身高更高的人而被打乱，需要额外调整，贪心就不成立了。所以"先处理身高高的、再处理身高低的"是这里贪心能够成立的核心原因：**每一步插入操作都不会被后续操作破坏**，因为后续插入的人身高更低，对已经确定位置的人不构成"身高≥我"的影响。

**身高相同时为什么按 k 升序？** 如果两人身高相同，谁的 k 更小，说明他前面被要求的"身高≥自己的人数"更少，理应更靠前插入；按 k 升序处理可以保证插入顺序跟最终位置的相对关系一致，不会互相冲突。

**插入方式**：排好序后，依次把每个人插入到结果列表的下标 `k` 处（类似链表/数组的插入操作，后面的元素整体后移）。

**复杂度分析**：排序时间复杂度 O(n log n)；插入操作如果用数组实现，每次插入平均需要 O(n) 移动其余元素，n 次插入总共 O(n²)；如果用支持 O(log n) 插入的数据结构（如平衡树、链表配合索引）可以优化到 O(n log n)，但对多数题目规模 O(n²) 已经足够通过。

## 代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> reconstructQueue(vector<vector<int>>& people) {
        // 身高降序；身高相同时 k 升序
        sort(people.begin(), people.end(), [](const vector<int>& a, const vector<int>& b) {
            if (a[0] == b[0]) return a[1] < b[1];
            return a[0] > b[0];
        });

        vector<vector<int>> result;
        for (auto& p : people) {
            result.insert(result.begin() + p[1], p); // 插入到下标为 k 的位置
        }
        return result;
    }
};
```

### Java

```java
class Solution {
    public int[][] reconstructQueue(int[][] people) {
        // 身高降序；身高相同时 k 升序
        Arrays.sort(people, (a, b) -> {
            if (a[0] == b[0]) return a[1] - b[1];
            return b[0] - a[0];
        });

        LinkedList<int[]> result = new LinkedList<>();
        for (int[] p : people) {
            result.add(p[1], p); // 插入到下标为 k 的位置，LinkedList 插入更高效
        }
        return result.toArray(new int[people.length][]);
    }
}
```

    def reconstructQueue(self, people: list[list[int]]) -> list[list[int]]:
        # 身高降序；身高相同时 k 升序
        people.sort(key=lambda p: (-p[0], p[1]))

        result = []

            result.insert(p[1], p)  # 插入到下标为 k 的位置
        return result

### Go

```go
func reconstructQueue(people [][]int) [][]int {
    // 身高降序；身高相同时 k 升序
    sort.Slice(people, func(i, j int) bool {
        if people[i][0] == people[j][0] {
            return people[i][1] < people[j][1]
        }
        return people[i][0] > people[j][0]
    })

    result := make([][]int, 0, len(people))
    for _, p := range people {
        k := p[1]
        result = append(result, nil)
        copy(result[k+1:], result[k:]) // 后面元素整体后移一位
        result[k] = p                  // 插入到下标为 k 的位置
    }
    return result
}
```

## 总结

- 遇到"每个元素受两个维度约束"的问题时，可以尝试先固定一个维度的处理顺序，把二维问题降成一维问题，这是一种通用的贪心降维技巧。
- 本题按身高降序处理的本质原因是：先确定的人身高更高，后续插入的人不会影响已确定的人的"前面身高≥自己的人数"这一约束，从而保证每一步插入都不会被后续操作破坏。
- 身高相同时按 k 升序排列，是为了让同身高的人之间的相对顺序跟插入顺序保持一致。
- 直接用数组插入的实现方式简单直观但是 O(n²)，如果对性能有更高要求，可以考虑链表或树状结构优化插入操作。
