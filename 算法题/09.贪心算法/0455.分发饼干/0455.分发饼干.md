# 0455. 分发饼干

**题目描述**

给定两个数组：`g` 表示每个孩子的胃口值，`s` 表示每块饼干的尺寸。只有当饼干尺寸大于或等于孩子的胃口值时，这块饼干才能满足这个孩子。每个孩子最多只能分到一块饼干，每块饼干也最多只能分给一个孩子。求最多能满足多少个孩子。

```
示例：
输入: g = [1,2,3], s = [1,1]
输出: 1
解释: 你有三个孩子和两块小饼干，3个孩子的胃口值分别是1,2,3。
但是你只有两块饼干，如果只满足胃口值最小的孩子，你可以让胃口值为1的孩子得到满足，
输出1。
```

## 思路

这题是贪心算法里最经典的入门题了，为什么呢？因为它的贪心点特别直观，同时又能完整体现"排序后贪心"这一大类问题的处理范式，很适合当作入门。

**贪心策略是什么**

你想啊，把孩子的胃口数组 `g` 和饼干尺寸数组 `s` 都从小到大排个序，然后用两个指针，一个指向"当前待满足的最小胃口孩子"，一个指向"当前待分配的最小尺寸饼干"。每次比较一下：如果当前这块饼干够满足当前这个孩子的胃口，那就把这块饼干分给他，两个指针都往后移；如果不够呢，说明这块饼干太小了，谁都满足不了——因为它已经是当前最小的饼干里最小的一块了，比它胃口更大的孩子肯定也满足不了。这种情况直接跳过这块饼干，只移动饼干指针就行。

**为什么这个局部最优选择能推导出全局最优**

这里要证明的是什么呢？就是"用最小的饼干去尝试满足最小的孩子"这个局部决策，不会比其他任何分配方式得到更少的满足人数。

咱们用反证法，也就是交换论证来看：假设最优解里，某块小饼干 `s_small` 被分给了一个胃口比较大的孩子 `g_big`，而胃口最小的那个孩子 `g_small` 反而分到了一块更大的饼干 `s_big`（或者根本没分到）。这时候你会发现 `s_small >= g_big > g_small`。既然 `s_small >= g_big`，那 `s_small` 肯定也能满足 `g_small`，因为 `g_small <= g_big <= s_small` 嘛。所以我们完全可以把 `s_small` 和 `s_big` 的分配对象交换一下——让 `s_small` 去满足 `g_small`，让 `s_big` 去满足 `g_big`（前提是 `s_big` 也够满足 `g_big`）。交换完之后，满足的孩子总数不会变少，这就说明"用最小饼干优先满足最小胃口孩子"这个策略，至少不会比其他任何分配方案差。

反过来想也是一样的道理：如果最小的饼干连最小胃口的孩子都满足不了，那这块饼干在整堆饼干里就是彻底的"废饼干"了，谁都满足不了它，直接丢掉它是唯一合理的选择，不会浪费掉本来可以满足别人的机会。

正因为每一步的决策都不会让全局能满足的人数变少（交换之后结果不变或者更好），所以从最小胃口、最小饼干开始的这个贪心策略就是最优的。

**复杂度分析**

排序这部分的时间复杂度是 O(n log n + m log m)，n、m 分别是孩子数和饼干数；双指针遍历是 O(n + m)；所以总的时间复杂度就是 O(n log n + m log m)。空间复杂度是 O(1)，不算排序本身可能用到的辅助空间。

## 代码

### C++

```cpp
class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end());  // 胃口从小到大排序
        sort(s.begin(), s.end());  // 饼干尺寸从小到大排序
        int child = 0;             // 指向当前待满足的孩子
        int cookie = 0;            // 指向当前待分配的饼干
        while (child < g.size() && cookie < s.size()) {
            if (s[cookie] >= g[child]) {  // 当前饼干够满足当前孩子
                child++;                  // 满足一个孩子，孩子指针后移
            }
            cookie++;  // 无论是否满足，这块饼干都已经用过（用掉或判定为废饼干），指针后移
        }
        return child;  // child 的值即为满足的孩子数
    }
};
```

## 总结

- 这题是"排序后贪心"这一大类问题的入门代表：先把两个数组都排好序，再用双指针从一端开始贪心匹配。
- 贪心策略的正确性可以用交换论证来证明：如果小饼干分给了不该分的大胃口孩子，交换一下发现结果不会变差，这就说明"小饼干优先满足小胃口"这个策略不会比其他方案差。
- 如果最小的饼干连最小胃口都满足不了，直接丢弃这块饼干就是唯一合理的选择，因为它对任何孩子都没用了。
- 以后遇到"两个数组做匹配、追求满足数量最大化"这类题目，可以先考虑一下排序后贪心是否可行，这往往是个挺高效的突破口。
