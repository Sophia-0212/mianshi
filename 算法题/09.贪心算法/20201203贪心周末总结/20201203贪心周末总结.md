# 贪心算法周末总结（2020.12.03）

这周整理了三道贪心算法题，分别对应股票买卖、跳跃游戏，还有数组取反最大化的问题。场景虽然各不相同，但你会发现它们都体现了贪心算法"通过局部最优决策逐步逼近全局最优"这个共同思路。

## 一、买卖股票的最佳时机 II（LeetCode 122）：利润拆解思想

这道题允许多次买卖股票，求能获得的最大利润。如果直接从"哪天买、哪天卖"的角度去想，会觉得情况很复杂，得枚举很多种买卖时机组合。

贪心的巧妙之处在哪儿呢？就是换一个角度看待"利润"这个整体目标：把整个持有周期的总利润，拆解成每一天的利润贡献。具体来说，设 `prices[i]` 为第 `i` 天的价格，那么从第 `i-1` 天到第 `i` 天，如果 `prices[i] - prices[i-1] > 0`，就说明这一天存在正的利润差，把这部分利润"吃下来"（也就是在第 `i-1` 天买入、第 `i` 天卖出，或者理解成累加这部分差值）；如果差值是负的或者为0，就不参与累加，跳过就行。

为什么这样拆解是对的呢？可以这么理解：假设最优解是在某几个区间段买入卖出（比如第2天买、第5天卖），那这一段区间内的利润 `prices[5] - prices[2]`，其实恰好等于把中间每一天的价格差都加起来：`(prices[3]-prices[2]) + (prices[4]-prices[3]) + (prices[5]-prices[4])`。这是一个简单的代数恒等式（中间项相互抵消）。既然整段区间的利润等于逐日利润之和，那我们只要把所有"逐日利润为正"的部分都累加起来，自然就覆盖了所有可能带来正收益的区间，得到的就是全局最大利润。反过来，如果某一天的差值是负的，把它包含进买卖区间只会拉低总利润，所以不应该包含进去。

这就是贪心的体现：每一天独立地做局部判断（今天比昨天贵就"赚一笔"），不需要考虑全局的买卖点规划，局部贪心的总和恰好就是全局最优解。

```
// 伪代码示意
profit = 0
for i in 1..n-1:
    if prices[i] > prices[i-1]:
        profit += prices[i] - prices[i-1]
return profit
```

## 二、跳跃游戏 I 和 II（LeetCode 55、45）：维护可达边界

跳跃游戏的核心场景是：给定一个数组，`nums[i]` 表示在下标 `i` 处最多能向前跳的步数，问能不能到达最后一个下标（55题），或者到达最后一个下标所需的最少跳跃次数（45题）。

**55题的贪心思路**：维护一个变量 `maxReach`，表示当前遍历到的位置为止，整体能到达的最远下标。遍历数组时，每到一个下标 `i`（前提是 `i <= maxReach`，也就是这个位置本身是可达的），就用 `i + nums[i]` 去更新 `maxReach`：`maxReach = max(maxReach, i + nums[i])`。如果遍历过程中发现某个下标 `i > maxReach`，说明这个位置根本到不了，可以直接判定失败。要是遍历完成后 `maxReach` 已经覆盖了最后一个下标，那就说明能到达终点。

这里的贪心体现在哪呢？我们不需要具体规划"在哪一步跳多远"，只需要放宽视角，维护一个"当前所有可达位置中，向前跳能到达的最远距离"这个整体边界，每步只更新这个边界就行，不用回溯或者枚举跳跃路径。

**45题在55题基础上多了一层"分层"的思想**：因为要求最少跳跃次数，需要额外维护两个边界——`curEnd` 表示当前这一次跳跃能到达的最远边界，`nextEnd` 表示如果再跳一次（也就是在当前区间内的某个点起跳）能到达的最远边界。遍历下标的时候不断用 `i + nums[i]` 更新 `nextEnd`；当遍历到 `i == curEnd` 的时候，说明当前这一跳的范围已经遍历完了，必须再跳一次才能继续往前，这时把跳跃次数加1，并把 `curEnd` 更新为 `nextEnd`（进入下一层的范围）。

这种"双层边界"的做法，说白了本质上是一种 BFS 分层的思想：把可达位置按跳跃次数分层，第一层是一次跳跃能到达的所有位置，第二层是两次跳跃能到达的所有位置，以此类推。用两个变量滚动维护当前层和下一层的边界，就避免了显式建图和BFS队列的开销，是贪心和分层思想结合的一个典型应用。

## 三、K次取反后最大化的数组和（LeetCode 1005）：两步贪心

这道题给定一个整数数组和一个整数 `K`，可以选择数组中的任意元素，把它变成相反数，这个操作最多能进行 `K` 次（对同一个元素也可以多次操作），求操作后数组所有元素之和的最大值。

贪心策略分两步走：

**第一步**：优先把绝对值最大的负数变成正数。具体做法是先把数组按绝对值从大到小排序，然后从左到右遍历，只要遇到负数且 `K` 还有剩余，就把它取反（变成正数），同时 `K` 减1。这一步的贪心依据很直观：把一个数取反能带来的"总和增量"是 `2 * |该数|`（从 `-x` 变成 `x`，增量是 `2x`），所以要优先处理绝对值最大的负数，这样能带来的增量最大，对总和的提升最明显。

**第二步**：处理完所有能处理的负数后，如果 `K` 还有剩余，就得考虑怎么"消耗掉"多余的取反次数了。这里有个关键性质：对同一个数取反两次，等于没操作（`-(-x) = x`）。所以如果剩余的 `K` 是偶数，可以两两配对、原地消耗，不会影响任何元素的值，直接忽略就行；但如果剩余的 `K` 是奇数，就必然会有一次"多余"的取反没法被抵消，一定会有恰好一个元素被取反奇数次，从而改变符号。

既然这一次不可避免的取反一定会发生，贪心策略就是让它发生在"绝对值最小"的那个元素上。为什么呢？因为对绝对值为 `m` 的元素取反，会让总和减少 `2m`（从 `+m` 变成 `-m`，或者反过来），绝对值越小，损失越小。所以第一步处理完负数之后，找到数组中绝对值最小的元素，如果剩余 `K` 是奇数，就对它再取反一次，这样才能让"必然发生的负面影响"降到最低。

```
// 伪代码示意
sort array by absolute value descending
for each num in array (from largest abs to smallest):
    if num < 0 and K > 0:
        num = -num
        K -= 1
if K is odd:
    find element with smallest absolute value, negate it once
return sum(array)
```

## 总结

这三道题分别展示了贪心算法在不同场景下的应用形式：股票问题是"整体目标可拆解为局部贡献之和"；跳跃游戏是"维护滚动更新的边界变量代替显式路径枚举"；取反最大化问题是"分步贪心，先处理收益最大的操作，再用最小代价消耗剩余资源"。三者的共同点是什么呢？就是都先证明了局部最优选择不会影响全局最优性，然后用一次或两次线性扫描就完成了求解，避免了指数级的枚举开销。
