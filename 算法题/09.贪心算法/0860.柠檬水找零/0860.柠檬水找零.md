# 0860. 柠檬水找零

**题目描述**

在柠檬水摊上，每一杯柠檬水的售价为 5 美元。顾客排队购买你的产品，一次购买一杯。每位顾客只买一杯柠檬水，然后向你付 5 美元、10 美元或 20 美元。你必须给每位顾客正确找零，也就是说净交易是每位顾客向你支付 5 美元。

注意，一开始你手头没有任何零钱。给定一个数组 `bills`，代表顾客付款的面额顺序，如果你能给每位顾客正确找零，返回 `true`，否则返回 `false`。

```
示例 1：
输入: [5,5,5,10,20]
输出: true
解释：
前 3 位顾客那里，我们按顺序收取 3 张 5 美元的钞票。
第 4 位顾客，我们收取一张 10 美元的钞票，并返还 5 美元。
第 5 位顾客，我们找还一张 10 美元的钞票和一张 5 美元的钞票。
由于所有客户都得到了正确的找零，所以我们输出 true。

示例 2：
输入: [5,5,10,10,20]
输出: false
解释：
前 2 位顾客那里，我们按顺序收取 2 张 5 美元的钞票。
对于接下来的 2 位顾客，我们收取一张 10 美元的钞票，然后返还 5 美元。
对于最后一位顾客，我们无法退回 15 美元，因为我们现在只有两张 10 美元的钞票。
由于不是每位顾客都得到了正确的找零，所以答案是 false。
```

## 思路

这是一道贪心模拟题。核心思路是按顺序处理每一位顾客的付款，实时维护手头现有的钞票数量，每一步都做出当前看起来"最合理"的找零决策，判断能否顺利进行到最后。

**先确定需要维护哪些状态**

顾客的付款只有三种面额：5、10、20。我们只需要维护手头 5 美元和 10 美元钞票的数量，记作 `five` 和 `ten`。20 美元的钞票不需要维护数量，为什么呢？因为它面额最大，永远不会被用来给别人找零（找零只会找比顾客所付金额小的钞票）。

**分情况讨论找零逻辑**

- 顾客付 5 美元：不需要找零，直接收下即可，`five += 1`。
- 顾客付 10 美元：需要找 5 美元的零钱。如果 `five >= 1`，则 `five -= 1`，`ten += 1`；如果没有 5 美元可用，则找零失败，返回 `false`。
- 顾客付 20 美元：需要找 15 美元的零钱，这里有两种找零方式：
  - 方式一：用一张 10 美元 + 一张 5 美元（`ten -= 1, five -= 1`）
  - 方式二：用三张 5 美元（`five -= 3`）
  - 贪心策略是：优先尝试方式一（10+5），只有在没有 10 美元的情况下，才尝试方式二（三张5美元）；如果两种方式都无法满足，则找零失败，返回 `false`。

**为什么要优先用"10+5"而不是"三张5元"来给20元找零？**

这是本题贪心思想的核心所在，得重点分析一下。表面上看，无论选哪种找零方式，只要凑够 15 美元，效果好像是一样的——都是把顾客的 20 美元换成等值的找零。但你要是往后多想一步，就会发现这两种方案对**后续找零能力**的影响是完全不同的。

关键在于分析 5 美元和 10 美元这两种钞票各自的"用途范围"：

- **5 美元钞票**的用途很广：它既可以单独用来给付 10 美元的顾客找零（付10元的顾客只能用5元找零），也可以配合一张 10 美元用来给付 20 美元的顾客找零，甚至可以三张凑在一起单独给付 20 美元的顾客找零。也就是说，5 美元钞票几乎在所有找零场景中都能派上用场。
- **10 美元钞票**的用途则很窄：它唯一的用处就是配合一张 5 美元，用来给付 20 美元的顾客找零（因为没有比 10 大又比 20 小的中间钞票需要用到它，而且题目里没有找零给付5元顾客的需求）。除此之外，10 美元钞票在任何其他找零场景中都用不上。

既然 10 美元钞票的用途明显比 5 美元钞票窄——只能用在一种场景里，而 5 美元几乎可以用在所有场景里——那么当我们有选择的时候（也就是面对付 20 美元的顾客，同时手头 10 美元和 5 美元都够用的情况），应该优先消耗那个用途窄、不灵活的资源（10 美元），保留用途广、灵活的资源（5 美元），这样才能让后续遇到各种不同付款方式的顾客时，有更大概率能够正确找零。

反过来想，如果我们优先用三张 5 美元来找零（哪怕手头有 10 美元可用），那就是在提前消耗掉了那个"万金油"资源，而把用途受限的 10 美元留在手里。一旦后续来了很多付 10 美元的顾客（需要用 5 美元找零）或者又来付 20 美元的顾客（需要 5 美元配合），我们手头的 5 美元很快就会枯竭，而留着的 10 美元却帮不上任何忙，从而更容易导致找零失败。

可以用一个简单的例子直观感受一下这种差异：假设顾客序列是 `[5, 5, 10, 20, 10]`。

- 走到第4位顾客（付20美元）时，手头有：`five = 1`（两张5被第3位顾客的找零消耗了一张），`ten = 1`。
- 如果优先用"10+5"找零：`ten -= 1, five -= 1`，此时 `five = 0, ten = 0`。接下来第5位顾客付10美元，需要一张5美元找零，但此时 `five = 0`，找零失败。

再看看如果这个例子里手头5美元更充足一些（比如序列是 `[5,5,5,10,20,10]`），二者的差别会体现得更明显——用"10+5"消耗掉10美元、保留更多5美元，能应付后续更多付10美元的顾客；而用"三张5美元"则会让5美元很快耗尽，即使10美元还剩着也无法拿来给付10美元的顾客找零。

这种"优先消耗稀缺/不灵活的资源，保留灵活/通用的资源"正是贪心算法中一种常见且重要的思想：当多种资源可以互相替代地完成同一个任务，但资源本身的"可复用性"或者"适用场景广度"不同时，应该优先使用适用场景窄的资源，把适用场景广的资源留到后面，因为未来的不确定性越大，越需要保留灵活性来应对各种可能出现的情况。

**为什么这个贪心策略能保证正确性？**

可以这样理解：在任意时刻，如果存在一种可行的找零方案能让后续所有顾客都被正确找零，那么"优先用10+5"这个策略下产生的钞票组合，一定不会比其他找零方式更差（也就是持有的资源灵活性不会更低）。为什么呢？因为如果某一种方案在某个时刻选择了"三张5美元"而不是"10+5"，我们总可以构造出一种等价或更优的调整——把本可以用10美元解决的场景换成用10美元解决，省下的5美元只会让后续的选择更宽松，不会让后续更难找零。所以贪心选择不会导致本可行的问题变得不可行，这也是贪心算法能够求解本题的正确性基础。

时间复杂度是 O(n)，n 为顾客数量，只需要遍历一次数组；空间复杂度是 O(1)，只需要维护两个计数变量。

## 代码

### C++

```cpp
class Solution {
public:
    bool lemonadeChange(vector<int>& bills) {
        int five = 0, ten = 0; // 手头5美元和10美元的数量，20美元不需要统计
        for (int bill : bills) {
            if (bill == 5) {
                five++; // 付5美元，无需找零，直接收下
            } else if (bill == 10) {
                if (five == 0) return false; // 没有5美元可找零，失败
                five--;  // 找出一张5美元
                ten++;   // 收下这张10美元
            } else { // bill == 20，需要找15美元
                if (ten > 0 && five > 0) {
                    ten--;   // 优先消耗用途窄的10美元
                    five--;  // 配合一张5美元找零
                } else if (five >= 3) {
                    five -= 3; // 没有10美元时，用三张5美元找零
                } else {
                    return false; // 两种方式都不满足，找零失败
                }
            }
        }
        return true; // 所有顾客都成功找零
    }
};
```

## 总结

- 本题是贪心模拟类问题，核心是维护5美元和10美元钞票的数量（20美元用途单一，不用统计），按顾客付款顺序模拟找零过程。
- 给付20美元的顾客找零时，应该优先使用"一张10美元+一张5美元"而不是"三张5美元"，原因在于5美元的适用场景更广（可用于找给付10元和付20元的顾客），而10美元的适用场景很窄（只能配合找给付20元的顾客），应优先消耗用途窄、不灵活的资源，保留用途广、灵活的资源。
- 这体现了贪心算法中"资源可复用性差异越大，越应该优先消耗稀缺/不灵活的一方"的通用思想，在很多资源调度类问题中都能见到类似策略。
- 只要在每一步找零时都按照这个优先级模拟，一旦某一步无法找零就立即返回失败，否则遍历完成后返回成功即可，整体逻辑简单，但背后的贪心依据值得仔细推敲。
