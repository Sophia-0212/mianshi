# 0860. 柠檬水找零

**题目描述**

在柠檬水摊上，每一杯柠檬水的售价为 5 美元。顾客排队购买你的产品，一次购买一杯。每位顾客只买一杯柠檬水，然后向你付 5 美元、10 美元或 20 美元。你必须给每位顾客正确找零，也就是说净交易是每位顾客向你支付 5 美元。

注意，一开始你手头没有任何零钱。给定一个数组 `bills`，代表顾客付款的面额顺序，如果你能给每位顾客正确找零，返回 `true`，否则返回 `false`。

```
示例 1：
输入: [5,5,5,10,20]
输出: true
解释：
前 3 位顾客那里，我们按顺序收取 3 张 5 美元的钞票。
第 4 位顾客，我们收取一张 10 美元的钞票，并返还 5 美元。
第 5 位顾客，我们找还一张 10 美元的钞票和一张 5 美元的钞票。
由于所有客户都得到了正确的找零，所以我们输出 true。

示例 2：
输入: [5,5,10,10,20]
输出: false
解释：
前 2 位顾客那里，我们按顺序收取 2 张 5 美元的钞票。
对于接下来的 2 位顾客，我们收取一张 10 美元的钞票，然后返还 5 美元。
对于最后一位顾客，我们无法退回 15 美元，因为我们现在只有两张 10 美元的钞票。
由于不是每位顾客都得到了正确的找零，所以答案是 false。
```

## 思路

贪心维护 5 元、10 元张数：收 5 元直接增加；收 10 元找 5 元；收 20 元优先找 10+5，否则找三张 5。零钱不足则失败，优先保留用途更多的 5 元。

时间 O(n)，空间 O(1)。

### LeetCode 写法与原有示例

```python
class Solution:
    # 方法：lemonadeChange；按题目要求处理输入并返回结果，核心算法见方法体。
    def lemonadeChange(self, bills: list[int]) -> bool:
        five, ten = 0, 0  # 手头5美元和10美元的数量
        for bill in bills:
            if bill == 5:
                five += 1  # 付5美元，直接收下
            elif bill == 10:
                if five == 0:
                    return False  # 没有5美元可找零
                five -= 1
                ten += 1
            else:  # bill == 20，需要找15美元
                if ten > 0 and five > 0:
                    ten -= 1   # 优先消耗用途窄的10美元
                    five -= 1  # 配合一张5美元
                elif five >= 3:
                    five -= 3  # 没有10美元时用三张5美元
                else:
                    return False  # 两种方式都不满足
        return True
```

```go
    five, ten := 0, 0 // 手头5美元和10美元的数量
    for _, bill := range bills {
        switch bill {
        case 5:
            five++ // 付5美元，直接收下

            if five == 0 {
                return false // 没有5美元可找零
            }
            five--
            ten++
        case 20:
            if ten > 0 && five > 0 {
                ten--  // 优先用10美元+5美元找零
                five--
            } else if five >= 3 {
                five -= 3 // 没有10美元时用三张5美元
            } else {
                return false // 无法找零
            }
        }
    }
    return true
}
```

class Solution {
public:
    // 方法：lemonadeChange；按题目要求处理输入并返回结果，核心算法见方法体。
    bool lemonadeChange(vector<int>& bills) {
        int five = 0, ten = 0; // 手头5美元和10美元的数量，20美元不需要统计
        for (int bill : bills) {
            if (bill == 5) {
                five++; // 付5美元，无需找零，直接收下
            } else if (bill == 10) {
                if (five == 0) return false; // 没有5美元可找零，失败
                five--;  // 找出一张5美元
                ten++;   // 收下这张10美元
            } else { // bill == 20，需要找15美元
                if (ten > 0 && five > 0) {
                    ten--;   // 优先消耗用途窄的10美元
                    five--;  // 配合一张5美元找零
                } else if (five >= 3) {
                    five -= 3; // 没有10美元时，用三张5美元找零
                } else {
                    return false; // 两种方式都不满足，找零失败
                }
            }
        }
        return true; // 所有顾客都成功找零
    }
};```

## 总结

- 本题是贪心模拟类问题，核心是维护5美元和10美元钞票的数量（20美元用途单一，不用统计），按顾客付款顺序模拟找零过程。
- 给付20美元的顾客找零时，应该优先使用"一张10美元+一张5美元"而不是"三张5美元"，原因在于5美元的适用场景更广（可用于找给付10元和付20元的顾客），而10美元的适用场景很窄（只能配合找给付20元的顾客），应优先消耗用途窄、不灵活的资源，保留用途广、灵活的资源。
- 这体现了贪心算法中"资源可复用性差异越大，越应该优先消耗稀缺/不灵活的一方"的通用思想，在很多资源调度类问题中都能见到类似策略。
- 只要在每一步找零时都按照这个优先级模拟，一旦某一步无法找零就立即返回失败，否则遍历完成后返回成功即可，整体逻辑简单，但背后的贪心依据值得仔细推敲。
