# 0053. 最大子序和

**题目描述**

给定一个整数数组 `nums`，请找到一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。

```
示例：
输入: nums = [-2,1,-3,4,-1,2,1,-5,4]
输出: 6
解释: 连续子数组 [4,-1,2,1] 的和最大，为 6。
```

## 思路

**贪心策略是什么**

从左到右遍历数组，维护一个累加和 `count`。每遍历到一个元素就把它加进 `count`，同时用 `result` 记录遍历过程中出现过的 `count` 的最大值。这里最关键的一步是：一旦 `count` 变成负数，就立刻把它重置为 0，重新开始累加。

**为什么"一旦为负就重置"是对的**

你想啊，假设当前累加和 `count` 已经变成负数了，这说明什么？从某个起点一直加到当前位置，这一段区间的总和是负的。那现在想一想：不管后面接上任何一段子数组，如果继续把这个已经为负的 `count` 带下去，会是什么效果？说白了，把一个负数加到后面任意一段和上，结果只会比不加这个负数更小——或者顶多相等，就是后面这段刚好抵消它，但那也不会比直接从 0 开始更好。换句话说，带着这段负的前缀往后走，纯粹是在拖后腿，不会让后面的和变得更大。

反过来想：要是我们把这段负的前缀直接丢掉，从下一个位置重新开始计数，那么从新起点开始的这段子数组的和，一定不会比"硬撑着带前面负数一起算"更差——为什么呢？因为丢掉的那部分本来就是负贡献，去掉负贡献只会让剩下的和更大或者不变。所以，只要发现当前累加和变负了，就可以放心把它清零，从下一个位置重新开始找新的候选子数组，这个决策不会丢掉任何能得到更优解的机会。

再稍微严谨一点地看：设 `nums[i..j]` 是最优子数组（和最大）。如果我们贪心遍历到某个位置 `k`（`i <= k < j`）时 `count` 变成了负数，那 `nums[i..k]` 这段的和就是负的。可你想，如果 `i` 到 `k` 这段和是负的，那说明 `nums[k+1..j]` 这段的和其实比 `nums[i..j]` 整体的和还要大（因为去掉了一段负贡献），这不就跟"`nums[i..j]` 是全局最大"这个假设矛盾了吗——除非说，最优子数组的起点本来就不应该是 `i`，而应该重新从 `k+1` 开始算。这正好说明，真正的最优子数组永远不会以一段"累加和为负"的前缀开头，所以贪心在检测到前缀为负时清零重来，天然地就跳过了所有不可能成为最优解起点的情况，不会漏掉真正的最优子数组。

有一点得注意：`result` 要在每一步累加之后就立刻更新（取当前 `count` 和历史 `result` 的较大值），不能只在清零的时候才更新，因为最大和可能恰好就出现在还没触发清零的中间某一步。

**与动态规划解法的关系**

这道题用动态规划也能求解：定义 `dp[i]` 表示以下标 `i` 结尾的连续子数组的最大和，那状态转移方程就是：

```
dp[i] = max(dp[i-1] + nums[i], nums[i])
```

这个含义是什么呢？就是说，以 `i` 结尾的最大子序和，要么是"接着前一个位置的最大子序和继续往后延伸"，要么就是"放弃前面所有的和，单独以 `nums[i]` 自己重新开始"。最终答案就是 `dp` 数组里的最大值。

贪心解法其实正是这个 DP 解法的空间优化版本。你观察一下状态转移方程就能发现：`dp[i-1] + nums[i]` 和 `nums[i]` 相比，取较大值本质上等价于判断"如果 `dp[i-1]` 是负数，那还不如放弃它单独重新开始"，这正好对应贪心里"count 一旦为负就清零"的逻辑（`dp[i-1] < 0` 的时候，`dp[i-1] + nums[i] < nums[i]`，所以会选择重新开始）。而且这里的状态转移只依赖前一个状态 `dp[i-1]`，根本不需要保留完整的 `dp` 数组，只需要用一个变量（也就是 `count`）滚动记录当前的状态就够了——这就是为什么贪心解法比标准 DP 解法省空间，把 O(n) 的数组空间优化成了 O(1) 的单变量空间。

**复杂度分析**

只需要遍历数组一次，时间复杂度 O(n)。只需要常数个变量（`count` 和 `result`），空间复杂度 O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        int result = INT_MIN;  // 记录遍历过程中出现过的最大和
        int count = 0;         // 当前累加和
        for (int i = 0; i < nums.size(); i++) {
            count += nums[i];           // 把当前元素计入累加和
            if (count > result) {
                result = count;         // 更新历史最大值
            }
            if (count < 0) {
                count = 0;  // 累加和为负，说明这段前缀只会拖累后面，重置为0重新开始
            }
        }
        return result;
    }
};
```

## 总结

- 贪心策略的核心就是"累加和一旦为负就清零重新计数"，因为带着负的前缀往后走只会拖累后面的和，永远不会比丢弃它更好。
- 正确性可以用反证法来说明：如果最优子数组的某段前缀和为负，那去掉这段前缀后剩余部分的和会更大，这就跟"该子数组是全局最优"矛盾了，所以最优解永远不会以负的前缀开头。
- `result` 要在每一步累加后立即更新，不能只在清零时才更新，不然会漏掉最大值恰好出现在清零之前的情况。
- 贪心解法本质上是 DP 解法 `dp[i] = max(dp[i-1] + nums[i], nums[i])` 的空间优化版本，因为状态转移只依赖前一个状态，用一个滚动变量就能代替整个 dp 数组。
