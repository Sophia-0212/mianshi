# 贪心算法理论基础

**题目描述**

本篇不针对具体题目，而是梳理贪心算法这一大类问题的通用思考框架，为后续 24 篇具体题目打基础。

## 思路

**贪心算法的本质**

先说贪心算法到底是个什么思路。你想啊，我们面对一个很复杂的全局最优问题的时候，贪心的做法就是把它拆成一步一步的局部决策，每一步我都只看当前这一步，怎么选最好就怎么选，完全不去管这个选择会不会影响后面。走完所有步骤之后，把这些局部最优的选择拼在一起，就指望着这个拼出来的结果正好是全局最优解。

这里有两个词我要单独拎出来讲一讲。第一个是"局部最优"，说白了就是站在当前这一步、只凭手头已知的信息，能挑出的最好选项。第二个词更关键，就是"期望"——为什么我要用"期望"这个词，而不是说"贪心保证能达到全局最优"？因为贪心这套策略并不是对所有题目都成立的，这一点必须先说清楚。大多数情况下，我们得先证明——或者反过来说，很多时候是先凭直觉猜一个策略，再回头去验证——局部最优确实能一步步推出全局最优，验证通过了才能放心用贪心，不能想都不想就直接上。

**贪心与动态规划的核心区别**

贪心和动态规划这两个经常被拿来一起比，因为你会发现它们表面上都是"靠局部决策一步步搭出全局解"，但骨子里完全是两回事。这里的关键是什么呢？

动态规划考虑的是"状态转移"：dp[i] 这个值依赖于 dp[i-1]、dp[i-2] 这些之前的状态，你做当前这一步决策的时候，得把之前所有可能的状态都综合考虑一遍，从里面挑最优的（就是 `dp[i] = max(dp[i-1], dp[i-2] + nums[i])` 这种形式）。说白了，DP 本质上是在对所有可能的路径做一次穷举式的最优化，只不过用状态复用的方式，把重复计算给避免掉了。

贪心呢？它压根不考虑之前的状态，只根据当前这一个局部信息做一次性决策，做完就完了，不会回头再调整。你可以把贪心理解成"无后效性"决策的一个极端简化版本：它直接假设当前这个局部最优选择，不会因为后面又冒出什么新信息而变得不是最优了，所以根本不需要存那么多状态、也不用挨个比较，直接选一个就往前走。

举个例子你就明白了：还是那道求数组最大子序和的题，DP 的解法要维护一个 `dp[i]`，表示"以第 i 个位置结尾的最大子序和"，每一步都要在 `dp[i-1] + nums[i]` 和 `nums[i]` 之间比一下，取较大的——这其实就是在两个状态之间做选择。贪心解法呢，只维护一个累加变量，一旦这个累加值变成负数了，直接清零重来，这个决策只看"当前累加值是不是负的"这一个局部信号，根本不需要显式地去比较多个状态。所以你可以这么理解：贪心很多时候其实就是 DP 在某些特殊问题结构下的一个化简和特例——因为在这些问题里，局部最优天然就等价于全局最优里的一部分，不需要额外保留别的状态分支。

**贪心算法没有固定套路**

这一点是学贪心时最容易让人犯迷糊的地方。你想，动态规划有一套相对固定的五步分析法——确定状态、找递推公式、想初始化、定遍历顺序、打印验证，这一套流程基本能套到大部分 DP 题上。但贪心不一样，它没有这种通用模板可用。每道贪心题的"贪心点"往往得结合具体的题目场景单独去发现，很难靠一套流程直接套出来。

那既然没有套路，贪心题的方法论核心其实就落在两件事上。

第一件事，**举反例验证**。拿到一道题先别急着写代码，凭直觉先猜一个贪心策略——比如"排序后从大到小选"或者"每次选局部极值"这种，猜完之后，主动去构造几组边界数据或者特殊情况，代入自己猜的策略去推演一遍，看看会不会冒出反例。如果试了半天都找不到反例，那这个策略成立的可能性就大大提高了；要是真找到反例了，那就得调整策略，或者干脆换个贪心方向重新想。这其实是一种"证伪驱动"的验证方式，比你直接从头去证明要容易上手得多。

第二件事，**数学证明（严格证明）**。为什么呢？因为光靠举反例、找不到反例，其实并不能严格证明这个策略是对的——毕竟你没有遍历所有情况啊。所以到了面试场景，或者需要给出严谨解释的时候，最终还是要从数学角度去证明"局部最优选择不会导致后面没法达到全局最优"。常见的证明思路有这么几种：

   - **交换论证法**：这里的关键是假设最优解里某个局部决策不是按贪心选的，然后证明把它换成贪心选择之后，结果不会变差，甚至可能更好——这样就说明贪心选择至少不会比别的选择差。
   - **数学归纳法**：先证明"前 k 步用贪心策略得到的就是前 k 步问题的最优解"，然后归纳到第 k+1 步，贪心选择依然保持最优性，这样一步步归纳到整个问题规模。
   - **反证法**：假设贪心策略给出的不是最优解，那就必然存在一个更优解，它和贪心选择在某一步是不一样的，顺着这个假设往下推，推出矛盾。

**做贪心题的一般方法**

把上面这两件事结合起来，实践中做贪心题我推荐这么一个流程：

1. 读完题先想："如果我站在某一步，凭直觉应该怎么选才最合理？"先形成一个初步的贪心猜想。
2. 拿 2-3 组自己构造的边界数据——比如全是正数、全是负数、单调递增、单调递减、有重复值这些特殊情况——手动模拟一下贪心策略，看看有没有明显的反例。
3. 如果没找到反例，那就尝试用交换论证或者归纳法，给出一个简要的正确性说明，哪怕不是特别严格的数学证明，至少也要能说清楚"为什么局部最优不会让后面变差"。
4. 最后实现代码，再拿题目给的示例和边界用例——空数组、单元素、全部相同这些——验证一遍。

后面每一篇具体题目的"思路"部分，我都会按照"贪心策略是什么 → 为什么局部最优能推出全局最优 → 复杂度分析"这个顺序展开来讲，重点会放在第二步的正确性说明上——这也正是贪心题目跟别的算法类型比起来，最容易被面试官往深里追问的地方。

## 总结

- 贪心算法的本质说白了就是"每一步选局部最优，指望拼出全局最优"，用"期望"这个词就是想强调这事儿不是必然成立的，必须经过验证。
- 贪心跟 DP 的核心区别在于要不要考虑之前的状态：DP 得在多个历史状态里比较取优，贪心只靠当前这一个局部信息一次性拍板，不回头。
- 贪心没有固定的解题模板，核心方法论就是"猜策略 → 举反例验证 → 数学证明（交换论证/归纳法/反证法）"这三步走。
- 后面每道贪心题我都会重点讲清楚"为什么贪心成立"，这才是贪心题真正的难点，也是跟暴力枚举、DP 解法比起来最容易被面试官追问的部分。
