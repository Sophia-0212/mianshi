# 0055. 跳跃游戏

**题目描述**

给定一个非负整数数组 `nums`，你最初位于数组的第一个下标。数组中的每个元素代表你在该位置可以跳跃的最大长度。判断你是否能够到达最后一个下标。

```
示例：
输入: nums = [2,3,1,1,4]
输出: true
解释: 可以先跳1步，从下标0到达下标1，然后再从下标1跳3步到达最后一个下标。

输入: nums = [3,2,1,0,4]
输出: false
解释: 无论怎样，总会到达下标3。但该下标的最大跳跃长度是0，
      所以永远不可能到达最后一个下标。
```

## 思路

**贪心策略是什么**

这里我维护一个变量 `cover`，表示"当前从起点出发，通过若干次跳跃能够到达的最远下标"。遍历数组的时候，对每个可达的下标 `i`，都用 `i + nums[i]`（也就是从这个位置起跳能到达的最远位置）去更新 `cover`，也就是 `cover = max(cover, i + nums[i])`。你想啊，只要遍历过程中当前下标 `i` 一直没超过 `cover`（说明这个位置本身是可达的），而且最终 `cover` 能覆盖到数组的最后一个下标，那就说明能到达终点。反过来，如果遍历中发现某个下标 `i` 已经超过了当前的 `cover`，那说明这个位置根本到不了，可以直接判定失败。

**为什么不需要模拟具体跳几步、每步跳多远**

这道题其实只关心"能不能到达终点"这一个是非问题，不关心"最少跳几次才能到达"（那是45题要解决的事儿）。既然只关心能不能到，那就不需要去枚举"第一步跳到哪、第二步跳到哪"这种具体路径了——为什么呢？因为路径的选择方式有指数级那么多种，暴力枚举肯定会超时的。

贪心这里的关键洞察是什么呢？就是只要某个下标 `i` 是可达的，那它能提供的"跳跃覆盖范围"就是一个确定的值，也就是 `i + nums[i]`（因为 `nums[i]` 是数组里固定的数值，不会因为你走了不同路径就改变）。说白了，"这个位置能跳多远"是这个位置本身自带的属性，跟你是通过什么路径走到这个位置的完全没关系。

基于这一点，我们只需要在遍历的过程中，把所有已经确认可达的位置能提供的最大覆盖范围都合并起来（不断取最大值），这就等价于把所有从起点出发、经过任意路径组合能达到的覆盖能力上限都穷举了一遍。为什么呢？因为不管你选择先跳到哪个中间位置、再从那个位置往后跳，这个中间位置能提供的覆盖范围早就已经被算进去、合并进 `cover` 里了，所以不会漏掉任何一种可能的跳跃组合方式。

反过来看，如果遍历到某个下标 `i` 时，发现 `i` 已经超过了当前的 `cover`，这就意味着从起点出发，通过之前所有已知可达位置的跳跃组合，都到不了 `i` 这个位置。既然连"站上 `i` 这个起跳点"这件事本身都做不到，那 `nums[i]` 这个位置能跳多远也就没意义了——因为你压根没机会站在这个位置起跳。所以一旦出现这种情况，可以立刻判定到不了终点，不用再往后遍历了。

**复杂度分析**

只需要遍历一次数组，时间复杂度 O(n)。只需要一个变量记录当前的覆盖范围，空间复杂度 O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int cover = 0;  // 当前能到达的最远下标
        for (int i = 0; i < nums.size(); i++) {
            if (i > cover) {
                return false;  // 当前下标本身已不可达，后面再大的跳跃也没用
            }
            cover = max(cover, i + nums[i]);  // 用当前可达位置更新最远覆盖范围
        }
        return true;  // 遍历完仍未提前返回false，说明所有位置都可达
    }
};
```

### Python

```python
class Solution:
    def canJump(self, nums: list[int]) -> bool:
        cover = 0  # 当前能到达的最远下标
        for i in range(len(nums)):
            if i > cover:
                return False  # 当前下标不可达，起跳点本身够不到
            cover = max(cover, i + nums[i])  # 更新最远覆盖范围
        return True
```

### Go

```go
func canJump(nums []int) bool {
    cover := 0 // 当前能到达的最远下标
    for i := 0; i < len(nums); i++ {
        if i > cover {
            return false // 当前下标不可达，直接判定失败
        }
        if i+nums[i] > cover {
            cover = i + nums[i] // 用当前可达位置更新最远覆盖范围
        }
    }
    return true
}
```

## 总结

- 贪心策略就是维护一个"最远可达覆盖范围" `cover`，遍历过程中不断用每个可达位置能提供的跳跃范围去更新它，根本不需要模拟具体的跳跃路径。
- 正确性的关键在于：一个位置能跳多远，是它自带的属性（由 `nums[i]` 决定），跟到达它的路径没关系，所以把所有可达位置的覆盖范围合并起来，就等价于穷举了所有路径组合的能力上限。
- 一旦发现某个下标超过了当前覆盖范围，说明这个位置本身就到不了，可以直接判定失败并提前返回，不用继续遍历。
- 这道题只关心"能不能到达"，跟45题"最少跳跃次数"是相关但不同的问题，本题的 `cover` 只需要合并更新，不用额外统计跳跃次数。
