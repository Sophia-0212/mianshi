# 0452. 用最少数量的箭引爆气球

**题目描述**

给定一个二维数组 `points`，其中 `points[i] = [xstart, xend]` 表示第 i 个气球在 x 轴上的直径区间。气球被完全填充在 x 轴上方，一支箭可以从 x 轴上任意一点垂直射出，如果一支箭的射出点在气球的直径区间内（包括边界），那么该气球会被引爆。求引爆所有气球所需的最少弓箭数。

```
示例：
输入: points = [[10,16],[2,8],[1,6],[7,12]]
输出: 2
解释: 在 x=6 处射出一支箭，可以射爆气球 [2,8] 和 [1,6]；
在 x=11 处射出一支箭，射爆气球 [10,16] 和 [7,12]。
```

## 思路

**贪心策略是什么**

先把所有气球按左边界 `xstart` 从小到大排个序（按右边界排也行，这里就讲左边界排序的版本）。排完之后遍历这些区间，维护一个变量 `arrowPos`，表示"当前这一箭能覆盖的范围的右边界"，初始值就设成第一个区间的右边界。

遍历到下一个区间的时候，看它的左边界是不是小于等于 `arrowPos`：

- 如果是，说明这个气球和前面用同一支箭覆盖的气球有重叠，那就继续用这支箭引爆，同时把 `arrowPos` 更新成当前气球右边界和 `arrowPos` 中较小的那个。为什么取较小的呢？因为箭要同时命中两者，就必须落在两者的交集内。
- 如果左边界超出了 `arrowPos`，说明这个气球跟前面的气球没有重叠了，那就必须新增一支箭，箭数加一，同时把 `arrowPos` 更新成这个新气球的右边界。

**为什么这样贪心是最优的**

先说说为什么要按左边界排序：这一步是为了让遍历过程"有序可依赖"。排序之后，后面遍历到的区间左边界肯定不会比前面的更小，这样任意时刻，我们只需要维护"当前这支箭能命中的范围"这一个变量，就能正确判断新来的区间是否落在这个范围内，不用考虑区间乱序带来的复杂关系——如果不排序，一个区间可能在数值上"跳来跳去"，就没法用一个单调推进的指针或变量去描述覆盖范围了。

再说说"取两者右边界中较小值"这一步，这是保证正确性的关键。咱们用反证法说明一下为什么必须收缩到较小值：假设一支箭要同时命中两个有重叠的气球A和B，箭的射出点必须同时落在A的区间和B的区间之内，也就是必须落在A、B两个区间的交集内。这个交集的右边界，正好就是A和B右边界中较小的那一个——毕竟交集不可能超过任意一个区间自身的范围嘛。那如果我们错误地不收缩、或者取了较大值，会怎样呢？相当于错误地扩大了"当前箭覆盖范围"这个变量所代表的真实意义——它本应表示"所有已经被这支箭命中的气球的公共交集"，一旦被错误扩大，后续再来一个新气球时，即使它的左边界落在这个被错误扩大的范围内，实际上它和之前某个气球的真实交集已经不存在了，就会被误判成"可以被同一支箭覆盖"，导致算法漏算了应该新增的箭数，得到一个数值上更小但实际不成立的错误解。

所以你看，"取较小值收缩覆盖范围"这一步维持了一个很重要的不变量：`arrowPos` 始终等于当前这支箭已经合并的所有气球的真实交集右边界。只要这个不变量成立，后面每一次"左边界 <= arrowPos"的判断就都是可信的，贪心策略给出的箭数就是真正可行、而且数量最少的。

**复杂度分析**

排序这部分的时间复杂度是 O(n log n)，遍历一次数组是 O(n)，所以总时间复杂度是 O(n log n)；空间复杂度 O(1)，不考虑排序本身可能用到的辅助空间。

## 代码

### C++

```cpp
class Solution {
public:
    static bool cmp(const vector<int>& a, const vector<int>& b) {
        return a[0] < b[0];  // 按左边界从小到大排序
    }

    int findMinArrowShots(vector<vector<int>>& points) {
        if (points.empty()) return 0;
        sort(points.begin(), points.end(), cmp);  // 按左边界排序
        int count = 1;                             // 至少需要一支箭
        int arrowPos = points[0][1];                // 第一支箭初始覆盖到第一个气球的右边界
        for (int i = 1; i < points.size(); i++) {
            if (points[i][0] > arrowPos) {
                // 左边界超出当前箭覆盖范围，说明没有重叠，必须新增一支箭
                count++;
                arrowPos = points[i][1];  // 新箭的覆盖右边界初始化为当前气球右边界
            } else {
                // 左边界在覆盖范围内，可以用同一支箭，收缩覆盖范围为交集右边界（取较小值）
                arrowPos = min(arrowPos, points[i][1]);
            }
        }
        return count;
    }
};
```

```java
class Solution {
    public int findMinArrowShots(int[][] points) {
        if (points.length == 0) return 0;
        // 按左边界从小到大排序
        Arrays.sort(points, (a, b) -> Integer.compare(a[0], b[0]));
        int count = 1;                    // 至少需要一支箭
        int arrowPos = points[0][1];      // 第一支箭覆盖到第一个气球的右边界
        for (int i = 1; i < points.length; i++) {
            if (points[i][0] > arrowPos) {
                // 没有重叠，新增一支箭
                count++;
                arrowPos = points[i][1];
            } else {
                // 有重叠，收缩覆盖范围为交集右边界
                arrowPos = Math.min(arrowPos, points[i][1]);
            }
        }
        return count;
    }
}
```

```go
import "sort"

func findMinArrowShots(points [][]int) int {
    if len(points) == 0 {
        return 0
    }
    // 按左边界从小到大排序
    sort.Slice(points, func(i, j int) bool {
        return points[i][0] < points[j][0]
    })
    count := 1                   // 至少需要一支箭
    arrowPos := points[0][1]     // 第一支箭覆盖到第一个气球的右边界
    for i := 1; i < len(points); i++ {
        if points[i][0] > arrowPos {
            // 没有重叠，新增一支箭
            count++
            arrowPos = points[i][1]
        } else {
            // 有重叠，收缩覆盖范围为交集右边界
            if points[i][1] < arrowPos {
                arrowPos = points[i][1]
            }
        }
    }
    return count
}
```

## 总结

- 按左边界排序是为了让遍历过程单调有序，这样只需要维护一个"当前箭覆盖范围"变量就能正确判断重叠关系，不用去处理乱序区间的复杂关系。
- 重叠的时候更新覆盖范围为两者右边界的较小值，说白了本质上就是维护"覆盖范围=已合并气球的真实交集"这一不变量，取较大值或者不更新都会导致后面判断出现误判。
- 边界重合（左边界恰好等于arrowPos）算作可以引爆，因为箭可以射在边界点上，所以判断条件用的是"严格大于才新增箭"，等号情况归入可合并这一类。
- 这题跟435（无重叠区间）思路高度相似，都是"排序+维护右边界"的区间处理范式，区别就在于边界重合的语义和最终统计目标不一样。
