# 0376. 摆动序列

**题目描述**

如果一个序列中，相邻两个元素的差严格地在正负之间交替（即差值符号交替变化），那么这个序列被称为摆动序列。给定一个整数数组 `nums`，求其中最长摆动子序列的长度（子序列可以不连续，但要保持原数组中的相对顺序）。

```
示例：
输入: nums = [1,7,4,9,2,5]
输出: 6
解释: 整个数组就是一个摆动序列，差值为 (6,-3,5,-7,3)，符号严格交替。

输入: nums = [1,17,5,10,13,15,10,5,16,8]
输出: 7
解释: 存在多种最长摆动子序列，一个例子是 [1,17,10,13,10,16,8]，差值为 (16,-7,3,-3,6,-8)。
```

## 思路

**贪心策略是什么**

这题我只统计数组里的"局部峰值"个数（局部峰值包括局部最大值和局部最小值）。说白了就是，只有当前元素跟前一个元素的差值符号，和"上一次记录的差值符号"发生变化的时候，才把这个位置算进摆动序列的长度里。我用两个变量，一个记录"上升趋势的差值"（prediff），一个记录"当前正在比较的差值"（curdiff）。当 `prediff <= 0 && curdiff > 0`（这是谷底转峰顶）或者 `prediff >= 0 && curdiff < 0`（峰顶转谷底）的时候，说明出现了一次新的摆动，计数就加一，同时更新 prediff。

**为什么这个局部最优选择能推导出全局最优**

这题的贪心本质是什么呢？其实就是在一段单调递增或单调递减的区间里，只有区间的两个端点（起点和终点）对摆动序列有意义，中间的元素全都可以删掉，不会影响最终摆动序列的长度——甚至可以说，删掉中间元素是必须的最优选择。

先直观感受一下，为什么"中间元素没用"：你想啊，假设有一段单调递增的子序列 `a1 < a2 < a3`，如果把这三个数都留在摆动子序列里，那 `a1` 到 `a2` 的差值和 `a2` 到 `a3` 的差值符号是一样的（都是正），这就不满足摆动序列"符号严格交替"的要求了嘛，所以 `a2` 必须被舍弃，摆动子序列里只能保留 `a1` 和 `a3` 这两个端点里的一个去跟前后的元素比较。再往深里说，在一段连续单调的区间内，不管这段区间多长，最终能贡献给摆动子序列的"有效峰值"都只有这段区间的起点或终点，中间元素留多少个都不会增加摆动次数，反而会因为符号不交替而必须被删掉。

再从"保留局部峰值不会让结果变差"这个角度证明一下最优性：假设最优摆动子序列里某处没选局部峰值，而是选了峰值附近的一个非峰值点，那这个非峰值点两侧的差值符号肯定跟相邻方向一致——不然它自己就是峰值了。也就是说这个点所在的摆动"转折"其实根本没真正发生。用真正的峰值点去代替它，摆动子序列的长度不会减少，因为峰值点是这段单调区间里离前一个峰值最远、离下一个峰值也不受影响的点，替换之后依然能跟相邻的峰值构成正确的符号交替关系。所以，"只统计局部峰值"这个策略不会比任何其他选择方式差，可以放心贪心。

这里有个边界情况得特别留意：如果数组里存在连续相同的元素（差值为0），相当于处在"平坡"上，既不算上升也不算下降，这时候不应该更新 prediff——也就是差值为0时不触发峰值判断，peak 不增加。得等到出现真正的符号变化才计数，否则会重复计数或者错误地把平坡也当成一次摆动。

初始状态怎么处理呢？数组的第一个元素本身默认就算摆动子序列的一部分（长度至少为1），prediff 初始设成0，表示"还没发生过摆动"，这样遍历到第二个元素的时候，只要出现非零的差值，就能触发第一次计数。

**复杂度分析**

只需要遍历数组一次，比较相邻元素的差值符号，时间复杂度 O(n)。只用了常数个变量记录前后差值和计数，空间复杂度 O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int wiggleMaxLength(vector<int>& nums) {
        if (nums.size() <= 1) return nums.size();  // 长度 0 或 1 时本身就是摆动序列
        int result = 1;    // 默认第一个元素算作序列的起点，长度至少为1
        int prediff = 0;   // 记录上一次真正发生摆动的差值符号（初始为0表示尚未摆动）
        for (int i = 1; i < nums.size(); i++) {
            int curdiff = nums[i] - nums[i - 1];  // 当前相邻元素的差值
            // 谷底转峰顶（prediff<=0 说明之前是下降或平坡，curdiff>0 说明现在上升）
            // 或者峰顶转谷底（prediff>=0 说明之前是上升或平坡，curdiff<0 说明现在下降）
            if ((prediff <= 0 && curdiff > 0) || (prediff >= 0 && curdiff < 0)) {
                result++;        // 出现一次新的摆动，长度加一
                prediff = curdiff;  // 更新为最近一次真正的摆动方向，供下次比较
            }
            // curdiff == 0（平坡）或方向未变化时，不更新prediff，跳过不计数
        }
        return result;
    }
};
```

## 总结

- 贪心策略就是只统计"局部峰值"（相邻差值符号发生变化的位置），说白了本质上就是删掉单调区间内部的所有中间元素，只留区间端点。
- 正确性证明的关键在哪儿呢？就在于单调区间内的中间元素不管留多少个都没法增加摆动次数（因为符号不会交替），而用峰值点去代替任意一个非峰值点，不会让摆动长度变差，所以贪心选峰值不会比任何其他方案差。
- 差值为0（平坡）的情况不能更新 prediff，不然会导致漏判或者重复计数，这是这题最容易出错的边界，得留意。
- 这题跟"最大子序和"（0053）都体现了"用一个方向标志/累加变量做单次遍历决策"的贪心手法，但摆动序列关注的是符号变化次数，最大子序和关注的是累加值的正负，这一点要分清楚，别搞混了。
