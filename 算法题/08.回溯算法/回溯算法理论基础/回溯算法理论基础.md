# 回溯算法理论基础

**题目描述**

本篇不针对具体题目，讲回溯算法（Backtracking）的通用原理和代码框架，作为整个回溯专题的入门篇。

回溯法要解决的问题，本质上都可以抽象成：在一个多层嵌套的"选择空间"里，按某种规则逐层做选择，最终找出所有满足条件的选择序列。例如从 `[1,2,3,4]` 里选 2 个数的所有组合，就是"选择空间"为 4 层（每层从剩下的数里选一个），要找出所有长度为 2 的合法选择序列。

## 思路

**回溯法的本质：暴力穷举 + 剪枝优化**

你想啊，很多人一听"回溯"就觉得这是个多高级的算法，其实说白了，它的地位更接近"暴力法的规范化写法"。回溯枚举的就是所有可能的组合方式，效率一般不高，大多数情况下是指数级复杂度，但它是很多"求所有解"这类问题唯一的通用解法——你没有更好的办法，只能老老实实把可能性都试一遍。那回溯比纯暴力强在哪呢？关键就是它在枚举的过程中，一旦发现某个分支不可能产生合法解，就立刻放弃这个分支，这就是我们说的剪枝，这样就避免了在明显没希望的地方继续往下钻。

**回溯法能解决的问题类型**

那回溯法能用在哪些地方呢？其实范围很窄，几乎只用于一类问题：在一个集合里，按某种规则找出所有子集、排列或者组合。具体来说可以分成五类：

1. **组合问题**：从 n 个数里找 k 个数的组合，这里不强调顺序，比如从 `[1,2,3]` 选 2 个，`[1,2]` 和 `[2,1]` 我们认为是同一种。
2. **切割问题**：把一个字符串按某种规则切成若干段，求所有切法。这个你可以理解成组合问题的变种，切割点的选择本质上就等价于做组合。
3. **子集问题**：求一个集合的所有子集，包括空集和它自己。
4. **排列问题**：n 个数的全排列，这里就要强调顺序了，`[1,2]` 和 `[2,1]` 是两个不同的排列。
5. **棋盘问题**：像 N 皇后、数独这种，在二维棋盘上按规则摆元素。

这五类问题的核心逻辑框架其实是一样的，区别就在于"要不要用 `startIndex` 来避免重复枚举"，以及"什么时候去收集结果"。后面每道题我都会明确说清楚它属于哪一类，跟其他题的区别在哪儿。

**回溯法的通用模板**

回溯本质上就是在一棵递归树上做深度优先遍历，也就是 DFS。你可以在脑子里画一棵"递归树"来帮助理解：树的每一层代表"做第几次选择"，每一层横向展开的每个分支就代表"这一次选了哪个候选值"。用伪代码表示大概是这样：

```
result = []          // 收集所有满足条件的结果
path = []             // 记录当前递归路径（当前已经选择的元素）

function backtrack(参数):
    if (终止条件):        // 到达树的叶子节点，或满足某个提前返回的条件
        result.add(path 的拷贝)
        return

    for 选择 in 本层可选择的集合:
        path.add(选择)          // 【选择】做出选择，加入路径
        backtrack(更新后的参数)   // 【递归】进入下一层，处理下一个位置
        path.removeLast()       // 【撤销选择】回溯，撤销这次选择，尝试下一个候选
```

这段模板里最关键的就是三步，我一般说"选择 - 递归 - 撤销选择"：

- **选择**：把当前候选值加入路径 `path`，相当于树形结构里从当前节点走到了子节点。
- **递归**：调用 `backtrack` 进入下一层，这一步是"纵向"移动，深度优先地往下探索。
- **撤销选择**：递归调用返回之后，把刚才加进路径的值给移除掉，这一步其实就是回到当前节点，让 `path` 恢复到进入这次循环之前的状态——为什么要这么做呢？因为这样才能在 `for` 循环的下一次迭代里去尝试其他候选值。

**for 循环和递归是什么关系**：这里的关键是，for 循环负责的是"横向遍历"，就是在树的同一层里依次去试每一个候选值；而递归调用负责"纵向遍历"，也就是选定一个候选值之后，深入到下一层继续做选择。这两个配合起来，才能把整棵递归树的所有节点、所有叶子节点都访问一遍。这也是为什么回溯代码里总是"for 循环嵌套递归"这个结构——外层 for 保证同一层的每个分支都被试到，内层递归保证每个分支都能继续往下走。

**剪枝是怎么回事**：剪枝就是在 for 循环内部、递归调用之前加一个判断，如果发现当前这个选择不可能产生合法解了（比如剩余可选的元素已经不够凑够目标个数了，或者当前路径的和已经超过目标值了），那就直接跳过这次选择，不再对这个分支进行递归，这样就减少了很多无意义的搜索。这里要强调一点：剪枝不会改变算法最终能找到的结果集合，它只是提前把注定失败的分支排除掉，说白了就是对暴力穷举的优化，而不是换了一种算法。

**回溯和 DFS 是什么关系**

这里的关键是，回溯法可以看作是 DFS（深度优先搜索）的一种具体应用方式。你想啊，DFS 说白了就是"一条路走到底，走不通就退回上一个节点换一条路走"，回溯法用的正是这个策略，只是它额外强调了"撤销选择"这一步——为什么呢？因为回溯法通常要维护一个共享的路径变量 `path`（而不是给每个递归分支单独开一个新的路径变量），所以退回上一个节点的时候，必须显式地把 `path` 恢复到之前的状态，不然下一个分支就会继承上一个分支留下的错误状态。所以可以这么理解："DFS + 显式维护和还原路径状态"，这就是回溯法。

**复杂度分析**

回溯法的时间复杂度一般是指数级或者阶乘级的，具体看问题类型，因为它本质上要遍历解空间树的一部分甚至全部节点。空间复杂度主要看递归深度（也就是栈空间）和 `path`、`result` 占用的空间。后面每道题我都会结合具体的树形结构来分析复杂度。

## 总结

- 回溯法说白了就是暴力穷举的规范化写法，核心价值在于配合剪枝减少无效搜索，而不是把问题本身的复杂度量级降下来。
- 回溯法能解决的问题可以归为五类：组合、切割、子集、排列、棋盘，代码框架都是一样的，区别就在于要不要用 `startIndex`、要不要用 `used` 数组，以及什么时候收集结果。
- 通用模板的核心就是"选择 - 递归 - 撤销选择"这三步，for 循环负责横向遍历同层节点，递归负责纵向深入下一层。
- 回溯本质上就是 DFS，只是额外强调了要用 `path` 记录路径，并且在回退的时候显式撤销，理解了这一点，就能把回溯代码和平常写的 DFS 代码联系起来了。
