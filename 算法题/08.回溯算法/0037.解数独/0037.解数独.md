# 0037. 解数独

**题目描述**

编写一个程序，通过填充空格来解决数独问题。数独的解法需遵循如下规则：数字 1-9 在每一行只能出现一次；数字 1-9 在每一列只能出现一次；数字 1-9 在每一个以粗实线分隔的 3x3 宫内只能出现一次。数独部分空格内已填入了数字，空白格用 `'.'` 表示，需要填入合适的数字使整个数独有唯一解。

```
示例：
输入：一个 9x9 的二维字符数组 board，部分单元格是数字，其余是 '.'
输出：直接在 board 上完成填数（原地修改），使其成为一个解好的数独
```

## 思路

这是困难题，是棋盘类回溯问题中比 N 皇后更进一步的例子：**N 皇后是一维递归（按行递归，每行只需要决定放哪一列），数独是二维回溯（需要同时确定行和列两个维度的位置）**。

**为什么数独需要二维回溯而不能像 N 皇后一样按单一维度递归呢**：你想啊，N 皇后每一行必须且只能放一个皇后，所以"按行递归"天然对应"每行做一次决策"；但数独不一样，每一行、每一列都可能有多个空格需要填，不存在"每行只做一次决策"的天然结构，所以需要同时用两个维度（行 `row` 和列 `col`）来定位"当前正在处理棋盘上的哪一个格子"，处理完一个格子后，按照"先移动列，列到头了再换行"的顺序移动到下一个格子。

**递归的推进方式**：可以把整个 9x9 棋盘按"行优先"的顺序拉成一条长度为 81 的序列（第 `row` 行第 `col` 列对应序列中的第 `row*9+col` 个位置），递归时按这个顺序依次处理每个位置：如果当前位置已经有数字（不是 `.`），直接跳到下一个位置；如果是空格，就尝试填入 1-9 中满足约束的数字。

**需要同时检查三个约束**：跟 N 皇后不一样，数独在每个位置需要同时满足行、列、3x3 宫格三个方向都不重复，检查函数需要遍历这三个范围分别判断：

1. 同一行是否已经存在这个数字。
2. 同一列是否已经存在这个数字。
3. 同一个 3x3 宫格内是否已经存在这个数字（宫格的起始行是 `(row/3)*3`，起始列是 `(col/3)*3`）。

**终止条件的设计（这题最需要讲清楚的难点）**：数独只需要找到**一个**解（题目保证有唯一解），一旦找到就要终止整个递归过程，不能继续尝试其他填法——这一点跟 N 皇后不一样，N 皇后要收集所有解。

问题在哪呢：数独是二维递归，一个格子对应一次函数调用，如果只是简单地 `return`，只会终止"当前格子的 for 循环"，并不会终止整个递归过程——上一层的调用者会继续尝试下一个数字，导致程序继续在已经找到解之后做无意义的搜索，甚至可能覆盖掉已经填好的正确答案。

正确的做法是让 `backtrack` 函数**返回一个布尔值**，表示"从当前格子开始，是否已经成功填满了整个棋盘"：

- 当处理到最后一个格子之后（即所有格子都已经填完），返回 `true`。
- 在每个格子尝试填入某个数字后，递归调用下一个格子。如果递归调用返回 `true`，说明后续所有格子都已经成功填好了，当前这一层也应该立即返回 `true`，不需要再撤销这次填入，也不需要再尝试其他数字。
- 只有当递归调用返回 `false`（说明填入这个数字后，后面某个格子无法继续填）时，才撤销当前这次选择（恢复为 `.`），尝试下一个候选数字。
- 如果 1-9 都尝试过仍然不行，返回 `false`，告诉上一层"这个格子填的数字导致后面走不通，请上一层换个数字"。

这样一来，`true` 会像 0332 重新安排行程那样，从"真正填满棋盘"的那一层，沿着递归调用链一路返回到最外层，实现真正意义上"找到解就终止整个搜索"的效果——而不是只终止某一层的 for 循环。

**说说"选择 - 递归 - 撤销选择"这三步**：

1. 选择：把候选数字 `k` 填入 `board[row][col]`。
2. 递归：调用 `backtrack` 处理下一个格子。
3. 撤销选择：只有在递归返回 `false` 时才需要撤销（恢复为 `.`），如果递归返回 `true`，直接把 `true` 向上传递，保留这次填入的结果。

**复杂度分析**：最坏情况下时间复杂度接近 O(9^m)（m 为空格数量），但实际由于约束检查会剪掉大量不合法分支，运行效率通常远高于这个理论上界。空间复杂度是 O(1)（原地修改棋盘，递归栈深度最多 81）。

## 代码

### C++

```cpp
class Solution {
private:
    bool isValid(vector<vector<char>>& board, int row, int col, char val) {
        for (int i = 0; i < 9; i++) {
            if (board[row][i] == val) return false;       // 同行冲突
            if (board[i][col] == val) return false;       // 同列冲突
        }
        int boxRow = (row / 3) * 3, boxCol = (col / 3) * 3;  // 所在 3x3 宫格起始坐标
        for (int r = boxRow; r < boxRow + 3; r++) {
            for (int c = boxCol; c < boxCol + 3; c++) {
                if (board[r][c] == val) return false;      // 同宫格冲突
            }
        }
        return true;
    }

    bool backtrack(vector<vector<char>>& board) {
        for (int row = 0; row < 9; row++) {
            for (int col = 0; col < 9; col++) {
                if (board[row][col] != '.') continue;   // 已有数字，跳过，处理下一个格子
                for (char val = '1'; val <= '9'; val++) {  // 横向遍历：尝试填入 1-9
                    if (!isValid(board, row, col, val)) continue;  // 冲突则跳过
                    board[row][col] = val;              // 【选择】填入数字
                    if (backtrack(board)) {             // 【递归】处理后续格子
                        return true;                        // 已找到完整解，一路向上返回 true，不再撤销
                    }
                    board[row][col] = '.';                // 【撤销选择】此数字走不通，恢复空格
                }
                return false;   // 1-9 都试过仍不行，说明当前分支无解，返回 false 让上一层换数字
            }
        }
        return true;   // 遍历完所有格子都没有再遇到空格，说明整个棋盘已经填满，成功
    }

public:
    void solveSudoku(vector<vector<char>>& board) {
        backtrack(board);   // 原地修改 board，题目不要求返回值
    }
};
```

## 总结

- 数独是二维回溯（需要同时定位行 `row` 和列 `col` 两个维度），跟 N 皇后的一维行递归不一样，本质是因为每行可能有多个空格需要处理，不存在"每行只决策一次"的天然结构。
- 判断合法性需要同时检查行、列、3x3 宫格三个约束，宫格起始坐标用 `(row/3)*3` 和 `(col/3)*3` 计算，这是数独问题特有的第三重约束。
- 终止条件的设计是这题的核心难点：`backtrack` 函数必须返回布尔值表示"是否已经找到完整解"，找到解后要让 `true` 一路沿递归调用链向上传递直到最外层，中途不能撤销已经填好的数字，不然会破坏已经找到的正确解。
- 跟 0332 重新安排行程很相似，这题也是"只需要找到一个解就终止整个搜索"的回溯场景，这类题目的通用处理方式是让回溯函数带返回值，通过返回值的传递控制是否继续尝试其他分支。
