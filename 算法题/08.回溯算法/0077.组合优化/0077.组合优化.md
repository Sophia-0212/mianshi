# 0077. 组合（剪枝优化）

**题目描述**

在 0077 题"求 1 到 n 中 k 个数的组合"的基础上，本篇讨论如何对回溯过程做剪枝优化，减少不必要的递归调用，提升效率。题目本身不变：

```
示例：
输入：n = 4, k = 2
输出：[[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]
```

## 思路

**未剪枝版本有什么问题**：0077 题原始的解法里，for 循环的遍历范围是 `[startIndex, n]`，也就是说，即使剩余的数字已经不够凑够 `k` 个了，循环还是会继续往下遍历，进了递归之后才发现凑不够数，这就白白浪费了一次递归调用。举个例子你就明白了：`n=4, k=4`，当 `path` 已经选了 `[1]`，这时候 `startIndex=2`，还需要再选 3 个数，剩余可选的数字是 `2,3,4` 正好 3 个，不多不少，没问题；但如果 `path` 选的是 `[4]`，`startIndex=5`，这时候已经没数字可选了，可还是要走一遍 for 循环（发现 `5 > n` 才退出），这个例子里浪费不算大，但你想啊，当 `n` 很大、`k` 也比较大的时候，这种无效的遍历和递归调用会明显增多。

**剪枝条件怎么推导出来的**：设当前 `path` 已经选了 `path.size()` 个数，那还需要选 `k - path.size()` 个数才能凑够 `k` 个。假设本次 for 循环遍历到数字 `i`，那从 `i` 到 `n` 一共有 `n - i + 1` 个候选数字。这里的关键是什么呢？如果 `n - i + 1 < k - path.size()`，说明从 `i` 开始往后选，最多也凑不够剩下需要的数量，那这个分支和它后面的分支就可以直接剪掉，不用再遍历了。

把不等式 `n - i + 1 >= k - path.size()` 移一下项，就能解出 `i` 的上界：

```
i <= n - (k - path.size()) + 1
```

也就是说，for 循环的遍历上界不再是 `n` 了，而是 `n - (k - path.size()) + 1`。这样一来，一旦 `i` 超过这个上界，直接结束 for 循环就行（而不是继续遍历到 `n` 再让递归内部去判断），后面这些必然失败的分支就完全不会被访问到了。

**为什么这样剪枝是安全的呢**：因为这个上界推导的依据是"剩余候选数字个数 >= 剩余需要选的个数"，这是能凑够 `k` 个数的一个必要条件，一旦不满足，就说明从当前位置往后不可能有解，所以剪掉不会漏掉任何合法组合。

**复杂度分析**：剪枝并不会改变算法的渐进时间复杂度上界（最坏情况下仍然是指数级），但它能显著减少实际执行中访问的分支数量，尤其是当 `k` 接近 `n` 或者 `n` 很大的时候，剪枝效果会很明显。你可以这么理解：剪枝版本相比未剪枝版本，省掉的是那些"确定不可能产生解"的分支遍历，这部分在没有剪枝的时候也会被递归调用一次（进了递归后 for 循环范围为空直接返回），剪枝之后这些无效调用就被完全跳过了。

## 代码

### C++

```cpp
class Solution {
private:
    vector<vector<int>> result;
    vector<int> path;

    void backtrack(int n, int k, int startIndex) {
        if (path.size() == k) {              // 终止条件：已经选够 k 个数
            result.push_back(path);
            return;
        }
        // 剪枝：i 的上界是 n - (k - path.size()) + 1，超过这个值不可能凑够 k 个数
        for (int i = startIndex; i <= n - (k - path.size()) + 1; i++) {
            path.push_back(i);               // 【选择】把 i 加入路径
            backtrack(n, k, i + 1);          // 【递归】进入下一层
            path.pop_back();                 // 【撤销选择】回退
        }
    }

public:
    vector<vector<int>> combine(int n, int k) {
        backtrack(n, k, 1);
        return result;
    }
};
```

### Java

```java
class Solution {
    private List<List<Integer>> result = new ArrayList<>();
    private LinkedList<Integer> path = new LinkedList<>();

    public List<List<Integer>> combine(int n, int k) {
        backtrack(n, k, 1);
        return result;
    }

    private void backtrack(int n, int k, int startIndex) {
        if (path.size() == k) {                  // 终止条件：已经选够 k 个数
            result.add(new ArrayList<>(path));
            return;
        }
        // 剪枝：i 超过 n - (k - path.size()) + 1 时，剩余数字不够凑够 k 个，提前结束循环
        for (int i = startIndex; i <= n - (k - path.size()) + 1; i++) {
            path.addLast(i);                     // 【选择】
            backtrack(n, k, i + 1);              // 【递归】
            path.removeLast();                   // 【撤销选择】
        }
    }
}
```

### Python

```python
class Solution:
    def combine(self, n: int, k: int) -> list[list[int]]:
        result = []
        path = []

        def backtrack(start_index: int):
            if len(path) == k:                   # 终止条件：已经选够 k 个数
                result.append(path[:])
                return
            # 剪枝：上界为 n - (k - len(path)) + 1，超过则剩余数字不够凑够 k 个
            upper_bound = n - (k - len(path)) + 1
            for i in range(start_index, upper_bound + 1):
                path.append(i)                   # 【选择】
                backtrack(i + 1)                  # 【递归】
                path.pop()                        # 【撤销选择】

        backtrack(1)
        return result
```

### Go

```go
func combine(n int, k int) [][]int {
    var result [][]int
    var path []int

    var backtrack func(startIndex int)
    backtrack = func(startIndex int) {
        if len(path) == k {                       // 终止条件：已经选够 k 个数
            tmp := make([]int, len(path))
            copy(tmp, path)
            result = append(result, tmp)
            return
        }
        // 剪枝：上界为 n - (k - len(path)) + 1，超过这个值不可能凑够 k 个数
        upperBound := n - (k - len(path)) + 1
        for i := startIndex; i <= upperBound; i++ {
            path = append(path, i)                // 【选择】
            backtrack(i + 1)                       // 【递归】
            path = path[:len(path)-1]              // 【撤销选择】
        }
    }
    backtrack(1)
    return result
}
```

## 总结

- 剪枝条件的本质其实就是一种"必要条件检查"：拿候选区间剩余的数量和还需要选择的数量做个对比，一旦发现剩余数量不够了，就直接放弃这个分支以及它之后的所有分支。
- 剪枝上界 `n - (k - path.size()) + 1` 要结合具体的 `path` 长度动态算出来，每次进入 for 循环都要重新算一遍，不是一个固定的常量，这点要注意。
- 剪枝优化不会改变最终的结果集合，它只是提前排除了注定失败的搜索路径，是回溯法优化的常规手段，写完基础版本之后值得追加考虑一下。
- 剪枝的效果会随着 `n` 增大、`k` 接近 `n/2` 附近变得更明显，为什么呢？因为这时候"刚好选不够"的边界情况在未剪枝版本里会被频繁触发。
