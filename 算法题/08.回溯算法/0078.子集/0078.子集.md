# 0078. 子集

**题目描述**

给定一个不含重复元素的整数数组 `nums`，返回该数组所有可能的子集（幂集）。解集不能包含重复的子集，可以按任意顺序返回。

```
示例：
输入: nums = [1,2,3]
输出: [[],[1],[1,2],[1,2,3],[1,3],[2],[2,3],[3]]
```

## 思路

**子集问题和组合问题的区别**：这是理解这道题的核心，你得先搞清楚这一点。组合问题（比如 0077 题）要收集的是"选够 k 个数"的叶子节点，只有到达特定深度才收集结果；但子集问题不一样，它要收集的是**树上的所有节点**（包括根节点，也就是空集），为什么呢？因为对于子集问题来说，路径 `path` 走到树上任意一个节点的时候，`path` 当前的内容都已经是一个合法的子集了——不需要等到"选够某个数量"才算一个有效结果，每一步的中间状态本身就是答案的一部分。

**为什么每个节点都要收集呢**：拿 `[1,2,3]` 举个例子，递归树的根节点对应空集 `[]`，往下走一层选了 `1`，这时候 `path=[1]` 已经是一个合法子集了，要收集；接着往下走选了 `2`，`path=[1,2]` 也是合法子集，也要收集；以此类推一直到叶子节点 `path=[1,2,3]`。你可以这么理解：子集问题是"在遍历整棵树的过程中，每经过一个节点就收集一次"，而组合问题是"只有走到满足条件的叶子节点才收集一次"。

**代码上怎么体现呢**：其实改动很小，只需要把"收集结果"的逻辑从"终止条件里判断后收集"，改成"进入 `backtrack` 函数后立即收集（在任何 for 循环和终止判断之前）"。终止条件依然需要（`startIndex >= nums.length()` 的时候没有更多可选元素了，自然结束递归），但它的作用变了，只用来告诉程序"没有更多分支可以展开了"，不再承担"决定是否收集结果"的职责了——因为收集结果这件事已经在每次进入函数时都做过了。

**怎么避免重复子集呢**：仍然用 `startIndex` 保证每层只能选比上一层更靠后的元素，这样就不会出现 `[1,2]` 和 `[2,1]` 被当作两个子集的情况（这题元素不重复，暂时不涉及"树层去重"，这个问题会在 0090 子集 II 里处理）。

**递归树的结构**：树的深度最多是 `nums.length()`（选完所有元素），树的宽度是当前 `startIndex` 到数组末尾的元素个数。因为每个节点都要收集，所以最终收集到的子集总数就是 `2^n`（每个元素都有"选"或"不选"两种状态，对应树上"继续递归"和"不再选这个元素"这两条路径）。

**复杂度分析**：一共有 `2^n` 个子集，每个子集平均长度是 `n/2`，所以时间复杂度是 O(n × 2^n)，空间复杂度是 O(n)（递归深度）。

## 代码

### C++

```cpp
class Solution {
private:
    vector<vector<int>> result;
    vector<int> path;

    void backtrack(vector<int>& nums, int startIndex) {
        result.push_back(path);      // 关键区别：每进入一次函数就收集当前路径，而不是等到叶子节点
        if (startIndex >= nums.size()) {   // 终止条件：没有更多元素可选，自然结束
            return;
        }
        for (int i = startIndex; i < nums.size(); i++) {  // 横向遍历：本层可选的元素
            path.push_back(nums[i]);        // 【选择】
            backtrack(nums, i + 1);         // 【递归】纵向进入下一层
            path.pop_back();                  // 【撤销选择】
        }
    }

public:
    vector<vector<int>> subsets(vector<int>& nums) {
        backtrack(nums, 0);
        return result;
    }
};
```

### Java

```java
class Solution {
    private List<List<Integer>> result = new ArrayList<>();
    private LinkedList<Integer> path = new LinkedList<>();

    public List<List<Integer>> subsets(int[] nums) {
        backtrack(nums, 0);
        return result;
    }

    private void backtrack(int[] nums, int startIndex) {
        result.add(new ArrayList<>(path));  // 关键区别：每次进入函数都收集当前路径
        if (startIndex >= nums.length) {      // 终止条件：没有更多元素可选
            return;
        }
        for (int i = startIndex; i < nums.length; i++) {  // 横向遍历
            path.addLast(nums[i]);             // 【选择】
            backtrack(nums, i + 1);            // 【递归】
            path.removeLast();                   // 【撤销选择】
        }
    }
}
```

### Python

标准库对比（`itertools.combinations` 枚举各个长度的组合再拼起来可以得到所有子集，但需要循环长度 0 到 n，本质仍是绕不开手写逻辑的封装，这里仅作对比）：

```python
from itertools import combinations

class Solution:
    def subsets(self, nums: list[int]) -> list[list[int]]:
        result = []
        for size in range(len(nums) + 1):          # 依次枚举子集长度 0 到 n
            result.extend(list(c) for c in combinations(nums, size))
        return result
```

手写回溯实现（体现"每个节点都收集"的核心逻辑）：

```python
class Solution:
    def subsets(self, nums: list[int]) -> list[list[int]]:
        result = []
        path = []

        def backtrack(start_index: int):
            result.append(path[:])       # 关键区别：每次进入函数都收集当前路径（包括空集）
            if start_index >= len(nums):   # 终止条件：没有更多元素可选
                return
            for i in range(start_index, len(nums)):   # 横向遍历
                path.append(nums[i])        # 【选择】
                backtrack(i + 1)              # 【递归】
                path.pop()                     # 【撤销选择】

        backtrack(0)
        return result
```

### Go

```go
func subsets(nums []int) [][]int {
    var result [][]int
    var path []int

    var backtrack func(startIndex int)
    backtrack = func(startIndex int) {
        tmp := make([]int, len(path))
        copy(tmp, path)
        result = append(result, tmp)    // 关键区别：每次进入函数都收集当前路径
        if startIndex >= len(nums) {      // 终止条件：没有更多元素可选
            return
        }
        for i := startIndex; i < len(nums); i++ {  // 横向遍历
            path = append(path, nums[i])   // 【选择】
            backtrack(i + 1)                 // 【递归】
            path = path[:len(path)-1]         // 【撤销选择】
        }
    }
    backtrack(0)
    return result
}
```

## 总结

- 子集问题与组合、切割问题最本质的区别是：组合、切割问题收集的是树的叶子节点（满足特定条件才收集），子集问题收集的是树的**所有节点**（每次进入递归函数就收集，不需要额外的终止条件判断）。
- 代码上的调整其实很小——就是把收集结果的代码从"终止条件判断之后"移到"函数最开始"，但背后的思路转变（叶子节点 vs 所有节点）得理解清楚，不然遇到类似的变形题容易写错。
- 终止条件在子集问题里依然存在，但它的作用变成了"没有更多元素可选时停止递归"，不再承担"决定是否收集结果"的职责，这点要分清楚。
- `n` 个元素的子集总数是 `2^n`，这是判断子集类问题时间复杂度的常用基准，跟组合问题的 `C(n,k)` 形成对比，记住这个对比能帮你快速估算复杂度。
