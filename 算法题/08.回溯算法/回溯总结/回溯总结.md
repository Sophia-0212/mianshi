# 回溯总结

本篇是"回溯算法"专题的收官总结，我把整个大类 22 篇涉及的核心技巧都串一遍：通用模板、五大类问题模型的区别、两种去重方式怎么选，还有怎么画回溯树来辅助分析复杂度。

## 回溯法的通用模板

先回顾一下贯穿全篇的核心框架：

```
result = []
path = []

function backtrack(参数):
    if (终止条件):
        result.add(path 的拷贝)   // 或者：在函数入口处收集（子集类问题）
        return
    for 选择 in 本层可选择的集合:
        path.add(选择)          // 【选择】
        backtrack(更新后的参数)   // 【递归】
        path.removeLast()       // 【撤销选择】
```

"选择-递归-撤销选择"这三步是所有回溯代码不变的骨架，22 篇文章的差异说白了都体现在"本层可选择的集合是什么""什么时候算终止、收集结果""要不要去重、怎么去重"这几个可变的点上。

## 五大类问题的模型区别

| 问题类型 | 代表题目 | 是否需要 startIndex | 是否需要 used 数组 | 收集结果的时机 |
|---|---|---|---|---|
| 组合问题 | 77/216/39/40 | 需要 | 不需要（39靠传i不传i+1，40靠startIndex） | 满足特定条件的叶子节点 |
| 切割问题 | 131/93 | 需要（表示切割线位置） | 不需要 | 字符串耗尽（叶子节点） |
| 子集问题 | 78/90/491 | 需要 | 不需要（491用局部哈希set去重） | 每个节点（包括根节点） |
| 排列问题 | 46/47 | 不需要 | 需要 | 排列长度达到数组长度的叶子节点 |
| 棋盘问题 | 51/37 | 不适用（用行/行列定位） | 不适用（用棋盘本身状态判断冲突） | 棋盘填满/摆放完成 |

**判断一道新题属于哪一类，问自己这三个问题就行**：

1. 答案强调元素顺序吗？强调就是排列模型（不需要 startIndex，需要 used 数组）；不强调就是组合/切割/子集模型（需要 startIndex）。
2. "还没选够/还没切完"的中间状态本身算不算一个有效答案？算，就是子集类的收集方式（每个节点都收集）；不算，就是组合/切割类的收集方式（只收集满足条件的叶子节点）。
3. 候选集合是"从原始数据里选/切"，还是"在棋盘上按位置摆放并检查冲突"？前者是组合/切割/子集/排列，后者是棋盘问题，需要设计专门的冲突检查函数（如 N 皇后的三方向检查、数独的行列宫格检查）。

## 两种去重方式的选择

- **排序 + 相邻去重**（40/90/47）：适用于数组可以被排序的场景，判断条件是 `i > startIndex（或0） && nums[i]==nums[i-1]`，排列问题（47）还需额外加上 `!used[i-1]` 来区分树层重复和树枝合法重复。
- **哈希 set 去重**（491）：适用于不能排序的场景（如子序列问题要求保持原始顺序），在每层递归入口新建一个局部 `set`，记录本层已经处理过的数值。

两者解决的其实是同一个问题（避免同一层内重复选择相同数值），选哪种取决于题目是否允许打乱原始顺序。

## 如何画回溯树辅助分析复杂度

画图的时候建议明确三个要素：

1. **深度**：树有多深，通常对应"总共要做几次选择"（组合问题是 k，排列问题是 n，切割/子集问题是数组或字符串长度，棋盘问题是行数或格子总数）。
2. **宽度**：每一层有多少个分支，对应"这一层的候选集合大小"（组合问题的候选集合随 startIndex 收缩、排列问题固定为剩余未使用元素数、棋盘问题固定为该维度的取值范围如 n 列或 1-9 数字）。
3. **剪枝点**：在哪些地方可以提前判断"这个分支不可能产生解"从而不再展开子树（个数不够、和已超、不合法子串/IP段、行列宫格冲突等）。

复杂度的上界说白了就是"深度 × 宽度"的某种组合（组合数 C(n,k)、排列数 n!、子集数 2^n、棋盘问题的 n! 或 9^m），剪枝不会改变这个理论上界，但能显著减少实际访问的节点数。

## 总结

- 回溯法的本质就是"暴力穷举 + 剪枝优化"，通用模板"选择-递归-撤销选择"贯穿所有变体，差异体现在候选集合定义、终止/收集时机、去重方式这三个维度上。
- 五大类问题（组合、切割、子集、排列、棋盘）可以通过"是否强调顺序""中间状态是否算答案""是否在棋盘上按位置摆放"这三个问题快速定位模型，进而套用对应的代码框架（是否需要 startIndex、是否需要 used 数组）。
- 去重技巧分两种：排序后相邻去重（更常用，常数开销小）和哈希 set 去重（不依赖排序，适用于要求保持原始顺序的场景），本质都是判断"本层是否已经处理过这个值"。
- 画回溯树时明确深度、宽度、剪枝点这三要素，就能快速判断一道新题的复杂度量级，也能帮助设计合适的剪枝策略，这是分析和设计回溯算法的通用方法论。
