# 0047. 全排列 II

**题目描述**

给定一个可能包含重复数字的数组 `nums`，按任意顺序返回所有不重复的全排列。

```
示例：
输入: nums = [1,1,2]
输出: [[1,1,2],[1,2,1],[2,1,1]]
```

## 思路

这题是在 0046 全排列的基础上加入去重要求，是排列问题里最容易搞混判断条件的一道题，我这里仔细讲一讲。

**排序是前提**：跟之前所有去重题一样，先对 `nums` 排序，让相同的数值相邻，这样才能给"树层去重"提供可比较的相邻关系。

**去重的判断条件（比组合去重要复杂一点）**：在 for 循环里，如果想跳过"本层重复选择相同值"的分支，你可能会直觉地写成和 0040/0090 一样的 `i > 0 && nums[i] == nums[i-1]`（排列问题没有 `startIndex`，所以判断条件里的下界是 0 而不是 `startIndex`），但这里还需要**额外加上一个条件**：`!used[i-1]`，也就是"前一个相同的值当前没有被使用（在当前路径中处于空闲状态）"。完整条件是：

```
i > 0 && nums[i] == nums[i-1] && !used[i-1]
```

**为什么需要 `!used[i-1]` 这个额外条件呢，这里得仔细琢磨**：

回顾一下组合问题的树层去重，判断的是"本层 for 循环内，前一个位置是否已经被处理过"——因为组合问题用 `startIndex` 保证只在"本层"内横向比较。但排列问题**没有 `startIndex`**，每一层都是从 0 开始遍历整个数组，所以不能简单用"下标顺序"来判断是否属于同一层了。这里得换一个角度想：

- 当 `used[i-1] == false` 时，说明 `nums[i-1]` 这个值**当前不在路径中**（可能它还没被选过，也可能它刚刚被撤销选择弹出了）。这意味着什么呢？当前的 for 循环遍历到 `i-1` 和 `i` 这两个下标，是在**同一层**尝试的两个分支——先尝试了 `nums[i-1]`，撤销后又要尝试 `nums[i]`，而两者数值相同，属于典型的"树层重复"，要跳过。
- 当 `used[i-1] == true` 时，说明 `nums[i-1]` 这个值**正在被使用**，也就是它是当前路径（树枝）上更靠前一层选中的元素。这时候 `nums[i]` 和它数值相同，但属于"树枝"关系（一个在祖先层，一个在当前层），这是允许同时出现的合法情况（比如结果 `[1,1,2]` 里两个 `1` 就是分别在不同层被选中的）。

一句话概括：`used[i-1]` 的状态帮我们区分了"前一个相同的值是刚被撤销（同层重复，要去重）"还是"前一个相同的值正挂在路径上（跨层，不去重）"，这正是排列问题去重要比组合问题去重多一步判断的原因——因为排列问题没有 `startIndex` 天然区分层次，只能靠 `used` 状态间接判断。

**`used` 数组的双重职责**：这题的 `used` 数组既要承担 0046 题"避免同一元素在同一路径中重复使用"的职责，又要在去重判断中承担"辅助判断树层/树枝关系"的职责，这是这题比 0046 复杂的根本原因。

**复杂度分析**：跟 0046 相同量级（最坏 O(n × n!)），去重能减少实际生成的重复分支，但不改变最坏情况的渐进复杂度。

## 代码

### C++

```cpp
class Solution {
private:
    vector<vector<int>> result;
    vector<int> path;
    vector<bool> used;

    void backtrack(vector<int>& nums) {
        if (path.size() == nums.size()) {     // 终止条件：排列长度达到数组长度
            result.push_back(path);
            return;
        }
        for (int i = 0; i < nums.size(); i++) {
            // 树层去重：nums[i] 与前一个值相同，且前一个值当前未被使用（说明前一个刚被撤销，
            // 属于同层重复尝试），跳过；如果 used[i-1]==true 说明前一个值在树枝上，不跳过
            if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) {
                continue;
            }
            if (used[i]) {                       // 该元素已在当前路径中使用，跳过
                continue;
            }
            used[i] = true;                // 【选择】标记已使用
            path.push_back(nums[i]);       // 【选择】加入路径
            backtrack(nums);               // 【递归】
            path.pop_back();                 // 【撤销选择】
            used[i] = false;                 // 【撤销选择】恢复未使用状态
        }
    }

public:
    vector<vector<int>> permuteUnique(vector<int>& nums) {
        sort(nums.begin(), nums.end());   // 排序，为树层去重提供相邻关系
        used.assign(nums.size(), false);
        backtrack(nums);
        return result;
    }
};
```

### Java

```java
class Solution {
    private List<List<Integer>> result = new ArrayList<>();
    private LinkedList<Integer> path = new LinkedList<>();
    private boolean[] used;

    public List<List<Integer>> permuteUnique(int[] nums) {
        Arrays.sort(nums);          // 排序，为树层去重提供相邻关系
        used = new boolean[nums.length];
        backtrack(nums);
        return result;
    }

    private void backtrack(int[] nums) {
        if (path.size() == nums.length) {      // 终止条件
            result.add(new ArrayList<>(path));
            return;
        }
        for (int i = 0; i < nums.length; i++) {
            // 树层去重：前一个相同值当前未被使用，说明是同层重复尝试，跳过
            if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) {
                continue;
            }
            if (used[i]) {                        // 该元素已在当前路径使用，跳过
                continue;
            }
            used[i] = true;                 // 【选择】
            path.addLast(nums[i]);          // 【选择】
            backtrack(nums);                // 【递归】
            path.removeLast();                // 【撤销选择】
            used[i] = false;                  // 【撤销选择】
        }
    }
}
```

### Python

```python
class Solution:
    def permuteUnique(self, nums: list[int]) -> list[list[int]]:
        nums.sort()   # 排序，为树层去重提供相邻关系
        result = []
        path = []
        used = [False] * len(nums)

        def backtrack():
            if len(path) == len(nums):        # 终止条件
                result.append(path[:])
                return
            for i in range(len(nums)):
                # 树层去重：前一个相同值当前未被使用（used[i-1] is False），
                # 说明前一个刚被撤销，属于同层重复尝试，跳过；
                # 若前一个正被使用（在树枝上），则不跳过，允许出现如 [1,1,2] 这样的合法结果
                if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
                    continue
                if used[i]:                       # 该元素已在当前路径使用，跳过
                    continue
                used[i] = True             # 【选择】
                path.append(nums[i])        # 【选择】
                backtrack()                   # 【递归】
                path.pop()                     # 【撤销选择】
                used[i] = False               # 【撤销选择】

        backtrack()
        return result
```

            copy(tmp, path)

            if i > 0 && nums[i] == nums[i-1] && !used[i-1] {
                continue
            }

                continue

            used[i] = true                 // 【选择】
            path = append(path, nums[i])   // 【选择】
            backtrack()                      // 【递归】
            path = path[:len(path)-1]         // 【撤销选择】
            used[i] = false                    // 【撤销选择】
        }
    }
    backtrack()
    return result
}

## 总结

- 排列去重的判断条件比组合去重多了 `!used[i-1]` 这一项，原因是排列问题没有 `startIndex` 区分层次，只能借助 `used` 的状态间接判断"前一个相同值是同层刚撤销的（要去重）"还是"跨层挂在路径上的（不去重）"。
- 理解 `used[i-1]` 的两种状态是这题的关键：`false` 代表同层重复尝试（去重），`true` 代表树枝上的合法重复（不去重），这跟组合问题里单纯依靠下标位置判断层次的方式完全不一样。
- `used` 数组在这题承担两个职责——防止同一元素重复使用（0046 已有的职责）和辅助去重判断（这题新增的职责），两者的判断逻辑要分开写清楚，不要混在一个条件里。
- 也可以把 `i > 0 && nums[i] == nums[i-1] && !used[i-1]` 改成 `&& used[i-1]`（跳过条件反过来），同样能正确去重，但效率上前者（跳过 `used[i-1]==false` 的情况）通常被认为剪枝更彻底，建议按本文的写法记忆，遇到变体时理解本质而不是死记条件式。
