# 回溯算法去重问题的另一种写法

**题目描述**

本篇不针对具体题目，是一篇方法论文档，介绍回溯去重的另一种实现方式——不排序，直接用哈希 set 记录本层已经使用过的值，并对比这种写法和"排序 + 相邻去重"两种方式的适用场景与效率差异。

## 思路

**先回顾一下已经学过的两种去重场景**：

1. **组合/子集/排列问题中的"排序 + 相邻去重"**（0040/0090/0047）：先对数组排序，让相同的数值相邻，然后在 for 循环中判断"当前值是否和前一个位置的值相同"来决定要不要跳过，本质上是利用排序后数值的物理相邻性来判断是否属于同一层的重复选择。

2. **0491 递增子序列中的"哈希 set 去重"**：因为不能排序（要保持子序列的原始相对顺序），改用一个局部的哈希 `set`，在进入某一层 for 循环之前新建一个空 `set`，遍历候选值的时候先查 `set` 里是否已经出现过这个数值，出现过就跳过，没出现过就记录下来继续处理。

**两种方式的通用性对比一下**：

"排序 + 相邻去重"依赖数组可以被排序这个前提，一旦题目要求保持原始顺序（比如子序列问题），这种方式就失效了。而"哈希 set 去重"不依赖排序，只要能在每一层递归开始时创建一个新的 `set` 来记录"本层已经处理过的数值"，就可以在任意场景下正确去重——即使不排序，只要 `set` 是每层独立的局部变量，判断的就是"同一层内是否已经选过这个数值"，这个逻辑跟是否排序完全无关。

也就是说，**"排序 + 相邻去重"其实是"哈希 set 去重"在数组已排序场景下的一种特殊优化写法**：排序之后，"相同的值"在物理位置上必然相邻，所以可以只比较 `nums[i]` 和 `nums[i-1]` 这一个相邻位置，不需要维护一个额外的数据结构去记录"本层出现过的所有值"。而哈希 set 的方式更通用，不管数组是否有序，都能正确地判断"这个值在本层是否已经出现过"。

**换成哈希 set 写法后，0040/0090 这类题目会怎么变呢**：以 0090 子集 II 为例，可以把去重逻辑从

```
if (i > startIndex && nums[i] == nums[i-1]) continue;
```

改写成：

```
unordered_set<int> used;  // 本层去重，进入函数时新建
for (...) {
    if (used.count(nums[i])) continue;
    used.insert(nums[i]);
    ...
}
```

这两种写法在排序后的数组上产生的结果是完全一致的，只是哈希 set 版本不再依赖 `i > startIndex` 这种基于位置的判断，而是直接查值是否出现过。

**两种方式的效率差异在哪呢**：

- **排序 + 相邻去重**：需要先排序（O(n log n)），之后的去重判断是 O(1) 的下标比较，不需要额外的空间开销，也不用创建额外的数据结构。
- **哈希 set 去重**：不需要排序，但每一层递归都要创建一个新的 `set`（有一定的常数开销），而且每次插入、查找操作虽然是均摊 O(1)，但相比直接比较数组下标，哈希计算本身还有额外的常数开销。当数值范围很大、分布稀疏的时候，用哈希 set 记录"本层出现过的值"依然方便（不需要排序整个数组），但如果数据量很大、每层的候选元素很多，频繁创建和销毁 `set` 的常数开销会比排序方式更明显。

**那到底该怎么选呢**：如果题目允许排序（不要求保持原始顺序），优先用"排序 + 相邻去重"，因为它更简单、常数开销更小；如果题目明确要求保持原始相对顺序（比如子序列问题），排序不可用，那就必须用哈希 set 的方式；如果不确定，也可以直接用哈希 set 的写法，因为它在两种场景下都能正确工作，只是在可以排序的场景下效率会略低于排序方案。

## 代码

由于本篇是方法论对比，以下用 0090 子集 II 的双写法对照，展示两种去重方式在同一问题上的实现差异。

### C++

```cpp
// 写法一：排序 + 相邻去重（要求数组可排序）
void backtrackSorted(vector<int>& nums, int startIndex, vector<int>& path, vector<vector<int>>& result) {
    result.push_back(path);
    for (int i = startIndex; i < nums.size(); i++) {
        if (i > startIndex && nums[i] == nums[i - 1]) continue;  // 相邻位置比较去重
        path.push_back(nums[i]);
        backtrackSorted(nums, i + 1, path, result);
        path.pop_back();
    }
}

// 写法二：哈希 set 去重（不要求排序，通用写法）
void backtrackHashSet(vector<int>& nums, int startIndex, vector<int>& path, vector<vector<int>>& result) {
    result.push_back(path);
    unordered_set<int> used;   // 每层新建，记录本层已处理过的数值
    for (int i = startIndex; i < nums.size(); i++) {
        if (used.count(nums[i])) continue;  // 值已出现过，跳过
        used.insert(nums[i]);
        path.push_back(nums[i]);
        backtrackHashSet(nums, i + 1, path, result);
        path.pop_back();
    }
}
```

### Java

```java
// 写法一：排序 + 相邻去重
void backtrackSorted(int[] nums, int startIndex, LinkedList<Integer> path, List<List<Integer>> result) {
    result.add(new ArrayList<>(path));
    for (int i = startIndex; i < nums.length; i++) {
        if (i > startIndex && nums[i] == nums[i - 1]) continue;  // 相邻位置比较去重
        path.addLast(nums[i]);
        backtrackSorted(nums, i + 1, path, result);
        path.removeLast();
    }
}

// 写法二：哈希 set 去重
void backtrackHashSet(int[] nums, int startIndex, LinkedList<Integer> path, List<List<Integer>> result) {
    result.add(new ArrayList<>(path));
    Set<Integer> used = new HashSet<>();   // 每层新建
    for (int i = startIndex; i < nums.length; i++) {
        if (used.contains(nums[i])) continue;   // 值已出现过，跳过
        used.add(nums[i]);
        path.addLast(nums[i]);
        backtrackHashSet(nums, i + 1, path, result);
        path.removeLast();
    }
}
```

### Python

```python
# 写法一：排序 + 相邻去重
def backtrack_sorted(nums, start_index, path, result):
    result.append(path[:])
    for i in range(start_index, len(nums)):
        if i > start_index and nums[i] == nums[i - 1]:   # 相邻位置比较去重
            continue
        path.append(nums[i])
        backtrack_sorted(nums, i + 1, path, result)
        path.pop()

# 写法二：哈希 set 去重
def backtrack_hashset(nums, start_index, path, result):
    result.append(path[:])
    used = set()          # 每层新建，记录本层已处理过的数值
    for i in range(start_index, len(nums)):
        if nums[i] in used:    # 值已出现过，跳过
            continue
        used.add(nums[i])
        path.append(nums[i])
        backtrack_hashset(nums, i + 1, path, result)
        path.pop()
```

### Go

```go
// 写法一：排序 + 相邻去重
func backtrackSorted(nums []int, startIndex int, path *[]int, result *[][]int) {
    tmp := make([]int, len(*path))
    copy(tmp, *path)
    *result = append(*result, tmp)
    for i := startIndex; i < len(nums); i++ {
        if i > startIndex && nums[i] == nums[i-1] { // 相邻位置比较去重
            continue
        }
        *path = append(*path, nums[i])
        backtrackSorted(nums, i+1, path, result)
        *path = (*path)[:len(*path)-1]
    }
}

// 写法二：哈希 set 去重（Go 用 map[int]bool 模拟 set）
func backtrackHashSet(nums []int, startIndex int, path *[]int, result *[][]int) {
    tmp := make([]int, len(*path))
    copy(tmp, *path)
    *result = append(*result, tmp)
    used := make(map[int]bool)   // 每层新建
    for i := startIndex; i < len(nums); i++ {
        if used[nums[i]] {         // 值已出现过，跳过
            continue
        }
        used[nums[i]] = true
        *path = append(*path, nums[i])
        backtrackHashSet(nums, i+1, path, result)
        *path = (*path)[:len(*path)-1]
    }
}
```

## 总结

- "排序 + 相邻去重"和"哈希 set 去重"解决的其实是同一个问题（同一层内避免重复选择相同数值），前者依赖排序带来的物理相邻性，后者用额外的数据结构直接记录"本层出现过的值"，不依赖数组的顺序。
- 当题目要求保持原始相对顺序（不能排序）的时候，只能用哈希 set 去重，这就是 0491 题必须采用这种写法的根本原因。
- 当题目允许排序的时候，两种写法都能得到正确结果，"排序 + 相邻去重"通常常数开销更小，是更常见的首选写法；哈希 set 写法更通用，但每层新建 `set` 有额外的空间和时间开销。
- 理解这两种去重方式本质上相通的地方（都是判断"本层是否已经处理过这个数值"），有助于在面对新的去重变形题时灵活选择合适的实现方式，而不是死记某一种固定写法。
