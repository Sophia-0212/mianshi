# 0042. 接雨水

**题目描述**

给定 `n` 个非负整数表示每个宽度为 1 的柱子的高度图，计算按此排列的柱子，下雨之后能接多少雨水。

```
示例：
输入: height = [0,1,0,2,1,0,1,3,2,1,2,1]
输出: 6
解释：上面是由数组 [0,1,0,2,1,0,1,3,2,1,2,1] 表示的高度图，
在这种情况下，可以接 6 个单位的雨水。
```

## 思路

这道题其实是单调栈和双指针/动态规划两种思路的一个经典交汇点，也是"接雨水"这一类问题的标准形态。我这里会详细讲两种方法，最后还会跟 84 题做个对比。

### 方法一：按列计算 —— 双指针 / 动态规划

**核心思路是这样的**：你不要去想"一个凹槽能接多少水"，咱们换个角度——**一列一列地算**。你想啊，对于下标 `i` 处的这根柱子，它头顶上能接多少雨水，其实只取决于两个东西：它左边所有柱子里的最大高度 `leftMax[i]`，还有它右边所有柱子里的最大高度 `rightMax[i]`。这一列最终能积多少水，就是 `min(leftMax[i], rightMax[i]) - height[i]`（如果算出来是负数，说明这根柱子本身比两边的屏障都高，根本积不住水，那就取 0）。

那为什么要取"两边最大值里较小的那个"呢？你可以想象水是从两边往中间灌的：水面的高度不可能超过左边最高的柱子，也不可能超过右边最高的柱子，因为只要超过了其中较矮的那道屏障，水就会从那个方向溢出去、流走。所以说，水面的高度是被"较矮的那道屏障"卡住的，也就是 `min(leftMax[i], rightMax[i])`。再减去当前柱子自己的高度，就是这一列实际能蓄住的水量。

**先说动态规划的做法**：如果直接暴力地对每个 `i` 都往左、往右扫一遍求最大值，那是 O(n²)，效率不行。优化的思路是预处理两个数组：
- `leftMax[i]`：表示 `height[0..i]` 里的最大值，可以从左往右递推着算：`leftMax[i] = max(leftMax[i-1], height[i])`。
- `rightMax[i]`：表示 `height[i..n-1]` 里的最大值，从右往左递推：`rightMax[i] = max(rightMax[i+1], height[i])`。

这两个数组各预处理一遍是 O(n)，之后对每个位置 O(1) 就能算出积水量，累加起来就是总答案，整体下来是 O(n) 时间、O(n) 额外空间。

**那双指针怎么进一步优化空间呢**？能不能不预处理整个数组，把空间压到 O(1)？这里的关键点是：对于位置 `i`，只要我们已经知道 `leftMax[i] <= rightMax[i]`，那这一列的积水量就完全由 `leftMax[i]` 决定了——根本不需要精确知道 `rightMax[i]` 具体是多少，只要知道它不小于 `leftMax[i]` 就够了。所以我们可以用左右两个指针 `left`、`right` 从两端往中间靠，同时维护 `leftMax`、`rightMax` 这两个变量（表示指针已经扫过的部分里的最大值）：

- 如果 `leftMax < rightMax`：说明当前 `left` 指针这一列的水位肯定是被 `leftMax` 卡住的（因为右边至少存在一个比 `leftMax` 更高的屏障，就算右指针还没扫到那个具体位置，也已经能确定右侧最大值不会小于 `leftMax`），所以直接用 `leftMax - height[left]` 累加进答案，然后 `left++`。
- 反过来，如果 `leftMax >= rightMax`：对称处理 `right` 指针，用 `rightMax - height[right]` 累加，然后 `right--`。

这样一来，只需要维护几个常数变量，空间复杂度就降到了 O(1)，时间复杂度还是 O(n)（因为每次循环 `left` 或 `right` 至少会往前挪一步）。

### 方法二：单调栈 —— 按行/凹槽计算

**这里换一个角度来想**：不是一列一列地算，而是直接去找"凹槽"这种结构——看哪三根柱子能凑成一个能蓄水的槽。咱们维护一个**从栈底到栈顶高度递减（或者非严格递减）**的栈，栈里存的是下标。遍历整个柱子数组：

1. 只要栈不为空，并且当前柱子高度 `height[i]` 比栈顶下标对应的高度还大，那就说明找到了一个凹槽的右边界，这时候要触发结算：
   - 弹出栈顶，记为 `mid`，也就是凹槽的槽底。
   - 如果弹出之后栈空了，说明左边根本没有屏障来接水，这一路是蓄不住水的，直接跳出内层循环。
   - 否则栈顶剩下的这个下标 `left` 就是凹槽的左边界。
   - 那这个凹槽能接多少水呢？宽度是 `i - left - 1`（左右边界之间、除去边界本身的列数），高度是 `min(height[left], height[i]) - height[mid]`（两侧屏障里较矮的那个减去槛底的高度），宽乘高累加进答案里。
   - 因为中间可能存在多层凹槽（比如高度先递减再递减），所以要用 `while` 循环连续结算，一直结算到栈顶高度不小于当前高度为止。
2. 结算完了之后，把当前下标压进栈里，当作新的"潜在槛底/右边界"，接着等后面出现更高的柱子来触发下一轮结算。

说白了，这个过程其实是"按行"累加雨水的思路：每弹一次栈，就相当于确定了一层凹槽的宽度和这一层的水量，一层一层累加起来，最终就是总的雨水量。

**那为什么这个单调栈找的是"凹槽"，而不像 739 题那样只是简单找"下一个更大值"呢**？因为接雨水这道题需要同时知道左右两个屏障的高度，而单调栈天生维护的性质——弹出的元素左边紧挨着的一定是比它更高（或相等）的元素，右边触发弹出的元素也比它高——正好同时给出了左右两侧的屏障，一次弹栈操作就能把一层完整的蓄水量算出来。

**复杂度这块给大家理一下**：
- 方法一（动态规划）：时间 O(n)，空间 O(n)。
- 方法一（双指针）：时间 O(n)，空间 O(1)。
- 方法二（单调栈）：时间 O(n)（每个下标入栈出栈各一次），空间 O(n)（栈占的空间）。

三种方法的时间复杂度都一样，但双指针法空间最优，是最推荐的写法；单调栈法则提供了另外一种"按层蓄水"的视角，理解了它对做 84 题也很有帮助（下面会讲这两题的对称关系）。

## 代码

### C++

```cpp
// 方法一：双指针，O(n) 时间 O(1) 空间
class Solution {
public:
    int trap(vector<int>& height) {
        int left = 0, right = height.size() - 1;
        int leftMax = 0, rightMax = 0; // 分别记录左右指针扫过范围内的最大高度
        int water = 0;
        while (left < right) {
            leftMax = max(leftMax, height[left]);
            rightMax = max(rightMax, height[right]);
            if (leftMax < rightMax) {
                // 左边屏障更矮，当前列的水位由leftMax决定
                water += leftMax - height[left];
                left++;
            } else {
                // 右边屏障更矮（或相等），当前列的水位由rightMax决定
                water += rightMax - height[right];
                right--;
            }
        }
        return water;
    }
};
```

```cpp
// 方法二：单调栈，按凹槽逐层结算
class Solution {
public:
    int trap(vector<int>& height) {
        stack<int> st;   // 栈中存下标，高度从栈底到栈顶递减
        int water = 0;
        for (int i = 0; i < (int)height.size(); i++) {
            // 当前柱子比栈顶柱子高，说明形成了凹槽的右边界
            while (!st.empty() && height[i] > height[st.top()]) {
                int mid = st.top(); st.pop(); // 槽底
                if (st.empty()) break;        // 左边没有屏障，无法蓄水
                int left = st.top();          // 凹槽左边界
                int width = i - left - 1;                          // 凹槽宽度
                int h = min(height[left], height[i]) - height[mid]; // 凹槽这一层的高度
                water += width * h;
            }
            st.push(i); // 当前下标入栈，作为新的潜在槽底
        }
        return water;
    }
};
```

// 方法二：单调栈
class Solution {
    public int trap(int[] height) {
        Deque<Integer> stack = new ArrayDeque<>(); // 栈中存下标，高度递减
        int water = 0;
        for (int i = 0; i < height.length; i++) {

                int mid = stack.pop();          // 槽底
                if (stack.isEmpty()) break;      // 左边没有屏障

                water += width * h;
            }
            stack.push(i);
        }
        return water;
    }
}

# 方法二：单调栈
class Solution:
    def trap(self, height: list[int]) -> int:
        stack = []   # 栈中存下标，高度从栈底到栈顶递减
        water = 0
        for i, h in enumerate(height):

                if not stack:

                depth = min(height[left], h) - height[mid]  # 这一层高度
                water += width * depth
            stack.append(i)
        return water

// 方法二：单调栈
func trapStack(height []int) int {
    stack := make([]int, 0, len(height)) // 栈中存下标，高度递减
    water := 0
    for i, h := range height {
        for len(stack) > 0 && h > height[stack[len(stack)-1]] {
            mid := stack[len(stack)-1]
            stack = stack[:len(stack)-1] // 槽底出栈
            if len(stack) == 0 {
                break // 左边没有屏障
            }
            left := stack[len(stack)-1]      // 左边界
            width := i - left - 1             // 凹槽宽度
            depth := min(height[left], h) - height[mid] // 这一层高度
            water += width * depth
        }
        stack = append(stack, i)
    }
    return water
}

func min(a, b int) int {
    if a < b {
        return a
    }
    return b
}

## 总结

- 接雨水这道题的核心公式就是"每一列的积水量 = min(左边最高, 右边最高) - 自身高度"，双指针法靠维护左右两个指针扫过的历史最大值，在不知道对面精确最大值的情况下，也能确定当前列的水位归属到底是谁，这样就把空间优化到了 O(1)。
- 单调栈法换了个视角来看这道题：不是一列一列地算，而是直接定位"凹槽"——左边界、槛底、右边界，一次弹栈就能同时确定凹槽的宽和高，说白了本质是"按层"累加雨水，而双指针/DP 是"按列"累加雨水，两种思路殊途同归，最后结果是一样的。
- 单调栈法里有个容易漏掉的边界条件：一旦弹出槛底之后栈变空了，说明左边根本没有更高的屏障能把水围住，这时候一定要记得 `break` 跳出内层循环。
- 双指针能简化到 O(1) 空间，关键的判断依据就是：只要 `leftMax < rightMax`，就能确定右边一定存在能挡住水的屏障（哪怕还没扫到它具体在哪），所以当前列的水位必然是由 `leftMax` 决定的。这其实是一种"提前确定归属、不用知道精确对手值"的技巧，在双指针这类问题里还挺常见的。
