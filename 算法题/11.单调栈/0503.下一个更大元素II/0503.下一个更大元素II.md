# 0503. 下一个更大元素 II

**题目描述**

给定一个循环数组 `nums`（最后一个元素的下一个元素是数组的第一个元素），返回 `nums` 中每个元素的下一个更大元素。数字 `x` 的下一个更大的元素是指在遍历中它后面（包括循环情况下从头开始遍历）第一个比它大的数字，如果不存在则输出 -1。

```
示例：
输入: nums = [1,2,1]
输出: [2,-1,2]
解释：
第一个 1 的下一个更大元素是 2
2 找不到下一个更大元素，输出 -1
第二个 1 由于是循环数组，向后循环到开头的 2，所以下一个更大元素是 2
```

## 思路

这道题是在 496 题"下一个更大元素 I"的基础上，多加了一个"循环"的条件，重点就是怎么在不破坏单调栈这个模板的前提下，把循环处理好。

**先说说为什么普通单调栈没法直接处理循环**：单调栈遍历一次数组，只能得到"从当前位置到数组末尾"这个范围内的下一个更大元素，如果这个范围里找不到，普通做法就会认为不存在了。但循环数组是允许绕回到开头继续找的，所以数组末尾的元素可能得从头再找一遍才行。

**那怎么处理循环呢——这里有个技巧，遍历两倍长度**：其实不需要真的把数组拼接成两倍长度的新数组（虽然这样也行，但会多用 O(n) 的额外空间），更省空间的做法是让下标 `i` 从 `0` 遍历到 `2n - 1`，但是通过取模 `i % n` 映射回原数组的真实下标去取值。这样等价于"虚拟地"把数组看成两倍长度、首尾相连，但实际存储用的还是原数组，没有多占空间。

具体是怎么个流程呢：

1. 先初始化一个答案数组 `res`，长度为 n，默认值都是 -1。
2. 用栈存**下标**（注意不是值，因为要往 `res` 里写答案，得知道原始位置在哪）。
3. 遍历虚拟下标 `i`，从 0 到 2n-1，取真实下标 `idx = i % n`，拿 `nums[idx]` 跟栈顶下标对应的值比较：
   - 只要栈不为空，并且 `nums[idx] > nums[栈顶下标]`，就说明栈顶那个下标等到了更大的值，弹出栈顶 `j`，记下 `res[j] = nums[idx]`。
   - 这里要注意一点：不用担心同一个下标被重复处理两次导致结果出错，因为一个下标一旦被弹出，就不会再压回栈里了；而当 `i >= n` 的时候，也就是遍历进入了"第二轮"，可能还有些真实下标（比如数组末尾的元素）留在栈里没被结算，这时候就用第二轮的元素继续尝试去弹出它们，这正好就模拟出了"循环数组"这个语义。
4. 当 `i >= n` 的时候，就不用再把 `idx` 重新压进栈了（因为它在第一轮已经压过一次了，要是第一轮就被弹出了，说明已经有答案了；要是还留在栈里，那就是原来的下标本身，没必要重复入栈弄出冗余）。这是实现上的一个小优化点：可以在压栈的时候判断一下 `i < n` 才允许 push。

**那为什么遍历两倍长度是对的呢**？你想，对于下标 `j`（0 <= j < n），它右边能扩展查找的范围就是 `j+1, j+2, ..., n-1, 0, 1, ..., j-1`（绕一圈回到自己前一个位置为止，不会超过一整圈，因为题目要求的是"下一个"，不会用自己本身）。用虚拟下标一直遍历到 `2n-1`，相当于让每个原始下标都有机会被"第二轮"里从 `n` 到 `n+j-1` 的这些元素比较到，这正好就覆盖了绕一圈的范围，而且也不会多算（因为一旦某个下标被弹出结算过了，就不会再影响后面的判断）。

**复杂度这块**：
- 时间复杂度 O(n)：虽然遍历的长度是 2n，但这仍然是常数倍的线性复杂度；每个下标最多入栈一次、出栈一次。
- 空间复杂度 O(n)：栈和答案数组都是 O(n) 级别的，不需要真的复制出一个两倍长度的新数组。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        int n = nums.size();
        vector<int> res(n, -1);   // 默认值-1，表示循环一圈也没找到更大元素
        stack<int> st;             // 栈中存下标，从栈底到栈顶对应值递减
        for (int i = 0; i < 2 * n; i++) {  // 遍历两倍长度模拟循环
            int idx = i % n;                // 取模映射回真实下标
            // 当前值比栈顶下标对应的值大，弹出并结算
            while (!st.empty() && nums[idx] > nums[st.top()]) {
                res[st.top()] = nums[idx];
                st.pop();
            }
            if (i < n) {
                st.push(idx); // 只在第一轮压入，避免重复入栈同一个下标
            }
        }
        return res;
    }
};
```

### Java

```java
class Solution {
    public int[] nextGreaterElements(int[] nums) {
        int n = nums.length;
        int[] res = new int[n];
        Arrays.fill(res, -1);          // 默认-1，表示循环一圈没找到
        Deque<Integer> stack = new ArrayDeque<>(); // 栈中存下标
        for (int i = 0; i < 2 * n; i++) {          // 遍历两倍长度
            int idx = i % n;                        // 映射回真实下标
            while (!stack.isEmpty() && nums[idx] > nums[stack.peek()]) {
                res[stack.pop()] = nums[idx];       // 结算
            }
            if (i < n) {
                stack.push(idx); // 仅第一轮入栈，避免重复
            }
        }
        return res;
    }
}
```

### Python

```python
class Solution:
    def nextGreaterElements(self, nums: list[int]) -> list[int]:
        n = len(nums)
        res = [-1] * n     # 默认-1，表示循环一圈没找到
        stack = []          # 栈中存下标，对应值从栈底到栈顶递减
        for i in range(2 * n):        # 遍历两倍长度模拟循环
            idx = i % n                # 映射回真实下标
            while stack and nums[idx] > nums[stack[-1]]:
                res[stack.pop()] = nums[idx]  # 结算
            if i < n:
                stack.append(idx)  # 仅第一轮入栈，避免重复
        return res
```

### Go

```go
func nextGreaterElements(nums []int) []int {
    n := len(nums)
    res := make([]int, n)
    for i := range res {
        res[i] = -1 // 默认-1，表示循环一圈没找到
    }
    stack := make([]int, 0, n) // 栈中存下标
    for i := 0; i < 2*n; i++ { // 遍历两倍长度模拟循环
        idx := i % n             // 映射回真实下标
        for len(stack) > 0 && nums[idx] > nums[stack[len(stack)-1]] {
            top := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            res[top] = nums[idx] // 结算
        }
        if i < n {
            stack = append(stack, idx) // 仅第一轮入栈
        }
    }
    return res
}
```

## 总结

- 处理循环数组的通用技巧就是"遍历两倍长度 + 取模映射真实下标"，说白了本质上是虚拟地把数组延展成两份首尾相连，但又避免了真正复制数组带来的额外空间开销。
- 栈里必须存下标而不是值，因为最终结果要写回 `res[原下标]`，只有下标才能定位到原数组的具体位置。
- 这里有个关键的实现细节，就是"只在第一轮（`i < n`）的时候才压栈"，不然第二轮遍历的时候，同一个下标就会被重复压进去，造成结果出错或者冗余计算。
- 这道题跟 496 题的联系是：如果把"循环"这个条件去掉，这道题就退化成了对单个数组求下一个更大元素（也就是 496 题预处理 `nums2` 的那一步），循环数组只是在这个基础上把查找范围扩展了一下而已。
