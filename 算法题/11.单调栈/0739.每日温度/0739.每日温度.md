# 0739. 每日温度

**题目描述**

给定一个整数数组 `temperatures`，表示每天的气温，返回一个数组 `answer`，其中 `answer[i]` 表示对于第 `i` 天，下一个更高气温出现在几天之后。如果气温在这之后都不会升高，则该位置用 0 代替。

```
示例：
输入: temperatures = [73,74,75,71,69,72,76,73]
输出: [1,1,4,2,1,1,0,0]
解释：
第0天(73°)，下一个更高温度在第1天(74°)，间隔1天
第2天(75°)，下一个更高温度在第6天(76°)，间隔4天
第6天(76°)是全局最高，之后没有更高的，输出0
```

## 思路

这道题是单调栈的入门题，我先讲一下暴力解法，再引出单调栈的优化思路。

**先看暴力解法**：对每一天 `i`，往右扫描，找到第一个比 `temperatures[i]` 大的天数，记录间隔天数。这样两层循环下来，时间复杂度是 O(n²)。数组一长就会超时，问题出在哪呢？就是对于每一天，都要重新扫描一遍右边的所有元素，而这些扫描里其实有大量重复劳动——比如说第0天扫描的时候会经过第1、2、3天，之后这几天又会作为起点被重新扫一遍，白白浪费了。

**那单调栈的核心思路是什么呢**？能不能让每个元素只被处理一次？答案是用一个栈来保存"还没找到答案的下标"，栈里这些下标对应的温度值保持**递增**（从栈底到栈顶递增，也就是说栈顶元素最大）。

具体是怎么做的呢：从左到右遍历数组，对每个新元素 `temperatures[i]`：

1. 只要栈不为空，并且当前温度 `temperatures[i]` 比栈顶下标对应的温度高，那就说明栈顶那一天等到了它的"更高温度"，弹出栈顶下标 `j`，这时候 `answer[j] = i - j`，因为 `i` 就是 `j` 之后第一个比它温度高的那天。这一步要用 `while` 循环，因为当前这个温度可能同时打破好几个栈内元素的单调性，得连续弹出好几个。
2. 弹出结束之后（栈空了，或者栈顶温度已经不低于 `temperatures[i]`），就把当前下标 `i` 压进栈里。这代表"到目前这个温度为止，还没等到比它更高的一天"，得留在栈里继续等着。

那为什么栈里维护的下标对应的温度一定是单调递增的呢（从栈底到栈顶递增）？你想啊，因为每次入栈之前都先把"比当前温度矮"的元素全部弹出去了，剩下能留在栈里、排在当前元素前面的，肯定是比当前温度更高（或者相等）的元素——这就保证了栈内从底往上看是非递增的，或者说从顶往下看是非递减的（也就是栈顶最小）。反过来说，栈里实际维护的是一个**从栈底到栈顶递减**的序列，一旦有新元素比栈顶大，就会触发弹出结算。

**那为什么能把 O(n²) 优化到 O(n) 呢**？暴力法里，每一天都要重新往右扫一遍，产生了大量重复扫描；而单调栈法里，每个下标只会被"压入栈"一次、"弹出栈"一次，一共加起来只有 2n 次操作，整个过程就是一次线性扫描搞定的。栈的作用，说白了就相当于把"还没确定答案、正在等待被结算的下标"先暂存起来，等到条件满足了（也就是遇到更大的数）才一次性结算，这样就避免了对已经扫描过的区间重复扫描。

**复杂度这块**：
- 时间复杂度 O(n)：每个下标最多入栈一次、出栈一次。
- 空间复杂度 O(n)：最坏情况下（温度是递减序列），所有下标都会压进栈里，栈的大小能达到 n。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> answer(n, 0);      // 默认0，表示后面没有更高的
        stack<int> st;                 // 栈中存下标，对应温度从栈底到栈顶递减
        for (int i = 0; i < n; i++) {
            // 当前温度比栈顶下标对应的温度高，说明栈顶那天等到了更高温度
            while (!st.empty() && temperatures[i] > temperatures[st.top()]) {
                int j = st.top();
                st.pop();
                answer[j] = i - j;     // 结算：间隔天数 = 当前下标 - 栈顶下标
            }
            st.push(i);                // 当前下标入栈，等待被后面更高的温度结算
        }
        return answer;
    }
};
```

### Java

```java
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] answer = new int[n];         // 默认0
        Deque<Integer> stack = new ArrayDeque<>(); // 栈中存下标，温度从栈底到栈顶递减
        for (int i = 0; i < n; i++) {
            // 当前温度比栈顶对应温度高，弹出并结算
            while (!stack.isEmpty() && temperatures[i] > temperatures[stack.peek()]) {
                int j = stack.pop();
                answer[j] = i - j;         // 间隔天数
            }
            stack.push(i);                 // 当前下标入栈
        }
        return answer;
    }
}
```

### Python

```python
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        n = len(temperatures)
        answer = [0] * n          # 默认0，表示后面没有更高的
        stack = []                 # 栈中存下标，温度从栈底到栈顶递减
        for i, cur in enumerate(temperatures):
            # 当前温度比栈顶下标对应温度高，说明栈顶那天等到了更高温度
            while stack and cur > temperatures[stack[-1]]:
                j = stack.pop()
                answer[j] = i - j  # 结算：间隔天数
            stack.append(i)        # 当前下标入栈，等待被结算
        return answer
```

### Go

```go
func dailyTemperatures(temperatures []int) []int {
    n := len(temperatures)
    answer := make([]int, n)      // 默认0
    stack := make([]int, 0, n)    // 栈中存下标，温度从栈底到栈顶递减
    for i := 0; i < n; i++ {
        // 当前温度比栈顶下标对应温度高，弹出并结算
        for len(stack) > 0 && temperatures[i] > temperatures[stack[len(stack)-1]] {
            j := stack[len(stack)-1]
            stack = stack[:len(stack)-1] // 弹出栈顶
            answer[j] = i - j            // 结算间隔天数
        }
        stack = append(stack, i) // 当前下标入栈
    }
    return answer
}
```

## 总结

- 单调栈的本质说白了就是"延迟结算"：遇到还确定不了答案的元素，先压进栈里暂存着，等到未来某个元素能触发结算条件了（这里就是"比栈顶更大"），才一次性批量弹出计算，这样就避免了暴力法里的重复扫描。
- 这道题栈里维护的是下标而不是数值本身，因为最终答案得算下标差（也就是间隔天数），要是只存数值，位置信息就丢了。
- 判断"该入栈还是该弹栈"的关键，就在于比较新元素和栈顶元素的大小关系，这决定了栈该维护成什么单调性方向（递增栈是用来找更小值的，递减栈是用来找更大值的）。这道题要找的是"下一个更大元素"，所以用的是栈内自底向上非递增的写法（也就是说，找到更大值就弹栈）。
- 时间复杂度能从 O(n²) 降到 O(n)，关键就在于每个下标只会被压入和弹出各一次，总的操作次数是线性的。
