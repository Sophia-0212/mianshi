# 0084. 柱状图中最大的矩形

**题目描述**

给定 `n` 个非负整数，用来表示柱状图中各个柱子的高度，每个柱子彼此相邻，且宽度为 1。求在该柱状图中，能够勾勒出来的矩形的最大面积。

```
示例：
输入: heights = [2,1,5,6,2,3]
输出: 10
解释: 最大的矩形由下标2、3处的柱子（高度5、6）中较矮的高度5为矩形高，
宽度从下标2到下标3，但实际上可以扩展——
以高度5为矩形高时，宽度能扩展到下标1右边、下标4左边之间(下标2到3)，面积5*2=10。
```

## 思路

### 暴力解法与问题所在

最直接的想法就是，咱们枚举每一根柱子，把它当作矩形的高度 `heights[i]`，然后往左、往右扩展，看能扩展到多宽——也就是找到左边第一个比 `heights[i]` 矮的柱子位置 `left`，右边第一个比 `heights[i]` 矮的柱子位置 `right`，那以 `heights[i]` 为高的矩形，最大宽度就是 `right - left - 1`，面积就是 `heights[i] * (right - left - 1)`。每个 `i` 都这样算一遍，取所有面积里的最大值，就是答案。

这个思路本身是对的，但如果暴力实现（对每个 `i` 都分别往左往右线性扫一遍），那就是 O(n²) 了。问题出在哪呢？其实就是往左往右扫描的时候，会重复遍历一大堆已经比较过的柱子，效率浪费在这上面了。

### 单调栈优化：核心目标转换

那优化的关键在哪呢——能不能对每个位置 `i`，用 O(1) 均摊的代价，就求出"左边第一个比它矮的下标"和"右边第一个比它矮的下标"？这正好就是单调栈的经典用法：**维护一个从栈底到栈顶高度递增的栈**（跟接雨水的递减栈刚好是相反的，这个后面我会详细对比）。

遍历柱子数组，对每个新柱子 `heights[i]`，你想啊：

1. 只要栈不为空，并且当前高度 `heights[i]` 小于栈顶下标对应的高度，这就说明栈顶那根柱子往右扩展、扩到当前位置就必须停下来了（因为遇到了比它矮的柱子），也就是说找到了栈顶柱子"右边第一个更矮的柱子"就是当前下标 `i`。这时候就要触发结算了：
   - 弹出栈顶，记为 `mid`。
   - 弹出之后，如果栈空了，说明 `mid` 左边根本没有比它更矮的柱子（也就是说从最左边一直到 `mid`，都比它高或者相等），这种情况下矩形的左边界就是 -1（相当于可以一直扩展到数组最左端）。
   - 如果栈不空，那新的栈顶下标 `left` 就是 `mid` 左边第一个比它矮的柱子。
   - 于是以 `heights[mid]` 为高的矩形，宽度就是 `i - left - 1`，面积是 `heights[mid] * (i - left - 1)`，拿这个去更新最大面积。
2. 结算完了以后，把当前下标 `i` 压进栈里，继续等着被后面更矮的柱子触发结算。
3. 遍历结束之后，栈里可能还剩一些下标（对应的柱子一直没遇到过比它更矮的柱子），这些柱子其实可以认为一直扩展到了数组最右端（下标 `n`），所以遍历完还得对栈里剩下的元素再结算一遍（右边界当作 `n`）。这里有个常用的小技巧：在数组末尾人为加上一个高度为 0 的哨兵柱子，这样栈里所有的元素最终都会被这个 0 触发弹出，就不用额外写一段"处理剩余栈"的代码了。

**那为什么这样做能保证结果是对的呢**？你想，栈里维护的是"从栈底到栈顶高度递增"这个性质，也就是说栈中任意一个下标 `mid`，它左边紧挨着在栈里的下标 `left` 对应的高度，一定小于 `heights[mid]`（因为能留在栈里排在 `mid` 前面，说明 `mid` 入栈的时候它还没被弹出，也就是说它比 `mid` 矮或者一样高——这里为了处理高度相等时不重复计算的问题，实际操作中弹出条件我们定为 `heights[i] < heights[st.top()]`，相等的时候不弹出，交给后面更矮的柱子统一处理，这样既不会漏算，又保证每个下标只会被弹出一次）。而触发弹出的这个当前下标 `i` 对应的高度是比 `mid` 矮的，正好就是 `mid` 右边第一个更矮的位置。所以每次弹出操作，`left`（新栈顶）和 `i`（当前下标）恰好就是 `mid` 左右两个矮边界，一次弹出就能把以 `mid` 为高的矩形最大宽度算出来了。

### 与接雨水的对称关系

这道题和 42 题"接雨水"都是用单调栈来解决的，但栈的单调性方向刚好是反过来的，这里面有个挺有意思的对称关系：

- **接雨水**：维护的是**递减栈**（栈顶最小），要找的是"比当前元素更高的柱子"来当凹槽的边界——因为水得被两边更高的柱子围住才能蓄住，所以要找"更高"的。
- **柱状图最大矩形**：维护的是**递增栈**（栈顶最大），要找的是"比当前元素更矮的柱子"来当矩形的边界——因为矩形的高度受限于这段区间里最矮的那根柱子，一旦碰到更矮的柱子，前面那些高柱子就没法再往右扩展了，所以要找"更矮"的。

可以这么理解：接雨水是"找容器的墙"（墙必须比水面高），柱状图这道题是"找矩形的限制"（限制必须比当前柱子矮）。这两题都是通过一次单调栈遍历，把原本 O(n²) 的双向扩展查找优化成了 O(n) 的线性遍历，只不过栈的单调方向和触发弹出的比较符号（大于还是小于）正好是互为镜像的关系。

**复杂度这块说一下**：
- 时间复杂度 O(n)：加上哨兵之后，每个下标入栈一次、出栈一次，总的操作次数是线性的。
- 空间复杂度 O(n)：最坏情况下（严格递增序列），所有下标会同时压在栈里。

## 代码

### C++

```cpp
class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {
        heights.push_back(0);       // 哨兵，保证栈中所有元素最终都会被弹出结算
        stack<int> st;                // 栈中存下标，高度从栈底到栈顶递增
        int maxArea = 0;
        for (int i = 0; i < (int)heights.size(); i++) {
            // 当前高度比栈顶柱子矮，说明栈顶柱子右边界就是当前下标
            while (!st.empty() && heights[i] < heights[st.top()]) {
                int mid = st.top(); st.pop();          // 取出待结算的柱子
                int left = st.empty() ? -1 : st.top();  // 左边界：栈为空则视为-1
                int width = i - left - 1;               // 矩形宽度
                maxArea = max(maxArea, heights[mid] * width);
            }
            st.push(i); // 当前下标入栈
        }
        heights.pop_back(); // 恢复原数组（避免副作用）
        return maxArea;
    }
};
```

### Java

```java
class Solution {
    public int largestRectangleArea(int[] heights) {
        int n = heights.length;
        int[] h = new int[n + 1];
        System.arraycopy(heights, 0, h, 0, n);
        h[n] = 0; // 哨兵，保证栈中所有元素最终都会被弹出结算

        Deque<Integer> stack = new ArrayDeque<>(); // 栈中存下标，高度递增
        int maxArea = 0;
        for (int i = 0; i < h.length; i++) {
            while (!stack.isEmpty() && h[i] < h[stack.peek()]) {
                int mid = stack.pop();                       // 待结算柱子
                int left = stack.isEmpty() ? -1 : stack.peek(); // 左边界
                int width = i - left - 1;                     // 矩形宽度
                maxArea = Math.max(maxArea, h[mid] * width);
            }
            stack.push(i);
        }
        return maxArea;
    }
}
```

class Solution:

        h = heights + [0]  # 哨兵，保证栈中所有元素最终都会被弹出结算
        stack = []           # 栈中存下标，高度从栈底到栈顶递增

### Go

```go
func largestRectangleArea(heights []int) int {
    h := append(append([]int{}, heights...), 0) // 哨兵，保证栈中所有元素最终都会被弹出结算
    stack := make([]int, 0, len(h))               // 栈中存下标，高度递增
    maxArea := 0
    for i, cur := range h {
        // 当前高度比栈顶柱子矮，说明栈顶柱子右边界就是当前下标
        for len(stack) > 0 && cur < h[stack[len(stack)-1]] {
            mid := stack[len(stack)-1]
            stack = stack[:len(stack)-1] // 待结算柱子出栈
            left := -1
            if len(stack) > 0 {
                left = stack[len(stack)-1] // 左边界
            }
            width := i - left - 1// 矩形宽度
            if area := h[mid] * width; area > maxArea {
                maxArea = area
            }
        }
        stack = append(stack, i)
    }
    return maxArea
}
```

## 总结

- 这道题的核心，就是把"暴力向左向右扩展找矮柱子"这个 O(n²) 的过程，用单调栈一次遍历优化到了 O(n)：栈维护的是"从栈底到栈顶高度递增"的性质，每次弹出操作正好同时确定了被弹出柱子的左右两个"更矮边界"。
- 在数组末尾加一个高度为 0 的哨兵柱子，这是个很常用的小技巧，可以避免遍历结束之后还要单独写一段代码去处理栈里剩下的元素，让所有柱子都能在主循环里统一被结算掉。
- 这道题跟 42 题接雨水的单调栈方向刚好相反：接雨水是找"更高"的柱子来当蓄水墙（用的是递减栈），这道题是找"更矮"的柱子来当矩形边界（用的是递增栈），理解这种对称关系，有助于以后碰到单调栈题目时判断该往哪个方向维护——关键就看题目需要找的是"更大"还是"更小"的元素。
- 求矩形宽度的公式 `i - left - 1` 里，`left` 和 `i` 都是边界柱子本身（它们不算在矩形范围内），所以要减 1 把这两个边界位置排除掉，只统计中间部分的宽度。
