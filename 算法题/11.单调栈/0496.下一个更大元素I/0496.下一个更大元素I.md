# 0496. 下一个更大元素 I

**题目描述**

给定两个没有重复元素的数组 `nums1` 和 `nums2`，其中 `nums1` 是 `nums2` 的子集。对于 `nums1` 中的每个元素，找出它在 `nums2` 中对应位置右边的第一个比它大的元素，如果不存在则输出 -1。

```
示例：
输入: nums1 = [4,1,2], nums2 = [1,3,4,2]
输出: [-1,3,-1]
解释：
4 在 nums2 中的下一个更大元素不存在，输出 -1
1 在 nums2 中的下一个更大元素是 3
2 在 nums2 中的下一个更大元素不存在，输出 -1
```

## 思路

这道题其实是"单调栈"跟"哈希表"结合的一个经典模式，咱们先把题目结构理清楚，再展开讲算法。

**先看题目结构**：`nums1` 是 `nums2` 的子集，这就意味着，如果我能提前把 `nums2` 里**每一个**元素的"下一个更大元素"都算出来，那对 `nums1` 里的每个元素，直接查表就能拿到答案了，根本不需要针对 `nums1` 再单独跑一次遍历。这就是解题的关键突破口——把问题拆成两步来做：

1. 对 `nums2` 跑一遍单调栈，把 `nums2` 里每个元素的下一个更大元素都算出来，存进一个哈希表 `map`（key 是元素值，value 是它的下一个更大元素，找不到的话就记成 -1）。
2. 遍历 `nums1`，每个元素直接去 `map` 里查表，就能得到答案。

**那为什么能用元素值本身当 key 呢**？因为题目保证了 `nums2` 里没有重复元素，所以"元素值"和"下标"是一一对应的关系，用值当 key 不会产生歧义。要是数组里允许有重复元素，那就必须用下标当 key 了，再通过下标映射回原数组。

**单调栈求 nums2 的下一个更大元素**：这一步说白了跟 739 题每日温度是同一个模板——维护一个从栈底到栈顶递减的栈（这里存的是元素值而不是下标，因为咱们只关心值和值之间的映射关系，不需要算距离）。遍历 `nums2`：

1. 当前元素比栈顶元素大，说明栈顶那个元素等到了它的"下一个更大元素"，弹出栈顶并记下 `map[栈顶元素] = 当前元素`，用 `while` 循环来处理连续弹出的情况。
2. 弹出结束之后，把当前元素压进栈里，接着等被后面更大的元素结算。
3. 遍历结束以后，栈里剩下的那些元素都没找到比它更大的值，它们在 `map` 里应该记为 -1（可以提前初始化好，也可以遍历结束后统一处理，或者干脆在查询的时候用类似 `map.getOrDefault` 的方式，默认返回 -1）。

**复杂度这块**：
- 时间复杂度是 O(m + n)，其中 m 是 `nums1` 的长度，n 是 `nums2` 的长度：单调栈遍历 `nums2` 是 O(n)，查表遍历 `nums1` 是 O(m)。
- 空间复杂度是 O(n)：哈希表和栈最坏情况下都要存 n 个元素。

说白了，这种"先在大范围里把所有答案都预处理出来，再对子集查表"的思路，是一种很常见的解题技巧：一旦发现查询的集合是全集的子集，往往就可以把重复的计算合并到一次预处理里搞定。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        unordered_map<int, int> nextGreater; // 值 -> 下一个更大值
        stack<int> st;                       // 栈中存元素值，从栈底到栈顶递减
        for (int num : nums2) {
            // 当前值比栈顶值大，弹出并记录映射
            while (!st.empty() && num > st.top()) {
                nextGreater[st.top()] = num;
                st.pop();
            }
            st.push(num); // 当前值入栈，等待被结算
        }
        // 栈中剩余元素没有找到更大值，对应 -1（下面查表时用 getOrDefault 处理，此处无需显式赋值）

        vector<int> res;
        res.reserve(nums1.size());
        for (int num : nums1) {
            // 查表，找不到说明没有下一个更大元素
            res.push_back(nextGreater.count(num) ? nextGreater[num] : -1);
        }
        return res;
    }
};
```

### Java

```java
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        Map<Integer, Integer> nextGreater = new HashMap<>(); // 值 -> 下一个更大值
        Deque<Integer> stack = new ArrayDeque<>();           // 栈中存元素值，从栈底到栈顶递减
        for (int num : nums2) {
            // 当前值比栈顶值大，弹出并记录映射
            while (!stack.isEmpty() && num > stack.peek()) {
                nextGreater.put(stack.pop(), num);
            }
            stack.push(num); // 当前值入栈
        }

        int[] res = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) {
            // 查表，默认值 -1 表示没有找到更大元素
            res[i] = nextGreater.getOrDefault(nums1[i], -1);
        }
        return res;
    }
}
```

### Python

```python
class Solution:
    def nextGreaterElement(self, nums1: list[int], nums2: list[int]) -> list[int]:
        next_greater = {}   # 值 -> 下一个更大值
        stack = []           # 栈中存元素值，从栈底到栈顶递减
        for num in nums2:
            # 当前值比栈顶值大，弹出并记录映射
            while stack and num > stack[-1]:
                next_greater[stack.pop()] = num
            stack.append(num)  # 当前值入栈

        # 查表，get 的默认值 -1 表示没有下一个更大元素
        return [next_greater.get(num, -1) for num in nums1]
```

### Go

```go
func nextGreaterElement(nums1 []int, nums2 []int) []int {
    nextGreater := make(map[int]int) // 值 -> 下一个更大值
    stack := make([]int, 0, len(nums2)) // 栈中存元素值，从栈底到栈顶递减
    for _, num := range nums2 {
        // 当前值比栈顶值大，弹出并记录映射
        for len(stack) > 0 && num > stack[len(stack)-1] {
            top := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            nextGreater[top] = num
        }
        stack = append(stack, num) // 当前值入栈
    }

    res := make([]int, len(nums1))
    for i, num := range nums1 {
        if v, ok := nextGreater[num]; ok {
            res[i] = v // 查表成功
        } else {
            res[i] = -1 // 没有找到更大元素
        }
    }
    return res
}
```

## 总结

- 这道题的核心其实不在单调栈本身（这个模板和 739 题完全一样），关键是要识别出"子集查询"这个结构，把问题拆成"对全集预处理 + 对子集查表"两步，这样就避免了对 `nums1` 里每个元素都重复扫一遍 `nums2`。
- 因为 `nums2` 里的元素不重复，所以可以直接拿元素值当哈希表的 key；但如果存在重复元素，就必须改成用下标当 key 了，不然值会冲突覆盖。
- 单调栈这里存的是元素值而不是下标，因为咱们只需要建立"值到值"的映射关系，不涉及位置的计算（不像 739 题那样需要算下标差）。
- 哈希表查询是 O(1)，配合 O(n) 的单调栈预处理，整体复杂度就是线性的，比对 `nums1` 里每个元素都在 `nums2` 里线性扫一遍（那样是 O(m*n)）要高效得多。
