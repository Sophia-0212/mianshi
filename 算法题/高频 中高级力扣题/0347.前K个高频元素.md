# 0347. 前K个高频元素

**题目描述**

给定一个整数数组 `nums` 和一个整数 `k`，返回其中出现频率前 `k` 高的元素。可以按任意顺序返回答案。

```
示例：
输入: nums = [1,1,1,2,2,3], k = 2
输出: [1,2]
解释: 元素1出现3次，元素2出现2次，元素3出现1次，频率最高的2个是1和2
```

要求：答案唯一确定（假设频率相同时任意返回其中一个都算正确）。

## 思路

先用哈希表统计频次，再选前 `k` 个：

- 小顶堆：堆大小超过 `k` 就弹出最低频元素。平均时间 O(n+m log(k+1))，空间 O(m+k)。
- 大顶堆：全部 `m` 个不同值建堆，弹出 `k` 次。平均时间 O(n+m+k log m)，空间 O(m)。
- 按频次排序后取前 k 个：平均时间 O(n+m log m)，空间 O(m)。
- Python 可调用 `Counter(nums).most_common(k)`。

m 为不同值个数。



## Python

### LeetCode 写法与原有示例

标准库一行解：`collections.Counter.most_common(k)` 底层同样是用堆（`heapq.nlargest`）实现的，直接返回前 k 高频元素。

```python
from collections import Counter

# 依赖说明：Python 标准库 collections：deque 是双端队列，Counter 是计数器，defaultdict 是带默认值的字典。

class Solution:
    # 方法：topKFrequent；按题目要求处理输入并返回结果，核心算法见方法体。
    def topKFrequent(self, nums: list[int], k: int) -> list[int]:
        count = Counter(nums)  # 统计频率
        return [num for num, _ in count.most_common(k)]  # 库函数直接取前k高频
```


手写实现（面试考察点，用 `heapq` 手动维护小顶堆还原底层原理）：

```python
import heapq
from collections import Counter

# 依赖说明：Python 标准库 heapq：提供基于列表的最小堆操作。；Python 标准库 collections：deque 是双端队列，Counter 是计数器，defaultdict 是带默认值的字典。；len：Python 内置函数：返回容器中元素的数量。

class Solution:
    # 方法：topKFrequent；按题目要求处理输入并返回结果，核心算法见方法体。
    def topKFrequent(self, nums: list[int], k: int) -> list[int]:
        freq = Counter(nums)  # 哈希统计频率
        min_heap = []  # heapq 默认就是小顶堆，堆顶是最小元素

        for num, cnt in freq.items():
            heapq.heappush(min_heap, (cnt, num))  # 按 (频率, 元素值) 入堆，堆顶频率最小
            if len(min_heap) > k:
                heapq.heappop(min_heap)  # 堆内超过k个，弹出频率最小的

        return [num for _, num in min_heap]  # 堆中剩余的k个即为答案
```

## Go

### LeetCode 写法与原有示例

Go 没有内置堆，需要实现 `container/heap` 接口的 `Len`/`Less`/`Swap`/`Push`/`Pop` 方法来自定义小顶堆。

```go
// 依赖说明：Go 标准库 container/heap：堆操作。
import "container/heap"

// 定义 (频率, 元素值) 对组成的小顶堆
type pair struct {
    freq int
    num  int
}
type minHeap []pair

// 方法：Len；按题目要求处理输入并返回结果，核心算法见方法体。
func (h minHeap) Len() int            { return len(h) }
// 方法：Less；按题目要求处理输入并返回结果，核心算法见方法体。
func (h minHeap) Less(i, j int) bool  { return h[i].freq < h[j].freq } // 频率小的排前面，堆顶最小
// 方法：Swap；按题目要求处理输入并返回结果，核心算法见方法体。
func (h minHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
// 方法：Push；按题目要求处理输入并返回结果，核心算法见方法体。
func (h *minHeap) Push(x interface{}) { *h = append(*h, x.(pair)) }
// 方法：Pop；按题目要求处理输入并返回结果，核心算法见方法体。
func (h *minHeap) Pop() interface{} {
    old := *h
    n := len(old)
    item := old[n-1]
    *h = old[:n-1]
    return item
}

// 方法：topKFrequent；按题目要求处理输入并返回结果，核心算法见方法体。
func topKFrequent(nums []int, k int) []int {
    freq := make(map[int]int) // 哈希统计频率
    for _, num := range nums {
        freq[num]++
    }

    h := &minHeap{}
    heap.Init(h)
    for num, cnt := range freq {
        heap.Push(h, pair{freq: cnt, num: num})
        if h.Len() > k {
            heap.Pop(h) // 堆内超过k个，弹出频率最小的
        }
    }

    result := make([]int, 0, k)
    for _, p := range *h {
        result = append(result, p.num)
    }
    return result
}
```

## C++

### LeetCode 写法与原有示例

```cpp
// 依赖说明：vector：C++ STL 动态数组。；unordered_map：C++ STL 哈希映射。；queue/priority_queue：C++ STL 队列容器。；pair：C++ STL 二元组工具。

class Solution {
public:
    // 方法：topKFrequent；按题目要求处理输入并返回结果，核心算法见方法体。
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> freq;  // 哈希统计频率
        for (int num : nums) {
            freq[num]++;
        }

        // 小顶堆：pair<频率, 元素值>，按频率比较，堆顶是频率最小的
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>> minHeap;

        for (auto& [num, count] : freq) {
            minHeap.push({count, num});
            if (minHeap.size() > k) {
                minHeap.pop();  // 堆内超过k个，弹出频率最小的（不够格留在前k）
            }
        }

        vector<int> result;
        while (!minHeap.empty()) {
            result.push_back(minHeap.top().second);
            minHeap.pop();
        }
        return result;
    }
};```

## 总结

- 找前 K 大问题有个通用套路，就是"用大小固定为 k 的堆，逐个元素跟堆顶比较，决定是否替换"，堆的大小始终维持在 k，而不是把所有元素都塞进堆里再排序，这个思路一定要记牢。
- 为什么用小顶堆而不是大顶堆呢？说白了就是因为堆顶要作为"当前 k 个候选里最容易被淘汰的那个"，这样才方便用一次比较就决定新元素能不能挤进前 k；这个"堆顶是最不合格的候选"正好对应小顶堆堆顶是最小值这个性质，两者是对上的。
- 复杂度上小顶堆方案是 O(n + m log k)，比对所有 m 个元素排序的 O(m log m) 更优，尤其是当 k 远小于 m 的时候，优势特别明显。
- Python 里 `Counter.most_common(k)` 是个很方便的库函数一行解，实际写代码时直接用挺好；但面试中通常会要求你手写 `heapq` 版本，理解"为什么是小顶堆"才是这道题真正考察的点。
