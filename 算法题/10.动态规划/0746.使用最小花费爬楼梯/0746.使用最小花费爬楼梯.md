# 0746. 使用最小花费爬楼梯

**题目描述**

给你一个整数数组 `cost`，其中 `cost[i]` 表示从楼梯第 i 个台阶向上爬需要支付的体力值。一旦你支付了这个体力值，你就可以选择向上爬一个或者两个台阶。你可以选择从下标为 0 或下标为 1 的台阶开始爬楼梯。请你计算并返回达到楼梯顶部的最低花费。这里"楼梯顶部"指的是数组的下一个下标位置，也就是下标为 `cost.length` 的位置，它本身不在数组范围内，不需要额外花费。

```
示例：
输入: cost = [10, 15, 20]
输出: 15
解释: 最低花费方式是从下标 1 开始，支付 15，然后向上爬两个台阶到达楼顶（下标 3，超出数组范围，无需再付费）。
```

## 思路

你想啊，这道题的递推公式跟前两道题——斐波那契数列、爬楼梯——在形状上挺像的，都是dp[i]由dp[i-1]和dp[i-2]推出来。但这里的关键是，这道题在"到达状态"之上又叠加了一层"花费最优"的要求，所以dp数组的含义和递推公式的推导方式都要比前两道题复杂一点，值得我逐字逐句把定义讲清楚，不然很容易在边界条件上翻车。

**第一步，先确定dp数组（下标）的含义**

这一步得格外谨慎，为什么呢？因为"到达第i个台阶"和"离开第i个台阶"这两种定义方式都能把题目做对，但过程会不一样，你要是混着用就一定会出错。这里我采用题目原本的设定：`cost[i]` 是"使用"第i个台阶需要付的代价，也就是说，只要你站上了第i个台阶，这次站上去的动作本身就要花 `cost[i]`，不管你后续是从这里往上跳还是干别的。

基于这个设定，我把dp[i]定义为：到达下标i这个台阶，总共要花费的最小体力值（这个花费已经包含了站上第i个台阶本身的 `cost[i]`）。

**第二步，确定递推公式**

要到达第i个台阶，题目规定每次只能爬1阶或2阶，所以上一步只能是从第i-1阶走1步上来，或者从第i-2阶走2步上来。这两条路径分别要花dp[i-1]和dp[i-2]，也就是走到上一个台阶为止已经花掉的钱，走到第i个台阶之后，还要再加上站上第i个台阶本身的花费 `cost[i]`。那我们求的是最小花费，自然就要在这两条可行路径里选花费更小的那一条，所以：

dp[i] = min(dp[i-1], dp[i-2]) + cost[i]

这里的 `min` 体现的是"选择从哪个更便宜的前置台阶跳过来"，加上 `cost[i]` 体现的是"不管从哪跳过来，站上第i阶这个动作本身都得付费"，说白了这部分花费是必须的，没法通过选路径来省掉。这两部分合在一起，才构成到达第i阶的总花费。

**第三步，dp数组怎么初始化**

题目明确说了可以选择从下标0或下标1开始爬楼梯，这意味着这两个位置都是合法的起点。起点本身没有"从更早的台阶跳过来"这个过程，但站上起点这个动作仍然要付费——因为付费的定义是"使用"这个台阶，不管是不是起点。所以：

dp[0] = cost[0]：直接选择从下标0出发，花费就是站上第0阶的代价。
dp[1] = cost[1]：直接选择从下标1出发，花费就是站上第1阶的代价，这里不需要经过下标0，因为题目允许直接从下标1起跳。

**第四步，确定遍历顺序**

因为dp[i]依赖dp[i-1]和dp[i-2]，必须先算出下标更小的值，所以遍历顺序是从小到大，i从2遍历到cost.length - 1。

**第五步，举例推导一下dp数组，验证一下**

拿示例 cost = [10, 15, 20] 来说（数组长度 n = 3）：

```
dp[0] = cost[0] = 10
dp[1] = cost[1] = 15
dp[2] = min(dp[1], dp[0]) + cost[2] = min(15, 10) + 20 = 30
```

这里我得特别说一下最终答案怎么取：楼顶是下标为 `cost.length`（也就是下标3）的位置，这个位置本身不在数组里，不需要额外付费，能到达它的方式只有两种——从下标n-1（也就是下标2）走1步上来，或者从下标n-2（也就是下标1）走2步上来。所以最终答案是：

```
min(dp[n-1], dp[n-2]) = min(dp[2], dp[1]) = min(30, 15) = 15
```

15正好对应题目给出的示例答案，也就是从下标1直接支付15，然后一步跨2个台阶越过下标2，直接到达楼顶，中途完全没有经过下标2，也没有再产生任何花费。这个例子挺能说明问题的：为什么最终答案不是dp[n-1]，而是dp[n-1]和dp[n-2]里的较小值？因为楼顶在数组之外，到达楼顶的"最后一跳"是可以跳过数组最后一个元素的，如果只看dp[n-1]就会漏掉"从倒数第二个台阶直接两步跨到楼顶、从而完全不产生最后一个台阶花费"这种更优的情况。

**复杂度说一下**

- 时间复杂度：O(n)，n为cost数组长度，遍历一次就行。
- 空间复杂度：用完整数组是O(n)；由于dp[i]只依赖前两个状态，可以用两个滚动变量优化到O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int minCostClimbingStairs(vector<int>& cost) {
        int n = cost.size();
        if (n == 1) return cost[0];  // 只有一个台阶，直接站上去即为总花费
        int prev2 = cost[0];  // dp[0]：从下标0出发的花费
        int prev1 = cost[1];  // dp[1]：从下标1出发的花费
        for (int i = 2; i < n; i++) {
            int curr = min(prev1, prev2) + cost[i];  // 核心递推：选更便宜的前置台阶跳过来，再加上站上第i阶自身的花费
            prev2 = prev1;  // 滚动更新 dp[i-2]
            prev1 = curr;   // 滚动更新 dp[i-1]
        }
        return min(prev1, prev2);  // 楼顶在数组之外，取最后两个台阶花费中较小的一个
    }
};
```

### Go

```go
func minCostClimbingStairs(cost []int) int {
    n := len(cost)
    if n == 1 {
        return cost[0] // 只有一个台阶，直接站上去即为总花费
    }
    prev2 := cost[0] // dp[0]：从下标0出发的花费
    prev1 := cost[1] // dp[1]：从下标1出发的花费
    for i := 2; i < n; i++ {
        curr := prev1 // 先假设 dp[i-1] 更小
        if prev2 < prev1 {
            curr = prev2
        }
        curr += cost[i] // 核心递推：选更便宜的前置台阶跳过来，再加上站上第i阶自身的花费
        prev2 = prev1   // 滚动更新 dp[i-2]
        prev1 = curr    // 滚动更新 dp[i-1]
    }
    if prev1 < prev2 { // 楼顶在数组之外，取最后两个台阶花费中较小的一个
        return prev1
    }
    return prev2
}
```

## 总结

- 这道题的关键是把dp[i]的含义定义清楚——"到达下标i需要的最小花费，且这个花费已经包含站上第i阶本身的cost[i]"，你要是定义模糊了，后面的初始化和最终答案都容易搞混。
- 递推公式 dp[i] = min(dp[i-1], dp[i-2]) + cost[i] 里，`min` 部分体现的是"选择更便宜的路径"，`+cost[i]` 部分体现的是"站上当前台阶必须付费"，这两部分分工不一样，缺一不可。
- 初始化 dp[0]=cost[0]、dp[1]=cost[1]，是因为题目允许从下标0或1任意一个位置直接起跳，这两个起点本身不需要经过更早的台阶。
- 最终答案不是dp[n-1]，而是min(dp[n-1], dp[n-2])，为什么呢？因为楼顶在数组下标范围之外，最后一步可以从倒数第二个台阶直接两步跨越到楼顶，所以必须把这种情况也纳入比较。
