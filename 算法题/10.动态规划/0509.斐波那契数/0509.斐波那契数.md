# 0509. 斐波那契数

**题目描述**

斐波那契数列由 0 和 1 开始，之后的每一项都等于前两项之和。也就是说，F(0) = 0，F(1) = 1，当 n > 1 时，F(n) = F(n - 1) + F(n - 2)。给定 n，求 F(n) 的值。

```
示例：
输入: n = 2
输出: 1
解释: F(2) = F(1) + F(0) = 1 + 0 = 1
```

n 的取值范围较小（通常 0 <= n <= 30），不需要考虑大数溢出问题，但这道题的价值不在于结果本身，而在于它是理解动态规划最合适的起点。

## 思路

刚接触动态规划的时候，很容易被"状态转移方程""最优子结构"这些术语给唬住，但斐波那契这道题其实完全不用动脑子想什么业务逻辑——递推关系题目已经直接给你了，就是个数学定义，我们要做的只是把这个定义翻译成代码而已。正因为这样，拿它来完整走一遍"DP五部曲"特别合适，你可以不用分心去想业务逻辑，专心搞懂这五步到底分别在干什么、为什么非要这么做。

**第一步，先确定dp数组（下标）的含义**

我设dp[i]表示斐波那契数列里第i个数的值。这一步看起来简单到好像都不用"确定"，但你别小看它，这恰恰是整个DP方法论里最容易被忽视、但又最重要的一步：你得先想清楚dp[i]到底代表什么，后面写递推公式的时候才知道等号两边、下标之间对不对得上。如果一开始就含糊地说"dp[i]是某种中间结果"，那写出来的递推公式大概率是站不住脚的。

**第二步，确定递推公式**

这题目已经把关系写得很清楚了：dp[i] = dp[i - 1] + dp[i - 2]（i >= 2）。这里唯一要注意的是，这个公式只在i >= 2的时候才成立，为什么呢？因为它依赖dp[i-1]和dp[i-2]必须是真实存在的合法下标，可是i = 0和i = 1这两个位置根本没有更早的项可以依赖，所以这两个必须单独拿出来处理，这就引出了第三步。

**第三步，dp数组怎么初始化**

题目定义直接给了：dp[0] = 0，dp[1] = 1。初始化这一步说白了，就是把"递推公式够不到的地基"先打好——递推公式讲的是"后面的项怎么由前面的项推出来"，但它没法回答"最开始的项从哪来"这个问题，这部分只能靠我们照着题目定义手动给出来，而且必须给对，不然后面推出来的值全都是错的。

**第四步，确定遍历顺序**

因为dp[i]得靠dp[i-1]和dp[i-2]才能算出来，所以必须保证在算dp[i]之前，这两个更小下标的值已经算好了。所以遍历顺序只能是从小到大、从左到右，也就是i从2一直递增到n。你要是反过来从大到小遍历，就会出现"还没算出来的值被拿去用"这种情况，结果肯定是错的。这一步看起来挺显然，但在依赖关系更复杂的DP问题里（比如二维dp、区间dp），遍历顺序对不对往往是最容易翻车的地方，斐波那契数列正好可以用来练"先看依赖关系、再定遍历方向"这个思维习惯。

**第五步，举例推导一下dp数组，验证一下**

拿n = 5举个例子，手动推一遍：

```
dp[0] = 0
dp[1] = 1
dp[2] = dp[1] + dp[0] = 1 + 0 = 1
dp[3] = dp[2] + dp[1] = 1 + 1 = 2
dp[4] = dp[3] + dp[2] = 2 + 1 = 3
dp[5] = dp[4] + dp[3] = 3 + 2 = 5
```

最后dp数组是 `[0, 1, 1, 2, 3, 5]`，dp[5] = 5，跟手算斐波那契数列的结果完全一致，说明前面四步定的递推关系、初始化和遍历顺序都是站得住脚的。这一步的意义在哪呢？就是写代码之前先在纸上把小规模的例子推一遍，这样能在编码之前就把逻辑漏洞揪出来，而不是等程序跑出错误答案了再回头排查。

**空间优化：滚动变量**

如果用一个完整的dp数组把0到n每一项都存下来，空间复杂度是O(n)。但你仔细看一下递推公式就会发现，算dp[i]的时候只用到了dp[i-1]和dp[i-2]这两个最近的值，更早之前的历史值一旦用过就再也不会碰了。既然这样，那就没必要用一个数组把所有历史都存起来，只需要拿两个变量滚动地记录"前一个数"和"前两个数"就行，每算出一个新数之后就把这两个变量往前挪一位。这是动态规划里一个特别常见、也特别重要的优化思路：当状态转移只依赖有限、固定数量的历史状态时，就可以把数组压缩成常数个变量，这样能把空间复杂度从O(n)降到O(1)，时间复杂度不受影响。这个优化点也是斐波那契数列作为入门题的另一层价值——它是学"滚动数组"这个技巧最直观的例子。

**复杂度说一下**

- 时间复杂度：O(n)，需要从2遍历到n，每一步只做一次加法。
- 空间复杂度：使用完整数组是O(n)；使用两个滚动变量优化后是O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int fib(int n) {
        if (n < 2) return n;  // n=0 返回0，n=1 返回1，对应初始化
        int prev2 = 0, prev1 = 1;  // prev2=dp[i-2], prev1=dp[i-1]，滚动变量代替数组
        int curr = 0;
        for (int i = 2; i <= n; i++) {
            curr = prev1 + prev2;  // 核心递推：dp[i] = dp[i-1] + dp[i-2]
            prev2 = prev1;         // 滚动：旧的 dp[i-1] 变成新一轮的 dp[i-2]
            prev1 = curr;          // 滚动：新算出的 dp[i] 变成新一轮的 dp[i-1]
        }
        return curr;
    }
};
```

class Solution:
    def fib(self, n: int) -> int:
        if n < 2:
            return n  # n=0 返回0，n=1 返回1，对应初始化
        prev2, prev1 = 0, 1  # prev2=dp[i-2]，prev1=dp[i-1]

        for i in range(2, n + 1):
            curr = prev1 + prev2  # 核心递推：dp[i] = dp[i-1] + dp[i-2]
            prev2, prev1 = prev1, curr  # 同时滚动更新两个变量，避免中间状态被覆盖
        return curr

## 总结

- 斐波那契数列是练"DP五部曲"最干净的例子，因为递推公式是题目直接给的，不需要你额外分析业务逻辑，可以把全部注意力放在这五个步骤各自的作用上。
- 初始化和遍历顺序看起来简单，但它们分别解决的是"递推公式够不到的边界"和"依赖关系决定的计算方向"这两个问题，这在更复杂的DP里恰恰是最容易翻车的地方。
- 当状态转移只依赖有限几个最近的历史状态时（这题就只依赖前两项），可以拿滚动变量代替完整数组，把空间复杂度从O(n)优化到O(1)。
- 举例手动推导dp数组是验证思路对不对的有效手段，应该在写代码之前就做完，而不是靠运行结果跑出来再反向排查错误。
