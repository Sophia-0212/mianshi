# 20210304动规周末总结

## 思路

这周把股票买卖系列剩下的几道题（188、309）结合前面已经学过的 121、122、123 做了一次串联总结，重点体会一下"状态数"是怎么随着交易规则的复杂度递增的。

**从 121 到 188：状态数的演进主线**

121 题（只能买卖一次）只需要 2 个状态：持有、不持有。122 题（不限次数买卖）状态数也是 2 个，但递推公式里买入的"基准现金"从固定的 0 变成了"昨天不持有状态的现金"，为什么呢？因为可以反复交易，每次买入都要以之前积累的利润为起点，而不是每次都从 0 开始——这里的关键是要看到一个重要规律：**状态数量不变，但递推公式的"基准值"可以携带更多历史信息**，这也是一种扩展方式，不一定非要增加状态维度。

123 题（最多两次交易）把状态数扩展到了 5 个：无操作、第一次持有、第一次卖出、第二次持有、第二次卖出。这是"固定次数"限制下的手写展开，因为 2 次交易只产生固定的 5 种局面，可以逐个枚举写清楚。

188 题把 123 题里的"固定两次"泛化成了"任意 k 次"，状态数变成 `2k+1` 个。由于 `k` 是运行时才知道的变量，不能再手写展开出固定行数的递推式，必须把"对状态编号的枚举"从人工列举升级为一层循环——这是我这周体会最深的一点：**同一个思想（持有/卖出的转移逻辑）在状态数固定和状态数可变这两种场景下，代码结构会发生质变，从"顺序语句"变成"循环语句"**，但背后的转移逻辑本身没有变化。

**309 题：给状态编号嵌入"时序信息"**

309 题（含冷冻期）没有走"增加交易次数"这条路，而是给"不持有"这个状态本身加了个限制——卖出后第二天不能买入。这就促使我们把"不持有"从 1 种状态拆成了 3 种：保持卖出、今日卖出、冷冻期，用状态编号本身记录"距离上次卖出过去了几天"。这跟前面几题"状态数增加是因为交易次数变多"的原因完全不同，是"状态数增加是因为需要记录额外的时序约束"，但两者其实都体现了同一个更本质的方法论：**当你发现线性递推 `dp[i]` 只依赖 `dp[i-1]` 表达不清楚某个约束时，说明当前的状态定义遗漏了某个维度的信息，需要往状态编号里补充这个信息，而不是去修改递推的"依赖跨度"（比如强行让 `dp[i]` 依赖 `dp[i-3]`）**。

**状态机 DP 的通用方法论**

把 121、122、123、188、309（以及后面的 714）放在一起看，可以提炼出一套通用的解题模板：

1. 先想清楚问题里有哪些互斥的"局面"（是否持有股票？买卖了几次？是否处于冷冻期/手续费扣除节点？），每一种互斥的局面对应一个状态编号；
2. 画出这些状态之间的转移关系——哪个状态可以转移到哪个状态，转移时需不需要付出代价（买入花钱、卖出的手续费、冷冻期不能转移等）；
3. 把转移图翻译成递推公式：每个状态的今日值等于"所有能转移到它的来源状态，昨天的值经过对应代价调整后，取最大值"；
4. 如果状态个数依赖一个变量（如 k 次交易），把"枚举状态编号"这一步从手写展开改成循环。

这套方法论不仅适用于股票问题，说白了它本质上是通用的"状态机 DP"解题模板——任何"存在有限种互斥局面，且局面之间有明确转移规则和代价"的问题，都可以先画转移图，再翻译成递推公式，这个顺序（先想清楚状态和转移图，再写代码）远比直接套用某道具体题的公式更重要，因为它能应对任何新增的约束条件。

## 总结

- 股票系列 DP 的状态数演进：121/122（2种）→ 123（5种，固定次数手写展开）→ 188（2k+1种，可变次数需循环枚举）→ 309（4种，因时序约束拆分"不持有"状态）。
- 状态数增加的原因分两类：一类是交易次数变多（123、188），另一类是需要记录额外的时序/限制信息（309的冷冻期），两者都源于"当前状态定义无法表达某个约束"这一根本问题。
- 通用方法论是"先画状态转移图，再翻译成递推公式"：明确互斥局面、画转移关系、标注转移代价，最后才落地成代码，这个顺序对任何状态机 DP 问题都适用，不局限于股票问题。
