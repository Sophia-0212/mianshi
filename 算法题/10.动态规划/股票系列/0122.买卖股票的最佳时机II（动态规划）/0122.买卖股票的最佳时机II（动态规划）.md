# 122. 买卖股票的最佳时机 II（动态规划）

**题目描述**

给定一个数组 `prices`，其中 `prices[i]` 表示某支股票第 `i` 天的价格。可以进行多次买卖，但每次买入前必须先把之前买的卖出（即不能同时持有多份），求能获得的最大利润。

```
示例：
输入: prices = [7,1,5,3,6,4]
输出: 7
解释: 第2天买入(1)，第3天卖出(5)，利润4；第4天买入(3)，第5天卖出(6)，利润3。总利润 = 4 + 3 = 7。
```

这篇我用动态规划（状态机 DP）来讲这道题，跟常见的"利润拆解"贪心解法不一样——贪心是把整体涨幅拆成每天涨跌的和，只累加正数，这个思路更简洁，但只适用于"不限交易次数"这种最宽松的场景；一旦题目加上交易次数限制，比如后面的 123、188 题，贪心的"利润拆解"就不好使了，必须靠状态机 DP。所以我这里重点讲 DP，贪心只做个简单对比。

## 思路

**1. 确定 dp 数组（状态）的含义**

这里的关键是，跟 121 题完全一样，仍然只有两种持股状态：

- `dp[i][0]`：第 `i` 天结束时"持有"股票，此时手上现金的最大值
- `dp[i][1]`：第 `i` 天结束时"不持有"股票，此时手上现金的最大值

你注意，状态定义这里完全没变，这一点其实很重要：说明"能交易几次"这个约束条件，并不需要靠增加状态维度来处理（这点跟后面 123 题不一样，123 题因为限定了"最多两次"，必须把状态从 2 种扩展到 5 种）。122 题里唯一变化的地方，是递推公式中"买入"这一项的写法。

**2. 确定递推公式**

"不持有"状态的递推公式跟 121 题一模一样：

```
dp[i][1] = max(dp[i-1][1], dp[i-1][0] + prices[i])
```

含义没变：延续昨天的不持有状态，或者今天从"持有"状态卖出。这一项在 121、122 两题里没有任何区别，为什么呢？因为"卖出"这个动作本身不受"能交易几次"这个约束的影响。

真正的差异在"持有"状态的递推公式上：

```
dp[i][0] = max(dp[i-1][0], dp[i-1][1] - prices[i])
```

对比一下 121 题的 `dp[i][0] = max(dp[i-1][0], -prices[i])`，你会发现买入这一项从固定值 `-prices[i]` 变成了 `dp[i-1][1] - prices[i]`。

**3. 讲清楚这个差异的本质**

这是本篇最需要讲透的地方。你想啊，121 题只能买卖一次，意味着"买入"这个动作在整个过程里只会发生一次，而且发生的时候，账户里没有任何"之前交易攒下的利润"可用——所以买入后现金永远是"0 减去当前股价"，也就是 `-prices[i]`，这个 0 是一个固定不变的基准点。

而 122 题允许反复买卖，这就意味着"买入"这个动作可能发生很多次，每一次买入，账户里可能已经因为之前几轮"低买高卖"积累了一些利润。今天要买入时，正确的做法不是回到 0 这个基准重新开始，而是站在"昨天不持有股票时的现金" `dp[i-1][1]` 的基础上，再减去今天的股价。说白了就是，买入的"本金"不再是固定的 0，而是一个随着交易进行不断变化、且是当前最优的历史累积利润。

可以这样理解这两个公式的区别：`-prices[i]` 本质上就是 `0 - prices[i]`，这里的 0 是"从未交易过、账户从零开始"的基准；而 `dp[i-1][1] - prices[i]` 里的 `dp[i-1][1]` 则是"经过若干轮交易后，此刻账户里能达到的最大现金"。121 题因为只有一次机会，这个基准永远锁定在 0；122 题因为机会不限，这个基准会随着交易滚动更新，每次买入都是站在"目前为止最优的不持有状态"上出发的。可以说，**"能否多次买卖"决定的就是"买入这个动作的基准现金是固定的 0，还是滚动更新的 dp[i-1][1]"**，这是理解整个股票 DP 系列题目差异的一把钥匙——之后的 123、188 题在处理"第二次买入""第 k 次买入"时，其实也都是复用这个"从上一个不持有状态转移过来"的逻辑，只是不持有状态的下标（对应第几次交易）会变多而已。

**4. 确定初始化**

跟 121 题一样：

- `dp[0][0] = -prices[0]`：第一天买入
- `dp[0][1] = 0`：第一天不买

**5. 确定遍历顺序**

`dp[i]` 只依赖 `dp[i-1]`，那就从前往后遍历，`i` 从 1 到 `n-1`。

**6. 举例推导 dp 数组**

我拿 `prices = [7,1,5,3,6,4]` 这个例子来推一下：

| i | prices[i] | dp[i][0]（持有） | dp[i][1]（不持有） |
|---|---|---|---|
| 0 | 7 | -7 | 0 |
| 1 | 1 | max(-7, 0-1) = -1 | max(0, -7+1) = 0 |
| 2 | 5 | max(-1, 0-5) = -1 | max(0, -1+5) = 4 |
| 3 | 3 | max(-1, 4-3) = 1 | max(4, -1+3) = 4 |
| 4 | 6 | max(1, 4-6) = 1 | max(4, 1+6) = 7 |
| 5 | 4 | max(1, 7-4) = 3 | max(7, 1+4) = 7 |

关键对比第 3 天：`dp[3][0] = max(-1, dp[2][1] - 3) = max(-1, 4-3) = 1`。这里的 `4` 就是第 2 天卖出后攒下的利润，第 3 天再次买入的时候，是站在这个 `4` 的基础上花掉 `3`，得到 `1`，而不是像 121 题那样重新以 `-3` 作为买入后的现金。正是这个"利润滚动"，让 122 题能够捕捉到"低买高卖"发生多次的收益（4 + 3 = 7），而 121 题因为只能交易一次，只能捕捉到全程最大的一次涨幅（1 到 6，利润 5）。最终 `dp[5][1] = 7`，跟题目预期是一致的。

**复杂度分析**

- 时间复杂度：O(n)
- 空间复杂度：O(n)（可用滚动变量优化到 O(1)）

## 代码

### C++

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        if (n == 0) return 0;
        vector<vector<int>> dp(n, vector<int>(2, 0)); // dp[i][0]持有 dp[i][1]不持有
        dp[0][0] = -prices[0]; // 第一天买入
        dp[0][1] = 0;          // 第一天不买
        for (int i = 1; i < n; i++) {
            // 持有：延续昨天 或 用昨天不持有的利润今天买入（可反复买卖）
            dp[i][0] = max(dp[i - 1][0], dp[i - 1][1] - prices[i]);
            // 不持有：延续昨天 或 今天卖出
            dp[i][1] = max(dp[i - 1][1], dp[i - 1][0] + prices[i]);
        }
        return dp[n - 1][1]; // 最后一天不持有即为最大利润
    }
};
```

class Solution {
    public int maxProfit(int[] prices) {
        int n = prices.length;
        if (n == 0) return 0;
        int[][] dp = new int[n][2]; // dp[i][0]持有 dp[i][1]不持有
        dp[0][0] = -prices[0]; // 第一天买入
        dp[0][1] = 0;          // 第一天不买
        for (int i = 1; i < n; i++) {
            // 持有：延续昨天 或 用昨天不持有的累积利润今天再买入
            dp[i][0] = Math.max(dp[i - 1][0], dp[i - 1][1] - prices[i]);
            // 不持有：延续昨天 或 今天卖出
            dp[i][1] = Math.max(dp[i - 1][1], dp[i - 1][0] + prices[i]);
        }
        return dp[n - 1][1];
    }
}

### Python

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        n = len(prices)
        if n == 0:
            return 0
        dp0, dp1 = -prices[0], 0  # dp0持有 dp1不持有，第一天初始化
        for i in range(1, n):
            # 持有：延续昨天 或 用昨天不持有的现金今天买入（可反复交易）
            new_dp0 = max(dp0, dp1 - prices[i])
            # 不持有：延续昨天 或 今天卖出
            new_dp1 = max(dp1, dp0 + prices[i])
            dp0, dp1 = new_dp0, new_dp1  # 滚动更新
        return dp1
```

```go
func maxProfit(prices []int) int {
    n := len(prices)
    if n == 0 {
        return 0
    }
    dp0, dp1 := -prices[0], 0 // dp0持有 dp1不持有，第一天初始化
    for i := 1; i < n; i++ {
        // 持有：延续昨天 或 用昨天不持有的现金今天买入
        newDp0 := max(dp0, dp1-prices[i])
        // 不持有：延续昨天 或 今天卖出
        newDp1 := max(dp1, dp0+prices[i])
        dp0, dp1 = newDp0, newDp1 // 滚动更新
    }
    return dp1
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```

## 总结

- 122 题的状态定义跟 121 题完全一致（持有/不持有两种），差异只体现在"买入"这一项的递推公式上，说明状态维度的设计取决于"是否需要区分更多局面"，而不是取决于交易次数本身。
- 核心区别在这里：121 题买入基准固定为 0（`-prices[i]`），因为只有一次机会；122 题买入基准是滚动的 `dp[i-1][1]`（历史最优不持有现金），因为可以反复交易，每次买入都要站在之前积累的利润上出发。
- "卖出"的递推公式在两题中完全相同，为什么呢？因为卖出动作本身不受交易次数限制的影响，只有"买入的本金来源"会随约束变化。
- 贪心的"利润拆解"解法（只累加每日正涨幅）在本题中跟 DP 结果等价且更简洁，但它依赖"不限次数"这个宽松条件；一旦加上次数限制，贪心思路就失效了，DP 状态机才是唯一能自然扩展的框架。
