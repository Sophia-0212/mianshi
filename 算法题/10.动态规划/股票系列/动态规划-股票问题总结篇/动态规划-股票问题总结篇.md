# 动态规划-股票问题总结篇

股票买卖系列一共六道题：121、122、123、188、309、714，你看着题目描述都很相似（都是"买卖股票求最大利润"），但每一道题在"能否多次买卖""是否限制次数""有没有冷冻期/手续费"这几个维度上组合出了不同的约束，这些约束逐步驱动状态机的设计从最简单的 2 状态演化到最复杂的 2k+1 状态。这篇作为整个系列的收官总结，我先用一张表格完整对比六题的差异，再讲清楚这些约束条件是怎么一步步影响状态机设计的。

## 六题对比表

| 题号 | 能否多次买卖 | 是否限制买卖次数 | 是否有冷冻期 | 是否有手续费 | 状态数 | 核心递推公式差异点 |
|------|------|------|------|------|------|------|
| 121 | 否（只能一次） | 固定1次 | 无 | 无 | 2 | 买入基准固定为 `-prices[i]`（只能买一次，无历史利润可用） |
| 122 | 是（不限次数） | 不限 | 无 | 无 | 2 | 相比121：买入基准从固定0变为 `dp[i-1][1] - prices[i]`（可复用历史利润反复交易） |
| 123 | 是（最多两次） | 固定2次 | 无 | 无 | 5 | 相比122：把"1次交易"手写展开成"2次交易"的5个状态（无操作+2×持有/卖出） |
| 188 | 是（最多k次） | 给定k次 | 无 | 无 | 2k+1 | 相比123：k是变量，把状态枚举从手写5行改成循环遍历`2k`个状态（奇偶位分别对应持有/卖出） |
| 309 | 是（不限次数） | 不限 | 有 | 无 | 4 | 相比122：把"不持有"拆成保持卖出/今日卖出/冷冻期三态，持有的买入来源排除"今日卖出" |
| 714 | 是（不限次数） | 不限 | 无 | 有 | 2 | 相比122：卖出公式多减一项 `-fee`，其余递推结构完全相同 |

## 从约束到状态机设计：一条完整的推导链

**能否多次买卖，决定"买入基准"用固定值还是历史值**

这是六题里最基础的分岔点。你想啊，121 题只能买一次，所以"持有"状态的买入永远以 0 为基准（`-prices[i]`），因为不存在"之前交易攒下的利润"这个概念。122/309/714 都允许多次买卖，买入基准统一换成了"昨天不持有状态的现金"（`dp[i-1][1] - prices[i]` 或其变体），说白了就是让每一次新的买入都能继承之前所有交易积累下来的利润，这是"多次买卖"在公式上的唯一直接体现，而且这一改动不需要增加状态数——**状态数与"能否多次买卖"这一条件本身并不直接绑定，绑定的是买入基准写法**。

**是否限制买卖次数，决定状态数是常数还是随参数变化**

123 题限制最多两次交易，把"第几次交易"也编码进状态编号里，状态数从2变成5（`2×2+1`）。188 题把"两次"泛化成"k次"，状态数变成 `2k+1`，为什么呢？因为 `k` 是运行时输入，代码结构必须从"手写枚举"升级成"循环枚举"。这条主线说明：**当约束涉及"具体的交易次数上限"时，状态数会随次数上限线性增长（`2k+1`），且当次数上限是变量而非常量时，状态枚举的实现方式也要跟着从常量代码变为循环代码**。

**是否有冷冻期，决定"不持有"状态要不要拆分成多个时序子状态**

309 题的冷冻期约束不涉及"交易次数"，而是涉及"卖出后能不能立刻买入"这个时序限制。由于线性 DP 的 `dp[i]` 只能看到 `dp[i-1]`，没法直接"回看两天前"，所以需要把"距离上次卖出过去了几天"这个信息编码进状态编号本身——于是"不持有"从1种拆成3种（保持卖出、今日卖出、冷冻期）。这条主线说明：**当约束是"某个动作后的若干天内不能做另一个动作"时，应该往状态里拆出"计时器"维度，而不是试图让递推公式依赖更早的历史下标**，而且冷冻期天数越长，需要拆分的状态就越多（一天冷冻期需要拆3态，如果是两天冷冻期则还需要再拆一态）。

**是否有手续费，只改变某一步的代价，不改变状态数**

714 题的手续费约束和冷冻期完全不同——它不影响"下一步能做什么"，只是给"完成一次交易"这个动作增加了一个固定成本。因为这个成本只在"一次完整交易"发生时结算一次，所以只需要在买入或卖出中任选一处的公式里减去 `fee` 就行，状态数完全不变（还是2个）。这条主线说明：**约束如果只影响转移的"代价大小"而不影响"能不能转移""转移目标是什么"，就不需要增加状态维度，只需要修改对应转移公式里的常数项**。

## 建立判断力：新约束该加状态还是改系数

综合六道题，我可以总结出一个判断框架，用来应对新出现的约束条件：

- 先问：这个约束会不会改变"我现在能不能做某个动作"（比如能不能买入、能不能卖出）？如果是，且这个限制取决于"最近几步做过什么"，那就需要拆分状态、给状态编号加入时序信息（对应309的冷冻期）。
- 再问：这个约束是不是与"总共能交易几次"有关？如果是，状态数需要随这个次数上限增长，且如果次数上限是变量，枚举方式要用循环而不是手写（对应123、188）。
- 最后问：这个约束是不是只增加了某个动作的"固定代价"，不影响动作本身能不能发生？如果是，只需要在对应的递推公式里加减一个常数项，状态数不变（对应714）。
- 如果约束只是"允许重复做某个动作"（比如从"只能一次"变成"不限次数"），通常只需要把"买入基准"从固定值改成"复用上一次不持有状态的现金"，状态数也不变（对应121到122的升级）。

这套框架的核心价值在于：遇到一道新的股票类变体题（甚至任何状态机 DP 问题），你不需要从零开始设计状态，而是先定位新增的约束条件属于上述哪一类，就能快速判断应该"加状态维度""改递推系数"还是"两者都不用改，只调整基准值"，这比死记硬背六道题各自的公式更有迁移价值。

## 总结

- 六道题共享同一套"持有/不持有"状态机骨架，差异全部来自"能否多次买卖""是否限次数""有无冷冻期""有无手续费"这四个维度的组合，理解了这四个维度各自怎么影响状态设计，就能推导出任意组合下的解法，而不需要死记六个独立公式。
- 状态数的变化不是随意的：交易次数限制驱动状态数按 `2k+1` 增长且需要循环枚举，时序类约束（冷冻期）驱动状态被拆分出计时器维度，而单纯的代价类约束（手续费）和"能否重复交易"类约束都不需要增加状态数，只需要修改公式里的基准值或常数项。
- 判断新约束该如何影响状态设计的关键问题是："这个约束改变的是能不能转移，还是转移的代价大小，还是需要额外的历史信息才能判断能不能转移"——这三种情况分别对应"拆分状态""改常数项""拆分状态并引入计时器"三种不同的应对方式。
- 这套从约束到状态机设计的推导方法，不仅是股票系列的收官总结，更是通用状态机 DP 的方法论模板：先枚举约束维度，再逐一判断每个维度该如何影响状态设计，最后才落地成具体的递推公式，这个顺序应当成为解决任何新变体题目的默认思考路径。
