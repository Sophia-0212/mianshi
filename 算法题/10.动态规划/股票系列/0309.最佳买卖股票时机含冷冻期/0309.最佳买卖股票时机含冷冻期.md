# 309. 最佳买卖股票时机含冷冻期

**题目描述**

给定一个数组 `prices`，其中 `prices[i]` 表示某支股票第 `i` 天的价格。可以完成任意多次买入和卖出（不限次数，但同一时刻最多持有一股，必须先卖出才能再买入），唯一的额外限制是：卖出股票后，第二天处于"冷冻期"，冷冻期这一天不能买入股票（可以正常进入下一个冷冻期之后的交易）。求能获得的最大利润。

```
示例：
输入: prices = [1,2,3,0,2]
输出: 3
解释: 对应的一种交易方案为：第 1 天买入(price=1)，第 2 天卖出(price=2)，
     第 3 天冷冻期不能买入，第 4 天买入(price=0)，第 5 天卖出(price=2)，
     利润 = (2-1) + (2-0) = 3。
```

## 思路

**1. 确定 dp 数组（状态）的含义**

你想啊，这道题是 122 题（不限次数买卖）的延伸。122 题只需要"持有/不持有"两种状态就够了，但本题多了"卖出后第二天不能买入"这一条时序约束，如果继续只用两种状态，递推公式没法表达出"今天能不能买入"要看"昨天是不是刚卖出"这个信息，所以这里的关键是，必须把"不持有"这一种状态进一步拆细。

拆分的思路是这样的：一个"不持有股票"的状态，光知道"不持有"是不够的，还得知道"我是不是处于冷冻限制中"，以及"我今天是不是刚完成卖出（导致明天要进入冷冻期）"。按这个思路可以拆出 4 种状态：

- `dp[i][0]`：第 `i` 天结束时，处于"持有股票"的状态
- `dp[i][1]`：第 `i` 天结束时，处于"不持有股票，且保持卖出后的状态（不是今天卖出的，也不是冷冻期，可以随时买入）"
- `dp[i][2]`：第 `i` 天结束时，处于"不持有股票，且是今天卖出的"
- `dp[i][3]`：第 `i` 天结束时，处于"不持有股票，且处于冷冻期（即昨天卖出，今天作为冷冻期不能买入）"

这 4 种状态的每一种，各自代表的手上现金最大值。为什么要把"不持有"拆成 1、2、3 三种而不是两种或者合并处理呢？因为这三者在"今天能不能买入"这一点上是不同的：状态1可以买入，状态2（今天刚卖出）第二天要进冷冻期不能买入，状态3（今天正处于冷冻期）今天不能买入但明天可以。这三种"时序位置"必须分开记录，不然递推公式没有办法区分。

**2. 确定递推公式**

我逐条来看这4个状态今天分别可能从昨天的哪些状态转移过来。

- `dp[i][0]`（今天持有）：

```
dp[i][0] = max(dp[i-1][0], dp[i-1][1] - prices[i], dp[i-1][3] - prices[i])
```

今天持有股票，只可能来自两类操作：昨天已经持有，今天不动，延续 `dp[i-1][0]`；或者今天买入。买入操作要求"昨天不处于冷冻期限制中"，也就是昨天必须是"保持卖出状态"（状态1）或者"冷冻期结束"（状态3，因为状态3表示今天是冷冻期，但递推里 `dp[i-1][3]` 表示昨天是冷冻期，那么今天冷冻期已经结束，可以买入）。这里最容易出错的地方是：**不能从 `dp[i-1][2]`（昨天刚卖出）直接买入**，为什么呢？因为如果昨天卖出，那么"今天"恰好就是冷冻期，规则规定冷冻期这一天不能买入，所以状态2不能作为买入的来源，只有状态1和状态3可以。

- `dp[i][1]`（今天保持卖出状态）：

```
dp[i][1] = max(dp[i-1][1], dp[i-1][3])
```

"保持卖出状态"是指"手上没股票，且已经过了冷冻期限制，随时可以买入"。这个状态今天成立，只能来自：昨天就已经是这个状态（继续保持不动）；或者昨天是冷冻期（状态3），冷冻期只持续一天，今天冷冻期结束，自然转入"可以自由买入"的状态1。

- `dp[i][2]`（今天卖出）：

```
dp[i][2] = dp[i-1][0] + prices[i]
```

今天卖出的前提是昨天必须持有股票，卖出后现金增加 `prices[i]`。这个状态没有"取 max"的必要，为什么呢？因为"今天卖出"这个动作只有一种来源——昨天持有，今天卖出，不存在"延续"的说法（"今天卖出"这个状态定义本身就要求动作发生在今天，不可能是延续昨天的同一状态）。

- `dp[i][3]`（今天冷冻期）：

```
dp[i][3] = dp[i-1][2]
```

今天处于冷冻期，唯一的原因是昨天卖出了股票（状态2），冷冻期紧跟在卖出后的第二天自动发生，不需要额外决策，也不需要取 max。

这套递推公式里，最核心也最容易出错的一环是状态2和状态3为什么必须拆开、不能合并成一个"不持有且受限"的状态。原因在于：状态2（今天卖出）和状态3（今天冷冻期）在"下一天能否买入"这件事上表现完全不同——如果把两者合并成一个状态 X，那么递推到第二天时，没法区分"X 是因为昨天刚卖出（所以今天是冷冻期，不能买入）"还是"X 已经是冷冻期结束后的状态（今天可以买入）"，这两种情况必须分开记录，才能让第二天的买入判断（`dp[i][0]` 的转移来源）正确排除"昨天刚卖出"这一种情况。换句话说，状态2和状态3的拆分本质上是在给"不持有"这个大状态里再嵌入一个"距离上次卖出过去了几天"的计时器，只是这里冷冻期只有一天，所以只需要多拆一个状态就能表达"计时器归零前"和"计时器归零后"两种情形，如果冷冻期是两天，则还需要再拆出一个状态。

**3. 确定初始化**

第 0 天：

- `dp[0][0] = -prices[0]`：第一天买入，花掉本金
- `dp[0][1] = 0`：第一天不操作，保持"可以买入"的状态，现金为 0
- `dp[0][2] = 0`：第一天不可能"卖出"（还没有持有过股票），初始化为 0（不参与实际有效转移，只是占位，保证不会因为初始化成负值污染后续 max 计算）
- `dp[0][3] = 0`：第一天不可能处于冷冻期（冷冻期至少要发生一次卖出之后），同样初始化为 0 占位

**4. 确定遍历顺序**

从前往后遍历，`i` 从 1 到 `n-1`，因为 `dp[i]` 的四个分量都只依赖 `dp[i-1]` 的分量，不存在同一天内的先后依赖。

**5. 举例推导 dp 数组**

我拿 `prices = [1,2,3,0,2]` 这个例子来推一下：

| i | prices[i] | dp[i][0]持有 | dp[i][1]保持卖出 | dp[i][2]今日卖出 | dp[i][3]冷冻期 |
|---|---|---|---|---|---|
| 0 | 1 | -1 | 0 | 0 | 0 |
| 1 | 2 | max(-1,0-2,0-2)=-1 | max(0,0)=0 | -1+2=1 | 0 |
| 2 | 3 | max(-1,0-3,0-3)=-1 | max(0,0)=0 | -1+3=2 | 1 |
| 3 | 0 | max(-1,0-0,1-0)=1 | max(0,1)=1 | -1+0=-1 | 2 |
| 4 | 2 | max(1,1-2,2-2)=1 | max(1,2)=2 | 1+2=3 | -1 |

最终答案取最后一天所有"不持有"状态中的最大值：`max(dp[4][1], dp[4][2], dp[4][3]) = max(2, 3, -1) = 3`，跟预期输出一致，对应交易方案：第1天买入(1)、第2天卖出(2)，第4天买入(0)、第5天卖出(2)，利润 `(2-1)+(2-0)=3`。

你观察表格里第 3 行（i=3）会看到 `dp[3][0]=1` 恰好来自 `dp[2][3]-prices[3]=1-0=1`——这一步印证了"从冷冻期结束状态买入"是允许的；而 `dp[4][3]=-1` 来自 `dp[3][2]=-1`，说明第5天本应处于冷冻期（因为第4天没有卖出，`dp[3][2]=-1` 是一个不划算的历史值，不会被最终答案选中），这个分支最终没有贡献最优解，但递推过程依然要把它算出来，因为不能提前判断哪个分支最终会被淘汰。

**复杂度分析**

- 时间复杂度：O(n)，遍历一次数组，每天做常数次比较
- 空间复杂度：O(n)（用滚动变量可以优化到 O(1)，因为每天只依赖前一天的 4 个值）

## 代码

### C++

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        if (n == 0) return 0;
        // dp[i][0]持有 dp[i][1]保持卖出 dp[i][2]今日卖出 dp[i][3]冷冻期
        vector<vector<int>> dp(n, vector<int>(4, 0));
        dp[0][0] = -prices[0]; // 第一天买入
        dp[0][1] = 0;          // 第一天不操作，保持可买入状态
        dp[0][2] = 0;          // 第一天不可能卖出，占位
        dp[0][3] = 0;          // 第一天不可能冷冻期，占位
        for (int i = 1; i < n; i++) {
            // 持有：延续昨天持有，或从"保持卖出"/"冷冻期结束"买入（不能从"今日卖出"直接买）
            dp[i][0] = max(dp[i - 1][0], max(dp[i - 1][1] - prices[i], dp[i - 1][3] - prices[i]));
            // 保持卖出：延续昨天保持卖出，或昨天冷冻期结束转入
            dp[i][1] = max(dp[i - 1][1], dp[i - 1][3]);
            // 今日卖出：唯一来源是昨天持有，今天卖出
            dp[i][2] = dp[i - 1][0] + prices[i];
            // 冷冻期：唯一来源是昨天刚卖出
            dp[i][3] = dp[i - 1][2];
        }
        // 最终答案在所有"不持有"状态里取最大值（持有状态不可能是全局最优）
        return max({dp[n - 1][1], dp[n - 1][2], dp[n - 1][3]});
    }
};
```

```java
class Solution {
    public int maxProfit(int[] prices) {
        int n = prices.length;
        if (n == 0) return 0;
        // dp[i][0]持有 dp[i][1]保持卖出 dp[i][2]今日卖出 dp[i][3]冷冻期
        int[][] dp = new int[n][4];
        dp[0][0] = -prices[0]; // 第一天买入
        dp[0][1] = 0;          // 保持可买入状态
        dp[0][2] = 0;          // 占位：第一天不可能卖出
        dp[0][3] = 0;          // 占位：第一天不可能冷冻期
        for (int i = 1; i < n; i++) {
            // 持有：延续昨天 或 从"保持卖出"/"冷冻期结束"买入
            dp[i][0] = Math.max(dp[i - 1][0], Math.max(dp[i - 1][1] - prices[i], dp[i - 1][3] - prices[i]));
            // 保持卖出：延续昨天 或 冷冻期结束转入
            dp[i][1] = Math.max(dp[i - 1][1], dp[i - 1][3]);
            // 今日卖出：只能来自昨天持有
            dp[i][2] = dp[i - 1][0] + prices[i];
            // 冷冻期：只能来自昨天刚卖出
            dp[i][3] = dp[i - 1][2];
        }
        return Math.max(dp[n - 1][1], Math.max(dp[n - 1][2], dp[n - 1][3])); // 不持有状态中取最大
    }
}
```

### Python

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        n = len(prices)
        if n == 0:
            return 0
        # dp0持有 dp1保持卖出 dp2今日卖出 dp3冷冻期
        dp0, dp1, dp2, dp3 = -prices[0], 0, 0, 0  # 第一天初始化
        for i in range(1, n):
            # 持有：延续昨天 或 从"保持卖出"/"冷冻期结束"买入（不能从"今日卖出"直接买）
            new_dp0 = max(dp0, dp1 - prices[i], dp3 - prices[i])
            # 保持卖出：延续昨天 或 冷冻期结束转入
            new_dp1 = max(dp1, dp3)
            # 今日卖出：只能来自昨天持有
            new_dp2 = dp0 + prices[i]
            # 冷冻期：只能来自昨天刚卖出
            new_dp3 = dp2
            dp0, dp1, dp2, dp3 = new_dp0, new_dp1, new_dp2, new_dp3  # 同步滚动更新
        return max(dp1, dp2, dp3)  # 不持有状态中取最大
```

```go
func maxProfit(prices []int) int {
    n := len(prices)
    if n == 0 {
        return 0
    }
    // dp0持有 dp1保持卖出 dp2今日卖出 dp3冷冻期
    dp0, dp1, dp2, dp3 := -prices[0], 0, 0, 0 // 第一天初始化
    for i := 1; i < n; i++ {
        // 持有：延续昨天 或 从"保持卖出"/"冷冻期结束"买入
        newDp0 := max(dp0, max(dp1-prices[i], dp3-prices[i]))
        // 保持卖出：延续昨天 或 冷冻期结束转入
        newDp1 := max(dp1, dp3)
        // 今日卖出：只能来自昨天持有
        newDp2 := dp0 + prices[i]
        // 冷冻期：只能来自昨天刚卖出
        newDp3 := dp2
        dp0, dp1, dp2, dp3 = newDp0, newDp1, newDp2, newDp3 // 同步滚动更新
    }
    return max(dp1, max(dp2, dp3)) // 不持有状态中取最大
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```

## 总结

- 冷冻期约束的核心处理方式是把 122 题的"不持有"状态拆成三种更细的时序状态：保持卖出、今日卖出、冷冻期，用状态编号本身携带"距离上次卖出过去了几天"的信息，弥补线性 DP 无法直接"回看更早历史"的局限。
- 最容易出错的一步是"持有"状态的买入来源：只能从"保持卖出"或"冷冻期结束"转移，绝不能从"今日卖出"直接买入，因为那等价于跳过了冷冻期这一天的限制。
- 状态2（今日卖出）和状态3（冷冻期）不能合并，因为它们对"明天能否买入"的影响不同：合并后递推公式无法区分这两种历史，会导致允许在冷冻期当天买入的错误结果。
- 这套"给状态拆出时序信息"的技巧具有通用性：只要约束是"某个动作后的第几天不能做另一个动作"，都可以通过拆分状态编号、让状态本身携带"计时器"信息来解决，冷冻期天数越长，需要拆分的状态就越多。
