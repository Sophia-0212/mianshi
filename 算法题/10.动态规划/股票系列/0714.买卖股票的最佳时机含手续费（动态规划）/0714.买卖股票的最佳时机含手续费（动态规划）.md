# 714. 买卖股票的最佳时机含手续费（动态规划）

**题目描述**

给定一个数组 `prices`，其中 `prices[i]` 表示某支股票第 `i` 天的价格，再给定一个整数 `fee` 代表交易手续费。可以完成任意多次买入和卖出（不限次数），但每完成一次交易（一次买入加一次对应的卖出算一次交易）都需要支付手续费 `fee`。求能获得的最大利润。

```
示例：
输入: prices = [1,3,2,8,4,9], fee = 2
输出: 8
解释: 能够达到的最大利润为 8，对应的交易方案为：
     第 1 天买入(price=1)，第 4 天卖出(price=8)，扣除手续费2，利润 = 8-1-2 = 5；
     第 5 天买入(price=4)，第 6 天卖出(price=9)，扣除手续费2，利润 = 9-4-2 = 3；
     总利润 5+3 = 8。
```

## 思路

这里的关键是，本题的状态定义跟 122 题（不限次数买卖，不含手续费）几乎完全一样，仍然只需要"持有/不持有"两种状态：

- `dp[i][0]`：第 `i` 天结束时处于"持有股票"状态的最大现金
- `dp[i][1]`：第 `i` 天结束时处于"不持有股票"状态的最大现金

递推公式里，"持有"这一条跟 122 题完全一样：

```
dp[i][0] = max(dp[i-1][0], dp[i-1][1] - prices[i])
```

今天持有，来自昨天已持有（延续），或者昨天不持有、今天买入（基准现金是昨天"不持有"的现金，因为可以反复交易，每次买入都要接续之前积累的利润，而不是像 121 题那样固定用 0 做基准）。

唯一的区别出现在"卖出"这一步。你想啊，122 题卖出时现金直接增加 `prices[i]`；本题因为每次交易要扣手续费，卖出时要多减去一个 `fee`：

```
dp[i][1] = max(dp[i-1][1], dp[i-1][0] + prices[i] - fee)
```

今天不持有，来自昨天已不持有（延续），或者昨天持有、今天卖出——卖出获得 `prices[i]`，但这笔交易要扣掉手续费 `fee`，所以净收入是 `prices[i] - fee`。

**为什么手续费只需要在卖出这一步扣一次，不会漏算也不会多算**

题目里"一次交易"的定义是"一次买入 + 一次卖出"合起来算一次，手续费是针对这个完整的买卖过程收取的，不是分别对买入和卖出各收一次。所以说白了就是，只要在"买入"和"卖出"这两个动作里选一个地方统一扣费，就能保证每完成一次交易恰好扣一次费，不会重复扣，也不会漏扣。

具体选在哪一步扣其实无关紧要（选买入那一步扣也完全等价，只要全局统一），这里我选择在卖出时扣除，是因为这样更符合直觉——"卖出变现的时候，交易所才真正把这笔交易的手续费划走"，把手续费和"利润结算"的动作绑在一起，读代码时更容易对应到"这笔交易最终净赚了多少"这个语义上。如果选择在买入时扣（即 `dp[i][0] = max(dp[i-1][0], dp[i-1][1] - prices[i] - fee)`，卖出维持 `dp[i-1][0] + prices[i]`），结果是完全一样的，为什么呢？因为无论扣费动作放在买入还是卖出，一次完整交易（一买一卖）从始至终只经历一次"买入状态转移"和一次"卖出状态转移"，只要保证这两步中恰好有一步减了 `fee`，总账就是对的——这也说明本题的手续费本质上是"每次交易固定成本"，而不是"每次操作的成本"，两者的区别决定了扣费只应该出现一次，而不是在买入和卖出两处各扣一次（那样会导致每次交易被扣两次手续费，答案偏小）。

**初始化**

第 0 天：

- `dp[0][0] = -prices[0]`：第一天买入，花掉本金
- `dp[0][1] = 0`：第一天不买，现金为 0（第一天不可能完成一次交易，因此也不涉及扣手续费）

**遍历顺序**

从前往后遍历，`i` 从 1 到 `n-1`，因为 `dp[i]` 只依赖 `dp[i-1]`。

**举例推导**

我拿 `prices = [1,3,2,8,4,9], fee = 2` 这个例子来推一下：

| i | prices[i] | dp[i][0]持有 | dp[i][1]不持有 |
|---|---|---|---|
| 0 | 1 | -1 | 0 |
| 1 | 3 | max(-1,0-3)=-1 | max(0,-1+3-2)=0 |
| 2 | 2 | max(-1,0-2)=-1 | max(0,-1+2-2)=0 |
| 3 | 8 | max(-1,0-8)=-1 | max(0,-1+8-2)=5 |
| 4 | 4 | max(-1,5-4)=1 | max(5,-1+4-2)=5 |
| 5 | 9 | max(1,5-9)=1 | max(5,1+9-2)=8 |

最终 `dp[5][1] = 8`，跟预期输出一致。对比不含手续费的 122 题算法，你会发现如果本例不扣手续费，最优策略可能会拆成更多次小额交易（比如低点买高点卖的每一次波动都单独交易），但手续费的存在会"惯性地"抑制过于频繁的小额交易——为什么呢？因为每多做一次交易就要多扣一次固定成本，如果两次波动之间的价差不足以覆盖手续费，DP 会自动通过 `max` 比较选择"不卖"（延续持有）而不是"卖了再买"，这正是递推公式里 `max(dp[i-1][1], ...)` 这一项在起作用：它允许状态"什么都不做"，从而避免了不划算的频繁交易。

**复杂度分析**

- 时间复杂度：O(n)，遍历一次数组
- 空间复杂度：O(n)（用滚动变量可优化到 O(1)）

## 代码

### C++

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices, int fee) {
        int n = prices.size();
        if (n == 0) return 0;
        vector<vector<int>> dp(n, vector<int>(2, 0)); // dp[i][0]持有 dp[i][1]不持有
        dp[0][0] = -prices[0]; // 第一天买入
        dp[0][1] = 0;          // 第一天不买
        for (int i = 1; i < n; i++) {
            // 持有：延续昨天 或 以昨天"不持有"现金为基准买入（可反复交易）
            dp[i][0] = max(dp[i - 1][0], dp[i - 1][1] - prices[i]);
            // 不持有：延续昨天 或 今天卖出并扣除手续费fee（只在此处扣一次，覆盖一次完整交易）
            dp[i][1] = max(dp[i - 1][1], dp[i - 1][0] + prices[i] - fee);
        }
        return dp[n - 1][1]; // 最终不持有状态即为最大利润
    }
};
```

### Java

```java
class Solution {
    public int maxProfit(int[] prices, int fee) {
        int n = prices.length;
        if (n == 0) return 0;
        int[][] dp = new int[n][2]; // dp[i][0]持有 dp[i][1]不持有
        dp[0][0] = -prices[0]; // 第一天买入
        dp[0][1] = 0;          // 第一天不买
        for (int i = 1; i < n; i++) {
            // 持有：延续昨天 或 以昨天不持有现金为基准买入
            dp[i][0] = Math.max(dp[i - 1][0], dp[i - 1][1] - prices[i]);
            // 不持有：延续昨天 或 今天卖出并扣手续费（一次交易只扣一次）
            dp[i][1] = Math.max(dp[i - 1][1], dp[i - 1][0] + prices[i] - fee);
        }
        return dp[n - 1][1]; // 最大利润
    }
}
```

### Python

```python
class Solution:
    def maxProfit(self, prices: list[int], fee: int) -> int:
        n = len(prices)
        if n == 0:
            return 0
        dp0, dp1 = -prices[0], 0  # dp0持有 dp1不持有，第一天初始化
        for i in range(1, n):
            # 持有：延续昨天 或 以昨天不持有现金为基准买入
            new_dp0 = max(dp0, dp1 - prices[i])
            # 不持有：延续昨天 或 今天卖出并扣手续费fee（一次交易只扣一次）
            new_dp1 = max(dp1, dp0 + prices[i] - fee)
            dp0, dp1 = new_dp0, new_dp1  # 滚动更新
        return dp1  # 最大利润
```

### Go

```go
func maxProfit(prices []int, fee int) int {
    n := len(prices)
    if n == 0 {
        return 0
    }
    dp0, dp1 := -prices[0], 0 // dp0持有 dp1不持有
    for i := 1; i < n; i++ {
        // 持有：延续昨天 或 以昨天不持有现金为基准买入
        newDp0 := max(dp0, dp1-prices[i])
        // 不持有：延续昨天 或 今天卖出并扣手续费fee
        newDp1 := max(dp1, dp0+prices[i]-fee)
        dp0, dp1 = newDp0, newDp1 // 滚动更新
    }
    return dp1 // 最大利润
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```

## 总结

- 本题的状态定义跟 122 题完全一致（持有/不持有两种状态），是 122 题最直接的变体，唯一改动集中在"卖出"这一条递推公式，需要多减去手续费 `fee`。
- 手续费本质上是"每次完整交易的固定成本"，只需要在买入或卖出中任选一处统一扣除就能覆盖每次交易，选在卖出时扣更符合"变现时结算成本"的直觉，但选在买入时扣效果完全等价。
- 引入手续费后，DP 会通过 `max(延续, 交易)` 这一比较结构自动抑制"价差不够覆盖手续费"的频繁小额交易，不需要额外写规则去限制交易频率，这是状态机 DP 递推公式本身自带的正确性。
- 判断一道股票题属于哪种子类型的关键，是看它在 121/122 这套基础状态机上具体改动了哪一步：122 改的是买入基准（从固定0变为可反复利用的历史现金），714 改的是卖出的净收入公式（多减一项常数），两者改动的位置不同、意图也不同，识别这个"改动点"是快速定位题目本质的捷径。
