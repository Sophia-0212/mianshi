# 背包问题理论基础 多重背包

这一篇不讲具体的例题，而是讲背包问题家族里的第三种基础模型——**多重背包**。前面接触过 01 背包（每种物品最多选一次）和完全背包（每种物品可以选无限次），你想啊，多重背包正好是介于这两者之间的一种模型。

## 多重背包的模型

在 01 背包中，每种物品只有两种选择：选或者不选，也就是选 0 次或 1 次。在完全背包中，每种物品的可选次数没有上限，只要背包容量允许，可以一直重复选下去。而在**多重背包**中，每一种物品都有一个**限定的可选数量上限**——比如物品 `i` 的重量是 `weight[i]`、价值是 `value[i]`，但它最多只能被选 `count[i]` 次，这个 `count[i]` 既不是固定的 1，也不是无限，而是题目给定的一个具体的有限次数。

换句话说，你可以这么理解：01 背包可以看成是多重背包在"每种物品数量上限都是 1"时的特殊情况；完全背包可以看成是多重背包在"每种物品数量上限是无穷大"时的特殊情况。多重背包才是这三者中最"通用"的模型，01 背包和完全背包都是它的两个极端场景。

多重背包要解决的问题和 01 背包类似：在背包容量的限制下，从这些"数量有限"的物品里做选择，使得选出的物品总重量不超过背包容量，同时让选出物品的总价值最大。

## 转化思路：把多重背包转化为 01 背包

多重背包最基础、最直观的处理方式，是**把它直接转化成 01 背包**来解决，不需要发明一套全新的算法。

转化的核心思路是"展开"：对于每一种"数量有限"的物品，按照它的数量上限，把它展开成多个**独立的**01 背包物品。

具体来说，如果物品 `i` 的重量是 `weight[i]`、价值是 `value[i]`，最多能选 `count[i]` 次，那么可以把它拆分成 `count[i]` 个"重量都是 `weight[i]`、价值都是 `value[i]`"的独立物品。这些独立物品在 01 背包模型下，每一个都只能选 0 次或 1 次。而"从这 `count[i]` 个独立物品里选出 `k` 个（`k` 从 0 到 `count[i]`）"这件事，其效果完全等价于原来"这一种物品选 `k` 次"的效果——为什么呢？因为不管选的是哪 `k` 个"复制品"，它们的重量和价值都完全相同，选出 `k` 个带来的总重量增加、总价值增加，和原来"这种物品选 `k` 次"是完全一样的。

把所有种类的物品都按照各自的 `count[i]` 展开之后，就得到了一个物品数量更多（每种原始物品变成了 `count[i]` 个独立物品，物品总数是所有 `count[i]` 的和），但结构上纯粹是 01 背包的新问题。这个新问题可以直接套用 01 背包最标准的解法：一维 `dp` 数组，容量维度**倒序**遍历（这是 01 背包区别于完全背包的关键写法，倒序遍历保证每个物品在本轮循环中只会被计入一次，避免被错误地重复选取）。

用一个简单的例子说明"展开"的过程：假设有一种物品，`weight = 2`，`value = 3`，`count = 3`（最多能选 3 次）。展开之后，就变成了 3 个独立的物品：`weight = [2, 2, 2]`，`value = [3, 3, 3]`。这 3 个物品互相独立，每个只能选 0 次或 1 次。接下来直接调用标准的 01 背包模板来求解这个展开后的问题即可。

```python
def multi_pack_via_01(weights, values, counts, capacity):
    # 第一步：展开——把每种"数量有限"的物品，按 count 展开成多个独立的 01 背包物品
    expanded_weights = []
    expanded_values = []
    for w, v, c in zip(weights, values, counts):
        for _ in range(c):          # 按数量上限 c，展开成 c 个重量、价值都相同的独立物品
            expanded_weights.append(w)
            expanded_values.append(v)

    # 第二步：01 背包求解——对展开后的物品列表，套用标准 01 背包模板
    dp = [0] * (capacity + 1)       # dp[j]：容量为 j 时能装下的最大价值
    for i in range(len(expanded_weights)):        # 外层遍历每一个展开后的独立物品
        for j in range(capacity, expanded_weights[i] - 1, -1):  # 内层倒序遍历容量（01 背包标准写法）
            dp[j] = max(dp[j], dp[j - expanded_weights[i]] + expanded_values[i])  # 选或不选这个物品，取较大价值
    return dp[capacity]
```

上面这段代码分成两个明确的阶段：第一段循环在做"展开"，把"一种物品选多次"的问题，转化成"多个独立物品各选一次"的问题，这一步不涉及任何动态规划，只是数据结构上的预处理；第二段循环才是真正的 01 背包求解过程，容量倒序遍历、`max` 取较大价值，和标准 01 背包模板完全一致，因为经过第一步展开之后，问题在结构上已经**变成**了一个纯粹的 01 背包问题，不再需要考虑"物品被重复选取"这件事。

## 关于效率的补充说明

按数量上限直接展开物品，思路上是很直观的，但你想，如果某种物品的 `count[i]` 很大（比如成千上万），展开后的物品总数会变得很大，进而拖慢求解速度，因为 01 背包求解的时间复杂度和物品总数成正比。

对于这种场景，多重背包还有一种更高效的处理方式，叫做**二进制拆分优化**：把每种物品的数量上限 `count[i]` 不按"1, 1, 1, ..., 1"这样展开成 `count[i]` 份，而是按二进制位的方式拆分成 `1, 2, 4, 8, ...` 这样数量级递增的若干份（外加一份用来补足剩余数量），这样只需要 `O(log(count[i]))` 个"打包物品"就能表示出"选 0 到 `count[i]` 之间任意数量"的所有可能组合，而不需要展开成 `count[i]` 个独立物品。这种方式能把处理每种物品的复杂度从 `O(count[i])` 降低到 `O(log(count[i]))`，在物品数量上限很大的场景下效果明显。

这里只是先点一下这个优化方向的存在，不展开完整的推导过程——这一篇的重点是把"多重背包转化为 01 背包"这个最基础、最直观的思路讲清楚，这是理解多重背包的第一步，也是后续理解二进制拆分优化的必要前提（二进制拆分本质上也是一种"展开成独立 01 背包物品"的思路，只是展开的方式更巧妙）。

## 总结

多重背包是介于 01 背包（每种物品选 0 或 1 次）和完全背包（每种物品选无限次）之间的模型，每种物品有一个限定的可选数量上限。理解多重背包最直接的方式，是把它转化为一个纯粹的 01 背包问题：按照每种物品的数量上限，把它展开成对应数量的独立物品，之后直接套用 01 背包的标准解法（一维数组、容量倒序遍历）即可。这种"展开"思路是理解多重背包，以及后续学习更高效的二进制拆分优化的基础。
