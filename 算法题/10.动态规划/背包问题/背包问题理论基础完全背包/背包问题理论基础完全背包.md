# 背包问题理论基础 完全背包

## 完全背包与01背包的模型区别

01背包的约束是"每个物品最多选一次"（选0次或1次）。完全背包放宽了这个约束：**每一种物品可以被选择无限次**，只要背包剩余容量足够，同一个物品可以反复放入。生活中的类比是硬币兑换——同一枚面额的硬币可以用任意多次，这与"每件商品只有一份"的01背包场景完全不同。

这个看似很小的差异，会直接影响递推公式的写法和一维数组的遍历顺序，是完全背包区别于01背包最核心的两个点。

## 二维dp下的递推公式差异

先回顾01背包的二维递推公式：

```
dp[i][j] = max(dp[i-1][j], dp[i-1][j - weight[i]] + value[i])
```

这里"选择放入物品i"对应的项是 `dp[i-1][j-weight[i]] + value[i]`——用的是**上一行**（i-1）的数据，因为01背包里物品i只能用一次，一旦决定放入，就不能再考虑它了，接下来的状态必须退回到"只考虑前i-1个物品"的层面。

完全背包的二维dp[i][j]表示"从前i种物品中选择（每种可以选任意多次），放入容量为j的背包能得到的最大价值"，递推公式变成：

```
dp[i][j] = max(dp[i-1][j], dp[i][j - weight[i]] + value[i])
```

唯一但关键的区别在于第二项：这里是 `dp[i][j-weight[i]]`，而不是 `dp[i-1][j-weight[i]]`。为什么会有这个差异呢？原因是——选完一次物品i之后，物品i依然可以继续被选（它的"可选次数"没有用完），所以状态不需要退回到"i-1"这一层，而是继续停留在"考虑到第i种物品为止"这一层（即仍然是dp[i][...]）。这一个下标的差异，就是二维形式下完全背包和01背包递推公式的全部区别，但它带来的语义变化非常大——`dp[i][j-weight[i]]` 里可能已经包含了"选过物品i"的信息，再加一次value[i]，就实现了"物品i被再次选中"的效果，从而自然支持了无限次选取。

## 一维数组遍历顺序：核心考点

把二维压缩成一维之后，完全背包的递推公式变成：

```
dp[j] = max(dp[j], dp[j - weight[i]] + value[i])
```

这个式子从字面上看，跟01背包一维数组的公式完全一样。但**遍历容量j时的方向必须是正序（从小到大）**，这与01背包必须倒序遍历刚好相反。这是完全背包一维实现里最容易被忽略、也最容易和01背包搞混的地方。

要讲清楚"为什么"，关键还是要回到"dp[j-weight[i]]读到的是新值还是旧值"这个问题上：

- 在01背包里，倒序遍历保证了`dp[j-weight[i]]`读到的是"本轮循环还未更新过的旧值"（也就是还没考虑物品i的状态），这样才能保证物品i在本轮里只被使用一次。如果正序遍历，`dp[j-weight[i]]`可能已经在本轮被更新成"用过一次物品i"之后的值，再叠加一次就等价于用了两次，这在01背包里是bug，因为01背包不允许重复选取。

- 而在完全背包里，情况完全反过来：**我们希望`dp[j-weight[i]]`读到的正是"本轮循环中已经被更新过的新值"**，因为完全背包允许物品i被无限次选取。正序遍历j时，当计算`dp[j]`用到`dp[j-weight[i]]`时，如果`dp[j-weight[i]]`已经在本轮更新过（即已经包含了"选过一次物品i"的效果），那么再用它来更新`dp[j]`，效果就是在此基础上再叠加一次物品i，这正好实现了"同一个物品被连续多次选取"的语义。换句话说，完全背包依赖的正是正序遍历带来的"重复叠加"效果，这个效果在01背包里是错误的，但在完全背包里恰恰是我们需要的。

用一个具体例子对比会更直观：假设只有一个物品，weight=2，value=3，背包容量bagWeight=6，如果每种物品能选无限次，理论上最多能选3次（2+2+2=6），总价值应该是9。用正序遍历一维数组验证：

- `j=2`：`dp[2] = max(0, dp[0]+3) = 3`（选了第1次）
- `j=4`：`dp[4] = max(0, dp[2]+3) = max(0, 3+3) = 6`（这里的`dp[2]`已经是"选过一次"之后的值3，再加一次value，相当于选了第2次）
- `j=6`：`dp[6] = max(0, dp[4]+3) = max(0, 6+3) = 9`（`dp[4]`已经是"选过两次"之后的值6，再加一次，相当于选了第3次）

最终`dp[6]=9`，恰好等于选3次的总价值，这正是完全背包想要的结果。可以看到，正序遍历时后面的容量在计算时"借用"了前面刚刚更新出的新值，一步步把同一个物品的多次选取效果累积起来，这个过程与01背包里"避免重复叠加"的诉求正好相反。

## 对比小结

把01背包和完全背包的一维实现放在一起对比，可以得到一个更本质的结论：**遍历顺序不是死记硬背的规则，而是由"物品是否允许被重复选取"这个约束直接决定的**。

- 01背包：每个物品最多选一次 → 必须避免同一轮循环里的"重复叠加" → 内层容量倒序遍历。
- 完全背包：每个物品可以选无限次 → 恰恰需要利用同一轮循环里的"重复叠加"来实现多次选取的效果 → 内层容量正序遍历。

记住这个因果关系，比死记"01倒序、完全正序"这两个结论本身更重要，因为后续还会遇到更多背包变体（比如多重背包、二维费用背包），遇到新场景时，只要想清楚"这个物品能不能重复选"，就能自己推出遍历顺序该怎么写，而不需要照搬固定套路。

## 一维完全背包代码模板

下面给出一个完整的一维完全背包代码模板（以C++为例），可以作为后续所有完全背包变体题目的骨架参考：

```cpp
#include <vector>
#include <algorithm>
using namespace std;

int completeBackpack(vector<int>& weight, vector<int>& value, int bagWeight) {
    // dp[j] 表示容量为 j 的背包，在"每种物品可选无限次"的前提下能装下的最大价值
    vector<int> dp(bagWeight + 1, 0);  // 初始化：容量为0时无论怎么选价值都是0

    for (int i = 0; i < weight.size(); i++) {      // 外层遍历每一种物品
        for (int j = weight[i]; j <= bagWeight; j++) {
            // 内层容量正序遍历（与01背包相反）：
            // dp[j - weight[i]] 可能已经是本轮更新过的新值，
            // 这正是我们需要的效果——让物品i可以被连续多次叠加选取
            dp[j] = max(dp[j], dp[j - weight[i]] + value[i]);
        }
    }
    return dp[bagWeight];  // 容量恰好为bagWeight时能达到的最大价值
}
```

这段代码和01背包一维模板相比，唯一的语法差异就是内层循环`j`的遍历方向（从`weight[i]`往`bagWeight`正序，而不是从`bagWeight`往`weight[i]`倒序），但正是这一个方向的改变，让整个算法的语义从"每个物品最多用一次"变成了"每个物品可以用任意多次"。

## 小结

- 完全背包与01背包的根本区别是物品能否被重复选取，这个区别直接决定了二维dp递推公式中第二项该用`dp[i-1][...]`还是`dp[i][...]`。
- 一维数组下，完全背包必须正序遍历容量，因为正序遍历会让`dp[j-weight[i]]`读到本轮已更新的新值，从而自然实现物品的重复叠加选取，这与01背包倒序遍历的诉求（避免重复叠加）刚好相反。
- 遍历顺序的选择本质上由"物品是否允许重复选取"这一条件决定，理解这一层因果关系，比记住"01倒序、完全正序"的结论更重要，能帮助举一反三应对后续更复杂的背包变体。
