# 背包理论基础 01背包（二）：一维滚动数组优化

## 为什么可以压缩成一维

上一篇讲了01背包的二维dp数组解法，`dp[i][j]` 表示"从前i个物品中选，放入容量为j的背包能得到的最大价值"，递推公式是：

```
dp[i][j] = max(dp[i-1][j], dp[i-1][j - weight[i]] + value[i])
```

你仔细看这个式子会发现一个关键事实：**计算第 i 行的任何一个格子，用到的都只是第 i-1 行的数据**，完全不会用到第 i-2 行、第 i-3 行……更早的行。换句话说，一旦第 i-1 行算完了，第 i-2 行及之前的数据就再也不会被用到了，留着它们纯粹是浪费空间。

既然每一轮只依赖"上一轮"的结果，那就可以用一个一维数组去"滚动覆盖"——用同一个数组，先存第0行的结果，然后原地更新成第1行的结果，再原地更新成第2行的结果，以此类推。这样数组的物理空间只需要一份（长度为bagWeight+1），而不需要为每个物品都单独开一行，空间复杂度从O(n×bagWeight)降到O(bagWeight)。

把二维公式里的i去掉、j保留，就得到了一维滚动数组的递推公式：

```
dp[j] = max(dp[j], dp[j - weight[i]] + value[i])
```

这里的 `dp[j]` 在赋值号左边表示"更新后（考虑了物品i之后）的值"，右边的 `dp[j]` 和 `dp[j-weight[i]]` 则表示"更新前（还没考虑物品i，即上一轮遗留下来）的值"。这个公式看起来简单，但它藏着01背包里最容易出错的一个细节：**同一个数组里，左边和右边的dp[j]、dp[j-weight[i]]，到底是"新值"还是"旧值"，完全取决于遍历顺序**，而这直接关系到答案对不对。

## 核心难点：为什么内层容量必须倒序遍历

这是一维01背包最重要、也最容易被忽略的知识点：外层遍历物品，内层遍历容量时，**容量必须从大到小（倒序）遍历**，不能正序。我用一个具体例子把这件事讲透。

假设只有一个物品，重量 `weight = 2`，价值 `value = 3`，背包容量 `bagWeight = 4`。dp数组初始全部为0，即 `dp = [0, 0, 0, 0, 0]`（下标0到4）。

**如果按正序遍历容量（j 从小到大，从weight开始到bagWeight）：**

- `j=2`：`dp[2] = max(dp[2], dp[2-2] + 3) = max(0, dp[0]+3) = max(0, 0+3) = 3`。此时 `dp = [0,0,3,0,0]`。
- `j=3`：`dp[3] = max(dp[3], dp[1]+3) = max(0, 0+3) = 3`。此时 `dp = [0,0,3,3,0]`。
- `j=4`：`dp[4] = max(dp[4], dp[2]+3)`。你注意这里的 `dp[2]` 已经是**在本轮循环中刚被更新过的值**（等于3，代表"已经选了一次物品i"之后的价值），所以 `dp[4] = max(0, 3+3) = 6`。

最终 `dp[4] = 6`。但这个结果是错的——你想，只有一个物品，重量2，价值3，容量4的背包最多也只能选一次这个物品，正确答案应该是3，不是6。为什么会算出6呢？本质上是因为在计算 `dp[4]` 时，用到的 `dp[2]` 已经"包含了物品i被使用过一次的效果"，导致物品i在同一轮循环里被相当于用了两次（一次用在j=2上，一次借着j=2的结果用在j=4上）。这其实等价于"每个物品可以选无限次"，也就是完全背包的逻辑，而不是01背包该有的"最多选一次"。这就是正序遍历在01背包场景下的bug所在。

**如果按倒序遍历容量（j 从bagWeight递减到weight）：**

- `j=4`：`dp[4] = max(dp[4], dp[4-2]+3) = max(0, dp[2]+3)`。此时 `dp[2]` 还没被本轮循环更新过，仍是初始值0，所以 `dp[4] = max(0, 0+3) = 3`。此时 `dp = [0,0,0,0,3]`。
- `j=3`：`dp[3] = max(dp[3], dp[1]+3) = max(0, 0+3) = 3`。此时 `dp = [0,0,0,3,3]`。
- `j=2`：`dp[2] = max(dp[2], dp[0]+3) = max(0, 0+3) = 3`。此时 `dp = [0,0,3,3,3]`。

最终 `dp[4] = 3`，这才是正确答案。倒序遍历的关键在于：当我们计算 `dp[j]` 时，用到的 `dp[j-weight[i]]` 一定是"更小下标位置"，而更小的下标在**本轮遍历中还没有被访问过**（因为j是从大往小走的），所以它保留的必然是"上一轮"（也就是还没考虑物品i）的旧值。这就保证了物品i在这一轮循环里，最多只会被使用一次，完全符合01背包"每个物品选0次或1次"的约束。

一句话总结这个现象背后的原理：**倒序遍历保证了dp[j-weight[i]]在被读取时还是"旧值"（上一个物品遍历完之后的状态），从而避免同一个物品在同一轮内被重复叠加使用**。

## 遍历顺序的完整结论

综合上面的分析，一维滚动数组下的01背包，遍历顺序必须严格遵守：

1. **外层遍历物品**（`for i in 0..n-1`），内层遍历容量（`for j in bagWeight..weight[i]`）——两层顺序不能颠倒，如果外层遍历容量、内层遍历物品，会导致背包容量还没被"填满"到当前物品的层级就被后面的物品破坏了推导的前提，实践中一般不这样写。
2. **内层容量必须从大到小遍历**，且终止条件是 `j >= weight[i]`（一旦 `j < weight[i]`，物品i根本装不下，`dp[j]` 保持不变即可，不需要显式处理，只需让循环在weight[i]处停止）。

对应的伪代码骨架：

```
for i in 0..n-1:                          # 外层：遍历每个物品
    for j in bagWeight downto weight[i]:   # 内层：容量倒序遍历，直到weight[i]为止
        dp[j] = max(dp[j], dp[j-weight[i]] + value[i])
```

这个顺序组合（外层物品、内层容量倒序）是01背包一维写法的标准范式，后面几乎所有01背包变体的题目，只要用一维数组实现，都会遵循这套顺序规则。与之相对，后续学到的完全背包问题，因为每个物品可以选无限次，内层容量反而要改成正序遍历——这也从另一个角度印证了"遍历顺序不是随便定的，而是由问题的约束（选一次 vs 选无限次）决定的"。

## 小结

- 一维滚动数组能够压缩空间的前提，是二维dp的递推只依赖"上一行"，因此可以用同一份数组原地覆盖，空间复杂度从O(n×bagWeight)降到O(bagWeight)。
- 01背包一维写法的核心陷阱在于内层容量的遍历方向：倒序遍历能保证读取到的`dp[j-weight[i]]`是"旧值"，从而让每个物品在一轮循环里只被使用一次；正序遍历会读到"新值"，等价于把01背包错误地退化成了完全背包。
- 记住结论：一维01背包固定写法是"外层物品、内层容量从大到小遍历到weight[i]"，这是区分01背包和完全背包一维写法最直观的标志。
