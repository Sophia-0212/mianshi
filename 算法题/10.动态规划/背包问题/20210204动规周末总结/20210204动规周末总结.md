# 2021.02.04 动规周末总结

这周做的几道题都围绕"完全背包"这个模型展开，但表面上很相似的递推公式，背后对应的其实是几种完全不同的问题类型。趁着周末把这几道题串起来做个总结，重点理清楚两件事：一是"求最优解"和"求方案数"这两类完全背包问题在递推公式上的本质区别；二是 322（零钱兑换）和 279（完全平方数）这两道题之间的模型相似性。

## 完全背包的两种"性格"：求最优解 vs 求方案数

完全背包的外壳很好认：每种物品数量不限，可以重复选取，反映在代码上就是"内层遍历容量时必须正序"。但同样是完全背包的外壳，题目问的东西不同，递推公式里状态转移的组合方式会完全不同，这也是这一类问题里最容易混淆、最容易在写代码时"顺手写错"的地方。

**求方案数的完全背包**，比如零钱兑换 II（518）、组合总和 IV（377）这一类题目，问的是"有多少种不同的方式能凑出目标值"。这类问题的 `dp[j]` 存的是"方案条数"，每考虑多一种物品，就要把"用上这种物品后能凑出 j 的方案数"累加到已有的方案数上，因为这是在统计有多少条不同的路径能到达这个状态，递推公式的核心动作是**累加**：

```
dp[j] += dp[j - coins[i]]
```

这一类问题里，外层和内层的遍历顺序（先遍历物品还是先遍历容量）会直接决定统计出来的是"组合数"还是"排列数"，是需要非常小心处理的地方。

**求最优解的完全背包**，比如这周做的零钱兑换（322）、完全平方数（279），问的是"凑出目标值最少/最多需要多少个物品"（或者"能凑出的最大价值是多少"）。这类问题的 `dp[j]` 存的是"最优代价"本身，它根本不关心到底有多少种方案能达到这个最优值，只关心这一个最优解，所以递推公式的核心动作是**取最优（min 或 max）**：

```
dp[j] = min(dp[j], dp[j - coins[i]] + 1)
```

正是因为这类问题不是在"数路径条数"，而是在"比较代价"，所以外层遍历物品还是遍历容量，其实对最终结果的正确性并不敏感——只要每一个 `(物品, 容量)` 的组合都被访问并执行了 `min`/`max` 更新，`dp[j]` 最终一定会收敛到全局最优。这一点和"求方案数"那一类问题对遍历顺序高度敏感形成了鲜明的对比。

把这两类放在一起看会更清楚：外壳都是"完全背包"（物品可重复选，内层容量正序遍历），但递推公式的"组合方式"完全不同——一个是 `+=`（累加，回答"有多少种"），一个是 `min`/`max` 结合 `+1` 或 `+value`（取最优，回答"最少/最多是多少"）。混淆这两者，往硬套错了递推公式的组合方式，是背包问题这一类题目里最常见、也最隐蔽的错误来源，因为代码结构（两层循环、正序还是倒序）看上去几乎一样，唯一的差别就藏在赋值语句那一行。

## 322 和 279：同一个模型的两种"物品来源"

这周还有一个很有意思的发现：零钱兑换（322）和完全平方数（279）本质上是**同一道题**，只是换了一个包装。

322 题问的是"给定硬币面值数组，最少用多少枚硬币凑出金额 amount"；279 题问的是"最少用多少个完全平方数相加等于 n"。如果把"完全平方数"（`1, 4, 9, 16, ...`）看成硬币的面值集合，把 `n` 看成要凑的金额，279 题就变成了"硬币面值是 `1,4,9,16,...`，最少用多少枚硬币凑出金额 n"——和 322 题一字不差地对应。两题的递推公式也确实完全一样，都是 `dp[j] = min(dp[j], dp[j-物品]+1)`。

两题唯一的区别是"物品集合"（也就是隐含的 `coins` 数组）从哪里来：322 题是题目直接给出的数组，直接拿来用即可；279 题需要自己先枚举 `1` 到 `sqrt(n)`，把每个满足 `i*i <= n` 的 `i*i` 收集起来，才能得到这个隐式的"coins 数组"。

这说明了一个更普遍的道理：解决背包类问题，"识别出物品集合到底是什么、容量对应的是什么"这一步的观察和转化能力，往往比记住递推公式本身更重要。递推公式一旦确定了问题类型（求方案数 or 求最优解），写法是相对固定的；但把一道看起来"不像背包问题"的题目（比如"最少用多少个完全平方数凑出 n"）转化成"这其实是一个完全背包"，才是真正需要练习和积累经验的地方。以后遇到新的题目，可以多问一句："能不能把某种可重复使用的东西看成硬币，把某个目标数值看成金额？"——如果能，往往就可以直接套用已经掌握的完全背包套路，不需要从零开始想递推公式。

## 小结

- 完全背包"求方案数"（`+=` 累加）和"求最优解"（`min`/`max` 结合 `+1`）是两种性格完全不同的问题，外壳相似但递推组合方式不同，也导致前者对遍历顺序敏感、后者不敏感。
- 322（零钱兑换）与 279（完全平方数）是同一个"最少用多少个给定面值的物品凑出目标值"模型的两种呈现，区别仅在于物品集合是题目直接给定还是需要自己枚举生成。
- 做背包类题目时，先判断"这道题问的是方案数还是最优解"，再判断"物品集合和容量分别对应什么"，两步做完之后递推公式基本就能自己推出来，不需要死记硬背。
