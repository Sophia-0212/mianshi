# 0377. 组合总和 Ⅳ

**题目描述**

给定一个由不同正整数组成的数组 `nums` 和一个目标整数 `target`，从 `nums` 中选取数字（每个数字可以被重复使用任意次），求恰好组成 `target` 的排列数。这里"排列"意味着选取数字的顺序不同则视为不同的方案。

```
示例：
输入: nums = [1, 2, 3], target = 4
输出: 7
解释: 所有可能的组合为：
(1, 1, 1, 1)
(1, 1, 2)
(1, 2, 1)
(1, 3)
(2, 1, 1)
(2, 2)
(3, 1)
```

数据保证答案符合 32 位整数范围，`nums` 中不含 0。

## 思路

本题和 518 题（零钱兑换 II）几乎是"同一个骨架、不同的表皮"：都是完全背包（元素可重复使用），状态转移方程的形式也一样是"累加型"，但本题求的是排列数而不是组合数，这直接体现在遍历顺序的选择上。

**1. 确定 dp 数组（下标）的含义**

`dp[j]` 表示：使用 `nums` 中的数字（可重复使用），凑成总和为 `j` 的排列数。

**2. 确定递推公式**

对于每一个 `j`，考虑排列的"最后一位"填的是哪个数字。如果最后一位填的是 `nums[i]`，那么前面部分就是一个凑成 `j - nums[i]` 的排列，有多少种这样的排列，加到 `dp[j]` 上就贡献多少种以 `nums[i]` 结尾、总和为 `j` 的方案：

```
dp[j] += dp[j - nums[i]]   (当 j >= nums[i] 时)
```

单看这一行公式，和 518 题的 `dp[j] += dp[j - coins[i]]` 一模一样。差别在哪呢？在于"外层循环放在哪里"：如果外层是遍历 `nums`，那么每个 `nums[i]` 在被处理时，`dp[j]` 已经是"用前面已处理过的物品能凑出的方案数"，这样统计出来的是不区分先后顺序的组合数（就像 518 题那样）。但本题要求区分顺序，所以要让"对每一个 `j`，所有的 `nums[i]` 都有机会被当作最后一位来尝试"——这就必须把 `target`（容量）放在外层，`nums`（物品）放在内层，这样计算 `dp[j]` 时会依次让每个 `nums[i]` 都尝试作为"最后一步"，从而把不同的排列顺序分别统计出来。

**3. dp 数组如何初始化**

`dp[0] = 1`，表示凑成总和 0 只有一种方案，即什么都不选。这同样是整个递推链条的种子，如果初始化为 0，所有的 `dp[j]` 都会因为累加不到任何基础值而恒为 0。

其余 `dp[j]`（`j >= 1`）初始化为 0。

**4. 确定遍历顺序**

```
for j in range(1, target + 1):      # 外层：容量（目标和）
    for num in nums:                # 内层：物品
        if j >= num:
            dp[j] += dp[j - num]
```

外层容量、内层物品，这正是求排列数的固定搭配，和 518 题的"外层物品、内层容量"刚好相反。你可以这样理解：外层遍历到某个具体的 `j` 时，内层会让 `nums` 里的每一个数字都有机会成为"凑出 j 的最后一步"，`nums[i]` 作为最后一步贡献的方案数是 `dp[j-nums[i]]`（前面部分的排列数，前面部分内部的顺序已经在更早的 `dp` 值里被正确统计过了）。因为每个数字轮流被当作"最后一位"分别累加，`(1,3)` 和 `(3,1)` 会在计算 `dp[4]` 时分别通过"最后一位是3，前面凑出1"和"最后一位是1，前面凑出3"被计入两次，这正是排列数需要的效果。

内层遍历物品时不需要限定方向（正序或倒序都可以），因为这里不存在"同一物品要不要被重复计入同一行"的问题——外层每个 `j` 只计算一次，内层只是在收集"以哪个数字结尾"的所有可能。

**5. 举例推导验证**

咱们用 `nums = [1, 2, 3], target = 4` 推导一遍，`dp` 数组长度为 5，初始 `dp = [1, 0, 0, 0, 0]`。

`j = 1`：只有 `num=1` 满足 `j >= num`。`dp[1] += dp[0] = 1` → `dp = [1,1,0,0,0]`

`j = 2`：`num=1` 时 `dp[2] += dp[1] = 1`；`num=2` 时 `dp[2] += dp[0] = 1+1=2` → `dp = [1,1,2,0,0]`

`j = 3`：`num=1` 时 `dp[3] += dp[2] = 2`；`num=2` 时 `dp[3] += dp[1] = 2+1=3`；`num=3` 时 `dp[3] += dp[0] = 3+1=4` → `dp = [1,1,2,4,0]`

`j = 4`：`num=1` 时 `dp[4] += dp[3] = 4`；`num=2` 时 `dp[4] += dp[2] = 4+2=6`；`num=3` 时 `dp[4] += dp[1] = 6+1=7` → `dp = [1,1,2,4,7]`

最终 `dp[4] = 7`，跟题目给出的 7 种排列一致。

作为对照，如果这道题问的是"组合数"（不区分顺序），用 518 的写法（外层物品 `nums`，内层容量 `j`）重新推导同样的输入会得到 `dp[4] = 4`（对应组合 `{1,1,1,1}`、`{1,1,2}`、`{1,3}`、`{2,2}` 这四种不区分顺序的搭配），这正好印证了两题的核心区别只在遍历顺序，而不在状态转移方程本身。

**复杂度分析**

- 时间复杂度：`O(target * len(nums))`，双层循环，外层遍历所有目标和，内层遍历所有物品。
- 空间复杂度：`O(target)`，一维 dp 数组。

## 代码

### C++

```cpp
class Solution {
public:
    int combinationSum4(vector<int>& nums, int target) {
        vector<int> dp(target + 1, 0); // dp[j]：凑成总和 j 的排列数
        dp[0] = 1; // 递推种子：凑成 0 只有一种方案（不选任何数字）
        for (int j = 1; j <= target; j++) {      // 外层遍历容量（目标和）：让每个 j 都尝试所有物品作为"最后一步"
            for (int num : nums) {               // 内层遍历物品：保证顺序不同的方案被分别统计，得到排列数
                if (j >= num) {
                    dp[j] += dp[j - num]; // 核心递推：以 num 结尾时，累加前面凑出 j-num 的排列数
                }
            }
        }
        return dp[target];
    }
};
```

                }
            }
        }
        return dp[target];
    }
}

func combinationSum4(nums []int, target int) int {
    dp := make([]int, target+1) // dp[j]：凑成总和 j 的排列数
    dp[0] = 1                   // 递推种子：凑成 0 只有一种方案

            }
        }
    }
    return dp[target]
}

## 总结

- 本题与 518 题（零钱兑换 II）的状态转移方程形式完全相同（`dp[j] += dp[j-x]`），唯一的区别是遍历顺序：本题外层容量、内层物品，得到排列数；518 题外层物品、内层容量，得到组合数。
- 外层容量在外，意味着对每一个目标和都会让所有物品轮流尝试作为"最后一步"，从而把同一组合的不同排列顺序分别统计出来。
- `dp[0] = 1` 是这一类"累加型"计数 dp 通用的初始化方式，代表"凑成 0 的方案数为 1（不选任何元素）"，是后续所有累加的起点。
- 判断一道计数类背包题该用哪种遍历顺序，先确认题目是否区分选取顺序：不区分选组合数写法（先物后容），区分就选排列数写法（先容后物）。
