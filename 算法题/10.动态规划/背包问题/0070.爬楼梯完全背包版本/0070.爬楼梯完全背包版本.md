# 0070. 爬楼梯（完全背包版本）

**题目描述**

爬楼梯的推广版本：一共有 `n` 阶楼梯，每次可以向上爬 `1` 到 `m` 阶中的任意数量（`m` 是给定的一个正整数上限），每种爬法内部的顺序不同视为不同的方案，求爬到楼顶一共有多少种不同的方法。

```
示例：
输入: n = 3, m = 3
输出: 4
解释: 爬到第 3 阶楼梯，一共有 4 种方法：
[1,1,1]
[1,2]
[2,1]
[3]
```

当 `m = 2` 时，这道题就退化为最初的爬楼梯问题（每次只能爬 1 阶或 2 阶）。

## 思路

原始的爬楼梯问题（每次只能爬 1 或 2 阶）通常直接用"斐波那契式"的递推 `dp[i] = dp[i-1] + dp[i-2]` 解决，但这个写法只适用于"每次爬的阶数固定是 1 和 2 这两种"的场景，一旦上限 `m` 变成任意值，就不能简单枚举了。这里换一个视角：把"每次能爬的阶数"看作一种可以重复使用的"物品"（因为一次爬楼梯的过程中，1 阶、2 阶……m 阶这些跨度都可以被反复使用），把"总阶数 n"看作背包的"容量"，这样问题就转化成了一个标准的完全背包模型，并且因为爬楼梯的过程中"先爬1阶再爬2阶"和"先爬2阶再爬1阶"是两种不同的方法（这一点和 377 题"顺序不同算不同方案"完全对应），所以这是完全背包里"求排列数"的应用。

**1. 确定 dp 数组（下标）的含义**

`dp[j]` 表示：爬到第 `j` 阶楼梯，一共有多少种不同的方法（区分每一步爬的顺序）。

**2. 确定递推公式**

考虑爬到第 `j` 阶的"最后一步"跨了多少阶。如果最后一步跨了 `i` 阶（`1 <= i <= m`），那么在跨出这一步之前，应该正好停在第 `j - i` 阶，而爬到第 `j-i` 阶的方法数就是 `dp[j-i]`。把每一种可能的最后一步累加起来：

```
dp[j] += dp[j - i]   (对每个 1 <= i <= m，当 j >= i 时)
```

这个形式和 377 题的 `dp[j] += dp[j-nums[i]]` 本质上是同一个模型：377 题里的 `nums` 换成了这里的"每次可爬的阶数 1 到 m"，`target` 换成了"总阶数 n"。

**3. dp 数组如何初始化**

`dp[0] = 1`，表示站在第 0 阶（起点，还没开始爬）算作一种方案，是整条递推链的种子。这和前面两题的初始化逻辑完全一致。

其余 `dp[j]`（`j >= 1`）初始化为 0。

**4. 确定遍历顺序**

因为要求的是排列数（顺序不同算不同方案），所以遵循"外层容量、内层物品"的搭配：外层遍历楼梯的阶数 `j`（从 1 到 n），内层遍历每次能爬的步数 `i`（从 1 到 m）：

```
for j in range(1, n + 1):        # 外层：容量（当前要爬到的阶数）
    for i in range(1, m + 1):    # 内层：物品（每次可以爬的步数）
        if j >= i:
            dp[j] += dp[j - i]
```

外层容量在外的原因和 377 题一致：对每一个 `j`，让 1 到 m 这些可能的"最后一步"都轮流被尝试一次，这样"先爬1再爬2"和"先爬2再爬1"会分别在计算 `dp[3]` 时被累加两次（一次是"最后一步爬了2阶，前面用 dp[1] 爬到第1阶的方法"，一次是"最后一步爬了1阶，前面用 dp[2] 爬到第2阶的方法"），从而正确统计出不同顺序的方案数。

**5. 举例推导验证**

用 `m = 3, n = 3` 推导，`dp` 数组长度为 4，初始 `dp = [1, 0, 0, 0]`。

`j = 1`：内层 `i` 只能取 1（因为 `i <= j`）。`dp[1] += dp[0] = 1` → `dp = [1,1,0,0]`

`j = 2`：`i=1` 时 `dp[2] += dp[1] = 1`；`i=2` 时 `dp[2] += dp[0] = 1+1=2` → `dp = [1,1,2,0]`

`j = 3`：`i=1` 时 `dp[3] += dp[2] = 2`；`i=2` 时 `dp[3] += dp[1] = 2+1=3`；`i=3` 时 `dp[3] += dp[0] = 3+1=4` → `dp = [1,1,2,4]`

最终 `dp[3] = 4`，跟题目给出的 4 种方法（`[1,1,1]`、`[1,2]`、`[2,1]`、`[3]`）完全一致。

**与原始 70 题的对照**

当 `m = 2` 时，内层循环只会遍历 `i = 1` 和 `i = 2`，递推公式退化为 `dp[j] = dp[j-1] + dp[j-2]`，这正是原始爬楼梯题目"斐波那契式"的递推关系。也就是说，原始的 70 题只是这个完全背包模型在 `m = 2` 这个特殊值下的表现，而把问题抽象成背包模型之后，`m` 可以取任意正整数，模型本身不需要做任何改动——这正是把具体问题抽象为背包模型的价值所在，同一套代码框架能覆盖一整类问题，而不需要针对每一种 `m` 单独设计递推式。

**复杂度分析**

- 时间复杂度：`O(n * m)`，双层循环，外层遍历楼梯阶数，内层遍历每次可爬的步数。
- 空间复杂度：`O(n)`，一维 dp 数组。

## 代码

### C++

```cpp
class Solution {
public:
    int climbStairs(int n, int m) {
        vector<int> dp(n + 1, 0); // dp[j]：爬到第 j 阶的方法数（区分顺序）
        dp[0] = 1; // 递推种子：站在起点（第0阶）算一种方案
        for (int j = 1; j <= n; j++) {         // 外层遍历容量（阶数）：让每一步都能作为"最后一步"被尝试
            for (int i = 1; i <= m; i++) {     // 内层遍历物品（每次可爬的步数）：保证顺序不同分别计数，得到排列数
                if (j >= i) {
                    dp[j] += dp[j - i]; // 核心递推：最后一步爬 i 阶，累加前面爬到 j-i 阶的方法数
                }
            }
        }
        return dp[n];
    }
};
```

```java
        int[] dp = new int[n + 1]; // dp[j]：爬到第 j 阶的方法数

                }
            }
        }
        return dp[n];
    }
```
```go
}
```

## 总结

- 把"每次可爬的阶数"抽象为可重复使用的物品，"总阶数 n"抽象为容量，爬楼梯的推广版本就是一道标准的完全背包"求排列数"问题，递推公式为 `dp[j] += dp[j-i]`。
- 因为爬楼梯每一步的先后顺序不同算不同的方法，遍历顺序沿用 377 题的搭配：外层容量、内层物品，这样才能让每一步的跨度都有机会作为"最后一步"被单独统计。
- 原始的 70 题（每次只能爬 1 或 2 阶）只是这里 `m = 2` 时的特例，此时递推公式退化为熟悉的 `dp[j] = dp[j-1] + dp[j-2]`，说明抽象出背包模型后，同一套框架可以自然覆盖任意 `m` 的情况。
- 三道题（518、377、本题）放在一起对比，能清楚看到"完全背包求组合数"和"求排列数"只在遍历顺序上有差别，状态转移方程的核心形式始终是 `dp[j] += dp[j-x]`。
