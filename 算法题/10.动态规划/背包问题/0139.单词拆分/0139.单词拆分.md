# 0139. 单词拆分

**题目描述**

给定一个字符串 `s` 和一个字符串列表 `wordDict`（字典），判断 `s` 是否可以被拆分为一个或多个字典中出现的单词的拼接。字典中的单词可以被重复使用多次。

```
示例：
输入: s = "leetcode", wordDict = ["leet", "code"]
输出: true
解释: 可以拆分成 "leet" + "code"
```

字典里的每个单词都可以被重复使用，你想啊，这就意味着可以把字典中的单词看成"物品"，且是可以重复选取的完全背包物品；把字符串 `s` 的长度看成背包的"容量"。这样问题就转化为了："能否用字典里的单词（可重复使用）恰好拼出长度为 `len(s)` 且内容与 `s` 完全一致的字符串"。这其实是完全背包的第三种典型问题类型——**判定性问题（能否装满）**，和"求最优解"（min/max）、"求方案数"（累加）都不一样。

## 思路

### 1. 确定 dp 数组（下标）的含义

`dp[j]` 表示：字符串 `s` 的前 `j` 个字符组成的子串 `s[0:j]`，是否能够被字典 `wordDict` 中的单词拼接组成。`dp[j]` 是一个布尔值（`true`/`false`）。

这里的下标 `j` 就是"背包容量"，对应到本题就是"已经处理到 `s` 的第几个字符"；字典中的每个单词就是"物品"。

### 2. 确定递推公式

对每一个位置 `j`（表示考察前 `j` 个字符能否被拼接成功），枚举字典中的每一个单词 `word`：如果 `dp[j - len(word)]` 为 `true`（说明 `s` 的前 `j - len(word)` 个字符已经能被成功拼接），并且 `s` 这个字符串中从下标 `j - len(word)` 到 `j` 的这一段子串恰好等于 `word` 本身（逐字符匹配），那就可以推出 `dp[j] = true`——为什么呢？因为可以先用已经验证过合法的前缀拼法，再紧接着拼上这个 `word`，正好凑到长度 `j`。

用递推公式表达：

```
若存在某个 word ∈ wordDict，满足 j >= len(word)
   且 dp[j - len(word)] == true
   且 s[j-len(word) : j] == word，
则 dp[j] = true
```

这里我要特别说明一下递推公式的"合并方式"：`dp[j]` 由 `dp[j - len(word)]` 转移而来，这一点和数值型的背包递推（比较大小取 min/max，或者数值累加）都不一样。这里的合并逻辑是**逻辑或（or）**——只要字典中存在**任意一个**单词能让上述转移条件成立，`dp[j]` 就是 `true`；不需要考虑"取哪个最大"或者"一共有几种拼法"，因为本题只关心"能不能拼出来"这一个是非判断，不是优化问题（不求最优代价），也不是计数问题（不数方案条数）。所以说，完全背包的递推公式合并方式，到这里就总结出了第三种类型：`min`/`max` 求最优解、`+=` 求方案数、`or`（逻辑或）求"是否可行"，三者并列，分别对应"最优化""计数""判定"这三类不同性质的问题。

### 3. dp 数组如何初始化

`dp[0] = true`：表示空字符串（前 0 个字符，什么都不拼）天然被认为是"合法"的初始状态。这一步是整个递推能够启动的关键——如果 `dp[0]` 不是 `true`，后续任何 `dp[j]` 都无法通过"前缀合法 + 拼接一个单词"的方式被推出来。

其余 `dp[j]`（`j > 0`）初始化为 `false`，表示在还没有真正验证之前，默认认为"前 j 个字符尚不能被拼接成功"，需要通过递推逐步把满足条件的位置更新为 `true`。

### 4. 确定遍历顺序

外层遍历容量 `j`（从 `1` 到 `len(s)`），内层遍历字典中的每一个单词 `word`：

```
for j in 1 .. len(s):
    for word in wordDict:
        if j >= len(word) and dp[j - len(word)] and s[j-len(word):j] == word:
            dp[j] = true
            break  // 已经确定 dp[j] = true，不需要再看其他单词
```

之所以外层必须是容量 `j`（按长度从小到大递增处理），是因为我们要判断的是"`s` 的某个前缀是否合法"，而 `dp[j]` 的判断依赖于更短的前缀 `dp[j - len(word)]` 是否已经确定，所以必须先把短的前缀算出来，才能推更长的前缀——这是一种"按 j 递增"的天然约束，和纯数值型完全背包（可以自由讨论"先遍历物品再遍历容量"还是反过来）不完全一样。内层遍历字典单词，是因为对每个固定的 `j`，需要尝试字典里所有的单词，看是否有某个单词的长度和内容能够匹配上 `s` 在这个位置的结尾片段。由于本题需要做字符串切片和逐字符比较，实践中常见的写法就是"外层容量、内层物品"，这里主要考虑的是"按 `s` 的前缀长度递增计算 `dp`"这一约束，而不是像纯数值型完全背包那样纠结"到底数组合数还是排列数"。

### 5. 举例推导 dp 数组验证

咱们拿 `s = "leetcode"`（长度 8），`wordDict = ["leet", "code"]` 来走一遍。初始化 `dp[0] = true`，`dp[1..8]` 全部为 `false`。

- `j = 1,2,3`：尝试用 `"leet"`（长度4，`j < 4` 不满足）和 `"code"`（长度4，同样不满足），`dp[1]=dp[2]=dp[3]` 都保持 `false`。
- `j = 4`：尝试 `"leet"`（长度4），检查 `dp[4-4]=dp[0]=true`，且 `s[0:4] = "leet"` 恰好等于 `word`，条件成立，`dp[4] = true`。再尝试 `"code"`（长度4），`s[0:4]="leet" != "code"`，不成立，但 `dp[4]` 已经是 `true`，跳出内层循环即可。
- `j = 5,6,7`：`"leet"` 长度不够或者切出的子串不匹配（比如 `j=8` 之前的位置，`s[j-4:j]` 都不等于 `"leet"`），`"code"` 长度也不够或不匹配，`dp[5]=dp[6]=dp[7]` 保持 `false`。
- `j = 8`：尝试 `"leet"`（长度4），检查 `dp[8-4]=dp[4]=true`，但 `s[4:8] = "code"`，和 `"leet"` 不相等，不成立。再尝试 `"code"`（长度4），检查 `dp[8-4]=dp[4]=true`，且 `s[4:8] = "code"` 恰好等于 `word`，条件成立，`dp[8] = true`。

最终 `dp[8] = true`（`len(s) = 8`），说明 `s = "leetcode"` 确实可以被拆分成字典中单词的拼接（`"leet" + "code"`），跟预期一致。

### 复杂度分析

时间复杂度：外层遍历 `j` 共 `O(n)` 次（`n = len(s)`），内层遍历字典单词共 `O(m)` 次（`m` 为字典单词数），每次判断子串是否匹配需要 `O(k)`（`k` 为单词平均长度，最坏可达 `O(n)`）。综合来看粗略是 `O(n * m * k)`，如果简化考虑单词长度与 `n` 同阶，可以粗略记作 `O(n^2)` 到 `O(n^3)` 之间，具体取决于实现方式（是否预先用哈希集合存字典、子串比较是否优化）。

空间复杂度：一维 `dp` 数组长度为 `n + 1`，共 `O(n)`。

## 代码

### C++

```cpp
class Solution {
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> wordSet(wordDict.begin(), wordDict.end());  // 用哈希集合加速单词查找
        int n = s.size();
        vector<bool> dp(n + 1, false);  // dp[j]：s 的前 j 个字符能否被拼接成功
        dp[0] = true;                    // 空字符串天然合法，是递推的起点
        for (int j = 1; j <= n; j++) {          // 外层按前缀长度递增遍历容量 j
            for (int len = 1; len <= j; len++) { // 内层枚举当前这一段"结尾单词"的长度
                string word = s.substr(j - len, len);  // 取出 s 中从 j-len 到 j 的子串
                if (dp[j - len] && wordSet.count(word)) {  // 前缀合法 且 结尾子串恰好是字典中的单词
                    dp[j] = true;  // 逻辑或：只要有一种拼法成立，dp[j] 就是 true
                    break;         // 已确定为 true，无需再尝试其他长度
                }
            }
        }
        return dp[n];  // 前 n 个字符（即整个字符串）是否能被成功拼接
    }
};
```

```python
class Solution:
    def wordBreak(self, s: str, wordDict: list[str]) -> bool:
        word_set = set(wordDict)  # 哈希集合加速单词查找
```

### Go

```go
func wordBreak(s string, wordDict []string) bool {
    wordSet := make(map[string]bool)
    for _, w := range wordDict {
        wordSet[w] = true // 哈希集合加速单词查找
    }
    n := len(s)
    dp := make([]bool, n+1) // dp[j]：s 的前 j 个字符能否被拼接成功
    dp[0] = true            // 空字符串天然合法，递推起点

    for j := 1; j <= n; j++ { // 外层按前缀长度递增遍历容量 j
        for length := 1; length <= j; length++ { // 内层枚举结尾单词的长度
            word := s[j-length : j] // 取出 s 中从 j-length 到 j 的子串
            if dp[j-length] && wordSet[word] {
                dp[j] = true // 逻辑或：只要有一种拼法成立，dp[j] 就是 true
                break
            }
        }
    }
    return dp[n]
}
```

## 总结

- 这道题是完全背包"能否装满"这一判定性问题的典型代表：把字典单词看作可重复使用的物品，把 `len(s)` 看作容量，递推公式的合并方式是逻辑或（or），只要有任意一种拼法能成立，`dp[j]` 就是 `true`。
- 这也补上了完全背包递推公式合并方式的第三种类型：`min`/`max` 求最优解、`+=` 求方案数、`or` 求"是否可行"，三者分别对应优化、计数、判定这三种不同性质的问题目标。
- 初始化 `dp[0] = true` 是整个递推能够启动的关键，代表"空字符串"天然合法，这一点一定要记住。
- 遍历顺序上，外层必须按 `s` 的前缀长度 `j` 递增处理（因为 `dp[j]` 依赖更短前缀的 `dp` 值），内层枚举可能的结尾单词长度并做子串匹配，这一点和纯数值型完全背包"讨论组合数/排列数"的遍历顺序考量不同，本题的约束来自"字符串前缀依赖关系"本身。
