# 0494. 目标和

**题目描述**

给定一个非负整数数组 `nums` 和一个整数 `target`。数组中每个数字前面都要添加 `'+'` 或 `'-'`，然后把所有整数连接起来可以构造一个表达式，求该表达式计算结果等于 `target` 的不同添加符号的方法数。

```
示例：
输入: nums = [1,1,1,1,1], target = 3
输出: 5
解释: 一共有 5 种添加符号的方法使得表达式的结果为 3。
-1+1+1+1+1 = 3
+1-1+1+1+1 = 3
+1+1-1+1+1 = 3
+1+1+1-1+1 = 3
+1+1+1+1-1 = 3
```

数组长度范围 1 到 20，元素值范围 0 到 1000，`target` 的绝对值不超过 1000。

## 思路

### 问题转化：从"填符号"到"选子集"

你想啊，暴力的思路很直接：每个数字前面无非就是加号或减号两种选择，一共 2^n 种组合，直接枚举完了再判断和是不是等于 target。这个思路回溯法是能做的，但数据一大就超时了。所以关键是要把它变成背包问题，这里需要做一次比较关键的数学转化。

设数组的总和为 `sum`。你想，在最终确定的一种符号方案里，把所有添加了 `'+'` 号的数字加起来记为 `x`，那添加了 `'-'` 号的数字之和自然就是 `sum - x`——因为每个数字只能选一种符号，两部分正好把 `sum` 瓜分完了。

那表达式的结果就是：

```
x - (sum - x) = target
```

整理一下：

```
2x = target + sum
x = (target + sum) / 2
```

说白了，到这里问题就从"给每个数字定符号，使表达式等于 target"转化成了：**从 nums 中选出若干个数字（每个数字最多选一次），使它们的和恰好等于 x，问有多少种选法**。这正好就是 01 背包的模型，只不过背包容量不再是"最大价值"，而是要求"恰好装满"，问的还是方案数而不是最优值。

不过推公式之前，得先处理两种无解的边界情况：

1. 如果 `target + sum` 是奇数，说明 x 不是整数，那肯定没法通过选子集得到，直接返回 0。
2. 如果 `x` 是负数，等价于 `|target| > sum`，这种情况不管怎么加减都凑不出这么大的绝对值，也返回 0。

确定了合法的 x 之后，问题就完全变成一个标准的"01 背包求装满方案数"问题了：背包容量是 x，物品就是 nums 里的每个数，重量等于数值本身，价值都是 1——其实价值这个概念在计数问题里已经不重要了。

接下来我按"动规五部曲"给你讲一下。

**1. 确定 dp 数组（下标）的含义**

`dp[j]` 表示：从 nums 中选数字，凑成和为 `j` 的不同选法数量。这里要注意，`dp[j]` 是"方案数"，不是"最大价值"，也不是"是否可行"，这一点很关键，它决定了递推公式必须用累加，而不能取 max/min。

**2. 确定递推公式**

对 01 背包来说，一维遍历版本是外层遍历物品、内层遍历容量。当考虑到第 `i` 个数字 `nums[i]` 时，容量为 `j` 的方案数由两部分构成：

- 不选 `nums[i]`：方案数还是原来的 `dp[j]`（选它之前已经统计过的凑出 j 的方式）。
- 选 `nums[i]`：那剩下的容量 `j - nums[i]` 之前已经有多少种方式能凑出来，选上 `nums[i]` 之后就新增了同样多的方案。

这两部分是"不选"和"选"两种互斥情况的方案数相加，所以递推公式是：

```
dp[j] += dp[j - nums[i]]
```

这里我要重点强调一下：这跟"01 背包求最大价值"的递推公式 `dp[j] = max(dp[j], dp[j-weight[i]] + value[i])` 长得挺像，但本质完全不一样：

- 求最大价值是个**最优化问题**，每个状态只关心"最优解是多少"，递推时用 max 在"选"和"不选"之间挑一个更好的出来。
- 求方案数是个**计数问题**，每个状态关心的是"有多少种不同的达到方式"，递推时要把"选"和"不选"两条路径的方案数都算进去，用加法累加，而不是二选一。

这也是初学者最容易搞混的地方：一看到递推公式长得像 01 背包，就下意识套用 max，结果把方案数问题做成了可行性判断，答案就算错了。

**3. dp 数组如何初始化**

`dp[0] = 1`：为什么呢？什么都不选，凑出和为 0，这本身就是唯一的一种方案（空集嘛），所以要初始化为 1，而不是 0。如果初始化成 0，后面所有的累加都会从 0 开始，最终结果全部是 0，这个坑一定要避开。

其余 `dp[j] = 0`（`j` 从 1 到 x），道理很简单，还没开始选任何数字之前，凑不出正数的和，方案数当然是 0。

**4. 确定遍历顺序**

这是标准的一维 01 背包，结论就是：外层遍历物品（nums 的每一个数），内层遍历容量要倒序遍历（从 x 到 `nums[i]`）。

倒序遍历的原因我再讲一下：一维 dp 数组是从二维数组压缩过来的，`dp[i][j]` 依赖于 `dp[i-1][j-nums[i]]`——上一行、更小的容量。你想，如果内层从小到大正序遍历，`dp[j-nums[i]]` 在本轮循环中可能已经被更新成了"选过 nums[i] 之后"的值，这样再用它去更新 `dp[j]`，就相当于让 `nums[i]` 被选了两次，等价于变成了完全背包了。所以必须倒序，这样才能保证 `dp[j-nums[i]]` 用的是"还没选 nums[i]"的旧值。

**5. 举例推导 dp 数组验证**

咱们拿示例 `nums = [1,1,1,1,1]`，`target = 3` 走一遍。

先算 `sum = 5`，`target + sum = 8`，是偶数，`x = 4`。也就是转化成了：从 5 个 1 中选若干个，使得和恰好为 4，问方案数。

初始化：`dp = [1, 0, 0, 0, 0]`（下标 0~4）。

处理第 1 个 `nums[0] = 1`，j 从 4 倒序到 1：

- `dp[4] += dp[3] = 0` → `dp[4] = 0`
- `dp[3] += dp[2] = 0` → `dp[3] = 0`
- `dp[2] += dp[1] = 0` → `dp[2] = 0`
- `dp[1] += dp[0] = 1` → `dp[1] = 1`

当前：`dp = [1, 1, 0, 0, 0]`

处理第 2 个 `nums[1] = 1`：

- `dp[4] += dp[3] = 0` → 0
- `dp[3] += dp[2] = 0` → 0
- `dp[2] += dp[1] = 1` → 1
- `dp[1] += dp[0] = 1` → 2

当前：`dp = [1, 2, 1, 0, 0]`

处理第 3 个 `nums[2] = 1`：

- `dp[4] += dp[3] = 0` → 0
- `dp[3] += dp[2] = 1` → 1
- `dp[2] += dp[1] = 2` → 3
- `dp[1] += dp[0] = 1` → 3

当前：`dp = [1, 3, 3, 1, 0]`

处理第 4 个 `nums[3] = 1`：

- `dp[4] += dp[3] = 1` → 1
- `dp[3] += dp[2] = 3` → 4
- `dp[2] += dp[1] = 3` → 6
- `dp[1] += dp[0] = 1` → 4

当前：`dp = [1, 4, 6, 4, 1]`

处理第 5 个 `nums[4] = 1`：

- `dp[4] += dp[3] = 4` → 5
- `dp[3] += dp[2] = 6` → 10
- `dp[2] += dp[1] = 4` → 10
- `dp[1] += dp[0] = 1` → 5

最终 `dp[4] = 5`，正好等于题目给出的答案 5，说明这套推导是对的。你仔细看整个过程还会发现，每一步的 `dp` 其实就是组合数 C(k, j) 的分布（5 个 1 选 j 个的方案数），这也很符合直觉，因为每个数都是 1 的时候，"凑出和为 j"就等价于"选 j 个数字"。

### 复杂度分析

设数组长度为 n，转化后的背包容量为 x（`x <= sum <= 20 * 1000`）。

- 时间复杂度：O(n * x)，两层循环，外层 n 次，内层最多 x 次。
- 空间复杂度：O(x)，只用了一个一维数组。

## 代码

### C++

```cpp
class Solution {
public:
    int findTargetSumWays(vector<int>& nums, int target) {
        int sum = 0;
        for (int num : nums) sum += num;  // 先求数组总和

        // (target + sum) 必须是非负偶数，否则无法凑出整数容量 x
        if ((target + sum) % 2 != 0 || abs(target) > sum) {
            return 0;
        }

        int x = (target + sum) / 2;  // 转化为：选子集凑出和为 x 的方案数
        vector<int> dp(x + 1, 0);
        dp[0] = 1;  // 什么都不选，凑出和为 0，唯一方案

        for (int i = 0; i < nums.size(); i++) {       // 外层：遍历物品
            for (int j = x; j >= nums[i]; j--) {      // 内层：容量倒序，保证每个数只用一次
                dp[j] += dp[j - nums[i]];             // 累加"选"与"不选"两种方案数，而非取max/min
            }
        }
        return dp[x];
    }
};
```

## 总结

- 这道题最核心的一步，其实不是背包本身，而是"填符号"到"选子集使和为 x"这个数学转化：`x = (target + sum) / 2`。这一步要是想不到，后面的背包模型根本无从下手，所以说这才是真正的难点。
- dp 数组的含义从"最大价值"变成了"方案数"，递推公式也从 max/min 变成了累加 `dp[j] += dp[j-nums[i]]`，这是计数类背包问题的通用写法，一定要跟最优化类背包问题区分开，别搞混了。
- 遍历顺序依然遵循 01 背包的老结论：容量维度倒序遍历，这样才能防止同一个数字在同一轮被选用两次。
- 提前处理好奇偶性和绝对值越界这两种边界情况，能避免数组开出负数长度，或者做一堆没意义的计算。
