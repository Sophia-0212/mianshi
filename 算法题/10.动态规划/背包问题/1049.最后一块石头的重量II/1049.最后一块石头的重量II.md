# 1049. 最后一块石头的重量 II

**题目描述**

有一堆石头，用整数数组 `stones` 表示，其中 `stones[i]` 表示第 `i` 块石头的重量。每一回合，可以从中选出任意两块石头，然后将它们一起粉碎。假设石头的重量分别为 `x` 和 `y`，且 `x <= y`，那么粉碎的可能结果如下：

- 如果 `x == y`，那么两块石头都会被完全粉碎；
- 如果 `x != y`，那么重量为 `x` 的石头将会完全粉碎，而重量为 `y` 的石头新重量为 `y - x`。

最后，最多只会剩下一块石头。返回此石头的最小可能重量。如果没有石头剩下，返回0。

```
示例：
输入：stones = [2,7,4,1,8,1]
输出：1
解释：
组合 2 和 4，得到 2，故数组转化为 [2,7,1,8,1]，
组合 7 和 8，得到 1，故数组转化为 [2,1,1,1]，
组合 2 和 1，得到 1，故数组转化为 [1,1,1]，
组合 1 和 1，得到 0，故数组转化为 [1]，
此时数组中只剩下一块石头的重量为1，这就是最小可能的重量。
```

## 思路

### 问题转化：从"两两撞击"到"分堆求差"

这道题表面上是在模拟"石头两两撞击"的过程，如果真按题目描述去模拟撞击顺序，会非常复杂，而且撞击的先后顺序对最终结果的影响也不直观。这里得换一个角度看这个问题的本质。

关键观察是这样的：不管撞击的顺序如何安排，最终的效果都等价于——把所有石头分成两堆，一堆记为正（pos），一堆记为负（neg），最后剩下的重量就是这两堆重量之差的绝对值 `|sum(pos) - sum(neg)|`。为什么呢？因为每一次"y-x"的撞击，本质上就是在给某几块石头的重量做正负抵消，最终所有石头都会被归入"正贡献"或"负贡献"两个阵营中的一个，抵消后剩下的就是两阵营总重量的差值。

那问题就变成了：**如何把石头分成两堆，使得两堆的重量尽可能接近**，这样两堆之差（也就是最后剩下的石头重量）就会尽可能小。

这个"分成两堆让重量尽量接近"的思路，和上一题（分割等和子集）的转化方式高度相似——同样是转化为01背包问题：设石头总重量为 `sum`，令背包容量 `target = sum / 2`（整数除法，向下取整），把每块石头当作物品，`weight[i] = value[i] = stones[i]`，用01背包求出**其中一堆最多能凑到多接近target的重量**，即 `dp[target]`。

设 `dp[target]` 求出的这一堆重量为 `p`，那么另一堆的重量就是 `sum - p`。因为 `dp[target]` 是在不超过target（即不超过sum一半）的前提下取到的最大值，所以必然有 `p <= sum - p`，也就是说 `p` 是较小的一堆，`sum - p` 是较大的一堆。两堆之差即为最终答案：

```
答案 = (sum - p) - p = sum - 2p = sum - 2 * dp[target]
```

### DP五部曲

**1. 确定dp数组（下标）的含义**

采用一维滚动数组。`dp[j]` 表示：**从石头中选取若干块（每块最多选一次），放入一个容量为j的背包，能够凑出的、不超过j的最大重量（这里weight和value都等于石头自身重量）。**

**2. 确定递推公式**

对每块石头 `stones[i]`：

```
dp[j] = max(dp[j], dp[j - stones[i]] + stones[i])   # 核心递推：这块石头分不分到"较小堆"里，取较大值
```

不选：`dp[j]` 不变；选（前提 `j >= stones[i]`）：`dp[j] = dp[j-stones[i]] + stones[i]`，两者取大。

**3. dp数组如何初始化**

`dp[0] = 0`，容量为0时凑不出任何重量。其余 `dp[j]`（j从1到target）初始化为0，理由和上一题相同——权重不可能为负，初始0不会干扰后续max比较，且会被递推逐步覆盖。

**4. 确定遍历顺序**

同样遵循01背包一维数组的固定范式：外层遍历物品（每块石头），内层遍历容量且从大到小倒序，直到当前石头重量为止：

```
for i in 0..n-1:                          # 外层遍历每块石头
    for j in target downto stones[i]:     # 内层容量倒序遍历
        dp[j] = max(dp[j], dp[j-stones[i]] + stones[i])
```

**5. 举例推导dp数组验证**

咱们用示例 `stones = [2,7,4,1,8,1]`，`sum = 2+7+4+1+8+1 = 23`，`target = 23/2 = 11`（向下取整）。

初始：`dp[0..11]` 全部为0。

**处理 stones[0]=2**（j从11倒序到2）：只有 `j=2` 时 `dp[2]=max(0, dp[0]+2)=2`，其余j此时对应的 `dp[j-2]` 仍是0（还没有别的石头参与），不会产生新的非零值。处理后仅 `dp[2]=2`，其余为0。

**处理 stones[1]=7**（j从11倒序到7）：
- `j=11`：`dp[11]=max(0, dp[4]+7)=max(0,0+7)=7`
- `j=10`：`dp[10]=max(0, dp[3]+7)=7`
- `j=9`：`dp[9]=max(0, dp[2]+7)=max(0,2+7)=9`
- `j=8`：`dp[8]=max(0, dp[1]+7)=7`
- `j=7`：`dp[7]=max(0, dp[0]+7)=7`

处理后：`dp = [0,0,2,0,0,0,0,7,7,9,7,7]`（下标0到11）。

**处理 stones[2]=4**（j从11倒序到4）：
- `j=11`：`dp[11]=max(7, dp[7]+4)=max(7,7+4)=11`
- `j=10`：`dp[10]=max(7, dp[6]+4)=max(7,0+4)=7`
- `j=9`：`dp[9]=max(9, dp[5]+4)=max(9,0+4)=9`
- `j=8`：`dp[8]=max(7, dp[4]+4)=max(7,0+4)=7`
- `j=7`：`dp[7]=max(7, dp[3]+4)=max(7,0+4)=7`
- `j=6`：`dp[6]=max(0, dp[2]+4)=max(0,2+4)=6`
- `j=5`：`dp[5]=max(0, dp[1]+4)=4`
- `j=4`：`dp[4]=max(0, dp[0]+4)=4`

处理后：`dp = [0,0,2,0,4,4,6,7,7,9,7,11]`。此时 `dp[11]` 已经达到target=11，后面即使继续处理剩余石头也不会超过target（因为target是理论上限），只可能维持或者被其他组合同样凑到11。

**处理 stones[3]=1**（j从11倒序到1）：`dp[11]=max(11, dp[10]+1)=max(11,7+1)=11`（不变）；其余格子可能有小幅更新，但不影响最终 `dp[11]`。

**处理 stones[4]=8、stones[5]=1**：同理，`dp[11]` 已经是target=11这个理论上限，后续不会再增大。

最终 `dp[target] = dp[11] = 11`。代入公式：

```
答案 = sum - 2 * dp[target] = 23 - 2*11 = 1
```

结果为1，跟题目示例给出的答案完全一致。这里 `dp[11]=11` 对应的具体分堆方式是选出重量和为11的一堆（比如2+4+1+4，不过这里没有两个4，实际上是2+4+1+... 需要保证选出的石头重量和恰好为11，例如7+4=11，或者2+8+1=11等等，只要总和为11即可），另一堆的重量则是23-11=12，两堆之差为1，正好对应最后剩下的石头重量。

### 复杂度分析

设石头数量为n，总重量为sum，背包容量target=sum/2：

- 时间复杂度：O(n × target)
- 空间复杂度：O(target)

## 代码

### C++

```cpp
class Solution {
public:
    int lastStoneWeightII(vector<int>& stones) {
        int sum = 0;
        for (int s : stones) sum += s;              // 求石头总重量
        int target = sum / 2;                        // 背包容量：较小堆的理论上限

        vector<int> dp(target + 1, 0);               // dp[j]：容量j下能凑出的最大重量
        for (int i = 0; i < stones.size(); i++) {    // 外层：遍历每块石头
            for (int j = target; j >= stones[i]; j--) { // 内层：容量倒序遍历，01背包关键
                dp[j] = max(dp[j], dp[j - stones[i]] + stones[i]); // 核心递推：该石头分不分入较小堆
            }
        }
        return sum - 2 * dp[target]; // 两堆之差：较大堆(sum-dp[target]) - 较小堆(dp[target])
    }
};
```

### Python

```python
class Solution:
    def lastStoneWeightII(self, stones: list[int]) -> int:
        total = sum(stones)              # 求石头总重量
        target = total // 2              # 背包容量：较小堆的理论上限

        dp = [0] * (target + 1)          # dp[j]：容量j下能凑出的最大重量
        for stone in stones:                       # 外层：遍历每块石头
            for j in range(target, stone - 1, -1):   # 内层：容量倒序遍历，01背包关键
                dp[j] = max(dp[j], dp[j - stone] + stone)  # 核心递推：该石头分不分入较小堆

        return total - 2 * dp[target]  # 两堆之差
```

### Go

```go
func lastStoneWeightII(stones []int) int {
    sum := 0
    for _, s := range stones {
        sum += s // 求石头总重量
    }
    target := sum / 2 // 背包容量：较小堆的理论上限

    dp := make([]int, target+1) // dp[j]：容量j下能凑出的最大重量
    for _, stone := range stones { // 外层：遍历每块石头
        for j := target; j >= stone; j-- { // 内层：容量倒序遍历，01背包关键
            if dp[j-stone]+stone > dp[j] {
                dp[j] = dp[j-stone] + stone // 核心递推：该石头分不分入较小堆
            }
        }
    }
    return sum - 2*dp[target] // 两堆之差
}
```

## 总结

- 本题的转化思路是"两两撞击"等价于"分成两堆求重量差的绝对值"，这一步转化想清楚之后，问题就退化成了标准的01背包：让较小的一堆尽可能接近sum的一半。
- `target = sum / 2` 是较小堆重量的理论上限，`dp[target]` 求出的就是较小堆能达到的最大重量，答案公式为 `sum - 2*dp[target]`。
- 和分割等和子集一题的区别在于：本题不要求恰好装满（不用判断dp[target]是否等于target），只需要dp[target]本身尽可能大即可，因为最终答案是用总量减去两倍的dp[target]。
- 两题都属于"给定总量，把物品分成两部分，使某个指标相等或尽量接近"的题型，套路都是取总量的一半作为背包容量去做01背包。
