# 0063. 不同路径 II

**题目描述**

一个机器人位于一个 `m x n` 网格的左上角，机器人每次只能向下或者向右移动一步，机器人试图达到网格的右下角。现在考虑网格中有障碍物，那么从左上角到右下角将会有多少条不同的路径？网格用 `obstacleGrid` 表示，其中 `1` 表示障碍物，`0` 表示空地，机器人不能走进有障碍物的格子。

```
示例：
输入: obstacleGrid = [[0,0,0],[0,1,0],[0,0,0]]
输出: 2
解释: 3x3 网格的中间位置(1,1)有一个障碍物，
从左上角到右下角一共有 2 条不同的路径：
1. 向右 -> 向右 -> 向下 -> 向下
2. 向下 -> 向下 -> 向右 -> 向右
```

如果起点或终点本身就是障碍物，直接返回 0。

## 思路

这道题是上一题"不同路径"的进阶版，核心递推公式的思路不变，但因为多了障碍物这个限制，dp 数组的初始化和状态转移都要加一层判断逻辑，这也是这道题真正的难点所在，下面按 DP 五部曲展开分析。

**1. 确定 dp 数组（下标）的含义**

还是定义 `dp[i][j]` 表示从起点 `(0, 0)` 走到网格坐标 `(i, j)` 位置的不同路径数。跟上一题唯一的区别是，如果 `(i, j)` 本身是障碍物，那机器人根本不可能停在这个格子上，所以约定这时候 `dp[i][j] = 0`。

**2. 确定递推公式**

递推公式在非障碍物格子上，跟上一题完全一样：

```
dp[i][j] = dp[i-1][j] + dp[i][j-1]   （当(i,j)不是障碍物时）
dp[i][j] = 0                         （当(i,j)是障碍物时）
```

这里有个很容易被忽视、但非常关键的点要重点说一下：当我们套用 `dp[i][j] = dp[i-1][j] + dp[i][j-1]` 这条公式的时候，**完全不需要在公式里额外判断 `dp[i-1][j]` 或 `dp[i][j-1]` 是不是障碍物**。为什么呢？因为如果上方格子 `(i-1, j)` 是障碍物，按我们的约定它的值 `dp[i-1][j]` 早就已经被设成 0 了；同理左方格子如果是障碍物，`dp[i][j-1]` 也已经是 0。0 加上任何值，或者两边都是 0，天然就正确地表示"这条来源路径不可用"，不会给总和带来任何多余的贡献。也就是说，障碍物的影响是通过"把值设为 0"自动往后传递的，递推公式本身不需要感知障碍物，只需要在给当前格子赋值之前先判断"我自己是不是障碍物"就够了。

**3. dp 数组如何初始化**

初始化是这道题的核心难点。第一行 `dp[0][j]` 和第一列 `dp[i][0]` 不能像上一题那样简单地全设成 1，而要考虑障碍物的阻断效应：

- 对第一行：从左往右遍历 `j = 0, 1, ..., n-1`，只要当前格子 `(0, j)` 不是障碍物，就设 `dp[0][j] = 1`；但一旦遇到某个 `j` 位置是障碍物，`dp[0][j]` 直接设为 0，而且**从这个障碍物开始，之后所有 `j' > j` 的格子也必须全部是 0**，不能再设成 1。
- 对第一列同理：从上往下遍历，一旦遇到障碍物，该格子及其之后的所有格子都设为 0。

为什么障碍物之后的整行/整列都要清零呢？因为第一行和第一列的格子只能靠"一直沿着边缘走一个方向"到达（第一行只能一路向右，第一列只能一路向下），一旦中途被障碍物挡住，机器人绝对没办法绕路（想绕路就必须先向下再向右回到边缘，但那样就已经离开第一行/第一列了，不在我们讨论的这段初始化范围内，而是要进入内部的递推来处理，可内部递推同样依赖这段边缘的值，如果边缘错误地保留了 1，会导致后面的路径数被错误地叠加），所以必须严格地把障碍物之后的边缘格子清零，这样才能保证后续二维递推的正确性。

如果起点 `(0, 0)` 本身就是障碍物，那就直接让整个 dp 表都保持 0（或者提前特判返回 0）就行。

**4. 确定遍历顺序**

跟上一题一样，还是外层从上到下遍历行、内层从左到右遍历列，保证算 `dp[i][j]` 时它依赖的上方格子和左方格子都已经算完。对每个格子，先判断是不是障碍物：如果是，`dp[i][j]` 保持（或设为）0，跳过递推公式；如果不是，才套用 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`。

**5. 举例推导 dp 数组验证**

拿题目给的示例来说，`obstacleGrid = [[0,0,0],[0,1,0],[0,0,0]]`，是一个 3x3 网格，中间 `(1,1)` 是障碍物。

先初始化第一行：`(0,0)=0` 不是障碍物 -> `dp[0][0]=1`；`(0,1)=0` 不是障碍物 -> `dp[0][1]=1`；`(0,2)=0` 不是障碍物 -> `dp[0][2]=1`。第一行没有障碍物，全部是 1。

初始化第一列：同理，第一列也没有障碍物，`dp[0][0]=1, dp[1][0]=1, dp[2][0]=1`。

接下来逐格递推：

- `(1,1)` 是障碍物，直接 `dp[1][1] = 0`。
- `(1,2)` 不是障碍物：`dp[1][2] = dp[0][2] + dp[1][1] = 1 + 0 = 1`。
- `(2,1)` 不是障碍物：`dp[2][1] = dp[1][1] + dp[2][0] = 0 + 1 = 1`。
- `(2,2)` 不是障碍物：`dp[2][2] = dp[1][2] + dp[2][1] = 1 + 1 = 2`。

最终 dp 表为：

```
1  1  1
1  0  1
1  1  2
```

`dp[2][2] = 2`，跟题目给的答案完全一致，你可以清楚看到障碍物 `(1,1)` 的那个 0 是怎么"传递"影响到 `(1,2)` 和 `(2,1)`，最终共同决定了终点的路径数只有 2 条。

**复杂度分析**

时间复杂度：还是要遍历整张 `m x n` 网格一次，每个格子的判断和计算都是 O(1)，所以总时间复杂度是 O(m × n)。

空间复杂度：用了一张 `m x n` 的二维数组，空间复杂度是 O(m × n)。同样可以用一维滚动数组优化到 O(n)，只是遇到障碍物的时候需要把对应位置手动清零，思路跟二维版本一致，这里就不展开代码了。

## 代码

### C++

```cpp
class Solution {
public:
    int uniquePathsWithObstacles(vector<vector<int>>& obstacleGrid) {
        int m = obstacleGrid.size(), n = obstacleGrid[0].size();
        vector<vector<int>> dp(m, vector<int>(n, 0));

        // 初始化第一列：遇到障碍物后，之后的格子全部保持为0（无法绕过）
        for (int i = 0; i < m && obstacleGrid[i][0] == 0; i++) {
            dp[i][0] = 1;
        }
        // 初始化第一行：遇到障碍物后，之后的格子全部保持为0
        for (int j = 0; j < n && obstacleGrid[0][j] == 0; j++) {
            dp[0][j] = 1;
        }

        for (int i = 1; i < m; i++) {
            for (int j = 1; j < n; j++) {
                if (obstacleGrid[i][j] == 1) {
                    dp[i][j] = 0; // 当前格子是障碍物，机器人无法停留，路径数为0
                    continue;
                }
                // 递推公式：不是障碍物时，路径数=上方路径数+左方路径数
                // 若上方或左方是障碍物，其dp值早已是0，会自动正确地传递
                dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
            }
        }
        return dp[m - 1][n - 1];
    }
};
```

class Solution:
    def uniquePathsWithObstacles(self, obstacleGrid: list[list[int]]) -> int:
        m, n = len(obstacleGrid), len(obstacleGrid[0])
        dp = [[0] * n for _ in range(m)]

        # 初始化第一列，遇到障碍物后停止赋1，后面保持默认的0

            dp[0][j] = 1

func uniquePathsWithObstacles(obstacleGrid [][]int) int {
    m, n := len(obstacleGrid), len(obstacleGrid[0])
    dp := make([][]int, m)
    for i := range dp {
        dp[i] = make([]int, n)
    }

    // 初始化第一列：遇到障碍物后不再赋1，后续保持初始的0
    for i := 0; i < m && obstacleGrid[i][0] == 0; i++ {
        dp[i][0] = 1
    }
    // 初始化第一行：遇到障碍物后不再赋1
    for j := 0; j < n && obstacleGrid[0][j] == 0; j++ {
        dp[0][j] = 1
    }

    for i := 1; i < m; i++ {
        for j := 1; j < n; j++ {
            if obstacleGrid[i][j] == 1 {
                dp[i][j] = 0 // 障碍物格子，路径数为0
                continue
            }
            // 递推：路径数=上方+左方；上方或左方若是障碍物其值已是0，自动正确传递
            dp[i][j] = dp[i-1][j] + dp[i][j-1]
        }
    }

    return dp[m-1][n-1]
}

## 总结

- 递推公式的核心思路跟"不同路径"这一题完全一致，这道题的难点全都集中在初始化和障碍物判断上，而不在递推逻辑本身。
- 第一行/第一列初始化时一旦碰到障碍物，之后的整行/整列都必须保持为 0，因为沿边缘走一旦被挡住就彻底没法绕路。
- 递推公式内部不需要专门判断上方/左方格子是不是障碍物，因为障碍物格子的 dp 值本来就是 0，会自动正确地往下游传递"此路不通"这个信息。
- 这种"用 0 表示不可达，让 0 在状态转移中自然传播"的技巧，在很多带约束条件的网格 DP 题目里都会用到，是处理约束条件的常见通用手段。
