# 0673. 最长递增子序列的个数

**题目描述**

给定一个未排序的整数数组 `nums`，返回最长递增子序列的个数（子序列不要求连续，但要求严格递增）。

```
示例：
输入: nums = [1,3,5,4,7]
输出: 2
解释: 最长递增子序列的长度是4，有两种方案得到长度为4的递增子序列，分别是 [1,3,4,7] 和 [1,3,5,7]。

输入: nums = [2,2,2,2,2]
输出: 5
解释: 最长递增子序列的长度是1，方案有5种，即选取数组中任意一个单独的元素。
```

## 思路

这道题是300题「最长递增子序列」的进阶版本，300题只需要求出最长递增子序列的**长度**，这道题还要求出有多少种**不同的方案**能达到这个最长长度。既然是在300题基础上的延伸，自然要沿用300题的状态定义，再新增一个用来统计方案数的数组，做"双重DP"（两个数组同步更新，但含义不同、更新逻辑也不同）。

**状态定义**：

- `dp[i]` 表示以 `nums[i]` 作为结尾的最长递增子序列的长度（这和300题完全一样）。
- `count[i]` 表示以 `nums[i]` 作为结尾、且长度恰好为 `dp[i]`（也就是"以nums[i]结尾能达到的最长长度"）的递增子序列，有多少种不同的方案。

这两个数组要同步维护：`dp[i]` 回答"以i结尾最长能有多长"，`count[i]` 回答"达到这个最长长度有几种走法"。

**初始化**：每个位置单独自己就构成一个长度为1的递增子序列，所以 `dp[i]` 初始化为1（每个元素本身都是长度至少为1的递增子序列）；对应地，达到长度1的方案数显然是唯一的（就是它自己），所以 `count[i]` 初始化为1。

**状态转移方程（这道题的核心难点）**：

对于每个 `i`，向前遍历所有 `j`（`0 <= j < i`），检查 `nums[j] < nums[i]` 是否成立——只有满足这个条件，才能把 `nums[j]` 结尾的子序列接上 `nums[i]`，构成一个新的、以 `nums[i]` 结尾、长度为 `dp[j]+1` 的递增子序列。一旦满足 `nums[j] < nums[i]`，接下来要分两种情况讨论"如何更新 `dp[i]` 和 `count[i]`"：

**情况一：`dp[j] + 1 > dp[i]`**。这说明通过 `j` 这条路径接过来，能构成一个比"目前已知以i结尾的最长长度"更长的子序列——说白了就是发现了一条全新的、更优的最长路径。既然长度记录被刷新了，那之前累积的 `count[i]`（对应的是旧的、较短的最长长度下的方案数）就完全没意义了，必须清空重新赋值，而不能累加。所以这里的更新是：

```
dp[i] = dp[j] + 1
count[i] = count[j]   // 重新赋值，不是累加！
```

为什么是"重新赋值"而不是"累加"呢：因为在发现这条更长路径之前，`count[i]` 里保存的方案数都是对应旧的、较短长度的方案，这些方案已经不能代表"以i结尾的最长递增子序列"了（它们比新发现的路径短），所以必须完全丢弃，只保留新长度对应的方案数，即 `count[j]`（因为这次是通过j转移过来的，方案数直接继承j的方案数）。

**情况二：`dp[j] + 1 == dp[i]`**。这说明通过 `j` 这条路径接过来得到的长度，正好和"目前已知以i结尾的最长长度"相等——说白了就是发现了另一条**同样长**、能达到相同最长长度的路径，这是一条与之前记录并列的等长方案，不应该覆盖，而应该把这条新路径带来的方案数累加进去：

```
count[i] += count[j]   // 累加，因为是并列的等长方案
```

这两种情况的判断条件（`>` 还是 `==`）正是这道题最容易出错、也最需要讲透的地方：**判断的本质是在问"这次转移是刷新了最长记录，还是追平了最长记录"**。刷新记录（`>`）意味着旧方案数全部作废，只能重新赋值；追平记录（`==`）意味着旧方案数依然有效，只是又多了一种新的走法达到同样的长度，需要累加。如果不区分这两种情况、一律用 `+=` 累加，会把"更短路径下的旧方案数"错误地也算进最终答案，导致结果偏大；如果一律用 `=` 赋值，则会在追平的场景下把之前已经统计到的方案数覆盖丢失，导致结果偏小。这两种错误在实际调试时都不容易一眼看出来，必须在写代码之前先把这个判断逻辑想清楚。

**最终答案的汇总**：遍历完所有 `i` 之后，先找出全局最长递增子序列的长度 `maxLen = max(dp)`，再把所有满足 `dp[i] == maxLen` 的下标对应的 `count[i]` 累加起来，就是最终答案。这一步是因为最长递增子序列可能以数组中不同的位置结尾（比如示例1中 `[1,3,4,7]` 以下标4结尾，`[1,3,5,7]` 也以下标4结尾，但如果换一个例子，最长子序列也可能分别以不同下标结尾），必须把所有"以某个位置结尾且恰好达到全局最长长度"的方案数全部加总，才能得到完整的答案。

**举例验证**：以 `nums = [1,3,5,4,7]` 为例手推。`dp[0]=1, count[0]=1`（对应 [1]）。`dp[1]`：只有 `nums[0]=1<3`，`dp[0]+1=2>dp[1]`初始值1，刷新，`dp[1]=2, count[1]=count[0]=1`（对应 [1,3]）。`dp[2]`（`nums[2]=5`）：`nums[0]=1<5`，`dp[0]+1=2>dp[2]`初始1，刷新，`dp[2]=2, count[2]=count[0]=1`；再看 `nums[1]=3<5`，`dp[1]+1=3>dp[2]`当前2，再次刷新，`dp[2]=3, count[2]=count[1]=1`（对应 [1,3,5]）。`dp[3]`（`nums[3]=4`）：`nums[0]=1<4`，`dp[0]+1=2>dp[3]`初始1，刷新为2，`count[3]=1`；`nums[1]=3<4`，`dp[1]+1=3>2`，刷新为3，`count[3]=count[1]=1`；`nums[2]=5`不小于4，跳过。最终 `dp[3]=3, count[3]=1`（对应 [1,3,4]）。`dp[4]`（`nums[4]=7`）：`nums[0]=1<7`，`dp[0]+1=2>dp[4]`初始1，刷新，`dp[4]=2,count[4]=1`；`nums[1]=3<7`，`dp[1]+1=3>2`，刷新，`dp[4]=3,count[4]=count[1]=1`；`nums[2]=5<7`，`dp[2]+1=4>3`，刷新，`dp[4]=4,count[4]=count[2]=1`；`nums[3]=4<7`，`dp[3]+1=4==dp[4]`当前4，追平，累加，`count[4]+=count[3]`，即 `count[4]=1+1=2`。全局 `maxLen=4`，只有下标4满足 `dp[i]==4`，答案就是 `count[4]=2`，跟示例结果一致，也印证了 [1,3,5,7] 和 [1,3,4,7] 两条路径分别被正确统计并在下标4处合并累加。

**复杂度说一下**：双重循环，外层 `i` 从0到n-1，内层 `j` 从0到i-1，时间复杂度O(n²)；额外用了两个长度为n的一维数组，空间复杂度O(n)。

## 代码

### C++

```cpp
class Solution {
public:
    int findNumberOfLIS(vector<int>& nums) {
        int n = nums.size();
        vector<int> dp(n, 1), count(n, 1); // 每个元素单独成序列，长度1，方案数1
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {           // 只有严格递增才能转移
                    if (dp[j] + 1 > dp[i]) {        // 情况一：发现更长路径，刷新记录
                        dp[i] = dp[j] + 1;
                        count[i] = count[j];        // 重新赋值，旧方案数作废
                    } else if (dp[j] + 1 == dp[i]) { // 情况二：追平最长记录，累加方案
                        count[i] += count[j];
                    }
                }
            }
        }
        int maxLen = *max_element(dp.begin(), dp.end()); // 全局最长长度
        int result = 0;
        for (int i = 0; i < n; i++) {
            if (dp[i] == maxLen) {
                result += count[i];  // 累加所有达到最长长度的方案数
            }
        }
        return result;
    }
};
```

                    dp[i] = dp[j] + 1
                    count[i] = count[j] // 重新赋值，旧方案数作废
                } else if dp[j]+1 == dp[i] { // 情况二：追平最长记录，累加方案
                    count[i] += count[j]
                }
            }
        }
    }

    for _, v := range dp {
        if v > maxLen {

        if dp[i] == maxLen {
            result += count[i] // 累加所有达到最长长度的方案数
        }
    }

## 总结

- 这道题的核心是"双重DP"：`dp[i]` 沿用300题的定义记录长度，`count[i]` 是新增的、专门记录方案数的数组，两者必须同步更新，且更新逻辑不同——这是"在已有DP基础上扩展统计维度"的典型技巧，遇到"不仅要求最优值、还要求方案数"的题目都可以借鉴这个模式。
- 最容易出错的地方是 `dp[j]+1 > dp[i]` 与 `dp[j]+1 == dp[i]` 这两种情况的区分：前者是发现更优解，必须清空重新赋值；后者是发现同样优的并列解，需要累加。混淆两者会导致方案数统计错误（多算或少算）。
- 最终答案要遍历所有 `dp[i] == maxLen` 的位置并累加对应 `count[i]`，因为最长递增子序列可能在数组中以多个不同的位置结尾，不能只看某一个位置的 `count`。
- 这道题和300题的关系类似"求最优值"与"求最优方案数"的一般性扩展关系，做完300题后再做这道题，可以体会同一个状态定义如何被复用并附加统计信息，这也是动态规划题型训练中常见的递进式练习方式。
