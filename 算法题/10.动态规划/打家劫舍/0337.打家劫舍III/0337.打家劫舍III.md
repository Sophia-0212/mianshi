# 337. 打家劫舍 III

**题目描述**

小偷发现新的可以偷窃的地区，这个地区所有房屋的排列不是链式而是二叉树结构。每个节点是一间房屋，如果两间直接相连的房屋（即父节点和子节点）在同一晚上被偷，房屋将自动报警。给定二叉树的根节点 `root`，计算在不触动警报的情况下，小偷一晚能够偷窃的最高金额。

```
示例：
输入: root = [3,2,3,null,3,null,1]
        3
       / \
      2   3
       \   \
        3   1
输出: 7
解释: 小偷一晚能够偷窃的最高金额是 3 + 3 + 1 = 7（偷根节点的两个孙子节点3和1，以及左子节点下的3）。
```

## 思路

前两题（198、213）处理的都是线性结构，房屋排成一排或一圈，可以用一维数组按下标顺序递推。但本题的房屋组织成二叉树，节点之间没有"下标顺序"这个概念，没法直接套用一维 dp 数组。这就需要把 DP 的思想从线性结构推广到树形结构上，用递归代替循环来完成状态转移。我还是按 DP 五部曲梳理，但五部曲在树形结构上会有不同的呈现形式。

**1. 确定 dp 数组（含下标）的含义——这里是"状态数组"而不是下标数组**

线性 DP 中 `dp[i]` 的下标 `i` 对应数组位置，但树上没有这种线性下标。树形 DP 的做法是：**为每个节点关联一个长度为 2 的状态数组**，而不是全局的一维数组。对于二叉树上的每一个节点 `cur`，我定义：

- `dp[0]`：不偷 `cur` 这个节点时，以 `cur` 为根的子树能获得的最大金额；
- `dp[1]`：偷 `cur` 这个节点时，以 `cur` 为根的子树能获得的最大金额。

这里必须用"数组（两个状态）"而不是"单个值"来表示每个节点的最优解，为什么呢？因为线性结构中 `dp[i-1]` 天然包含了"第 i-1 个位置偷或不偷"两种可能里的较优值，因为线性遍历是单向的，后面的状态可以放心地只依赖一个综合值。但树形结构中，父节点要不要偷，取决于子节点偷还是不偷这两种情况分别的结果，而不是子节点的综合最优值——如果只给子节点保留一个"综合最优值"，父节点在计算"偷自己"这个分支时，就没法知道"子节点不偷"这一种情况下具体能拿多少钱。所以每个节点必须同时保留"偷"和"不偷"两个状态，供父节点按需选用，这是树形 DP 相比线性 DP 多出来的关键技巧。

**2. 确定递推公式**

设当前节点为 `cur`，其左子节点返回的状态数组为 `left = [left[0], left[1]]`，右子节点返回的状态数组为 `right = [right[0], right[1]]`。

- **不偷当前节点**（`val0`）：当前节点不偷，那么左右孩子分别既可以偷也可以不偷，各自选择较优的那种情况，两者互不影响，直接相加：

```
val0 = max(left[0], left[1]) + max(right[0], right[1])
```

- **偷当前节点**（`val1`）：一旦偷了当前节点，左右孩子（作为直接相连的父子关系）就都不能偷，只能取孩子"不偷"状态下的值，加上当前节点自身的金额：

```
val1 = nums[cur] + left[0] + right[0]
```

这两个式子分别对应"不偷/偷当前节点"两种互斥选择，节点 `cur` 最终返回 `[val0, val1]` 交给它的父节点使用。

**3. dp 数组如何初始化**

树形 DP 的"初始化"对应的是递归的终止条件（base case）：当遍历到空节点（某个节点没有左孩子或没有右孩子）时，返回 `[0, 0]`——空节点没有房屋，不偷是唯一选择，偷与不偷的收益都是 0。这一步保证了递归到叶子节点时，叶子节点的左右孩子（即空节点）能提供正确的边界值：叶子节点的 `val0 = max(0,0)+max(0,0) = 0`，`val1 = nums[叶子] + 0 + 0 = nums[叶子]`，符合直觉（叶子节点不偷收益为0，偷收益就是自身金额）。

**4. 确定遍历顺序**

必须使用**后序遍历**（左 → 右 → 中）。为什么呢？因为父节点的状态计算依赖左右孩子的状态数组已经算出来，也就是子问题必须先于父问题求解——这正好对应树形结构里"先处理子树，再处理根"的后序遍历顺序。如果用前序遍历（先处理父节点），会出现父节点计算时子节点状态还未知的问题，递推没法进行。

**5. 举例推导**

我拿示例 `root = [3,2,3,null,3,null,1]` 来推一下（结构见上方示例代码块），从叶子节点开始自底向上计算：

- 节点 `3`（左子树最深的叶子，2的右孩子）：无子节点，返回 `[0, 3]`。
- 节点 `2`：左孩子为空返回 `[0,0]`，右孩子是上面的节点3返回 `[0,3]`。
  - `val0 = max(0,0) + max(0,3) = 3`（不偷2，右孩子选择偷，拿到3）
  - `val1 = 2 + 0 + 0 = 2`（偷2，左右孩子都只能取"不偷"状态，均为0）
  - 节点2返回 `[3, 2]`
- 节点 `1`（右子树最深的叶子，3的右孩子）：无子节点，返回 `[0, 1]`。
- 节点 `3`（根的右孩子）：左孩子为空返回 `[0,0]`，右孩子是节点1返回 `[0,1]`。
  - `val0 = max(0,0) + max(0,1) = 1`
  - `val1 = 3 + 0 + 0 = 3`
  - 该节点返回 `[1, 3]`
- 根节点 `3`：左孩子是节点2返回 `[3,2]`，右孩子是节点3返回 `[1,3]`。
  - `val0 = max(3,2) + max(1,3) = 3 + 3 = 6`（根不偷，左孩子选"不偷"拿3，右孩子选"偷"拿3）
  - `val1 = 3 + 3 + 1 = 7`（根偷，左右孩子都只能取"不偷"状态：left[0]=3, right[0]=1）
  - 根节点返回 `[6, 7]`

最终答案是 `max(6, 7) = 7`，跟预期输出一致。

**复杂度分析**

- 时间复杂度：O(n)，每个节点只会被访问一次（后序遍历），n 为树中节点总数。
- 空间复杂度：O(h)，h 为树的高度，即递归调用栈的深度（最坏情况树退化为链，h = n）。

## 代码

### C++

```cpp
class Solution {
public:
    // 返回长度为2的数组：[0]表示不偷当前节点的最大金额，[1]表示偷当前节点的最大金额
    pair<int, int> robTree(TreeNode* cur) {
        if (cur == nullptr) return {0, 0};  // 空节点：偷与不偷收益都是0

        auto left = robTree(cur->left);    // 后序遍历：先递归处理左子树
        auto right = robTree(cur->right);  // 再递归处理右子树

        // 不偷当前节点：左右孩子各自选择偷或不偷中较优的情况，互不影响
        int val0 = max(left.first, left.second) + max(right.first, right.second);
        // 偷当前节点：左右孩子必须都不偷，只能取它们"不偷"状态的值
        int val1 = cur->val + left.first + right.first;

        return {val0, val1};  // 把两种状态交给父节点使用
    }

    int rob(TreeNode* root) {
        auto result = robTree(root);          // 对根节点做树形DP
        return max(result.first, result.second); // 根节点偷或不偷取较优
    }
};
```

class Solution {
    public int rob(TreeNode root) {
        int[] result = robTree(root);           // 对根节点做树形DP，返回[不偷,偷]两个状态
        return Math.max(result[0], result[1]);  // 根节点偷或不偷取较优
    }

    // 返回长度为2的数组：[0]不偷当前节点的最大金额，[1]偷当前节点的最大金额
    private int[] robTree(TreeNode cur) {
        if (cur == null) {
            return new int[]{0, 0};  // 空节点：偷与不偷收益都是0
        }

        int[] left = robTree(cur.left);    // 后序遍历：先处理左子树
        int[] right = robTree(cur.right);  // 再处理右子树

        // 不偷当前节点：左右孩子各自取偷/不偷中较优的一种，互不影响
        int val0 = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);
        // 偷当前节点：左右孩子必须都不偷，取它们"不偷"状态的值
        int val1 = cur.val + left[0] + right[0];

        return new int[]{val0, val1};  // 把两种状态交给父节点使用
    }
}

// robTree 返回长度为2的数组：[0]不偷当前节点的最大金额，[1]偷当前节点的最大金额
func robTree(cur *TreeNode) [2]int {
    if cur == nil {
        return [2]int{0, 0} // 空节点：偷与不偷收益都是0
    }

    left := robTree(cur.Left)   // 后序遍历：先递归处理左子树
    right := robTree(cur.Right) // 再递归处理右子树

    // 不偷当前节点：左右孩子各自选择偷/不偷中较优的情况，互不影响
    val0 := max(left[0], left[1]) + max(right[0], right[1])
    // 偷当前节点：左右孩子必须都不偷，只能取它们"不偷"状态的值
    val1 := cur.Val + left[0] + right[0]

    return [2]int{val0, val1} // 把两种状态交给父节点使用
}

func rob(root *TreeNode) int {
    result := robTree(root)            // 对根节点做树形DP
    return max(result[0], result[1])   // 根节点偷或不偷取较优
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}

## 总结

- 树形 DP 的核心是把线性 DP 中"按下标顺序递推"的思想，替换成"按后序遍历顺序、通过递归返回值传递状态"，本质仍然是子问题最优解组合成父问题最优解，只是子问题之间的依赖关系由数组下标变成了树的父子关系。
- 每个节点必须返回"偷"和"不偷"两个状态（而不是一个综合最优值），是因为父节点在决定要不要偷自己时，需要精确知道"子节点不偷"这一种情况下的具体收益，如果子节点只给出一个笼统的最优值，父节点就没法拆分出这个信息。
- 递归的终止条件（空节点返回 `[0,0]`）对应线性 DP 里的初始化步骤，是整个递推能够正确启动的基础，容易被忽略导致空指针或者收益计算错误。
- 易错点在于"偷当前节点"的公式：必须用 `left[0]` 和 `right[0]`（孩子不偷的状态），而不是 `left[1]`、`right[1]` 或者笼统的孩子最优值，混淆这一点会导致方案中出现"父子同时被偷"的非法情况。
