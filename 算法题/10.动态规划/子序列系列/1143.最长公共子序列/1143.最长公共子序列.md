# 1143. 最长公共子序列

**题目描述**

给定两个字符串 `text1` 和 `text2`，求它们的最长公共子序列（Longest Common Subsequence，LCS）的长度。如果不存在公共子序列，返回 0。

这里"子序列"的定义是：可以从原字符串中删除任意个字符（也可以不删除），剩下的字符不改变原有的相对顺序所组成的新字符串。注意子序列不要求连续，这一点和"子数组/子串"完全不同。

```
示例：
输入: text1 = "abcde", text2 = "ace"
输出: 3
解释: 最长公共子序列是 "ace"，它的长度为 3。
```

要求：`text1`、`text2` 由小写英文字母组成，长度范围在 1 到 1000 之间。

## 思路

这是一道经典的双序列动态规划问题，咱们还是用"DP五部曲"来推导。

**1. 先确定dp数组以及下标的含义**

我把 `dp[i][j]` 定义为：`text1` 的前 `i` 个字符构成的子串，跟 `text2` 的前 `j` 个字符构成的子串，这两者的最长公共子序列长度是多少。

这里下标 `i`、`j` 是从 1 开始计数的，而不是直接用字符串的下标（从 0 开始）。为什么要这么做呢？你想啊，这样做的好处是可以很自然地表达"空字符串"这个边界情况：`dp[0][j]` 表示 `text1` 取 0 个字符（也就是空串）时跟 `text2` 前 `j` 个字符的最长公共子序列，这明显只能是 0；同理 `dp[i][0]` 也天然是 0。要是你直接用字符串下标从 0 开始定义 dp，反而还要额外处理 `i=0` 或 `j=0` 时没法访问 `dp[i-1]`/`dp[j-1]` 的问题，所以下标整体往右移一位，用"前 i 个字符"这种表述，是双序列 DP 里非常常见、也非常好用的一个技巧。

**2. 确定递推公式**

递推的时候要看 `text1` 的第 `i` 个字符（也就是 `text1[i-1]`，因为字符串下标从 0 开始）和 `text2` 的第 `j` 个字符（`text2[j-1]`）是不是相等，分两种情况：

- 如果 `text1[i-1] == text2[j-1]`：这说明这两个字符可以同时加进公共子序列里，那么 `dp[i][j] = dp[i-1][j-1] + 1`，也就是在"前 i-1 个字符与前 j-1 个字符的最长公共子序列"的基础上，再算上这一对相等的字符。

- 如果 `text1[i-1] != text2[j-1]`：这两个字符没法同时出现在同一个公共子序列里，毕竟它们本身就不相等嘛。但这里的关键是，这**不代表** `dp[i][j]` 就要归零了。这时候应该考虑两种可能：放弃 `text1` 的第 `i` 个字符（这时候最长公共子序列长度是 `dp[i-1][j]`），或者放弃 `text2` 的第 `j` 个字符（这时候是 `dp[i][j-1]`）。取这两者中大的那个：`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`。

第二种情况正是这道题最核心、也最容易在第一次接触时想错的地方，后面我会专门展开对比说明为什么。

**3. dp数组怎么初始化**

根据第一步的定义，`dp[i][0]` 表示 `text2` 取 0 个字符时的最长公共子序列长度，不管 `text1` 取多长都只能是 0，所以 `dp[i][0] = 0`（对所有 `i` 都成立）。同理 `dp[0][j] = 0`（对所有 `j` 都成立）。这也是为什么要把下标定义成"前 i 个字符"而不是直接用字符下标——第 0 行、第 0 列的初始化含义变得非常自然，不需要特殊讨论了。

**4. 确定遍历顺序**

`dp[i][j]` 的计算依赖 `dp[i-1][j-1]`（左上方）、`dp[i-1][j]`（正上方）、`dp[i][j-1]`（正左方）这三个已经算出来的值，所以遍历顺序是从上到下、从左到右，外层遍历 `i`（对应 `text1`），内层遍历 `j`（对应 `text2`），反过来也行，只要保证算 `dp[i][j]` 的时候，它依赖的那三个格子已经填好就没问题。

**5. 举个例子推一遍dp数组**

用示例 `text1 = "abcde"`，`text2 = "ace"` 来手推一遍二维表格（行是 `text1`，列是 `text2`，第 0 行/列是空串边界，全都是 0）：

```
      ""  a   c   e
  ""   0  0   0   0
  a    0  1   1   1
  b    0  1   1   1
  c    0  1   2   2
  d    0  1   2   2
  e    0  1   2   3
```

咱们挑几个关键格子说一下：
- `dp[1][1]`：`text1[0]='a'` 跟 `text2[0]='a'` 相等，所以 `dp[1][1] = dp[0][0] + 1 = 1`。
- `dp[2][1]`：`text1[1]='b'` 跟 `text2[0]='a'` 不相等，`dp[2][1] = max(dp[1][1], dp[2][0]) = max(1, 0) = 1`。你注意，这里没有清零，而是继承了上方 `dp[1][1]=1` 这个"已经找到的公共子序列长度"。
- `dp[4][2]`：`text1[3]='d'` 跟 `text2[1]='c'` 不相等，`dp[4][2] = max(dp[3][2], dp[4][1]) = max(2, 1) = 2`，同样是继承左上方向已经有的最大值，而不是归零。
- `dp[5][3]`：`text1[4]='e'` 跟 `text2[2]='e'` 相等，`dp[5][3] = dp[4][2] + 1 = 2 + 1 = 3`。

最终 `dp[5][3] = 3`，也就是最长公共子序列长度为 3（对应 "ace"），跟示例输出一致。

**复杂度分析**

时间复杂度是 O(n×m)，n、m 分别是 `text1`、`text2` 的长度，因为要填满整个二维 dp 表。空间复杂度同样是 O(n×m)。不过你会发现 `dp[i][j]` 只依赖上一行和当前行左边的值，所以可以用滚动数组把空间优化到 O(m)（只保留当前行和上一行，或者用一维数组配合"先取旧值再更新"的技巧），但这里为了逻辑讲得清楚，代码部分先给出二维数组的完整实现。

**本题跟 0718 最长重复子数组的核心区别（这里是重点）**

这是本题最值得花时间琢磨的地方。0718 题求的是"最长重复子数组"，本质上是两个数组的**最长公共子串（要求连续）**；1143 题求的是**最长公共子序列（不要求连续）**。两者的递推公式表面上看只差了"不匹配时怎么处理"这一步，但背后的设计思想完全不一样。

在 0718 题里，`dp[i][j]` 表示"以 `nums1[i-1]`、`nums2[j-1]` 结尾的最长公共子数组长度"，一旦 `nums1[i-1] != nums2[j-1]`，就说明以这两个位置结尾根本不可能存在公共部分（因为子数组要求连续，末尾字符必须匹配上），所以直接 `dp[i][j] = 0`，清零重新开始计数。这个"清零"是必须的，因为 dp 的定义本身就是"以某个位置结尾"，不匹配就意味着这个以它结尾的连续序列直接断掉了。

而在 1143 题里，`dp[i][j]` 表示的是"前 i 个字符和前 j 个字符的最长公共子序列长度"，这个定义本身就不要求子序列非得以 `text1[i-1]` 或 `text2[j-1]` 结尾。当 `text1[i-1] != text2[j-1]` 时，这只是说明"这两个具体字符凑不成一对"，但完全不影响之前已经在 `text1` 前 i-1 个字符与 `text2` 前 j 个字符之间（或者 `text1` 前 i 个字符与 `text2` 前 j-1 个字符之间）已经找到的那些公共子序列——它们依然合法有效，因为子序列本来就允许跳过任意字符。换句话说，遇到不匹配的时候，本质上是在做一个选择：要不要把 `text1` 当前这个字符纳入考虑（不纳入就是 `dp[i-1][j]`），要不要把 `text2` 当前这个字符纳入考虑（不纳入就是 `dp[i][j-1]`），两者取较大值，而不是把已有的成果直接推翻清零。

举个具体例子说明为什么不能清零：`text1 = "abc"`，`text2 = "adc"`。走到 `i=2, j=2` 时，`text1[1]='b'` 跟 `text2[1]='d'` 不相等。如果像 0718 那样清零，`dp[2][2]` 就会变成 0，但实际上 `text1` 前 2 个字符 "ab" 与 `text2` 前 2 个字符 "ad" 之间，公共子序列 "a" 依然存在，长度是 1（对应 `dp[1][1]=1`），这个信息不应该丢掉。继续往后走到 `i=3, j=3` 时，`text1[2]='c'` 跟 `text2[2]='c'` 相等，`dp[3][3] = dp[2][2] + 1`。要是 `dp[2][2]` 之前被误清零成了 0，最终结果就会错误地算成 1（"c"），可正确答案应该是 2（"ac"）。说白了就是因为子序列允许跳跃、不要求连续，之前已经匹配上的字符不会因为中间出现了一个不匹配的字符就作废。

所以我这么总结二者的分水岭：**"连续"型的子数组/子串 DP，不匹配就意味着断裂，必须清零重开；"不连续"型的子序列 DP，不匹配只是少了一种可能性，但历史上已经匹配到的部分依然保留，通过 `max(左, 上)` 的方式继承下来。** 这一点决定了整个双序列 DP 家族在设计递推公式时的分支方向，也是判断一道题该往哪个方向想的重要标志：题目要求"连续"就往清零方向想，要求"不要求连续/可以跳过"就往继承方向想。

## 代码

### C++

```cpp
class Solution {
public:
    int longestCommonSubsequence(string text1, string text2) {
        int n = text1.size(), m = text2.size();
        // dp[i][j] 表示 text1 前 i 个字符与 text2 前 j 个字符的最长公共子序列长度
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0)); // 第0行第0列天然初始化为0

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (text1[i - 1] == text2[j - 1]) {
                    // 字符匹配：在前i-1、前j-1的基础上，公共子序列长度加1
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    // 字符不匹配：不清零，而是继承“舍弃text1当前字符”或“舍弃text2当前字符”中较大的结果
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        return dp[n][m]; // 两个字符串全部字符都参与比较后的最终结果
    }
};
```

### Java

```java
class Solution {
    public int longestCommonSubsequence(String text1, String text2) {
        int n = text1.length(), m = text2.length();
        // dp[i][j] 表示 text1 前 i 个字符与 text2 前 j 个字符的最长公共子序列长度
        int[][] dp = new int[n + 1][m + 1]; // 数组默认初始化为0，对应第0行第0列的边界

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (text1.charAt(i - 1) == text2.charAt(j - 1)) {
                    // 字符匹配：在前i-1、前j-1的基础上加1
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    // 字符不匹配：继承左方向和上方向中较大的值，而不是清零
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        return dp[n][m]; // 最终答案
    }
}
```

```python
class Solution:
    def longestCommonSubsequence(self, text1: str, text2: str) -> int:
        n, m = len(text1), len(text2)
        # dp[i][j] 表示 text1 前 i 个字符与 text2 前 j 个字符的最长公共子序列长度
        dp = [[0] * (m + 1) for _ in range(n + 1)]  # 第0行第0列天然为0（空字符串边界）

        for i in range(1, n + 1):
            for j in range(1, m + 1):
                if text1[i - 1] == text2[j - 1]:
                    # 字符匹配：在前i-1、前j-1的基础上加1
                    dp[i][j] = dp[i - 1][j - 1] + 1
                else:
                    # 字符不匹配：继承左、上两个方向中较大的值，而不是清零
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

        return dp[n][m]  # 最终答案
```

### Go

```go
func longestCommonSubsequence(text1 string, text2 string) int {
    n, m := len(text1), len(text2)
    // dp[i][j] 表示 text1 前 i 个字符与 text2 前 j 个字符的最长公共子序列长度
    dp := make([][]int, n+1)
    for i := range dp {
        dp[i] = make([]int, m+1) // 初始化为0，第0行第0列天然表示空字符串
    }

    for i := 1; i <= n; i++ {
        for j := 1; j <= m; j++ {
            if text1[i-1] == text2[j-1] {
                // 字符匹配：在前i-1、前j-1的基础上加1
                dp[i][j] = dp[i-1][j-1] + 1
            } else {
                // 字符不匹配：继承左、上两个方向中较大的值，而不是清零
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
            }
        }
    }
    return dp[n][m] // 最终答案
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```

## 总结

- 递推公式的核心分支就在于字符匹不匹配：匹配时 `dp[i][j] = dp[i-1][j-1] + 1`；不匹配时是 `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`——说白了就是**继承左方向和上方向已有的最大值，而不是清零**，这是本题最容易出错、也最关键的一步。
- 为什么不清零呢？因为子序列允许跳过字符、不要求连续，当前这两个字符不匹配，并不会让之前已经找到的公共子序列失效，只是说明当前这一对字符不能同时被选中而已。
- 这正是"连续"（子数组/子串，比如 0718 最长重复子数组）跟"不连续"（子序列，比如本题）这两类双序列 DP 在设计递推公式时的关键分界线：连续型不匹配就得清零重开，不连续型不匹配只是少一种选择，得继承历史最优。
- 下标从 1 开始、用"前 i 个字符"来定义 dp 数组，能让第 0 行、第 0 列的初始化（对应空字符串）变得很自然，这是双序列 DP 里通用的处理技巧。
