# 115. 不同的子序列

**题目描述**

给定两个字符串 `s` 和 `t`，求 `s` 的子序列中等于 `t` 的个数（子序列不要求连续，只要求保持相对顺序）。

```
示例：
输入: s = "rabbbit", t = "rabbit"
输出: 3
解释: s 中有 3 种不同的子序列可以匹配出 t = "rabbit"
（分别对应 s 中三个不同的 'b' 被舍弃的方案）
```

结果可能很大，题目保证在 32 位有符号整数范围内。

## 思路

这道题怎么理解呢？你可以把它看成，是咱们子序列系列里第一次从"判断能不能匹配、求个长度"跳到"数一数到底有几种方案"上来的题，而且也是双字符串 DP 里明显往上走一个台阶的难度。说实话，难点还真不在于状态怎么定义——那个一说就懂，真正容易把人绕进去的地方是递推公式里"两种情况要加起来"这一步，你得想明白为什么是加而不是像求长度那样取个最大值。

**1. 确定 dp 数组以及下标的含义**

咱们先把 dp 数组定义清楚：`dp[i][j]` 表示的是，`s` 的前 `i` 个字符里面，有多少种子序列能等于 `t` 的前 `j` 个字符组成的那个字符串。

这个思路其实是接着 392 题的路子往下走的，392 题里咱们用长度或者计数去代替布尔值，但这一题呢，走得更远一步：392 题你只要知道"能不能匹配上"就行了，说到底是个 yes/no 的问题；而这一题问的是"到底有多少种匹配方式"，所以 `dp[i][j]` 存的是一个具体的计数值，不是能不能，而是有几种。

**2. 确定递推公式**

这一步要分两种情况来讨论：`s[i-1]` 和 `t[j-1]` 到底是相等还是不相等。

**情况一：`s[i-1] == t[j-1]`**

```
dp[i][j] = dp[i-1][j-1] + dp[i-1][j]
```

这一行公式是这道题最容易把人绕进去的地方，一定要跟面试官讲清楚为什么是"两种情况加起来"而不是"随便选一种就完事"。你想啊，当 `s[i-1]` 和 `t[j-1]` 恰好相等的时候，`s` 的这个字符其实是**既可以选择用它，也可以选择不用它**的，这是两种完全独立、互不重叠的匹配方案：

- 第一种，用 `s[i-1]` 去匹配 `t[j-1]`：那问题不就变成了"s 前 i-1 个字符里有多少种子序列能等于 t 前 j-1 个字符"嘛，这正好就是 `dp[i-1][j-1]`。
- 第二种，不用 `s[i-1]`（就算它跟 `t[j-1]` 相等，我也主动放弃它，把它当成一个多余的字符直接跳过）：这时候问题就变成"s 前 i-1 个字符里有多少种子序列能等于 t 前 j 个字符"，也就是 `dp[i-1][j]`。

那为什么要相加呢？因为这两种方案对应的是 `s` 里不同字符被选中或者被舍弃的具体方式，它们是两个完全不重叠的方案集合，谁也不包含谁，所以这里必须做的是相加，而不是取较大值，也不能只挑一种。这其实也是这道题和之前那些"求长度"类题目（比如 1143）最大的思维差异：求长度的时候咱们只关心"最优值是多少"，用一个 `max` 就搞定了；但求方案数的时候咱们关心的是"总共能有多少种可能"，必须把所有互斥的可能性一个不落地全部累加起来，用 `+`。

**情况二：`s[i-1] != t[j-1]`**

```
dp[i][j] = dp[i-1][j]
```

这种情况下字符不相等，说白了 `s[i-1]` 根本没机会去匹配 `t[j-1]`，唯一能做的就是跳过 `s[i-1]`，看看 `s` 前 `i-1` 个字符能匹配出多少种 `t` 前 `j` 个字符，也就是 `dp[i-1][j]`。你会发现这一情况其实正好是"情况一"里"不用当前字符"那个分支的延续，只不过因为字符不相等，"用当前字符"这个选项直接就被排除掉了，所以这里不需要相加，直接继承过来就够了。

**3. dp 数组如何初始化**

先看 `dp[i][0]`，它表示的是当 `t` 是空字符串的时候，`s` 前 `i` 个字符里有多少种子序列能等于这个空字符串。这里的关键是，空字符串永远都是任何字符串的子序列，而且只有"什么都不选"这唯一一种方案，所以 `dp[i][0] = 1`，这个对所有的 `i` 都成立。

再看 `dp[0][j]`（这里 `j > 0`），它表示的是当 `s` 是空字符串的时候，能匹配出 `t` 前 `j` 个字符（`j>0`，非空）的方案数是多少——这个显然就是 0 嘛，空字符串怎么可能凑出一个非空的子序列呢，对吧。

**4. 确定遍历顺序**

遍历顺序这块没什么特殊的，老规矩，从上到下、从左到右去遍历 `i` 和 `j` 就行。为什么可以这么简单粗暴呢？因为 `dp[i][j]` 依赖的是 `dp[i-1][j-1]` 和 `dp[i-1][j]`，这两个都在它的上一行，所以只要按行递增去遍历，需要的值早就算好了，完全够用。

**5. 举例推导 dp 数组**

咱们拿 `s = "bag"`，`t = "ag"` 来举个例子看看（行是 `s`，列是 `t`）：

| dp | 空 | a | g |
|----|---|---|---|
| 空 | 1 | 0 | 0 |
| b  | 1 | 0 | 0 |
| a  | 1 | 1 | 0 |
| g  | 1 | 1 | 1 |

推导的关键点在这儿：`s[1]='a'` 和 `t[0]='a'` 是匹配的，所以 `dp[2][1] = dp[1][0] + dp[1][1] = 1 + 0 = 1`；接着往下看，`s[2]='g'` 和 `t[1]='g'` 也匹配上了，所以 `dp[3][2] = dp[2][1] + dp[2][2] = 1 + 0 = 1`。最后算出来 `dp[3][2] = 1`，也就是说，"bag" 里头只有一种子序列能凑出 "ag" 来。

**复杂度分析**

- 先看时间复杂度，就是 O(n·m)，两层循环嘛，没什么好说的。
- 空间复杂度也是 O(n·m)，不过这里可以用滚动数组压缩到 O(m)，但要注意一个坑：情况一的累加会用到本行还没更新过的旧值，所以更新的时候得从右往左走，或者提前把旧值存一下，不然一不小心就把需要的数据覆盖掉了。

## 代码

### C++

```cpp
class Solution {
public:
    int numDistinct(string s, string t) {
        int n = s.size(), m = t.size();
        vector<vector<unsigned long long>> dp(n + 1, vector<unsigned long long>(m + 1, 0));
        for (int i = 0; i <= n; i++) dp[i][0] = 1;  // t为空时，只有"什么都不选"这一种方案
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (s[i - 1] == t[j - 1]) {
                    // 字符相等：可以用当前字符匹配(dp[i-1][j-1])，也可以不用(dp[i-1][j])，两种方案相加
                    dp[i][j] = dp[i - 1][j - 1] + dp[i - 1][j];
                } else {
                    // 字符不等：只能跳过s[i-1]，继承dp[i-1][j]
                    dp[i][j] = dp[i - 1][j];
                }
            }
        }
        return (int)dp[n][m];
    }
};
```

### Java

```java
class Solution {
    public int numDistinct(String s, String t) {
        int n = s.length(), m = t.length();
        long[][] dp = new long[n + 1][m + 1];
        for (int i = 0; i <= n; i++) dp[i][0] = 1;  // t为空时只有一种方案：什么都不选
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    // 相等：用当前字符匹配 + 不用当前字符匹配，两种互斥方案相加
                    dp[i][j] = dp[i - 1][j - 1] + dp[i - 1][j];
                } else {
                    // 不等：只能跳过s[i-1]
                    dp[i][j] = dp[i - 1][j];
                }
            }
        }
        return (int) dp[n][m];
    }
}
```

## 总结

- 你会发现 `dp[i][j]` 从原来"求长度"升级成了"求方案数"，这其实是子序列 DP 从判定类问题过渡到计数类问题的一个关键跨越。
- 字符相等的时候，递推公式用的是"相加"而不是"取最大值"，为什么呢，因为"用当前字符"和"不用当前字符"是两种互斥、但又都合法的方案，必须把所有方案数一个不落地累加起来，这也正是计数类 DP 最核心的思维方式。
- 字符不相等的时候，就只能继承 `dp[i-1][j]`，因为当前字符压根没机会参与匹配，这一分支其实也顺带解释清楚了"相等情况"里面那个 `dp[i-1][j]` 项到底是从哪儿来的。
- 还有一点容易被忽略：`dp[i][0] = 1` 而不是 0，因为空字符串永远都是任何字符串的子序列，而且只有唯一的一种（空）匹配方式，这个初始化条件说白了很多人第一次做的时候都容易漏掉。
