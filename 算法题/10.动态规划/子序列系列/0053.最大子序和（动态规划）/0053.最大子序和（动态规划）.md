# 0053. 最大子序和（动态规划）

**题目描述**

给定一个整数数组 `nums`，请找到一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。

```
示例：
输入: nums = [-2,1,-3,4,-1,2,1,-5,4]
输出: 6
解释: 连续子数组 [4,-1,2,1] 的和最大，为 6。
```

这道题在贪心算法分类里已经用贪心解法做过一次了，就是累加和一旦为负就清零重置那个思路。这里咱们换个角度，用动态规划重新推一遍。你可能会觉得这两种解法风格完全不搭——一个就维护两个变量，一个要维护一整个数组——但是往下推你会发现，它们本质上讲的是同一件事，只是表达方式不一样，这也正是这道题放进"子序列系列"里重讲一遍的价值所在。

## 思路

咱们还是用"DP五部曲"来推导这道题。

**1. 先确定 dp 数组和下标的含义**

`dp[i]` 表示的是：以下标 `i` 结尾的连续子数组，最大和是多少。

这里我要强调一下，一定是"以 i 结尾"，不能说成"前 i 个元素里的最大子数组和"，这两个说法看着差不多，其实完全不是一回事。为什么呢？跟 300 题最长上升子序列的道理是类似的：子数组要求必须连续，如果丢掉"结尾"这个限定，`dp[i]` 和 `dp[i-1]` 之间就建立不起递推关系了——你就算知道"前 i-1 个元素里最大子数组和是多少"，也没法回答"这个最大子数组是不是刚好在第 i-1 位结束、能不能接上 `nums[i]`"这个问题。所以必须把"结尾位置"死死钉住，才能问出一个能递推下去的问题：以 `nums[i]` 结尾的子数组，最好能做到多大。

**2. 确定递推公式**

你想啊，以 `nums[i]` 结尾的子数组，来源只有两种，没有第三种可能：

- 接着"以 `nums[i-1]` 结尾的最大子数组"往后延伸一位，把 `nums[i]` 加进去，也就是 `dp[i-1] + nums[i]`。
- 前面的累积不要了，直接以 `nums[i]` 自己重新起一个子数组，就是 `nums[i]` 本身。

这两种来源说白了就是"接着走"和"另起一行"，取两者中大的那个：

```
dp[i] = max(dp[i-1] + nums[i], nums[i])
```

那什么时候该"另起一行"呢？关键是看 `dp[i-1]` 是不是负数——如果 `dp[i-1]` 是负的，接着走反而会把和拉低，这时候 `dp[i-1] + nums[i]` 就会小于 `nums[i]`，公式自然就会选后面那一项，等于是把前面的负贡献直接扔掉了。这一点很重要，后面讲贪心和 DP 的关系时会专门展开说。

还有一点得提一下：最终答案**不是** `dp[n-1]`，而是整个 `dp` 数组里出现过的最大值。为什么？因为全局最优的连续子数组不一定刚好在数组末尾结束，它可能在中间某个位置就已经达到最大和了，后面反而被更小甚至负数的元素拖了后腿。所以遍历的时候要额外拿一个变量 `result`，一直记录 `dp` 数组里出现过的最大值。

**3. dp 数组怎么初始化**

`dp[0] = nums[0]`，这个很直接：以第一个元素结尾的子数组，只有它自己这一种可能，最大和当然就是它本身。

**4. 确定遍历顺序**

从前往后遍历。因为 `dp[i]` 要依赖 `dp[i-1]`，必须保证前面的状态先算出来才行。

**5. 举个例子推一遍 dp 数组**

以 `nums = [-2,1,-3,4,-1,2,1,-5,4]` 为例：

| i | nums[i] | dp[i] | 说明 |
|---|---------|-------|------|
| 0 | -2 | -2 | 自身 |
| 1 | 1 | 1 | max(-2+1, 1) = max(-1, 1) = 1，放弃前面，重新开始 |
| 2 | -3 | -2 | max(1-3, -3) = max(-2, -3) = -2，接着走更优 |
| 3 | 4 | 4 | max(-2+4, 4) = max(2, 4) = 4，放弃前面 |
| 4 | -1 | 3 | max(4-1, -1) = max(3, -1) = 3，接着走 |
| 5 | 2 | 5 | max(3+2, 2) = max(5, 2) = 5，接着走 |
| 6 | 1 | 6 | max(5+1, 1) = 6，接着走 |
| 7 | -5 | 1 | max(6-5, -5) = max(1, -5) = 1，接着走 |
| 8 | 4 | 5 | max(1+4, 4) = 5，接着走 |

`dp` 数组为 `[-2,1,-2,4,3,5,6,1,5]`，最大值是 `dp[6]=6`，所以答案就是 6，对应的连续子数组是 `[4,-1,2,1]`，跟预期一致。

**复杂度分析**

时间复杂度是 O(n)，只需要遍历一次数组。空间复杂度是 O(n)，因为要开一个长度为 n 的 `dp` 数组；不过你注意到 `dp[i]` 只依赖 `dp[i-1]`，所以完全可以用一个滚动变量代替整个数组，把空间压到 O(1)。

**跟贪心解法的关系（这里是重点）**

贪心解法里的核心操作是：维护一个累加和 `count`，每一步把当前元素加进去，一旦 `count` 变成负数就清零重置。你细品一下，这个操作跟上面 DP 的递推公式其实说的是同一件事，只是换了个说法。

咱们把贪心的 `count` 对应到 DP 的 `dp[i]` 上看看：贪心里"把当前元素加进 count"，对应的就是 DP 里"接着走"这一分支，也就是 `dp[i-1] + nums[i]`；贪心里"count 变负就清零重置为 0，下一步从 `nums[i+1]` 重新开始累加"，对应的就是 DP 里"放弃前面、另起一行"这一分支 `nums[i]`——因为 `count` 清零之后下一步算的是 `0 + nums[i+1] = nums[i+1]`，跟 DP 里 `dp[i+1] = nums[i+1]` 完全是一回事。

再看看触发条件是不是也对得上：DP 里选"另起一行"是因为 `dp[i-1] + nums[i] < nums[i]`，两边同时减掉 `nums[i]`，就变成 `dp[i-1] < 0`；贪心里触发清零的条件是 `count < 0`。你看，这就是同一个判断条件的两种写法而已——`dp[i-1]` 跟清零之前的 `count`，本质上就是同一个量，只不过贪心解法把它当成一个滚动变量来维护，没有显式保留整个数组，所以表面上看起来像是两种完全不同的算法，其实说白了，贪心解法就是这个 DP 解法做了空间优化（滚动数组）之后的版本。

理解了这层关系之后，你会发现很多"贪心"解法背后其实都藏着一个 DP 的影子：只要 DP 的状态转移只依赖上一个状态、不需要回溯历史信息，就可以把整个数组压缩成一个变量，写成看起来更"直觉"的贪心形式。反过来说，如果遇到一个贪心解法你想不明白为什么是对的，可以试着先写出对应的 DP 状态转移方程，用 DP 严谨的推导去验证一下贪心策略到底对不对——这也正是这道题放在子序列系列里重讲一遍的用意，用 DP 的框架去"翻译"一下贪心，理解会更扎实。

## 代码

### C++

```cpp
class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        int n = nums.size();
        vector<int> dp(n);
        dp[0] = nums[0];          // 初始化：只有一个元素时，最大和就是它自己
        int result = dp[0];       // 记录dp数组中出现过的最大值
        for (int i = 1; i < n; i++) {
            // 接着前面走(dp[i-1]+nums[i])，或放弃前面重新开始(nums[i])，取较大值
            dp[i] = max(dp[i - 1] + nums[i], nums[i]);
            result = max(result, dp[i]);  // 更新全局最大和
        }
        return result;
    }
};
```

### Go

```go
func maxSubArray(nums []int) int {
    n := len(nums)
    dp := make([]int, n)
    dp[0] = nums[0] // 初始化：只有一个元素时，最大和就是它自己
    result := dp[0] // 记录dp数组中出现过的最大值

    for i := 1; i < n; i++ {
        // 接着前面走，或放弃前面重新开始，取较大值
        if dp[i-1]+nums[i] > nums[i] {
            dp[i] = dp[i-1] + nums[i]
        } else {
            dp[i] = nums[i]
        }
        if dp[i] > result {
            result = dp[i] // 更新全局最大和
        }
    }
    return result
}
```

## 总结

- `dp[i]` 就是"以 `nums[i]` 结尾的连续子数组最大和"，递推公式是 `dp[i] = max(dp[i-1]+nums[i], nums[i])`，最后答案要取整个 `dp` 数组里的最大值，不是 `dp[n-1]`。
- 贪心解法里"累加和为负就清零"这个操作，本质上就是 DP 递推公式里"放弃前面另起一行"这个分支被触发的条件（也就是 `dp[i-1] < 0`），说白了这两个是同一个决策的两种说法。
- 贪心解法其实就是这个 DP 解法的空间优化版本：因为状态转移只依赖上一个状态，所以可以用一个滚动变量代替整个 `dp` 数组，把空间复杂度从 O(n) 降到 O(1)。
- 遇到一个贪心策略想不清楚为什么对的时候，可以先试着写出对应的 DP 状态转移方程，用 DP 严谨的推导反过来验证一下贪心到底对不对。
