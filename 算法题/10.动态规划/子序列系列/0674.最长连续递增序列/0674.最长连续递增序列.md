# 0674. 最长连续递增序列

**题目描述**

给定一个未经排序的整数数组 `nums`，找出其中最长且**连续递增**的子序列，并返回该序列的长度。

这里的"连续"指的是下标连续，也就是说子序列必须是原数组中一段连续的区间，不能像普通子序列那样跳着选元素。

```
示例：
输入: nums = [1,3,5,4,7]
输出: 3
解释: 最长连续递增序列是 [1,3,5]，长度为 3。
尽管 [1,3,4,7] 也是递增的子序列，但它不是连续的，因为 5 和 4 在原数组中是连续的两个下标，
中间不能跳过 4 而直接从 5 跳到 7。
```

## 思路

你看这道题啊，第一眼看上去跟 300. 最长上升子序列长得几乎一样，对不对？但它就多了"连续"这两个字的限制，别看只是加了个限定词，这一下子就把整个递推逻辑给简化了不少。那我还是按咱们平时说的 DP 五部曲，一步一步给你捋一遍。

**1. 确定 dp 数组（dp table）以及下标的含义**

先说说 `dp[i]` 到底代表什么。它表示的是：以下标 `i` 结尾的最长连续递增子序列的长度。这里我得特别强调一下啊，是"以 `nums[i]` 结尾"，而不是"以 `nums[i]` 为起点"，也不是"数组前 `i` 个元素里能找到的最长值"——这几种说法听着差不多，但其实完全是两回事，一定要分清楚。那为什么这个定义这么重要呢？因为它直接决定了我后面写递推公式的时候，只需要盯着 `nums[i]` 和它前一个元素 `nums[i-1]` 之间的关系就行了，完全不用回头去翻更早之前的历史记录，这就是这个定义带来的好处。

**2. 确定递推公式**

那递推公式怎么推出来呢？我这里分两种情况来看。第一种情况，如果 `nums[i] > nums[i-1]`，说明从 `nums[i-1]` 走到 `nums[i]` 这一步还是递增的，没有断掉，那么以 `nums[i]` 结尾的这段连续递增序列，说白了就是在"以 `nums[i-1]` 结尾的连续递增序列"基础上，再往后多接一个元素而已，写出来就是这样：

```
dp[i] = dp[i-1] + 1
```

那第二种情况呢，如果 `nums[i] <= nums[i-1]`，这就说明递增关系在这里断掉了，那以 `nums[i]` 结尾的连续递增序列就没办法接着往前算了，只能从头重新起算，长度直接变成 1（也就是序列里只有 `nums[i]` 自己）：

```
dp[i] = 1
```

**3. dp 数组如何初始化**

初始化这一步其实很简单：`dp` 数组里每一个位置都填成 1。为什么呢？你想啊，任何单独一个元素，它自己本身就可以构成一个长度为 1 的"连续递增序列"——序列里就它自己，压根不需要跟谁比较，天然就是满足递增的。所以实际操作的时候，直接把 `dp` 数组整个填成 1，比如 `dp = new int[nums.length]`。这里要提一句，多数语言里 new 出来的整型数组默认全是 0，所以写代码的时候要记得显式赋值成 1，或者也可以在遍历的时候先赋个 1，再去判断要不要加 1。

**4. 确定遍历顺序**

遍历顺序这块，关键是 `dp[i]` 的值要依赖 `dp[i-1]`，所以必须保证算 `dp[i]` 之前，`dp[i-1]` 已经算完了，那顺理成章就得从前往后遍历，也就是下标从小到大。说白了这也很符合直觉，连续递增序列本来就是"从左往右一点点累积"出来的过程，天然就该顺序遍历。

**5. 举例推导 dp 数组**

光说不练假把式，咱们拿示例 `nums = [1,3,5,4,7]` 来举个例子，下标从 0 开始：

| 下标 i | nums[i] | 与 nums[i-1] 比较 | dp[i] |
|---|---|---|---|
| 0 | 1 | 无（起点） | 1 |
| 1 | 3 | 3 > 1，递增 | dp[0]+1 = 2 |
| 2 | 5 | 5 > 3，递增 | dp[1]+1 = 3 |
| 3 | 4 | 4 <= 5，不递增，断开 | 1 |
| 4 | 7 | 7 > 4，递增 | dp[3]+1 = 2 |

最后算出来 `dp = [1,2,3,1,2]`，取里面最大的值就是 3，这就是答案。你可以看到 `dp[2]=3` 正好对应的就是 `[1,3,5]` 这一段连续递增的区间，跟我们预期的一样。

**复杂度分析**

这个算法只需要一次线性遍历，每个位置的计算都是 O(1) 的，所以时间复杂度是 O(n)。空间上呢，因为用了一个长度为 n 的 `dp` 数组，空间复杂度是 O(n)。不过你想啊，`dp[i]` 其实只依赖 `dp[i-1]` 这一个历史状态，所以完全可以用一个滚动变量去代替整个数组，把空间复杂度优化到 O(1)。只不过这样一优化，可读性就会差一些，所以面试的时候如果没有特别要求，我建议还是先写出 O(n) 空间的版本，稳一点。

**本题与 300 题的本质区别（重点）**

这道题跟 300. 最长上升子序列放在一起看，题面几乎是同一句话，都是在说"找最长的递增子序列"，但就是"连续"这两个字，直接把整个 DP 的设计思路给改变了，这里值得好好对比一下。

先看 300 题：它的子序列不要求下标连续，可以跳着选，所以 `dp[i]` 表示的是"以 `nums[i]` 结尾的最长上升子序列的长度"，那要算它就得把所有满足 `j < i` 且 `nums[j] < nums[i]` 的位置 `j` 都考虑一遍，然后从这些 `dp[j]` 里挑一个最大的，再加一：

```
dp[i] = max(dp[j] + 1)，其中 0 <= j < i 且 nums[j] < nums[i]
```

你看，这就意味着算每一个 `dp[i]` 的时候，都得把它左边所有可能的前驱位置挨个枚举一遍，看看哪个前驱能接到 `nums[i]` 前面，还能给出最大的长度。这其实就是个双层循环，时间复杂度是 O(n^2)。

那再看本题（674 题），因为它要求子序列在下标上必须连续，"接续"关系就只能发生在紧挨着的前一个位置上。也就是说，`nums[i]` 想接到某个更长序列的后面，唯一的候选前驱就只有 `nums[i-1]`，根本不存在"跳过 `nums[i-1]` 直接去接 `nums[i-2]`"这种可能性，为什么呢，因为那样一来下标就不连续了嘛。所以递推的时候只需要比较 `nums[i]` 和 `nums[i-1]` 这一对相邻元素就够了，完全不用像 300 题那样把 `j < i` 的所有位置都枚举一遍，这样一来直接把时间复杂度从 O(n^2) 降到了 O(n)。

还有一个核心的分歧点，就是"断开"之后怎么处理。300 题里即使 `nums[i]` 接不到 `nums[i-1]` 后面，`dp[i]` 依然可能等于某个更早的 `dp[j]+1`（只要能找到 `nums[j] < nums[i]` 且 `j` 更靠前的位置），这是因为不连续子序列允许"跳过中间不满足条件的元素"，所以前面积累的递增趋势不会因为某一个位置不满足就整个作废。但本题就不一样了，只要某个地方出现 `nums[i] <= nums[i-1]`，之前积累的那段递增关系就会因为下标必须连续这个硬性约束彻底断掉，`dp[i]` 只能"清零重新开始"，直接置为 1，没有任何回头去找更早前驱的余地。

所以说白了，"连续"和"不连续"这两个字，其实决定的就是 DP 递推时候选前驱的数量：不连续子序列的候选前驱是"左边所有满足条件的位置"，得挨个枚举比较，就算断开了也还能从别的更早位置续上；而连续子序列的候选前驱就只有唯一一个"紧邻的前一个位置"，一旦这个唯一候选不满足条件，那就没有退路了，只能清零重开。这也正是为什么本题用一个简单的 O(n) 单层遍历就能解决，而 300 题得用 O(n^2)（或者用贪心加二分优化到 O(n log n)）的根本原因。

## 代码

### C++

```cpp
class Solution {
public:
    int findLengthOfLCIS(vector<int>& nums) {
        int n = nums.size();
        vector<int> dp(n, 1);  // dp[i] 初始化为 1，每个元素自身构成长度为1的序列
        int result = 1;        // 记录最长长度，至少为 1
        for (int i = 1; i < n; i++) {
            if (nums[i] > nums[i - 1]) {
                dp[i] = dp[i - 1] + 1;  // 递增，接续前一个数的长度 +1
            } else {
                dp[i] = 1;  // 不递增，断开，重新从 1 开始计数
            }
            result = max(result, dp[i]);  // 更新全局最长长度
        }
        return result;
    }
};
```

## 总结

- 这道题的核心递推就是比较相邻的两个元素 `nums[i]` 和 `nums[i-1]`，一旦不满足递增条件，就必须把 `dp[i]` 清零重置为 1。这也是"连续子序列"跟"不连续子序列"最本质的区别：连续子序列一旦断开就没有回头路了，而不连续子序列断开之后，还有可能从更早的位置续上。
- 300 题（不要求连续）得枚举所有 `j < i` 的前驱再取最大值，时间复杂度是 O(n^2)；而本题（要求连续）因为候选前驱是唯一的，只需要一层 O(n) 遍历就能解决。这也提醒我们做题的时候，一定要先看清楚"连续"跟"不连续"这类关键限定词，它会直接决定你 DP 状态转移该怎么设计。
- `dp[i]` 只依赖 `dp[i-1]`，所以完全可以用一个滚动变量去替代整个数组，把空间复杂度从 O(n) 优化到 O(1)，代价就是牺牲了 dp 数组本身的可读性和可调试性。
- 以后遇到"连续区间"这类问题的时候，可以优先考虑这种只看相邻元素关系的线性遍历思路，往往会比套用一般子序列那种双重循环的模板要高效得多。
