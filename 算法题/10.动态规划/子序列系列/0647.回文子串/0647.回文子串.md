# 0647. 回文子串

**题目描述**

给定一个字符串 `s`，请统计其中回文子串的个数。子串要求是连续的一段字符，即使内容相同，只要出现在字符串中的位置不同，也要计为不同的子串。

```
示例：
输入: s = "aaa"
输出: 6
解释: 6个回文子串分别是 "a", "a", "a", "aa", "aa", "aaa"。
说明：这里的 "a" 出现了三次（下标0、1、2各自单独构成一个回文子串），
"aa" 出现了两次（下标[0,1]和下标[1,2]），"aaa" 出现一次（下标[0,2]），
虽然子串的内容有重复，但因为它们在原字符串中的起止位置不同，所以分别计数，总共 3+2+1=6 个。
```

## 思路

你想啊，拿到"统计回文子串个数"这个问题，第一反应可能是暴力枚举所有子串再逐一判断是否回文，但这样时间复杂度是 O(n³)（枚举起止点 O(n²)，判断回文再花 O(n)），效率上肯定不理想。那有没有更好的办法呢？其实回文子串这件事本身有很强的"子问题重叠"特性——判断一个大区间是否回文，完全可以复用它去掉两端后中间小区间是否回文的结果，这不就是动态规划的典型场景嘛，把重复计算的部分记录下来就行了。这类"在一个区间 `[i, j]` 上做判断或统计"的动规问题，一般叫它区间DP。下面我按照DP五部曲来一步步推导。

**1. 确定dp数组（dp table）的含义**

先说dp数组的含义：定义 `dp[i][j]` 表示字符串 `s` 在闭区间 `[i, j]`（也就是从下标 `i` 到下标 `j` 的这一段子串，两端都包含在内）是不是回文串，它是个布尔类型的值：`true` 就表示 `s[i..j]` 是回文串，`false` 就表示不是。

**2. 确定递推公式**

那怎么判断 `s[i..j]` 是不是回文串呢？这里其实可以分两种情况来看：

- 如果 `s[i] != s[j]`，两端字符都不相等，那很明显，整个区间 `[i, j]` 肯定不可能是回文串，直接 `dp[i][j] = false`，这个没什么争议。
- 但如果 `s[i] == s[j]`，两端字符相等，这时候是不是就能马上说整体是回文了呢？还不能，为什么呢？因为回文要求的是"整体对称"，两端相等只是个必要条件，还得看看去掉两端之后剩下的中间部分 `[i+1, j-1]` 是不是也回文才行。这里还要再细分三种小情况：
  - 区间长度为1，也就是 `i == j`（单个字符），这种一个字符自己肯定是回文，天然成立。
  - 区间长度为2，也就是 `j - i == 1`（两个相邻字符），这种情况去掉两端之后中间根本没剩下字符，所以只要两端相等就必然回文，不用再往中间看了。
  - 区间长度大于等于3，也就是 `j - i >= 2`，这时候去掉两端后中间还剩下至少一个字符构成的子区间 `[i+1, j-1]`，这才是真正需要依赖 `dp[i+1][j-1]` 的结果的地方：只有中间那部分也是回文，整体才能算回文。

那把上面这三种小情况合并成一条能写进代码里复用的判断条件的话，就是：`j - i <= 1`（对应长度1或2的情况）可以直接判定为回文，否则就要再去看 `dp[i+1][j-1]`。所以说白了，完整的递推公式就是：

```
dp[i][j] = (s[i] == s[j]) 且 (j - i <= 1 或者 dp[i+1][j-1] == true)
```

这里我要特别强调一下，为什么要单独把 `j - i <= 1` 拎出来做特判，而不能无条件地直接去访问 `dp[i+1][j-1]`？你想啊，当 `j - i <= 1` 时，`i+1` 会大于 `j-1`（比如 `i=2, j=3` 时 `i+1=3, j-1=2`，就出现了 `i+1 > j-1` 这种"反区间"），这种反区间在语义上根本不代表一个有效的子串范围。如果不加特判直接去查这个位置的 `dp` 值，轻则读到一个从未被正确赋值、含义不明的格子（因为这个位置本来就不该被当作"合法区间"来解读），重则在某些实现里还会造成数组下标越界（比如 `i+1` 恰好等于数组长度这种更极端的边界场景）。所以说，这个特判不是可选的优化，而是保证递推公式本身语义正确、不出现未定义行为的必要环节。

**3. 确定初始化**

初始化这块很简单：`dp` 数组的所有元素都初始化为 `false`。为什么呢？因为一个区间到底是不是回文，完全要靠递推逐步确定，在没有任何计算之前，你不能默认任何区间就是回文，所以起始状态统一设为 `false`，之后再通过递推公式把真正是回文的格子改写为 `true`。

**4. 确定遍历顺序（这里是本题最容易出错、也最核心的地方）**

这一步是重点，得先看清楚依赖关系：计算 `dp[i][j]` 需要用到 `dp[i+1][j-1]`。把这个依赖关系翻译成"表格坐标"的语言就是：`i+1` 比 `i` 大，`j-1` 比 `j` 小，也就是说，`dp[i][j]` 依赖的是它"行号更大、列号更小"的那个格子，说白了，就是依赖它左下方的格子（如果把 `i` 当作行、`j` 当作列，`i` 增大就是往下走，`j` 减小就是往左走）。

那这就带来一个关键约束：**在计算 `dp[i][j]` 之前，`dp[i+1][j-1]` 必须已经算出来了**。如果按照大多数人写二维DP时的习惯——外层循环 `i` 从 0 递增到 n-1，内层循环 `j` 从 0（或从 `i`）递增到 n-1——你想想会发生什么：当处理到第 `i` 行的时候，第 `i+1` 行根本还没有被计算过（因为 `i+1` 行要等到外层循环走到 `i+1` 的那一轮才会被填），这时候去读 `dp[i+1][j-1]` 读到的只会是初始化的 `false`，而不是真实的计算结果，那整个递推就全错了。

我举个具体例子来说明。假设 `s = "cbbd"`，下标从0到3。要判断 `dp[0][3]`（也就是 `"cbbd"` 整体是否回文）：`s[0]='c'`，`s[3]='d'`，两端字符不相等，直接得 `dp[0][3]=false`，这个格子不依赖别的格子。但换个角度看依赖链条：判断 `dp[1][3]`（即 `"bbd"`）需要先判断 `s[1]` 和 `s[3]` 是否相等，`s[1]='b'`, `s[3]='d'`，不相等，`dp[1][3]=false`。再看 `dp[1][2]`（即 `"bb"`），`s[1]='b'`, `s[2]='b'`，相等，且 `j-i=1<=1`，命中特判，直接 `dp[1][2]=true`。这个例子还没体现出跨行依赖，换用 `s="babad"` 这种更长一点的例子会更清楚：判断 `dp[0][4]`（`"babad"`）时 `s[0]='b'`, `s[4]='d'` 不等，直接 `false`；但如果要判断类似 `dp[0][2]`（`"bab"`）呢：`s[0]='b'`, `s[2]='b'` 相等，`j-i=2`，不满足 `<=1`，这时候就必须去看 `dp[1][1]`（也就是第1行的格子）。所以要正确算出 `dp[0][2]`，前提就是第1行（`i=1`）的 `dp[1][1]` 得早已经算好才行。

由此就能反推出正确的遍历顺序了：既然 `dp[i][...]` 这一整行都依赖 `dp[i+1][...]` 这一行的部分格子，那就必须保证"第 `i+1` 行先算完，第 `i` 行才能开始算"，也就是行号要从大到小遍历。所以外层循环 `i` 要从字符串长度减一（`n-1`）递减到 0（也就是从字符串的最后一个下标往前走到第一个下标）。而内层循环 `j`，因为要求区间合法（`j >= i`），并且同一行内 `dp[i][j]` 不依赖同一行中别的 `j`（它依赖的是下一行的 `j-1` 列），所以内层 `j` 从 `i` 递增到 `n-1` 就行，方向本身不会引发错误，但一般习惯写成从 `i` 到 `n-1` 递增，逐个把这一行填满。

这里给大家归纳成一句话方便记忆：**只要发现递推公式依赖"左下方"的格子（行号变大、列号变小），遍历顺序就必须是外层行号从大到小、内层列号从小到大（或者从i往右）**，这样才能保证用到某个格子的时候，它已经在更早的外层循环轮次里被正确算出来了。说到底，这也是所有区间DP问题的通用排雷经验：先看清依赖方向，再反推遍历顺序，千万不能凭习惯默认从上到下、从左到右去写循环。

**5. 举例推导dp数组**

光说公式可能还是有点抽象，咱们用 `s = "aaa"`（下标0,1,2）来手推一下。按照"i从2到0递减，j从i到2递增"的顺序填表：

- `i=2`：只有 `j=2`（因为要求`i<=j`才合法）。`dp[2][2]`：单字符，天然回文，`true`。
- `i=1`：`j=1`：`dp[1][1]=true`（单字符）。`j=2`：`s[1]='a', s[2]='a'` 相等，`j-i=1<=1`，命中特判，`dp[1][2]=true`。
- `i=0`：`j=0`：`dp[0][0]=true`。`j=1`：`s[0]='a', s[1]='a'` 相等，`j-i=1<=1`，`dp[0][1]=true`。`j=2`：`s[0]='a', s[2]='a'` 相等，`j-i=2`，不满足特判，这时候就要看 `dp[1][1]`——这个值在 `i=1` 那一轮早就算好了，是 `true`，所以 `dp[0][2]=true`。

统计一下所有 `dp[i][j]=true` 的格子：`dp[0][0], dp[1][1], dp[2][2]`（3个单字符）、`dp[0][1], dp[1][2]`（2个长度2的）、`dp[0][2]`（1个长度3的），加起来一共 6 个，正好对应 "a","a","a","aa","aa","aaa"，跟示例结果对上了。这个推导过程其实也再次验证了遍历顺序的必要性：你看 `dp[0][2]` 的计算严格依赖此前已经算好的 `dp[1][1]`，如果遍历顺序反了，`dp[1][1]` 在算 `dp[0][2]` 时还停留在初始值 `false`，那 `dp[0][2]` 就会被错误地判成 `false`，答案就错了。

**复杂度分析**：这里两层循环遍历所有满足 `i <= j` 的区间组合，所以时间复杂度是 O(n²)；因为用了一个 n×n 的二维数组来保存所有区间的判断结果，空间复杂度也是 O(n²)。

## 代码

### C++

```cpp
class Solution {
public:
    int countSubstrings(string s) {
        int n = s.size();
        vector<vector<bool>> dp(n, vector<bool>(n, false)); // dp[i][j]初始化为false
        int result = 0;
        for (int i = n - 1; i >= 0; i--) {        // 外层i从大到小，保证i+1行先算完
            for (int j = i; j < n; j++) {         // 内层j从i到n-1，保证区间[i,j]合法
                if (s[i] == s[j]) {                // 两端字符相等才有可能是回文
                    if (j - i <= 1) {              // 长度为1或2，特判直接为回文
                        dp[i][j] = true;
                    } else if (dp[i + 1][j - 1]) { // 长度>=3，依赖中间区间的结果
                        dp[i][j] = true;
                    }
                }
                if (dp[i][j]) {
                    result++;                      // 每确定一个回文区间，计数加一
                }
            }
        }
        return result;
    }
};
```

        boolean[][] dp = new boolean[n][n]; // 默认初始化为false

        for (int i = n - 1; i >= 0; i--) {          // 外层i从大到小，保证i+1行先算完

class Solution:

        n = len(s)

        result = 0

## 总结

- 区间DP的遍历顺序不能凭习惯默认从上到下、从左到右，一定要先分析清楚递推公式依赖的是哪个方向的格子，再反推遍历顺序：这道题里 `dp[i][j]` 依赖的是"左下方"的 `dp[i+1][j-1]`，所以外层 `i` 必须从大到小遍历（这样才能保证 `i+1` 行先算完），内层 `j` 从 `i` 到末尾递增。
- `j - i <= 1` 这个特判是必须要有的，不是可有可无的优化：当区间长度为1或2时，去掉两端后中间不剩字符，或者说访问的是一个不合法的"反区间"，如果不加特判直接访问 `dp[i+1][j-1]`，会读到语义不明的值，甚至可能导致下标问题。
- 这道题很容易和"最长回文子序列"搞混，得注意区分：子串要求连续，子序列可以不连续，两者的dp定义和递推公式并不通用，做题的时候一定要看清题目问的是"子串"还是"子序列"。
- 另外补充一点，这道题也可以用中心扩展法在 O(n²) 时间、O(1) 空间解决（枚举每个中心向两边扩展），但动态规划这种写法更能体现区间DP"从小区间结果推大区间结果"的通用思想，建议还是先掌握动规的做法。
