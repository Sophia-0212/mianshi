# 为了绝杀编辑距离，卡尔做了三步铺垫

编辑距离（LeetCode 72 题）是双字符串 DP 里最经典、也最容易让人第一次接触就手足无措的一道难题——插入、删除、替换这三种操作交织在一个递推公式里，你要是没有铺垫直接上手，很容易在"到底该往哪个方向递推""为什么要加1"这些细节上卡壳。所以子序列系列里特意安排了 392 判断子序列、115 不同的子序列、583 两个字符串的删除操作这三道题，专门给编辑距离做铺垫。你可别以为这是四道孤立的题，其实是一条精心设计的思维阶梯：每一题都在前一题的状态定义基础上往前多走一步，逐步引入新的操作类型和新的思维方式，最终在 72 题这里汇聚成一个统一的框架。这篇文档就是梳理这条阶梯的每一步台阶。

**第一步：392 判断子序列——学会"用状态表达匹配关系"**

392 题问的是一个是非问题：`s` 是不是 `t` 的子序列。这题最直观的解法是双指针，一次线性扫描就搞定了，根本用不上 DP。但你要是换个角度，用 DP 来解这道题，会引出一个关键的状态定义：`dp[i][j]` 表示 `s` 前 `i` 个字符和 `t` 前 `j` 个字符的最长公共子序列长度。这个长度要是恰好等于 `s` 的总长度，就说明 `s` 完整地被 `t` 按顺序包含了，也就是子序列关系成立。

这一步真正教会咱们的，不是"怎么判断子序列"（双指针早解决了），而是**"怎么用一个数值状态去表达两个字符串之间的匹配关系"**。你看，状态不再是简单的布尔值"是/否"了，而是一个可以累加、可以比较、可以传递信息的数字。这个数字语言一旦建立起来，后面的题目就能在它之上做各种"加法"：加计数、加代价、加操作类型。递推公式上，字符相等时 `dp[i][j] = dp[i-1][j-1] + 1`；不相等时（因为本题 `s` 不能跳过、只能跳过 `t`）`dp[i][j] = dp[i][j-1]`。这个"相等就+1，不相等就继承"的骨架，会在后面三题里反复出现、不断变形。

**第二步：115 不同的子序列——学会"计数要用加法，不是取最大值"**

392 题解决的是"能不能匹配"，115 题解决的是"有多少种匹配方式"，这可是一次质的跳跃。`dp[i][j]` 表示 `s` 前 `i` 个字符中，有多少种子序列等于 `t` 前 `j` 个字符组成的字符串。

这一步最核心的思维转变，就体现在字符相等时的递推公式上：`dp[i][j] = dp[i-1][j-1] + dp[i-1][j]`。你注意这里是**相加**，不是像 1143 题那样用 `max`。为什么呢？因为当 `s[i-1]` 和 `t[j-1]` 相等的时候，`s` 的这个字符可以选择"用它来匹配"（对应 `dp[i-1][j-1]`），也可以选择"不用它，把它当多余字符跳过"（对应 `dp[i-1][j]`）——这是两种互不重叠、都合法的方案，你要统计"总共有多少种方案"，就必须把它们加起来，而不是只挑一个更优的。这正是本题教给咱们的关键一课：**求最优值（最长、最短）用 `max`/`min`，求方案数用 `+`**。这个区分在后面处理更复杂的组合类 DP 问题时会反复用到，编辑距离本身虽然求的是最小操作数（用 `min`），但如果稍加改造去求"有多少种编辑方式能达到最小操作数"，就得用到这里学的加法思维。

115 题还有一个铺垫价值：它是第一次让咱们在"字符相等"这一分支里看到"两种子选择"的存在（用/不用当前字符）。这个"存在多种子选择、要么取最优要么加总"的意识，直接为编辑距离里"字符不等时要在删除/插入/替换三个方向里选"打下了基础。

**第三步：583 两个字符串的删除操作——学会"把具体操作类型建模进递推公式"**

583 题第一次真正把一个"操作"（删除）显式地写进了递推公式里。`dp[i][j]` 表示 `word1` 前 `i` 个字符和 `word2` 前 `j` 个字符，通过删除操作变成相同所需的最小步数。字符相等时不需要操作，直接继承 `dp[i-1][j-1]`就行；字符不相等时，必须删除其中一个字符才能继续比较，这时候有两种选择——删 `word1` 当前字符（`dp[i-1][j] + 1`）或者删 `word2` 当前字符（`dp[i][j-1] + 1`），取步数更少的那个方向。

这一步教会咱们两件事。第一，**"操作"在递推公式里体现为"移动到哪个方向 + 加上操作代价"**：删除 `word1` 的字符对应"`i` 减 1，`j` 不变，代价+1"，删除 `word2` 的字符对应"`i` 不变，`j` 减 1，代价+1"。这种"方向对应操作、步数对应代价"的建模方式，正是理解编辑距离递推公式的钥匙。第二，本题第一次出现"同一个不相等分支下有两个操作可选，取 `min`"的结构，这正是编辑距离里"删除、插入、替换三选一取 `min`"的雏形，只不过本题只有两个可选方向（删 `word1` 或删 `word2`），编辑距离会扩展到三个方向。

值得一提的是，583 题还可以转化成"先求最长公共子序列 LCS，再用 `n + m - 2*lcs` 算出删除步数"，这个转化展示了问题之间互相归约的能力，不过直接定义删除步数的 dp（如上所述）更贴近题目语义，也更直接地为编辑距离做铺垫。

**第四步：72 编辑距离——三步铺垫的汇合点**

编辑距离的 `dp[i][j]` 表示 `word1` 前 `i` 个字符转换成 `word2` 前 `j` 个字符所需的最少操作数。字符相等时继承 `dp[i-1][j-1]`（这一步跟前三题完全一样）；字符不相等时，在删除、插入、替换三个方向中取最小：

```
dp[i][j] = min(dp[i-1][j] + 1, dp[i][j-1] + 1, dp[i-1][j-1] + 1)
```

你对照前面三步就能看出，这个公式可不是凌空出现的：`dp[i-1][j] + 1`（删除）和 `dp[i][j-1] + 1`（插入）正是 583 题里"删 `word1`"和"删 `word2`"这两个方向的直接延续（只不过在编辑距离里，"删 `word2` 字符"的效果反过来看等价于"在 `word1` 里插入一个字符"，方向一样，只是换了个说法）；`dp[i-1][j-1] + 1`（替换）则是全新引入的第三个方向，对应"两个字符不相等时，花一次代价直接把它们变成相等，然后跳到 392/115/583 都在用的那个'两边同时前进一格'的骨架"。三个方向取 `min`，正是 583 题"两个方向取 `min`"结构的自然扩展。

咱们可以这样总结四道题层层递进的关系：392 建立了"用状态数值表达匹配"的语言；115 教会了"计数场景用加法、区分最优值与方案数"；583 第一次把具体操作显式建模进递推公式，并引入"多个方向取最优"的结构；72 把删除、插入、替换三种操作统一到同一个"三方向取 min"的框架里，是前三步思维方式的综合运用。要是你直接从零开始学编辑距离，很容易被"三种操作"这个表面复杂度给吓住；但顺着这条阶梯一步步走过来，你会发现编辑距离的递推公式其实是"意料之中"的结果，每一部分都能在前面某道题里找到对应的影子。这也是"卡尔三步铺垫"这个说法的意思：不是三道孤立的题目，而是专门为编辑距离铺设的一条思维阶梯。

## 总结

- 392 题：建立起"用长度/计数表达匹配关系"的状态语言，这是后续所有双字符串 DP 的基础骨架。
- 115 题：教会咱们"求方案数要用加法，不是取最大值"，并第一次出现"字符相等时有两种子选择"的结构。
- 583 题：第一次把具体操作（删除）显式建模进递推公式，教会咱们"方向对应操作、步数对应代价"，还引入了"不相等时多方向取 min"的结构。
- 72 题：三步铺垫的汇合点，把删除、插入、替换统一到"三方向取 min"的框架里，理解了前三题就能看懂这个公式为什么不是凌空出现的。
