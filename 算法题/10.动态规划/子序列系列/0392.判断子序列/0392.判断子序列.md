# 392. 判断子序列

**题目描述**

给定字符串 `s` 和 `t`，判断 `s` 是否是 `t` 的子序列。子序列不要求连续，只要求在 `t` 中能找到与 `s` 顺序一致的字符（可以跳过 `t` 中任意字符）。

```
示例：
输入: s = "abc", t = "ahbgdc"
输出: true
解释: t 中依次出现 a(下标0)、b(下标2)、c(下标5)，顺序与 s 一致，所以 s 是 t 的子序列。
```

一般假设 `s` 的长度远小于 `t`（例如 `s` 长度不超过 100，`t` 长度可达 10000 以上），这个数据规模的提示很重要，后面会解释原因。

## 思路

这题乍一看挺简单的，你想啊，用双指针一次遍历就能搞定了，压根用不上动态规划。但既然把它放进子序列系列里，咱们不妨换个角度，用 DP 的思路重新理解一遍——为什么呢？因为它其实是"卡尔三步铺垫"（392 → 115 → 583 → 72）的第一步，这里学到的"用状态去记录匹配关系"这套思维方式，后面三道题会不断拿来复用、层层加码，最后一路撑到编辑距离这道硬骨头。所以我这里打算两个思路都讲：先讲双指针这个直观解法，再讲 DP 解法，重点是把 DP 解法背后那套"状态语言"给讲透。

**思路一：双指针（直观解法）**

思路很直白：同时维护两个指针 `i`、`j`，分别指向 `s` 和 `t` 当前走到的位置。每一步就比较 `s[i]` 和 `t[j]`：如果相等，说明这个字符对上了，那两个指针就一起往后挪一位；如果不相等，说明 `t[j]` 这个字符对 `s` 来说没用，那就只挪 `j`（跳过它，继续在 `t` 里往后找）。等遍历结束了，看 `i` 有没有恰好走到 `s` 的末尾（也就是 `i == s.length`）——如果走到了，说明 `s` 里每个字符都按顺序在 `t` 中找到了归宿，返回 `true`；如果没走到，说明 `s` 还有字符没匹配上，那就返回 `false`。

这个解法的时间复杂度是 O(n)（`n` 是 `t` 的长度），空间复杂度 O(1)，说白了对这道题的数据规模已经绰绰有余了，面试里最推荐直接这么写。

**思路二：动态规划（为后续题目铺垫的解法）**

双指针虽然效率高，但它只能回答一个是非问题——"是不是子序列"。可一旦题目变成"有多少种不同的匹配方式"（115 题），或者"要删掉多少个字符才能让两个字符串相同"（583 题），双指针这种贪心式的扫描就不够用了，为什么呢？因为这些问题得把所有可能的匹配方案都考虑进去，而不是随便找到一种就完事。这也就是为什么要引入 DP：DP 记录的是"前 i 个字符和前 j 个字符之间存在某种关系"，这个更细粒度的状态才能撑得住更复杂的问题。下面就用 DP 五部曲把本题捋一遍。

**1. 确定 dp 数组以及下标的含义**

`dp[i][j]` 表示 `s` 的前 `i` 个字符和 `t` 的前 `j` 个字符，这两者的最长公共子序列长度。

这里我特意不用布尔值来定义状态（比如"`s` 前 `i` 个字符是不是 `t` 前 `j` 个字符的子序列"），而是跟 1143 题一样，用"长度"来定义。为什么这么选呢？你想啊，如果最终算出来的最长公共子序列长度正好等于 `s` 的总长度，那就说明 `s` 整体都被 `t` 按顺序包含进去了，也就是说 `s` 是 `t` 的子序列；反过来如果小于 `s` 的长度，说明 `s` 里有字符没能按顺序匹配上，那 `s` 就不是子序列。用长度而不是布尔值，说白了就是为了让这套状态定义能直接搬用 1143 题最长公共子序列的整套推导，不用另起一套逻辑——这也正是本题被放在"三步铺垫"第一步的原因：它先教会我们"用长度去表达匹配关系"这个通用技巧。

**2. 确定递推公式**

这一步和 1143 题完全一样，分两种情况来讨论 `s[i-1]` 跟 `t[j-1]` 是否相等：

- `s[i-1] == t[j-1]`：这时候两个字符可以一起算进公共子序列里，所以 `dp[i][j] = dp[i-1][j-1] + 1`。
- `s[i-1] != t[j-1]`：这一步是本题跟标准 1143 题唯一不一样的地方，也是最要留心的地方。标准 1143 题里，两个字符串的地位是完全对等的，不匹配的时候要同时考虑"丢掉 `s` 当前字符"和"丢掉 `t` 当前字符"这两种可能，取 `max(dp[i-1][j], dp[i][j-1])`。但本题的目标是"判断 `s` 是不是 `t` 的子序列"，`s` 和 `t` 的地位并不对等：我们只关心能不能从 `t` 里面"挑出"一个 `s` 来，`t` 的字符可以随便跳过，但 `s` 的字符一个都不能丢（`s` 要整体被匹配上才行）。所以字符不相等的时候，就只需要考虑"跳过 `t` 当前字符"这一种可能，也就是 `dp[i][j] = dp[i][j-1]`，不用去考虑 `dp[i-1][j]`（也就是放弃 `s` 当前字符这种情况），因为放弃 `s` 的字符根本不符合"判断 `s` 整体是否被包含"这个目标。

```
dp[i][j] = dp[i-1][j-1] + 1              若 s[i-1] == t[j-1]
dp[i][j] = dp[i][j-1]                    若 s[i-1] != t[j-1]
```

**3. dp 数组如何初始化**

先看 `dp[0][j] = 0`（对所有 `j` 都成立）：`s` 是空字符串的时候，跟任何 `t` 前缀的最长公共子序列长度当然都是 0。再看 `dp[i][0] = 0`（对所有 `i>0` 都成立）：`t` 是空字符串的时候，压根匹配不出任何非空的 `s` 前缀，长度也是 0。这两种情况其实跟数组默认初始化为 0 的结果是一样的，所以不用额外去赋值。

**4. 确定遍历顺序**

遍历顺序是从上到下、从左到右，为什么这么走呢？因为 `dp[i][j]` 依赖的是上一行的 `dp[i-1][j-1]` 和同一行前一列的 `dp[i][j-1]`，只要按行递增去遍历，就能保证要用到的值都已经算好了。

**5. 举例推导 dp 数组**

拿 `s = "abc"`，`t = "ahbgdc"` 来举例（行是 `s`，列是 `t`）：

| dp | 空 | a | h | b | g | d | c |
|----|---|---|---|---|---|---|---|
| 空 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| a  | 0 | 1 | 1 | 1 | 1 | 1 | 1 |
| b  | 0 | 1 | 1 | 2 | 2 | 2 | 2 |
| c  | 0 | 1 | 1 | 2 | 2 | 2 | 3 |

最终 `dp[3][6] = 3`，正好等于 `s` 的长度 3，这说明 `s` 完完整整地被匹配上了，返回 `true`。那如果换成 `s = "axc"` 呢？最终 `dp` 值就会小于 3（因为 `x` 在 `t` 里怎么都找不到匹配），这时候就返回 `false`。

**复杂度分析**

DP 解法的时间复杂度是 O(n·m)（`n`、`m` 分别是 `s`、`t` 的长度），空间复杂度也是 O(n·m)。跟双指针解法的 O(m) 时间、O(1) 空间比一比，DP 解法在效率上明显吃亏——这也是为什么真正做这道题的时候更推荐用双指针。但就像开头说的，DP 解法这套"用长度表达是否包含"的状态语言，会在后面 115、583、72 题里被反复拿来复用和扩展，是理解那几道更难题目绕不过去的一环。

## 代码

下面代码把两种解法都给出来了：双指针解法（实际用这个）和 DP 解法（拿来理解状态设计）。

### C++

```cpp
// 解法一：双指针（推荐）
class Solution {
public:
    bool isSubsequence(string s, string t) {
        int i = 0, j = 0;  // i指向s，j指向t
        while (i < s.size() && j < t.size()) {
            if (s[i] == t[j]) {
                i++;  // 匹配成功，s的指针前进
            }
            j++;      // t的指针总是前进（无论是否匹配）
        }
        return i == s.size();  // i走到s末尾，说明s被完整匹配
    }
};

// 解法二：动态规划（理解状态设计用）
class SolutionDP {
public:
    bool isSubsequence(string s, string t) {
        int n = s.size(), m = t.size();
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));  // 默认初始化为0
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (s[i - 1] == t[j - 1]) {
                    dp[i][j] = dp[i - 1][j - 1] + 1;  // 字符匹配，长度加1
                } else {
                    dp[i][j] = dp[i][j - 1];  // 不匹配，只能跳过t当前字符（s不能跳）
                }
            }
        }
        return dp[n][m] == n;  // 最长公共子序列长度等于s总长，说明s被完整包含
    }
};
```

## 总结

- 双指针才是本题最直接高效的解法（O(m) 时间、O(1) 空间），实际做题的时候优先用它。
- DP 解法的思路是把"是否子序列"这个问题，转化成"求最长公共子序列长度，再看是否等于 `s` 的长度"，这个转化才是本题真正的核心价值：用长度去代替布尔值，给后面更复杂的双字符串 DP 问题铺路。
- 本题的递推公式跟 1143 题最长公共子序列几乎一模一样，唯一的区别就是字符不匹配的时候只能跳过 `t`（也就是 `dp[i][j-1]`），不能跳过 `s`（所以不取 `dp[i-1][j]`），说白了就是因为本题要求 `s` 必须被整体匹配上，`s` 和 `t` 的地位并不对等。
- 本题是"卡尔三步铺垫"（392→115→583→72）的起点，这里学到的"用状态表达匹配关系"会在后续三题里被逐步复用、逐步扩展。
