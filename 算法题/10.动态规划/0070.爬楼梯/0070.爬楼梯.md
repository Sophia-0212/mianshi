# 0070. 爬楼梯

**题目描述**

假设你正在爬楼梯，需要 n 阶你才能到达楼顶。每次你可以爬 1 或 2 个台阶，问有多少种不同的方法可以爬到楼顶。

```
示例：
输入: n = 3
输出: 3
解释: 有三种方法可以爬到楼顶。
1 阶 + 1 阶 + 1 阶
1 阶 + 2 阶
2 阶 + 1 阶
```

## 思路

你第一次看到这道题的递推公式，可能会发现它跟斐波那契数列长得一模一样：dp[i] = dp[i-1] + dp[i-2]。要是你只满足于"公式对了、答案也对了"，很容易就把这道题当成斐波那契的换皮题，套个公式就过去了。但这么做恰恰跳过了 DP 五部曲里最关键的两步——"确定 dp 数组的含义"和"推导递推公式成立的道理"，而这两步才是真正决定你是理解了这道题、还是只是蒙对了答案。

**第一步，先确定 dp 数组（下标）的含义**

我设 dp[i] 表示爬到第 i 阶楼梯，总共有多少种不同的方法。这里要注意，dp[i] 的含义和斐波那契数列的 dp[i]（"第 i 个斐波那契数是多少"）表面上看都是"一个下标对应一个数值"，但语义完全不一样：斐波那契数列的 dp[i] 是个抽象的数学定义，本身没有现实解释；而这里的 dp[i] 是"方法数"，是一个具体计数问题的答案，它对不对得靠对爬楼梯这个动作的分析来保证，不能想当然地认为它一定等于前两项之和。

**第二步，确定递推公式，这一步才是本题真正的核心**

要求 dp[i]，得先问一个具体的问题：要想恰好站在第 i 阶，上一步是从哪跨过来的？因为每次只能爬 1 阶或 2 阶，答案就只有两种可能：

- 从第 i-1 阶爬 1 个台阶上来；
- 从第 i-2 阶爬 2 个台阶上来。

除此之外没有第三种方式能恰好落在第 i 阶——不可能从第 i-3 阶直接跳上来（题目限定每次最多爬 2 阶），也不可能从第 i 阶本身"原地不动"算作一种方法。所以你看，到达第 i 阶的所有方法，可以按"最后一步是爬 1 阶还是爬 2 阶"分成两类，这两类互不重叠、又覆盖了全部情况，根据加法原理，dp[i] 就等于这两类方法数之和：

dp[i] = dp[i-1] + dp[i-2]

这个推导过程，才是这道题真正想教给我们的东西：递推公式不是从天上掉下来的数学规律，而是从"到达状态 i 的所有方式，可以划分成哪几种互斥的情况，每种情况又能归结到哪个更小的子状态"这个具体分析里导出来的。你想啊，如果把 1~2 阶换成 1~3 阶，用同样的分析方式就会得到 dp[i] = dp[i-1] + dp[i-2] + dp[i-3]，形式变了但道理没变——这正好说明"死记公式"和"理解公式从哪来"是两种完全不同的能力，只有后者才能应对题目条件的变化。

**第三步，dp 数组怎么初始化**

dp[1] = 1：只有 1 阶楼梯的时候，只有一种走法（爬 1 阶）。
dp[2] = 2：有 2 阶楼梯的时候，可以是"1+1"，也可以直接"2"，一共两种走法。

这里你可能会问，为什么不从 dp[0] 开始初始化呢？因为"爬 0 阶楼梯有几种方法"这个问题本身语义上就有点别扭（有的题解会强行定义 dp[0]=1，说"什么都不做"也算一种方法，但这个定义说白了就是为了凑公式硬引入的技巧性设定，不是从题目本身自然推出来的），直接从 dp[1] 和 dp[2] 这两个有明确物理意义的值开始初始化，逻辑更清楚，也更不容易搞混。

**第四步，确定遍历顺序**

因为 dp[i] 得靠 dp[i-1] 和 dp[i-2] 才能算出来，必须保证这两个更小的状态先被算出来，所以遍历顺序是从小到大，i 从 3 递增到 n。这一点和斐波那契数列完全一致——只要递推公式的依赖方向是"当前状态依赖更小的状态"，遍历顺序就得正向走。

**第五步，举例推导 dp 数组来验证一下**

拿 n = 5 举个例子：

```
dp[1] = 1
dp[2] = 2
dp[3] = dp[2] + dp[1] = 2 + 1 = 3
dp[4] = dp[3] + dp[2] = 3 + 2 = 5
dp[5] = dp[4] + dp[3] = 5 + 3 = 8
```

对照题目给的 n=3 时答案是 3，我们推出来的 dp[3] = 3，完全吻合。dp 数组最终是 `[_, 1, 2, 3, 5, 8]`（下标 0 处不用），你会发现这串数值和斐波那契数列是一致的（只是下标错开了一位），但要注意：数值序列一致只是这道题分析出来的结果，不是我们分析的起点——起点始终应该是"到达第 i 阶只能从 i-1 或 i-2 走来"这个物理事实。

**复杂度说一下**

- 时间复杂度：O(n)，从 3 遍历到 n，每步一次加法。
- 空间复杂度：用完整数组是 O(n)；因为 dp[i] 只依赖前两个状态，可以用两个滚动变量把空间优化到 O(1)。

## 代码

### C++

```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;  // n=1 返回1，n=2 返回2，对应初始化
        int prev2 = 1, prev1 = 2;  // prev2=dp[i-2], prev1=dp[i-1]
        int curr = 0;
        for (int i = 3; i <= n; i++) {
            curr = prev1 + prev2;  // 核心递推：到达第i阶 = 从i-1爬1阶 + 从i-2爬2阶
            prev2 = prev1;         // 滚动更新 dp[i-2]
            prev1 = curr;          // 滚动更新 dp[i-1]
        }
        return curr;
    }
};
```

## 总结

- 递推公式长得和斐波那契数列一样，不代表这是同一个问题：斐波那契数列的公式是数学定义直接给出来的，而爬楼梯的公式是从"到达第 i 阶只能由 i-1 阶爬1步或 i-2 阶爬2步而来"这个物理事实分析推导出来的，两边公式长得一样只是分析结果的巧合，不是分析的起点。
- DP 五部曲里"确定 dp 数组含义"和"推导递推公式的道理"这两步，才是区分"真正理解题目"和"照抄公式"的关键；一旦题目条件变了（比方说允许爬 1~3 阶），只有真正理解了推导过程的人才能正确地把公式改成 dp[i]=dp[i-1]+dp[i-2]+dp[i-3]。
- 初始化选择从 dp[1]、dp[2] 开始而不是 dp[0]，是因为这两个值有清晰、没有歧义的现实含义，避免为了凑边界硬引入不自然的定义。
- 同样可以用两个滚动变量把空间复杂度从 O(n) 优化到 O(1)，这是这种递推形状（只依赖前两个状态）通用的优化手段。
