# 685. 冗余连接 II

**题目描述**

给定一个有向图，它原本是一棵"有根树"——除了根节点没有父节点外，其余每个节点都恰好只有一个父节点，且从根节点出发能到达所有其他节点。现在往这棵树上多加了一条有向边（`edges` 数组比合法树多一条边），导致图不再是一棵合法的树。要求找出这条可以删除、使图重新变成合法有根树的多余边。如果存在多个可以删除的候选答案，返回在输入 `edges` 数组中**最后出现**的那一条。

```
示例：
输入: edges = [[1,2],[1,3],[2,3]]
输出: [2,3]
解释: 节点 1 是根，指向 2 和 3；但 3 同时被 1 和 2 指向，形成环，删除 [2,3] 后恢复合法树
```

```
示例：
输入: edges = [[1,2],[2,3],[3,4],[4,1],[1,5]]
输出: [4,1]
解释: 1→2→3→4→1 形成环，且没有节点入度为2，删除环上最后加入的边 [4,1] 即可
```

## 思路

**先回顾一下 684 题（无向图版本）作为对比**

684 题「冗余连接」是无向图版本：一棵无向树本身有 n 个节点、n-1 条边，多加一条边后就变成 n 条边了，图里出现了一个环。因为无向图不存在"方向"，唯一可能出现的异常就是"成环"。处理方式很直接：用并查集从头开始，依次对每条边的两个端点做 `union`，如果某条边的两个端点在 `union` 之前 `find` 出来的根节点已经相同，就说明这条边连接的两个点已经能通过之前处理过的边互相到达，加上这条边一定会形成环，它就是多余边——由于是"依次处理、第一条触发"，天然就满足了"如果有多个候选取最后出现的那条"这个要求。

**685 题的复杂之处：有向图会出现两种不同的异常模式**

685 题是有向图版本，情况就比 684 题复杂多了，因为有向图多了"入度"这个维度，一棵合法的有根树要求根节点入度为 0，其余节点入度都恰好为 1。多加一条有向边之后，会破坏这个性质，具体表现为两种**互斥的**异常模式：

**模式一：某个节点的入度变成了 2。** 这就意味着这个节点原本只应该有一条边指向它（一个父节点），现在多了一条边也指向它，导致它同时有两个"父节点"。既然只有这一个节点入度异常，多余的边必然是指向这个节点的两条边中的某一条——但具体是哪一条呢，不能简单地说"最后加入的那条"，因为如果两条边中较早的那条恰好是构成整棵树结构必需的边，删掉它反而会让其他节点失去到根节点的路径，图就断裂成多个分量，不再是一棵连通的树了。所以需要实际验证：先假设删除**较晚**出现的那条边（因为题目要求多个候选里取最后出现的，优先假设晚的那条是答案），用并查集把除这条边外的其余所有边都 `union` 一遍，检查能否顺利构成一棵合法树（也就是 `union` 过程中不出现"两端点已经同根"的成环情况）。如果假设成立（能顺利构成树），那么较晚的这条边就是答案；如果在 `union` 过程中仍然出现成环（说明删掉晚的这条边后，图依然存在别的环，这条边并不是唯一的问题所在），就说明真正应该删除的是**较早**出现的那条边。

**模式二：所有节点入度都不超过 1，但图中存在环。** 如果没有出现任何节点入度为 2，就说明图中不存在"两条边争抢同一个父节点"的问题，那么唯一的异常来源就是多加的这条边直接首尾相连形成了一个环（比如示例二中 1→2→3→4→1）。这种情况下问题结构和 684 题完全一样——图里只有"成环"这一种异常，直接用最朴素的并查集方法，从头依次 `union` 每条边的两个端点，第一条使两端点 `find` 出来的根节点相同的边，就是答案。

**为什么必须先检查入度为2的情况，不能直接套用684题的方法**

如果图里同时存在"某节点入度为2"和"图中有环"这两种情况（这在多加一条边的场景下是完全可能同时发生的，因为这一条多余的边既可能造成某点入度变成2，又可能恰好让图整体连成环），直接套用684题那种"从头到尾依次union，第一条触发成环的边即为答案"的方法就会出错——为什么呢，因为并查集在遇到入度为2的两条边时，只有当第二条边被处理到才会暴露"重复父节点"的问题，但真正需要删除的可能是这两条边里较早的一条（如果晚的一条对维持树的连通性是必需的），而"逐条union找第一条成环边"这种做法完全没有能力区分这两种候选，找到的"第一条成环边"未必是正确答案。所以必须先扫描一遍统计每个节点的入度，一旦发现入度为2的节点，就必须先按照模式一的专门逻辑来判断，排除掉这种特殊情况之后，剩下的"纯环"场景才能安全地退化为684题的处理方式。

**实现步骤总结**

1. 用一个 `parent` 数组（不是并查集的 parent，是记录树结构里"孩子→父亲"关系的数组）遍历一遍 `edges`：对每条边 `[u, v]`（`u` 指向 `v`，即 `u` 是 `v` 的父节点），检查 `parent[v]` 是否已经被赋值过。如果没有，正常赋值 `parent[v] = u`；如果已经被赋值过，说明 `v` 出现了第二个父节点，即 `v` 的入度为 2，记录这两条边——较早赋值时的那条边（`earlierEdge`）和当前正在处理、触发冲突的这条边（`laterEdge`），然后可以提前结束这一遍扫描（后面不需要再更新 `parent` 数组）。
2. **如果存在入度为2的节点**（即上一步记录到了 `earlierEdge` 和 `laterEdge`）：先假设答案是 `laterEdge`，用并查集把 `edges` 中除 `laterEdge` 之外的所有边都 `union` 一遍。如果整个过程没有出现成环（两端点已经同根还要union的情况），说明假设成立，直接返回 `laterEdge`；如果过程中出现了成环，说明 `laterEdge` 不是真正的答案，那么答案就是 `earlierEdge`（因为已经证明问题不止在这两条边的其中一条上，必须删除较早的那条才能同时消除入度冲突和潜在的环）。
3. **如果不存在入度为2的节点**：说明是纯环结构，用最朴素的并查集从头开始依次 `union` 每条边的两个端点，第一条触发"两端点已经同根"的边就是答案，直接返回。

**复杂度分析**

设节点数为 n，因为树原本有 n-1 条边，多加一条后 `edges` 共有 n 条边（对应 n 个节点，因为题目保证节点编号从 1 到 n）。整个算法只需要对这 n 条边做常数次遍历（一次找入度冲突，最多两次并查集处理），每次并查集的 `find`/`union` 操作在路径压缩优化下均摊接近 O(1)，所以总的时间复杂度是 **O(n)**。空间复杂度是 **O(n)**，用于并查集的 `parent` 数组以及记录父节点关系的辅助数组。

### C++

```cpp
class Solution {
public:
    vector<int> ufParent; // 并查集数组，与记录树结构的 parent 区分开

    int find(int x) {
        if (ufParent[x] != x) {
            ufParent[x] = find(ufParent[x]); // 路径压缩
        }
        return ufParent[x];
    }

    // 尝试把除 skipIndex 外的所有边都union，能成功构成树则返回 true
    bool buildWithoutEdge(vector<vector<int>>& edges, int n, int skipIndex) {
        ufParent.resize(n + 1);
        for (int i = 1; i <= n; i++) ufParent[i] = i; // 初始化，每个节点父节点是自己
        for (int i = 0; i < (int)edges.size(); i++) {
            if (i == skipIndex) continue; // 跳过被假设删除的这条边
            int u = edges[i][0], v = edges[i][1];
            int ru = find(u), rv = find(v);
            if (ru == rv) return false; // 两端点已经同根，加入会成环，说明假设失败
            ufParent[ru] = rv; // 合并两个集合
        }
        return true; // 顺利处理完所有边，没有成环
    }

    vector<int> findRedundantDirectedConnection(vector<vector<int>>& edges) {
        int n = edges.size();
        vector<int> parentOf(n + 1, 0); // parentOf[v] 记录 v 当前的父节点
        int earlierIdx = -1, laterIdx = -1; // 记录入度为2冲突的两条边下标

        for (int i = 0; i < n; i++) {
            int u = edges[i][0], v = edges[i][1];
            if (parentOf[v] != 0) {
                earlierIdx = -1; // 先重置，下面重新定位
                for (int j = 0; j < i; j++) { // 找到较早那条给 v 赋父节点的边
                    if (edges[j][1] == v) { earlierIdx = j; break; }
                }
                laterIdx = i; // 当前这条是较晚触发冲突的边
                break; // v 入度为2，无需继续扫描
            }
            parentOf[v] = u;
        }

        if (laterIdx != -1) { // 存在入度为2的节点
            if (buildWithoutEdge(edges, n, laterIdx)) {
                return edges[laterIdx]; // 删除较晚的边即可成树，它就是答案
            }
            return edges[earlierIdx]; // 否则真正的答案是较早的那条
        }

        // 不存在入度为2的节点，退化为纯环检测（与684题相同）
        ufParent.resize(n + 1);
        for (int i = 1; i <= n; i++) ufParent[i] = i;
        for (auto& e : edges) {
            int u = e[0], v = e[1];
            int ru = find(u), rv = find(v);
            if (ru == rv) return e; // 第一条使两端点同根的边即为多余边
            ufParent[ru] = rv;
        }
        return {}; // 理论上不会走到这里（题目保证有解）
    }
};
```

```python
class Solution:
    def findRedundantDirectedConnection(self, edges: list[list[int]]) -> list[int]:
        n = len(edges)
        uf_parent = list(range(n + 1))  # 并查集数组，初始每个节点父节点是自己

        def find(x: int) -> int:
            if uf_parent[x] != x:
                uf_parent[x] = find(uf_parent[x])  # 路径压缩
            return uf_parent[x]

        def build_without_edge(skip_index: int) -> bool:
            # 尝试把除 skip_index 外的所有边都union，能成功构成树则返回 True
            nonlocal uf_parent
            uf_parent = list(range(n + 1))  # 重新初始化并查集
            for i, (u, v) in enumerate(edges):
                if i == skip_index:
                    continue  # 跳过被假设删除的边
                ru, rv = find(u), find(v)
                if ru == rv:
                    return False  # 成环，假设失败
                uf_parent[ru] = rv
            return True

        parent_of = [0] * (n + 1)  # parent_of[v] 记录 v 当前的父节点
        earlier_idx = later_idx = -1

        for i, (u, v) in enumerate(edges):
            if parent_of[v] != 0:
                for j in range(i):  # 找到较早给 v 赋父节点的边
                    if edges[j][1] == v:
                        earlier_idx = j
                        break
                later_idx = i
                break  # v 入度为2，提前结束扫描
            parent_of[v] = u

        if later_idx != -1:  # 存在入度为2的节点
            if build_without_edge(later_idx):
                return edges[later_idx]  # 删除较晚的边即可成树
            return edges[earlier_idx]  # 否则答案是较早的那条

        # 不存在入度为2的节点，退化为纯环检测
        uf_parent = list(range(n + 1))
        for u, v in edges:
            ru, rv = find(u), find(v)
            if ru == rv:
                return [u, v]  # 第一条成环边即为答案
            uf_parent[ru] = rv

        return []  # 题目保证有解，理论不会到达这里
```

```go
    return true
```

## 总结

- 685 题比 684 题多了"方向"这个维度，导致异常模式从单一的"成环"分裂成两种互斥情况：某节点入度为2（多父节点冲突），或所有节点入度都合法但整体构成环（纯环结构）。
- 必须先扫描判断是否存在入度为2的节点，因为这种情况下候选答案是明确的两条边中的一条，不能直接套用684题"逐条union找第一条成环边"的方法，否则可能在同时存在入度冲突和环的场景下选错答案。
- 处理入度为2的节点时，优先假设删除较晚出现的那条边（符合"多个候选取最后出现"的要求），用并查集验证剩余边能否构成合法树；验证失败就说明较晚的边是树结构必需的，答案退化为较早的那条边。
- 排除入度为2的特殊情况后，剩下的纯环场景处理方式和684题完全一致：并查集逐条union，第一条导致两端点同根的边就是答案；整体时间复杂度 O(n)，空间复杂度 O(n)。
