# 0130. 被围绕的区域

**题目描述**

给定一个 `m x n` 的二维网格 `board`，网格中只包含两种字符：`'X'` 和 `'O'`。找到所有被 `'X'` 完全包围的区域，把这些区域里的每一个 `'O'` 都变成 `'X'`。

这里"包围"有一个特殊规则：**如果一个 `'O'` 区域和网格边界上的 `'O'` 直接或间接相连（上下左右方向），那么这个区域就不算被包围**，要原样保留，不能替换。只有那些完全被 `'X'` 包裹、无法通过相邻的 `'O'` 走到边界的区域，才会被替换成 `'X'`。

```
示例：
输入：
board = [
  ["X","X","X","X"],
  ["X","O","O","X"],
  ["X","X","O","X"],
  ["X","O","X","X"]
]
输出：
board = [
  ["X","X","X","X"],
  ["X","X","X","X"],
  ["X","X","X","X"],
  ["X","O","X","X"]
]
解释：中间那一片 O（(1,1)(1,2)(2,2)）没有任何一个格子挨着边界，被 X 完全包围，所以全部变成 X。
但是 (3,1) 这个 O 本身就在网格的边界上（最后一行），它不算被包围，原样保留。
```

## 思路

这道题最容易踩的坑是**从内部出发去判断一个 `'O'` 是否被围住**：你想啊，如果对网格里每一个 `'O'` 都做一次 DFS/BFS 去看它能不能走到边界，会出现大量重复搜索，而且逻辑上也挺绕的（判断"走不到边界"是一个否定性的条件，写起来容易出错）。

那更好的思路是什么呢？换一个方向想问题：不去找"被围住的"，而是先找出"绝对不会被围住的"，剩下的自然就是被围住的了。

这里的关键是，一个 `'O'` 只要能通过相邻的 `'O'` 一路连到边界，它就不会被替换。所以咱们可以反过来做：

1. **从边界出发做标记**：遍历网格最外层一圈（第一行、最后一行、第一列、最后一列）的所有格子，如果某个格子是 `'O'`，就从它出发做一次 DFS（或 BFS），把所有与它上下左右相连的 `'O'` 都标记成"安全"（比如临时改成一个特殊字符 `'A'`，或者用一个 `visited` 二维数组记录）。这一步会把所有"能连到边界"的 `'O'` 全部标记出来，不管它们离边界有多远，只要是连通的都会被找到。

2. **二次遍历整个网格**：把网格再扫一遍，这时候就只剩两种情况了——被标记为"安全"的格子（说明连到了边界，要还原成 `'O'`），和没有被标记的、原本是 `'O'` 的格子（说明无法连到边界，也就是被包围的区域，替换成 `'X'`）。

这个"先从边界反向标记安全区，再统一处理剩余部分"的做法，其实是网格类图论题里一个很通用的范式，好处是每个格子只会在标记阶段被访问一次（因为一旦标记就不会重复进入 DFS），不存在从每个 `'O'` 各自出发搜索的重复计算问题。

**与 1020 题（飞地的数量）的对比**

这道题和 1020 题"飞地的数量"几乎是同一套模板，甚至可以说是同一段代码换了最后一步的输出方式：

- 两题都是"从边界出发标记安全区，再遍历网格处理剩余部分"；
- 1020 题的"安全区"是与边界相连的陆地（`1`），本题的"安全区"是与边界相连的 `'O'`，标记逻辑完全一致；
- 唯一的区别就在最后一步怎么处理"剩余部分"：1020 题是**统计**没被标记的陆地格子数量（作为飞地数量返回），本题是**修改**没被标记的 `'O'` 格子（原地替换成 `'X'`）。

如果把这两题的 DFS/BFS 标记部分抽出来看，代码结构可以完全共用，只是调用方在最后一步一个做累加计数，一个做原地写入。理解了这一层，你就会发现图论里大量"网格 + 边界"类问题都可以套用同一个模板：**先反向标记出不会被处理的部分，再对网格做一次线性遍历完成最终结果**。

**复杂度分析**

设网格大小为 `m x n`。标记阶段每个格子最多进入一次 DFS/BFS（靠标记去重），边界格子数是 O(m+n)，但递归展开后覆盖的仍是整个连通分量，整体访问次数不超过 `m*n`；二次遍历是 O(m*n)。所以总的时间复杂度就是 O(m*n)，空间复杂度主要是递归栈（DFS 最坏 O(m*n)）或者 BFS 队列 O(m*n)。

## 代码

### C++

```cpp
class Solution {
public:
    void solve(vector<vector<char>>& board) {
        int m = board.size(), n = board[0].size();

        // 从 (row, col) 出发做 DFS，把相连的 'O' 标记为安全字符 'A'
        function<void(int, int)> dfs = [&](int row, int col) {
            if (row < 0 || row >= m || col < 0 || col >= n) return; // 越界，终止
            if (board[row][col] != 'O') return; // 不是待标记的 O，终止（包括已标记过的 A）
            board[row][col] = 'A'; // 标记为安全区，防止重复访问，同时作为最终还原的依据
            dfs(row - 1, col); // 上
            dfs(row + 1, col); // 下
            dfs(row, col - 1); // 左
            dfs(row, col + 1); // 右
        };

        // 第一遍：只从四条边界出发标记安全区
        for (int i = 0; i < m; i++) {
            dfs(i, 0);     // 最左列
            dfs(i, n - 1); // 最右列
        }
        for (int j = 0; j < n; j++) {
            dfs(0, j);     // 最上行
            dfs(m - 1, j); // 最下行
        }

        // 第二遍：把没被标记的 O 变成 X，把标记过的 A 还原成 O
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (board[i][j] == 'O') board[i][j] = 'X'; // 未连到边界，被围住，替换
                else if (board[i][j] == 'A') board[i][j] = 'O'; // 连到边界，安全，还原
            }
        }
    }
};
```

## 总结

- 判断"是否被包围"这类否定性条件，正面枚举每个点去验证往往效率低，逻辑也绕；反过来先标记"一定不会被处理"的部分（本题就是连到边界的 `'O'`），再统一处理剩余部分，这样做才是更清晰也更高效的思路。
- 这道题的标记阶段本质上就是在网格上做连通分量的 DFS/BFS，只不过搜索的起点固定在边界格子，而不是任意格子。
- 它和 1020 题"飞地的数量"共享同一套"边界出发标记安全区 + 二次遍历"模板，区别仅在于最后一步是做统计计数还是做原地修改，这就说明同一套图论范式其实可以套用在不同的输出需求上。
- 用临时字符（比如 `'A'`）代替额外的 `visited` 数组，既完成了标记去重，也天然区分出了三种最终状态（安全区、被围区、原始 X），这是网格类问题里常见的一个空间优化技巧。
