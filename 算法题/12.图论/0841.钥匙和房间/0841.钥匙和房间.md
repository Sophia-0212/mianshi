# 841. 钥匙和房间

**题目描述**

有 `n` 个房间，编号从 `0` 到 `n-1`。一开始你站在 `0` 号房间外面，除 `0` 号房间自动是打开的之外，其余所有房间都锁着。给定一个列表 `rooms`，`rooms[i]` 是房间 `i` 里放着的钥匙列表，每把钥匙对应一个房间编号，拿到某把钥匙就可以打开对应的房间。你可以自由地在已打开的房间之间移动，并拿走里面所有的钥匙。请判断：能否通过不断拿钥匙、开新房间的方式，最终进入所有房间。

```
示例 1：
输入: rooms = [[1],[2],[3],[]]
输出: true
解释: 从 0 号房间拿到钥匙 1，进入 1 号房间拿到钥匙 2，
     进入 2 号房间拿到钥匙 3，进入 3 号房间。所有房间都进入了。

示例 2：
输入: rooms = [[1,3],[3,0,1],[2],[0]]
输出: false
解释: 无法进入 2 号房间。
```

## 思路

**把问题转化成图的连通性问题**

这道题表面上是"钥匙和房间"这么个场景题，但你抽象一下就会发现它其实是一道标准的图遍历题：把每个房间看作图上的一个节点，"房间 `i` 里有一把钥匙能打开房间 `j`" 就等价于存在一条从节点 `i` 指向节点 `j` 的有向边（`rooms` 数组本身就是这张图的邻接表表示）。问题就转化成了：**从节点 0 出发，能否通过图中的边到达所有节点？** 这是图论里最基础的一类问题——判断从某个起点出发，DFS/BFS 能否遍历到全部节点，属于"遍历型"问题（区别于上一题"路径收集型"问题）。

**为什么这里的 visited 不需要撤销**

这是这道题和"所有可能的路径"（797 题）的关键区别。797 题要收集所有路径，同一个节点可能出现在多条不同路径中，所以 `visited` 要在递归返回后撤销（或者根本不用 `visited`，靠 `path` 回溯）。而这道题只关心"从 0 出发最终能覆盖到哪些房间"，这是一个纯粹的连通性判断：一个房间只要被进入过一次，它就永久处于"已开启"状态，不会因为换了一条路径就变回锁着。所以这里的 `visited` 数组一旦标记为 `true` 就永远不撤销，这正是图论深搜理论基础里提到的"遍历型"用法：防止死循环 + 避免同一节点被重复处理。

**具体做法：DFS 版**

1. 建立 `visited` 数组，长度为 `n`，初始全部为 `false`。
2. 从房间 0 开始做 DFS：先标记 `visited[0] = true`（进入并标记这个房间已开启）。
3. 单层搜索逻辑：遍历当前房间 `rooms[room]` 里的每一把钥匙 `key`，如果 `visited[key]` 还是 `false`，说明这个房间还没进过，递归调用 `dfs(key)` 进入它。
4. 递归的终止条件其实隐含在"如果已经 visited 就不再递归"这个判断里，不需要额外写一个显式的终止分支——当一个房间的所有钥匙对应的房间都已经访问过，for 循环走完自然结束这一层递归。
5. 遍历结束后，检查 `visited` 数组里是否所有元素都为 `true`。如果有任何一个房间没被访问到，就说明无法进入所有房间。

**具体做法：BFS 版**

DFS 和 BFS 在这类"只判断能否到达"的问题上是完全等价的，只是遍历顺序不同。BFS 用队列实现：把房间 0 加入队列并标记为已访问；每次从队列取出一个房间，遍历它的钥匙列表，把未访问过的钥匙对应房间标记为已访问并加入队列；直到队列为空。最后同样检查 `visited` 是否全为 `true`。两种方式复杂度相同，DFS 写法通常更简洁（递归天然处理了"深入-回退"），本篇代码统一采用 DFS。

**复杂度分析**

设房间数为 `n`，所有钥匙总数（即所有边数）为 `e`。DFS 过程中每个房间最多被标记访问一次（`visited` 保证不重复进入已访问房间的递归），每把钥匙最多被检查一次，所以时间复杂度是 O(n + e)，跟图论深搜理论基础中"遍历一次图"的复杂度结论完全一致。空间复杂度为 O(n)，来自 `visited` 数组和最坏情况下的递归栈深度（如果房间之间构成一条链，递归栈深度会达到 `n`）。

## 代码

### C++

```cpp
class Solution {
private:
    void dfs(vector<vector<int>>& rooms, int room, vector<bool>& visited) {
        visited[room] = true;              // 标记当前房间已开启，且不再撤销
        for (int key : rooms[room]) {      // 遍历当前房间里的所有钥匙
            if (!visited[key]) {           // 钥匙对应的房间还没进过
                dfs(rooms, key, visited);  // 递归进入这个房间
            }
        }
    }

public:
    bool canVisitAllRooms(vector<vector<int>>& rooms) {
        int n = rooms.size();
        vector<bool> visited(n, false);
        dfs(rooms, 0, visited);            // 从 0 号房间开始遍历
        for (bool v : visited) {           // 检查是否所有房间都被访问到
            if (!v) return false;
        }
        return true;
    }
};
```

class Solution {
    public boolean canVisitAllRooms(List<List<Integer>> rooms) {
        int n = rooms.size();
        boolean[] visited = new boolean[n];
        dfs(rooms, 0, visited);       // 从 0 号房间开始遍历

        for (boolean v : visited) {   // 检查是否所有房间都被访问到
            if (!v) return false;
        }
        return true;
    }

    private void dfs(List<List<Integer>> rooms, int room, boolean[] visited) {
        visited[room] = true;                    // 标记当前房间已开启，不撤销
        for (int key : rooms.get(room)) {        // 遍历当前房间里的所有钥匙
            if (!visited[key]) {                  // 对应房间还没进过
                dfs(rooms, key, visited);          // 递归进入
            }
        }
    }
}

class Solution:
    def canVisitAllRooms(self, rooms: list[list[int]]) -> bool:
        n = len(rooms)
        visited = [False] * n

        def dfs(room: int) -> None:
            visited[room] = True          # 标记当前房间已开启，不撤销
            for key in rooms[room]:       # 遍历当前房间里的所有钥匙
                if not visited[key]:      # 对应房间还没进过
                    dfs(key)              # 递归进入

        dfs(0)  # 从 0 号房间开始遍历
        return all(visited)  # 检查是否所有房间都被访问到

### Go

```go
func canVisitAllRooms(rooms [][]int) bool {
    n := len(rooms)
    visited := make([]bool, n)

    var dfs func(room int)
    dfs = func(room int) {
        visited[room] = true // 标记当前房间已开启，不撤销
        for _, key := range rooms[room] { // 遍历当前房间里的所有钥匙
            if !visited[key] { // 对应房间还没进过
                dfs(key) // 递归进入
            }
        }
    }

    dfs(0) // 从 0 号房间开始遍历

    for _, v := range visited { // 检查是否所有房间都被访问到
        if !v {
            return false
        }
    }
    return true
}
```

## 总结

- 这道题的本质是把"钥匙能开哪个房间"抽象成图的有向边，`rooms` 数组本身就是邻接表，问题转化成了标准的"从起点出发能否遍历全图"模板题。
- 属于"遍历型"图论问题，`visited` 一旦标记为 `true` 就永久有效，不需要在递归返回后撤销，这跟 797 题"路径收集型"问题（需要靠 path 回溯）形成鲜明对比。
- DFS 和 BFS 在此类连通性判断问题上等价，只是遍历顺序不同，选哪种主要看代码简洁度或是否有递归栈深度的顾虑。
- 时间复杂度 O(n + e)，空间复杂度 O(n)，是图论中"一次遍历"类问题的典型复杂度量级。
