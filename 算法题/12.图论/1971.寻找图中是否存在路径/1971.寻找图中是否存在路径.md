# 1971. 寻找图中是否存在路径

**题目描述**

给定一个包含 n 个节点的无向图，节点编号从 0 到 n-1，`edges` 是一个二维数组，`edges[i] = [ui, vi]` 表示节点 `ui` 和 `vi` 之间存在一条无向边。给定两个节点 `source` 和 `destination`，判断是否存在从 `source` 到 `destination` 的路径（路径可以经过任意数量的中间节点，包括0个）。

```
示例：
输入: n = 3, edges = [[0,1],[1,2],[2,0]], source = 0, destination = 2
输出: true
解释: 0 -> 1 -> 2 或者 0 -> 2 都可以到达

输入: n = 6, edges = [[0,1],[0,2],[3,5],[5,4],[4,3]], source = 0, destination = 5
输出: false
解释: 0 和 5 分别在两个不连通的分量里，无法互相到达
```

## 思路

这是一道"判断两点是否连通"的基础题，本质上就是判断 `source` 和 `destination` 是否属于同一个连通分量，可以用三种思路解决，这里重点讲并查集，并简单对比一下 DFS/BFS 的做法。

**并查集思路**

图是无向图，且是一次性给出所有边（静态图），理论上 DFS/BFS 遍历一次也能解决，但这题正好是练习并查集基本操作的典型场景：

1. 初始化并查集，`n` 个节点各自成一个集合。
2. 遍历 `edges`，把每条边的两个端点 `union` 到同一个集合。
3. 遍历完所有边后，调用 `isSame(source, destination)`（也就是比较 `find(source)` 和 `find(destination)` 是否相等），如果相等就说明两者在同一个连通分量里，存在路径，返回 true，否则返回 false。

并查集的核心动作说白了只有 `union` 和 `find` 两个：`union` 在合并两个集合的时候，把其中一个的根节点挂到另一个的根节点下面；`find` 通过不断跳转 `parent` 数组找到当前节点所在树的根节点，配合路径压缩把之后的查找优化到接近 O(1)。

**DFS/BFS 思路（对比）**

把 `edges` 转换成邻接表，从 `source` 出发做一次 DFS 或 BFS，用 `visited` 数组标记所有能到达的节点，遍历结束后检查 `destination` 是否被标记为已访问。这种做法同样能得到正确结果，复杂度也是 O(n + e)（e 为边数），但由于这道题只需要判断一次连通性（不是动态加边、多次查询的场景），DFS/BFS 和并查集在这里效率相当，选哪种更多是练习哪种数据结构的问题。那如果题目变成"多次询问不同的 source/destination 对是否连通"呢？这时候并查集的优势就会体现出来——只需要构建一次并查集，之后每次查询都是接近 O(1) 的 `isSame` 调用；而 DFS/BFS 每次查询都要重新遍历一次图。

**复杂度分析**

并查集做法：构建并查集 O(n)，遍历 `edges` 做 `union` 操作，`e` 条边总共 O(e)（均摊，路径压缩后每次操作接近 O(1)），最后一次 `isSame` 查询 O(1)（均摊）。总时间复杂度 O(n + e)，空间复杂度 O(n) 用于 `parent` 数组。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> parent;  // 并查集的父节点数组

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);  // 路径压缩：递归查找根节点，同时把路径上的节点直接接到根节点
        }
        return parent[x];
    }

    void unite(int x, int y) {
        int rootX = find(x), rootY = find(y);
        if (rootX != rootY) {
            parent[rootX] = rootY;  // 把 x 的根接到 y 的根下面，合并两个集合
        }
    }

    bool validPath(int n, vector<vector<int>>& edges, int source, int destination) {
        parent.resize(n);
        for (int i = 0; i < n; i++) {
            parent[i] = i;  // 初始化，每个节点的父节点是自己
        }
        for (auto& edge : edges) {
            unite(edge[0], edge[1]);  // 把每条边的两个端点合并到同一个集合
        }
        return find(source) == find(destination);  // 根节点相同说明连通
    }
};
```

## 总结

- 这道题是并查集最基础的应用：把每条边的两个端点合并到同一集合，最后判断两个目标节点是否属于同一集合。
- 因为这道题是静态图、只查询一次连通性，DFS/BFS 遍历一次同样能解决，复杂度相当；并查集的优势要在"边动态增加"或"多次查询"的场景下才能体现出来。
- 路径压缩是并查集能保持接近 O(1) 查询效率的关键，写 `find` 函数时要记得在回溯路径上把节点直接接到根节点，而不是简单地逐级向上找。
