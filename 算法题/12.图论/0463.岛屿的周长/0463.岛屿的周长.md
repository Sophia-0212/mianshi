# 463. 岛屿的周长

**题目描述**

给定一个二维网格 `grid`，`grid[i][j]` 为 `1` 表示陆地，为 `0` 表示水域。网格中恰好只有一个岛屿（即所有陆地格子四方向连通构成一片），且岛屿内部没有"湖"（也就是说不存在被陆地完全包围、无法通过网格边界到达的水域）。请计算这个岛屿的周长（即岛屿边界的总长度，每个陆地格子的边长视为 1）。

```
示例：
输入:
grid = [
  [0,1,0,0],
  [1,1,1,0],
  [0,1,0,0],
  [1,1,0,0]
]
输出: 16
```

## 思路

**核心观察：周长说白了就是"陆地格子暴露在外的边的总数"**

岛屿的周长看起来是个几何问题，但你把它转化一下就会发现，其实它是在统计：每个陆地格子的四条边里，有多少条边是"暴露"的——也就是这条边的另一侧不是陆地，是水域，或者已经超出了网格边界。把所有陆地格子的"暴露边数"加起来，就是整个岛屿的周长了。这个转化其实是解题的关键，因为它把一个看似需要描边、找轮廓的几何问题，变成了一个可以逐格独立统计的计数问题，思路一下就打开了。

**方法一：非 DFS 思路（直接双重循环统计，这是主要实现）**

那既然周长等于所有陆地格子暴露边数之和，最直接的做法是什么呢？就是双重循环遍历网格里的每一个格子，如果这个格子是陆地，也就是 `grid[i][j] == 1`，就检查它的上、下、左、右四个方向：

- 如果某个方向超出了网格边界，那这条边肯定暴露在外，周长 +1；
- 如果某个方向没超出边界，但该方向上是水域，也就是 `grid[ni][nj] == 0`，这条边也是暴露在外的，周长 +1；
- 如果该方向上是陆地，说明这条边是岛屿内部两个陆地格子的公共边，不暴露，不计入周长。

你会发现这个思路完全不需要递归，也不需要 `visited` 数组，为什么呢？因为它没有"遍历岛屿"这个过程——它只是在对网格做一次线性扫描，对每个陆地格子独立地做四次边界判断而已。四个方向可以用方向数组 `[(-1,0),(1,0),(0,-1),(0,1)]` 统一处理，这样能避免写四段重复的 if。

**方法二：DFS 思路（拿来对比讲一下）**

另一种更"图论化"的思路，是把岛屿看作一张图，陆地格子是节点，相邻陆地格子之间有边，从任意一个陆地格子出发做 DFS 遍历整个岛屿。DFS 过程中：

- 递归到某个坐标时，如果这个坐标已经超出网格边界，或者这个坐标是水域，说明碰到了岛屿的"边界"了，周长 +1，直接 `return`——这一步不再继续递归，因为水域或边界之外是没有陆地可走的；
- 如果这个坐标是陆地，但已经访问过了，也就是 `visited[i][j] == true`，说明是绕回来的格子，那也直接 `return`，不重复计数，也不再往下递归，这样能避免死循环；
- 除了这两种情况，也就是是陆地且未访问的时候，就标记 `visited[i][j] = true`，然后对四个方向分别递归。

伪代码：

```
function dfs(grid, i, j, visited):
    if (i, j) 越界 or grid[i][j] == 0:
        周长 += 1        // 碰到边界或水域，说明有一条边暴露
        return
    if visited[i][j]:
        return            // 已经访问过的陆地，不重复计数，不重复递归
    visited[i][j] = true  // 标记当前陆地已访问

    for (ni, nj) in 四个方向:
        dfs(grid, ni, nj, visited)
```

那 DFS 版本本质上是在图上做一次连通分量的遍历，每访问到一个"越界或水域"的相邻格子，就记一次周长贡献。思路上和方法一是完全等价的——本质上都是在数陆地格子的暴露边，只是遍历的组织方式不一样，从"双重循环扫描所有格子"变成了"从起点顺着岛屿的连通结构递归扩散"。

**两种方法对比一下，看看结论是啥**

| 维度 | 方法一（双重循环） | 方法二（DFS） |
|---|---|---|
| 是否需要 visited | 不需要 | 需要（防止在岛屿内部反复横跳导致死循环，也避免重复计数） |
| 是否需要递归 | 不需要 | 需要，有递归栈开销 |
| 实现复杂度 | 更简单，两层 for 循环 + 四方向判断 | 需要额外处理已访问陆地、越界、水域三种分支 |
| 时间复杂度 | O(mn) | O(mn)（每个陆地格子访问一次，加上四个方向的判断） |
| 空间复杂度 | O(1)（不算输入本身） | O(mn)（visited 数组）+ 递归栈最坏 O(mn) |

结论就是：**方法一明显更简洁高效**。为什么呢，我觉得有两点原因：第一，本题不需要"从岛屿的某个起点出发"这种探索过程，因为不管你从哪个陆地格子开始统计暴露边、按什么顺序统计，结果都是一样的，双重循环天然就能覆盖所有陆地格子，没必要非得多此一举用递归去"发现"它们；第二，方法一完全不需要额外的 `visited` 数组和递归调用栈，省去了 DFS 带来的那些额外空间开销和函数调用开销，在 `m x n` 规模下虽然同样是 O(mn)，但常数更小，也不容易因为岛屿形状特别长（比如一条蛇形岛屿）导致递归栈过深，甚至栈溢出。那 DFS 思路更适合什么场景呢？更适合那种"必须先找出岛屿范围再处理"的题目，比如统计岛屿数量、岛屿面积、区分多个岛屿。而本题已经明确告诉你只有一个岛屿，而且需要的信息（也就是暴露边数）和遍历顺序完全无关，所以直接扫描才是更对症的解法。

## 代码

### C++

```cpp
class Solution {
public:
    int islandPerimeter(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        int perimeter = 0;
        int dirs[4][2] = {{-1,0},{1,0},{0,-1},{0,1}};  // 上下左右四个方向

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] != 1) continue;  // 只处理陆地格子
                for (auto& d : dirs) {
                    int ni = i + d[0], nj = j + d[1];
                    // 越界，或者相邻格子是水域，说明这条边暴露在外
                    if (ni < 0 || ni >= m || nj < 0 || nj >= n || grid[ni][nj] == 0) {
                        perimeter++;
                    }
                }
            }
        }
        return perimeter;
    }
};
```

## 总结

- 岛屿周长说白了本质就是"所有陆地格子暴露在外的边数之和"，这个转化是解题的关键，把一个几何问题变成了逐格计数的问题。
- 方法一（双重循环统计）不需要递归，也不需要 `visited`，直接对每个陆地格子做四方向的边界/水域判断就行了，时间 O(mn)、空间 O(1)，是本题最简洁高效的做法。
- 方法二（DFS 遍历岛屿）思路上更"图论化"一点：碰到越界或水域就记一次周长，碰到已访问的陆地直接跳过不重复计数，本质上和方法一是等价的，只是多了 `visited` 数组和递归栈的开销。
- 那这两种方法怎么选呢？原则是：如果题目只需要统计跟遍历顺序无关的信息（就像本题这样），直接扫描更合适；但如果题目需要先明确岛屿的连通范围，再做进一步处理，比如统计岛屿数量、面积、区分多个岛屿，那 DFS/BFS 遍历会更自然一些。
