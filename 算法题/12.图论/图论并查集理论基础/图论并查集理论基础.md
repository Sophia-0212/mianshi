# 图论并查集理论基础

**题目描述**

这一篇不针对具体题目，讲一下并查集（Union-Find）这种数据结构的核心思想、路径压缩优化，以及它适合解决的问题类型，作为图论专题里"连通性判断"话题的第三种工具（前两种是 DFS 和 BFS）。

## 思路

**为什么需要并查集**

DFS/BFS 判断连通性的思路是"从一个点出发，把能到达的所有点都走一遍"，这对于"给定完整的图，判断两个点是否连通"这种静态查询是够用的。但如果场景是**动态的**——边是一条一条陆续加进来的，每加一条边就要立刻回答"现在这两个点是否连通"，那用 DFS/BFS 每次都要重新遍历一次图，效率就很低了（每次查询 O(V+E)）。并查集就是专门为这种"动态维护连通性、频繁查询两点是否连通"的场景设计的数据结构，单次操作的时间复杂度接近 O(1)（加了路径压缩和按秩合并后是均摊 O(log n) 甚至更低）。

**核心思想：用一个数组记录"父节点"**

并查集的底层说白了就是一个数组 `parent`，`parent[i]` 存的是节点 `i` 的"父节点"编号。一开始每个节点的父节点是自己（`parent[i] = i`），表示所有节点各自成一个独立的集合。整个数据结构的本质是把节点组织成若干棵"树"（不是二叉树，一个节点可以有任意多个孩子），**同一棵树里的所有节点都属于同一个连通分量**，树根就是这个集合的"代表元素"。

并查集只有两个基本操作，外加一个衍生判断：

- **find(x)**：找到节点 `x` 所在树的根节点。做法是顺着 `parent` 数组一路向上跳（`x = parent[x]`），直到跳到某个节点的父节点是它自己（说明这是根节点），返回这个根节点编号。
- **union(x, y)**：合并 `x` 和 `y` 所在的两个集合。做法是先分别找到 `x` 和 `y` 的根节点 `rootX`、`rootY`，如果两个根不同，就把其中一个根挂到另一个根下面（比如 `parent[rootX] = rootY`），这样两棵树就合并成了一棵树，也就是两个集合合并成了一个集合。
- **isSame(x, y)**：判断 `x` 和 `y` 是否属于同一个集合。做法是分别调用 `find(x)` 和 `find(y)`，比较两个根节点是否相同。

**路径压缩优化**

你想啊，如果不做任何优化，随着 `union` 不断执行，树可能会长成一条很长的链（比如每次都把新根接到链尾），这样 `find` 操作最坏情况下要跳 O(n) 次，就退化成链表的查找效率了。**路径压缩**的做法是：在 `find(x)` 递归/迭代查找根节点的过程中，把沿途经过的每一个节点都直接指向最终找到的根节点，而不是保持原来"逐级指向父节点"的链条。这样做一次 `find` 之后，这条路径上所有节点下次查找根节点都只需要一步。路径压缩通常用递归实现最直观：

```
function find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])   // 递归找根节点，同时把 x 直接接到根节点下面（路径压缩）
    return parent[x]
```

加了路径压缩后，`find` 和 `union` 的均摊时间复杂度会降到接近 O(1)（严格分析是 O(log n)，如果再加上"按秩合并"或"按大小合并"的优化，可以进一步逼近 O(1) 的反阿克曼函数级别，不过对做题而言，路径压缩已经足够高效了）。

**并查集适合解决的问题类型**

- **动态连通性判断**：不断加边，随时查询任意两点是否连通（这是并查集最本质的应用，比如 1971 题）。
- **环检测**：在构建一个无向图的过程中，如果某一步要加的边的两个端点已经属于同一个集合（`find` 结果相同），说明这条边会形成环，为什么呢，因为它连接的两个点已经能通过之前的边互相到达，这条新边就是"多余"的（比如 684、685 题）。
- **最小生成树 Kruskal 算法的基础**：Kruskal 算法按边权从小到大排序，依次尝试加边，用并查集判断加入这条边是否会形成环（会形成环就跳过，不会就加入生成树），这是并查集在生成树算法里的经典应用（这里不展开讲 Kruskal，只作为并查集应用场景的延伸提一下）。

**并查集与 DFS/BFS 的对比**

判断连通性这件事，DFS/BFS 和并查集都能做，区别在于使用场景：如果图是**静态给定**的（一次性给出所有边，只需要查询一次或很少次连通性），那 DFS/BFS 遍历一次就够了，不需要引入并查集这种额外的数据结构。但如果是**边逐渐增加、需要频繁查询**的动态场景，或者需要**在加边过程中实时判断是否成环**（DFS/BFS 判断成环需要额外记录父节点，比较复杂），那并查集就是更自然、更高效的选择。

**复杂度分析**

初始化 `parent` 数组 O(n)。单次 `find` 或 `union` 操作，在有路径压缩优化的情况下均摊接近 O(1)（严格为 O(log n)）。处理 `m` 条边总共的时间复杂度是 O(n + m)，比每次都用 DFS/BFS 重新遍历判断连通性（O(m × (n+m))）快得多。空间复杂度是 O(n)，只需要一个 `parent` 数组。

## 代码

并查集的四个基本操作模板（以数组实现为例）：

```
init(n):
    parent = new int[n]
    for i in 0..n-1:
        parent[i] = i          // 初始化时每个节点的父节点是自己

find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])   // 路径压缩：递归查找根节点的同时，把路径上的节点直接接到根节点
    return parent[x]

union(x, y):
    rootX = find(x)
    rootY = find(y)
    if rootX != rootY:
        parent[rootX] = rootY   // 把 x 的根接到 y 的根下面，合并两个集合

isSame(x, y):
    return find(x) == find(y)   // 根节点相同即属于同一个集合
```

## 总结

- 并查集的核心是用 `parent` 数组把节点组织成若干棵树，同一棵树内的节点属于同一个连通分量，树根是这个集合的代表元素。
- `find` 找根、`union` 合并集合、`isSame` 判断是否同集合，这是并查集的三个基本操作，路径压缩通过在 `find` 时把沿途节点直接接到根节点，把均摊时间复杂度优化到接近 O(1)。
- 并查集最适合"动态维护连通性、频繁查询两点是否连通"以及"边逐渐加入过程中实时检测是否成环"的场景；如果图是静态一次性给定、只需要查询一两次连通性，那 DFS/BFS 更简单直接。
- 并查集还是 Kruskal 最小生成树算法的核心组件，用来判断加入一条边是否会形成环，从而决定要不要把这条边纳入生成树。
