# 图论深搜理论基础

**题目描述**

这一篇不针对具体的题目，咱们主要聊聊图的存储方式，还有 DFS（深度优先搜索）在图论里的通用写法，算是整个图论专题的一个入门篇。

图这种结构，说白了就是由"节点"和"边"组成的：边可以是有方向的（有向图），也可以没方向（无向图），边上还可能带个权重，比如表示距离或者花费。那拿到一道图论题，第一件要想清楚的事其实永远是两个问题：这张图我要怎么存？用什么方式去遍历它？这一篇就是专门回答这两个问题的。

## 思路

**图的两种存储方式**

你想啊，图不像数组、链表那样天生就有个现成的存储结构，得咱们自己选一种方式，把"节点之间到底怎么连"这件事表示出来。常见的方式其实就两种。

**邻接矩阵**：搞一个 `n x n` 的二维数组 `grid`，`grid[i][j]` 就表示节点 `i` 到节点 `j` 之间有没有边（如果是带权图，就直接存边的权重，用 0 或者无穷大表示没边）。

- 空间复杂度是 O(n²)，这里的关键是：不管图里实际有多少条边，你都得先把这么大一个数组开出来。
- 查"i 和 j 之间有没有边"是 O(1)，因为就是直接下标访问，一步到位。
- 什么时候用它呢？节点数不多、边数接近节点数的平方（也就是稠密图），或者你需要频繁判断任意两个点是不是直连，这时候邻接矩阵就挺合适。
- 但它有个缺点：如果图很稀疏（边数比 n² 小很多，比如树这种结构），邻接矩阵就会浪费一大堆空间去存"这里没有边"这种没什么信息量的东西。

**邻接表**：这个思路不一样，给每个节点单独开一个列表，`list[i]` 里存的就是节点 `i` 直接相连的那些节点（如果是带权图，就存 `(邻居, 权重)` 这样的组合）。实现方式可以是数组套链表、数组套动态数组（比如 `vector<vector<int>>`），或者用哈希表也行。

- 空间复杂度是 O(n + e)，`e` 是边数，说白了就是只存实际存在的边，不会浪费空间。
- 查"i 的所有邻居"是 O(1)，直接拿到那个列表就行；但如果要查"i 和 j 之间有没有边"，就得遍历一遍 `list[i]`，最坏情况是 O(n)。
- 适用场景：边数比节点数平方小很多的稀疏图，说白了现实里大多数图论题遇到的都是稀疏图，所以邻接表其实是图论题里用得最多的存储方式。

那怎么记呢？其实一句话就能说清楚：**邻接矩阵是拿空间去换查询速度，邻接表反过来，是拿查询速度换空间**。稀疏图（也就是大多数场景）我们优先选邻接表；但如果题目里节点数特别小（比如就几百个以内），又需要频繁去查两个点是不是相连，那用邻接矩阵反而更省心。

**DFS 在图论中的通用模板**

DFS（深度优先搜索）的核心思想说白了就是"一条路走到底，走不通了（或者走完了）就退回上一个节点，换个方向接着走"。这其实跟二叉树的递归遍历、回溯算法的思路是一回事——图论里的 DFS 本质上也是在一棵隐式的"递归树"上做遍历，只不过这棵树是图的节点关系临时展开出来的，同一个节点可能在这棵树的好几个位置都出现（这也是为什么咱们需要 `visited` 数组，下面会讲到）。

写图论 DFS 我建议按"递归三部曲"来设计，这个思路和二叉树递归、回溯算法是完全一致的：

**第一步：确定递归函数的参数和返回值**

至少要传进去：当前访问到的节点（或者坐标），还有图本身（邻接表或者邻接矩阵）。至于是不是需要 `visited` 数组、路径 `path`、返回值（比如面积、路径列表），这个就得看具体题目要求了。

**第二步：确定终止条件**

图论 DFS 的终止条件跟树不太一样，树是"到叶子节点就停"，图论这边通常是这么几种情况：

- 当前节点已经被访问过了（这是为了避免重复访问，下面会细说），那就直接 `return`；
- 或者已经到达了题目要求的目标节点（比如找到终点了），这时候收集一下结果就 `return`；
- 或者当前节点已经没有任何可以扩展的邻居了（这种情况其实不需要显式判断，for 循环走完自然就退出了，这一层递归也就自然结束了）。

**第三步：确定单层搜索逻辑**

遍历当前节点的所有邻居，对每一个还没访问过的邻居，先标记成已访问，然后递归调用 DFS 深入到这个邻居里面去；等递归返回以后，如果题目要求回溯（比如要收集所有路径，而不只是判断连通性），这时候就得把刚才的标记或者路径记录撤销掉。

用伪代码写出来大概是这样：

```
function dfs(graph, node, visited):
    if node 已经是终止条件（如已访问过 / 到达目标）:
        处理结果
        return

    visited[node] = true   // 标记当前节点已访问

    for neighbor in graph[node]:   // 遍历当前节点的所有邻居
        if not visited[neighbor]:
            dfs(graph, neighbor, visited)   // 递归深入这个邻居

    // 如果需要回溯（收集所有路径而不仅仅判断连通性），在这里撤销标记
    // visited[node] = false
```

**visited 数组的作用**

`visited` 数组（或者集合）在图论 DFS 里几乎是个必需品，它的作用其实有两个：

1. **防止死循环**：图和树最大的区别就是图里可能有环（一个节点能通过若干条边绕回自己身上），你想啊，如果不标记已访问的节点，DFS 就会沿着这个环一直转下去，永远都停不下来。树因为天生无环（每个节点只有一个父节点），所以树的递归遍历一般是不需要 `visited` 的。
2. **避免重复计算或重复访问**：就算图是无环的（比如有向无环图，也就是 DAG），同一个节点也可能被好几条不同的路径指向。这时候不加 `visited` 的话，同一个节点就会被反复处理，不仅浪费时间，某些题目（比如统计连通分量个数）甚至会因此算出错误的结果。

这里有个地方要特别注意：`visited` 到底什么时候标记、什么时候撤销，得看题目类型。如果题目要求的是"把所有节点各标记一遍就行"（比如统计连通分量、算岛屿数量），那 `visited` 一旦标记成 true 就不用再撤销了。但如果题目要求的是"收集所有从起点到终点的路径"（比如力扣 797 题这种），那就必须在递归返回以后把 `visited` 的标记撤销掉（或者用撤销 `path` 来代替撤销 `visited`），为什么呢？因为同一个节点完全可能出现在好几条不同的合法路径里，不能因为它在路径 A 里被访问过了，就在路径 B 里把它跳过。

**复杂度分析**

DFS 遍历一遍图，时间复杂度通常是 O(V + E)（V 是节点数，E 是边数），这里的关键是：每个节点最多被访问一次（这是 `visited` 保证的），每条边也最多被遍历一次（从它两个端点各看一次，或者有向图就看一次）。但如果是"收集所有路径"这类问题（不撤销 `visited`，允许同一个节点出现在不同路径里），复杂度就会退化成指数级，因为这时候路径的数量本身可能就是指数级的。空间复杂度主要来自 `visited` 数组的 O(V)，再加上递归栈的深度，最坏情况下递归栈深度能到 O(V)。

## 总结

- 图的存储方式选邻接矩阵还是邻接表，说白了本质就是空间和查询速度之间的权衡：稀疏图选邻接表更省空间；稠密图，或者需要频繁判断两点是否直连的场景，选邻接矩阵更合适。
- 图论 DFS 遵循的是和二叉树、回溯一致的递归三部曲：先确定参数和返回值，再确定终止条件，最后确定单层搜索逻辑（遍历邻居、递归、可能还需要撤销）。
- `visited` 数组主要解决两个问题：防止图中的环导致死循环，还有避免同一个节点被重复处理；至于递归返回后要不要撤销标记，就得看题目要求的是"遍历型"（统计连通分量）还是"路径收集型"（找所有路径）。
- DFS 遍历一次图的复杂度是 O(V + E)，但如果任务是要穷举所有路径，那复杂度就会因为路径数量本身呈指数级增长而变得很高。
