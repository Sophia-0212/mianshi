# 684. 冗余连接

**题目描述**

给定一个无向图，它原本是一棵树（n 个节点，n-1 条边，无环、连通），现在多加了一条边，导致图中出现了一个环。`edges` 数组按顺序给出所有边（包括多余的那一条），要求找出这条可以删除、使图重新变成一棵树的边。如果有多个符合要求的答案，返回数组 `edges` 中最后出现的那一条。

```
示例：
输入: edges = [[1,2],[1,3],[2,3]]
输出: [2,3]
解释: 节点1、2、3原本应该构成一棵树，但1-2、1-3、2-3三条边形成了环，
     其中[2,3]是最后加入且导致成环的边，删除它后剩下[1,2]、[1,3]恰好构成一棵树
```

## 思路

这道题你一看就知道，其实是并查集"检测环"这个能力最直接的应用场景。你想啊，一棵树有个特点，就是任意两个节点之间只有一条唯一的路径，那如果再往里加一条边会怎么样呢？这条新边连接的两个节点，必然已经能通过树里原来的路径互相到达了，所以这条边一加进去，就会形成一个环。

那我的核心思路是这样的：按 `edges` 数组给的顺序，一条一条地尝试把每条边的两个端点 `union` 到同一个集合里去。关键是在 `union` 之前，我先用 `find` 检查一下这条边的两个端点是不是已经属于同一个集合了，也就是判断 `find(u) == find(v)` 是不是成立：

- 如果这两个端点还不在同一个集合里，说明这条边就是一条"正常"的树边，那我就正常执行 `union` 把它们合并起来。
- 但如果这两个端点已经在同一个集合里了，也就是它们的根节点相同，这就说明什么呢？说明这条边连接的两个点，已经能通过之前处理过的边互相到达了。那这条边一旦加进来，肯定就会形成环——它就是那条多余的边，我直接返回它，结束。

那为什么这么处理就一定对呢？因为题目保证输入里只多了一条边，也就是最多形成一个环，而且要求返回"最后出现"的那条多余边。我这里是按数组顺序正向遍历，第一次检测到成环就直接返回，这其实天然就满足了"最后出现"的要求——为什么呢？因为在它之前的所有边都能正常合并进去，不会被误判成多余边；它是第一条、也是唯一一条会触发成环判断的边。

那你可能会问，为什么不用 DFS 或 BFS 呢？说白了，如果用 DFS/BFS 来判断"加入这条边是否成环"，你得在加入每一条边之后，都重新做一次连通性检查，去判断这两个端点是不是已经连通了。如果图是一条边一条边逐步构建起来的，那每次都要重新遍历一遍已有的图，效率算下来是 O(e × (n+e))，挺高的。而并查集因为有路径压缩这个优化，每次 `union`、`find` 均摊下来接近 O(1)，处理完全部 `e` 条边总共也就 O(n + e)。所以说，这种"边逐步加入、动态判断连通性"的场景，并查集才是标准解法。

再说说复杂度：初始化并查集是 O(n)。然后遍历 `e` 条边（这里 `e` 其实就等于 `n`，因为树本身有 n-1 条边，再加上那1条多余边），每条边做一次 `find` 判断，可能再做一次 `union`，均摊下来都是 O(1)。所以总的时间复杂度是 O(n)，空间复杂度也是 O(n)，主要花在 `parent` 数组上。

## 代码

### C++

```cpp
class Solution {
public:
    vector<int> parent;

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);  // 路径压缩
        }
        return parent[x];
    }

    vector<int> findRedundantConnection(vector<vector<int>>& edges) {
        int n = edges.size();
        parent.resize(n + 1);  // 节点编号从1开始，开n+1大小
        for (int i = 0; i <= n; i++) {
            parent[i] = i;  // 初始化，每个节点的父节点是自己
        }
        for (auto& edge : edges) {
            int u = edge[0], v = edge[1];
            int rootU = find(u), rootV = find(v);
            if (rootU == rootV) {
                return edge;  // 两端点已同根，这条边会成环，就是多余边
            }
            parent[rootU] = rootV;  // 否则正常合并两个集合
        }
        return {};  // 理论上不会执行到这里（题目保证一定存在多余边）
    }
};
```

## 总结

- 咱们这道题的本质就是：树加上一条多余的边，必然会形成一个环，所以判断"多余边"说白了就是判断"这条边的两个端点，在加入它之前是不是已经连通了"。
- 做法上，按数组顺序正向遍历，用并查集逐条做 `union`，一旦遇到两端点已经同根的边，那就是答案了，这个做法天然就满足题目"返回最后出现的多余边"的要求，不用额外处理。
- 这其实是并查集处理"动态加边过程中检测环"这类场景的标准模板，相比每次都用 DFS/BFS 重新判断连通性，效率从 O(e×(n+e)) 直接降到了 O(n)，提升还是很明显的。
- 另外提一下，本题是 685 题（有向图版冗余连接）的基础，你把本题里"逐条 union、检测同根即成环"这个逻辑理解透了，其实就是理解 685 题里"纯环情况"那个分支的前提条件。
