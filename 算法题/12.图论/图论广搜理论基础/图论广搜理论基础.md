# 图论广搜理论基础

**题目描述**

这一篇也不针对具体题目，咱们来聊聊 BFS（广度优先搜索）在图论里的通用写法，以及 BFS 和 DFS 这两种搜索方式在图论场景下到底该怎么选，算是图论专题里 DFS 理论基础那一篇的姐妹篇。

## 思路

**BFS 的核心思想**

DFS 是"一条路走到底，走不通再回退"，走的是"纵深"路线；BFS 就不一样了，它是"一层一层往外扩散"，先把当前节点的所有邻居都访问完，再去访问邻居的邻居，走的是"横向铺开"路线。你要是把整个搜索过程画成一棵树，DFS 就是先纵向扎到底，再横向展开；BFS 反过来，是先把每一层横向走完，再往下一层走。

BFS 的标准实现靠的是一个队列（FIFO，先进先出）：把起点放进队列，然后不断从队头弹出一个节点，访问它所有的邻居，把里面没访问过的邻居标记成已访问，再放到队尾去，一直循环直到队列空了为止。因为队列的特性是"先加入的先被处理"，所以 BFS 天然就是按"离起点的层数"从近到远这么扩散的——这也是它为什么能求最短路径的根本原因。

**BFS 的通用模板**

```
function bfs(graph, start):
    queue = [start]          // 初始化队列，放入起点
    visited = {start}        // 标记起点已访问
    step = 0                 // 记录扩散的层数（如果需要求最短距离）

    while queue 不为空:
        size = queue.length          // 当前层的节点数量（一次性取出这一层的所有节点）
        for i in range(size):
            node = queue.popFront()  // 弹出队头节点
            if node 是目标节点:
                return step           // 第一次到达目标即为最短路径，直接返回
            for neighbor in graph[node]:   // 遍历当前节点的所有邻居
                if not visited[neighbor]:
                    visited[neighbor] = true   // 入队时立刻标记，防止重复入队
                    queue.pushBack(neighbor)
        step += 1   // 处理完一层，层数+1
```

这个模板里有两个实现细节咱们得特别留意一下：

**第一个是"入队的时候标记 visited"还是"出队的时候才标记"**。正确的做法是入队的时候就立刻标记为已访问，而不是等出队才标记。这里的关键是为什么呢？如果等出队才标记，那同一个节点在它还排着队等处理的这段时间里，就可能被其他节点当成"还没访问过的邻居"又放进队列一次，这样队列里就会出现重复的节点，不仅浪费时间，甚至还会导致逻辑出错（比如同一层被重复访问了两次）。入队的时候立刻标记，才能保证每个节点只会被加入队列一次。

**第二个是"按层处理"这种写法（就是内层 for 循环取 `size` 次这个操作）其实不是必须的**。如果题目不需要知道"现在走到第几层了"（比如只是判断连通性，或者遍历所有可达节点），这层 for 循环完全可以省掉，直接一个个弹出来处理就行；但如果题目需要求最短路径的步数（比如力扣 127 题单词接龙这种），按层处理能让你很清楚地知道"现在处理的是第几层"，所以这是求最短路径类 BFS 题目推荐的写法。

**BFS 与 DFS 在图论中的适用场景差异**

这其实是图论里最重要的一个选择题：拿到一道题，我该用 DFS 还是 BFS？咱们可以按下面这个经验来判断：

- **BFS 更适合求最短路径或者最少步数的问题**。为什么呢？因为 BFS 是按层扩散的，第一次到达某个节点的时候，走过的层数一定就是从起点到这个节点的最短路径长度（前提是每条边的权重都相同，也就是无权图）。DFS 找到的路径可不保证是最短的——DFS 可能一头钻进一条很长的路径里，绕了老大一圈弯路才到终点，就算后面会通过回溯去尝试别的路径，"第一次找到"的那条也不一定是最短的，除非把所有路径都穷举完再挑一个最短的比较，但这样一来就失去了 BFS "第一次到达即最短"这个效率优势了。
- **DFS 更适合遍历所有可能的路径，或者判断连通性这类问题**。如果题目要求"列出所有从 A 到 B 的路径"（比如力扣 797 题），DFS 配合回溯（递归到终点就收集路径，返回的时候撤销 path 最后一个元素）是最自然的写法，为什么呢，因为 DFS 的递归结构天生就契合"路径"这个概念——递归调用栈里当前的调用路径，本身就是图上从起点到当前节点的一条路径。如果题目只是判断"从 A 出发能不能到达图里所有节点"（比如力扣 841 题），或者"统计连通分量个数"（比如 200 题岛屿数量），那 DFS 和 BFS 其实都可以，选哪个更多是个人偏好，或者要考虑一下语言递归栈深度的问题（比如网格类问题的岛屿特别狭长的时候，DFS 递归可能会栈溢出，这种情况下 BFS 用显式队列会更安全）。

一句话记住就行：**要最短，选 BFS；要遍历全部或者求所有解，选 DFS**。

**复杂度分析**

BFS 遍历一次图的时间复杂度同样是 O(V + E)，这里的关键是：每个节点最多入队一次（出队的时候处理一次），每条边最多被遍历一次。空间复杂度是 O(V)，主要来自队列和 `visited` 数组，最坏情况下（比如图接近一条链，或者某一层节点特别多）队列里可能同时存在 O(V) 个节点。跟 DFS 用递归栈相比，BFS 用的是显式队列，不占用调用栈的空间，所以对于节点数特别多、递归深度可能超过语言默认栈大小限制的场景（比如特别大的网格），BFS 通常比递归版的 DFS 更稳妥。

## 总结

- BFS 是用队列来实现"层层扩散"这种遍历方式的，入队的时候立刻标记 `visited` 是标准写法，这样才能避免同一个节点被多次加入队列。
- BFS 因为是按层扩散、第一次到达就是最短路径，所以是求最短路径或最少步数问题的首选；DFS 因为递归结构天生契合"路径"这个概念，所以是遍历所有路径、判断连通性问题的首选。
- 判断连通性、统计连通分量这类问题，DFS 和 BFS 其实都能做，实际选的时候可以考虑一下递归栈深度的风险（网格特别大的时候 BFS 会更安全）。
- BFS 和 DFS 遍历一次图的时间复杂度都是 O(V + E)，核心差异在于空间使用方式（显式队列 vs 隐式递归栈）和访问顺序（层序 vs 深度优先）不一样。
