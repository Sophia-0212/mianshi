# Django 和 Flask 高频面试题

## 一、Django 高频面试题 Top 5

### 1. Django 和 Flask 有什么区别？

- Django 是“大而全”框架，内置 ORM、Admin、认证、表单和中间件。
- Flask 是轻量微框架，只提供路由、请求和响应等核心能力，其他功能通过扩展接入。
- Django 约定多，适合后台和标准化大型项目；Flask 更灵活，适合微服务和定制化 API。

### 2. Django 的 MVT 架构是什么？

- **Model**：数据模型和数据库交互。
- **View**：接收请求、执行业务逻辑、组织响应。
- **Template**：负责页面展示。
- URLConf 将请求路由到 View，流程是：请求 → URL → View → Model → Template → 响应。

### 3. Django ORM 如何工作？

Django ORM 用 Python 类映射数据表，通过 QuerySet 构造查询：

```python
User.objects.filter(age__gte=18)
```

QuerySet 通常惰性执行，真正取值时才访问数据库；复杂查询可使用 `Q`、`F`、聚合和原生 SQL。

### 4. Django 中间件是什么？

中间件位于请求和响应之间，常用于认证、日志、异常、Session 和跨域处理。请求阶段按注册顺序执行，响应阶段通常按相反顺序返回。

### 5. Django 如何处理事务和并发？

- `transaction.atomic()`：保证事务原子性。
- `select_for_update()`：加行锁。
- 唯一约束、幂等键：防止重复写入。
- 索引、连接池和合适的隔离级别：支撑高并发。

## 二、Flask 高频面试题 Top 5

### 1. Flask 为什么是微框架？

Flask 只提供路由、请求、响应和模板等基础能力，不强制绑定 ORM、认证或项目结构；数据库、缓存和 JWT 等通过扩展接入，因此灵活，但大型项目需要自行制定规范。

### 2. Flask 的请求上下文和应用上下文是什么？

- **请求上下文**：保存 `request`、`session` 等当前请求数据。
- **应用上下文**：保存 `current_app`、`g` 等应用级数据。
- 两者通过上下文栈实现；离开上下文后不能访问这些代理对象。

### 3. `g`、`current_app`、`request`、`session` 有什么区别？

- `request`：当前 HTTP 请求。
- `session`：当前用户会话。
- `current_app`：当前 Flask 应用。
- `g`：当前请求生命周期内临时保存数据。

### 4. Flask 如何管理数据库连接？

常用 Flask-SQLAlchemy 或 SQLAlchemy。请求开始时获取 Session，成功后提交，异常时回滚，请求结束时释放；生产环境使用连接池，不跨线程或协程随意共享连接。

### 5. Flask 如何实现异常处理、认证和模块拆分？

- `@app.errorhandler()`：统一处理异常。
- 装饰器或 Flask-JWT-Extended：实现认证。
- Blueprint：拆分业务模块。
- 扩展：接入数据库、缓存、JWT 和 CORS。
- Gunicorn、uWSGI：托管生产服务。

## 三、额外高频面试题 Top 5

### 1. Django 为什么适合大型项目？

因为它提供明确的项目结构和完整组件，包含 ORM、Admin、认证、表单和中间件，团队可以按统一约定开发；代价是灵活性和定制成本较低。

### 2. Flask 如何组织大型项目？

使用 Application Factory 创建应用，通过 Blueprint 按业务拆分路由，扩展集中初始化；配置、服务、数据访问和异常处理分别独立，避免所有代码堆在一个文件中。

### 3. Django 和 Flask 如何保证接口安全？

输入校验、身份认证、权限控制、CSRF 防护、SQL 参数化、限流和安全响应头都要配合使用。框架提供默认能力，但不能替代业务授权和安全配置。

### 4. Django ORM 和 SQLAlchemy 如何选择？

Django ORM 集成度高、约定统一，适合 Django 全家桶项目；SQLAlchemy 更灵活、表达能力强，适合 Flask 或需要精细控制 SQL 的服务。

### 5. Django、Flask 和 FastAPI 如何选择？

- Django：功能完整，适合后台和大型业务系统。
- Flask：轻量灵活，适合小型服务和定制化 API。
- FastAPI：原生异步、类型提示和自动文档完善，适合高并发 API 与 AI 服务。

选择依据是项目规模、团队规范、异步需求和生态依赖。
