# Go 学习路线图

建议按 **8 周、每周 8～10 小时**学习。主线是：

**语言基础 → 数据与抽象 → 工程与测试 → 并发 → 服务开发 → 可靠性与性能。**

目标：独立写出一个**可测试、可取消、可排查问题的 Go 服务**。

以下默认你已有一门编程语言基础；零基础先补变量、函数、循环、调用栈，再进入路线。

用一个项目贯穿学习：**任务执行服务**。从命令行接收任务，逐步支持 HTTP、并发执行、结果存储；最后可扩展为 Agent 工具执行器。

| 阶段 | 必学内容 | 项目产出 | 过关标准 |
|---|---|---|---|
| 第 1 周：基本语法 | 包、模块、变量、类型、控制流、函数、多返回值、指针、结构体 | 命令行任务执行器 | 能独立拆函数、拆包，处理输入和错误 |
| 第 2 周：数据与抽象 | 数组、切片、map、方法、接口、零值、`nil`、错误处理 | 增加多种任务类型 | 能解释切片共享、值复制、接口隐式实现 |
| 第 3 周：工程与测试 | `go mod`、`gofmt`、包边界、表驱动测试、子测试、依赖注入 | 为核心逻辑补测试 | 测试覆盖正常、失败和边界情况 |
| 第 4 周：并发基础 | goroutine、channel、`select`、`Mutex`、`WaitGroup` | 支持并发执行任务 | 能发现数据竞争，说明每个 goroutine 如何退出 |
| 第 5 周：并发控制 | `context`、超时、取消、并发上限、背压 | 有限并发的任务调度器 | 调用取消后任务能停止；任务堆积不会无限创建 goroutine |
| 第 6 周：HTTP 服务 | `net/http`、JSON、路由、中间件、参数校验、HTTP 客户端 | 提交任务、查询状态 API | 能贯通请求、业务逻辑、响应和错误处理 |
| 第 7 周：持久化与可靠性 | SQL、`database/sql`、连接池、事务、幂等、重试、优雅关闭 | 保存任务及结果 | 重启可查结果；重复请求不会重复执行 |
| 第 8 周：诊断与交付 | `slog`、基准测试、`-race`、`pprof`、构建、配置 | 可运行、可诊断的完整服务 | 能定位一次竞态或性能问题，并验证修复效果 |

学习时，优先建立这 **5 个直觉**：

1. **Go 的赋值和传参都是值复制。**  
   但复制切片后，两者可能仍共享底层数组。理解“复制了什么”，才能判断修改影响谁。

2. **接口描述调用方需要的能力。**  
   例如调度器只需要 `Execute(ctx) error`，就不应依赖某个具体 HTTP 工具。先出现替换需求，再提炼小接口。

3. **错误是需要逐层处理的信息。**  
   底层补充原因，上层决定重试、返回还是终止。学习 `errors.Is/As` 和 `%w`；避免每层重复打印同一个错误。

4. **并发的核心是生命周期和资源上限。**  
   每启动一个 goroutine，都回答：谁负责它、如何停止、最多存在多少个。

5. **`context` 传递取消信号，不会强制终止任务。**  
   执行逻辑必须主动响应；下游网络、数据库调用也要接收它。

每天按这个闭环推进：

**读一个概念 → 写最小例子 → 故意制造错误 → 解释原因 → 用进项目。**

例如学切片：先观察 `append` 前后的修改结果，再解释底层数组是否共享；学并发：先制造计数器竞态，再用 `go test -race` 检查并修复。

优先级要守住：

- **必须熟练**：切片、map、接口、错误、测试、`context`、并发控制、HTTP。
- **项目中掌握**：泛型、事务、连接池、性能分析。
- **后续深入**：反射、`unsafe`、调度器源码、GC 算法、复杂框架。

完成路线的验收题：**同时提交 100 个任务，只允许 10 个执行；每个任务有超时；客户端取消后能释放资源；重复提交不重复执行；失败原因可追踪。**

能独立实现并解释其中的取舍，就具备了 Go 后端开发的核心能力。

对于基本数据类型（如整数、浮点数、布尔值等）和结构体，传递的是值的副本，修改形参的值不会影响实参。
对于切片、映射、通道等引用类型，传递的是引用的副本，修改形参的内容会影响到实参。

数组：赋值、传参都是值传递，修改a不改b（显式使用指针除外），数组长度不同类型不同，数组长度不能改变

slice = cap + 指针（共享底层数组）+ len，改a则改b。

append 只能操作切片（slice），不能直接操作数组（array）。超出cap的则成新slice

map ：表示key -> value ,必须初始化后写入：slice和map不可比较不可作为map的key。map的:=赋值是指针，改a则改b (区分:数组是复制全部元素，map是复制描述信息，共享内部数据)，如果需要复制独立的map，需要用range遍历里面的每一个key-value
-两种创建方式：
m := make(map[string]int)//可是初始化后写入
m := map[string]int{"go": 1,}
注意：
var m map[string]int 得到的是 nil map，可读不能写入。
不存在的键也会返回 int 的零值 0，所以必须通过 ok 区分：
value, ok := scores["java"]
fmt.Println(value) // 0 // 两种情况：1.存在，值为0. 2.不存在，返回0
fmt.Println(ok)    // false
区分nil map 和 空map:1.空map可以写，nil map不可以写。2.空map用make创建，nil map用var


零值：整数、浮点：0，字符串:'',布尔：false,结构体的每个字段，也会得到各自的零值。未显式赋值的部分，Go 用零值补齐。
nil：它是指针、切片、map、接口等类型的零值。
nil 指针表示没有对象没有地址，0 表示对象的值是零。
var a []int      // nil 切片
b := []int{}    // 非 nil 的空切片
两者都可以直接 append，不必提前初始化。
nil 切片可以 append，但不能直接通过下标修改。append 会按需分配空间；下标赋值不会替你初始化容器。nil map不可以直接修改

Add(1) 要放在启动 goroutine 之前，如果放进新 goroutine，它可能还没执行 Add，主 goroutine 就先执行了 Wait，看到计数为零直接离开。
mu.Lock()   // 获取锁；被别人持有时，就等待
mu.Unlock() // 释放锁
Go 的 Mutex 不可重入：已经持有锁，也不能再次获取它。
两种锁死情况：1.A已经拿到A锁，又准备拿A锁。2.A拿B锁，B拿A锁，互等
 Mutex 同一时刻只允许一个持锁者。但如果大家都只读取数据，可以允许一起读。
 sync.RWMutex：读写锁。多人一起看 → 可以 ，有人修改   → 其他人不能看，也不能改。 只读取：RLock / RUnlock。会修改：Lock / Unlock

无缓冲channel:
ch := make(chan int) // 无缓冲：当面交接
ch <- value   // 发送
value := <-ch // 接收
- 你先伸手接：等同伴算完。
- 同伴先算完：等你伸手接。
- 双方就绪：交接完成，各自继续。
如果还没有人发送，就会停在这里等待，不会直接执行下面的打印。

有缓冲channel:
ch := make(chan int, 2) // 有缓冲：可以存放 2 个值
无缓冲是当面递东西，有缓冲是在两人之间放一个收纳箱。
ch := make(chan int, 2)
ch <- 10
ch <- 20
ch <- 30 // 缓冲区已满，等待有人接收
fmt.Println(<-ch)
这段代码会死锁：发送 30 卡住了，后面的接收永远执行不到，也没有其他 goroutine 来接收。

关闭channel:close(ch),通常由发送方关闭, 关闭不是清空数据，也不是强制停止 goroutine，而是声明“不会再发送”。

   类型          允许的操作
  ━━━━━━━━━━━━  ━━━━━━━━━━━━
   chan int      发送、接收
  ────────────  ────────────
   chan<- int    只能发送
  ────────────  ────────────
   <-chan int    只能接收

select:
普通：顺序接收：按写好的顺序等待。先收第一个，再收第二个，即使第二个先好，也要等着。
select: 谁先好接受谁，不用强行等待
超时后 main 返回，整个程序退出；如果是在持续运行的服务里，后台任务仍会继续。如何让任务主动停止，后面学 context。

nil channel：发送和接收都会一直等待。
var ch chan int
ch <- 10 // 永久阻塞
<-ch     // 永久阻塞
所以，正常通信前要用 make 创建通道：ch := make(chan int)
那 nil channel 有什么用？ 在 select 中，它可以用来禁用某个分支： nil channel 在普通收发中会阻塞，在 select 中相当于禁用对应分支。
