# Docker 高频面试题 Top 10

## 1. Docker 和虚拟机的区别？

| 对比项 | Docker 容器 | 虚拟机 |
|---|---|---|
| 隔离级别 | 进程级隔离，共享主机内核 | 硬件级隔离，独立内核 |
| 启动速度 | 秒级 | 分钟级 |
| 资源占用 | 几十MB~几百MB | 几GB |
| 性能 | 接近原生 | 有虚拟化损耗 |
| 隔离性 | 弱于VM（共享内核，隔离性略差） | 强 |

核心：容器基于 Linux Namespace（隔离）+ Cgroups（限制资源）实现轻量级隔离，不需要 Hypervisor 和 Guest OS。

## 2. 镜像（Image）和容器（Container）的关系？

- 镜像：只读模板，包含文件系统、依赖、启动配置，类似"类"
- 容器：镜像的运行实例，在镜像基础上加一层可写层，类似"对象"
- 一个镜像可以创建多个容器实例，容器间相互隔离

```bash
docker run image_name   # 基于镜像启动一个容器
docker commit container_name new_image  # 容器打包成新镜像
```

## 3. Dockerfile 常用指令？

| 指令 | 作用 |
|---|---|
| FROM | 指定基础镜像 |
| RUN | 构建时执行命令，会生成新的镜像层 |
| COPY / ADD | 拷贝文件到镜像；ADD支持解压和URL，COPY更单纯推荐用COPY |
| WORKDIR | 设置工作目录 |
| ENV | 设置环境变量 |
| EXPOSE | 声明容器运行时监听端口（仅声明，不做端口映射） |
| VOLUME | 声明挂载点 |
| CMD | 容器启动时默认执行命令，可被 `docker run` 参数覆盖 |
| ENTRYPOINT | 容器启动时固定执行的命令，不易被覆盖 |

## 4. CMD 和 ENTRYPOINT 区别？

- CMD：提供默认执行命令，`docker run image xxx` 中的 `xxx` 会整体替换 CMD
- ENTRYPOINT：容器的主命令，`docker run image xxx` 中的 `xxx` 作为参数追加，不会替换
- 常见组合：ENTRYPOINT 写死主程序，CMD 写默认参数，方便运行时覆盖参数不覆盖主程序

```dockerfile
ENTRYPOINT ["nginx"]
CMD ["-g", "daemon off;"]
```

## 5. Docker 网络模式有哪几种？

- **bridge**（默认）：docker0虚拟桥，容器间可通过自定义网络+DNS通信
- **host**：容器直接使用主机网络栈，无隔离，性能最好
- **none**：无网络，完全隔离
- **container**：与指定容器共享网络namespace
- **overlay**：跨主机容器通信，用于Docker Swarm集群

## 6. 数据卷（Volume）作用？和 Bind Mount 区别？

作用：容器删除后数据不丢失，实现数据持久化；多容器间共享数据。

| 类型 | 说明 | 管理方 |
|---|---|---|
| Volume | Docker管理的存储，位于 `/var/lib/docker/volumes` | Docker |
| Bind Mount | 挂载主机任意路径到容器 | 用户手动指定路径 |
| tmpfs | 挂载到内存，不落盘 | 内存 |

Volume 更适合生产环境（可备份、可迁移、驱动可插拔），Bind Mount 更适合开发调试（直接映射本地代码）。

## 7. 多阶段构建（Multi-stage Build）解决什么问题？

解决编译型语言镜像体积过大问题：编译阶段依赖的工具链（如Go/Node的编译器、构建依赖）不需要出现在最终运行镜像里。

```dockerfile
FROM golang:1.21 AS builder
WORKDIR /app
COPY . .
RUN go build -o main .

FROM alpine:3.19
COPY --from=builder /app/main /main
CMD ["/main"]
```

好处：最终镜像只保留运行时必需文件，体积可从几百MB降到几MB~几十MB，同时减少攻击面。

## 8. 镜像分层原理，为什么能省空间？

- Docker 镜像由多个只读层叠加而成，基于 UnionFS（联合文件系统，如 OverlayFS）
- 每条 Dockerfile 指令（RUN/COPY/ADD）生成一层，多个镜像可共享相同的底层（如相同的基础镜像层）
- 容器运行时在最上层加一层可写层，遵循 **写时复制（Copy-on-Write, COW）**：修改文件时先复制到可写层再改，不动只读层原始数据

好处：镜像复用、节省磁盘、加速拉取（相同层只下载一次）。

## 9. 容器间通信怎么做？

- 旧方式 `--link`：已废弃，硬编码环境变量方式不灵活
- 推荐方式：创建自定义 bridge 网络，容器加入同一网络后可通过**容器名/服务名**自动 DNS 解析互相访问

```bash
docker network create my-net
docker run -d --name app1 --network my-net image1
docker run -d --name app2 --network my-net image2
# app2 内部可以直接 ping app1
```

## 10. docker-compose 作用？和 k8s 区别？

**docker-compose**：通过一个 YAML 文件定义多容器应用（服务、网络、数据卷），一条命令 `docker-compose up` 启停整套应用，适合单机开发/测试环境。

**k8s（Kubernetes）**：生产级容器编排平台，解决跨多台机器的：

| 能力 | docker-compose | k8s |
|---|---|---|
| 适用场景 | 单机 | 集群/多机 |
| 弹性伸缩 | 无 | 支持（HPA） |
| 自愈能力 | 弱 | 强（Pod自动重启/重新调度） |
| 服务发现/负载均衡 | 简单DNS | Service/Ingress完整方案 |
| 滚动更新 | 无 | 原生支持 |

一句话：compose解决"怎么定义并启动一组容器"，k8s解决"如何在集群上稳定、弹性地运行和管理这些容器"。
