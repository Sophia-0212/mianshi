# 交叉评测实验室

你扮演排查负责人，逐步审查证据、选择动作、观察结果，最后理解为什么需要交叉盲评。

所有规则、模型输出、标签与数字均为教学模拟，无网络、无模型调用、无额外依赖，不作为真实项目经历证据。

## 启动

```bash
python3 '/Users/lixiaofei05/Desktop/ms/AI_Agent/项目/CRM智能问答检索引擎(RAG系统)/项目/07-RAG评测体系与优化闭环/交叉评测实验.py'
```

输入数字做选择，回车继续，`r` 重看选项，`q` 或 Ctrl+C 退出。完整体验约8–12分钟。
选错不会终止，会解释为什么不能得出结论；部分选项展开额外诊断。各分支最终回到同一教学链路。

## 选项

- `--no-animation`：关闭步骤间停顿。
- `--auto`：自动演示全部步骤，不等待输入。
- `--report 学习记录.json`：保存选择、观察结果和全部模拟统计记录；已有文件不会覆盖。

## 学习路径

高分答案出错 → 统一人工标准 → 升级同系列评委 → 更换跨系列评委 → 检查误杀 → 更换答案来源 → 交叉盲评 → 查看中间判断 → 独立验证。

后续批量统计使用“业务条件完整性通过/不通过”的自定义判据，不把它等同于 RAGAS Faithfulness。
批量记录是构造的判定标签，并非真实模型输出集；演示不做统计显著性检验，不证明任何真实模型的偏好。
换评委改善的是评测可信度，不会直接改变已有RAG答案质量。
