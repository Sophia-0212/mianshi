# 企业级 RAG 评测集如何划分

## 一、核心原则

评测集采用**分层 + 多标签**，不只按“简单题、难题”分类。一条样本可以同时属于“审批权限 + 表格 + 高风险 + 多跳问题”。

分类必须来自真实线上流量、历史 badcase 和业务专家补充，不能只由开发人员主观编题。

## 二、六个分类维度

### 1. 业务域

覆盖 CRM 核心业务：

- 客户归属与撞单
- 商机准入
- 开户与投放
- 合同与审批
- 预算、价格与折扣
- 行业准入
- 产品政策
- 系统操作

样本按线上流量分布抽样，低频高风险业务设置最低样本数。

### 2. 问题意图

- 事实查询：规则是什么
- 条件判断：是否满足要求
- 流程查询：下一步怎么做
- 多条件判断：同时满足哪些条件
- 对比分析：产品或政策差异
- 多跳问题：需要组合多个文档
- 无答案问题：知识库没有相关内容
- 冲突问题：新旧规则或多文档冲突

### 3. 难度

```text
L1：单文档、单事实
L2：单文档、多条件
L3：跨文档、多跳推理
L4：历史版本、冲突规则、复杂约束
```

### 4. 风险等级

- 普通：操作说明、产品介绍
- 中风险：客户归属、商机准入
- 高风险：价格、折扣、审批权限、合同和合规

高风险样本单独统计，不能被大量简单问题的平均分掩盖。

### 5. 文档特征

- 普通段落
- 表格
- 列表和前导句
- 多级标题
- 跨页内容
- 历史版本
- PDF/OCR 文档
- 中英文或缩写混合
- 业务编号和专有名词

### 6. 答案类型

- 有明确答案
- 证据不足，应拒答
- 需要澄清
- 应转人工
- 存在多个合法答案
- 文档之间存在冲突

## 三、样本结构

```json
{
  "question": "区域交叉客户如何归属？",
  "reference_answer": "……",
  "relevant_documents": ["doc_102", "doc_205"],
  "category": "客户归属",
  "intent": "条件判断",
  "difficulty": "L3",
  "risk_level": "high",
  "document_type": ["table", "versioned"],
  "answer_type": "supported"
}
```

## 四、300 条 Golden Set 的建议构成

```text
业务域覆盖：约 200 条，按线上流量分布
高风险问题：约 60 条
多跳和历史版本问题：约 60 条
表格、列表、OCR 等特殊文档：约 50 条
无答案、拒答、冲突问题：约 40 条
```

这些标签允许重叠，总数不需要相加等于 300。

## 五、数据集拆分

```text
开发集：用于调参数和定位 badcase
验证集：用于比较不同方案
发布集：固定不参与调参，只用于回归和发布门禁
```

发布集必须冻结版本。每次切分策略、Embedding、Rerank、Prompt 或模型变更，都要在发布集上重新运行，防止在同一批数据上反复调参造成指标虚高。

## 六、评测执行流程

```text
评测集分类
→ 调用真实 RAG 链路生成结果
→ 保存答案和实际召回上下文
→ 使用 RAGAS + GLM 评测
→ 按标签统计指标
→ 分析 badcase
→ 修复后在发布集回归
```

RAGAS 不是分类器。分类在评测前完成；RAGAS 负责根据真实生成结果计算 Context Recall、Context Precision、Faithfulness 和 Factual Correctness。

## 面试表述

> 我们的评测集采用多标签分层，不只按业务分类，还同时标记问题意图、难度、风险等级、文档类型和答案类型。这样既能看总体指标，也能单独看审批权限、历史版本、表格问题和无答案问题。开发集用于调参，验证集用于方案比较，固定发布集只用于回归和上线门禁，避免在同一批数据上反复调参造成指标虚高。

## 七、PR 冒烟集和 Golden Set 如何产生

评测集的产生顺序是：

```text
原始样本池
→ 清洗与去重
→ 逐条打标
→ 按标签分层
→ 按用途抽样
→ 形成不同评测集
```

样本创建时就完成业务域、意图、难度、风险、文档类型和答案类型标注。来源包括脱敏线上问题、历史 badcase、业务专家补充问题、文档变更后的新增问题和高风险专项问题。

### 1. Master Pool

Master Pool 是带完整标签的主样本池，所有评测集都从这里按分层规则抽样。它保留样本来源、标注人、标注时间、文档版本和复核记录。

### 2. PR 冒烟集

PR 冒烟集从已标注样本中挑选关键路径，通常 20～50 条，优先覆盖：

- 核心业务问题；
- 高风险问题；
- 历史高频 badcase；
- 表格、版本和拒答场景；
- 能快速发现服务不可用的样本。

它主要检查代码、接口和核心链路是否正常，不代替完整质量评测。

### 3. Golden Set

Golden Set 同样从 Master Pool 分层抽样，通常 200～300 条，要求覆盖主要业务、复杂问题、高风险场景、特殊文档和不同答案类型。样本经过业务专家复核后冻结，只用于版本回归和发布门禁。

Golden Set 允许修正明确的标注错误，但不能为了提高新版本得分而改题、改答案或删除困难样本。

### 4. 数据集关系

```text
Master Pool
├── PR Smoke Set：20～50 条，快速检查
├── Dev Set：允许调参
├── Validation Set：比较方案
└── Golden Set：冻结，发布门禁
```

PR 冒烟集可以是 Golden Set 的关键子集，也可以从 Master Pool 独立抽样。所有集合都必须记录版本和样本 ID，避免同一问题泄漏到多个用途相冲突的集合中。

### 面试表述

> 我们先建立带完整标签的 Master Pool，每条样本创建时就完成业务域、意图、难度、风险和文档特征标注。之后根据用途分层抽样：PR 冒烟集只保留 20～50 条关键路径和高风险 badcase，用于快速发现代码或核心链路回退；Golden Set 通常保留 200～300 条，覆盖主要业务、复杂问题和异常场景，经过人工复核后冻结，专门用于版本回归和发布门禁。两者来自同一个已标注样本池，但用途、规模和稳定性要求不同。
