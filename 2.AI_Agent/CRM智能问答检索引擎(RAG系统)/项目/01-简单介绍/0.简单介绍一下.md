# 介绍一下

我最近参与的是一个搜索推广 CRM 智能问答项目，主要服务销售、客服和广告运营人员，目前总用户1640多，日活890多。

项目主要解决知识分散、查找耗时和问答不准确的问题。销售 SOP、开户规范、客户归属规则和投放操作手册分散在多份文档中，我们通过 RAG 接入现有智能
助手，让员工能够统一查询并连续追问。整个系统主要分为三部分：知识侧、检索侧、问答侧。我全程都有参与。

知识侧，参与实现 Markdown 解析与结构感知切分，保留标题层级、表头和列表前导句，并采用 解析、写入 双进程流水线 完成批量入库。我经历了V1版本到V3版本迭代，的全过程

检索侧，我们通过提前对现有业务、知识库文档总数据量的分析，做了技术选型，最后选择基于 Milvus 构建 BGE 向量与 BM25 混合检索，通过 RRF 融合，再用 CrossEncoder 精排，兼顾口语表达和政策名称、CRM业务术语等精确查询。

问答侧，基于 LangGraph 构建支持多轮对话的知识问答型 RAG，通过相关性判断、答案校验和受控查询重写，提高复杂问题的回答质量。针对 Agent 可能出现的无限循环、重复检索和工具失败，我们增加了多层运行时兜底。

评测时，我们分别关注 召回率、排序质量 和 答案忠实度，通过 新旧方案对照 定位问题，持续优化整个问答链路。业务指标通过：问题解决率、转人工率、点赞点踩率 来衡量是否对一线业务有帮助。
