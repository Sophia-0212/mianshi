# 持久化：RDB 与 AOF

## RDB

RDB 是某一时刻的内存快照：

```text
内存 → dump.rdb
```

优点：文件紧凑，恢复快。  
缺点：两次快照之间的数据可能丢失。

## AOF

AOF 记录写命令：

```text
SET k v → appendonly.aof
```

优点：数据丢失窗口较小。  
缺点：文件更大，恢复通常更慢。

## fsync 策略

- `always`：每次写都刷盘，最可靠，性能最低。
- `everysec`：每秒刷盘，常用，最多丢约 1 秒数据。
- `no`：由操作系统决定，性能高，风险最大。

## AOF 重写

读取当前有效数据，生成更短的命令文件，删除历史冗余命令。

## 混合持久化

RDB 保存全量快照，AOF 保存后续增量，兼顾恢复速度和数据完整性。

## 选择

- 可接受少量丢失：RDB 或混合持久化。
- 更重视数据完整性：AOF 或混合持久化。
- 核心数据不能只依赖 Redis 持久化，应保留数据库主存储。
