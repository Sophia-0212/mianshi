# Redis 分布式锁

## 加锁

```redis
SET lock:order:1001 request-id NX EX 30
```

- `NX`：不存在才写入，保证互斥。
- `EX 30`：自动过期，避免死锁。
- `request-id`：标识锁持有者。

## 解锁

不能直接 `DEL`，必须校验持有者，并用 Lua 保证判断和删除原子化：

```lua
if redis.call('get', KEYS[1]) == ARGV[1] then
    return redis.call('del', KEYS[1])
end
return 0
```

## 续期

业务执行时间可能超过租期，需要看门狗定期续期；服务宕机后停止续期，锁最终释放。

## 风险

- 锁过期但业务仍在执行。
- 主从切换导致锁状态丢失。
- 网络分区造成多个客户端误判。

极高一致性场景应评估 ZooKeeper、etcd 或数据库方案。锁不能代替幂等和数据库约束。
