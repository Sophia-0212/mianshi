# 缓存常见问题

## 缓存穿透

请求查询不存在的数据，缓存和数据库都没有。

```text
大量无效请求 → 数据库
```

解决：参数校验、布隆过滤器、缓存空值。

## 缓存击穿

单个热点 Key 过期，大量请求同时查数据库。

解决：互斥锁、逻辑过期、热点 Key 延长 TTL。

## 缓存雪崩

大量 Key 同时过期，或 Redis 整体不可用。

解决：TTL 加随机值、多级缓存、限流熔断、集群高可用。

## 热 Key

单个 Key 请求集中，导致节点或 CPU 压力过高。

解决：本地缓存、Key 拆分、读副本、热点监控。

## 大 Key

单个 Key 的 Value 或集合过大，导致内存、网络和删除操作变慢。

解决：拆分 Key、限制集合大小、分批处理、使用 `UNLINK`。

## 缓存一致性

常见策略：

```text
更新数据库 → 删除缓存
```

删除失败时使用重试、消息补偿或延迟双删。高一致性场景应以数据库为准，并设计校验和修复机制。
