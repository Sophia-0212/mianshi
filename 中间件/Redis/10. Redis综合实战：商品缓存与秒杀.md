# Redis 综合实战：商品缓存与秒杀

## 商品查询

```text
请求
  ↓
Redis 商品缓存
  ├── 命中：返回
  └── 未命中：查询 MySQL → 回写 Redis → 返回
```

防护：

- 空值缓存和布隆过滤器防穿透。
- 互斥锁防击穿。
- TTL 随机化防雪崩。
- 热点商品使用本地缓存。

## 秒杀库存

不能先查库存再扣库存：

```text
查库存 = 1
多个请求同时判断成功
多个请求同时扣减
→ 超卖
```

应使用原子命令或 Lua：

```lua
local stock = tonumber(redis.call('get', KEYS[1]))
if not stock or stock <= 0 then
    return 0
end
redis.call('decrby', KEYS[1], ARGV[1])
return 1
```

## 秒杀链路

```text
请求
  ↓
限流
  ↓
Redis 原子扣库存
  ↓
写入订单消息
  ↓
MQ 异步创建订单
  ↓
MySQL 持久化
```

## 必须解决

- 同一用户重复下单：业务唯一索引或幂等键。
- Redis 扣库存成功但订单失败：补偿、回滚或对账。
- MQ 重复消费：消费幂等。
- Redis 故障：降级、熔断、限流。
- 库存初始化错误：数据库与 Redis 对账。

## 关键取舍

Redis 负责高并发校验和扣减，MySQL 负责最终持久化；两者之间通过可靠消息、幂等和补偿实现最终一致性。
