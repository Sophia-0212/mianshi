# 过期删除与内存淘汰

## 过期删除

设置 TTL 后，Key 到期不代表立即删除。

- 惰性删除：访问 Key 时检查，过期则删除。
- 定期删除：后台周期性抽样清理。

这样避免遍历全部 Key 阻塞 Redis。

## 内存淘汰

达到 `maxmemory` 后，根据策略删除 Key：

- `noeviction`：拒绝写入。
- `allkeys-lru`：所有 Key 中淘汰最近最少使用者。
- `allkeys-lfu`：所有 Key 中淘汰访问频率最低者。
- `volatile-lru`：仅设置 TTL 的 Key 中执行 LRU。
- `volatile-ttl`：优先淘汰剩余 TTL 最短者。
- `allkeys-random`：随机淘汰。

## 必须区分

```text
过期删除：Key 到期后的清理
内存淘汰：内存不足时的清理
```

缓存通常选择 `allkeys-lru` 或 `allkeys-lfu`，并设置合理 TTL。
