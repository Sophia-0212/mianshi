# 主从、哨兵与 Cluster

## 主从复制

```text
Master → Replica
```

主节点处理写入，从节点复制数据并可分担读请求。复制通常是异步的，存在短暂延迟。

## 哨兵

哨兵负责：

- 监控节点健康。
- 判断主节点是否故障。
- 选举新主节点。
- 通知客户端新的主节点地址。

哨兵解决高可用，不解决大规模数据分片。

## Cluster

Redis Cluster 将 16384 个哈希槽分配给多个主节点：

```text
CRC16(key) mod 16384 → 槽位 → 节点
```

每个主节点可配置副本，实现分片和故障转移。

## 跨槽限制

多 Key 命令要求 Key 位于同一槽位。可使用 Hash Tag：

```text
user:{1001}:name
user:{1001}:orders
```

相同 `{1001}` 会落入同一槽位。

## 选择

- 数据量小、重视自动故障转移：哨兵。
- 数据量大、需要水平扩展：Cluster。
