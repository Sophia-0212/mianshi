# Redis 数据结构

**设计目的：**让 Redis 直接处理整值读写、字段更新、队列、集合、排序、位标记、消息消费，减少应用端读改写。

**String：**整值读写、整数原子增减；`SET` / `GET` / `INCR`；缓存 JSON、计数、分布式锁（`SET NX EX`）。

**`SET key value`：**存值，键已存在则覆盖；`SET name Alice` → 将 `name` 设为 `Alice`。

**`GET key`：**取值；`GET name` → `Alice`；键不存在返回 `nil`（空）。

**`INCR key`：**整数原子加 1，返回新值；`SET views 10` 后执行 `INCR views` → `11`；键不存在从 0 加到 1，值非整数或结果超出有符号 64 位范围则报错；并发计数不丢增量，`GET` → 加 1 → `SET` 可能相互覆盖。

**Hash：**按字段读写对象，避免整段 JSON 反序列化、重写；`HSET` / `HGET`；用户资料、商品属性、购物车。

**List：**有序、可重复，两端快速入队、出队；`LPUSH` / `RPOP`；简单队列、最新消息列表；无消费确认，可靠消费考虑 Stream / MQ。

**Set：**无序、唯一，支持去重、成员判断、交并差集；`SADD` / `SISMEMBER`；标签、共同关注、独立访客去重。

**ZSet：**成员唯一、按分值排序，支持改分、查排名、范围查询；`ZADD` / `ZREVRANGE`；排行榜、延迟队列（分值存执行时间）。

**Bitmap：**基于 String，每个布尔标记占一位；`SETBIT` / `GETBIT`；签到、活跃用户、在线状态；适合密集编号，稀疏编号浪费空间。

**Stream：**消息带 ID，支持追加、消费组、确认、待处理消息追踪；任务分发、事件流；重试、幂等需业务配合，复杂消息需求评估专业 MQ。
