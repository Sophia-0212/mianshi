# 一次 HTTP 请求的完整链路

```text
用户输入 URL
  ↓
浏览器检查缓存
  ↓
DNS 将域名解析为 IP
  ↓
建立 TCP 连接
  ↓
建立 TLS 连接（HTTPS）
  ↓
发送 HTTP 请求
  ↓
Nginx / 网关接收请求
  ↓
负载均衡转发到应用实例
  ↓
应用处理业务
  ↓
查询 Redis / MySQL，或发送 MQ 消息
  ↓
应用返回 HTTP 响应
  ↓
Nginx 转发响应
  ↓
浏览器解析并渲染
```

## 关键说明

- DNS：域名 → IP。
- TCP：保证数据可靠、有序传输。
- TLS：加密通信，验证服务端身份。
- HTTP：定义请求和响应格式。
- Nginx：反向代理、负载均衡、限流。
- Redis：高速缓存。
- MySQL：持久化存储和事务。
- MQ：异步、解耦、削峰。

## 面试表达

一次请求先通过 DNS 找到服务端 IP，再通过 TCP 建立连接；HTTPS 还要完成 TLS 握手。客户端发送 HTTP 请求，请求经过 Nginx 或网关转发到应用服务。应用根据业务查询缓存和数据库，必要时发送消息，最后返回 HTTP 响应。
