# TCP 三次握手

## 流程

```text
客户端 → SYN(seq=x) → 服务端
客户端 ← SYN+ACK(seq=y, ack=x+1) ← 服务端
客户端 → ACK(ack=y+1) → 服务端
```

## 每次握手做什么

1. 客户端发送 SYN：请求建立连接，并发送初始序列号。
2. 服务端发送 SYN+ACK：确认收到请求，同时发送自己的初始序列号。确认客户端发送没问题，服务端接收没问题。
3. 客户端发送 ACK：确认收到服务端的序列号。确认客户端发送接收没问题，确认服务端发送接收没问题。

完成后，双方都确认对方具备发送和接收能力，连接建立。

## 为什么是三次

两次只能确认：

- 客户端能发送，服务端能接收；
- 服务端能发送，客户端能接收。

第三次让服务端确认客户端已收到自己的响应，避免旧连接请求建立错误连接。

## 面试重点

- SYN、ACK 是 TCP 报文标志位。
- `seq` 是序列号，`ack` 是确认号。
- 三次握手建立连接；四次挥手关闭连接。
- SYN 队列可能受到 SYN Flood 攻击。

## 四次挥手

### 完整流程

假设客户端主动关闭连接：

```text
客户端                                      服务端
ESTABLISHED                                 ESTABLISHED
    │                                           │
    │── FIN(seq=u)   ──────────────────────────>│
FIN_WAIT_1                                      │
    │  <─ ACK(ack=u+1) ─────────────────────────│
FIN_WAIT_2                                  CLOSE_WAIT
    │                                           │
    │                       服务端处理完剩余数据   │
    │<─   FIN(seq=v) ───────────────────────────│
    │                                      LAST_ACK
    │──   ACK(ack=v+1) ────────────────────────>│
TIME_WAIT                                  CLOSED
    │
    │  等待 2MSL
    │
CLOSED
```

### 每次挥手做什么

1. 客户端发送 FIN：客户端不再发送数据，进入 `FIN_WAIT_1`。
2. 服务端发送 ACK：确认收到 FIN；服务端仍可向客户端发送数据，进入 `CLOSE_WAIT`。
3. 服务端发送 FIN：服务端数据发送完毕，进入 `LAST_ACK`。
4. 客户端发送 ACK：确认收到服务端 FIN，进入 `TIME_WAIT`；服务端收到后进入 `CLOSED`。

客户端等待 2MSL 后进入 `CLOSED`。

TCP 是全双工通信，两个方向必须分别关闭，因此通常需要四个报文。若 ACK 和 FIN 同时满足条件，也可能合并为一个报文。

## 为什么挥手通常是四次

收到 FIN 只代表对方不再发送数据，不代表对方不能继续接收数据。被动关闭方可能还有数据要发送，因此先回复 ACK，发送完剩余数据后再发送 FIN。

## TIME_WAIT

主动关闭方发送最后一个 ACK 后进入 TIME_WAIT，通常持续 2MSL。

作用：

- 确保最后的 ACK 能到达对方。
- 让旧连接中的延迟报文失效。

## MSL 与 2MSL

### MSL 是什么

MSL（Maximum Segment Lifetime）是 TCP 报文在网络中允许存在的最大时间。超过 MSL，报文应当在网络中失效。

MSL 不是 TCP 报文的实际传输时间，而是协议规定的最长存活时间。不同系统的取值可能不同。

### 为什么等待 2MSL

客户端发送最后一个 ACK 后，无法确定服务端是否收到 ACK：

```text
客户端 ── ACK ──> 服务端
```

等待 2MSL 可以覆盖一个完整往返：

```text
最后 ACK 到达服务端：最多 MSL
服务端重传 FIN 到达客户端：最多 MSL
总计：2MSL
```

因此：

1. 如果 ACK 丢失，客户端仍能收到服务端重传的 FIN 并重新确认。
2. 旧连接中的延迟报文经过 2MSL 后失效，避免影响新连接。

实际系统通常使用实现规定的 TIME_WAIT 时长，不一定直接等于字面上的两倍固定秒数。

## 面试重点

- 三次握手建立连接，四次挥手释放连接。
- FIN 表示发送方向关闭，ACK 表示确认收到。
- 关闭连接后，连接两端仍可能处于不同状态。
- TIME_WAIT 过多会占用端口资源。
