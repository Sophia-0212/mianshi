# 复述：一次请求链路

## 标准答案

客户端输入 URL 后，先通过 DNS 将域名解析为 IP，然后建立 TCP 连接；如果使用 HTTPS，还要完成 TLS 握手。客户端发送 HTTP 请求，请求到达 Nginx 或网关后，由负载均衡转发到应用实例。应用根据业务查询 Redis 和 MySQL，必要时发送 MQ 消息，最后返回 HTTP 响应。

## 极简版

```text
DNS 找地址
→ TCP 建连接
→ TLS 做加密
→ HTTP 发请求
→ Nginx 做转发
→ 应用查 Redis / MySQL
→ MQ 做异步处理
→ 返回响应
```

## 检查标准

能够说明：

- DNS 做什么。
- TCP 为什么可靠。
- HTTPS 比 HTTP 多了什么。
- Nginx 为什么存在。
- Redis、MySQL、MQ 各自负责什么。
- 请求失败可能发生在哪一层。
