# 后端面试：中间件学习路线图

## 一、先建立基础

先补齐这些知识，否则中间件容易停留在背诵：

- TCP/IP、HTTP、长连接
- Linux、进程、线程、IO、多路复用
- 数据库事务、锁、索引、MVCC
- 并发、线程池、限流、熔断、重试
- 一致性、可用性、分区容错
- CAP、BASE、最终一致性

重点理解：

> 请求如何到达服务，服务如何访问数据，多个服务如何通信，故障如何传播与恢复。

## 二、核心学习顺序

### 1. Redis：优先级最高

学习顺序：

1. 数据结构：String、Hash、List、Set、ZSet、Bitmap、Stream
2. 底层结构：SDS、跳表、压缩列表、哈希表
3. 持久化：RDB、AOF
4. 过期删除、淘汰策略
5. 主从复制、哨兵、集群
6. 缓存问题：穿透、击穿、雪崩、热 Key、大 Key
7. 分布式锁
8. Redis 高并发与性能优化

必须能回答：

- Redis 为什么快？
- 为什么单线程仍然高性能？
- 缓存与数据库如何保持一致？
- 分布式锁如何避免误删、续期、集群故障？
- Redis 集群如何分片？

实战：

- 商品详情缓存
- 热点 Key 防护
- Redis 分布式锁
- 延迟队列
- 秒杀库存扣减

### 2. 消息队列：Kafka / RocketMQ / RabbitMQ

先掌握通用模型：

- Producer
- Broker
- Topic
- Partition / Queue
- Consumer
- Consumer Group
- Offset
- ACK
- 重试
- 死信队列

重点问题：

- 为什么需要消息队列？
- 如何保证消息不丢失？
- 如何保证消息不重复？
- 如何保证消息顺序？
- 消息积压怎么办？
- 如何实现延迟消息？
- 如何实现事务消息？
- Kafka 为什么吞吐量高？
- RocketMQ 与 Kafka 如何选择？

必须建立一个认识：

> 消息队列通常只能保证“至少一次”，业务必须具备幂等性。

实战：

- 订单创建后异步扣库存
- 支付结果通知
- 消息重试与死信处理
- 消费者幂等
- 消息积压监控

### 3. Nginx / 网关

学习内容：

- 反向代理
- 负载均衡
- 动静分离
- 限流
- 熔断
- SSL
- 灰度发布
- 一致性 Hash
- 连接复用
- 高并发配置

必须理解：

- 四层负载均衡和七层负载均衡
- 轮询、权重、IP Hash、最少连接
- Nginx 与网关的职责边界
- 服务如何优雅上下线

### 4. RPC 与注册中心

学习内容：

- 服务发现
- 注册与订阅
- 心跳与健康检查
- 序列化
- 网络通信
- 超时
- 重试
- 熔断
- 负载均衡
- 链路追踪

常见组件：

- Dubbo
- gRPC
- Spring Cloud
- Nacos
- ZooKeeper
- etcd

重点问题：

- RPC 和 HTTP 有什么区别？
- 为什么 RPC 需要注册中心？
- 重试为什么可能造成请求放大？
- 注册中心宕机后服务还能工作吗？
- 如何处理服务雪崩？

### 5. Elasticsearch

学习内容：

- 倒排索引
- 分词
- Document、Index、Shard、Replica
- Refresh、Flush
- 查询类型
- 深分页
- 写入一致性
- 数据同步
- 分片设计

重点问题：

- 倒排索引为什么适合全文检索？
- Elasticsearch 为什么不适合强事务？
- 深分页为什么慢？
- MySQL 与 Elasticsearch 如何同步？
- 分片数如何设计？

### 6. 分布式协调与任务调度

学习内容：

- ZooKeeper
- 分布式锁
- Leader 选举
- 配置中心
- 任务调度
- 一致性哈希
- 时间轮
- 定时任务高可用

## 三、分阶段学习

### 第 1 阶段：基础，1 周

目标：

- 理解网络、并发、数据库、分布式基本概念
- 能画出一个请求链路

```text
客户端
  ↓
Nginx
  ↓
网关
  ↓
RPC 服务
  ↓
Redis / MySQL / MQ
```

### 第 2 阶段：Redis，2 周

目标：

- 掌握缓存、锁、集群
- 完成缓存项目

### 第 3 阶段：消息队列，2 周

目标：

- 掌握可靠投递、幂等、顺序、积压
- 完成订单异步化项目

### 第 4 阶段：Nginx、RPC、注册中心，2 周

目标：

- 能解释微服务调用链
- 能分析超时、重试、熔断、雪崩

### 第 5 阶段：ES、协调组件，1 周

目标：

- 掌握搜索、分片、同步、选举

### 第 6 阶段：综合项目，2 周

实现一个简化电商系统：

```text
Nginx
  ↓
网关
  ↓
订单服务 ── Redis
  ↓
MQ
  ↓
库存服务 ── MySQL
  ↓
ES 搜索服务
```

加入：

- 缓存
- 分布式锁
- 消息重试
- 幂等
- 限流
- 熔断
- 监控
- 链路追踪

## 四、每个中间件的学习方法

按这 8 个问题总结：

1. 解决什么问题？
2. 核心数据结构是什么？
3. 工作流程是什么？
4. 为什么性能高？
5. 如何保证可靠性？
6. 如何扩展和集群？
7. 常见故障是什么？
8. 如何在项目中落地？

例如学习 Redis，不要只背“缓存穿透解决方案”，要能说清：

```text
请求不存在数据
→ 查询缓存失败
→ 查询数据库失败
→ 大量请求打到数据库
→ 使用布隆过滤器 / 空值缓存拦截
```

## 五、面试回答模板

回答任何中间件问题，都按这个顺序：

```text
定义
→ 使用场景
→ 核心原理
→ 关键问题
→ 解决方案
→ 项目实践
→ 方案取舍
```

例如“为什么使用消息队列”：

```text
消息队列用于解耦、异步、削峰。
订单创建后，发送消息给库存、积分、通知服务，
避免同步调用导致响应慢和系统强耦合。
但它会引入重复消费、消息丢失、消息积压等问题，
因此需要持久化、ACK、重试、死信和业务幂等。
```

## 六、学习资料与实践方式

每个组件只选一套主资料：

- Redis：官方文档 + 《Redis 设计与实现》
- Kafka：官方设计文档
- RocketMQ：官方文档 + 源码关键流程
- Nginx：官方文档
- Elasticsearch：官方文档
- RPC：Dubbo 或 gRPC 官方文档

学习时坚持：

```text
看原理
→ 画流程图
→ 写最小 Demo
→ 制造故障
→ 记录解决方案
→ 用自己的话复述
```

## 七、最终掌握标准

至少能独立回答：

- Redis 为什么快？
- 缓存和数据库如何一致？
- 分布式锁如何实现？
- MQ 如何保证消息不丢？
- 消费重复如何处理？
- 消息积压如何解决？
- Kafka 为什么吞吐高？
- RPC 如何发现服务？
- 如何解决服务雪崩？
- Elasticsearch 为什么查询快？
- 如何设计一个高并发系统？

学习优先级：

```text
Redis ＞ 消息队列 ＞ Nginx ＞ RPC/注册中心 ＞ Elasticsearch ＞ ZooKeeper
```

如果时间有限，优先把 Redis、消息队列、限流熔断、分布式锁、幂等、缓存一致性学透。
