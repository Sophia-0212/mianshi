# Java 高频 Top 10 面试题

## 1. Java 的特点是什么？

Java 是面向对象、静态类型、跨平台的语言。

- 源码编译为字节码，由 JVM 执行。
- 自动垃圾回收，减少手动内存管理。
- 支持封装、继承、多态。
- 提供丰富的标准库和并发工具。

面试口述：Java 通过 JVM 实现“一次编译，到处运行”；通过面向对象组织业务，通过自动 GC 管理内存。

## 2. `==` 和 `equals()` 有什么区别？

- 基本类型：`==` 比较值。
- 引用类型：`==` 比较是否为同一个对象。
- `equals()` 默认也比较引用；重写后可比较业务内容。

如果重写 `equals()`，必须同时重写 `hashCode()`，否则放入 `HashMap`、`HashSet` 时可能出现查找错误。

## 3. `String` 为什么不可变？`StringBuilder` 和 `StringBuffer` 有什么区别？

`String` 的值创建后不能修改。不可变带来线程安全、字符串常量池复用和可缓存哈希值等好处。

- `String`：拼接会创建新对象。
- `StringBuilder`：可变，非线程安全，性能较好。
- `StringBuffer`：可变，方法带同步，线程安全但性能较低。

循环拼接字符串优先使用 `StringBuilder`。

## 4. `ArrayList` 和 `LinkedList` 有什么区别？

- `ArrayList`：动态数组，随机访问快，尾部插入通常快。
- `LinkedList`：双向链表，按下标访问慢，已定位节点时插入删除快。

大多数场景优先使用 `ArrayList`；选择集合要根据访问和修改模式，而不是只看理论复杂度。

## 5. `HashMap` 的工作原理是什么？

`HashMap` 通过 Key 的哈希值定位桶，再用 `equals()` 确认 Key 是否相同。

- JDK 8 中桶内结构主要是链表，冲突严重时转为红黑树。
- 容量不足时扩容并重新分布元素。
- Key 应稳定、正确实现 `equals()` 和 `hashCode()`。
- 允许一个 `null` Key 和多个 `null` Value。
- 非线程安全，并发写入应使用 `ConcurrentHashMap`。

## 6. `HashMap` 和 `ConcurrentHashMap` 有什么区别？

- `HashMap`：非线程安全，允许 `null` Key 和 Value。
- `ConcurrentHashMap`：线程安全，不允许 `null` Key 或 Value。
- `ConcurrentHashMap` 使用 CAS、Node 和细粒度控制降低锁竞争，支持并发读写。

如果要实现复合操作，例如“没有才写入”，应使用 `putIfAbsent` 或 `computeIfAbsent`，不能拆成普通的 `get` 加 `put`。

## 7. `final`、`finally`、`finalize` 有什么区别？

- `final`：修饰变量、方法或类；变量只能赋值一次，方法不能重写，类不能继承。
- `finally`：异常处理中的收尾代码，通常用于释放资源。
- `finalize()`：历史上的 GC 前回调，执行时机不可靠，已不推荐使用。

资源释放优先使用 `try-with-resources`。

## 8. `synchronized` 和 `volatile` 有什么区别？

- `volatile` 保证变量的可见性和一定的有序性，但不保证复合操作的原子性。
- `synchronized` 保证互斥、可见性和原子性，并能保护临界区。

```java
volatile boolean running = true;

synchronized void increment() {
    count++;
}
```

`count++` 包含读取、计算、写回，不能仅依赖 `volatile` 保证线程安全。

## 9. Java 线程池的核心参数有哪些？

`ThreadPoolExecutor` 的核心参数：

- `corePoolSize`：核心线程数。
- `maximumPoolSize`：最大线程数。
- `keepAliveTime`：非核心线程空闲存活时间。
- `workQueue`：任务队列。
- `threadFactory`：线程创建方式。
- `RejectedExecutionHandler`：任务拒绝策略。

执行流程：核心线程未满则创建；否则进入队列；队列满后创建非核心线程；达到最大线程数后执行拒绝策略。

线程数要结合任务类型、CPU 核数、I/O 等待时间和压测结果设置，不能盲目固定。

## 10. JVM 内存区域和垃圾回收如何工作？

JVM 主要区域：

- **堆**：对象和数组，GC 重点管理区域。
- **虚拟机栈**：线程私有，保存栈帧和局部变量。
- **程序计数器**：记录当前字节码位置。
- **方法区/元空间**：类元数据、常量等。
- **本地方法栈**：支持 native 方法。

GC 从 GC Roots 判断对象是否可达，回收不可达对象。常见问题：

- `OutOfMemoryError`：内存不足或对象持续积压。
- 频繁 Full GC：对象分配过快、老年代压力大或堆配置不合理。
- 接口停顿：可能与 GC 暂停、锁竞争或慢 I/O 有关。

排查应结合堆转储、GC 日志、线程栈和监控数据，不能只看异常名称。

## 代码库如何与数据库进行通信的？

**项目主要通过 MyBatis 访问数据库**：业务层调用 Repository，再调用 Mapper；MyBatis 将 XML、注解或SQL Provider 中的 SQL 与参数绑定，通过数据源获取连接，由 JDBC 驱动与 MySQL 通信，并将查询结果映射为 Java 对象。

### XML、MyBatis、JDBC三者的区别：

| 名称 | 是什么 | 负责什么 |
| --- | --- | --- |
| XML | 文本格式 | 一种文本格式，用标签组织数据。 |
| MyBatis | 持久层框架 | MyBatis 是 Java 持久层框架：你写 SQL，它负责绑定参数、执行 SQL、调用 JDBC、把结果转成 Java 对象。 |
| JDBC | Java 数据库访问标准接口 | 是 Java 访问关系型数据库的标准接口。 |

### 调用关系是：

```text
调用 Mapper 方法
    ↓
MyBatis 找到 XML 中对应的 SQL
    ↓
通过 JDBC 驱动执行 SQL
    ↓
MyBatis 将结果映射成 Java 对象
```

**MyBatis 可以不用 XML，改用注解写 SQL；JDBC 也可以脱离 MyBatis，直接在 Java 中调用。**

## 线上数据库的配置是远程请求到？

**项目通过百度 Gravity 配置中心加载远程配置**，**客户端内部使用 RestTemplate 发起 HTTP 请求**。 我核对了本地依赖源码，流程是：

```text
应用启动
  → Gravity 客户端读取应用名、环境、AppKey 等启动配置
  → 使用 AppKey 获取认证 Token
  → 携带 Token，通过 HTTP GET 拉取配置
  → 将配置加入 Spring Environment
  → @ConfigurationProperties 绑定数据库参数
  → 创建 HikariCP 数据源
```

## 常见三层架构 和 DDD架构

### 常见三层架构：

```text
Controller → Service → DAO/Mapper → 数据库
```

| 层 | 职责 | 客户档案例子 |
| --- | --- | --- |
| Controller 接口层 | 接收请求、校验参数格式、返回结果 | 接收“申领客户”请求 |
| Service 业务层 | 执行业务规则、组织流程、控制事务 | 判断能否申领、是否超出客保量 |
| DAO/Mapper 数据访问层 | 执行 SQL，读写数据 | 查询客户、插入客保记录 |

### 这个项目进一步采用了 DDD 风格分层：

| 层 | 职责 |
| --- | --- |
| Interface 接口层 | 对外提供 HTTP 接口 |
| Application 应用层 | 编排一个完整业务用例，例如申领客户 |
| Domain 领域层 | 表达核心业务规则，例如客户是否具备申领资格 |
| Infrastructure 基础设施层 | 实现数据库、缓存、消息和外部系统访问 |

## JVM

**JVM（Java 虚拟机）负责执行 Java 字节码，并管理内存、垃圾回收和运行时优化。**

JVM，有四部分：

1. **类加载**：把代码准备好

2. **内存区域**：存放运行数据

3. **执行引擎**：让代码跑起来

4. **垃圾回收**：释放无用对象

## 中间件：

**中间件是为业务系统提供通用能力的软件，解决通信、缓存、消息、流量分发等问题。**

常见类型包括：

| 类型 | 代表组件 | 解决的问题 |
| --- | --- | --- |
| 缓存 | Redis | 减少数据库访问、缓存热点数据、实现分布式锁 |
| 消息队列 | Kafka、RabbitMQ、RocketMQ | 异步处理、系统解耦、削峰填谷 |
| 网关与代理 | Nginx、API 网关 | 请求路由、负载均衡、鉴权、限流 |
| 配置中心 | Nacos、Apollo | 集中管理和分发配置 |
| 注册中心 | ZooKeeper、Nacos | 服务注册与发现 |
